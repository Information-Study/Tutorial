## 觀念說明

### 核心比喻：大樓門牌 + 房號

> [!example] 一台伺服器可以同時提供很多服務
> 一台機器只有一個 IP `203.0.113.5`，
> 但它同時跑著網站、郵件、遠端管理、資料庫……
>
> **封包到了這台機器，怎麼知道該交給哪個程式？**
>
> 答案：**埠號（Port）**。
>
> | 現實 | 網路 |
> | --- | --- |
> | **大樓地址**「信義路五段 7 號」 | **IP 位址** |
> | **房號**「12 樓 A 室」 | **埠號** |
> | 大樓管理員 | 作業系統 |
> | 各個住戶 | 各個服務程式 |
>
> 「**IP 位址 + 埠號**」合起來才能精確定位到某一個服務，
> 這個組合叫做 **socket**。
>
> ```
> 203.0.113.5:443    ← 網站服務
> 203.0.113.5:22     ← SSH 遠端管理
> 203.0.113.5:3306   ← MySQL 資料庫
> ```

### 埠號的基本資料

| 特性 | 說明 |
| --- | --- |
| 長度 | **16 位元** |
| 範圍 | **0 ～ 65535**（2¹⁶ = 65536 個） |
| 在哪一層 | **第 4 層（傳輸層）** |
| TCP 與 UDP | **各自有一套**（TCP 80 與 UDP 80 是不同的） |

### 三個範圍

| 範圍 | 名稱 | 說明 |
| --- | --- | --- |
| **0 ～ 1023** | **知名埠（Well-Known）** | 標準服務用；**Linux 上需要 root 權限才能綁定** |
| 1024 ～ 49151 | 註冊埠（Registered） | 向 IANA 登記的應用程式 |
| **49152 ～ 65535** | **動態／臨時埠（Ephemeral）** | **客戶端連出去時自動使用** |

> [!note] 為什麼客戶端也需要埠號
> 你用瀏覽器連到網站時：
> ```
> 你的電腦          →          網站伺服器
> 192.168.1.10:54321  →  93.184.216.34:443
>                ^^^^^                  ^^^
>              臨時埠（隨機）        知名埠（固定）
> ```
>
> **伺服器端的埠是固定的**（大家都知道網站在 443），
> **客戶端的埠是隨機的**（每開一個連線就配一個）。
>
> 這樣回應封包回來時，作業系統才知道要交給**哪一個分頁／哪一個程式**。
>
> ```bash
> # 看你的系統用哪個範圍當臨時埠
> $ cat /proc/sys/net/ipv4/ip_local_port_range
> 32768	60999
> ```

> [!warning] 為什麼 1024 以下需要 root
> 這是 Unix 的傳統安全設計：
> **防止一般使用者冒充系統服務**。
>
> 如果任何人都能綁定 80 埠，
> 一個普通使用者就能在伺服器上架一個假的網站服務來釣魚。
>
> **但這也帶來麻煩** —— Nginx 為了綁 80/443 必須用 root 啟動。
>
> **現代解法**：
> ```bash
> # 方法 1：給執行檔特定能力（不需要完整 root）
> $ sudo setcap 'cap_net_bind_service=+ep' /usr/bin/nginx
>
> # 方法 2：降低門檻（Linux 特有）
> $ sudo sysctl -w net.ipv4.ip_unprivileged_port_start=80
>
> # 方法 3（最常見）：主程序用 root 綁埠，
> #                   然後 worker 程序降權到 www-data
> ```
> Nginx、Apache 用的是**方法 3**。

## 主機（Host）與服務

> [!note] 「主機」是硬體，「服務」是跑在上面的軟體
> 一台**主機（Host）** 擁有 IP 位址，
> 根據上面安裝了什麼軟體，提供不同的服務。
>
> | 服務軟體 | 提供什麼 | 預設埠 |
> | --- | --- | --- |
> | **Web server**（Nginx、Apache） | 網頁服務 | 80 / 443 |
> | **Mail server** | 郵件收發 | 25 / 587 / 993 |
> | **FTP server** | 檔案上傳下載 | 21 / 20 |
> | **Database server**（MySQL、PostgreSQL） | 資料查詢 | 3306 / 5432 |
> | **SSH server**（sshd） | 遠端管理 | 22 |
> | **DNS server** | 名稱解析 | 53 |
>
> **同一台主機可以同時跑全部這些服務**，
> 靠不同的埠號區分。

> [!tip] 「預設埠」可以改
> 埠號只是約定，不是強制。
> 你可以把 SSH 改到 2222、把網站放在 8080。
>
> **改埠的效果**：
> - ✅ **大幅減少自動化掃描的騷擾**（機器人主要掃預設埠）
> - ❌ **不能算是安全措施**（真正的攻擊者會全埠掃描）
> - ⚠️ 增加管理複雜度（每個人都要記得非標準埠）
>
> 這叫 **security through obscurity（隱晦式安全）** ——
> 它可以當作「減少雜訊」的手段，
> **但絕不能取代真正的防護**（金鑰認證、Fail2ban、防火牆）。

## 必須記住的埠號

### 最常用的（一定要背）

| 埠 | 協定 | 服務 | 備註 |
| --- | --- | --- | --- |
| **20 / 21** | TCP | **FTP**（資料 / 控制） | **明文，應改用 SFTP** |
| **22** | TCP | **SSH / SFTP / SCP** | **加密的遠端管理** |
| 23 | TCP | Telnet | **明文，絕對不要用** |
| 25 | TCP | SMTP（郵件傳送） | 伺服器之間 |
| **53** | **TCP + UDP** | **DNS** | **兩種都要開放** |
| 67 / 68 | UDP | DHCP（伺服器 / 客戶端） | 廣播 |
| **80** | TCP | **HTTP** | 未加密的網頁 |
| 110 | TCP | POP3 | 舊的收信協定 |
| 123 | UDP | NTP | 時間同步 |
| 143 | TCP | IMAP | 收信 |
| 161 / 162 | UDP | SNMP / SNMP Trap | 設備監控 |
| **443** | TCP（+UDP for HTTP/3） | **HTTPS** | **加密的網頁** |
| **445** | TCP | **SMB / CIFS** | Windows 檔案共享，**絕不對外** |
| 465 / 587 | TCP | SMTPS / Submission | 寄信（加密） |
| 514 | UDP | Syslog | 日誌傳送 |
| 636 | TCP | LDAPS | 加密的目錄服務 |
| 993 / 995 | TCP | IMAPS / POP3S | 加密的收信 |
| **3306** | TCP | **MySQL / MariaDB** | **絕不對外** |
| **3389** | TCP | **RDP 遠端桌面** | **絕不對外** |
| **5432** | TCP | **PostgreSQL** | **絕不對外** |
| 5900+ | TCP | VNC | 遠端桌面，**絕不對外** |
| **6379** | TCP | **Redis** | **絕不對外**（預設無密碼！） |
| 8080 / 8443 | TCP | HTTP / HTTPS 替代埠 | 常見的應用伺服器 |
| 27017 | TCP | MongoDB | **絕不對外** |

> [!tip] 記憶技巧
> - **加密版通常是原版 + 隨機數字**：
>   HTTP 80 → HTTPS **443**；IMAP 143 → IMAPS **993**；POP3 110 → POP3S **995**
> - **20/21 相鄰**：FTP 的資料與控制
> - **22 SSH** 是維運人員最常用的數字
> - **53 DNS**：TCP 和 UDP 都要記得

### 為什麼有些埠「絕對不該對外」

> [!danger] 這些埠開到網際網路上等於開門迎賊
> | 埠 | 為什麼危險 |
> | --- | --- |
> | **23（Telnet）** | **完全明文**，密碼直接在網路上傳 |
> | **445（SMB）** | 勒索軟體最愛的入侵管道，歷史上多次重大漏洞 |
> | **3389（RDP）** | **全世界的機器人都在掃這個埠**做暴力破解 |
> | **3306 / 5432（資料庫）** | 直接存取你的所有資料 |
> | **6379（Redis）** | **預設沒有密碼**，歷史上大量未授權存取事件 |
> | **27017（MongoDB）** | 同上，曾有數萬個資料庫被公開在網路上 |
> | **5900（VNC）** | 常常沒有密碼或密碼很弱 |
> | **11211（Memcached）** | **反射放大攻擊**的主要來源 |
>
> **正確做法**：
> - 這些服務**只監聽 `127.0.0.1` 或內網介面**
> - 需要遠端存取時**走 VPN 或 SSH 隧道**
> - 對外只開放真正需要公開的服務（通常只有 80/443）

## 主要的應用層協定

### SSH（Secure Shell）— 埠 22

**SSH 是維運人員最重要的工具**，沒有之一。

| 特性 | 說明 |
| --- | --- |
| 用途 | **加密的遠端登入與管理** |
| 取代 | Telnet（明文）、rlogin、rsh |
| 預設埠 | **22 / TCP** |
| 加密 | 全程加密，包含帳密與所有指令 |

```bash
# 基本連線
$ ssh username@192.168.1.50

# 指定埠
$ ssh -p 2222 username@主機

# 執行單一指令後離開
$ ssh username@主機 'df -h'
```

**SSH 家族**：

| 工具 | 用途 |
| --- | --- |
| **ssh** | 遠端登入 |
| **scp** | 複製檔案（`scp 檔案 user@host:/path/`） |
| **sftp** | 互動式檔案傳輸 |
| **ssh 隧道** | 把遠端的埠映射到本機（見下方） |

> [!tip] SSH 隧道：不用開埠也能安全存取內部服務
> 這是維運人員最實用的技巧之一。
>
> ```bash
> # 把遠端伺服器的 MySQL(3306) 映射到我的本機 13306
> $ ssh -L 13306:localhost:3306 user@伺服器
>
> # 之後就可以在本機用
> $ mysql -h 127.0.0.1 -P 13306 -u root -p
> ```
>
> **這樣做的好處**：
> - MySQL **完全不需要對外開放**
> - 流量走 SSH，**全程加密**
> - 有 SSH 的身分驗證把關
>
> 三種隧道：
> | 參數 | 方向 | 用途 |
> | --- | --- | --- |
> | **`-L`** | 本地轉發 | 把遠端服務拉到本機（最常用） |
> | `-R` | 遠端轉發 | 把本機服務推到遠端 |
> | `-D` | 動態轉發 | 當成 SOCKS 代理 |
>
> 完整說明見 `40-Linux伺服器管理/01-SSH與遠端管理`。

### FTP vs SFTP vs FTPS

| | **FTP** | **SFTP** | **FTPS** |
| --- | --- | --- | --- |
| 埠 | 21（控制）+ 20（資料） | **22**（走 SSH） | 990 或 21 + TLS |
| 加密 | ❌ **完全明文** | ✅ | ✅ |
| 基於什麼 | 獨立協定 | **SSH 的子系統** | FTP + TLS |
| NAT 友善 | ❌（主動模式有問題） | ✅ **單一埠** | ⚠️ 需要處理資料埠 |
| 建議 | **不要用** | ✅ **首選** | 需相容舊系統時 |

> [!danger] FTP 是明文協定
> FTP 的**帳號、密碼、檔案內容全部都是明文**傳輸。
> 同一個網段上任何人用 tcpdump 就能看到。
>
> ```bash
> # 示範（在測試環境）：抓 FTP 密碼
> $ sudo tcpdump -i any -A 'tcp port 21' | grep -i 'USER\|PASS'
> USER admin
> PASS mypassword123        ← 就這樣看到了
> ```
>
> **機關若還有 FTP 服務，應盡快改為 SFTP。**

> [!note] FTP 主動模式 vs 被動模式
> | | **主動（Active）** | **被動（Passive）** |
> | --- | --- | --- |
> | 資料連線由誰發起 | **伺服器 → 客戶端** | **客戶端 → 伺服器** |
> | NAT 後面 | ❌ **失敗**（伺服器連不進來） | ✅ 可用 |
> | 防火牆友善 | ❌ | ✅ |
>
> 這就是「**FTP 能登入但列不出目錄**」的經典原因 ——
> 用了主動模式，而客戶端在 NAT 後面。
> **解法：改用被動模式**（現代客戶端預設）。

### SMB / CIFS — 埠 445

Windows 的**檔案與印表機共享**協定。

| 版本 | 狀態 |
| --- | --- |
| **SMB v1** | **必須停用**（WannaCry 等勒索軟體的入侵管道） |
| SMB v2 | 可用 |
| **SMB v3** | **建議**（支援加密） |

> [!danger] SMB v1 必須停用
> ```powershell
> # Windows：檢查與停用 SMB v1
> Get-WindowsOptionalFeature -Online -FeatureName SMB1Protocol
> Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol
> ```
> ```bash
> # Linux Samba：在 smb.conf 中要求最低版本
> [global]
>     server min protocol = SMB3
>     client min protocol = SMB3
> ```
>
> **445 埠絕對不可以對外開放。**
> 這是勒索軟體橫向擴散的主要途徑。

### RDP（遠端桌面）— 埠 3389

> [!danger] RDP 是暴力破解的頭號目標
> 把 3389 開到網際網路上，**幾小時內就會開始被掃描與嘗試登入**。
>
> 大量的勒索軟體事件都是從「**對外開放且密碼不強的 RDP**」開始的。
>
> **正確做法**：
> 1. **不要對外開放 3389**
> 2. 遠端存取走 **VPN**
> 3. 若必須開放，至少要：
>    - 限制來源 IP
>    - 啟用**網路層級驗證（NLA）**
>    - 使用**強密碼 + MFA**
>    - 部署 **RD Gateway**（走 443 + 驗證）
>    - 帳號鎖定政策
>    - 完整的登入日誌與告警

### WebSocket（WS / WSS）

> [!note] 解決 HTTP「伺服器不能主動推送」的問題
> 傳統 HTTP 是**請求-回應**模型：
> **客戶端問，伺服器才答。伺服器不能主動說話。**
>
> 這對即時應用是個問題：
> - 聊天室：新訊息來了怎麼通知？
> - 即時報價：價格變了怎麼推？
> - 線上遊戲：其他玩家的動作怎麼同步？
>
> **舊做法**：客戶端每隔幾秒就問一次（polling）——
> 浪費頻寬又有延遲。

| 特性 | WebSocket |
| --- | --- |
| 位於 | **應用層**（與 HTTP 同層，但是不同協定） |
| 基於 | TCP |
| 埠 | **80（ws://）/ 443（wss://）** —— 沿用 HTTP 的埠 |
| 特點 | **全雙工**、只需**一次交握**即建立**持久連線** |
| 優點 | **伺服器可以主動推播**、低延遲、省頻寬 |
| 應用 | 聊天室、即時遊戲、協作編輯、即時儀表板、通知 |

```
① 客戶端送出 HTTP 請求，帶著 Upgrade: websocket 標頭
② 伺服器回應 101 Switching Protocols
③ 之後這條 TCP 連線就變成 WebSocket，雙向自由通訊
```

> [!tip] 反向代理要特別設定才能支援 WebSocket
> 這是實務上很常踩的坑。
>
> ```nginx
> location /ws/ {
>     proxy_pass http://backend;
>     proxy_http_version 1.1;
>     proxy_set_header Upgrade $http_upgrade;      # 必要
>     proxy_set_header Connection "upgrade";        # 必要
>     proxy_read_timeout 3600s;                     # 避免長連線被切斷
> }
> ```
> 少了 `Upgrade` 與 `Connection` 標頭，WebSocket 就會升級失敗。

## 完整實戰範例

### 看本機開了哪些埠

```bash
# 最常用的組合（背起來）
$ sudo ss -tulpn
Netid State  Local Address:Port   Peer Address:Port  Process
tcp   LISTEN 0.0.0.0:22           0.0.0.0:*          users:(("sshd",pid=812))
tcp   LISTEN 127.0.0.1:3306       0.0.0.0:*          users:(("mysqld",pid=1234))
tcp   LISTEN *:443                *:*                users:(("nginx",pid=2341))
udp   UNCONN 0.0.0.0:53           0.0.0.0:*          users:(("systemd-resolve"))
```

| 參數 | 意義 |
| --- | --- |
| `-t` | TCP |
| `-u` | UDP |
| `-l` | 只看 LISTEN（正在等待連線的） |
| `-p` | 顯示是**哪個程序**（需要 root） |
| `-n` | 顯示數字不做名稱解析（**快很多**） |

> [!warning] 重點是看「Local Address」
> | 顯示 | 意義 | 外面連得到嗎 |
> | --- | --- | --- |
> | `127.0.0.1:3306` | **只有本機**連得到 | ❌ **安全** |
> | `0.0.0.0:22` 或 `*:22` | **所有介面**都接受 | ✅ 要有防火牆保護 |
> | `192.168.1.10:8080` | 只有這個介面 | 僅該網段 |
> | `[::]:443` | IPv6 所有介面 | ✅ |
>
> **這是排錯的第一個檢查點**：
> 「服務起來了但外面連不上」——
> 八成是它只監聽 `127.0.0.1`。

### 測試遠端的埠

```bash
# nc（最通用）
$ nc -zv example.com 443
Connection to example.com 443 port [tcp/https] succeeded!

# 測多個埠
$ nc -zv 192.168.1.50 22 80 443 3306

# 沒有 nc 時用 bash 內建
$ timeout 3 bash -c '</dev/tcp/example.com/443' && echo OPEN || echo CLOSED

# 用 nmap 掃描（自己的機器）
$ sudo nmap -sV -p 1-1000 192.168.1.50
PORT    STATE SERVICE VERSION
22/tcp  open  ssh     OpenSSH 9.6p1 Ubuntu
80/tcp  open  http    nginx 1.24.0
443/tcp open  ssl/http nginx 1.24.0
```

> [!danger] nmap 掃描要有授權
> 在**自己管理的網路**上掃描是正常的維運與稽核動作，
> 但**仍應知會相關人員並留下紀錄**（否則會觸發資安告警）。
>
> **在別人的網路或主機上掃描，可能觸犯刑法妨害電腦使用罪。**

### 找出「誰佔用了這個埠」

這是最常見的實務問題之一。

```bash
# 情境：啟動 nginx 卻說 Address already in use

# 方法 1：ss
$ sudo ss -tulpn | grep :80
tcp LISTEN 0.0.0.0:80  users:(("apache2",pid=1234,fd=4))
                                ^^^^^^^ 原來是 Apache 佔著

# 方法 2：lsof
$ sudo lsof -i :80
COMMAND  PID USER FD TYPE DEVICE NODE NAME

### 檢查對外服務的埠暴露情況

```bash
#!/usr/bin/env bash
# 檢查有哪些服務監聽在所有介面上（可能對外暴露）
echo "=== 監聽在所有介面（0.0.0.0 或 *）的服務 ==="
sudo ss -tulpn | awk '
  NR==1 {next}
  $5 ~ /^(0\.0\.0\.0|\*|\[::\]):/ {
    print $1, $5, $7
  }
'
echo ""
echo "=== 只監聽本機（安全）==="
sudo ss -tulpn | grep -E '127\.0\.0\.1|\[::1\]'
```

> [!tip] 定期執行這個檢查
> 把它納入**每月維護**：
> 1. 列出所有對外監聽的埠
> 2. 逐一確認「**這個真的需要對外嗎**」
> 3. 不需要的改成只監聽 `127.0.0.1`
> 4. 需要的確認防火牆規則正確
>
> 這是最基本也最有效的攻擊面縮減。
> 見 [[08-系統強化與稽核]]。

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| 服務啟動了但外面連不上 | **只監聽 `127.0.0.1`** | `ss -tulpn` 確認；改設定的 `bind-address`／`listen` |
| `Address already in use` | 埠被別的程序佔用 | `sudo ss -tulpn \| grep :埠` 找出來 |
| 非 root 綁不了 80 埠 | 1024 以下需要特權 | `setcap` 或用反向代理；或主程序 root + worker 降權 |
| FTP 能登入但列不出目錄 | **主動模式在 NAT 後面失效** | 改用被動模式；或改用 SFTP |
| DNS 有時通有時不通 | **只開了 UDP 53，沒開 TCP 53** | 兩個都要開放（大回應會走 TCP） |
| WebSocket 連線失敗 | 反向代理缺 `Upgrade`/`Connection` 標頭 | 補上 Nginx 的 WebSocket 設定 |
| 改了 SSH 埠但連不上 | 防火牆沒開新埠、SELinux 擋住 | `ufw allow 2222`；`semanage port -a -t ssh_port_t -p tcp 2222` |
| 資料庫被入侵 | **3306/5432 對外開放** | 改成只監聽內網或 127.0.0.1；走 SSH 隧道 |
| Redis 被植入挖礦程式 | **6379 對外且預設無密碼** | 設 `requirepass`、`bind 127.0.0.1`、關閉 `CONFIG` 指令 |
| 遭勒索軟體 | **445 或 3389 對外開放** | 立刻關閉；改走 VPN |
| 埠掃描顯示 filtered | 防火牆 drop（不回應） | 正常的防護行為 |
| 埠掃描顯示 closed | 沒有服務在聽，但主機有回 RST | 主機存在，服務沒開 |

## 安全性注意事項

> [!danger] 攻擊面 = 對外開放的埠 × 每個服務的漏洞
> **每多開一個埠，就多一個可能被攻破的入口。**
>
> **最小化原則**：
> 1. **只開真正需要對外的埠**（通常只有 80/443）
> 2. 內部服務**只監聽內網介面或 127.0.0.1**
> 3. 管理埠（SSH、RDP、資料庫）**一律走 VPN**
> 4. **定期盤點**對外開放的埠
> 5. 用**外部視角**驗證（從網際網路掃描自己）

```bash
# 從外部檢查自己開了哪些埠（用線上服務或另一台外部主機）
# 注意：只能掃描自己有權限的主機
$ nmap -Pn -p- 你的公有IP
```

> [!warning] 明文協定必須淘汰
> | 明文（不安全） | 加密替代 |
> | --- | --- |
> | Telnet (23) | **SSH (22)** |
> | FTP (21) | **SFTP (22)** / FTPS |
> | HTTP (80) | **HTTPS (443)** |
> | SNMP v1/v2c (161) | **SNMP v3** |
> | LDAP (389) | **LDAPS (636)** / StartTLS |
> | POP3 (110) / IMAP (143) | **POP3S (995) / IMAPS (993)** |
> | rsh、rlogin | SSH |
>
> **明文協定的密碼會直接暴露在網路上**，
> 同網段的任何人（或 ARP 欺騙的攻擊者）都能看到。
>
> 機關的**網路設備管理**尤其要注意 ——
> 很多交換器與印表機預設還開著 Telnet 與 SNMP v2c。

> [!tip] 改埠號的正確定位
> 把 SSH 從 22 改到 2222：
> - ✅ **日誌會乾淨很多**（自動化掃描大幅減少）
> - ✅ 降低被隨機掃描工具找到的機會
> - ❌ **擋不住針對性攻擊**（`nmap -p-` 全埠掃描幾分鐘就找到）
>
> **它是「減少雜訊」的手段，不是安全措施。**
>
> 真正的 SSH 防護：
> ```
> 1. 停用密碼登入，改用金鑰（PasswordAuthentication no）
> 2. 停用 root 直接登入（PermitRootLogin no）
> 3. 安裝 Fail2ban 自動封鎖
> 4. 防火牆限制來源 IP
> 5. 啟用 MFA
> ```
> 見 [[07-SSH-安全強化]] 與 [[03-Fail2ban入侵防護]]。

> [!danger] 預設無密碼的服務
> 有些服務**預設完全沒有驗證**，一旦對外開放就是災難：
>
> | 服務 | 埠 | 問題 |
> | --- | --- | --- |
> | **Redis** | 6379 | 預設無密碼；曾大量被用來植入挖礦與後門 |
> | **MongoDB**（舊版） | 27017 | 預設無驗證；數萬個資料庫曾被公開 |
> | **Elasticsearch** | 9200 | 預設無驗證 |
> | **Memcached** | 11211 | 無驗證，且是反射放大攻擊來源 |
> | **Docker API** | 2375 | **開放等於給了 root 權限** |
> | **Kubernetes API** | 8080（舊版） | 未驗證存取 |
>
> **這些服務一律**：
> - `bind 127.0.0.1` 或內網 IP
> - **設定密碼／啟用驗證**
> - 防火牆阻擋
> - 定期用外部掃描驗證沒有暴露

## 練習題

> [!question]- 練習 1：盤點你的機器
> ```bash
> sudo ss -tulpn
> ```
> 回答：
> 1. 有哪些服務監聽在 `0.0.0.0` 或 `*`（對所有介面開放）？
> 2. 有哪些只監聽 `127.0.0.1`？
> 3. **每一個對外監聽的服務，你都知道它為什麼要對外嗎？**
> 4. 有沒有你不認識的服務？
>
> 第 3、4 題如果答不出來，那就是攻擊面的問題。

> [!question]- 練習 2：SSH 隧道實作
> 假設遠端伺服器上有 MySQL 只監聽 `127.0.0.1:3306`。
> ```bash
> # 建立隧道
> ssh -L 13306:localhost:3306 user@伺服器
>
> # 另一個終端機
> mysql -h 127.0.0.1 -P 13306 -u root -p
> # 或用 nc 測試
> nc -zv 127.0.0.1 13306
> ```
> 想想：
> 1. 這樣做的流量走哪個埠出去？（答：22）
> 2. MySQL 需要對外開放嗎？（答：完全不用）
> 3. 這比開埠轉發安全在哪裡？

> [!question]- 練習 3：埠號記憶測驗
> 不查表，說出下列服務的預設埠：
> SSH、HTTP、HTTPS、DNS、MySQL、PostgreSQL、RDP、SMB、Redis、NTP
>
> 然後反過來，說出這些埠是什麼服務：
> 22、25、53、143、445、587、993、3389、6379、8080
>
> 參考答案：
> SSH=22、HTTP=80、HTTPS=443、DNS=53、MySQL=3306、
> PostgreSQL=5432、RDP=3389、SMB=445、Redis=6379、NTP=123
>
> 22=SSH、25=SMTP、53=DNS、143=IMAP、445=SMB、
> 587=Submission(寄信)、993=IMAPS、3389=RDP、6379=Redis、8080=HTTP替代

## 小測驗

Q1. 用「大樓門牌 + 房號」的比喻說明 IP 與埠號的關係。「socket」指的是什麼？

Q2. 埠號的三個範圍是什麼？為什麼 1024 以下需要 root 才能綁定？

Q3. 你用瀏覽器連網站時，你這一端的埠號是固定的還是隨機的？為什麼需要它？

Q4. DNS 為什麼要同時開放 TCP 53 與 UDP 53？

Q5. FTP、SFTP、FTPS 的差別是什麼？為什麼建議用 SFTP？

Q6. 「FTP 能登入但列不出目錄」的經典原因是什麼？怎麼解決？

Q7. SSH 隧道（`-L`）在做什麼？它比埠轉發安全在哪裡？

Q8. WebSocket 解決了 HTTP 的什麼問題？反向代理要加什麼設定才能支援它？

Q9. 請列出至少六個「絕對不該對外開放」的埠，並說明各自的風險。

Q10. 把 SSH 從 22 改到 2222 算不算安全措施？它的實際效果是什麼？真正的 SSH 防護有哪些？

> [!question]- 測驗答案
> **Q1.** **IP 位址是「大樓地址」**（信義路五段 7 號），
> **埠號是「房號」**（12 樓 A 室）。
> 一台機器只有一個 IP，但可以同時跑很多服務，靠埠號區分該交給哪個程式。
> **「socket」就是「IP 位址 + 埠號」的組合**，
> 例如 `203.0.113.5:443`，它能精確定位到某一個服務。
>
> **Q2.** ①**0～1023 知名埠**（標準服務）；②1024～49151 註冊埠；
> ③**49152～65535 動態／臨時埠**（客戶端使用）。
> 1024 以下需要 root 是 Unix 的傳統安全設計，
> **防止一般使用者冒充系統服務** ——
> 若任何人都能綁 80 埠，就能在伺服器上架假網站釣魚。
>
> **Q3.** **隨機的**（從臨時埠範圍分配，如 32768～60999）。
> 需要它是因為**回應封包回來時，作業系統要知道該交給哪一個程式／哪一個分頁** ——
> 你可能同時開了 20 個分頁連到同一個網站，靠不同的來源埠區分。
>
> **Q4.** 因為 **DNS 平常用 UDP**（一問一答，成本低），
> 但在**回應太大**（超過 512 位元組或協商的 EDNS 大小）、
> **區域轉送（AXFR/IXFR）**、DNS over TLS 時會**改用 TCP**。
> 只開 UDP 的話，大回應的查詢就會失敗，症狀是「有時通有時不通」。
>
> **Q5.** **FTP（21+20）完全明文**，帳密與檔案內容都能被監聽；
> **SFTP（22）走 SSH**，全程加密且**只需單一埠**，NAT 友善；
> **FTPS（990 或 21+TLS）**是 FTP 加上 TLS 加密，但仍有資料埠的問題。
> **建議 SFTP**，因為它加密、單一埠、NAT 友善，而且維運人員本來就會用 SSH。
>
> **Q6.** 因為使用了 **FTP 的主動模式（Active Mode）** ——
> 資料連線是**伺服器主動連回客戶端**的，
> 而客戶端在 NAT 後面，伺服器根本連不進來。
> **解法**：改用**被動模式（Passive Mode）**（現代客戶端預設），
> 或直接改用 **SFTP**。
>
> **Q7.** `ssh -L 本機埠:localhost:遠端埠 user@host`
> 把**遠端主機上的某個服務映射到你的本機埠**上。
> 比埠轉發安全在於：
> ①該服務**完全不需要對外開放**（可以只監聽 127.0.0.1）；
> ②流量**走 SSH 全程加密**；
> ③**有 SSH 的身分驗證（金鑰）把關**，而埠轉發是直接把服務暴露給全世界。
>
> **Q8.** HTTP 是**請求-回應**模型，**伺服器不能主動推送**給客戶端，
> 只能靠客戶端不斷輪詢（polling），浪費頻寬又有延遲。
> **WebSocket 提供全雙工的持久連線**，只需一次交握，
> 伺服器可以主動推播（聊天室、即時報價、通知）。
> 反向代理需加上：
> ```nginx
> proxy_http_version 1.1;
> proxy_set_header Upgrade $http_upgrade;
> proxy_set_header Connection "upgrade";
> ```
>
> **Q9.** 任六個：
> **23 Telnet**（完全明文）、**445 SMB**（勒索軟體橫向擴散主要途徑）、
> **3389 RDP**（全世界機器人都在掃、暴力破解）、
> **3306 MySQL / 5432 PostgreSQL**（直接存取所有資料）、
> **6379 Redis**（**預設無密碼**，大量挖礦植入事件）、
> **27017 MongoDB**（預設無驗證，數萬資料庫曾被公開）、
> **5900 VNC**（常無密碼或弱密碼）、
> **11211 Memcached**（反射放大攻擊來源）、
> **2375 Docker API**（**開放等於給了 root 權限**）。
>
> **Q10.** **不算安全措施，只能算「減少雜訊」。**
> **實際效果**：日誌會乾淨很多、大幅減少自動化掃描的騷擾
> （機器人主要掃預設埠），但**擋不住針對性攻擊** ——
> `nmap -p-` 全埠掃描幾分鐘就找到了。
> 這叫 security through obscurity（隱晦式安全）。
> **真正的 SSH 防護**：①**停用密碼登入改用金鑰**；
> ②**停用 root 直接登入**；③安裝 **Fail2ban** 自動封鎖；
> ④防火牆**限制來源 IP**；⑤啟用 **MFA**。
