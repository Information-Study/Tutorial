## 四種方式的比較 ★★

| | **Git hook** | **★★ GitHub Actions（雲端 runner）** | **★★★ self-hosted runner** | **Deployer** |
| --- | --- | --- | --- | --- |
| 設定複雜度 | ★ 最簡單 | 中 | ★★ 中高 | 中 |
| **需要對外網路** | ✗ | **★★ 需要**（runner 要連進來） | **✗ 只要連得出去** | ✗ |
| 建置在哪 | **伺服器上** | 雲端 | **★ 內網的 runner** | 本機或 CI |
| **適合機關內網** | ✓ | **✗✗ 通常不行** | **★★★ 最適合** | ✓ |
| 測試與品質檢查 | ✗ | ✓ | ✓ | 部分 |
| 核准流程 | ✗ | **✓ Environments** | ✓ | ✗ |
| 多台部署 | ✗ | ✓ | ✓ | **✓ 內建** |
| 稽核記錄 | 弱 | **✓ 完整** | ✓ | 中 |
| **推薦度** | ★ 小專案 | ★ 有公網 IP 時 | **★★★ 機關內網** | ★★ PHP 專案 |

> [!danger] 機關內網的關鍵限制 ★★★
> ```
> ★★★ GitHub 的雲端 runner 需要「從外部連進你的伺服器」
>   → 機關的伺服器通常【沒有公網 IP】
>   → 或防火牆【不允許外部 SSH】
>
> ★★ 三種可行的方案：
>   ① ★★★ self-hosted runner（★ 推薦）
>      → runner 裝在【內網的機器】上
>      → ★ 它主動【連出去】向 GitHub 拉工作
>        → 防火牆只要允許【出向】的 443
>      → ★★ 完全不需要開放任何入向的埠
>
>   ② ★★ 內部的 GitLab CE / Gitea + 內部 runner
>      → 完全不依賴外部服務
>      → ★ 適合完全封閉的環境
>
>   ③ ★ Git hook（最簡單）
>      → 推到伺服器上的 bare repo 就觸發部署
>      → ★ 但沒有測試與核准流程
> ```

## ★★★ GitHub Actions（self-hosted runner）

### 安裝 runner

```bash
#!/usr/bin/env bash
# ★★ 在【內網的建置機】上安裝 GitHub Actions runner
# ★ 不要裝在正式的 web 伺服器上（★ 隔離建置環境）
set -euo pipefail

RUNNER_USER=runner
RUNNER_DIR=/opt/actions-runner
REPO_URL="https://github.com/Information-Study/crm-api"

# ═══ ★ 專用使用者 ═══
sudo useradd -m -s /bin/bash "$RUNNER_USER" 2>/dev/null || true
sudo mkdir -p "$RUNNER_DIR"
sudo chown "$RUNNER_USER:$RUNNER_USER" "$RUNNER_DIR"

# ═══ 下載 ═══
cd "$RUNNER_DIR"
VER=$(curl -s https://api.github.com/repos/actions/runner/releases/latest | jq -r .tag_name | tr -d v)
sudo -u "$RUNNER_USER" curl -fsSL -o actions-runner.tar.gz \
    "https://github.com/actions/runner/releases/download/v${VER}/actions-runner-linux-x64-${VER}.tar.gz"
sudo -u "$RUNNER_USER" tar xzf actions-runner.tar.gz && rm -f actions-runner.tar.gz

# ═══ ★★ 註冊（token 從 GitHub repo → Settings → Actions → Runners 取得）═══
echo "★★ 到 $REPO_URL/settings/actions/runners/new 取得註冊 token"
read -rsp "  Registration token: " TOKEN; echo

sudo -u "$RUNNER_USER" ./config.sh \
    --url "$REPO_URL" \
    --token "$TOKEN" \
    --name "internal-builder-$(hostname)" \
    --labels self-hosted,linux,x64,internal,php83,node22 \
    --work _work \
    --unattended \
    --replace

# ═══ ★★ 裝成 systemd 服務 ═══
sudo ./svc.sh install "$RUNNER_USER"
sudo ./svc.sh start
sudo ./svc.sh status

# ═══ ★★ 建置環境 ═══
sudo apt update
sudo apt install -y php8.3-{cli,mysql,mbstring,xml,curl,zip,bcmath,gd,intl} \
                    nodejs npm git jq rsync
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
sudo php -r "copy('https://getcomposer.org/installer','/tmp/c.php');" && \
  sudo php /tmp/c.php --install-dir=/usr/local/bin --filename=composer && rm /tmp/c.php

# ═══ ★★★ runner 到部署目標的 SSH 金鑰 ═══
sudo -u "$RUNNER_USER" ssh-keygen -t ed25519 \
    -f "/home/$RUNNER_USER/.ssh/id_ed25519_deploy" -N '' -C "runner@$(hostname)"
echo "★★ 把這把公鑰加到目標伺服器的 deploy 使用者："
sudo cat "/home/$RUNNER_USER/.ssh/id_ed25519_deploy.pub"

# ★★ known_hosts（★ 不要用 StrictHostKeyChecking=no）
read -rp "  部署目標的主機名或 IP: " TARGET
sudo -u "$RUNNER_USER" ssh-keyscan -t ed25519 "$TARGET" | \
    sudo -u "$RUNNER_USER" tee -a "/home/$RUNNER_USER/.ssh/known_hosts"

echo "✓ runner 安裝完成"
```

> [!danger] self-hosted runner 的安全風險 ★★★
> ```
> ★★★ runner 會【執行 repo 中的任意程式碼】
>   → 任何能推送到觸發分支的人 = 能在 runner 上執行指令
>
> ★★ 必要的防護：
>   ① ★★★ 【絕對不要】在公開的 repo 上用 self-hosted runner
>      → 任何人送 PR 就能執行程式碼
>      → ★ 私有 repo 才安全
>
>   ② ★★ runner 用【專用的低權限使用者】
>      → 不要用 root
>      → ★ 不要給它 sudo（除非必要且限制指令）
>
>   ③ ★★★ runner 【不要裝在正式的 web 伺服器上】
>      → 用一台獨立的建置機
>      → ★ 被入侵時不影響正式服務
>
>   ④ ★★ 限制 workflow 的觸發條件
>      → 只在 main / tag 觸發
>      → ★ pull_request 不要用 self-hosted runner
>
>   ⑤ ★ 定期清理 _work 目錄
>      → 避免累積敏感資料
> ```

```yaml
# ★★ .github/workflows/ 的安全設定
on:
  push:
    branches: [main]              # ★★ 只有 main
    tags: ['v*']
  workflow_dispatch:              # ★ 手動觸發
  # ★★★ 不要用 pull_request（★ 外部的 PR 會執行程式碼）

permissions:
  contents: read                  # ★★ 最小權限
```

### ★★★ 完整的 pipeline

```yaml
# .github/workflows/deploy.yml
name: 建置與部署

on:
  push:
    tags: ['v*']
  workflow_dispatch:
    inputs:
      environment:
        description: '部署環境'
        required: true
        default: staging
        type: choice
        options: [staging, production]
      skip_migrate:
        description: '跳過資料庫遷移'
        type: boolean
        default: false

concurrency:
  group: deploy-${{ github.event.inputs.environment || 'production' }}
  cancel-in-progress: false        # ★★ 部署不能被取消

permissions:
  contents: read

env:
  PHP_VERSION: '8.3'
  NODE_VERSION: '22'

jobs:
  # ═══════════════════════════════════════════
  # ★★ 【1】品質檢查
  # ═══════════════════════════════════════════
  quality:
    name: 品質檢查
    runs-on: [self-hosted, linux, internal]
    steps:
      - uses: actions/checkout@v4

      - name: 快取 composer
        uses: actions/cache@v4
        with:
          path: vendor
          key: composer-${{ hashFiles('composer.lock') }}
          restore-keys: composer-

      - name: 安裝相依（含 dev）
        run: composer install --no-interaction --prefer-dist --no-progress

      # ═══ ★★★ 安全掃描 ═══
      - name: 掃描 config/ 外的 env()
        run: |
          if grep -rn "env(" app/ routes/ database/ --include='*.php' | grep -v config/; then
            echo "::error::★★★ config/ 以外使用了 env()（config:cache 後會是 null）"
            exit 1
          fi
          echo "✓ 沒有不當的 env() 使用"

      - name: 掃描危險函式
        run: |
          if grep -rn --include='*.php' -E '\b(eval|exec|shell_exec|system|passthru|proc_open)\s*\(' app/; then
            echo "::error::★★★★ 發現危險函式"
            exit 1
          fi
          echo "✓ 沒有危險函式"

      - name: 掃描 mass assignment 風險
        run: |
          if grep -rn 'protected \$guarded = \[\]' app/Models/; then
            echo "::error::★★★ 發現 \$guarded = []（mass assignment 風險）"
            exit 1
          fi
          echo "✓ Model 有正確的 fillable/guarded"

      - name: composer audit
        run: composer audit --no-interaction

      # ═══ 靜態分析 ═══
      - name: Pint（程式碼風格）
        run: ./vendor/bin/pint --test

      - name: PHPStan
        run: ./vendor/bin/phpstan analyse --memory-limit=2G --no-progress

      # ═══ 測試 ═══
      - name: 測試
        env:
          DB_CONNECTION: sqlite
          DB_DATABASE: ':memory:'
          CACHE_STORE: array
          SESSION_DRIVER: array
          QUEUE_CONNECTION: sync
        run: |
          cp .env.example .env
          php artisan key:generate
          php artisan test --parallel

  # ═══════════════════════════════════════════
  # ★★ 【2】建置
  # ═══════════════════════════════════════════
  build:
    name: 建置
    needs: quality
    runs-on: [self-hosted, linux, internal]
    outputs:
      artifact: ${{ steps.pack.outputs.name }}
    steps:
      - uses: actions/checkout@v4

      - name: 後端相依（★ --no-dev）
        run: |
          rm -rf vendor
          composer install --no-dev --optimize-autoloader \
            --no-interaction --prefer-dist --no-progress

      - name: 快取 npm
        uses: actions/cache@v4
        with:
          path: ~/.npm
          key: npm-${{ hashFiles('package-lock.json') }}

      - name: 前端建置
        run: |
          npm ci --no-audit --no-fund
          npm run build

      # ═══ ★★★ 秘密掃描 ═══
      - name: 掃描建置產物的秘密
        run: |
          PAT='sk_live_[0-9a-zA-Z]{24,}|AKIA[0-9A-Z]{16}|gh[pousr]_[A-Za-z0-9]{36}|-----BEGIN (RSA |EC )?PRIVATE KEY'
          for d in public/build dist; do
            [ -d "$d" ] || continue
            if grep -rlEI "$PAT" "$d"; then
              echo "::error::★★★★ 建置產物中發現秘密"
              exit 1
            fi
          done
          find public/build dist -name '*.map' -delete 2>/dev/null || true
          echo "✓ 秘密掃描通過"

      - name: 打包
        id: pack
        run: |
          NAME="release-${GITHUB_SHA::7}-$(date +%Y%m%d%H%M%S)"
          echo "$GITHUB_SHA" > VERSION
          tar czf "$NAME.tar.gz" \
            --exclude='.git' --exclude='.github' \
            --exclude='node_modules' --exclude='tests' \
            --exclude='.env' --exclude='auth.json' \
            --exclude='storage/logs/*' --exclude='storage/framework/cache/*' \
            .
          echo "name=$NAME" >> "$GITHUB_OUTPUT"
          ls -lh "$NAME.tar.gz"

      - uses: actions/upload-artifact@v4
        with:
          name: ${{ steps.pack.outputs.name }}
          path: ${{ steps.pack.outputs.name }}.tar.gz
          retention-days: 30

  # ═══════════════════════════════════════════
  # ★★★ 【3】部署（★ 需要人工核准）
  # ═══════════════════════════════════════════
  deploy:
    name: 部署到 ${{ github.event.inputs.environment || 'production' }}
    needs: build
    runs-on: [self-hosted, linux, internal]
    environment:
      name: ${{ github.event.inputs.environment || 'production' }}
      url: ${{ vars.SITE_URL }}
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: ${{ needs.build.outputs.artifact }}

      - name: 設定 SSH
        run: |
          mkdir -p ~/.ssh && chmod 700 ~/.ssh
          echo "${{ secrets.DEPLOY_SSH_KEY }}" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          # ★★★ 用 known_hosts 防中間人（★ 不要用 StrictHostKeyChecking=no）
          echo "${{ secrets.DEPLOY_KNOWN_HOSTS }}" > ~/.ssh/known_hosts
          chmod 644 ~/.ssh/known_hosts

      - name: 上傳
        env:
          H: ${{ secrets.DEPLOY_HOST }}
          U: ${{ secrets.DEPLOY_USER }}
          A: ${{ needs.build.outputs.artifact }}
        run: |
          scp -i ~/.ssh/deploy_key "$A.tar.gz" "$U@$H:/tmp/"
          echo "✓ 已上傳 $A.tar.gz"

      - name: 部署
        id: deploy
        env:
          H: ${{ secrets.DEPLOY_HOST }}
          U: ${{ secrets.DEPLOY_USER }}
          A: ${{ needs.build.outputs.artifact }}
          SITE: ${{ vars.SITE_URL }}
          SKIP_MIGRATE: ${{ github.event.inputs.skip_migrate }}
        run: |
          ssh -i ~/.ssh/deploy_key "$U@$H" \
            "ARTIFACT='$A' SITE='$SITE' SKIP_MIGRATE='$SKIP_MIGRATE' bash -s" <<'REMOTE'
          set -euo pipefail
          APP=/var/www/crm-api
          TS=$(date +%Y%m%d-%H%M%S)
          REL="$APP/releases/$TS"
          PHP_V=8.3

          # ═══ 前置檢查 ═══
          grep -q '^APP_DEBUG=false' "$APP/shared/.env" || { echo "✗✗ APP_DEBUG"; exit 1; }

          # ═══ ★★ 資料庫備份 ═══
          if [ "$SKIP_MIGRATE" != "true" ]; then
              DB_N=$(grep '^DB_DATABASE=' "$APP/shared/.env"|cut -d= -f2-)
              DB_U=$(grep '^DB_USERNAME=' "$APP/shared/.env"|cut -d= -f2-)
              DB_P=$(grep '^DB_PASSWORD=' "$APP/shared/.env"|cut -d= -f2-)
              mkdir -p /backup/db
              MYSQL_PWD="$DB_P" mysqldump -h 127.0.0.1 -u "$DB_U" --single-transaction \
                --routines --triggers --no-tablespaces "$DB_N" | gzip > "/backup/db/$DB_N-$TS.sql.gz"
              echo "  ✓ 資料庫已備份"
          fi

          # ═══ 解壓 ═══
          mkdir -p "$REL"
          tar xzf "/tmp/$ARTIFACT.tar.gz" -C "$REL"
          rm -f "/tmp/$ARTIFACT.tar.gz"

          # ═══ 連結 shared ═══
          ln -sfn "$APP/shared/.env" "$REL/.env"
          rm -rf "$REL/storage" && ln -sfn "$APP/shared/storage" "$REL/storage"

          cd "$REL"

          # ═══ 遷移與最佳化 ═══
          [ "$SKIP_MIGRATE" = "true" ] || php artisan migrate --force --no-interaction
          php artisan optimize
          php artisan filament:assets 2>/dev/null || true
          php artisan filament:optimize 2>/dev/null || true
          php artisan storage:link 2>/dev/null || true

          # ═══ 權限 ═══
          find "$REL" -type d -exec chmod 750 {} \;
          find "$REL" -type f -exec chmod 640 {} \;
          chmod 755 "$REL/artisan"
          chmod -R 770 "$REL/bootstrap/cache" "$APP/shared/storage"
          chmod -R o+rX "$REL/public"

          # ═══ ★★ 煙霧測試 ═══
          php "$REL/artisan" --version >/dev/null || { echo "✗✗ artisan 失敗"; exit 1; }
          php "$REL/artisan" db:show >/dev/null || { echo "✗✗ DB 連不上"; exit 1; }
          [ -f "$REL/bootstrap/cache/config.php" ] || { echo "✗✗ 快取失敗"; exit 1; }
          echo "  ✓ 煙霧測試通過"

          # ═══ ★★★ 原子切換 ═══
          PREV=$(readlink "$APP/current" 2>/dev/null || echo "")
          ln -sfn "$REL" "$APP/current.tmp" && mv -Tf "$APP/current.tmp" "$APP/current"
          echo "  ✓ 已切換：$(basename "${PREV:-無}") → $TS"

          # ═══ ★★★ 重載 ═══
          sudo systemctl reload "php$PHP_V-fpm"
          sudo nginx -t && sudo systemctl reload nginx
          php "$APP/current/artisan" queue:restart 2>/dev/null || true
          sleep 3
          sudo supervisorctl restart laravel-workers: 2>/dev/null || true

          # ═══ ★★★ 驗證 ═══
          sleep 3
          FAIL=0
          for i in 1 2 3; do
              C=$(curl -sko /dev/null -w '%{http_code}' --max-time 20 "$SITE/api/health/live")
              [ "$C" = 200 ] || FAIL=$((FAIL+1))
              sleep 2
          done
          curl -sk "$SITE/api/health/live" | grep -q '"status"' || FAIL=$((FAIL+1))
          [ "$(curl -sko /dev/null -w '%{http_code}' "$SITE/.env")" = 200 ] && FAIL=$((FAIL+1))

          if [ "$FAIL" -gt 0 ]; then
              echo "✗✗ 驗證失敗（$FAIL）—— 回退"
              tail -25 "$APP/shared/storage/logs/laravel-$(date +%Y-%m-%d).log" 2>/dev/null || true
              [ -n "$PREV" ] && { ln -sfn "$PREV" "$APP/current.tmp"; mv -Tf "$APP/current.tmp" "$APP/current"; }
              sudo systemctl reload "php$PHP_V-fpm"
              php "$APP/current/artisan" queue:restart 2>/dev/null || true
              sudo supervisorctl restart laravel-workers: 2>/dev/null || true
              exit 1
          fi

          # ═══ 清理 ═══
          (cd "$APP/releases" && ls -1dt */ | tail -n +6 | xargs -r rm -rf)
          echo "  ✓ 部署完成：$TS"
          echo "$(date -Is)|$ARTIFACT|$TS" >> "$APP/shared/deploy.log"
          REMOTE

      # ═══ ★★ 部署後的完整驗證 ═══
      - name: 部署後驗證
        env:
          SITE: ${{ vars.SITE_URL }}
        run: |
          FAIL=0
          t(){ printf '%-40s ' "$1"
               C=$(curl -sko /dev/null -w '%{http_code}' --max-time 15 "$SITE$2")
               [ "$C" = "$3" ] && echo "✓ ($C)" || { echo "✗ ($C≠$3)"; FAIL=1; }; }
          t "首頁"              /                       200
          t "★★ API 健康檢查"    /api/health/live        200
          t "★★★ .env 擋住"      /.env                   404
          t "★★★★ PathInfo"      /storage/x.jpg/y.php    404
          t "★★ 未認證 401"      /api/user               401
          exit $FAIL

      # ═══ 通知 ═══
      - name: 通知（成功）
        if: success()
        run: |
          curl -sf -X POST "${{ secrets.NOTIFY_WEBHOOK }}" \
            -H 'Content-Type: application/json' \
            -d "$(jq -n \
              --arg t "✅ 部署成功" \
              --arg r "$GITHUB_REPOSITORY" \
              --arg s "${GITHUB_SHA::7}" \
              --arg a "$GITHUB_ACTOR" \
              --arg e "${{ github.event.inputs.environment || 'production' }}" \
              --arg u "${{ vars.SITE_URL }}" \
              '{text: "\($t)\nrepo: \($r)\ncommit: \($s)\n環境: \($e)\n觸發者: \($a)\n\($u)"}')" \
            || true

      - name: 通知（失敗）
        if: failure()
        run: |
          curl -sf -X POST "${{ secrets.NOTIFY_WEBHOOK }}" \
            -H 'Content-Type: application/json' \
            -d "$(jq -n \
              --arg s "${GITHUB_SHA::7}" \
              --arg a "$GITHUB_ACTOR" \
              --arg l "$GITHUB_SERVER_URL/$GITHUB_REPOSITORY/actions/runs/$GITHUB_RUN_ID" \
              '{text: "❌ 部署失敗（已自動回退）\ncommit: \($s)\n觸發者: \($a)\n日誌: \($l)"}')" \
            || true
```

### ★★ Environments 的核准設定

```
★★★ GitHub repo → Settings → Environments → New environment

  名稱：production

  ★★ Deployment protection rules
    ☑ Required reviewers        → ★ 指定核准的人（1~2 人）
    ☑ Wait timer               → ★ 可選，例如 5 分鐘
    ☑ Deployment branches      → ★★ 只允許 main 與 tag

  ★★ Environment secrets（★ 只有這個環境的 job 讀得到）
    DEPLOY_SSH_KEY
    DEPLOY_HOST
    DEPLOY_USER
    DEPLOY_KNOWN_HOSTS
    NOTIFY_WEBHOOK

  ★ Environment variables（非機密）
    SITE_URL = https://crm.internal.example.gov.tw
```

> [!tip] Environments 的價值 ★★
> ```
> ★★ 三個好處：
>   ① 【人工核准】—— 部署到 production 前要有人按核准
>      → ★ 避免誤觸發、避免半夜的意外部署
>
>   ② ★★ 【秘密隔離】—— staging 與 production 的秘密分開

## 部署通知 ★

```bash
#!/usr/bin/env bash
# /usr/local/bin/notify-deploy —— 部署通知（★ 支援多種管道）
set -uo pipefail
STATUS="${1:?}"      # success | failure | rollback
COMMIT="${2:-unknown}"
ENV="${3:-production}"
ACTOR="${4:-${SUDO_USER:-$USER}}"
DETAIL="${5:-}"

case "$STATUS" in
  success)  ICON="✅"; TITLE="部署成功" ;;
  failure)  ICON="❌"; TITLE="部署失敗" ;;
  rollback) ICON="⏪"; TITLE="已回退" ;;
  *)        ICON="ℹ️"; TITLE="$STATUS" ;;
esac

MSG="$ICON $TITLE
環境：$ENV
版本：$COMMIT
觸發：$ACTOR
時間：$(date '+%Y-%m-%d %H:%M:%S')"
[ -n "$DETAIL" ] && MSG="$MSG
$DETAIL"

# ═══ ① Webhook（Teams / Slack / Discord / n8n）═══
if [ -n "${NOTIFY_WEBHOOK:-}" ]; then
    curl -sf -X POST "$NOTIFY_WEBHOOK" \
      -H 'Content-Type: application/json' \
      -d "$(jq -n --arg t "$MSG" '{text: $t}')" >/dev/null || \
      echo "⚠ webhook 通知失敗"
fi

# ═══ ② Email ═══
if [ -n "${NOTIFY_EMAIL:-}" ] && command -v mail >/dev/null; then
    echo "$MSG" | mail -s "$ICON $TITLE - $ENV" "$NOTIFY_EMAIL" || true
fi

# ═══ ③ 系統日誌（★ 稽核用）═══
logger -t deploy -p local0.info "$STATUS env=$ENV commit=$COMMIT actor=$ACTOR"

# ═══ ④ 本機記錄 ═══
echo "$(date -Is)|$STATUS|$ENV|$COMMIT|$ACTOR|$DETAIL" >> /var/log/deploy-history.log

echo "$MSG"

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| **runner 連不上 GitHub** ★★ | 防火牆擋出向 443 | 允許出向到 `*.github.com` |
| **SSH 連線失敗** ★★★ | `known_hosts` 沒設 | `ssh-keyscan` 放進 Secrets |
| **`sudo: no tty present`** ★★ | 需要密碼 | sudoers 設 `NOPASSWD` |
| **Permission denied（部署）** ★★ | 使用者或權限 | 確認 deploy 使用者的權限 |

| **秘密出現在日誌** ★★★★ | 直接 `echo $SECRET` | GitHub 會遮蔽已知的 secret，**但不要故意印** |
| **同時兩個部署** ★★ | 沒有 concurrency | `concurrency: { group: deploy }` |
| **測試環境的 secret 洩漏到正式** ★★ | 共用 Secrets | 用 **Environment secrets** |
| runner 磁碟滿 ★ | `_work` 累積 | 定期清理；`actions/checkout` 的 clean |
| **公開 repo 用 self-hosted** ★★★★ | 任何人的 PR 都能執行程式碼 | **只在私有 repo 用** |

★★★ self-hosted runner  ★ 機關內網的最佳選擇（只要出向 443）
Deployer                ★★ PHP 專案，多台部署方便
```

### self-hosted runner ★★★

```bash
# ★ 安裝在【獨立的建置機】上（不是正式伺服器）
./config.sh --url REPO --token TOKEN --labels self-hosted,internal
sudo ./svc.sh install runner && sudo ./svc.sh start
```

```
★★★ 五個安全要點：
  ① 只在私有 repo 用
  ② 專用的低權限使用者
  ③ 獨立的建置機
  ④ 只在 main / tag 觸發（不用 pull_request）
  ⑤ 定期清理 _work
```

### GitHub Actions pipeline

```
① quality  → env() 掃描 / 危險函式 / guarded / audit / pint / phpstan / test
② build    → composer --no-dev / npm ci + build / ★★ 秘密掃描 / 打包
③ deploy   → ★★ Environment 核准 → scp → 遠端部署 → ★★★ 驗證 → 失敗回退
```

```yaml
concurrency: { group: deploy-production, cancel-in-progress: false }
permissions: { contents: read }
environment: { name: production }        # ★★ 核准 + 秘密隔離
```

### Deployer

```php
before('deploy:symlink', 'smoke:test');   # ★★★ 切換前煙霧測試
after('deploy:symlink', 'reload:services');
after('reload:services', 'verify');
fail('verify', 'rollback');               # ★★ 驗證失敗自動回退
```
```bash
dep deploy production / dep rollback production
```

### ★★★ 四條紅線

```
① 公開 repo 絕不用 self-hosted runner
② 不用 StrictHostKeyChecking=no（用 known_hosts）
③ deploy 不給 NOPASSWD: ALL（只給 reload）
④ 秘密用 Environment secrets，不進 workflow
```

## 小測驗

Q1. **機關內網為什麼通常不能用 GitHub 的雲端 runner**？

Q2. **self-hosted runner 為什麼「只要出向 443」就能運作**？

Q3. **公開 repo 用 self-hosted runner 有什麼風險**？

Q4. **GitHub Environments 有哪三個價值**？

Q5. **為什麼不能用 `StrictHostKeyChecking=no`**？

Q6. **部署使用者的 sudoers 該怎麼設**？

Q7. **CI 的品質檢查應該包含哪些安全掃描**？

Q8. **煙霧測試在 pipeline 中該放在哪一步**？

Q9. **Deployer 的優缺點**？

Q10. **部署的稽核記錄該包含什麼**？

> [!question]- 測驗答案
> **Q1.** 因為 **GitHub 的雲端 runner 執行在 GitHub 的機器上，
> 部署時需要「從外部 SSH 連進你的伺服器」**。
> **機關的伺服器通常**：
> ①**沒有公網 IP**（在內網或 NAT 後面）；
> ②**防火牆不允許外部的 SSH 連線**（這是正確的安全設定）；
> ③即使開放，也會被資安單位質疑（**對外開放 SSH 是高風險**）。
> **三種可行的替代方案**：
> ①**★★★ self-hosted runner**（推薦）；
> ②內部的 **GitLab CE / Gitea + 內部 runner**（完全不依賴外部服務）；
> ③**Git hook**（最簡單，但沒有測試與核准）。
>
> **Q2.** 因為 **runner 是「主動連出去向 GitHub 拉工作」的（long polling）**，
> 而不是「GitHub 主動連進來」。
> **流程**：
> runner 啟動後**維持一個到 GitHub 的出向 HTTPS 連線**，
> 定期詢問「有沒有我的工作」→ 有的話就下載 workflow 定義並執行 →
> 執行結果與日誌**主動回傳**給 GitHub。
> **所以防火牆只要允許「出向的 443 到 `*.github.com`」** ——
> **完全不需要開放任何入向的埠**，
> 這對機關的資安要求來說是關鍵優勢。
> 而且 runner 裝在內網，**部署目標也在內網**，SSH 連線完全不經過外網。
>
> **Q3.** **★★★★ 任何人送一個 Pull Request 就能在你的內網機器上執行任意程式碼**。
> **攻擊流程**：
> 攻擊者 fork 你的公開 repo → 修改 workflow 或加一個惡意的測試 →
> 送 PR → **如果 workflow 設定為 `on: pull_request` 且用 self-hosted runner**，
> 那段程式碼就會**在你的內網機器上執行** →
> 可以掃描內網、竊取 SSH 金鑰、橫向移動。
> **防護**：
> ①**★★★★ 只在私有 repo 使用 self-hosted runner**；
> ②**不要用 `on: pull_request` 觸發 self-hosted 的 job**
> （只用 `push` 到 main / tag，或 `workflow_dispatch`）；
> ③runner 用**專用的低權限使用者**、裝在**獨立的建置機**上。
>
> **Q4.** ①**★★ 人工核准**（Required reviewers）——
> 部署到 production 前要有指定的人按核准，
> **避免誤觸發、避免半夜的意外部署**；
> ②**★★ 秘密隔離**（Environment secrets）——
> staging 與 production 的秘密**分開儲存**，
> staging 的 workflow **拿不到 production 的金鑰**；
> ③**★★ 完整的稽核記錄** ——
> 誰在什麼時候部署了什麼版本、誰核准的，
> **機關的稽核要求通常需要這個**。
> 另外還可以設 **Deployment branches**（只允許 main 與 tag 部署）
> 與 **Wait timer**（強制等待幾分鐘，給人反悔的機會）。
>
> **Q5.** 因為 **`StrictHostKeyChecking=no` 等於「接受任何主機的金鑰」** ——
> SSH 就無法偵測**中間人攻擊**。
> **攻擊情境**：攻擊者用 ARP spoofing 或 DNS 汙染
> 把 CI 的 SSH 連線導向自己的機器 →
> `StrictHostKeyChecking=no` 讓連線直接建立 →
> **攻擊者取得 CI 的部署金鑰，並拿到完整的部署產物**（可能含敏感設定）。
> **正確做法**：
> ```bash
> ssh-keyscan -t ed25519 crm.internal.example.gov.tw   # ★ 產生
> # → 放進 GitHub Secrets 的 DEPLOY_KNOWN_HOSTS
> echo "${{ secrets.DEPLOY_KNOWN_HOSTS }}" > ~/.ssh/known_hosts
> ```
> 並且**在伺服器上用 `ssh-keygen -lf` 核對指紋**。
>
> **Q6.** **只給「部署真正需要的指令」，而且是精確到參數的**：
> ```
> deploy ALL=(root) NOPASSWD: /bin/systemctl reload php8.3-fpm
> deploy ALL=(root) NOPASSWD: /bin/systemctl reload nginx
> deploy ALL=(root) NOPASSWD: /usr/sbin/nginx -t
> deploy ALL=(root) NOPASSWD: /usr/bin/supervisorctl restart laravel-workers\:*
> ```
> **注意是 `reload` 不是 `restart`**（reload 是零停機的，而且權限更小）。
> **★★★ 絕對不要 `deploy ALL=(ALL) NOPASSWD: ALL`** ——
> **CI 的金鑰一旦外洩，攻擊者就等於拿到 root**。
> **驗證**：
> ```bash
> sudo -u deploy sudo -l                    # ★ 看實際的權限
> sudo -u deploy sudo cat /etc/shadow       # ★★ 應該被拒絕
> ```
>
> **Q7.** **五類掃描**：
> ①**★★★ `config/` 外的 `env()` 使用** ——
> `grep -rn "env(" app/ routes/ | grep -v config/`（`config:cache` 後會是 null）；
> ②**★★★★ 危險函式** —— `eval`、`exec`、`shell_exec`、`system`、`proc_open`；
> ③**★★★ mass assignment** —— `protected $guarded = []`；
> ④**★★ 依賴弱點** —— `composer audit` 與 `npm audit`；
> ⑤**★★★★ 建置產物的秘密** ——
> `sk_live_`、`AKIA`、`-----BEGIN PRIVATE KEY` 等 pattern
> （**這一項在 build 階段做，發現就中止部署**）。
> 加上**靜態分析**（PHPStan）、**程式碼風格**（Pint）與**自動測試**。
> **每一項失敗都應該讓 CI 中止**，而不是只警告。
>
> **Q8.** **★★★ 放在「原子切換之前」**。
> 因為煙霧測試是在**新的 release 目錄**上執行的，
> 此時符號連結還指著舊版本，**網站仍由舊版正常服務** ——
> 如果新版本有問題（vendor 沒裝好、語法錯誤、資料庫連不上、快取產生失敗），
> **就直接中止部署，使用者完全不受影響**。
> 在 Deployer 中：`before('deploy:symlink', 'smoke:test');`
> **切換之後再做一次「部署後驗證」**（實際的 HTTP 請求 + 佇列驗證），
> 這一層抓的是「單機測試過但整合起來有問題」的情況，
> 失敗則**自動回退**（`fail('verify', 'rollback')`）。
>
> **Q9.** **優點**：
> ①**內建 Laravel 的完整流程**（releases/current/shared 佈局、artisan 指令）——
> **不用自己寫幾百行的 bash**；
> ②**★★ 多台部署方便** —— 定義多個 `host()`，一個指令部署到所有機器；
> ③**內建回退**（`dep rollback`）；
> ④可以用 PHP 撰寫自訂任務（比 bash 好維護）。
> **缺點**：
> ①**沒有測試與核准流程**（要搭配 CI 使用）；
> ②**PHP 專用** —— 純前端專案要另外處理；
> ③**稽核記錄較弱**（不像 GitHub Actions 有完整的 run 記錄）。
> **實務組合**：**GitHub Actions 做品質檢查與核准，
> 呼叫 Deployer 執行實際的部署**。
>
> **Q10.** **五個必要欄位**：
> ①**時間**（ISO 8601 格式）；
> ②**環境**（staging / production）；
> ③**版本**（git commit SHA，**不只是 tag**）；
> ④**觸發者**（誰按下部署）；
> ⑤**結果**（success / failure / rollback）。
> **加分項**：**核准者**（誰按核准）、**耗時**、**變更摘要**（commit message）。
> **三個記錄位置**：
> ①**GitHub Actions 的 run 記錄**（自動、最完整）；
> ②**伺服器上的 `deploy.log`**（本機可查）；
> ③**系統日誌**（`logger -t deploy`，可送到集中式日誌）。
> **保留期限**：機關的稽核要求通常是**至少一年**。
> **查詢範例**：
> ```bash
> awk -F'|' '$2=="failure"' /var/log/deploy-history.log | wc -l
> ```
