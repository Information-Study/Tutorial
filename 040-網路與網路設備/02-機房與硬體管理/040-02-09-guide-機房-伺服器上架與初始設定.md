# 伺服器上架與初始設定

> [!abstract] 這篇你會學到
> - 拆箱驗收要看哪些東西，**哪些問題一旦簽收就變成你的責任**
> - 滑軌（rail kit）安裝的順序與五個常見裝錯，理線臂（CMA）該不該裝
> - ★★★★★ **帶外管理（BMC）初始設定的完整流程**：開機按什麼鍵、設定管理 IP、
>   **改掉出廠密碼**、建立個人帳號、換掉自簽憑證、設定告警
> - ★★★★★ 為什麼**帶外管理介面絕對不可以直接接對外網路**，正確的網段隔離做法
> - iDRAC／iLO／IPMI／XClarity 的**授權等級差異**：哪些功能是要買 License 才有的
> - ★★★★ BIOS/UEFI 的關鍵設定：**開機模式（UEFI vs Legacy）**、電源管理設定檔、
>   虛擬化開關（VT-x／AMD-V、VT-d／IOMMU、SR-IOV）、Secure Boot、TPM
> - ★★★★ RAID 卡設定與磁碟初始化：RAID 等級選擇、快取策略、
>   **為什麼「快速初始化」和「完整初始化」差很多**
> - ★★★★★ **韌體更新的正確順序與風險**：先更新誰、什麼時候絕對不能更新
> - 一份可以直接列印的**上架驗收清單**，簽了才算交機

> [!warning] 未實機驗證
> ★★★★★ 本篇的 **iDRAC／iLO／IPMI 操作步驟以各廠商公開文件的通用流程為準**，
> 但**不同世代的機型差異非常大**：
>
> - Dell PowerEdge：iDRAC7／8（12G～13G）、iDRAC9（14G～16G）介面完全不同，
>   `racadm` 的物件路徑（例如 `iDRAC.IPv4.Address`）在 iDRAC9 才是這個寫法
> - HPE ProLiant：iLO 4（Gen9）、iLO 5（Gen10／Gen10 Plus）、iLO 6（Gen11）選單位置不同
> - Supermicro／白牌：BMC 韌體版本之間差異更大，很多機型沒有 Redfish
>
> 本篇每一段操作都會標注「**適用機型與版本**」。動手前請以**你手上那台機器的
> 使用者手冊與該韌體版本的 Release Notes 為準**，不要把本篇的選單路徑當成規格。
> BIOS 選項名稱同樣依機型與 BIOS 版本而異，找不到同名選項時到廠商文件搜尋對應項目。

## 觀念說明

### ★★★★ 先看全貌：一台伺服器從貨車到交機的九個階段

```text
① 到貨簽收 ──► ② 拆箱驗收 ──► ③ 滑軌安裝 ──► ④ 主機上架 ──► ⑤ 接線與標籤
                    │                                                │
                （有問題就在這裡退回）                        （電源、網路、管理埠）
                                                                     │
                                                                     ▼
⑨ 交機簽收 ◄── ⑧ 驗收測試 ◄── ⑦ RAID 與 OS ◄── ⑥ BMC 初始化 ＋ BIOS 設定
      │                                                    │
（清單簽名歸檔）                              （改密碼、設管理 IP、韌體更新）
```

★★★★★ **這九個階段的順序不可以亂跳**，特別是：

- **④ 上架之前**一定要先做 ② 拆箱驗收 —— 螺絲鎖上去之後才發現面板凹陷，退貨會很難談
- **⑥ BMC 初始化**要在 ⑦ 裝 OS 之前 —— 有了帶外管理，後面裝 OS 就不用一直跑機房
- **韌體更新排在 ⑥ 的最後**，OS 裝好之後再更新韌體，等於把驗證過的環境再翻一次

### ★★★★★ 帶外管理（Out-of-Band Management）到底是什麼

伺服器主機板上有一顆**獨立的小電腦**，叫做 **BMC（Baseboard Management Controller）**。
它的特性是：

| 特性 | 說明 | 為什麼重要 |
| --- | --- | --- |
| ★★★★★ 獨立供電 | 只要**電源線插著**（主機關機也算），BMC 就是活的 | 主機當掉、關機，你還是連得進去 |
| ★★★★★ 獨立於 OS | 不依賴主機的作業系統、網路卡驅動、防火牆 | OS 掛掉、網路設定改壞，還是進得去 |
| ★★★★ 有自己的網路介面 | 專用管理埠，或與第一個網路埠共用（shared） | 這就是「帶外」的由來：不走業務網路 |
| ★★★★ 完整硬體視野 | 讀得到溫度、風扇、電壓、電源、記憶體錯誤、硬碟狀態 | 硬體告警的唯一可靠來源 |
| ★★★★★ 虛擬 KVM 與虛擬媒體 | 像坐在機器前面一樣，還能掛載遠端 ISO 裝 OS | 不用再抱螢幕鍵盤進機房 |
| ★★★★★ 遠端電源控制 | 開機、關機、強制斷電、冷重啟 | 半夜主機當掉，不用開車去機房 |

各家的名字不一樣，但做的是同一件事：

| 廠商 | 產品名 | 常見版本 | 標準協定支援 |
| --- | --- | --- | --- |
| Dell | **iDRAC**（Integrated Dell Remote Access Controller） | iDRAC7／8／9 | IPMI 2.0、Redfish（iDRAC9 完整） |
| HPE | **iLO**（Integrated Lights-Out） | iLO 4／5／6 | IPMI 2.0、Redfish |
| Lenovo | **XClarity Controller（XCC）**、舊稱 IMM2 | XCC／XCC2 | IPMI 2.0、Redfish |
| Supermicro | **IPMI／BMC**（近年也叫 SuperCloud Composer 管理） | 依主機板型號 | IPMI 2.0、部分機型 Redfish |
| Cisco UCS | **CIMC**（Cisco IMC） | 依 UCS 世代 | IPMI 2.0、Redfish |
| 通用標準 | **IPMI 2.0**、**Redfish**（DMTF 標準，走 HTTPS/REST） | — | 跨廠商用這兩個 |

> [!tip] 實務建議 ★★★★
> 如果你的機房是**混廠牌**，寫自動化腳本時**優先用 Redfish**（HTTPS + JSON，跨廠商一致），
> 其次才是 `ipmitool`。廠商專屬工具（`racadm`／`ilorest`）功能最完整但綁死單一品牌。

### ★★★★★ 為什麼帶外管理介面絕對不可以接對外網路

這是本篇最重要的一條，沒有之一。

> [!danger] ★★★★★ BMC 直連網際網路 = 把整台伺服器的最高權限掛在網路上
> BMC 的權限**高於作業系統**。取得 BMC 就等於：
>
> - 可以隨時關機、重開機 → **服務中斷**
> - 可以掛載自己的 ISO 開機 → **繞過作業系統所有防護，直接改磁碟資料**
> - 可以看虛擬 KVM 畫面 → **看到你打的每一個字，包含密碼**
> - 可以清除 BIOS 設定、刷韌體 → **可能讓機器變磚**
>
> 而 BMC 的防護能力遠不如 OS：更新頻率低、韌體漏洞修補慢、很多機型不支援
> 帳號鎖定與雙因素、日誌能力有限。**歷年 BMC 韌體都出現過可遠端利用的重大漏洞。**

正確的做法只有一種：**放在獨立的管理網段，不做 NAT、不開 port forwarding、
只能從跳板機（bastion／jump host）進入。**

```text
❌ 錯誤：                                    ✅ 正確：

  Internet                                    Internet
     │                                            │
  防火牆 ── port forward 443 ──► iDRAC         防火牆
                                                  │
                                            ┌─────┴──────┐
                                            │  跳板機     │ ← VPN／MFA 登入
                                            └─────┬──────┘
                                                  │ 只有這條路
                                        ┌─────────▼──────────┐
                                        │ VLAN 管理網段       │
                                        │ 10.99.0.0/24       │
                                        │ iDRAC / iLO / IPMI  │
                                        │ 交換器管理 IP        │
                                        │ PDU / UPS 管理卡     │
                                        └────────────────────┘
                                          （此網段無預設路由到 Internet）
```

管理網段的四條硬規則：

1. ★★★★★ **獨立 VLAN**，與業務網段 L3 隔離，ACL 只允許跳板機來源
2. ★★★★★ **沒有到 Internet 的預設路由**（韌體更新用離線檔案或內部鏡像）
3. ★★★★ **所有管理介面都在這一段**：BMC、交換器管理 IP、PDU、UPS 管理卡、
   KVM 切換器、環境監控主機 —— 詳見 [[040-02-13-guide-機房-機房實體安全]]
4. ★★★★ **跳板機要記錄操作**，並且要有 MFA，詳見 [[090-02-06-guide-防護-遠端存取安全]]

### ★★★★ 授權等級：為什麼別人的 iDRAC 有虛擬 KVM，你的沒有

BMC 的功能是**分級授權**的，這件事在編列預算時最容易漏掉。

> [!warning] ★★★★ 授權等級以下為「常見的分級概念」，實際名稱與功能對應請以採購當下的廠商報價單為準
> 廠商會調整分級內容，**不要拿本表去跟廠商爭執**，請在採購階段就把
> 「需要遠端虛擬主控台與虛擬媒體」**寫進規格書**。

| 廠商 | 常見分級 | 一般來說要買到什麼等級才有虛擬 KVM／虛擬媒體 |
| --- | --- | --- |
| Dell iDRAC | Basic → **Express** → **Enterprise** → Datacenter | ★★★★ 一般需要 **Enterprise** 以上 |
| HPE iLO | Standard → **Advanced**（及其他組合包） | ★★★★ 一般需要 **Advanced** |
| Lenovo XCC | 基本 → **Enterprise**（或以 Feature on Demand 加購） | ★★★★ 需要進階授權 |
| Supermicro | 部分功能需要 **SFT-OOB-LIC** 之類的授權金鑰 | 依主機板型號 |

> [!danger] ★★★★★ 採購階段的三個致命疏漏
> 1. **沒買虛擬 KVM 授權** → 每次裝 OS、進 BIOS 都要跑機房，五年下來的人力成本遠超授權費
> 2. **沒買專用管理網路埠**（有些入門機型 BMC 只能與 NIC1 共用）→ 管理流量被迫走業務網段，
>    ★★★★★ 直接違反「管理網段隔離」原則
> 3. **授權綁機器序號**，換主機板要重新申請 → 保固維修換板後 BMC 功能會掉，
>    要跟廠商索取新授權，這件事寫進 [[040-02-12-guide-機房-設備生命週期管理]] 的維修流程

### ★★★ UEFI 與 Legacy BIOS：為什麼現在幾乎都選 UEFI

| 項目 | Legacy BIOS（CSM） | **UEFI** |
| --- | --- | --- |
| 磁碟分割表 | MBR，★★★ **單一分割上限 2 TiB** | GPT，實務上不受此限 |
| 開機分割 | MBR 開機磁區 | ESP（EFI System Partition，FAT32） |
| Secure Boot | 不支援 | ★★★★ 支援 |
| 開機項目管理 | 靠開機順序 | NVRAM 開機項目，Linux 用 `efibootmgr` 管理 |
| 現況 | 新平台逐步移除支援 | ★★★★ **新機一律選這個** |

> [!danger] ★★★★★ 開機模式在裝 OS「之前」就要決定，事後改要重裝
> 以 Legacy 模式安裝的系統，把 BIOS 改成 UEFI 之後**開不起來**（反之亦然）。
> 這不是「調一下設定」，是**整台重裝**。
> 上架流程一定要把「開機模式」放在 BIOS 設定的第一項，
> 並且寫進 [[020-02-03-01-svc-標準化-新機建置標準流程]] 的標準參數表。

### ★★★ 硬體 RAID 卡、HBA、軟體 RAID 怎麼選

| 模式 | 說明 | 適用 |
| --- | --- | --- |
| **硬體 RAID（有快取電池／BBU、FBWC）** | RAID 卡自己做同位運算，OS 看到一顆虛擬磁碟 | ★★★★ 傳統 ext4／XFS 的資料庫與一般伺服器 |
| **HBA／IT 模式（直通）** | 卡只當通道，OS 看得到每一顆實體磁碟 | ★★★★★ **ZFS、Ceph、TrueNAS 一定要用這個** |
| **軟體 RAID（mdadm／ZFS／Storage Spaces）** | OS 做 RAID | 預算有限、或需要跨機型可攜性 |

> [!danger] ★★★★★ ZFS 絕對不要架在硬體 RAID 上
> ZFS 需要**直接看到每一顆實體磁碟**才能做校驗與自我修復。架在硬體 RAID 的
> 虛擬磁碟上，ZFS 的資料完整性保護會失效，而且出問題時兩層都在猜。
> 詳見 [[020-01-24-guide-進階儲存-ZFS與Btrfs]] 與 [[020-01-29-guide-Linux-網路儲存與軟體RAID]]。

## 安裝或基礎操作

### ★★★★★ 步驟一：拆箱驗收（簽收之前一定要做完）

> [!danger] ★★★★★ 簽收單簽下去，外觀損傷就變成你的責任
> 貨運簽收時，**先看外箱**：箱體嚴重擠壓、防倒指示器（Tilt Watch）或
> 撞擊指示器（Shock Watch）變色 → **當場在簽收單上註記，並拍照**。
> 有些採購合約規定「外觀瑕疵須於到貨 N 日內提出」，N 通常很短，
> ★★★★ 實際天數**依採購合約與廠商保固條款確認**。

拆箱檢查清單（照著打勾）：

| # | 檢查項目 | 判定 | 星號 |
| --- | --- | --- | --- |
| 1 | 外箱有無擠壓、破損、水漬；防倒／防撞標籤有無變色 | 有異常 → 拍照＋簽收單註記 | ★★★★★ |
| 2 | **機身序號（Service Tag／Serial Number）與出貨單一致** | 不一致 → 立即反映，不要上架 | ★★★★★ |
| 3 | **實際配置與訂單規格一致**：CPU 顆數／型號、記憶體容量與條數、硬碟顆數與容量、網卡、RAID 卡 | 少一顆記憶體就是少一顆 | ★★★★★ |
| 4 | 前面板、機殼、耳片有無凹陷變形 | 影響上架與 EMI 密封 | ★★★★ |
| 5 | **滑軌組（rail kit）有沒有附**、左右是否成對、螺絲包齊全 | 缺件當場叫料 | ★★★★ |
| 6 | 電源線數量與規格（C13/C14、C19/C20）符合 PDU 插座 | 規格不符要換線 | ★★★★ |
| 7 | 理線臂（CMA）、擋板（bezel）、鑰匙、前面板蓋 | 依訂單 | ★★ |
| 8 | **BMC 出廠密碼標籤／拉出式資訊卡**（Dell 服務標籤抽屜、HPE 機身標籤） | ★★★★★ **拍照存檔後撕下收好，不要留在機身上** | ★★★★★ |
| 9 | 保固卡／授權金鑰（iDRAC Enterprise、iLO Advanced、OS 授權） | 立刻登錄到資產系統 | ★★★★ |
| 10 | 硬碟托架（caddy）數量、空槽是否有擋板（blank） | 缺擋板會破壞風道 | ★★★ |

> [!danger] ★★★★★ 出廠密碼標籤是最高機密
> 新一代伺服器（Dell 14G 以後、HPE Gen10 以後）**每台的 BMC 出廠密碼都不一樣**，
> 印在機身的拉出式標籤上。這張標籤**任何進得了機房的人都看得到**。
> 正確做法：**拍照存進密碼保管系統 → 撕下標籤（或用不透明標籤覆蓋）→
> 初始設定第一件事就是改掉它**。
> 密碼保管的做法見 [[090-07-02-guide-資安實踐-密碼與帳號管理實務]] 與
> [[090-03-03-guide-應用安全-機密管理與金鑰保護]]。

驗收結果請填 `_表單範本/020-02-01-新機建置驗收表.docx`（vault 內路徑，用檔案總管開），
規格登記填 `_表單範本/020-02-02-伺服器規格與用途登記表.docx`。

### ★★★★ 步驟二：滑軌安裝

滑軌分兩大類：

| 類型 | 特性 | 適用 |
| --- | --- | --- |
| **免工具滑軌（tool-less）** | 卡榫直接扣進方孔機櫃，不需螺絲 | ★★★★ 方孔機櫃，現在的主流 |
| **螺絲固定滑軌** | 要鎖螺絲，常見於圓孔／螺牙孔機櫃 | 舊機櫃、非標準機櫃 |
| **靜態導軌（static rail）** | 不能拉出來，只能整台抽出 | 淺機櫃、後方維護空間充足時 |
| **滑出式導軌（sliding rail）** | 可拉出做免關機維護（換風扇、記憶體） | ★★★★ 建議選這個 |

安裝順序：

1. ★★★★★ **先確認 U 位**：對照機櫃 U 位圖（[[040-02-03-guide-機房-機櫃規劃與設備上架]]），
   在前後立柱上用麥克筆或標記貼標好起始 U
2. ★★★★ **分清楚左右與前後**：滑軌上會印 `LEFT`／`RIGHT`、`FRONT`／`REAR`，
   ★★★ **裝反是最常見的錯誤**，裝反了主機推不進去
3. **先裝後端**，把滑軌後端卡榫扣進後立柱方孔，聽到「喀」一聲
4. **再拉伸前端**扣進前立柱，滑軌長度會自動適應機櫃深度
5. ★★★★ **用力搖一搖**確認兩端都卡實 —— 一邊沒卡好，主機推進去會整支掉下來
6. 確認**左右滑軌等高**：目視兩側 U 位刻度，差一格就裝不進去

> [!danger] ★★★★★ 重型伺服器上架至少兩人，並使用升降台
> 滿配的 2U 伺服器可以超過 30 公斤，4U 儲存機更重。
> **一個人抬 + 一個人對孔位 = 手滑砸下來，砸壞下面的機器，還可能壓傷手指。**
> ★★★★ 重機一律：兩人以上、由下往上裝、用機櫃升降台（server lift）。
> 實際重量**依機型規格書確認**，不要憑感覺。

> [!tip] 實務建議 ★★★
> **理線臂（CMA）裝不裝？** 裝了可以整台拉出來不用拔線，但會擋住機箱後方氣流出口。
> 高密度、高發熱的機櫃建議**不裝 CMA，改用足夠鬆的線長 + 側邊理線**；
> 一般密度的機櫃裝 CMA 維護方便很多。詳見 [[040-02-08-guide-機房-結構化佈線與標籤規範]]。

### ★★★★ 步驟三：接線與標籤

上架後接線的順序與原則：

| 順序 | 線材 | 原則 | 星號 |
| --- | --- | --- | --- |
| 1 | **接地線**（若機型有接地端子） | 先接地 | ★★★★ |
| 2 | **電源線 A**（PSU1） | 接 **A 路 PDU** | ★★★★★ |
| 3 | **電源線 B**（PSU2） | 接 **B 路 PDU**（★★★★★ 不同迴路、不同 UPS） | ★★★★★ |
| 4 | **BMC 專用管理埠** | 接**管理 VLAN** 的交換器埠 | ★★★★★ |
| 5 | 業務網路埠（NIC1／NIC2） | 依網路規劃接，做 bonding 就接兩台不同交換器 | ★★★★ |
| 6 | 其他（光纖、SAS 外接、KVM） | 依需求 | ★★ |

> [!danger] ★★★★★ 雙電源接同一條迴路 = 沒有雙電源
> 這是機房最常見的假冗餘。兩顆 PSU 都插在同一條 PDU、同一個 UPS 上，
> 那條迴路跳脫 → 整台掉電。
> 一定要 **A 路接 A、B 路接 B**，而且 A、B 要來自**不同的配電盤迴路**。
> 詳見 [[040-02-04-guide-機房-電力系統與配電]]。

★★★★ **每一條線兩端都要貼標籤**，格式在 [[040-02-08-guide-機房-結構化佈線與標籤規範]]。
線接完馬上貼，不要想著「等一下再貼」—— 沒有一次是等一下真的會貼的。

同時要填 `_表單範本/040-02-04-線路標示紀錄.docx`。

### ★★★★★ 步驟四：第一次開機，進入設定介面

接上電源之後（**還沒按開機鈕**），BMC 已經開始運作了。多數機型會有一顆
狀態指示燈（Dell 稱系統識別燈、HPE 稱 UID）閃爍表示 BMC 正在啟動，
★★★ **等 30～60 秒讓 BMC 開機完成**再按主機電源鈕。

按下電源鈕後，在 POST（開機自我測試）畫面按下對應按鍵：

| 廠商 | 系統設定（BIOS/UEFI） | 開機選單 | 其他常用 |
| --- | --- | --- | --- |
| **Dell PowerEdge** | **F2** = System Setup（內含 BIOS 與 iDRAC Settings） | **F11** = Boot Manager | **F10** = Lifecycle Controller，**F12** = PXE 開機 |
| **HPE ProLiant Gen10／Gen11** | **F9** = System Utilities（RBSU） | **F11** = Boot Menu | **F10** = Intelligent Provisioning，**F12** = 網路開機 |
| **Lenovo ThinkSystem** | **F1** = System Setup | **F12** = 選擇開機裝置 | 依機型 |
| **Supermicro** | **DEL**（部分機型 **F2**） | **F11** = Boot Menu | 依主機板 |

> [!warning] ★★★★ 按鍵在 POST 畫面上一定會提示，以畫面顯示為準
> 上表是**常見對應**，機型與 BIOS 版本可能不同。★★★ **POST 畫面右上或下方
> 一定會列出可用按鍵**，看畫面比背表可靠。
> 遠端透過虛擬 KVM 操作時，按鍵可能被本機作業系統攔截（例如 F11 全螢幕），
> ★★★ 用虛擬主控台工具列的「虛擬鍵盤 / 傳送按鍵」功能送出。

### ★★★★★ 步驟五：設定 BMC 管理 IP

有三種做法，任選其一：

#### 做法 A：從 BIOS/UEFI 設定介面設（★★★★ 最推薦，第一次一定用這個）

以 **Dell PowerEdge 14G 以後（iDRAC9）** 為例：

```text
開機按 F2 → System Setup
  → iDRAC Settings
    → Network
      ├─ Enable NIC .................. Enabled
      ├─ NIC Selection ............... Dedicated   ★★★★★（有專用埠就一定選這個）
      ├─ IPv4 Settings
      │   ├─ Enable IPv4 ............. Enabled
      │   ├─ Enable DHCP ............. Disabled    ★★★★（管理 IP 用固定，不要 DHCP）
      │   ├─ Static IP Address ....... 10.99.10.21
      │   ├─ Static Gateway .......... 10.99.10.254
      │   ├─ Static Subnet Mask ...... 255.255.255.0
      │   └─ Static Preferred DNS .... 10.99.1.10
      └─ VLAN Settings ............... 依網路規劃決定要不要打 VLAN tag
  → User Configuration            ★★★★★ 下一步就在這裡改密碼
```

以 **HPE ProLiant Gen10／Gen11（iLO 5／6）** 為例：

```text
開機按 F9 → System Utilities
  → System Configuration
    → iLO 5 Configuration Utility
      → Network Options
        ├─ Network Interface Adapter .. ON (Dedicated)  ★★★★★
        ├─ DHCP Enable ................ OFF             ★★★★
        ├─ IP Address ................. 10.99.10.22
        ├─ Subnet Mask ................ 255.255.255.0
        └─ Gateway IP Address ......... 10.99.10.254
      → User Management             ★★★★★ 改預設帳號密碼
```

> [!warning] 未實機驗證 ★★★★
> 上面的選單路徑是 **iDRAC9 與 iLO 5／6 的常見結構**。
> iDRAC7/8（Dell 12G/13G）與 iLO 4（Gen9）的選單名稱不同（例如 iLO 4 是
> `iLO 4 Configuration Utility`）。**以你機器上實際顯示的選單為準。**

> [!danger] ★★★★★ `NIC Selection` 一定選 Dedicated（專用埠）
> 選 `Shared`／`LOM` 會讓 BMC 流量與業務流量走同一條實體線，
> ★★★★★ **管理網段的隔離就破功了**。
> 只有在機型完全沒有專用管理埠時才用 shared，這時**務必用 VLAN tag
> 把 BMC 流量打到管理 VLAN**，並在交換器端做嚴格的 ACL。

#### 做法 B：用 `ipmitool` 從已安裝的 OS 內設定（★★★ 適用於已經有 OS 的機器）

適用於任何支援 IPMI 2.0 的機型。先安裝工具：

```bash
sudo apt update && sudo apt install -y ipmitool
```

```text
Reading package lists... Done
Building dependency tree... Done
The following NEW packages will be installed:
  ipmitool
...
Setting up ipmitool (1.8.19-4build2) ...
```

> [!info]- Rocky / AlmaLinux（RHEL 系）對照
> ```bash
> sudo dnf install -y ipmitool
> sudo systemctl enable --now ipmi
> ```
> RHEL 系需要載入 `ipmi_si`、`ipmi_devintf` 核心模組才能用本機介面：
> ```bash
> sudo modprobe ipmi_si ipmi_devintf
> ```

查目前設定（`1` 是 LAN channel 編號，★★★ **不同機型 channel 可能是 1、2 或 8**）：

```bash
sudo ipmitool lan print 1
```

典型輸出（**你的機器數值會不同**）：

```text
Set in Progress         : Set Complete
IP Address Source       : Static Address
IP Address              : 10.99.10.23
Subnet Mask             : 255.255.255.0
MAC Address             : 00:00:00:00:00:00
Default Gateway IP      : 10.99.10.254
802.1q VLAN ID          : Disabled
Cipher Suite Priv Max   : XXXXXXXXXXXXXXX
```

找不到 channel 時逐一試：

```bash
for ch in 1 2 3 8; do echo "== channel $ch =="; sudo ipmitool lan print $ch 2>/dev/null | head -4; done
```

設定固定 IP：

```bash
sudo ipmitool lan set 1 ipsrc static
sudo ipmitool lan set 1 ipaddr 10.99.10.23
sudo ipmitool lan set 1 netmask 255.255.255.0
sudo ipmitool lan set 1 defgw ipaddr 10.99.10.254
```

★★★★ 每一行下完都會回 `Setting LAN IP Address to 10.99.10.23` 之類的確認訊息，
**沒有回應就是沒設定成功**。設完再 `lan print 1` 確認一次。

> [!danger] ★★★★ 改 BMC 網路設定會斷掉你自己的遠端連線
> 如果你正在**透過 BMC 網路**遠端操作（`ipmitool -H`），改 IP 會當場把自己踢掉。
> ★★★★★ **只從主機本機（in-band，不加 `-H`）改 BMC 網路**，或是安排到現場改。

#### 做法 C：用廠商工具（★★★ 批次部署時用）

Dell（需安裝 OMSA／iDRAC Tools 提供的 `racadm`，**適用 iDRAC9**）：

```bash
sudo racadm set iDRAC.NIC.Enable Enabled
sudo racadm set iDRAC.NIC.Selection Dedicated
sudo racadm set iDRAC.IPv4.DHCPEnable Disabled
sudo racadm set iDRAC.IPv4.Address 10.99.10.21
sudo racadm set iDRAC.IPv4.Netmask 255.255.255.0
sudo racadm set iDRAC.IPv4.Gateway 10.99.10.254
sudo racadm getsysinfo
```

HPE（需安裝 `hponcfg` 或 `ilorest`，**適用 iLO 4／5／6**）：

```bash
sudo ilorest login
sudo ilorest list --selector=EthernetInterface.
sudo ilorest logout
```

> [!warning] 未實機驗證 ★★★★
> `racadm` 物件路徑（`iDRAC.IPv4.Address` 等）是 **iDRAC9 的寫法**；
> iDRAC7/8 使用舊的 `cfgLanNetworking` 群組語法，**兩者不通用**。
> `ilorest` 的 selector 名稱依 iLO 版本與 Redfish schema 版本而異。
> 請先用 `racadm help` / `ilorest --help` 對照你手上版本的實際語法。

### ★★★★★ 步驟六：改掉出廠密碼，建立正式帳號

★★★★★ **這一步不做完，前面全部白做。**

出廠帳密的現況：

| 廠商 | 舊機型（常見固定值） | 新機型 |
| --- | --- | --- |
| Dell iDRAC | `root` / `calvin`（13G 以前） | ★★★★ 14G 以後**每台隨機**，印在服務標籤抽屜 |
| HPE iLO | — | ★★★★ `Administrator` + **每台隨機**，印在機身標籤 |
| Supermicro | `ADMIN` / `ADMIN`（舊板） | 新板多為每台隨機，印在標籤 |
| Lenovo XCC | 依世代，舊為 `USERID` / `PASSW0RD`（零） | 新機型多為每台隨機 |

> [!danger] ★★★★★ `root/calvin` 是全世界都知道的密碼
> 掃描器會直接試這組。舊機型（Dell 12G/13G）**上架後第一件事就是改掉**，
> 沒有例外、沒有「等一下再改」。

改密碼（在 BIOS 的 iDRAC Settings / iLO Configuration Utility 裡的 User Configuration）：

用 `ipmitool` 改（通用做法）：

```bash
# 1. 先列出目前的使用者
sudo ipmitool user list 1
```

```text
ID  Name             Callin  Link Auth  IPMI Msg   Channel Priv Limit
1                    true    false      false      NO ACCESS
2   root             true    true       true       ADMINISTRATOR
```

```bash
# 2. 改 ID 2 的密碼（會互動式提示輸入兩次，不會留在 shell history）
sudo ipmitool user set password 2
```

```text
Password for user 2:
Password for user 2:
Set User Password command successful (user 2)
```

```bash
# 3. 另外建一個你自己的具名帳號（ID 3），不要大家共用 root
sudo ipmitool user set name 3 opsadmin
sudo ipmitool user set password 3
sudo ipmitool user priv 3 4 1          # priv 4 = ADMINISTRATOR，channel 1
sudo ipmitool user enable 3
sudo ipmitool user list 1
```

> [!danger] ★★★★★ 不要用 `ipmitool user set password 2 'MyPassw0rd'`
> 密碼直接寫在指令列會進入 shell history、進入 `ps` 的行程列表、
> 進入稽核日誌。**一律用互動式輸入。**

帳號規劃原則：

| 原則 | 說明 | 星號 |
| --- | --- | --- |
| **具名帳號，不共用** | 每個維運人員一個帳號，出事查得到是誰 | ★★★★★ |
| **保留一個緊急帳號** | 密碼封存在保險箱／密碼保管系統，平時停用 | ★★★★ |
| **停用或改名預設帳號** | `root`／`ADMIN`／`USERID` 這些名字本身就是攻擊目標 | ★★★★★ |
| **最小權限** | 只需要看狀態的人給 Read-Only／Operator，不要一律 Administrator | ★★★★ |
| **接 LDAP／AD**（進階授權才有） | 人員異動時集中管理，離職即失效 | ★★★★ |
| **密碼進保管系統** | 見 [[090-03-03-guide-應用安全-機密管理與金鑰保護]] | ★★★★★ |

### ★★★★ 步驟七：BMC 的其他必做設定

| 設定 | 做什麼 | 為什麼 | 星號 |
| --- | --- | --- | --- |
| **時間與 NTP** | 指向內部 NTP 伺服器 | ★★★★★ **時間不對，日誌就沒有鑑識價值**，見 [[020-01-28-cmd-Linux-時間同步NTP與chrony]] | ★★★★★ |
| **主機名稱** | 設成與資產編號一致，例如 `idrac-srv-web01` | 一堆 `iDRAC-XXXXXX` 誰認得出來 | ★★★★ |
| **關閉不用的服務** | Telnet、IPMI over LAN（若改用 Redfish）、VNC、非必要的 SNMP v1/v2c | 減少攻擊面 | ★★★★★ |
| **停用 IPMI over LAN** | 只在確定改用 Redfish/HTTPS 管理後才停 | ★★★★★ IPMI 2.0 的 cipher suite 0 與 RAKP 有已知弱點 | ★★★★★ |
| **SNMP v3 告警** | 硬體告警送到監控系統 | 見 [[100-01-03-guide-日誌-系統監控與告警]] | ★★★★ |
| **Email 告警** | 嚴重事件寄信給維運信箱 | 監控系統掛掉時的最後防線 | ★★★ |
| **Syslog 外送** | BMC 日誌送到集中日誌伺服器 | ★★★★ BMC 本身空間有限會覆蓋，見 [[100-01-02-guide-日誌-日誌集中與輪替]] | ★★★★ |
| **登入警語（login banner）** | 顯示「未經授權不得使用」 | 部分稽核項目要求 | ★★★ |
| **Session timeout** | 設 10～15 分鐘 | 防止有人開著頁面離開 | ★★★ |
| **憑證** | 換掉出廠自簽憑證 | 見下一段 | ★★★★ |

### ★★★★ 步驟八：換掉 BMC 的自簽憑證

BMC 出廠一定是自簽憑證，瀏覽器每次都跳警告。看久了大家就養成「反正按繼續」的習慣，
★★★★ **這正是中間人攻擊需要的條件**。

正確做法：用**內部 CA 簽發** BMC 的憑證。

```text
① 在 BMC 介面產生 CSR
   Dell iDRAC9：iDRAC Settings → Services → Web Server → SSL → Generate CSR
   HPE iLO 5：  Security → SSL Certificate → Customize Certificate
   ★★★★★ CSR 的 CN 要填 BMC 的 FQDN，SAN 要同時包含 FQDN 與 IP

② 把 CSR 拿去內部 CA 簽
   → [[090-01-08-guide-PKI-用自建CA簽發伺服器憑證]]

③ 憑證匯回 BMC 上傳
   → BMC 會自己重啟 Web 服務（約 30～60 秒斷線，主機不受影響）

④ 確認所有維運人員的電腦都信任內部根 CA
   → [[090-01-09-guide-PKI-根憑證派送與信任]]
```

> [!warning] ★★★★ 一定要填 SAN
> 現在的瀏覽器**只看 SAN，不看 CN**。只填 CN 的憑證瀏覽器一樣會報錯。
> 而且維運人員常常直接打 IP 連線，所以 **SAN 要同時放 DNS 名稱與 IP**。
> 詳見 [[090-01-04-guide-PKI-CN與SAN設定與瀏覽器相容性]]。

## 進階應用

### ★★★★ BIOS/UEFI 關鍵設定總表

> [!warning] ★★★★ 選項名稱依機型與 BIOS 版本而異
> 下表是**設定的目的與常見名稱**。找不到同名選項時，
> 到廠商的 BIOS 設定手冊搜尋對應功能，不要亂改看起來像的選項。

#### 開機與安全

| 設定項（常見名稱） | 建議值 | 理由 | 星號 |
| --- | --- | --- | --- |
| **Boot Mode** / Boot Configuration | **UEFI** | ★★★★★ 裝 OS 前就要定，事後改要重裝 | ★★★★★ |
| **Secure Boot** | 先 **Disabled** 裝 OS，確認發行版支援後再 Enabled | ★★★★ 開著可能讓未簽章的驅動、DKMS 模組（顯卡、儲存卡）載不起來 | ★★★★ |
| **Secure Boot Policy** | Standard（用預設金鑰） | 自訂金鑰要有配套管理流程 | ★★★ |
| **TPM Security** | **Enabled**（TPM 2.0） | ★★★★ 磁碟加密（LUKS／BitLocker）與量測開機需要 | ★★★★ |
| **Boot Sequence** | 依實際：本機磁碟優先，安裝期間才調 PXE／虛擬光碟優先 | ★★★★ 裝完 OS 記得**改回本機磁碟優先** | ★★★★ |
| **PXE / Network Boot** | 不用就 Disabled | 減少攻擊面 | ★★★ |
| **Setup Password / System Password** | ★★★★ 設定 BIOS 密碼並存進密碼保管系統 | 防止有實體接觸的人改開機順序 | ★★★★ |

> [!danger] ★★★★★ BIOS 密碼忘記會很痛苦
> 部分機型忘記 BIOS 密碼要**拔電池 / 短接跳線清除 CMOS**（需要停機拆機），
> 有些機型甚至要送修。★★★★★ **設了一定要存進密碼保管系統**，
> 而且要有兩個人以上知道取用方式。

#### 電源與效能

| 設定項（常見名稱） | 建議值 | 理由 | 星號 |
| --- | --- | --- | --- |
| **System Profile** / Power Regulator / Workload Profile | 依用途選：`Performance Per Watt` 省電、`Performance` 低延遲 | ★★★★ 資料庫、交易系統選 Performance；一般 Web／檔案伺服器可用省電模式 | ★★★★ |
| **C-States**（CPU 省電狀態） | 低延遲需求 → Disabled；一般 → Enabled | ★★★ 關掉會明顯增加待機耗電與發熱 | ★★★ |
| **Turbo Boost** | 一般 Enabled | 需要「每一顆核心效能完全一致」時才關 | ★★★ |
| **Fan Speed / Thermal Profile** | 預設自動；高密度機櫃可調高 | ★★★★ 手動固定高轉速 = 噪音大、耗電高、風扇壽命短 | ★★★ |
| **Hot Spare（電源供應器）** | 高可用需求關閉 | ★★★ 開啟時其中一顆 PSU 會待機，實際上仍是雙路 | ★★ |
| **Power Cap** | 一般不設 | ★★★ 設了會限制效能，只有在配電容量吃緊時才用，見 [[040-02-04-guide-機房-電力系統與配電]] | ★★★ |
| **AC Power Recovery / Auto Power On** | **Last State** 或 **On** | ★★★★★ 停電復電後主機要不要自己開機，**這個設定會直接影響停電應變流程** | ★★★★★ |

> [!danger] ★★★★★ `AC Power Recovery` 要跟停電應變流程一起決定
> - 設成 **On**（復電就自動開機）：復電後不用人到現場，但**復電瞬間所有主機同時開機
>   會產生突波（inrush current），可能把 UPS 或斷路器打跳**
> - 設成 **Off**（復電維持關機）：要人工開機，但可以控制開機順序
> - 設成 **Last State**（回到斷電前的狀態）：折衷做法
>
> ★★★★ **不同機器可以設不同值**：核心設備（DNS、AD、儲存）設 On 讓它先起來，
> 其餘設 Off 由人工分批開機。這件事要寫進 [[040-02-14-guide-機房-機房異常應變]] 的復電程序。

#### 虛擬化相關（★★★★ 要跑 VM 或容器一定要開）

| 設定項（常見名稱） | 建議值 | 用途 | 星號 |
| --- | --- | --- | --- |
| **Virtualization Technology** / VT-x / AMD-V / SVM Mode | **Enabled** | ★★★★★ 沒開就跑不了 KVM／Hyper-V／ESXi／Proxmox | ★★★★★ |
| **VT-d** / **IOMMU** / AMD-Vi | **Enabled** | ★★★★ PCIe 裝置直通（GPU passthrough、SR-IOV）必要 | ★★★★ |
| **SR-IOV Global Enable** | 需要虛擬功能網卡時 Enabled | 給 VM 直接分配網卡的虛擬功能 | ★★★ |
| **Hyper-Threading / SMT** | 一般 Enabled | ★★★ 某些授權以核心數計費、某些資安基準建議關閉，**依授權與資安要求決定** | ★★★ |
| **NUMA / Memory Node Interleaving** | Interleaving **Disabled**（保留 NUMA 拓撲） | ★★★★ 關掉 interleaving 才看得到 NUMA 節點，虛擬化平台才能做記憶體親和性 | ★★★★ |
| **Above 4G Decoding** | 有大記憶體 GPU／加速卡時 Enabled | 大 BAR 空間需求 | ★★★ |

### ★★★★ RAID 卡設定與磁碟初始化

#### 進入 RAID 設定介面

| 廠商 | 進入方式 |
| --- | --- |
| Dell PERC | F2 → System Setup → Device Settings → 選擇 PERC 卡 |
| HPE Smart Array | F9 → System Utilities → System Configuration → 選擇 Smart Array |
| Broadcom/LSI MegaRAID | POST 時按提示鍵（常見 `Ctrl+R`），或從 UEFI Device Settings 進入 |

#### RAID 等級選擇

| 等級 | 最少磁碟 | 可用容量 | 容錯 | 適用 | 星號 |
| --- | --- | --- | --- | --- | --- |
| **RAID 0** | 2 | 100% | ★★★★★ **完全沒有** | 只有暫存、快取，正式資料**絕對不要** | ★★★★★ |
| **RAID 1** | 2 | 50% | 壞 1 顆 | ★★★★ 系統碟的標準做法 | ★★★★ |
| **RAID 5** | 3 | (N-1)/N | 壞 1 顆 | ★★★ 中小容量；**大容量碟不建議** | ★★★★ |
| **RAID 6** | 4 | (N-2)/N | 壞 2 顆 | ★★★★ 大容量碟建議用這個 | ★★★★ |
| **RAID 10** | 4 | 50% | 每組壞 1 顆 | ★★★★★ 資料庫首選，重建快、寫入效能好 | ★★★★ |

> [!danger] ★★★★★ 大容量磁碟不要用 RAID 5
> RAID 5 只能壞一顆。當大容量磁碟（例如 8 TB 以上）壞一顆進入重建時：
>
> 1. **重建時間非常長**（可能數十小時到數天），這段期間陣列**沒有任何保護**
> 2. 重建會對**每一顆剩餘磁碟做全碟讀取**，同批出廠的磁碟很可能在這時候接著壞
> 3. 重建期間讀到**不可修復讀取錯誤（URE）**就可能導致重建失敗
>
> ★★★★★ **大容量磁碟一律 RAID 6 或 RAID 10**，並且**一定要有熱備援（hot spare）**。
> ★★★★★ **RAID 不是備份**，RAID 擋硬體故障，不擋誤刪、勒索軟體、機房整個沒了。
> 備份策略見 [[090-03-04-guide-應用安全-備份災難復原與入侵應變]]。

#### 快取策略

| 設定 | 選項 | 建議 | 星號 |
| --- | --- | --- | --- |
| **寫入策略** | Write Back / Write Through | ★★★★★ **有電池／超級電容（BBU／FBWC）且健康** → Write Back（快很多）；**沒有或電池壞掉** → 必須 Write Through | ★★★★★ |
| **讀取策略** | Read Ahead / No Read Ahead | 循序讀多 → Read Ahead | ★★★ |
| **磁碟快取（Disk Cache）** | Enabled / Disabled | ★★★★ 一般 **Disabled**（磁碟自己的快取沒有電池保護，斷電會掉資料） | ★★★★ |

> [!danger] ★★★★★ 電池壞掉時卡會自動退回 Write Through，效能會突然變很慢
> 這是「系統突然變慢」最常見的硬體原因之一，而且**沒有人會聯想到 RAID 卡電池**。
> ★★★★ 把「RAID 卡電池／超級電容狀態」列入 [[040-02-10-guide-機房-機房巡檢與紀錄]] 的每月巡檢項目。
> **強制在電池壞掉時維持 Write Back，斷電就是掉資料**，不要這樣做。

#### 初始化：Fast vs Full

| 方式 | 做什麼 | 耗時 | 什麼時候用 |
| --- | --- | --- | --- |
| **Fast Initialization**（快速） | 只清掉開頭的中繼資料 | 幾秒 | ★★★ 趕時間、之後會做 Consistency Check |
| **Full / Background Initialization**（完整） | 把整個陣列寫過一遍、建立同位一致性 | 數小時～數天（依容量） | ★★★★ **正式環境建議做完整初始化** |

> [!danger] ★★★★★ 建立虛擬磁碟會清除磁碟上所有資料
> 這是**不可逆**的操作。對已經有資料的磁碟按下 `Create Virtual Disk`，
> 資料就沒了。★★★★★ **對舊機器、換下來的磁碟操作前，一定要先確認上面沒有還要的資料。**

### ★★★★★ 韌體更新：順序與風險

> [!danger] ★★★★★ 韌體更新是最容易把機器變磚的操作
> 更新過程中**斷電、拔線、按重開機 = 機器可能永久損壞**，要送修換主機板。
> 這不是「不小心的話會有點麻煩」，是**真的救不回來**。

#### 什麼時候該更新韌體

| 情境 | 該不該更新 | 說明 |
| --- | --- | --- |
| **新機上架，還沒上線** | ★★★★★ **應該，而且要一次更到底** | 這是最安全的時機，出問題重來就好 |
| 有明確的**資安漏洞公告**且該漏洞可被利用 | ★★★★ 應該，排定變更時段 | 走 [[100-02-08-guide-維運-變更管理流程]] |
| 廠商指出**你遇到的故障**由該版韌體修正 | ★★★★ 應該 | 保留原版檔案以便回退 |
| 「看到有新版本」 | ★★★★★ **不要** | 沒有理由就不要動正式環境的韌體 |
| **正式環境上線中、沒有停機時段** | ★★★★★ **絕對不要** | 韌體更新常需要重開機 |
| **有硬體正在故障、陣列正在重建** | ★★★★★ **絕對不要** | 見下方 |

> [!danger] ★★★★★ 四個「絕對不能更新韌體」的時刻
> 1. **RAID 陣列正在重建（rebuild）或初始化** → 中斷會導致陣列毀損、資料全失
> 2. **有電源路徑處於單邊供電**（一顆 PSU 壞了、一路 PDU 在維修）→ 更新中掉電就變磚
> 3. **UPS 正在放電或電池異常** → 同上
> 4. **你沒有帶外管理可用**（BMC 壞掉、管理網路不通）→ 更新後開不起來就要跑機房，
>    而且看不到畫面完全無法判斷

#### ★★★★★ 更新順序

一般建議的順序（**若廠商文件指定其他順序，以廠商文件為準**）：

```text
① BMC 韌體（iDRAC / iLO / IPMI）
     └─ 先更新它，後面才有可靠的遠端管理與更新工具
          ▼
② BIOS / UEFI
     └─ 更新後通常要冷重啟一次
          ▼
③ CPLD / 背板 / 電源供應器韌體（如果廠商有出）
          ▼
④ RAID 卡 / HBA 韌體
          ▼
⑤ 網路卡 / HBA / 光纖卡韌體
          ▼
⑥ 磁碟韌體（SSD / HDD）
     └─ ★★★★ 風險最高，非必要不做
          ▼
⑦ 全部完成後：冷重啟（拔電或 BMC 冷開機），驗證所有元件版本
```

> [!tip] 實務建議 ★★★★★ 用廠商的整包更新方式，不要一片片手動刷
> - **Dell**：Lifecycle Controller 的 **Firmware Update**，或 **Dell Repository Manager**
>   產生的更新包，會自動處理相依性與順序
> - **HPE**：**Service Pack for ProLiant（SPP）** 的 Smart Update Manager（SUM）
> - **Lenovo**：**XClarity Essentials / UpdateXpress**
>
> 這些工具**知道正確的更新順序與版本相依關係**，比人工判斷可靠得多。

#### 更新前的準備（★★★★★ 一項都不能少）

```text
□ 備份 BIOS 設定與 BMC 設定（匯出設定檔）
□ 備份 RAID 卡設定（記錄陣列組態，至少截圖）
□ 記錄目前所有元件的版本號（更新失敗要知道回退到哪一版）
□ 下載「目前版本」的韌體檔案（回退用）★★★★★ 很多人只下載新版
□ 確認兩路電源都正常
□ 確認 RAID 沒有在重建、沒有磁碟預警
□ 確認帶外管理連得上
□ 確認有停機時段，並已通知使用者
□ 現場或遠端有人可以處理（不要按下去就下班）
```

> [!danger] ★★★★★ 不是每一種韌體都能降版
> 部分 BIOS／BMC 韌體**設有防降版保護（anti-rollback）**，更新上去就回不來。
> ★★★★ 更新前務必在 Release Notes 確認「是否支援降版」，
> 以及有沒有「必須先更新到某中間版本」的跳版限制。

## 完整實戰範例

以下是一台 **2U 機架伺服器**從貨到交機的完整流程。
情境設定（依你的環境調整）：

| 項目 | 設定值 |
| --- | --- |
| 資產編號 | `SRV-APP-021` |
| 機櫃／U 位 | `R03`，第 20～21 U |
| 管理網段 | `10.99.10.0/24`，gateway `10.99.10.254`，VLAN 99 |
| BMC IP | `10.99.10.21`，主機名 `bmc-srv-app-021` |
| 業務網段 | `10.10.20.0/24` |
| 磁碟配置 | 2× SSD 做 RAID 1（系統）＋ 6× HDD 做 RAID 6（資料）＋ 1 顆 hot spare |
| 用途 | 應用伺服器（要跑 KVM 虛擬機） |

### 第 1 步：到貨驗收

```text
□ 外箱無擠壓、防倒標籤未變色 ................ 通過（已拍照）
□ 序號 XXXXXXX 與出貨單一致 ................. 通過
□ CPU 2 顆、記憶體 8×32GB、SSD 2、HDD 7 ..... 通過（開箱後逐一點數）
□ 滑軌組完整、左右成對 ...................... 通過
□ 電源線 2 條 C13-C14 ....................... 通過
□ iDRAC Enterprise 授權卡 ................... 通過
□ 出廠密碼標籤已拍照存進密碼保管系統 ......... 完成，標籤已撕下收好 ★★★★★
```

填 `_表單範本/020-02-01-新機建置驗收表.docx` 並拍照存檔。

### 第 2 步：滑軌與上架

```text
1. 對照機櫃 U 位圖，在 R03 前後立柱標記第 20U 起始位置
2. 確認滑軌左右（印字 LEFT/RIGHT）
3. 先扣後立柱 → 再拉伸扣前立柱 → 兩端各搖三下確認卡實
4. 兩人抬機，由下往上滑入，聽到卡榫扣住的聲音
5. 鎖上前面板耳片螺絲（★★★ 不鎖螺絲的話拉出來時可能整台滑出）
6. 前後各留一格空 U，貼上機櫃面板標籤「SRV-APP-021 / 20-21U」
```

### 第 3 步：接線

```text
接地線  → 機櫃接地銅排
PSU1    → PDU-A  插座 12   （A 路，UPS-A）  ★★★★★
PSU2    → PDU-B  插座 12   （B 路，UPS-B）  ★★★★★
iDRAC   → SW-MGMT-01 Gi1/0/21（管理 VLAN 99）★★★★★
NIC1    → SW-CORE-01 Gi1/0/21（業務 VLAN 20）
NIC2    → SW-CORE-02 Gi1/0/21（業務 VLAN 20，做 bonding）
```

每條線兩端貼標籤，填 `_表單範本/040-02-04-線路標示紀錄.docx`。

驗證電源冗餘（★★★★ 這一步很多人跳過）：

```text
① 兩顆 PSU 都亮綠燈
② 拔掉 PSU1 的電源線 → 主機不能斷電，PSU1 燈變橘／滅，BMC 應該發出告警
③ 插回 PSU1，等 30 秒
④ 拔掉 PSU2 → 同樣不能斷電
⑤ 插回 PSU2，確認兩顆都恢復綠燈、告警清除
```

> [!danger] ★★★★★ 這個測試只能在「還沒上線」的時候做
> 上線後拔電源線測試 = 拿正式服務賭。要驗證就在交機前做完。

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★ 主機推不進滑軌，差一點點 | 左右滑軌沒有裝在同一 U 位；或滑軌左右裝反 | 退出來重新對照 U 位刻度，確認滑軌上的 `LEFT`／`RIGHT` 印字 |
| ★★★★★ 主機推到一半整支滑軌掉下來 | 滑軌後端卡榫沒有真的扣進方孔 | ★★★★★ 立刻停止，兩人扶住取下，重裝並用力搖晃確認兩端都卡實 |
| ★★★★★ BMC 完全連不上，ping 不通 | ① `NIC Selection` 選成 Dedicated 但線接在 LOM 埠<br>② 交換器埠 VLAN 設錯<br>③ BMC 還在開機 | 對照專用管理埠位置（機身有小扳手或 `MGMT` 圖示）；查交換器埠 VLAN；等 60 秒再試 |
| ★★★★ BMC 通了但網頁打不開 | 瀏覽器擋自簽憑證／舊 TLS 版本；BMC Web 服務當掉 | 換瀏覽器試；`ipmitool mc reset cold` 重啟 BMC（★★★ 主機不會關機，但會斷所有 BMC 連線） |
| ★★★★★ 密碼標籤撕掉了但還沒改密碼，現在進不去 | 出廠隨機密碼只印在標籤上 | ★★★★★ 機身另一處可能有備份標籤；沒有的話**只能進 BIOS 重設 BMC 密碼**（需停機）或聯絡原廠 |
| ★★★★ `ipmitool` 回 `Could not open device at /dev/ipmi0` | 核心模組沒載入 | `sudo modprobe ipmi_si ipmi_devintf`，並寫進 `/etc/modules-load.d/` |
| ★★★★ `ipmitool lan print 1` 回 `Invalid channel` | 該機型 LAN channel 不是 1 | 用迴圈試 1／2／3／8，找到有回應的那個 |
| ★★★★★ 裝完 OS 開不了機，直接跳到 BIOS | ① Boot Mode 與安裝時不一致<br>② Boot Sequence 還停在虛擬光碟<br>③ UEFI 開機項目沒建立 | 確認 Boot Mode；把本機磁碟拉到第一順位；★★★★★ 模式不一致要重裝 |
| ★★★★ 開機找不到磁碟 | RAID 尚未建立虛擬磁碟；或 RAID 卡在 HBA 模式但 OS 沒有驅動 | 進 RAID 設定確認有 VD；HBA 模式要確認 OS 內建驅動支援 |
| ★★★★★ 系統突然變很慢，找不到原因 | RAID 卡電池／超級電容故障，快取自動退回 Write Through | `perccli64 /c0/bbu show`（或 `ssacli` 對應指令）檢查電池狀態，更換電池模組 |
| ★★★★ 虛擬機／容器建不起來，說沒有虛擬化支援 | BIOS 的 VT-x／AMD-V 沒開 | `grep -c -E 'vmx\|svm' /proc/cpuinfo` 回 0 → 進 BIOS 開啟，需**冷重啟**（暖開機可能不生效） |
| ★★★★ PCIe 直通失敗，IOMMU group 找不到 | VT-d／IOMMU 沒開；或核心參數沒加 | BIOS 開 VT-d；核心參數加 `intel_iommu=on`（AMD 為 `amd_iommu=on`） |
| ★★★★★ 韌體更新後開機黑畫面 | 更新失敗或版本不相容 | ★★★★★ **不要反覆斷電重試**；用 BMC 的復原模式（部分機型有雙 BIOS／recovery image）；不行就聯絡原廠 |
| ★★★★ 記憶體容量比訂單少 | 有一條沒插好、插槽順序錯誤、或該條故障 | `sudo dmidecode -t memory` 逐槽對照；重插；仍缺就報修 |
| ★★★★ 開機一直有嗶聲／面板橘燈 | 硬體異常（記憶體、電源、風扇、溫度） | 從 BMC 讀取 SEL：`sudo ipmitool sel list`，依事件內容處理 |
| ★★★★ Secure Boot 開啟後某些驅動載不起來 | 第三方 / DKMS 模組未簽章 | 先關閉 Secure Boot 確認是不是這個原因；要用就得建立自己的 MOK 簽章流程 |
| ★★★★ 兩顆 PSU 有一顆一直亮橘燈 | 該路 PDU 沒電、線沒插好、PSU 故障 | 換插座測試 → 換線測試 → 都不行就是 PSU 故障，報修（★★★★ **熱插拔更換前確認另一顆是好的**） |
| ★★★ 風扇轉速一直很高、噪音大 | 進風溫度過高；有插未知的 PCIe 卡導致 BIOS 拉高風扇；擋板缺失 | 查 [[040-02-02-guide-機房-空調系統與溫溼度監控]]；補上空槽擋板；檢查 BIOS 風扇策略 |
| ★★★★★ BMC 日誌時間全部不對 | NTP 沒設定或設錯 | 立刻修正 NTP，★★★★★ **時間錯誤的日誌在資安事件調查時形同無效** |

排查 BMC 硬體事件的標準三步：



## 安全性注意事項

> [!danger] ★★★★★ 帶外管理介面絕對不可以直接接對外網路
> 這是本篇唯一一條沒有例外的規則。BMC 的權限高於作業系統，
> 而它的防護能力遠低於作業系統。**只能放在獨立管理網段，只能從跳板機進入。**
> 不做 NAT、不做 port forwarding、不開放任何來自 Internet 的連線。

> [!danger] ★★★★★ 出廠密碼一定要在上架當天改掉
> 舊機型的 `root/calvin`、`ADMIN/ADMIN` 是公開資訊，掃描器第一個試。
> 新機型的隨機密碼印在機身標籤上，**任何進得了機房的人都看得到**。
> 改完密碼、撕下標籤、存進密碼保管系統，三件事一起做。

| 項目 | 做法 | 星號 |
| --- | --- | --- |
| **管理網段隔離** | 獨立 VLAN、ACL 限制來源、無 Internet 預設路由 | ★★★★★ |
| **改掉所有出廠密碼** | BMC、BIOS、RAID 卡（部分機型有密碼） | ★★★★★ |
| **具名帳號、不共用** | 每人一組帳號，離職即停用 | ★★★★★ |
| **停用不必要的服務** | Telnet、IPMI over LAN（改用 Redfish 後）、SNMP v1/v2c、VNC | ★★★★★ |
| **IPMI 的先天弱點** | ★★★★★ IPMI 2.0 的 RAKP 驗證有已知的雜湊外洩問題、cipher suite 0 等同無驗證。**能用 Redfish（HTTPS）就不要用 IPMI over LAN** | ★★★★★ |
| **憑證換成內部 CA 簽發** | 避免大家習慣忽略憑證警告 | ★★★★ |
| **韌體更新納入弱點管理** | BMC 韌體漏洞要跟 OS 一樣列管，見 [[090-07-03-guide-資安實踐-弱點與修補管理流程]] | ★★★★★ |
| **BMC 日誌外送** | Syslog 送到集中日誌，BMC 本身空間會覆蓋 | ★★★★ |
| **虛擬媒體管理** | ★★★★ 不用時 **Disconnect**，掛著的 ISO 是可寫入的攻擊面 |★★★★ |
| **實體安全** | 機櫃上鎖、機房門禁、BIOS 密碼防止有實體接觸者改開機順序 | ★★★★★ |
| **前面板存取控制** | 有些機型可以從機身面板重設 BMC 密碼 → 依政策鎖住 | ★★★★ |
| **報廢／維修前清除** | 送修或報廢前清除 BMC 設定與帳號、清除磁碟資料 | ★★★★★ |

> [!danger] ★★★★★ 送修前一定要清乾淨
> 主機板送修 = BMC 裡的帳號密碼、網路設定、日誌全部跟著出去。
> 磁碟送修或報廢 = 上面的資料跟著出去。
> ★★★★ 送修前的資料清除程序寫在 [[040-02-12-guide-機房-設備生命週期管理]]。

> 包含 IP、主機名稱、要建立哪些帳號與權限、要關閉哪些服務。
>
> **參考答案**
> - IP：`172.16.99.x`（依 IP 配置表取號），mask `255.255.255.0`，gw `172.16.99.254`
> - NIC Selection：**Dedicated**（★★★★★），DHCP：**Disabled**
> - 主機名稱：`bmc-<資產編號>`，例如 `bmc-srv-app-021`
> - NTP：`172.16.99.10`，時區設定正確
> - 帳號：① 停用或改名預設帳號 ② `opsadmin`（Administrator，具名）
>   ③ `monitor`（Read-Only，給監控用）④ 緊急帳號（平時停用，密碼封存）
> - 關閉：Telnet、SNMP v1/v2c、VNC、IPMI over LAN（改用 Redfish 後）
> - 憑證：內部 CA 簽發，SAN 含 FQDN 與 IP
> - Syslog 外送、SNMP v3 trap、Session timeout 15 分鐘

> [!question]- 練習 2：判斷這台機器的 RAID 規劃有沒有問題
> 某台檔案伺服器：12 顆 16 TB HDD，全部做成一組 RAID 5，沒有 hot spare，
> RAID 卡電池顯示 `Degraded` 但寫入策略被手動鎖定為 Write Back。
> 請指出所有問題並給出建議。
>
> **參考答案**
> 1. ★★★★★ **大容量碟做 RAID 5**：16 TB × 12 顆，重建時間極長且期間毫無保護，
>    重建中再壞一顆就全毀 → 應改為 **RAID 6 或 RAID 10**
> 2. ★★★★ **沒有 hot spare**：壞碟後要等人到現場才開始重建 → 至少配一顆 global hot spare
> 3. ★★★★★ **電池 Degraded 卻鎖定 Write Back**：斷電時快取中的資料會遺失 →
>    立刻改回 Write Through 並更換電池模組
> 4. ★★★★ **單一大陣列**：一組 12 顆的陣列任何一次重建都是全部磁碟一起承壓 →
>    考慮切成兩組較小的 RAID 6
> 5. ★★★★★ 補充：**RAID 不是備份**，要確認有獨立的備份機制

> [!question]- 練習 3：寫出一台正式環境伺服器的韌體更新前檢查
> 這台機器要在週六凌晨 2:00 更新 BIOS 與 BMC 韌體。列出你在按下更新之前
> 必須確認的所有項目，以及三個「發現了就要中止更新」的情況。
>
> **參考答案**
> 更新前確認：備份 BIOS/BMC 設定、記錄目前所有版本、下載目前版本韌體檔（回退用）、
> 兩路電源都正常、RAID 沒有在重建、無磁碟預警、BMC 連得上、
> 已通知使用者且在核准的停機時段內、現場或遠端有人待命。
>
> ★★★★★ 中止更新的三個情況（任一成立就停）：
> 1. RAID 正在重建或初始化
> 2. 只有單邊電源可用（一顆 PSU 壞、或一路 PDU 在維修）
> 3. 帶外管理連不上（更新後開不起來就完全無法判斷）

> [!question]- 練習 4：設計上架驗收清單的簽核流程
> 你的機關有採購人員、機房管理員、系統管理員三種角色。請設計上架驗收的
> 分工與簽核順序，並說明哪些項目「沒過就不能簽收」。
>
> **參考答案**
> - **採購人員**：核對出貨單、序號、規格與訂單一致、保固與授權登錄
> - **機房管理員**：U 位、載重、電源迴路分配、線材標籤、環境影響評估
> - **系統管理員**：BMC 設定、BIOS 設定、RAID、韌體、OS 安裝與初始安全設定
>
> ★★★★★ 沒過就不能簽收的項目：序號不符、規格短缺、外觀嚴重損傷、
> 雙電源實測不通過、BMC 出廠密碼未改、BMC 出現在非管理網段。

> [!question]- 練習 5：解釋一個現場情境
> 半夜某台伺服器沒有回應，ping 不通、SSH 連不上。你連上它的 iDRAC，
> 發現 iDRAC 網頁正常、可以看到溫度與電源狀態一切正常，
> 虛擬主控台畫面停在一個 kernel panic 訊息。請說明接下來的處置順序，
> 以及這個情境證明了什麼。
>
> **參考答案**
> 處置順序：① 先把畫面**截圖存證**（重開機就沒了）② 到 BMC 看 SEL 有沒有硬體事件
> ③ 記錄事件到工單 ④ 依業務衝擊決定是否立即 `power cycle` ⑤ 開機後撈 kernel log
> （`journalctl -k -b -1`）分析原因。
>
> ★★★★★ 這個情境證明了帶外管理的價值：**OS 完全掛掉，但你還是看得到畫面、
> 讀得到硬體狀態、可以遠端重開機**，不用半夜開車去機房。
> 這也就是為什麼虛擬 KVM 授權該在採購時就編進預算。

## 小測驗

Q1. （是非）BMC（iDRAC／iLO）只有在主機開機時才會運作。

Q2. （選擇）以下哪一個是把 BMC 接到網路上時**最重要**的原則？
　　(A) 用固定 IP 而不是 DHCP
　　(B) 放在獨立管理網段，不可直接連到 Internet
　　(C) 一定要換成內部 CA 簽發的憑證
　　(D) 主機名稱要跟資產編號一致

Q3. （簡答）為什麼 `NIC Selection` 應該選 `Dedicated` 而不是 `Shared`？

Q4. （選擇）新機的 Boot Mode 設定為什麼必須在裝 OS **之前**就決定？
　　(A) 之後改會讓 BIOS 密碼失效
　　(B) 之後改系統開不起來，等於要整台重裝
　　(C) 之後改會清除 RAID 設定
　　(D) 之後改會讓韌體降版

Q5. （這行指令會發生什麼）`grep -c -E 'vmx|svm' /proc/cpuinfo` 回傳 `0`，代表什麼？

Q6. （簡答）12 顆 16 TB 硬碟要做陣列，為什麼不建議 RAID 5？請講出兩個理由。

Q7. （是非）RAID 卡電池壞掉時，把寫入策略手動鎖定在 Write Back 可以維持效能，是可以接受的臨時做法。

Q8. （選擇）韌體更新的建議順序，哪一個排在**最前面**？
　　(A) BIOS
　　(B) RAID 卡
　　(C) BMC（iDRAC／iLO）
　　(D) 磁碟

Q9. （簡答）舉出三個「絕對不能開始更新韌體」的情況。

Q10.（這行指令會發生什麼）在正透過 `ipmitool -I lanplus -H 10.99.10.21 ...` 遠端操作時，
　　執行 `ipmitool lan set 1 ipaddr 10.99.20.21` 會發生什麼事？

> [!question]- 測驗答案
> **Q1.** ★★★★★ **錯**。BMC 只要**電源線插著就在運作**，主機關機也一樣。
> 這正是它能「主機掛掉還連得進去」的原因。見〈觀念說明〉的 BMC 特性表。
>
> **Q2.** ★★★★★ **(B)**。其他三項都重要，但 (B) 是唯一沒有例外的硬規則 ——
> BMC 權限高於 OS 而防護能力低於 OS，暴露在 Internet 等於把最高權限掛在網路上。
> 見〈為什麼帶外管理介面絕對不可以接對外網路〉。
>
> **Q3.** ★★★★★ 選 `Shared`／`LOM` 會讓 BMC 流量與業務流量走**同一條實體線**，
> 管理網段的隔離就破功了。只有機型完全沒有專用埠時才用 shared，
> 且必須用 VLAN tag 打到管理 VLAN 並在交換器做嚴格 ACL。見〈步驟五〉。
>
> **Q4.** ★★★★★ **(B)**。以 Legacy 安裝的系統改成 UEFI 之後開不起來（反之亦然），
> 這不是調設定，是整台重裝。所以 Boot Mode 要排在 BIOS 設定的第一項。
> 見〈UEFI 與 Legacy BIOS〉。
>
> **Q5.** ★★★★★ 代表 **BIOS 裡的虛擬化功能（VT-x／AMD-V）沒有開啟**，
> 這台機器跑不了 KVM／Hyper-V／ESXi／Proxmox。要進 BIOS 開啟
> `Virtualization Technology`，並且**做冷重啟**（暖開機可能不生效）。見〈虛擬化相關〉。
>
> **Q6.** ★★★★★ 任兩個：①RAID 5 只能壞一顆，重建期間**完全沒有保護**；
> ②大容量碟的重建時間極長（數十小時到數天），風險窗口太大；
> ③重建要對所有剩餘磁碟做全碟讀取，同批磁碟很可能接著壞；
> ④重建期間遇到不可修復讀取錯誤（URE）就可能重建失敗。見〈RAID 等級選擇〉。
>
> **Q7.** ★★★★★ **錯**。電池是快取的斷電保護，電池壞了還開 Write Back，
> **斷電就是直接掉資料**。正確做法是**立刻改回 Write Through**（會慢，但資料是完整的）
> 並更換電池模組。見〈快取策略〉。
>
> **Q8.** ★★★★ **(C) BMC**。先把 BMC 更到位，後面才有可靠的遠端管理與更新工具可用。
> 順序是 BMC → BIOS → CPLD/背板/PSU → RAID/HBA → 網卡 → 磁碟。見〈更新順序〉。
>
> **Q9.** ★★★★★ 任三個：①RAID 正在重建或初始化 ②只有單邊電源可用
> ③UPS 正在放電或電池異常 ④帶外管理連不上 ⑤正式環境上線中且沒有停機時段。
> 見〈四個「絕對不能更新韌體」的時刻〉。
>
> **Q10.** ★★★★ 會把**你自己的連線斷掉**。`-H` 代表你正在走 BMC 網路遠端操作，
> 改掉它的 IP 等於當場切斷這條路徑，而且指令可能只執行了一半。
> ★★★★★ **BMC 網路設定只能從主機本機（in-band，不加 `-H`）改，或到現場改。**
> 見〈做法 B〉的 danger 提示。
