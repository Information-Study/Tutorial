# UPS 電池維護與更換

> [!abstract] 這篇你會學到
> - 為什麼 UPS 電池是整個機房裡**唯一會自己老化、而且老化時完全不吭聲**的元件
> - ★★★★★ **溫度是電池壽命的頭號殺手** —— 機房多熱一點，電池就少活一半
> - 三種健康度判定方法怎麼選：**狀態旗標**（免費但遲鈍）／**內阻量測**（快但要儀器）／
>   **放電測試**（最準但有風險）
> - ★★★★ 用 `upsc` 的四個欄位做**趨勢追蹤**，在電池報廢前三個月就知道要編預算
> - ★★★★★ 一份可以直接印出來照做的**電池更換 SOP**，含帶電作業安全規則
> - 換完之後**一定要做的三件事**：容量校正、續航重測、基準值重新歸檔
> - 台灣的**廢鉛蓄電池處理法規責任**在哪裡，以及不能自己丟的理由
> - 把電池告警接進監控，讓 `RB`、續航衰退、溫度異常都會自己叫人

> [!warning] 未實機驗證
> ★★★★★ **本篇不列任何具體的電池規格數字當作通則。**
>
> 電池的設計壽命、浮充電壓、內阻基準值、溫度補償係數、更換週期，
> **每一款電池、每一款 UPS 都不一樣**，而且同型號不同批次也可能不同。
> 本篇提供的是**判定方法與流程**，所有數值請以下列來源為準（優先序由高到低）：
>
> 1. 你那顆電池的**原廠規格書（datasheet）**
> 2. UPS 原廠的**維護手冊**
> 3. 電池供應商／維護廠商提供的**書面建議值**
>
> 文中出現的數字（如「約 25°C」「80% 容量」）是**業界常見的通用參考點**，
> 用來說明判定邏輯，不是你可以直接套用的規格。
> 廠商工具（原廠電池測試軟體、內阻計）的操作步驟因型號差異極大，
> **本篇未在特定機型上實機驗證**。
>
> **法規部分**：台灣的廢棄物處理規定會修訂，本篇只講「責任歸屬與流程骨架」，
> ★★★★★ **實際的廢棄物代碼、申報欄位、清除機構資格，一律以環境部現行公告
> 與你委託的合格清除處理機構所提供的書面資料為準，不要憑印象填。**

## 觀念說明

### ★★★★★ 電池是機房裡最特別的一種元件

```
硬碟壞掉    → SMART 會警告、RAID 會降級、監控會叫  ★ 你會知道
風扇壞掉    → 溫度上升、IPMI 會告警                ★ 你會知道
電源供應器壞 → 冗餘電源會告警                       ★ 你會知道
交換器壞掉  → 網路不通，全公司都知道                ★ 你一定知道

★★★★★ UPS 電池老化 → 什麼都不會發生
                      面板還是綠燈
                      upsc 還是回 OL
                      battery.charge 還是 100
                      ────────────────────────
                      直到停電那一天，它撐了 40 秒就沒電
```

★★★★★ **「電池能不能撐」這件事，只有在真的放電時才會被驗證。**
而真的放電的那一天，就是你最不想出事的那一天。

這推導出本篇唯一的核心結論：

> [!danger] ★★★★★ 電池必須「主動」檢查，不能「被動」等告警
> 依賴 `ups.status` 出現 `RB` 才換電池，等同於**依賴 UPS 自己承認自己壞了**。
>
> - `RB` 的判定邏輯是廠商定的，**通常很保守**，出現時電池往往已經衰退很久
> - 有些機型只在**執行自我測試時**才更新 `RB`，如果你從不測試，它永遠不會亮
> - ★★★★★ **有些低階機型根本不回報 `RB`**
>
> 正確做法：**定期主動測試 + 趨勢追蹤 + 到期換**，三者缺一不可。

### VRLA 電池的基本認識 ★★★

機房 UPS 幾乎清一色用 **VRLA（Valve-Regulated Lead-Acid，閥控式鉛酸電池）**，
也常被叫做 SLA（Sealed Lead-Acid）或「免維護電池」。

| 特性 | 說明 | 對維運的意義 |
| --- | --- | --- |
| ★★★ **密封、免加水** | 不像老式開放式電池要補充電解液 | 「免維護」≠「免檢查」，★★★★ 這是最大的誤解 |
| ★★★ **有洩壓閥** | 內壓過高時排氣 | 排氣＝電解液流失＝容量永久損失，不可逆 |
| ★★★★★ **怕熱** | 高溫加速內部化學反應與極板腐蝕 | **溫度是壽命的頭號變數**，見下一節 |
| ★★★★ **怕深放** | 放到很低再充回來會傷害極板 | 每次深度放電都在扣壽命 |
| ★★★ **會自放電** | 不接負載也會慢慢掉電 | 備品電池要定期充電，不能買回來擺三年 |
| ★★★★ **老化不可逆** | 沒有「保養一下就恢復」這回事 | ★★★★★ 判定該換就是該換，不要期待它變好 |

`upsc` 裡的 `battery.type` 通常會顯示：

```bash
upsc ups1@localhost battery.type
```
```text
PbAc
```
★★ `PbAc` = Lead-Acid（鉛酸）。若顯示 `Li-ion` 則是鋰電池機型，
維護與更換方式完全不同（不在本篇範圍，請依原廠手冊）。

### ★★★★★ 溫度：影響壽命的頭號因素

這是本篇**最重要的一段**。

```
                     電池壽命
   長 ▲
      │  ╲
      │    ╲
      │      ╲                 ★★★★★ 業界常用的經驗法則：
      │        ╲                 環境溫度每高於額定溫度約 10°C，
      │          ╲               VRLA 電池的預期壽命大約「減半」
      │            ╲
      │              ╲___
   短 └──────────────────────►  環境溫度
        額定    +10°C   +20°C
        (常見約 25°C)
```

> [!warning] ★★★★ 這條「10°C 減半」是經驗法則，不是精確公式
> 它源自化學反應速率隨溫度上升的通則（Arrhenius 關係），**方向絕對正確**，
> 但確切的係數、額定溫度基準點，**每款電池的規格書都不同**。
>
> ★★★★★ 用它來做**決策方向**（「機房太熱要處理」）是對的；
> 用它來**精算「我的電池還剩幾個月」是錯的**。
> 精算要靠內阻量測與放電測試。

**這條法則的三個實務推論 ★★★★★**：

| 推論 | 說明 | 該做什麼 |
| --- | --- | --- |
| ① ★★★★★ **省空調錢＝花電池錢** | 機房溫度調高幾度省下的電費，可能遠低於電池提早更換的成本 | 電池區溫度**不要**跟著整機房調高，見 [[040-02-02-guide-機房-空調系統與溫溼度監控]] |
| ② ★★★★★ **電池不要放在熱點** | 機櫃底部若剛好是回風區或旁邊有高發熱設備，電池區溫度會比機房均溫高很多 | **在電池位置量測溫度**，不要只看機房中央的溫度計 |
| ③ ★★★★ **溫度紀錄要留** | 事後檢討「為什麼電池兩年就壞」時，唯一的證據就是溫度趨勢 | 溫度納入巡檢紀錄（[[040-02-10-guide-機房-機房巡檢與紀錄]]） |

**量測位置 ★★★★**：

```
    ┌───────── 機櫃 ─────────┐
    │ ...                    │
    │                        │
    │  U03 ┌──────────────┐  │
    │  U02 │              │  │  ← ★★★★ 溫度計放這裡（電池匣正面進風處）
    │  U01 │   UPS + 電池  │  │     而不是機房中央或櫃頂
    │      └──────────────┘  │
    └────────────────────────┘
           ★★★ 同時記錄「機房均溫」與「電池區溫度」，兩者的差值本身就是資訊
```

有些 UPS 會回報電池溫度：

```bash
upsc ups1@localhost | grep -i temp
```
```text
battery.temperature: 27.5
ups.temperature: 31.0
```

> [!warning] ★★★ 不是每台都有溫度欄位
> 沒有 `battery.temperature` 的機型很常見。此時：
> - 用機櫃內獨立的溫溼度感測器（放在電池區）
> - 或至少在每次巡檢時用手持式溫度計量一次並記錄

### 除了溫度之外的五個壽命殺手 ★★★★

| # | 因素 | 機制 | 你能做什麼 |
| --- | --- | --- | --- |
| ① ★★★★★ **深度放電次數** | 每次放到很低都會傷害極板 | 設定合理的 `battery.charge.low`，讓主機提早關機而不是把電榨乾；用 killpower 避免關機後繼續放電（[[040-02-06-svc-機房-UPS安裝與監控設定]]） |
| ② ★★★★ **頻繁的淺放電** | 市電品質差、頻繁瞬斷 | 查上游供電品質；`upsc` 的 `input.voltage` 波動與 `TRIM`／`BOOST` 出現頻率是線索 |
| ③ ★★★★ **充電電壓不當** | 過充→失水、鼓脹；欠充→硫化 | 這是 UPS 充電器的職責，★★★ 但溫度補償失效時會過充，是「熱失控」的前奏 |
| ④ ★★★ **長期不用** | 自放電 + 硫化 | 備品電池至少每半年充電一次；不要買一堆囤著 |
| ⑤ ★★★★ **電池串內不一致** | 串聯電池中最弱的一顆決定整串表現 | ★★★★★ **一次換整串，不要只換壞掉那一顆** |

> [!danger] ★★★★★ 絕對不要混用新舊電池
> 串聯電池組中，充放電電流是**共通的**。把一顆新電池放進舊電池串裡：
>
> ```
> 充電時：新電池內阻低 → 較早充飽 → 之後持續被過充 → 失水鼓脹
> 放電時：舊電池先沒電 → 新電池被舊電池「反向充電」 → 極性反轉損壞
> 結果：★★★★★ 新電池的壽命被拉到跟舊電池一樣短，甚至更短
> ```
>
> **正確做法：整串一起換，同品牌、同型號、同容量，且盡量同批號。**
> 「只壞一顆，換一顆就好」省下的錢，會在半年後全部賠回去。

### 熱失控（Thermal Runaway）★★★★★

這是 VRLA 電池最危險的失效模式，雖然罕見，但後果嚴重。

```
① 電池老化 / 充電器溫度補償失效
        ▼
② 充電電流偏高 → 電池發熱
        ▼
③ 溫度上升 → 電池內阻下降 → 充電電流「更高」   ★★★★★ 正回饋
        ▼
④ 溫度持續上升 → 電池鼓脹、洩壓閥排氣
        ▼
⑤ 外殼變形、電解液外洩、極端情況冒煙起火
```

★★★★★ **巡檢時看到下列任一現象，立刻停止使用該電池組**：

| 現象 | 嚴重度 | 立即動作 |
| --- | --- | --- |
| ★★★★★ 電池外殼**鼓脹、變形** | 立即危險 | 停用、隔離、通知廠商，**不要嘗試繼續使用** |
| ★★★★★ 電池**發燙**（明顯高於周圍） | 立即危險 | 同上 |
| ★★★★★ 聞到**刺鼻酸味**或看到液體滲出 | 立即危險 | 同上；★ 注意通風，避免吸入 |
| ★★★★ 端子**嚴重腐蝕**（白色／綠色粉狀物） | 高 | 排入近期更換；清潔處理須斷電並戴防護 |
| ★★★★ UPS 面板持續顯示電池異常 | 高 | 依原廠指示處理，排入更換 |

> [!danger] ★★★★★ 發現鼓脹電池的處理原則
> 1. **不要用力扳、不要敲、不要嘗試「壓回去」**
> 2. **不要在旁邊使用明火或會產生火花的工具**
> 3. 立刻通知 UPS 維護廠商，由**原廠或合格廠商**處理
> 4. 若鼓脹嚴重且無法立即處理，考慮**將 UPS 轉為旁路運轉並斷開電池**
>    （★★★★★ 這個動作必須由熟悉該機型的人執行，
>    轉旁路期間機房**完全沒有停電保護**，要有時間管制）
> 5. 全程留下照片紀錄，做為後續求償與檢討的依據

## 安裝或基礎操作

### 三種健康度判定方法 ★★★★★

```
┌────────────────────────────────────────────────────────────────┐
│ 方法 A：狀態旗標（RB）                                          │
│  怎麼做：upsc ups1@localhost ups.status | grep RB              │
│  成本：★ 零（已經有的東西）                                     │
│  風險：★ 無                                                     │
│  準確度：★★ 低 —— 出現時通常已經很晚了                          │
│  頻率：★★★★ 每天（納入日常巡檢）                                │
└────────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────────┐
│ 方法 B：內阻／阻抗量測                                          │
│  怎麼做：專用內阻計，逐顆量測並與基準值比對                      │
│  成本：★★★ 要買儀器（或委外）                                   │
│  風險：★★ 低（不需放電，設備仍受保護）                          │
│  準確度：★★★★ 高 —— 能在容量下降前就發現劣化                    │
│  頻率：★★★★ 每半年～每年                                        │
└────────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────────┐
│ 方法 C：放電（容量）測試                                        │
│  怎麼做：讓 UPS 實際帶載放電，量測實際續航時間或容量             │
│  成本：★★ 中（要停機時間窗與人力）                              │
│  風險：★★★★★ 高 —— 測試期間機房沒有停電保護，                   │
│                    且老化電池可能在測試中直接失效                │
│  準確度：★★★★★ 最高 —— 這是唯一直接證明「撐得住」的方法          │
│  頻率：★★★★ 每年一次，且換完電池後必做                          │
└────────────────────────────────────────────────────────────────┘
```

★★★★★ **三種都要做，而且是互補的**：
A 提供每日的最低限度警覺，B 提供早期預警與趨勢，C 提供最終確認。

### 方法 A：日常狀態檢查（每天）★★★★

```bash
# ★★★★ 每日巡檢的最小集合
upsc ups1@localhost ups.status
```
```text
OL
```

```bash
# 一次撈出四個關鍵欄位
for v in ups.status battery.charge battery.runtime battery.voltage; do
    printf '%-20s %s\n' "$v" "$(upsc ups1@localhost "$v" 2>/dev/null || echo '(無此欄位)')"
done
```
```text
ups.status           OL
battery.charge       100
battery.runtime      2280
battery.voltage      27.3
```

**每天要看的四件事 ★★★★★**：

| 欄位 | 正常長相 | 異常長相 | 判定 |
| --- | --- | --- | --- |
| ★★★★★ `ups.status` | `OL` | 含 `RB` | **電池需更換**，排入更換流程 |
| ★★★★★ `ups.status` | `OL` | 含 `OB` 但市電正常 | 充電器或偵測異常，立刻查 |
| ★★★★ `battery.charge` | 接近 100 | 長期停在 100 以下且不再上升 | 電池無法充飽，衰退中 |
| ★★★★★ `battery.runtime` | 與基準值相近 | **持續下降** | **老化最早、最可靠的指標** |
| ★★★ `battery.voltage` | 穩定在浮充電壓附近 | 明顯偏低或劇烈波動 | 電池串或充電器異常 |

**趨勢比絕對值重要 ★★★★★**：

```bash
#!/bin/bash
# /usr/local/sbin/ups-battery-trend
# 每天記錄一行，長期累積成趨勢；由 systemd timer 每日執行一次
set -u
UPS="ups1@localhost"
LOG="/var/log/ups-battery-trend.csv"

# 第一次執行時寫表頭
[ -s "$LOG" ] || echo "date,status,charge,runtime,batt_voltage,batt_temp,load" > "$LOG"

get() { upsc "$UPS" "$1" 2>/dev/null | head -1; }

printf '%s,%s,%s,%s,%s,%s,%s\n' \
    "$(date +%F)" \
    "$(get ups.status | tr ' ' '|')" \
    "$(get battery.charge)" \

### 方法 B：內阻量測 ★★★★

**原理**：電池老化時，內部極板硫化、腐蝕、電解液減少，都會讓**內阻上升**。
內阻上升通常**早於**容量明顯下降，所以是很好的早期指標。

```
       容量                    內阻
  100% ┤━━━━━━━━╲              ┤              ╱━━━
       │         ╲             │         ╱
       │          ╲            │    ╱
   80% ┤ - - - - - ╲ 報廢線    │╱
       │            ╲          │
       └────────────────► 時間  └────────────────► 時間
                ▲                        ▲
                │                        │
        ★★★ 容量掉到這裡才       ★★★★★ 內阻在更早的時間點
            知道，已經太晚              就開始明顯上升
```

**怎麼做**：

```
準備：★★★★ 電池內阻計（也叫電池測試儀 / 阻抗計）
      ★★★★★ 絕緣柄工具、防護眼鏡、絕緣手套
      ★★★ 電池位置圖與編號表（沒有的話先畫一張）

步驟：
 ① 記錄環境溫度（★★★ 內阻受溫度影響，比較時要在相近溫度下比）
 ② 逐顆量測：內阻值、開路電壓、端子溫度
 ③ 全部記錄在同一張表上（每顆都有固定編號）
 ④ 與「基準值」比對
```

★★★★★ **「基準值」哪裡來？** 三個來源，優先序：

| 優先 | 來源 | 說明 |
| --- | --- | --- |
| 1 ★★★★★ | **這批電池剛裝好時你自己量的值** | 最準。所以**換電池的當天一定要量一次並存檔** |
| 2 ★★★★ | 電池原廠規格書標示的參考內阻 | 次佳，但實際值會有個體差異 |
| 3 ★★★ | 同一串電池中其他顆的平均值 | ★★★★ 用來抓「離群值」很有效 —— 某一顆明顯高於其他顆就是它有問題 |

> [!warning] ★★★★★ 不要在網路上找一個「內阻超過 X mΩ 就該換」的數字直接套用
> 內阻的絕對值與電池容量（Ah）、型號、溫度**強相關**。
> 20Ah 電池與 100Ah 電池的正常內阻差好幾倍。
>
> ★★★★★ **正確的判定是「相對」的**：
> - 與**自己的初始基準值**比，上升超過廠商建議的比例 → 排入更換
> - 與**同串其他顆**比，明顯離群 → 該顆有問題，但要整串換
>
> 具體的百分比門檻請跟你的電池供應商要書面建議值。

**內阻量測紀錄表範例**：

| 電池編號 | 位置 | 開路電壓 | 內阻 | 初裝基準內阻 | 增幅 | 端子溫度 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| B01 | 匣1-左1 | （量測值） | （量測值） | （初裝值） | +8% | （量測值） | ✅ 正常 |
| B02 | 匣1-左2 | | | | +11% | | ✅ 正常 |
| B03 | 匣1-左3 | | | | **+47%** | | ⚠ ★★★★ 離群，整串排入更換 |
| B04 | 匣1-左4 | | | | +9% | | ✅ 正常 |

★★★★ **只要有一顆離群，整串都要排入更換計畫**（見前面「不要混用新舊電池」）。

> [!tip] ★★★ 沒有內阻計怎麼辦
> 選項：
> 1. **委外**：請 UPS 維護廠商在年度保養時一併量測，並要求提供**書面報告與數值**
>    （★★★★ 契約裡要寫明「提供每顆電池的量測數值」，不是只給一句「正常」）
> 2. **共用**：多個單位合購一台，或跟同機關的其他機房借用
> 3. ★★ **退而求其次**：至少每顆量**開路電壓**（三用電表就可以），
>    找出明顯偏低的那顆。準確度遠不如內阻，但聊勝於無

### 方法 C：放電（容量）測試 ★★★★★

這是**唯一能回答「停電時到底能撐幾分鐘」的方法**。

> [!danger] ★★★★★ 放電測試是一次「刻意製造的無保護狀態」
> 測試期間：
> - 機房**完全沒有市電保護**（正在用電池）
> - 如果電池已經嚴重老化，**可能在測試中直接失效** → 整櫃硬斷電
> - 如果此時真的發生市電事故，**沒有任何緩衝**
>
> ★★★★★ **必須做的風險控管**：
> 1. 走**變更管理流程**（[[100-02-08-guide-維運-變更管理流程]]），有核准、有時間窗
> 2. 選在**離峰時段**（例如假日清晨），並事先公告
> 3. **兩人以上在場**，一人操作一人計時記錄，隨時可以中止
> 4. ★★★★★ **測試前先確認所有主機的自動關機設定是正確的**
>    （見 [[040-02-06-svc-機房-UPS安裝與監控設定]]）—— 這樣即使電池提早失效，
>    主機也已經先安全關機了
> 5. 先做**快速測試**確認電池沒有立即問題，再做放電測試
> 6. **設定中止條件**：時間到、電量降到門檻、或任何異常現象出現就立刻恢復市電

**兩種做法**：

| 做法 | 說明 | 適用 |
| --- | --- | --- |
| ★★★ **假負載測試**（廠商執行） | 用專用假負載箱取代真實設備，UPS 帶假負載放電到規定終止條件 | ★★★★★ **最安全也最準**，機房設備完全不受影響；缺點是要委外、要把 UPS 從線上移出 |
| ★★★★ **實際負載測試**（自己執行） | 直接拔市電，讓 UPS 帶真實設備放電，量測到達某個門檻的時間 | 不用委外、測到的是真實條件；★★★★★ 但機房真的在無保護狀態 |

## 進階應用

### 更換週期判定：三個訊號的組合 ★★★★★

不要只用一個指標決定。用下面這張表做綜合判定：

| # | 訊號 | 資料來源 | 權重 |
| --- | --- | --- | --- |
| ① | ★★★★ **服役年限接近廠商標示的設計壽命** | 資產紀錄（[[040-02-11-guide-機房-資訊設備盤點]]） | 中 —— 設計壽命是「理想溫度下」的值，實際往往更短 |
| ② | ★★★★★ **實測續航無法滿足設計需求** | 年度放電測試 | **最高** —— 這是唯一直接的證據 |
| ③ | ★★★★ **內阻明顯上升或有離群顆** | 內阻量測紀錄 | 高 —— 早期預警 |
| ④ | ★★★ **`RB` 旗標出現** | `ups.status` | 中 —— 出現就一定要換，但沒出現不代表沒事 |
| ⑤ | ★★★★★ **外觀異常**（鼓脹／漏液／腐蝕／發燙） | 巡檢 | **絕對** —— 出現任一項立刻停用 |
| ⑥ | ★★★ **累計深度放電次數多** | 停電事件紀錄 | 中 —— 輔助判斷 |
| ⑦ | ★★★★ **環境溫度長期偏高** | 溫度趨勢紀錄 | 高 —— 用來解釋「為什麼提早壞」與調整預期壽命 |

**判定矩陣 ★★★★★**：

```
⑤ 外觀異常                      → 立刻停用，緊急更換
② 續航 < 全部主機關機所需時間×2  → 立刻排更換（最優先）
② 續航 < 設計需求               → 本年度更換
③ 內阻離群 或 ④ RB 出現         → 本年度更換
① 屆齡 + ⑦ 長期高溫             → 提前一年編列預算
只有 ① 屆齡，其他都正常          → ★★★ 加密監測（改成每半年測一次），
                                   但可以延後更換
```

> [!tip] ★★★★ 「屆齡但測試都正常」該不該換？
> 這是機關最常吵的問題。實務建議：
>
> - **關鍵機房**（服務中斷會影響對外業務）→ ★★★★★ **屆齡就換**，
>   不要賭。電池成本遠低於一次停機事故。
> - **次要機房 / 測試環境** → 可以延，但必須**提高測試頻率**
>   （改為每半年做一次放電測試），且要有書面的風險接受紀錄。
>
> ★★★★★ **不管哪一種，都不能「不測也不換」。**

### 預算與採購前置作業 ★★★★

電池更換是**可預期的支出**，應該提前一年編列，不要等到壞了才緊急採購。

| 時間點 | 該做的事 |
| --- | --- |
| ★★★★ 更換前 12 個月 | 依趨勢圖判定「明年要換」，寫進年度預算需求 |
| ★★★★ 更換前 6 個月 | 確認**確切型號、規格、數量**（★★★★★ 拍照記錄電池標籤，不要憑記憶） |
| ★★★★ 更換前 3 個月 | 詢價、確認交期（★★★ 部分型號交期長，要預留） |
| ★★★★★ 更換前 1 個月 | 確認**廢電池處理方式**與**清除機構**已就緒（見後面「廢電池處理」） |
| ★★★ 更換前 2 週 | 排定施工時間窗、送變更申請、通知使用單位 |

**確認規格時要拍下來的資訊 ★★★★★**：

```
電池本體標籤上：
  ┌────────────────────────────────┐
  │ 品牌 / 型號                     │  ← ★★★★★ 最重要
  │ 額定電壓 (V)                    │  ← ★★★★★
  │ 額定容量 (Ah) 與其對應的放電率  │  ← ★★★★★ 「20Ah」要看是幾小時率
  │ 端子型式（F1 / F2 / 螺絲 / 其他）│  ← ★★★★ 買錯裝不上去
  │ 外型尺寸 (長×寬×高)             │  ← ★★★★ 電池匣塞不下就白買了
  │ 製造日期 / 批號                 │  ← ★★★ 用來推算實際服役時間
  └────────────────────────────────┘

UPS 本體上：
  ┌────────────────────────────────┐
  │ UPS 品牌 / 型號 / 序號          │
  │ 原廠電池組料號（RBC 之類的編號）│  ← ★★★★★ 有這個最省事，直接報料號
  │ 電池組串接方式與顆數            │  ← ★★★★
  └────────────────────────────────┘
```

> [!warning] ★★★★ 「相容電池」與「原廠電池組」的取捨
> - **原廠電池組**：貴，但尺寸、接頭、線束都對，裝得上、保固單純
> - **相容／副廠電池**：便宜，但要自己確認尺寸與端子，且可能影響 UPS 保固
>
> ★★★★★ **機關環境的建議**：
> 除非採購規範要求，否則**優先用原廠電池組**。
> 省下的價差如果換來「裝不上去」或「保固失效」，代價高得多。
> 若要用副廠，**採購文件裡要寫明規格與相容性責任由供應商承擔**。

### ★★★★★ 電池更換 SOP

> [!danger] ★★★★★ 動手之前：電池是「永遠帶電」的東西
> **這是本篇最重要的安全提醒。**
>
> UPS 拔掉市電之後，**電池端仍然帶電**，而且是**低內阻、大電流**的電源。
> 一支扳手掉下去跨接正負極，會產生：
> - **瞬間數百甚至上千安培的短路電流**
> - **電弧與高溫**（足以燒熔金屬工具）
> - **飛濺的熔融金屬**
> - 嚴重時電池破裂、電解液噴濺
>
> ★★★★★ **絕對規則**：
> 1. **脫掉所有金屬飾品**：手錶、戒指、手鍊、金屬框眼鏡鏈
> 2. **只用絕緣柄工具**，並且**只用一支**（另一手不要碰任何金屬）
> 3. **戴防護眼鏡與耐酸手套**
> 4. **兩人作業**，一人操作一人監護，監護者手邊要有急救聯絡資訊
> 5. **不要單獨作業，不要在疲勞時作業，不要趕時間**
> 6. ★★★★★ **不熟悉這台機型就不要動手** —— 請原廠或合格廠商執行

**階段 0：準備（更換前一天）★★★★**

```
□ 變更申請已核准，時間窗已確認
□ 新電池已到貨，★★★★★ 拆箱檢查：型號正確、無鼓脹、無漏液、端子完好
□ 新電池已量測開路電壓，★★★★ 每顆都記錄（做為初始基準值）
□ 工具備妥：絕緣柄工具、防護眼鏡、耐酸手套、三用電表、
   （有的話）內阻計、標籤機、相機
□ 廢電池的暫存位置與清運方式已確認
□ 電池位置圖／編號表已備妥（沒有就先畫）
□ ★★★★★ 確認「更換期間機房沒有停電保護」這件事已被主管知悉並接受
□ 使用單位已通知
```

**階段 2：安全斷電 ★★★★★**

> [!danger] ★★★★★ 這一步的做法取決於你的 UPS 型式，不要照抄
> - **有旁路（bypass）的機型**：可以轉旁路，設備繼續供電但**沒有電池保護**
> - **沒有旁路的機型**：必須關閉 UPS 輸出，**所有設備都要先關機**
> - **熱插拔電池匣的機型**：部分機型設計為可在運轉中更換電池，
>   ★★★★★ **但這必須以你手上那台的原廠手冊為準**，
>   不要因為「聽說可以熱插拔」就直接動手
>
> ★★★★★ **不確定就停機做。**
> 為了省一次停機時間而在帶電狀態下亂拆電池，是本篇裡風險最高的行為。

```
2-1 依機型選擇：
    (A) 停機更換（★★★★★ 最安全，建議）
        □ 依關機順序關閉所有主機（可直接用平常的關機 SOP）
        □ 關閉 UPS 輸出
        □ 關閉 UPS 輸入斷路器
        □ ★★★★ 用三用電表確認 UPS 輸出端無電壓
    (B) 轉旁路更換（設備不停機，但無保護）
        □ 依原廠程序轉入維護旁路
        □ ★★★★★ 確認已在旁路，且開始計時（旁路時間越短越好）
        □ 通知所有人「現在無停電保護」
```

**階段 3：拆除舊電池 ★★★★★**

```
3-1 ★★★★★ 拆線順序：先拆「串聯中間」的接線，把電池串「切斷」成低電壓區段
    ── 目的是降低作業時接觸到高電壓的機會
    ── 具體順序依你那台的線束配置，★★★★ 依原廠手冊

3-2 ★★★★★ 拆下的線頭立刻用絕緣膠帶包覆或套上絕緣套
    ── 不要讓裸露的線頭在電池匣裡晃來晃去

3-3 逐顆取出舊電池
    ── ★★★ 電池很重，注意搬運姿勢與落地保護
    ── ★★★★ 取出後立刻在電池上貼「廢電池」標籤，寫上拆除日期
    ── ★★★★★ 舊電池的端子用絕緣膠帶封住（★ 這是運送與暫存的基本要求）

3-4 清潔電池匣
    ── 用乾布清除灰塵
    ── ★★★★ 若有電解液痕跡（白色結晶／濕痕），依原廠指示處理，
              並拍照留存 —— 這是漏液的證據
```

**階段 4：安裝新電池 ★★★★★**

```
4-1 ★★★★★ 逐顆量測新電池的開路電壓並記錄
    ── 明顯偏低的那顆先挑出來，不要裝上去
    ── ★★★★ 這份紀錄就是本批電池的「初始基準值」

4-2 依原本的位置與方向放入
    ── ★★★★★ 對照階段 1 拍的照片

4-3 ★★★★★ 接線：極性絕對不能接反
    ── 紅=正(+)、黑=負(-) 是慣例，★★★★ 但一定要對照本體標示，不要只看顏色
    ── 接反的後果：短路、電池損壞、UPS 損壞，可能起火
    ── ★★★★ 接線順序與拆除相反：先接各段內部，串聯的最後一條接線最後接

4-4 ★★★★ 端子鎖固
    ── 螺絲端子：★★★★ 依原廠規定的扭力鎖緊
       ── 太鬆 → 接觸電阻大 → 發熱 → ★★★★★ 是端子燒毀的主因
       ── 太緊 → 端子座裂開、螺牙滑牙
    ── 插接式端子（F1/F2）：確認完全插到底，輕拉不會鬆脫

4-5 ★★★★ 檢查
    □ 每一條線都接對位置（對照照片）
    □ 極性正確
    □ 沒有工具、螺絲、包裝材料留在電池匣內  ← ★★★★★ 這條真的會發生
    □ 端子都有絕緣護蓋（如果原本有）
    □ 用三用電表量整串電壓，確認與預期值相符
```

**階段 6：★★★★★ 換完之後一定要做的三件事**

這一段最常被跳過，但它決定了這次更換有沒有意義。

```bash
# 6-1 ★★★★★ 容量校正（Runtime Calibration）
```

> [!note] ★★★★ 什麼是容量校正
> UPS 內部的「預估剩餘時間」（`battery.runtime`）是**算出來的**，
> 依據是「電池容量 × 目前負載」。換了新電池之後，UPS 可能還在用舊電池的參數估算，
> 導致 `battery.runtime` 顯示錯誤（可能過高，也可能過低）。
>
> **校正**就是讓 UPS 實際放電一次，重新學習這批電池的真實表現。

> [!danger] ★★★★★ 容量校正等同於一次深度放電
> 校正過程中 UPS 會把電池放到相當低的程度，期間：
> - **機房沒有停電保護**
> - 校正時間可能長達數十分鐘到數小時（依容量與負載）
>
> **控管方式與放電測試相同**：排時間窗、走變更流程、兩人在場、
> ★★★★★ **確認主機的自動關機設定正常**（這是你的安全網）。
>
> ★★★ 執行方式因機型而異：有些在面板上有 Calibration 選項，
> 有些要透過原廠管理軟體，有些是透過 `upscmd` 的特定指令。
> **查你的機型手冊**，本篇不猜測指令名稱。

```bash
# 6-2 ★★★★★ 續航重測，並與「換之前」比對
#     做法就是「方法 C：放電測試」，但這次是驗收
sudo /usr/local/sbin/ups-discharge-log

### 廢電池處理 ★★★★★

> [!danger] ★★★★★ 廢鉛蓄電池不是一般垃圾
> 鉛酸電池含**鉛**與**硫酸**，是有害物質。
> 機關／企業產生的廢電池屬於**事業廢棄物**，處理責任在**產生者（也就是你的機關）身上**，
> 不會因為交給廠商就自動免責。
>
> ★★★★★ **絕對不可以**：
> - 丟進一般垃圾或資源回收桶
> - 交給沒有合格資格的人「順便載走」
> - 堆在機房角落「等以後再處理」
> - 拆解、破壞、傾倒電解液

**責任框架 ★★★★★**：

```
機關（產生者）
   │  ★★★★★ 責任不會因為委外而消失
   ├─► 委託【合格的清除機構】清運
   │      ★★★★★ 要驗證資格：查驗許可證，並保留影本
   │
   ├─► 委託【合格的處理機構】處理／再利用
   │      ★★★★★ 同樣要驗證資格
   │
   └─► 依規定【申報】
          ★★★★ 用主管機關指定的申報系統上傳聯單
          ★★★★★ 保留申報紀錄與聯單，做為稽核證據
```

> [!warning] ★★★★★ 實際的法規細節請以現行公告為準
> 台灣的廢棄物管理由**環境部**主管，相關規定會修訂。
> 本篇**刻意不列出**廢棄物代碼、申報欄位名稱、法條條號，
> 因為這些**會變動，寫錯會害你申報錯誤**。
>
> ★★★★★ **正確做法**：
> 1. 向你的機關**環安衛承辦人員**確認流程（大多數機關都有專責窗口）
> 2. 委託時，要求清除處理機構**提供其許可證影本與適用的廢棄物代碼**
> 3. 依機構提供的資料填寫申報，**不要自己憑印象選代碼**
> 4. 到環境部的事業廢棄物申報相關網站確認**當前的**申報方式
>
> **如果 UPS 是委外維護的**：合約中通常會約定廠商負責回收舊電池。
> ★★★★★ 但即使如此，**你仍應取得清運證明並歸檔**，不能只是「他載走了」。

**暫存期間的注意事項 ★★★★**：

| 項目 | 要求 |
| --- | --- |
| ★★★★★ 端子絕緣 | 每顆的正負極都要用絕緣膠帶封住，**防止互相碰觸短路** |
| ★★★★ 放置方式 | 直立擺放，**不可倒置**；不要疊太高 |
| ★★★★ 位置 | 通風、陰涼、不受日曬、遠離熱源與可燃物 |
| ★★★★★ 隔離 | **不要放在機房內**（酸氣與短路風險），移到指定暫存區 |
| ★★★★ 標示 | 明確標示「廢鉛蓄電池」、數量、拆除日期、待清運 |
| ★★★★ 時限 | 盡快清運，**不要長期堆置** |
| ★★★ 紀錄 | 拆下顆數、清運顆數、清運日期、承辦人 —— 三個數字要對得上 |

**清運紀錄要留什麼 ★★★★★**：

```
□ 清除機構名稱、許可證字號、許可證影本
□ 處理／再利用機構名稱與資格證明
□ 清運日期、車號、司機簽收
□ 廢棄物名稱、代碼、數量（顆數與重量）
□ 聯單編號 / 申報紀錄截圖
□ ★★★★ 現場照片（裝車前、裝車後）
□ 承辦人與主管簽核
```

★★★★ 這份紀錄要**與資產異動紀錄相互對應** ——
盤點表上「拆除 8 顆」，清運紀錄上就要有「清運 8 顆」。
稽核時對不上是常見的缺失。

### 電池監控告警設定 ★★★★★

把電池狀態接進監控（基礎設定見 [[040-02-06-svc-機房-UPS安裝與監控設定]]）。

**必設的六個告警 ★★★★★**：

| # | 告警 | 條件 | 嚴重度 | 通知對象 |
| --- | --- | --- | --- | --- |
| ① ★★★★★ | 電池需更換 | `ups.status` 含 `RB` | High | 維運 + 主管（要編預算） |
| ② ★★★★★ | 續航嚴重衰退 | `battery.runtime` 低於基準值的某個比例 | High | 維運 |
| ③ ★★★★★ | 電池溫度過高 | `battery.temperature` 超過門檻 | Critical | 維運 + 現場人員（★ 熱失控前兆） |
| ④ ★★★★ | 無法充飽 | `battery.charge` 連續 24 小時 < 100 且市電正常 | High | 維運 |
| ⑤ ★★★★ | 電池電壓異常 | `battery.voltage` 偏離正常區間 | High | 維運 |
| ⑥ ★★★★★ | **監控資料消失** | 超過 N 分鐘沒有 UPS 指標 | High | 維運（★★★★★ 等於失去監控） |

**續航衰退告警的門檻怎麼設 ★★★★**：

```
基準值 = 換電池後的驗收實測值（例如 3050 秒）
   │
   ├─ 掉到基準值的 80%（約 2440 秒）→ ★★★ 提醒：開始注意
   ├─ 掉到基準值的 60%（約 1830 秒）→ ★★★★ 警告：編列預算
   └─ 掉到「全部主機關完所需時間 × 2」→ ★★★★★ 嚴重：立刻排更換

★★★★★ 注意：比較時要考慮負載變化。
       正確做法是比「相同負載下的實測值」，或用「單位負載續航」做正規化。
```

**Prometheus 告警規則概念 ★★★★**：

```yaml
# 概念範例，實際請依你的指標名稱與環境調整
groups:
  - name: ups-battery
    rules:
      - alert: UPSBatteryNeedsReplacement
        # ★★★★★ RB 旗標
        expr: ups_replace_battery == 1
        for: 5m
        labels:
          severity: high
        annotations:
          summary: "UPS {{ $labels.ups }} 回報電池需更換"
          description: "請安排電池更換，並執行放電測試確認實際續航"

      - alert: UPSRuntimeDegraded
        # ★★★★ 續航低於基準值的 60%（基準值請寫成你的實測值）
        expr: ups_battery_runtime < 1830
        for: 30m
        labels:
          severity: high
        annotations:
          summary: "UPS {{ $labels.ups }} 續航明顯衰退"

      - alert: UPSBatteryOverheat
        # ★★★★★ 電池溫度過高，熱失控前兆
        expr: ups_battery_temperature > 35
        for: 10m
        labels:
          severity: critical
        annotations:
          summary: "UPS {{ $labels.ups }} 電池溫度過高，請立即現場查看"

      - alert: UPSMetricsMissing
        # ★★★★★ 沒有資料本身就是告警
        expr: absent(ups_online)
        for: 10m
        labels:
          severity: high
        annotations:
          summary: "收不到 UPS 監控資料，監控可能已失效"
```

> [!warning] ★★★★★ 上面 YAML 裡的數字是「範例佔位」
> `1830`、`35` 這些值**不是通用建議值**，是為了讓語法完整而填的。
> ★★★★★ **一定要換成你自己實測與規格書推導出來的門檻。**
> 抄了不改，等於沒設。

> [!note] ★★★★ 這裡出現一個常見的判斷分歧
> 「安全餘裕還有 5.4 倍，主機明明關得完，為什麼要換？」
>
> 因為 **UPS 的設計需求不只是「關得完」**：
> - 30 分鐘的需求可能包含「等待發電機起動」「等待短時間停電自然恢復」
> - 5.4 倍的餘裕是**在今天**；照這個衰退速度，再半年就會掉到 2 倍以下
> - ★★★★★ 電池衰退到後期**會加速**，不是線性的
>
> ★★★★★ **正確結論：本年度更換，不要拖到明年。**

**填寫判定矩陣**：

| 訊號 | 本案結果 | 判定 |
| --- | --- | --- |
| ① 服役年限 | 已達廠商標示設計壽命 | ⚠ |
| ② 實測續航 | 980 秒 < 設計需求 1800 秒 | ★★★★★ **不通過** |
| ③ 內阻 | （待量測，見步驟 2） | — |
| ④ `RB` | 未出現 | ✅ |
| ⑤ 外觀 | 目視無鼓脹漏液 | ✅ |
| ⑥ 深放次數 | 過去一年有 2 次真實停電 | ⚠ |
| ⑦ 環境溫度 | 電池區均溫比機房均溫高約 3°C | ⚠ |

★★★★★ **結論：② 不通過即足以判定更換。** 注意 ④ `RB` 根本沒出現 ——
再次證明「等 `RB` 才換」是錯的。

   → 若是，這次要順便改善散熱（[[040-02-02-guide-機房-空調系統與溫溼度監控]]）

③ 這次流程有沒有卡關？
   → 例如「交期比預期長兩週」「廢電池暫存區沒有規劃」
   → 寫進下一次的準備清單
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ 電池換了，`ups.status` 的 `RB` 還在 | 部分機型換完要手動執行「電池更換確認」或跑一次自我測試才會重判 | 依機型在面板／管理軟體上執行電池重設；或 `upscmd ... test.battery.start.quick` 後再看 |
| ★★★★★ 停電時只撐了幾分鐘，但平常自我測試都「通過」 | ★★★★★ 快速自我測試**不驗證容量**，只驗證電池沒完全失效 | 必須做放電測試才知道真實續航；把年度放電測試排進行事曆 |
| ★★★★ `battery.runtime` 換完電池後反而變短或顯示怪值 | UPS 還在用舊電池的參數估算，未做容量校正 | 執行容量校正（Runtime Calibration） |
| ★★★★ `battery.charge` 長期停在 100 以下上不去 | 電池老化無法充飽；或充電器故障 | 先量電池電壓與內阻；排除電池問題後查充電器 |
| ★★★★★ 電池外殼鼓脹 | 過充、溫度過高、熱失控前兆 | ★★★★★ **立刻停用該電池組**，不要嘗試繼續使用，通知廠商 |
| ★★★★ 端子有白色／綠色粉狀腐蝕物 | 電解液微量滲漏、環境潮濕 | 斷電後依安全程序清潔；若腐蝕嚴重，整串更換 |
| ★★★★★ 更換後 UPS 不開機或報錯 | 極性接反、線束沒接好、電壓不足、型號不相容 | ★★★★★ 立刻斷電，對照更換前的照片逐條檢查極性與接線 |
| ★★★★★ 換電池時工具短路產生火花 | 未使用絕緣工具、未脫金屬飾品 | ★★★★★ 立刻停止作業、確認人員安全與電池狀態；重新依安全規則作業 |
| ★★★★ 新電池裝不進電池匣 | 尺寸或端子型式買錯 | 採購前務必記錄尺寸與端子型式；★★★★ 這就是為什麼要拍照 |
| ★★★★★ 只換了壞掉的那一顆 | 「省錢」的錯誤決定 | 整串換掉；已經混用的話，把新的那顆也一起換掉重來 |
| ★★★★ 電池明明才用兩年就衰退嚴重 | 環境溫度長期偏高；或頻繁深度放電 | 查溫度趨勢紀錄；改善電池區散熱；檢討 `battery.charge.low` 設定與 killpower |
| ★★★★ 放電測試做到一半 UPS 直接斷電 | 電池已嚴重老化，撐不到預定門檻 | ★★★★★ 這代表**測試本身就是災難演練**；所以測試前必須確認主機自動關機正常 |
| ★★★★ 舊電池堆在機房角落好幾個月 | 沒有規劃暫存與清運流程 | ★★★★★ 更換前就要把清運安排好；電池不可長期堆置在機房 |
| ★★★★ 清運數量與拆除數量對不上 | 沒有逐顆點交與紀錄 | 拆除當下就編號、貼標籤、拍照；清運時逐顆核對 |
| ★★★ `battery.temperature` 欄位不存在 | 機型不回報電池溫度 | 用機櫃內獨立溫溼度感測器，感測點放在電池區 |
| ★★★★ 監控上續航一直在跳動，告警一直誤報 | 負載變動導致 `runtime` 估算值跟著變 | 告警加 `for:` 持續時間條件；或改用「相同負載下的年度實測值」做判定 |
| ★★★★★ 換完電池沒有做任何驗收，半年後停電還是撐不住 | 買到瑕疵品／型號錯／裝錯，但沒人發現 | ★★★★★ **換完必做放電測試驗收**，並留下比較表 |
| ★★★ 備品電池放了三年，要用時發現已經壞了 | 電池自放電 + 硫化 | 備品每半年充電一次；★★★★ 不要囤太多，依實際更換週期採購 |
| ★★★★ 委外維護廠商只給一句「電池正常」 | 契約沒有要求提供數值 | ★★★★★ 契約要寫明「須提供每顆電池的內阻／電壓量測數值與放電測試報告」 |

## 安全性注意事項

### ★★★★★ 人身安全的五條紅線

| # | 紅線 | 違反的後果 |
| --- | --- | --- |
| ① ★★★★★ | **不戴金屬飾品、不用非絕緣工具** | 短路電弧、燒傷、熔融金屬飛濺 |
| ② ★★★★★ | **不單獨作業** | 出事時無人求援 |
| ③ ★★★★★ | **不在鼓脹／發燙／漏液的電池旁使用明火或會產生火花的工具** | 氫氣爆燃、酸液噴濺 |
| ④ ★★★★★ | **不對不熟悉的機型動手** | 帶電作業判斷錯誤 |
| ⑤ ★★★★★ | **不趕時間、不在疲勞時作業** | 所有電氣事故的共同前因 |

> [!danger] ★★★★★ 「UPS 已經關機」不等於「沒有電」
> 這是最致命的誤解。UPS 關機、拔掉市電之後：
> - **電池端仍然帶著全部電壓**
> - 部分機型內部電容也還有殘電
>
> ★★★★★ **唯一安全的判斷方式是用三用電表實際量測**，
> 不是看面板燈有沒有滅。

### 資料安全與服務中斷風險 ★★★★★

```
電池維護活動的風險排序（由高到低）：

★★★★★ ① 容量校正 / 深度放電測試
        機房長時間無保護，且電池被放到很低
        → 必須走變更流程、排時間窗、確認自動關機正常

★★★★★ ② 帶電更換電池（轉旁路）
        機房無保護 + 人員接觸帶電體
        → 除非機型設計支援且人員受過訓練，否則不要做

★★★★  ③ 停機更換電池
        服務中斷但風險可控
        → ★★★★★ 這是最推薦的做法

★★★    ④ 快速自我測試
        短暫放電，風險低
        → 可以排進月維護

★★     ⑤ 內阻量測
        不放電，設備持續受保護
        → 風險最低的深度檢查方式
```

★★★★★ **決策原則：能用低風險方法達成目的，就不要用高風險方法。**
只有在低風險方法給不出答案時，才升級到放電測試。

### 環境與法規責任 ★★★★★

| 責任 | 說明 |
| --- | --- |
| ★★★★★ **產生者責任** | 廢電池的最終處理責任在機關身上，**委外不免責** |

## 練習題

> [!question]- 練習 1：建立你的電池趨勢紀錄（★★★ 入門）
> **題目**：在你的 NUT primary 上部署 `ups-battery-trend` 腳本，
> 用 systemd timer 每天早上 08:00 執行一次，並確認 CSV 有正確產生。
>
> **參考解答**：
> 1. 建立腳本並 `chmod 750`
> 2. 建立 service 與 timer：
>    ```ini
>    # /etc/systemd/system/ups-battery-trend.service
>    [Unit]
>    Description=記錄 UPS 電池趨勢
>    [Service]
>    Type=oneshot
>    ExecStart=/usr/local/sbin/ups-battery-trend
>    ```
>    ```ini
>    # /etc/systemd/system/ups-battery-trend.timer
>    [Unit]
>    Description=每日記錄 UPS 電池趨勢
>    [Timer]
>    OnCalendar=*-*-* 08:00:00
>    Persistent=true
>    [Install]
>    WantedBy=timers.target
>    ```
> 3. `sudo systemctl enable --now ups-battery-trend.timer`
> 4. 驗證：`systemctl list-timers ups-battery-trend.timer`
>    以及手動跑一次看 `/var/log/ups-battery-trend.csv`
>
> ★★★★ **加分**：加上 logrotate 或改成每年一個檔，避免無限成長。

> [!question]- 練習 2：從趨勢資料判定該不該換（★★★★）
> **題目**：假設你的趨勢檔顯示（負載都在 27～28%）：
> ```
> 2025-09: runtime 2280
> 2026-03: runtime 1580
> 2026-09: runtime  980
> ```
> 全部主機關完需要 180 秒，設計需求是 30 分鐘。請做出判定並說明理由。
>
> **參考解答**：
> - 一年掉了約 57%，且**下半年掉的比上半年多**（700 vs 600），衰退在加速
> - 目前 980 秒 = 16.3 分鐘 < 設計需求 1800 秒 → ★★★★★ **未達設計需求**
> - 安全餘裕 980/180 = 5.4 倍，看似還夠，但依此速度半年後會掉到約 600 秒（3.3 倍），
>   一年後更低
> - ★★★★★ **判定：本年度更換。** 理由寫成三點：未達設計需求、衰退加速、餘裕快速縮小
> - ★★★★ 同時檢查電池區溫度趨勢，判斷是否要一併改善散熱

> [!question]- 練習 3：規劃一次放電測試（★★★★★）
> **題目**：寫出一份完整的放電測試計畫，包含前置條件、中止條件、記錄方式、風險控管。
>
> **參考解答框架**：
> | 項目 | 內容 |
> | --- | --- |
> | 前置條件 | `ups.status` = 純 `OL`；`battery.charge` = 100；無 `RB`；快速測試已通過 |
> | 安全網 | ★★★★★ 確認 `nut-monitor` 運作、三台 secondary 都連著、upssched 計時器正確 |
> | 時間窗 | 假日清晨，避開業務時間；已走變更流程核准 |
> | 人力 | 兩人，一人操作一人計時記錄，隨時可恢復市電 |
> | 記錄 | `ups-discharge-log` 每 15 秒一筆，輸出到檔案（不是只用 watch 看） |
> | 中止條件 | ★★★★★ 電量降到設定下限／出現 `LB`／電壓下降加速／任何異常現象／預定時間到 |
> | 恢復 | 恢復市電，確認 `OL CHRG`，充飽前不再測試 |
> | 產出 | 與上次測試的比較表；判定結論；是否需編列預算 |

> [!question]- 練習 4：寫出你機房的電池更換 SOP（★★★★★）
> **題目**：依你實際的 UPS 機型，把本篇的十步驟 SOP 具體化成一份可以印出來照做的文件。
>
> **參考解答重點（每一項都要「具體」而不是「參考手冊」）**：
> - 你的機型是否支援熱插拔電池？→ ★★★★★ 直接寫「本機型必須停機更換」或「可熱插拔，程序為…」
> - 電池顆數、位置圖、編號規則
> - 拆線的實際順序（依你的線束配置）
> - 端子型式與所需工具
> - 停機順序（哪台先關、哪台最後關）
> - ★★★★ 更換前後要跑的指令（可以直接照抄本篇）
> - 廢電池的暫存位置與清運窗口聯絡方式
>
> ★★★★★ **驗收標準：一個沒換過電池的同事，拿著這份文件能不能安全完成？**

> [!question]- 練習 5：設計電池告警並驗證會叫（★★★★）
> **題目**：設定六個電池相關告警，並想辦法**實際驗證每一個都會發出通知**。
>
> **參考解答**：
> | 告警 | 驗證方式 |
> | --- | --- |
> | 停電 / `OB` | ★★★★ 拔電演練時自然會觸發 |
> | `RB` | ★★★ 難以人工製造 → 改為在監控端**手動注入測試指標**驗證規則正確 |
> | 續航衰退 | ★★★★ 暫時把門檻調到目前值之上，確認會告警，然後改回來 |
> | 電池溫度過高 | 同上，暫時調低門檻 |
> | 無法充飽 | 同上 |
> | ★★★★★ 監控資料消失 | **停掉 `nut-server` 十分鐘**，確認告警發出（這個一定要真的測） |
>
> ★★★★★ **重點**：「設了告警」不等於「告警會叫」。
> 最後一項（資料消失）是最容易設錯也最容易被忽略的，**一定要真的驗證**。

> [!question]- 練習 6：走一次廢電池處理流程（紙上作業）（★★★★）
> **題目**：假設你要處理 8 顆廢 VRLA 電池。列出你會依序聯絡誰、要索取哪些文件、
> 要留下哪些紀錄。
>
> **參考解答**：
> 1. **機關環安衛承辦** → 確認本機關的事業廢棄物處理流程與適用代碼
> 2. **UPS 維護廠商 / 合格清除機構** → 索取**許可證影本**、報價、清運排程
> 3. **確認處理／再利用機構資格**
> 4. 清運前：端子絕緣、暫存、標示、拍照
> 5. 清運當天：逐顆點交、司機簽收、拍照（裝車前後）
> 6. 清運後：取得**聯單／清運證明**，依規定申報，截圖存檔
> 7. 歸檔：與資產異動紀錄勾稽，數量一致
>
> ★★★★★ **最容易被忘的兩件事**：
> ① 許可證影本（稽核一定會問）；② 數量勾稽（拆 8 顆就要清 8 顆）。

## 小測驗

**Q1.** 為什麼「等 `ups.status` 出現 `RB` 才換電池」是錯誤的做法？請說出至少兩個理由。

**Q2.** （是非）每個月的快速自我測試都通過，就可以證明停電時 UPS 能撐滿設計的 30 分鐘。

**Q3.** 業界常說「環境溫度每高 10°C，VRLA 電池壽命減半」。
這句話可以用來做什麼、不可以用來做什麼？

**Q4.** 內阻量測的「基準值」有三個來源，請依優先順序列出，並說明為什麼第一名最好。

**Q5.** （這個決定會發生什麼）某機關的 UPS 有 4 顆串聯電池，量測發現只有 B03 明顯劣化，
承辦人為了省錢決定「只換 B03 一顆」。請描述接下來半年會發生什麼。

**Q6.** 放電（容量）測試被列為風險 ★★★★★ 的活動。請說明風險是什麼，
以及五項必要的風險控管措施。

**Q7.** 換完電池之後「一定要做的三件事」是什麼？如果只做了前兩件、漏了第三件，
會在什麼時候出問題？

**Q8.** （是非）電池更換完成後，應該立刻安排廢電池清運，越快清掉越好。

**Q9.** 巡檢時發現一顆電池外殼明顯鼓脹且摸起來比旁邊的燙。請依序寫出你的處理動作。

**Q10.** 你的監控上有「停電告警」「低電量告警」「RB 告警」。
主管問「這樣夠不夠？」請指出還缺哪一個**最關鍵**的告警，並說明理由。

> [!question]- 測驗答案
>
> **A1.** 至少三個理由（答對兩個即可）：
> ① ★★★★★ `RB` 的判定邏輯由廠商決定，**通常很保守**，出現時電池往往已衰退很久；
> ② 有些機型**只在執行自我測試時**才更新 `RB`，不測就永遠不亮；
> ③ ★★★★★ **部分低階機型根本不回報 `RB`**。
> 正確做法是「定期主動測試 + 趨勢追蹤 + 到期換」三者並行。
> → 見「觀念說明」開頭的 danger callout。
>
> **A2.** ✗ 錯。★★★★★ **快速自我測試只驗證「電池沒有完全失效」，不驗證容量。**
> 一顆只剩三成容量的電池，快速測試照樣「通過」。
> 要證明續航只有一個方法：**放電（容量）測試**。
> → 見「安裝或基礎操作 / 方法 A+」。
>
> **A3.** ★★★★★ **可以**用來做**決策方向**：判斷「機房太熱要改善散熱」、
> 「電池區不能跟著整機房調高溫度」、「解釋為什麼電池提早壞」。
> ★★★★★ **不可以**用來**精算「我的電池還剩幾個月」** ——
> 它是經驗法則（源自 Arrhenius 關係），確切係數與額定溫度基準每款電池都不同。
> 精算要靠內阻量測與放電測試。
> → 見「觀念說明 / 溫度：影響壽命的頭號因素」。
>
> **A4.** ① ★★★★★ **這批電池剛裝好時自己量的初始值**（最準，所以更換當天一定要量並存檔）；
> ② 電池原廠規格書的參考內阻（次佳，但有個體差異）；
> ③ 同一串電池其他顆的平均值（★★★★ 抓離群值很有效）。
> 第一名最好的原因：內阻絕對值與容量、型號、溫度強相關，
> **只有跟自己比才排除掉這些變數**。
> → 見「安裝或基礎操作 / 方法 B」。
>
> **A5.** ★★★★★ 半年內新電池會被拖垮：
> **充電時**新電池內阻低、較早充飽，之後持續被過充 → 失水、鼓脹；
> **放電時**舊電池先沒電，新電池會被舊電池「反向充電」 → 極性反轉損壞。
> 結果是新電池的壽命被拉到跟舊電池一樣短甚至更短，**省下的錢半年後全部賠回去**。
> 正確做法：整串一起換，同品牌、同型號、同容量、盡量同批號。
> → 見「觀念說明 / 絕對不要混用新舊電池」。
>
> **A6.** **風險**：測試期間機房**完全沒有市電保護**；老化電池可能在測試中直接失效導致整櫃硬斷電；
> 此時若真的發生市電事故則毫無緩衝。
> ★★★★★ **五項控管**：
> ① 走變更管理流程（有核准、有時間窗）；
> ② 選離峰時段並事先公告；
> ③ 兩人以上在場，一人操作一人記錄，隨時可中止；
> ④ ★★★★★ **測試前確認所有主機的自動關機設定正確**（這是安全網）；
> ⑤ 先做快速測試確認無立即問題，且設定明確的中止條件。
> → 見「安裝或基礎操作 / 方法 C」的 danger callout。
>
> **A7.** ① **容量校正**（讓 UPS 重新學習新電池，否則 `battery.runtime` 顯示錯誤）；
> ② **續航重測並與換之前比對**（證明這次更換有效，且建立新基準）；
> ③ ★★★★★ **更新所有紀錄**（資產表、`upsc` 基準檔、內阻基準、UPS 上的更換日期、
> 巡檢門檻、監控告警門檻、生命週期紀錄、廢電池清運紀錄）。
> **漏掉第三件的後果**：下一次判定時**沒有基準可比**，
> 監控告警門檻仍是舊值（可能永遠不會叫，或一直誤報），
> 而且稽核時拿不出完整紀錄。
> → 見「進階應用 / 階段 6」。
>
> **A8.** ✗ 錯。★★★★★ **必須等新電池驗收通過之後才清運舊電池。**
> 理由：如果新電池有問題（型號錯、有瑕疵、裝了不能用），
> **舊電池是你唯一的回復手段**。舊電池一旦清運掉就回不去了。
> 這也是為什麼變更申請單上要特別註記「更換完成驗收前不得清運舊電池」。
> （清運本身仍要盡快安排，不可長期堆置 —— 但順序是「驗收後」。）
> → 見「完整實戰範例 / 步驟 4」與「步驟 7-7」。
>
> **A9.** ★★★★★ 依序：
> ① **不要用力扳、敲、或嘗試「壓回去」**；
> ② **不要在旁邊使用明火或會產生火花的工具**；
> ③ 拍照留存證據；
> ④ 立刻通知 UPS 維護廠商，由原廠或合格廠商處理；
> ⑤ 若情況嚴重且無法立即處理，考慮由熟悉該機型的人**轉旁路並斷開電池**
> （★★★★★ 期間機房完全無保護，要有時間管制與人員在場）；
> ⑥ 通報主管、記錄事件、檢討環境溫度是否為肇因。
> 鼓脹＋發燙是**熱失控**的典型徵兆，屬於立即危險。
> → 見「觀念說明 / 熱失控」。
>
> **A10.** ★★★★★ 缺的是「**監控資料消失（沒有資料）也要告警**」。
> 理由：如果 driver 或 `upsd` 掛了，監控端**不會收到任何新資料**，
> 儀表板會維持在最後一筆的綠色狀態，所有「值超標」型的告警**永遠不會觸發**。
> 結果是「監控三個月前就死了，但畫面一片綠」，真的停電時一則告警都沒有。
> 實作上用 `absent(ups_online)` 之類的規則，或用「最後更新時間超過 N 分鐘」判定。
> ★★★★★ **這條原則對所有監控項目都成立。**
> → 見「進階應用 / 電池監控告警設定」第 ⑥ 項，
> 以及 [[100-01-04-guide-日誌-健康檢查與可用性監控]]。
