# 結構化佈線與標籤規範

> [!abstract] 這篇你會學到
> - 為什麼「能通就好」的佈線在三年後會變成**沒有人敢動的黑盒子**
> - ★★★★ Cat5e／Cat6／Cat6A／光纖怎麼選，以及 **100 公尺是怎麼分配的**（90 + 10）
> - 幹線（backbone）與水平佈線（horizontal）的差別，為什麼**跳線不能當幹線用**
> - ★★★★★ 一套可以直接抄的**雙端標籤規範與編號方式**，以及「標籤只貼一端」的災難
> - 色碼怎麼定：TIA-606 的欄位色碼**是什麼、不是什麼**，以及跳線顏色該由誰決定
> - ★★★★★ **測線儀報告要看哪幾欄**：PASS 不等於做得好，`PASS*` 是什麼意思
> - 現場最常見的**十二種施工缺失**，以及驗收時怎麼一眼抓出來
> - 把線路紀錄與盤點、機櫃圖、監控串起來，讓「拔錯線」變成很難發生的事

> [!warning] 未實機驗證
> ★★★★ 本篇的**標準名稱與方法論**（TIA-568 系列的通道／永久鏈路概念、
> TIA-606 的管理與標示原則、測線儀的測試項目）為業界通用內容。
>
> 但是：
> - ★★★★★ **具體的距離、拉力、彎曲半徑、通道損耗預算等數值**會依
>   **標準版本、線材規格書、收發器（transceiver）規格**而不同。
>   文中出現的數字是**業界常見的參考值**，用來說明判定邏輯；
>   **實際施工與驗收一律以現行標準版本與你採購的線材／模組規格書為準**。
> - **測線儀的畫面、報告欄位名稱、匯出格式**因廠牌與韌體版本而異，
>   本篇未在特定機型上實機驗證，示意輸出為「典型長相」。
> - ★★★★ 政府採購案的佈線驗收，通常在**招標規範**中已明訂測試標準與合格判準，
>   **以契約文件為最高依據**。

## 觀念說明

### ★★★★★ 佈線的真正成本不在材料，在「後續每一次動它」

```
第一年：全部重拉，線很新，工程師還記得哪條是哪條
        ─────────────────────────────────────────
第二年：新增一台伺服器，隨手拉一條，沒貼標籤    ★
第三年：換交換器，把跳線拔下來重插，順序亂了    ★★
第四年：查一個網路問題，花三小時追一條線        ★★★
第五年：★★★★★ 沒有人敢拔任何一條線
        因為「不知道拔了會斷掉什麼」
```

★★★★★ **結構化佈線要解決的不是「訊號能不能通」，而是「三年後還查不查得到」。**

一條沒有標籤的線，跟一條標了但兩端不一致的線，在維運上是**同一件事** ——
都要靠「拔看看誰斷了」才能確認，而那正是機房裡最不該做的事。

### 結構化佈線的六個子系統 ★★★

TIA-568 系列標準把整套佈線拆成幾個子系統。名詞不用背，但**分層的概念一定要懂**：

```
┌──────────────────────────────────────────────────────────────┐
│  進線間 / 引入設施 (Entrance Facility)                        │
│    ISP 光纖、電信線路進來的地方                                │
└───────────────────────┬──────────────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────────────┐
│  設備間 (Equipment Room) ＝ 你的機房                          │
│    核心交換器、路由器、防火牆、伺服器                          │
└───────────────────────┬──────────────────────────────────────┘
                        │  ★★★★★ 幹線（Backbone / Riser）
                        │  跨樓層、跨棟、機房到各樓層電信間
                        │  ── 通常用光纖，長距離、高頻寬
┌───────────────────────▼──────────────────────────────────────┐
│  電信間 (Telecommunications Room)  ＝ 各樓層的弱電機櫃        │
│    接取層交換器、配線架（patch panel）                        │
└───────────────────────┬──────────────────────────────────────┘
                        │  ★★★★★ 水平佈線（Horizontal Cabling）
                        │  電信間 → 各個資訊插座
                        │  ── 通常用銅纜（Cat6/6A），★★★★★ 最長 90 公尺
┌───────────────────────▼──────────────────────────────────────┐
│  工作區 (Work Area)                                          │
│    牆上／地板的資訊插座 → 跳線 → 電腦、電話、AP、印表機        │
└──────────────────────────────────────────────────────────────┘
```

★★★★★ **這張圖最重要的一句話**：
**幹線與水平佈線是「永久」的，跳線是「臨時」的。**
永久的部分一旦施工完成就不該再動；日常變更只動跳線。

### 通道（Channel）與永久鏈路（Permanent Link）★★★★★

這是**驗收時最常吵的觀念**，一定要搞清楚。

```
       ┌─── 永久鏈路 (Permanent Link) ────┐
       │   ★★★★★ 施工廠商負責的部分       │
       │   ★★★★★ 驗收測的就是這一段       │
       │                                  │
  ┌────┴────┐                     ┌───────┴──────┐
  │ 配線架   │═══════ 固定佈線 ═══│  資訊插座     │
  │  (Panel) │      （牆內／槽內） │   (Outlet)   │
  └────┬────┘                     └───────┬──────┘
       │                                  │
  ┌────┴────┐                        ┌────┴────┐
  │  跳線    │                        │  跳線    │
  └────┬────┘                        └────┬────┘
       │                                  │
  ┌────┴────┐                        ┌────┴────┐
  │ 交換器   │                        │  電腦    │
  └─────────┘                        └─────────┘
  └──────────────── 通道 (Channel) ─────────────┘
       ★★★★ 端到端的實際使用狀態，含兩端跳線
```

| | 永久鏈路 | 通道 |
| --- | --- | --- |
| 涵蓋範圍 | ★★★★★ 配線架 ↔ 資訊插座（**不含**跳線） | 交換器 ↔ 電腦（**含**兩端跳線） |
| 誰負責 | 佈線施工廠商 | 使用單位（跳線是消耗品） |
| ★★★★★ 驗收測哪個 | **測永久鏈路** | 通常不測（因為跳線會一直換） |
| 長度上限（參考值） | 90 公尺 | 100 公尺 |
| 合格標準 | ★★★ 較嚴（因為要留跳線的餘裕） | 較寬 |

> [!danger] ★★★★★ 驗收時最常見的爭議：廠商用「通道模式」測試
> 通道模式的合格標準比永久鏈路**寬鬆**（因為它假設你已經接受了跳線的損耗）。
>
> 廠商如果用通道模式測，可能會出現：
> - **永久鏈路測不過、但通道模式測得過**的線
> - 這些線在你日後換一條較長的跳線時，就會開始不穩
>
> ★★★★★ **契約與驗收要求裡一定要寫明「以永久鏈路（Permanent Link）模式測試」**，
> 並要求報告上明確標示測試模式。

### 100 公尺是怎麼分的 ★★★★★

這是最常被記錯的數字。

```
                        總長 100 公尺（Channel）
  ├──────────────────────────────────────────────────────────┤

  ├─ 跳線 ─┤├──────── 固定佈線 90 公尺 ────────┤├─ 跳線 ─┤
   （機櫃側）        （Permanent Link）           （工作區側）
   ★★★★★ 兩端跳線加起來最多 10 公尺
```

★★★★★ **常見的錯誤理解與後果**：

| 錯誤理解 | 實際後果 |
| --- | --- |
| ★★★★★ 「固定佈線可以拉到 100 公尺」 | 加上跳線就超過 100 公尺，訊號品質不保證，**驗收也不會過** |
| ★★★★ 「跳線隨便用多長都可以」 | 機櫃內用 5 公尺跳線繞一圈，等於吃掉一半的跳線預算 |
| ★★★★ 「反正 1G 沒問題」 | 1G 也許勉強能跑，但**日後升 10G 就會出問題**，等於要重拉 |
| ★★★ 「多拉一點餘長沒關係」 | 餘長也算長度；★★★★ 留餘長是對的，但要算進 90 公尺內 |

> [!tip] ★★★★ 實務規劃建議
> 規劃時**不要用滿 90 公尺**。留 10～15% 的餘裕給：
> - 施工時的實際走線繞路（規劃的直線距離 ≠ 實際拉線長度）
> - 兩端各留的維修餘長
> - 日後可能的小幅調整
>
> ★★★★★ 規劃階段就超過 80 公尺的點位，**要考慮改用光纖或增設中間電信間**。

### 線材選擇 ★★★★

> [!warning] ★★★★★ 下表的數字是「常見參考值」，不是規格書
> 實際支援的速率與距離，取決於**標準版本、線材品質、施工品質、
> 以及兩端設備／收發器的規格**。
> ★★★★★ **採購與驗收一律以線材規格書與招標文件為準。**

| 類別 | 常見支援 | 典型用途 | 備註 |
| --- | --- | --- | --- |
| ★★ **Cat5e** | 1000BASE-T（1G） | 舊建物既有線路 | ★★★★ **新案不要再用**，省下的錢遠低於日後重拉的成本 |
| ★★★★ **Cat6** | 1G 全距離；10G **僅短距離且有條件** | 一般辦公區水平佈線 | ★★★★★ 「Cat6 可以跑 10G」要看距離與干擾條件，**不要當成 100 公尺都能跑 10G** |
| ★★★★★ **Cat6A** | 10GBASE-T 全距離 | ★★★★★ **新案的預設選擇**（尤其機房與 AP） | 線徑粗、彎曲半徑大、佔線槽空間多，規劃要算進去 |
| ★★★ **Cat7 / Cat8** | 更高頻寬（Cat8 為極短距離設計） | 機櫃內短距高速互連 | ★★★ 端子型式與生態較特殊，一般機關案很少用 |
| ★★★★ **多模光纖 OM3／OM4** | 10G／40G／100G（★ 距離依收發器而定） | ★★★★★ 機房內／同棟樓層之間的幹線 | OM4 通常比 OM3 支援更長距離；**確切距離看收發器規格書** |
| ★★★★ **單模光纖 OS2** | 長距離 | ★★★★★ 跨棟、跨園區幹線 | 距離遠、成本以模組為主；★★★ 一次拉夠芯數，日後不用再開挖 |

**選擇決策樹 ★★★★★**：

```
這條線要拉到哪裡？
  │
  ├─ 機櫃內（同一櫃或相鄰櫃，數公尺）
  │     → ★★★★ Cat6A 跳線 或 DAC／光纖跳線（依設備介面）
  │
  ├─ 同一樓層，距離 < 80 公尺
  │     → ★★★★★ Cat6A 水平佈線
  │
  ├─ 同一樓層但 > 80 公尺，或跨樓層
  │     → ★★★★★ 光纖幹線（多模 OM4 或單模，依距離與預算）
  │       ★★★★ 不要用「兩段銅纜串接 + 中間放一台交換器」硬撐
  │
  └─ 跨棟 / 跨園區
        → ★★★★★ 單模光纖，且要考慮防雷／接地／管道權
```

> [!danger] ★★★★★ 三個絕對不要
> 1. ★★★★★ **不要為了省錢在新案用 Cat5e。**
>    重拉一次的人力、停機、天花板拆裝成本，遠高於線材差價。
> 2. ★★★★★ **不要用「串接兩段線」來突破距離限制。**
>    中間多一台交換器＝多一個故障點、多一個要供電與監控的東西、
>    多一個沒人記得它存在的黑盒子。
> 3. ★★★★★ **不要在拉光纖時只拉「現在需要的芯數」。**
>    拉線的成本主要在**施工與管道**，不在光纖本身。
>    ★★★★ 一次多拉幾芯備用，是佈線裡投資報酬率最高的決定。

### 幹線與水平佈線的分工 ★★★★

| | 幹線（Backbone） | 水平佈線（Horizontal） |
| --- | --- | --- |
| 連接 | 機房 ↔ 各樓層電信間 | 電信間 ↔ 資訊插座 |
| 介質 | ★★★★ 通常光纖 | ★★★★ 通常 Cat6A 銅纜 |
| 數量 | 少（每個電信間幾條） | 多（每個點位一條） |
| 變動頻率 | ★★★★★ 極低（拉了就不動） | 低（新增點位時才動） |
| 冗餘 | ★★★★★ **一定要有備援路徑** | 通常無冗餘 |
| 芯數規劃 | ★★★★★ **一次拉足，含備用** | 依點位數 + 備用比例 |

> [!tip] ★★★★★ 幹線冗餘的實務原則
> 幹線斷掉＝整層樓斷網。所以：
> - **兩條幹線走不同物理路徑**（不同管道間、不同垂直井）
> - ★★★★★ **不要兩條走同一個管道** —— 那不是冗餘，是「兩條一起被壓斷」
> - 兩條分別接到不同的核心交換器（見 [[040-01-16-guide-網路設備-鏈路聚合與STP]]）
> - 定期驗證備援真的會切換（★★★★ 不要只是「應該會」）

## 安裝或基礎操作

### 理線：水平與垂直 ★★★★

```
              機櫃正視圖（理線做對的樣子）

  ┌──────────────────────────────────────┐
  │ ▓▓▓ 24 埠配線架  P01-01 ~ P01-24     │ ← 配線架
  ├──────────────────────────────────────┤
  │ ═══ 水平理線架（1U）═══════════════  │ ← ★★★★ 每個配線架下方都要有
  ├──────────────────────────────────────┤
  │ ▓▓▓ 交換器  sw-acc-01                │
  ├──────────────────────────────────────┤
  │ ═══ 水平理線架（1U）═══════════════  │
  ├──────────────────────────────────────┤
  │ ▓▓▓ 24 埠配線架  P02-01 ~ P02-24     │
  ├──────────────────────────────────────┤
  │ ═══ 水平理線架（1U）═══════════════  │
  └──────────────────────────────────────┘
   ║                                    ║
   ║ ← 垂直理線槽（機櫃兩側）→          ║
   ║   跨 U 位的線走這裡，不要走機櫃中間 ║
```

**理線的六條規則 ★★★★★**：

| # | 規則 | 為什麼 |
| --- | --- | --- |
| ① ★★★★★ | **配線架與交換器之間一定要有水平理線架** | 沒有的話跳線會直接懸空往下垂，重量拉扯 RJ45 卡榫，時間久了接觸不良 |
| ② ★★★★★ | **跳線長度要分級備料**（例如 0.3／0.5／1／2／3 公尺） | 用 3 公尺跳線接相鄰 1U 的設備，多出來的 2.7 公尺會變成一團 |
| ③ ★★★★ | **跨 U 位的線走側邊垂直槽，不要走中間** | 走中間會擋住設備的抽換路徑與散熱氣流 |
| ④ ★★★★★ | **用魔鬼氈（Velcro）束帶，不要用尼龍束帶（cable tie）** | 尼龍束帶拉太緊會壓迫線芯改變絞距，影響高頻性能；且拆裝要剪斷 |
| ⑤ ★★★★ | **束線要「鬆而整齊」，能用手指伸進去** | 束太緊會壓扁線材；★★★ 判斷方式：綁完能輕鬆抽出單一條線 |
| ⑥ ★★★★★ | **前後分離：網路線走一側，電源線走另一側** | 降低電磁干擾；且日後動電源時不會碰到網路線 |

> [!danger] ★★★★★ 尼龍束帶是佈線的頭號敵人
> 現場最常見的「看起來很整齊、其實已經傷到線」就是尼龍束帶拉到底。
>
> ```
> 正常雙絞線：  ∿∿∿∿∿∿  絞距均勻，抗干擾靠這個
> 被束帶壓迫：  ∿∿▓▓∿∿  局部絞距被壓變形
>                   ↑
>          ★★★★★ NEXT（近端串音）在這裡劣化
>          測線儀會過（因為只是局部），但 10G 就是不穩
> ```
>
> ★★★★★ **驗收時看到整排尼龍束帶拉到底，要求全部改成魔鬼氈。**

**跳線長度分級表 ★★★★**（貼在機房備品櫃上）：

| 長度 | 用途 | 顏色建議 |
| --- | --- | --- |
| 0.3 m | 同一 U 或相鄰 U | 依用途色碼 |
| 0.5 m | 相隔 2～4 U | 依用途色碼 |
| 1.0 m | 同一機櫃內大部分連接 | 依用途色碼 |
| 2.0 m | 跨半個機櫃 | 依用途色碼 |
| 3.0 m | ★★★ 跨機櫃（**已經要考慮是不是規劃有問題**） | 依用途色碼 |
| 5 m 以上 | ★★★★★ **機櫃內原則上不該出現** | — |

### ★★★★★ 標籤規範：本篇的核心

**先講一個原則**：

> [!danger] ★★★★★ 標籤只貼一端，等於沒貼
> ```
> 情境：機櫃側標了「WEB01-eth0」，牆上插座沒標
>
> 三個月後你在牆邊，想知道這個插座對到機櫃哪一埠
>    → 只能拔掉，然後跑到機櫃看哪個燈滅了
>    → ★★★★★ 而那條線可能正在跑正式服務
> ```
> **每一條線的兩端都要有標籤，而且標籤內容必須完全一致。**
> 這是全篇最重要的一條規則。

#### 編號原則 ★★★★★

一個好的線路編號要滿足四件事：

| # | 要求 | 說明 |
| --- | --- | --- |
| ① ★★★★★ | **全域唯一** | 整棟建物內不會有兩條線同編號 |
| ② ★★★★★ | **看編號就知道位置** | 不用查表就知道大概在哪一棟、哪一層、哪一櫃 |
| ③ ★★★★ | **可排序、可擴充** | 新增點位不用重編既有編號 |
| ④ ★★★★ | **長度適中** | 太長貼不下，太短不夠用；★★★ 標籤機常見寬度容納不了太多字元 |

#### 推薦的編號格式 ★★★★★

**水平佈線（配線架 ↔ 資訊插座）**：

```
  A - 03 - TR1 - P02 - 15
  │    │    │     │     │
  │    │    │     │     └─ 埠號（01~24）
  │    │    │     └─────── 配線架編號（該電信間的第 2 面）
  │    │    └───────────── 電信間代號（該樓層第 1 間）
  │    └────────────────── 樓層（03 樓）
  └─────────────────────── 棟別（A 棟）

  完整編號：A03-TR1-P02-15
```

★★★★ **兩端都貼這個編號**：
- 機櫃側：貼在跳線上、並在配線架的埠位標示欄寫上
- 工作區側：貼在插座面板上、並貼在跳線上

**機房內設備連接（機櫃 ↔ 機櫃、設備 ↔ 交換器）**：

```
  DC1 - R03 - U26 - eth0  ──►  DC1 - R01 - SW01 - Gi1/0/12
  └──── 來源端 ────┘            └──── 目的端 ────┘

  標籤上兩端都寫（★★★★★ 這是機房內標籤的關鍵差異）：
  ┌────────────────────────────┐
  │ FROM: DC1-R03-U26 web01 eth0│
  │ TO:   DC1-R01-SW01 Gi1/0/12 │
  └────────────────────────────┘
```

> [!tip] ★★★★★ 機房內標籤要寫「兩端」，水平佈線標籤寫「線路編號」
> 差別的原因：
> - **水平佈線**：兩端位置固定，用一個唯一編號 + 一份對照表就夠了
> - ★★★★★ **機房內**：跳線經常變動，**標籤上直接寫出兩端**，
>   讓維運人員拿起線就知道它接哪裡，不用回頭查表
>
> 這是實務上非常有效的一個小差異，但很少人做對。

**光纖幹線**：

```
  BB - A03TR1 - A01ER - OM4 - 12C - 01
  │      │         │      │     │    │
  │      │         │      │     │    └─ 束內第幾芯對（01 = 1&2 芯）
  │      │         │      │     └────── 總芯數
  │      │         │      └──────────── 光纖種類
  │      │         └─────────────────── 目的端（A 棟 1 樓設備間）
  │      └───────────────────────────── 來源端（A 棟 3 樓電信間 1）
  └──────────────────────────────────── Backbone（幹線）
```

★★★★ 光纖一定要標**種類**（OM3／OM4／OS2）——
插錯種類的收發器會導致鏈路品質異常，而且很難查。

#### 標籤要貼在哪裡、貼幾張 ★★★★★

```
一條水平佈線，標籤總共要出現在 4 個地方：

  ① 配線架的埠位標示條      ← ★★★★★ 這是「面」的紀錄
  ② 配線架側的線纜本體上     ← ★★★★ 拆下面板時還看得到
  ③ 資訊插座的面板上         ← ★★★★★ 使用者端唯一的線索
  ④ 插座內側的線纜本體上     ← ★★★ 拆面板時看得到

一條機櫃內跳線，標籤要出現在 2 個地方：

  ① 靠近 A 端接頭處（★★★ 距離接頭幾公分，不要貼在接頭上）
  ② 靠近 B 端接頭處
```

**標籤本身的要求 ★★★★**：

| 項目 | 要求 | 為什麼 |
| --- | --- | --- |
| ★★★★★ **列印** | 用**標籤機列印**，不可手寫 | 手寫會褪色、看不懂、每個人字跡不同 |
| ★★★★★ **材質** | 用**纜線專用標籤**（自黏覆膜或標籤旗） | 一般紙標籤在機房會捲邊脫落 |
| ★★★★ **耐久** | 覆膜保護列印面 | 抽插時摩擦不會磨掉字 |
| ★★★★ **位置** | 距離接頭 2～5 公分 | 貼在接頭上會影響插拔 |
| ★★★ **方向** | 同一機櫃內方向一致（都朝外） | 不用轉頭找字 |
| ★★★★ **字體** | 夠大、清楚 | ★★★ 機櫃後方光線通常很差 |

> [!warning] ★★★★ 標籤旗（flag label）vs 環繞式標籤
> - **環繞式**：貼一圈在線上，字被繞掉一半，★★★ 要轉線才看得到
> - ★★★★ **標籤旗**：貼成一面小旗子，字在旗面上，**不用轉線就看得到**
>
> 機櫃內密集的跳線建議用**標籤旗**，可讀性差很多。
> 缺點是會佔一點空間，太密的線束可能不適合。

#### 色碼規範 ★★★★

> [!note] ★★★★ TIA-606 的色碼「不是」跳線顏色規範
> 很多人以為 TIA-606 規定了「跳線要用什麼顏色」。**不是的。**
>
> TIA-606 的色碼是給**標示欄位／端接欄位**用的（例如配線架上的色條），
> 用來區分這一區的線是「幹線」「水平」「進線」還是「設備間連接」。
>
> ★★★★★ **跳線顏色沒有強制標準，是各機房自己定的慣例。**
> 重點不是「用哪個顏色」，而是 ——
> **定了就寫成文件，全機房一致，而且新人看得到這份文件。**

**建議的跳線色碼（自訂慣例範例）★★★★**：

| 顏色 | 用途 | 說明 |
| --- | --- | --- |
| 🔵 **藍** | 一般內部服務網段 | 最大宗 |
| 🟢 **綠** | 管理／帶外管理（iDRAC／iLO／IPMI） | ★★★★★ 與服務網段明顯區隔，避免誤接（見 [[040-02-09-guide-機房-伺服器上架與初始設定]]） |
| 🟡 **黃** | DMZ／對外服務 | ★★★★ 拔之前會多想一秒 |
| 🔴 **紅** | ★★★★★ **關鍵鏈路：核心互連、防火牆、幹線** | 紅色＝「動它之前先問過」 |
| ⚪ **白／灰** | 語音／電話 | |
| 🟠 **橘** | 跨機房／跨棟連線 | |
| 🟣 **紫** | 儲存網路（iSCSI／備份） | |
| ⚫ **黑** | 暫時／測試用 | ★★★★ **黑色線出現超過一週就要處理掉** |

> [!tip] ★★★★★ 色碼要「少而明確」
> 定太多顏色沒有人記得住，最後大家亂拿。
> ★★★★★ **建議只嚴格區分三種**：
> ① **綠 = 帶外管理**（絕對不能接到服務網段）
> ② **紅 = 關鍵鏈路**（動之前要問）
> ③ **其他 = 一般**
>
> 剩下的顏色當成「有的話最好」，沒有也不影響安全。

**色碼文件要放哪裡 ★★★★**：

```
① 機房入口貼一張 A4 色碼對照表（護貝）        ← ★★★★★ 最有效
② 寫進維運文件庫（[[100-02-11-guide-維運-維運文件與知識庫]]）
③ 寫進佈線施工的招標規範（★★★★ 廠商施工時就要照做）
④ 新人到職清單裡（[[100-02-12-guide-維運-交接與新人上手]]）
```

## 進階應用

### 施工驗收：測線儀報告要看什麼 ★★★★★

這是驗收時**唯一有客觀依據的環節**，但大多數人只看最後那個「PASS」。

#### 銅纜測試報告的關鍵欄位 ★★★★★

一份典型的永久鏈路測試報告（示意）：

```text
========================================================
  Cable Test Report
========================================================
  Circuit ID      : A03-TR1-P02-15
  Test Date       : 2026-03-15 14:22
  Test Limit      : TIA Cat6A Permanent Link      ← ★★★★★ 看這個！
  Cable Type      : Cat6A UTP
  Overall Result  : PASS                          ← ★★ 只看這個不夠
  Length          : 47.2 m                        ← ★★★★
--------------------------------------------------------
  Wire Map        : PASS                          ← ★★★★★
  Insertion Loss  : PASS   Margin  6.4 dB         ← ★★★★ 看 Margin
  NEXT            : PASS   Margin  4.1 dB         ← ★★★★★ 看 Margin
  PS NEXT         : PASS   Margin  5.0 dB
  ACR-F (ELFEXT)  : PASS   Margin  7.2 dB
  PS ACR-F        : PASS   Margin  8.0 dB
  Return Loss     : PASS   Margin  3.8 dB
  Propagation Delay: PASS
  Delay Skew      : PASS
========================================================
```

**要看的六件事 ★★★★★**：

| # | 看什麼 | 為什麼 | 不合格的樣子 |
| --- | --- | --- | --- |
| ① ★★★★★ | **Test Limit（測試標準）** | 決定這份報告有沒有意義 | 用 `Cat6 Channel` 測 Cat6A 永久鏈路 → **報告無效** |
| ② ★★★★★ | **Wire Map（線序圖）** | 抓接錯線、斷線、短路、跨接對 | `FAIL` 或顯示 split pair |
| ③ ★★★★★ | **Margin（餘裕）** | ★★★★★ **PASS 只代表「剛好過」，Margin 才代表「做得好不好」** | Margin 接近 0 或負值 |
| ④ ★★★★ | **Length（長度）** | 對照設計圖，抓「拉太長」與「線材不實」 | 超過 90 公尺 |
| ⑤ ★★★★★ | **是否有 `PASS*`（星號）** | 見下面說明 | 出現 `*` |
| ⑥ ★★★★ | **報告是否逐條、可追溯** | 抓「只測幾條就交報告」 | 報告條數 < 點位數 |

> [!danger] ★★★★★ `PASS*`（帶星號）是什麼意思
> 測線儀在**測試值落在儀器量測不確定度範圍內**時，會標示 `PASS*` 或 `FAIL*`。
>
> 白話說：**「這條線在合格邊緣，儀器無法百分之百確定它是過還是不過」**。
>
> ★★★★★ **驗收時的正確立場**：
> - `PASS*` **一律要求重測或重做**，不接受
> - 因為它今天勉強過，明天溫度變了、跳線換了，就可能不過
> - ★★★★★ **契約與招標規範裡要明訂「不接受帶星號的結果」**
>
> 同理，Margin 極小（例如小於 1～2 dB）的線也值得追問：
> 是施工品質問題，還是線材品質問題？

**Margin（餘裕）怎麼看 ★★★★★**：

```
  合格線（Limit）
       │
       │  ← Margin 大 = ★★★★★ 施工品質好，日後有變動空間
  ─────┼─────────────────────  實測值
       │
       │  ← Margin 小 = ★★★ 剛好過，日後容易變不過
  ─────┼──── 實測值 ─────────
       │
       └──── 實測值（FAIL）

★★★★★ 判定原則：
  整批線的 Margin 應該「分佈相近」。
  如果大部分線 Margin 都有 5~8 dB，但有幾條只有 1 dB
  → ★★★★★ 那幾條一定有施工問題（壓迫、彎折、端接不良）
     即使它們標示 PASS，也要求重做
```

★★★★ **這個「看分佈找離群值」的技巧，比看單條線的絕對值有用得多。**

#### 光纖測試報告 ★★★★

光纖測試分兩層：

| | Tier 1（基本） | Tier 2（延伸） |
| --- | --- | --- |
| 儀器 | ★★★★ 光損失測試組（OLTS／光功率計＋光源） | ★★★★ OTDR |
| 測什麼 | **總插入損耗**（dB）、長度、極性 | 沿線每個事件點的位置與損耗 |
| 能回答 | 「這條光纖整體通不通、損耗夠不夠低」 | ★★★★★ 「損耗發生在哪一個接頭／熔接點」 |
| 驗收要求 | ★★★★★ **一定要有** | ★★★★ 幹線建議要求；水平光纖可視情況 |

**光纖報告要看的東西 ★★★★**：

| 項目 | 說明 |
| --- | --- |
| ★★★★★ **極性（Polarity）** | Tx/Rx 有沒有接對。★★★★★ 光纖最常見的錯誤就是極性接反，且症狀是「完全不通」 |
| ★★★★★ **插入損耗 vs 損耗預算** | 實測值必須低於依「長度 + 接頭數 + 熔接點數」算出的預算值 |
| ★★★★ **長度** | 對照設計 |
| ★★★★ **光纖種類標示** | OM3／OM4／OS2 要與採購一致 |
| ★★★★ **雙向測試** | ★★★ 好的報告會做雙向，單向測試可能漏掉某些問題 |
| ★★★★ **端面檢查** | ★★★★★ 用光纖顯微鏡確認端面清潔 —— **髒污是光纖故障的頭號原因** |

> [!danger] ★★★★★ 光纖端面清潔是被嚴重低估的事
> 一個指紋、一粒灰塵在光纖端面上，就足以造成鏈路不穩或完全不通。
>
> - ★★★★★ **每次插拔前都要清潔**（用專用清潔筆／清潔帶，不是用衣服擦）
> - ★★★★★ **未使用的接頭一定要蓋防塵蓋**
> - ★★★★ 驗收時要求提供**端面檢查的照片或報告**
> - ★★★★★ **不要用眼睛直視光纖出口** —— 雷射光會傷害視網膜且看不見

### 現場常見的十二種施工缺失 ★★★★★

驗收走一趟機房與電信間，這十二項一項一項看：

| # | 缺失 | 怎麼發現 | 後果 |
| --- | --- | --- | --- |
| ① ★★★★★ | **標籤只貼一端 / 兩端不一致** | 隨機抽 10 條，對照兩端 | 日後無法追線，等於沒標 |
| ② ★★★★★ | **尼龍束帶拉到底** | 目視：束帶處線材是否被壓出凹痕 | NEXT 劣化，10G 不穩 |
| ③ ★★★★★ | **彎曲半徑過小**（直角折、繞柱子折死） | 目視：有沒有近乎直角的轉折 | 損耗上升；光纖可能斷芯 |
| ④ ★★★★ | **剝皮過長、解絞過多** | 拆開一個配線架模組看端接 | ★★★★★ 高頻性能直接崩掉 |
| ⑤ ★★★★ | **強電弱電同槽或緊貼** | 目視線槽 | 電磁干擾；★★★ 也可能違反規範 |
| ⑥ ★★★★ | **沒有留維修餘長** | 看配線架後方與插座後方 | 日後重新端接時線不夠長，要整條重拉 |
| ⑦ ★★★★★ | **餘長盤成小圈捆死** | 目視天花板／地板下 | ★★★★ 小圈＝彎曲半徑不足；捆死＝壓迫 |
| ⑧ ★★★★ | **跳線長度不當**（5 米線接相鄰 U） | 目視機櫃 | 線團擋氣流、擋抽換 |
| ⑨ ★★★★★ | **沒有水平理線架，跳線懸空** | 目視 | 重量拉扯接頭，長期接觸不良 |
| ⑩ ★★★★ | **穿牆／穿樓板未做防火填塞** | 目視穿孔處 | ★★★★★ 消防檢查會被開缺失，火災時煙囪效應 |
| ⑪ ★★★★ | **線槽塞爆**（填充率過高） | 目視：蓋子蓋不上、線被壓扁 | 散熱差、壓迫、日後無法增加 |
| ⑫ ★★★★★ | **測試報告條數少於實際點位數** | 數報告 vs 數點位 | ★★★★★ 代表有線沒測過就交付 |

> [!warning] ★★★★★ 驗收時一定要「隨機抽驗」，不能只看報告
> 報告可以造假（同一條線測多次改編號），但現場的束帶、彎折、標籤造不了假。
>
> ★★★★★ **建議的驗收方法**：
> 1. 先看報告（全部條數、測試標準、有無星號、Margin 分佈）
> 2. 隨機抽 5～10% 的點位，**當場用測線儀複測**
> 3. 現場目視走一趟，逐項對照上面十二點
> 4. 抽驗 10 條標籤，確認兩端一致且與紀錄表相符
> 5. ★★★★ 抽驗結果與報告不符 → **要求全面複測**

### 讓「拔錯線」變得很難發生 ★★★★★

標籤與色碼的最終目的就是這件事。三層防護：

```
第一層：★★★★ 顏色
        綠色（帶外管理）與紅色（關鍵鏈路）一眼可辨
        → 手伸過去之前就會遲疑

第二層：★★★★★ 標籤
        拿起線就看得到 FROM / TO
        → 不用「拔看看誰斷了」

第三層：★★★★ 紀錄與監控
        線路紀錄表 + 交換器埠位描述 + 監控告警
        → 真的拔錯了，30 秒內會有人知道
```

**第三層的具體做法：把描述寫進交換器埠位 ★★★★**

> [!example] Juniper JunOS
> ```junos
> set interfaces ge-0/0/15 description "A03-TR1-P02-15 | 3F會議室AP | VLAN30"
> set interfaces ge-0/0/16 description "DC1-R03-U26 web01 eth0 | VLAN20"
> commit
> ```
>
> 查詢：
> ```junos
> show interfaces descriptions
> ```
> ```text
> Interface       Admin Link Description
> ge-0/0/15       up    up   A03-TR1-P02-15 | 3F會議室AP | VLAN30
> ge-0/0/16       up    up   DC1-R03-U26 web01 eth0 | VLAN20
> ```
>
> ★★★★★ **`description` 欄位的內容要與實體標籤一致**，
> 這樣「看設定」與「看線」得到的答案會相同。

> [!info]- Cisco IOS 對照
> ```cisco
> interface GigabitEthernet1/0/15
>  description A03-TR1-P02-15 | 3F會議室AP | VLAN30
> !
> interface GigabitEthernet1/0/16
>  description DC1-R03-U26 web01 eth0 | VLAN20
> ```
>
> 查詢：
> ```cisco
> show interfaces description
> ```
> ```text
> Interface              Status         Protocol Description
> Gi1/0/15               up             up       A03-TR1-P02-15 | 3F會議室AP | VLAN30
> Gi1/0/16               up             up       DC1-R03-U26 web01 eth0 | VLAN20
> ```
>
> ★★★★ 兩個平台的原則相同：**埠位描述 = 實體標籤內容**。
> 詳細操作見 [[040-01-13-guide-Cisco-埠設定與安全]] 與 [[040-01-08-guide-Juniper-埠設定與安全]]。

**從主機端反查實體位置 ★★★★**

在 Linux 上用 LLDP 找出「這張網卡接到哪台交換器的哪個埠」：

```bash
sudo apt install -y lldpd
sudo systemctl enable --now lldpd
# ★★★ 等一個 LLDP 週期（通常 30 秒左右）
sudo lldpctl eth0
```

```text
-------------------------------------------------------------------------------
LLDP neighbors:
-------------------------------------------------------------------------------
Interface:    eth0, via: LLDP
  Chassis:
    SysName:      sw-acc-3f-01
    SysDescr:     Juniper Networks, Inc. ex2300-24t
    MgmtIP:       10.20.30.5
  Port:
    PortID:       ifname ge-0/0/16
    PortDescr:    DC1-R03-U26 web01 eth0 | VLAN20
-------------------------------------------------------------------------------
```

★★★★★ **這是「不用進機房就知道線接在哪」的最快方法。**
前提是：① 交換器有開 LLDP；② 埠位描述有正確填寫。

> [!tip] ★★★★ 把 LLDP 資訊納入建置驗收
> 在新機建置流程（[[020-02-03-01-svc-標準化-新機建置標準流程]]）的驗收項目裡加一條：
> **`lldpctl` 能查到正確的交換器與埠位描述**。
>
> 這一條同時驗證了三件事：線接對了、埠位描述填了、LLDP 開了。

### 佈線規劃的容量預留 ★★★★

新建或整修時，**預留比重拉便宜太多**：

| 項目 | 建議預留 | 理由 |
| --- | --- | --- |
| ★★★★★ **線槽填充率** | 施工完成後不超過線槽容量的一定比例（依規範） | ★★★★★ 塞滿的線槽等於「以後不能再加線」 |
| ★★★★★ **光纖芯數** | 現在需要的數倍 | 施工成本主要在管道與人力，多拉幾芯幾乎不加錢 |
| ★★★★ **穿牆套管** | 多留幾個空管 | 事後打洞要走申請、要停機、要補防火 |
| ★★★★ **配線架埠位** | 預留一定比例空埠 | 新增點位不用加配線架 |
| ★★★★ **機櫃 U 位** | 為理線架、未來設備留空間 | 見 [[040-02-03-guide-機房-機櫃規劃與設備上架]] |
| ★★★ **電信間空間** | 預留擴充機櫃位置 | |

> [!danger] ★★★★★ 最貴的佈線決策：「先拉現在需要的就好」
> 佈線的成本結構是：
> ```
> 材料費（線材本身）      ★     小
> 施工費（人力、拉線）    ★★★★  大
> 管道與土建（開孔、走線架）★★★★★ 最大
> 停機與干擾成本          ★★★★★ 最大
> ```
> ★★★★★ **既然貴的是「拉這件事」而不是「線」，那就一次拉夠。**
> 三年後為了多兩條線再開一次天花板，成本是現在多拉的十倍以上。

## 完整實戰範例

### 場景

```
A 棟 3 樓要新增一間會議室（3F 會議室 C），需求：
  - 4 個網路資訊插座（2 個給有線設備、1 個給 AP、1 個備用）
  - 距離 3 樓電信間 TR1 約 45 公尺（走線實際長度）
  - AP 要用 PoE
  - 未來可能升 10G

既有環境：
  A 棟 3F 電信間 TR1
    ├─ 機櫃 R01
    │    ├─ U40  24 埠配線架 P01（已滿）
    │    ├─ U39  水平理線架
    │    ├─ U38  交換器 sw-acc-3f-01（Juniper EX，24 埠 PoE）
    │    ├─ U37  水平理線架
    │    └─ U36  24 埠配線架 P02（已用 12 埠，尚有 12 埠空位）
    └─ 幹線：兩條 OM4 光纖到 1F 設備間（走不同管道）
```

### 步驟 1：規劃（動工前把編號先定好）★★★★★

```
1-1 線材選擇
    距離 45 m < 80 m，且要考慮未來 10G
    → ★★★★★ Cat6A UTP（不用 Cat6，差價遠低於日後重拉）

1-2 使用既有配線架 P02 的空埠：13、14、15、16

1-3 ★★★★★ 先把編號表定出來（動工前就定，不是事後補）
```

| 線路編號 | A 端（配線架） | B 端（插座） | 用途 | VLAN | 色碼 |
| --- | --- | --- | --- | --- | --- |
| `A03-TR1-P02-13` | R01 P02 埠13 | 3F會議室C 東牆 面板1 埠1 | 桌面設備 | 30 | 藍 |
| `A03-TR1-P02-14` | R01 P02 埠14 | 3F會議室C 東牆 面板1 埠2 | 桌面設備 | 30 | 藍 |
| `A03-TR1-P02-15` | R01 P02 埠15 | 3F會議室C 天花板 AP位 | AP（PoE） | 40 | 藍 |
| `A03-TR1-P02-16` | R01 P02 埠16 | 3F會議室C 東牆 面板1 埠3 | 備用 | — | 藍 |

```
1-4 寫進招標／施工規範（★★★★★ 這一步決定驗收有沒有依據）
    □ 線材：Cat6A UTP，須提供規格書
    □ 測試：★★★★★ 以「永久鏈路（Permanent Link）」模式，
             依 Cat6A 標準測試，逐條提供報告
    □ ★★★★★ 不接受帶星號（PASS*）的測試結果
    □ 標籤：★★★★★ 兩端皆須貼標，內容一致，使用標籤機列印覆膜標籤
    □ 標籤內容：依業主提供之編號表
    □ 束線：★★★★ 一律使用魔鬼氈，禁用尼龍束帶
    □ 餘長：兩端各留維修餘長（★★★ 依規範，並整齊盤放於容許彎曲半徑內）
    □ 穿牆／穿樓板：須做防火填塞
    □ 交付：測試報告（電子檔 + 紙本）、竣工圖、標籤與編號對照表
```

### 步驟 2：施工中的查核 ★★★★

```
2-1 進場前確認
    □ 線材到貨，核對規格標示（★★★★ 拍照存證：線身印字含類別）
    □ 施工人員知道編號規則（★★★ 開工前開一次會，比事後改省事）

2-2 拉線階段抽查
    □ 走線路徑是否與規劃一致
    □ ★★★★★ 彎曲處是否有直角折
    □ ★★★★★ 是否與電力線同槽或緊貼
    □ 束帶是否為魔鬼氈
    □ 穿牆處是否預留防火填塞

2-3 端接階段抽查
    □ ★★★★ 隨機拆一個模組看剝皮長度與解絞長度
    □ 兩端線序是否一致（★★★ T568A 或 T568B 擇一，全案統一）
    □ 餘長是否留足且盤放正確
```

> [!warning] ★★★★★ T568A 與 T568B 不要混用
> 兩種線序的差別只在**橘與綠對調**。
> - 兩端**同一種** → 直通線，正常
> - 兩端**不同種** → 跳接線（crossover），現代設備多半有 Auto-MDIX 會自己協調，
>   ★★★★ **但這會讓故障排查變得莫名其妙**
>
> ★★★★★ **整個案子（最好是整棟建物）只用一種**，寫進規範，
> 並在配線架與插座上標示採用哪一種。

### 步驟 3：驗收 ★★★★★

**3-1 檢視測試報告**

```text
========================================================
  Cable Certification Report — Summary
  Project : A棟3F會議室C 新增點位
  Date    : 2026-04-08
  Tester  : （廠牌型號）  Firmware: （版本）
  Limit   : TIA Cat6A Permanent Link          ← ★★★★★ 確認正確
--------------------------------------------------------
  ID                   Length   Result   NEXT Margin
  A03-TR1-P02-13       44.8 m   PASS     5.2 dB
  A03-TR1-P02-14       45.1 m   PASS     4.9 dB
  A03-TR1-P02-15       47.6 m   PASS     1.1 dB   ← ★★★★★ 有問題！
  A03-TR1-P02-16       45.0 m   PASS     5.0 dB
========================================================
```

★★★★★ **發現離群值**：
`P02-15` 的 NEXT Margin 只有 1.1 dB，其他三條都在 5 dB 左右。

```
判斷：
  ✗ 不是線材問題（同一批線）
  ✗ 不是長度問題（47.6 m 與其他相差不多）
  ✓ ★★★★★ 幾乎確定是「這一條的施工品質」有問題

可能原因：
  - 端接時解絞過長
  - 某處被束帶壓迫
  - 走線時被折過
  - 模組本身瑕疵

處置：★★★★★ 要求廠商重做端接後複測，不接受「反正 PASS」
```

**3-2 現場抽驗**

```
□ 用測線儀複測 P02-15（重做後）
  → NEXT Margin 提升到 4.8 dB  ✅

□ 隨機抽 P02-13 複測
  → 與報告數值相近（★★★ 允許小幅差異）  ✅

□ 目視十二項缺失清單
  ✅ 標籤兩端一致
  ✅ 全部使用魔鬼氈
  ✅ 無直角折
  ⚠ 天花板段有一處餘長盤成過小的圈  → ★★★★ 要求重新盤放
  ✅ 穿牆已做防火填塞
  ✅ 強弱電分槽
  ✅ 報告條數 = 點位數 = 4

□ 抽驗標籤 4 條，兩端內容完全一致  ✅
```

**3-3 標籤與紀錄核對**

```
配線架 P02 埠位標示條：
  ┌────┬────┬────┬────┐
  │ 13 │ 14 │ 15 │ 16 │
  │會議│會議│會議│會議│
  │室C │室C │室C │室C │
  │桌1 │桌2 │AP  │備用│
  └────┴────┴────┴────┘

插座面板（3F會議室C 東牆）：
  ┌──────────────────┐
  │ ○ A03-TR1-P02-13 │
  │ ○ A03-TR1-P02-14 │
  │ ○ A03-TR1-P02-16 │
  └──────────────────┘

天花板 AP 位：
  標籤旗：A03-TR1-P02-15

★★★★★ 三處都對得上，且與紀錄表一致 → 通過
```

### 步驟 5：三個月後的回頭驗證 ★★★★

★★★★ 佈線案的真正驗收是在**三個月後**：

```
□ 標籤還在嗎？有沒有捲邊脫落？
   → ★★★ 脫落代表用錯標籤材質，要求廠商改善或自行更換

□ 紀錄表還正確嗎？（這三個月有沒有人動過線但沒更新）
   → ★★★★★ 不正確代表變更流程沒有落實，要修流程不是修表

□ 有沒有人「臨時拉一條」而沒有走流程？
   → ★★★★ 機櫃裡出現不明的黑色跳線就是徵兆

□ 使用者有沒有回報「網路不穩」？
   → ★★★★ 若集中在某幾個點位，回頭看那幾條的 Margin
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ 完全不通，測線儀顯示 Wire Map FAIL（open） | 端接不良、線芯沒壓到底、模組故障 | 重新端接兩端；換模組後複測 |
| ★★★★★ 完全不通，光纖鏈路兩端都亮但沒連線 | ★★★★★ **極性接反**（Tx/Rx 顛倒） | 對調一端的收發位置；或改用正確極性的跳線 |
| ★★★★ 1G 正常但 10G 一直重連 | Cat6 距離過長／施工品質不佳／Margin 太小 | 查該條的測試 Margin；★★★★ 距離超過條件就改 Cat6A 或光纖 |
| ★★★★★ 網路間歇性斷線，重插跳線就好一陣子 | 跳線懸空受重量拉扯、RJ45 卡榫斷裂 | 加裝水平理線架；換跳線；★★★★ 檢查卡榫是否斷了 |
| ★★★★ 測線儀顯示 split pair（分岔對） | 端接時線序看似對但實際配對錯 | ★★★★★ 重新端接，嚴格照 T568A/B 的**配對**而非只看顏色順序 |
| ★★★★ 測試 PASS 但 Margin 極小（離群） | 束帶壓迫、彎折、解絞過長 | 找出該條的物理路徑逐段檢查；重新端接後複測 |
| ★★★★★ 報告全部 PASS，但實際使用不穩 | ★★★★★ 用「通道模式」測而非永久鏈路；或報告造假 | 要求以永久鏈路模式重測；現場抽驗複測 |
| ★★★★ 出現 `PASS*`／`FAIL*` | 測試值落在儀器不確定度範圍內 | ★★★★★ **一律要求重做**，不接受 |
| ★★★★ 光纖損耗偏高但線沒問題 | ★★★★★ 端面髒污 | 用專用清潔工具清潔兩端；用顯微鏡確認；★★★ 未使用時蓋防塵蓋 |
| ★★★★★ 找不到某條線接到哪 | 標籤只貼一端／標籤脫落／紀錄未更新 | 短期：用 LLDP 或線路追蹤器（tone generator）找；長期：★★★★★ 補標籤並修正流程 |
| ★★★★ 拔錯線造成服務中斷 | 色碼未落實、標籤不清、無 FROM/TO 資訊 | 導入三層防護（顏色／標籤／紀錄與監控） |
| ★★★★ 線槽塞爆，新線加不進去 | 規劃時填充率沒留餘裕 | 短期：整理既有線、移除廢線；長期：★★★★★ 增設線槽 |
| ★★★★★ 機櫃裡有一堆不知道通到哪的「殭屍線」 | 設備汰換後線沒拆、也沒紀錄 | ★★★★ 每年做一次線路盤點：兩端都查不到用途的線，掛牌觀察一個月後移除 |
| ★★★ 標籤褪色／捲邊脫落 | 用一般紙標籤或手寫 | 換成標籤機列印的覆膜纜線專用標籤 |
| ★★★★ 同一棟樓有兩條線編號相同 | 編號規則沒有含棟別／樓層 | 改用含棟別+樓層+電信間的完整編號；★★★★★ 全域唯一 |
| ★★★★ PoE 設備供電不足或不穩 | 線材品質不佳、距離過長、線徑過細 | 確認線材規格；★★★ 檢查是否用了非標準的細線徑跳線 |
| ★★★★ 電磁干擾造成錯誤率上升 | 網路線與電力線同槽或平行貼合 | 分槽敷設；★★★ 必須交叉時盡量垂直交叉 |
| ★★★★★ 消防檢查被開缺失：穿樓板未防火填塞 | 施工時漏做 | 補做防火填塞；★★★★★ 寫進未來所有佈線案的驗收項目 |
| ★★★ 竣工圖與現況不符 | 施工中有變更但圖沒改 | ★★★★ 驗收條件加上「竣工圖須反映實際施工」 |

### 追一條沒有標籤的線 ★★★★

> [!warning] ★★★★★ 這是「補救」不是「方法」
> 需要用到下面這些手段，代表標籤制度已經失效。
> 追完之後**一定要補上標籤與紀錄**，否則下次還要再追一次。

**方法 A：LLDP（最快，但只適用於支援 LLDP 的設備）★★★★**

```bash
sudo lldpctl | grep -E 'Interface|SysName|PortID'
```
```text
Interface:    eth0, via: LLDP
    SysName:      sw-acc-3f-01
    PortID:       ifname ge-0/0/16
```

**方法 B：從交換器查 MAC 位址表 ★★★★**

> [!example] Juniper JunOS
> ```junos
> show ethernet-switching table | match 00:11:22
> ```
> ```text
> office   00:11:22:33:44:55  D  ge-0/0/16
> ```

> [!info]- Cisco IOS 對照
> ```cisco
> show mac address-table address 0011.2233.4455
> ```
> ```text
>  Vlan    Mac Address       Type        Ports
>    30    0011.2233.4455    DYNAMIC     Gi1/0/16
> ```

**方法 C：埠位閃燈法 ★★★**

```bash
# 在主機上產生持續流量，讓對應埠的燈狂閃
ping -f -i 0.01 <對端IP>
```
★★★ 缺點：只能確認「機櫃裡是哪個埠」，不能確認實體線的走向。

**方法 D：線路追蹤器（Tone Generator + Probe）★★★★**

```
發訊器接在 A 端 → 拿探棒沿線槽掃 → 嗶聲最大的就是那條
★★★★★ 這是唯一能追「牆內／天花板內」路徑的方法
★★★ 缺點：需要儀器，且線束密集時容易誤判
```

**方法 E：★★★★★ 最後手段 —— 拔看看**

> [!danger] ★★★★★ 拔線測試的紀律
> 如果真的走到這一步：
> 1. **一定要事先公告**，並在維護時間窗內做
> 2. **一次只拔一條**，拔之前拍照
> 3. ★★★★★ **拔之前先確認這不是關鍵鏈路**（紅色線一律不准用這招）
> 4. 確認後**立刻插回並貼上標籤**
> 5. 更新紀錄表
>
> ★★★★★ **絕對不要在沒有公告的情況下「拔看看」。**
> 這是機房事故最常見的直接原因。

## 安全性注意事項

### 實體安全 ★★★★

| 項目 | 說明 |
| --- | --- |
| ★★★★★ **帶外管理線必須實體隔離** | 綠色線（iDRAC／iLO／IPMI）走獨立交換器或至少獨立 VLAN，**絕不與服務網段共用**（見 [[040-02-09-guide-機房-伺服器上架與初始設定]]） |
| ★★★★ **未使用的埠要關閉** | 空的資訊插座若已接到交換器，等於一個「插上就進內網」的入口 |
| ★★★★★ **會議室／公共區域的插座** | 應納入獨立 VLAN 或加上埠安全機制（見 [[040-01-08-guide-Juniper-埠設定與安全]]） |
| ★★★★ **配線架與機櫃上鎖** | 見 [[040-02-13-guide-機房-機房實體安全]] |
| ★★★ **線路圖屬於敏感資訊** | 完整的佈線圖等於機房拓樸圖，★★★★ 不要隨意外流 |

> [!danger] ★★★★★ 「這個插座沒人用」不代表它是安全的
> 一個接到交換器但沒人用的插座，是**最理想的內網入侵點**：
> - 沒有人在用 → 插上去沒人會發現
> - 通常在會議室、走廊、茶水間 → 實體容易接近
>
> ★★★★★ **原則：沒有明確用途的埠，在交換器上一律 `disable`。**
> 需要時再開通，並走變更流程。

### 消防與法規 ★★★★★

| 項目 | 說明 |
| --- | --- |
| ★★★★★ **防火填塞** | 穿牆、穿樓板、穿防火區劃的孔洞**必須做防火填塞**。漏做會被消防檢查開缺失，火災時形成煙囪效應 |
| ★★★★ **纜線的耐燃等級** | 部分場所對纜線的耐燃等級有規範（例如回風空間）。★★★★★ **依建物性質與現行法規／招標規範確認** |
| ★★★★ **不阻礙逃生通道** | 線槽、走線架不得影響逃生路徑與消防設備 |
| ★★★★ **不遮蔽偵煙器／撒水頭** | 天花板走線時要注意 |
| ★★★ **接地** | 遮蔽型線材（STP／FTP）與金屬線槽的接地要依規範做，★★★★ 接地做錯比不做遮蔽更糟 |

> [!warning] ★★★★★ 防火填塞是驗收必查項目
> 這一項**很容易被漏掉**，因為孔洞通常在天花板上或牆角，不看不會發現。
> 而且它是**事後最難補救**的 —— 補做要重新拆天花板。
>
> ★★★★★ **寫進招標規範、寫進驗收清單、施工中就要抽查拍照。**

### 施工期間的服務保護 ★★★★★

```
★★★★★ 佈線施工是機房事故的高風險期。三個保護措施：

① 隔離工作區
   ── 現有的線束、機櫃用防塵布或隔板保護
   ── ★★★★ 施工人員不得碰觸不在工作範圍內的設備

② 明確的「不可觸碰」標示
   ── 核心設備、關鍵鏈路貼上明顯的警示標示
   ── ★★★★★ 紅色跳線 = 施工期間絕對不能動

③ 全程監工
   ── ★★★★★ 機關人員全程在場，不要「讓廠商自己做，做完再看」
   ── 施工前後各拍一次現況照片
```

> [!danger] ★★★★★ 佈線施工造成既有服務中斷的三大原因
> 1. **拉新線時扯到既有線束** → 用防塵布隔離，並要求緩慢施工
> 2. **為了走線而暫時拔掉既有跳線，插回時位置錯了** → ★★★★★ 施工前拍照，且**禁止未經同意拔任何既有跳線**
> 3. **在機櫃上方鑽孔，碎屑掉進設備** → ★★★★★ 機櫃頂部要完全遮蔽，且施工後清潔

## 練習題

> [!question]- 練習 1：算一算距離夠不夠（★★★ 入門）
> **題目**：從電信間到某個工作區，實際走線長度是 87 公尺。
> 機櫃側需要 2 公尺跳線，工作區側使用者要用 5 公尺跳線。這樣可以嗎？
>
> **參考解答**：
> - 固定佈線 87 m ≤ 90 m ✅（勉強合格，但已經沒什麼餘裕）
> - 跳線合計 2 + 5 = 7 m ≤ 10 m ✅
> - 通道總長 87 + 7 = 94 m ≤ 100 m ✅
>
> **表面上通過，但 ★★★★ 實務上有兩個問題**：
> ① 87 m 已經接近上限，**沒有餘裕給日後重新端接時的損耗**；
> ② 使用者用 5 m 跳線代表位置可能有問題，日後若換成更長的就會超標。
>
> ★★★★★ **建議**：規劃階段就不該讓固定佈線超過 80 m。
> 87 m 的點位應該考慮增設中間電信間或改用光纖。

> [!question]- 練習 2：設計你自己的編號規則（★★★★）
> **題目**：依你實際的建物與機房，設計一套線路編號規則，並寫出至少五個實例。
>
> **參考解答框架**：
> 規則要滿足四個條件：全域唯一、看編號知位置、可排序可擴充、長度適中。
>
> 範例（單棟建物）：
> ```
> <樓層2碼>-<電信間>-<配線架>-<埠2碼>
> 03-TR1-P02-15
> ```
> 範例（多棟建物）：
> ```
> <棟>-<樓層2碼>-<電信間>-<配線架>-<埠2碼>
> A-03-TR1-P02-15
> ```
> ★★★★ **檢查方式**：拿你的規則去套「最複雜的那個點位」（例如地下室、頂樓機房、
> 跨棟連通道），看規則會不會破功。

> [!question]- 練習 3：抓出測試報告的問題（★★★★★）
> **題目**：以下是某案的測試摘要，找出至少三個問題。
> ```text
> Limit  : TIA Cat6 Channel
> ID              Length   Result
> P01-01          88.4 m   PASS
> P01-02          91.2 m   PASS
> P01-03          87.9 m   PASS*
> P01-05          88.0 m   PASS
> ```
> （招標規範要求：Cat6A、永久鏈路模式、共 6 個點位）
>
> **參考解答**：
> 1. ★★★★★ **Test Limit 錯誤**：用 `Cat6 Channel` 測，但規範要求 **Cat6A 永久鏈路**。
>    通道模式標準較寬鬆，且 Cat6 不是 Cat6A → **整份報告無效，要求重測**
> 2. ★★★★★ **P01-02 長度 91.2 m 超過 90 m 上限**，永久鏈路模式下應該不合格
>    （用通道模式測才「過」，這正是模式錯誤造成的）
> 3. ★★★★★ **P01-03 是 `PASS*`（帶星號）**，落在儀器不確定度範圍內，不接受
> 4. ★★★★★ **只有 4 條報告，但有 6 個點位** —— P01-04 與 P01-06 沒有測試紀錄
>
> ★★★★★ **結論：這份報告四項全錯，應退回要求全面重測。**

> [!question]- 練習 4：制定你機房的色碼規範（★★★★）
> **題目**：寫出一份可以護貝貼在機房門口的色碼對照表，並說明如何確保它被遵守。
>
> **參考解答重點**：
> - ★★★★★ 至少嚴格定義三種：**綠=帶外管理、紅=關鍵鏈路、其他=一般**
> - 對照表要有：顏色樣本、用途、「動之前要不要問」的欄位
> - **確保被遵守的方法**：
>   ① 機房門口護貝張貼；② 寫進佈線招標規範；
>   ③ ★★★★★ **備品櫃只準備規範內顏色的跳線**（沒有其他顏色可拿，自然就遵守了）；
>   ④ 納入新人到職清單；⑤ 巡檢時檢查有無違規顏色

## 小測驗

**Q1.** 「網路線最長 100 公尺」這句話中的 100 公尺，實際上是怎麼分配的？
如果固定佈線拉了 95 公尺，會有什麼問題？

**Q2.** （是非）驗收佈線時，用「通道（Channel）模式」測試比「永久鏈路（Permanent Link）模式」
更貼近實際使用情況，所以應該優先要求廠商用通道模式測。

**Q3.** 測線儀報告上出現 `PASS*`（帶星號）代表什麼？驗收時應該怎麼處理？

**Q4.** 一批 24 條線的測試報告全部 PASS，其中 22 條的 NEXT Margin 在 5～7 dB，
另外 2 條只有 1.2 dB。請問這 2 條有沒有問題？為什麼？

**Q5.** （這個做法會發生什麼）施工廠商為了讓機櫃看起來整齊，用尼龍束帶把每一束跳線
都拉得緊緊的，外觀非常漂亮。

**Q6.** 為什麼「機房內跳線的標籤」要寫 FROM/TO 兩端位置，
而「水平佈線的標籤」寫一個唯一編號就好？

**Q7.** （是非）TIA-606 規定了跳線的顏色，所以機房應該嚴格按照 TIA-606 的顏色來買跳線。

**Q8.** 你在機櫃裡發現一條沒有標籤的線，需要知道它接到哪裡。
請依「風險由低到高」排出你會嘗試的方法順序。

**Q9.** 某佈線案完工三年後，發現「線路紀錄表跟現況完全對不上」。
請指出根本原因是什麼，以及正確的解法是「修表」還是「修別的東西」。

**Q10.** 拉光纖幹線時，承辦人為了節省預算，只拉了「現在需要的 4 芯」。
請說明這個決定為什麼是錯的，並用成本結構解釋。

> [!question]- 測驗答案
>
> **A1.** ★★★★★ **90 公尺固定佈線（永久鏈路）+ 兩端跳線合計 10 公尺 = 100 公尺通道。**
> 固定佈線拉 95 公尺的問題：
> ① 已超過 90 公尺上限，**永久鏈路測試不會過**；
> ② 加上跳線後通道會超過 100 公尺，訊號品質不受標準保證；
> ③ 即使 1G 勉強能通，日後升 10G 就會出問題，等於要重拉。
> ★★★★ 規劃時建議不超過 80 公尺，留餘裕給走線繞路與維修餘長。
> → 見「觀念說明 / 100 公尺是怎麼分的」。
>
> **A2.** ✗ 錯，而且是 ★★★★★ 等級的錯。
> 通道模式的合格標準**比永久鏈路寬鬆**，因為它假設你已接受跳線的損耗。
> 用通道模式測，可能出現「永久鏈路過不了但通道過得了」的線 ——
> 這些線在你換一條較長的跳線時就會開始不穩。
> ★★★★★ **驗收要測永久鏈路，因為那才是施工廠商交付的範圍；
> 跳線是會一直換的消耗品。** 契約要明訂測試模式。
> → 見「觀念說明 / 通道與永久鏈路」。
>
> **A3.** ★★★★★ 代表**測試值落在儀器的量測不確定度範圍內**，
> 白話說就是「這條線在合格邊緣，儀器無法確定它到底過不過」。
> ★★★★★ **驗收時一律要求重測或重做，不接受帶星號的結果**，
> 因為它今天勉強過，明天溫度變了、跳線換了就可能不過。
> 招標規範裡就要寫明這一條。
> → 見「進階應用 / `PASS*` 是什麼意思」。
>
> **A4.** ★★★★★ **有問題，即使標示 PASS 也應該要求重做。**
> 理由：同一批線材、同一批施工，Margin 應該分佈相近。
> 有 2 條顯著偏低（1.2 dB vs 5～7 dB）代表**這 2 條的施工品質有問題** ——
> 可能是束帶壓迫、彎折、解絞過長或模組瑕疵。
> 它們今天剛好過，但沒有任何餘裕，環境一變就會出狀況。
> ★★★★ 「看分佈找離群值」比看單條的絕對值有用得多。
> → 見「進階應用 / Margin 怎麼看」。
>
> **A5.** ★★★★★ **外觀漂亮，但已經傷到線。**
> 尼龍束帶拉到底會**局部壓迫線材、改變雙絞線的絞距**，
> 而抗干擾能力（NEXT）正是靠絞距維持的。
> 後果：測線儀可能還是 PASS（因為只是局部劣化），
> 但 **10G 會不穩**，而且是那種「時好時壞、查不出原因」的故障。
> ★★★★★ 正確做法是用**魔鬼氈（Velcro）**，束到「能用手指伸進去、能抽出單一條線」的鬆度。
> → 見「安裝或基礎操作 / 理線的六條規則」④⑤ 與 danger callout。
>
> **A6.** 因為兩者的**變動頻率不同**：
> - **水平佈線**兩端位置固定、幾乎不變動 → 一個唯一編號 + 一份對照表就夠了
> - ★★★★★ **機房內跳線經常變動** → 標籤上直接寫 FROM/TO，
>   讓維運人員**拿起線就知道它接哪裡，不用回頭查表**
>
> 機房裡最需要的是「當下立刻知道」，因為那通常是在排查故障或準備拔線的時刻。
> → 見「安裝或基礎操作 / 推薦的編號格式」的 tip callout。
>
> **A7.** ✗ 錯。★★★★ TIA-606 的色碼是給**標示欄位／端接欄位**用的
> （用來區分幹線、水平、進線等不同功能區），**不是跳線顏色規範**。
> ★★★★★ **跳線顏色沒有強制標準，是各機房自訂的慣例。**
> 重點不是用哪個顏色，而是「定了就寫成文件、全機房一致、新人看得到」。
> 實務建議只嚴格區分三種：綠=帶外管理、紅=關鍵鏈路、其他=一般。
> → 見「安裝或基礎操作 / 色碼規範」的 note callout。
>
> **A8.** ★★★★ 由低風險到高風險：
> ① **`lldpctl`**（完全不動線，最快，前提是設備支援 LLDP）；
> ② **從交換器查 MAC 位址表**（`show ethernet-switching table` / `show mac address-table`）；
> ③ **閃燈法**（`ping -f` 讓埠燈狂閃，只能確認機櫃內是哪個埠）；
> ④ **線路追蹤器**（Tone Generator + Probe，唯一能追牆內路徑的方法）；
> ⑤ ★★★★★ **拔看看** —— 最後手段，必須事先公告、在維護窗內、一次一條、
> 拍照、且**關鍵鏈路（紅線）一律不准用這招**。
> ★★★★★ 追完之後**一定要補標籤與紀錄**，否則下次還要再追一次。
> → 見「常見錯誤與排錯 / 追一條沒有標籤的線」。
>
> **A9.** ★★★★★ **根本原因是「變更流程沒有把紀錄更新綁進去」，不是表做得不好。**
> 三年裡一定有人新增點位、換交換器、改跳線，但沒有人更新表。
>
> **正確解法是「修流程」不是「修表」**：
> ① 在 [[100-02-08-guide-維運-變更管理流程]] 的檢查表加一項
> 「線路紀錄表已更新」，未勾選不得結案；
> ② 讓交換器埠位 `description` 與紀錄表一致，可以寫腳本自動比對找差異；
> ③ 每年做一次線路盤點。
> ★★★★★ 只重建一次表而不改流程，三年後會再壞一次。
> → 見「安裝或基礎操作 / 線路紀錄表」的 danger callout。
>
> **A10.** ★★★★★ 錯，因為**佈線的成本結構是「拉這件事」貴，不是「線」貴**：
> ```
> 材料費（光纖本身）        ★     小
> 施工費（人力、拉線）      ★★★★  大
> 管道與土建（開孔、走線架）★★★★★ 最大
> 停機與干擾成本            ★★★★★ 最大
> ```
> 既然貴的部分與芯數幾乎無關，一次多拉幾芯的邊際成本極低。
> 三年後為了多兩芯而重新開挖管道、拆天花板、安排停機，
> **成本是現在多拉的十倍以上**。
> ★★★★ 這是佈線裡投資報酬率最高的一個決定。
> → 見「觀念說明 / 三個絕對不要」③ 與「進階應用 / 佈線規劃的容量預留」。
