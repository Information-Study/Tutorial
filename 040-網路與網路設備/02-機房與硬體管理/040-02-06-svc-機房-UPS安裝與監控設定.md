# UPS 安裝與監控設定

> [!abstract] 這篇你會學到
> - 把 UPS **正確上架與接線**：位置、載重、輸入迴路、輸出插座分配、哪些設備不准接 UPS
> - 看懂 NUT（Network UPS Tools）的**三層架構**：driver → upsd → upsmon，出事時才知道要看哪一層
> - ★★★★★ 寫出**四個設定檔的完整可用範例**：`ups.conf`／`upsd.conf`／`upsd.users`／`upsmon.conf`
> - ★★★★★ 建立 **primary／secondary（舊稱 master／slave）架構**，讓一顆 UPS 保護整櫃主機
> - ★★★★ 用 `upssched` 做出**多主機依序關機**：先關前端、再關資料庫、最後關 primary
> - ★★★★★ 完整演練「**拔掉市電 → 看 `upsc` 變化 → 各主機依序關機 → 復電自動開機**」
> - 用 SNMP 管理卡取代 USB 線，把 UPS 狀態接進 Zabbix／Prometheus 與 [[100-01-03-guide-日誌-系統監控與告警]]
> - apcupsd 的對照寫法，以及什麼情況該選它而不是 NUT

> [!warning] 未實機驗證
> 本篇的 **NUT 設定檔內容以 NUT 官方文件（`ups.conf(5)`、`upsd.conf(5)`、`upsd.users(5)`、
> `upsmon.conf(5)` 手冊頁）的通用寫法為準**，指令與參數名稱皆為 NUT 標準用法。
>
> 但是：**各家 UPS 的驅動名稱、`upsc` 會吐出哪些變數、支援哪些 `instcmd`，
> 每一台機型都不一樣**，本篇的 `upsc` 輸出是「典型長相」而非你那台的實際輸出。
> ★★★★★ **上線前一定要在你自己的機型上跑一次 `upsc` 與拔電演練**，
> 不要把本篇的數值當成規格。
>
> apcupsd 與 SNMP 管理卡（APC NMC／Eaton NetworkCard-MS 等）的欄位名稱同樣依機型而異，
> 請以你手上那張卡的 Web 介面與 MIB 檔為準。

## 觀念說明

### ★★★★★ 先講清楚：UPS 不是「不斷電」，是「爭取關機時間」

機關最常見的錯誤觀念是「有 UPS 就不會停機」。實際上：

```
市電正常  ───────────────────────────────►  UPS 只是在旁邊充電
   │
   ▼ 停電
UPS 放電  ──── 5～30 分鐘 ────►  電池耗盡  ──►  輸出直接切斷（硬斷電）
   │                                              │
   │  ★★★★★ 這段時間你要做的事                    ▼
   └─► 偵測到停電 → 通知 → 依序關機 → 關掉 UPS      沒設定的話：
                                                  全部主機像被拔插頭一樣死掉
```

★★★★★ **沒有做自動關機設定的 UPS，價值只有「撐過瞬斷」而已。**
真正長時間停電時，它讓你的主機在第 20 分鐘被硬斷電，
跟第 0 秒被硬斷電的結果一模一樣 —— 檔案系統損毀、資料庫需要 recovery、RAID 需要重建一致性檢查。

### UPS 與主機之間的四種通訊路徑 ★★★★

| 路徑 | 介面 | 能監控幾台 | 典型用途 | 備註 |
| --- | --- | --- | --- | --- |
| ★★★ **USB** | UPS 的 USB Type-B 埠 → 主機 USB | **1 台**直連，其餘靠網路轉發 | 中小機房最常見 | 線長受 USB 規範限制，不要拉很長 |
| ★★ **RS-232（DB9）** | 序列埠 | 1 台 | 老機型、工控環境 | 現代伺服器多半要 USB 轉序列 |
| ★★★★ **SNMP 管理卡** | UPS 擴充槽插網卡 | **不限**，全都是網路用戶端 | 中大型機房、多機櫃 | 需要額外採購管理卡，成本最高但最乾淨 |
| ★ **乾接點（Relay／Dry contact）** | 繼電器接點 | 1 台 | 只給 PLC／機房監控盤讀「有電／沒電」 | 只有開關訊號，**沒有電量、負載、電壓** |

> [!tip] 選哪一種？
> ★★★★ **只有一個機櫃、預算有限** → USB 直連一台 Linux 主機當 NUT primary，其餘主機當 secondary。
> ★★★★ **兩個機櫃以上、或 UPS 與主機不在同一櫃** → 直接買 SNMP 管理卡，
> 少掉「primary 主機自己掛掉就全盤失效」的單點問題。
>
> ★★★ **不要買乾接點回來想做自動關機** —— 它給不出電池剩餘電量，
> 你無法判斷「還能撐多久」，只能做成「一停電就立刻關機」，這在瞬斷時會造成無謂停機。

### NUT 的三層架構 ★★★★★

這是本篇最重要的一張圖。**排錯時第一件事就是判斷卡在哪一層。**

```
┌─────────────────────────────────────────────────────────┐
│  【第一層】driver  （usbhid-ups / snmp-ups / nutdrv_qx）  │
│   職責：跟 UPS 講話，把廠商私有協定翻譯成 NUT 變數        │
│   設定檔：/etc/nut/ups.conf                              │
│   驗證：upsdrvctl start   / systemctl status nut-driver@ups1 │
│   壞掉的症狀：driver 起不來、找不到裝置                    │
└────────────────────────┬────────────────────────────────┘
                         │ 共享記憶體 / socket
                         ▼
┌─────────────────────────────────────────────────────────┐
│  【第二層】upsd    （NUT 的網路伺服器，預設 TCP 3493）     │
│   職責：把 driver 的資料開成網路服務，做帳號驗證           │
│   設定檔：/etc/nut/upsd.conf（監聽位址）                  │
│           /etc/nut/upsd.users（帳號密碼與權限）           │
│   驗證：upsc ups1@localhost                              │
│   壞掉的症狀：Connection refused / Access denied          │
└────────────────────────┬────────────────────────────────┘
                         │ TCP 3493
          ┌──────────────┼──────────────┬──────────────┐
          ▼              ▼              ▼              ▼
   ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
   │ upsmon     │ │ upsmon     │ │ upsmon     │ │ upsc / 監控 │
   │ (primary)  │ │(secondary) │ │(secondary) │ │  平台      │
   │ 本機       │ │ web01      │ │ db01       │ │ Zabbix 等  │
   └────────────┘ └────────────┘ └────────────┘ └────────────┘
   【第三層】upsmon 職責：盯狀態、發通知、時間到了執行關機
             設定檔：/etc/nut/upsmon.conf
             壞掉的症狀：狀態看得到但不會關機
```

> [!note] 三層各自獨立，可以分開驗證 ★★★★
> - `upsc` 有輸出 → 第一層與第二層都正常
> - `upsc` 有輸出但停電不關機 → 問題在第三層 `upsmon.conf`
> - `upsc` 說 `Access denied` → 問題在 `upsd.users`
> - `upsc` 說 `Connection refused` → 問題在 `upsd.conf` 的 `LISTEN` 或防火牆
>
> ★★★★ **不要一次改三個檔然後重開機看結果**，永遠一層一層往上驗。

### primary 與 secondary（舊稱 master / slave）★★★★★

```
                       ┌──────────────┐
                       │     UPS      │
                       └──────┬───────┘
                              │ USB 線（只能接一台！）
                              ▼
   ┌──────────────────────────────────────────┐
   │  nut-pri  (10.20.30.10)                  │
   │  角色：primary                            │
   │  跑：driver + upsd + upsmon(primary)      │
   │  ★★★★★ 它是「最後一個關機」的人           │
   │           而且由它負責叫 UPS 斷電          │
   └──────────────┬───────────────────────────┘
                  │ TCP 3493（管理網段）
        ┌─────────┼─────────┐
        ▼         ▼         ▼
   ┌────────┐ ┌────────┐ ┌────────┐
   │ web01  │ │ db01   │ │ file01 │
   │secondary│ │secondary│ │secondary│
   │只跑 upsmon│ │只跑 upsmon│ │只跑 upsmon│
   └────────┘ └────────┘ └────────┘
   ★★★★ 它們「先關機」，關完斷開連線，primary 才會動
```

★★★★★ **角色決定關機順序，寫錯了整個機制就失效。**

| 角色 | 在 `upsd.users` 寫 | 在 `upsmon.conf` 寫 | 停電到低電量時的行為 |
| --- | --- | --- | --- |
| ★★★★★ **primary** | `upsmon primary` | `MONITOR ... primary` | **等 secondary 全部斷線**（最多等 `HOSTSYNC` 秒）→ 才關自己 → 建立 killpower 旗標 → 關機途中叫 UPS 斷電 |
| ★★★★ **secondary** | `upsmon secondary` | `MONITOR ... secondary` | 一看到 `OB LB` **立刻**執行 `SHUTDOWNCMD` |

> [!warning] primary / secondary 與 master / slave 的用詞 ★★★
> NUT 2.8 起把 `master` / `slave` 改稱 `primary` / `secondary`，
> **舊關鍵字仍然可用（向下相容）**，但新設定建議寫 `primary` / `secondary`。
>
> ★★★ 混用會出現「有些版本看得懂、有些看不懂」的怪問題 ——
> **同一套環境裡的所有主機統一用同一組用詞**。
> 不確定手上版本支援哪一種，先跑 `upsd -h` 或 `dpkg -l nut-server` 看版本號，
> 2.7.x 以下請一律用 `master` / `slave`。

### killpower：為什麼關機還要「叫 UPS 斷電」 ★★★★★

這是新手最容易漏掉、而且**漏掉之後平常完全看不出問題**的一段。

```
情境：停電，電池撐了 20 分鐘，主機在第 18 分鐘全部關機完成
      ★ 此時 UPS 還有一點點電，還在輸出

第 22 分鐘：電池真的耗盡，UPS 輸出切斷
第 40 分鐘：★★★★★ 市電復電

問題來了：
  ┌─ 沒有 killpower ─────────────────────────────────┐
  │  UPS 一直帶著（已關機的）主機，電池被榨到全空       │
  │  復電後 UPS 要先充電，但主機是「關機」狀態          │
  │  → 主機不會自己開機，你得跑一趟機房按電源鍵         │
  │  → 更糟：電池深度放電，壽命大幅縮短                 │
  └────────────────────────────────────────────────┘
  ┌─ 有 killpower ───────────────────────────────────┐
  │  主機關完 → primary 主動下令 UPS「切斷輸出」        │
  │  → UPS 輸出斷電，電池停止放電（保住電池）           │
  │  → 復電後 UPS 恢復輸出                             │
  │  → 主機 BIOS 設 AC Power Recovery = Power On       │
  │    ★★★★★ 自動開機，不用跑機房                     │
  └────────────────────────────────────────────────┘
```

★★★★★ **killpower 要成立，需要三件事同時做對：**

1. `upsmon.conf` 裡有 `POWERDOWNFLAG /etc/killpower`
2. 系統關機流程的**最後階段**會檢查該旗標並執行 `upsdrvctl shutdown`
   （Debian／Ubuntu 的 `nut-client` 套件已附這個關機期腳本／unit）
3. ★★★★★ 伺服器 BIOS 的 **AC Power Recovery 設成 `Power On`（開機）**，
   不是 `Last State`，也不是 `Power Off` —— 這一項在 [[040-02-09-guide-機房-伺服器上架與初始設定]] 講。

### ups.status 的狀態碼 ★★★★★

`upsc` 輸出裡 **`ups.status` 是唯一要背起來的欄位**：

| 狀態碼 | 全名 | 意義 | 你該做什麼 |
| --- | --- | --- | --- |
| ★★★ `OL` | On Line | 市電正常 | 正常 |
| ★★★★ `OB` | On Battery | **正在放電**（停電中） | 告警、確認原因、準備關機 |
| ★★★★★ `LB` | Low Battery | **電量低**，關機門檻已達 | upsmon 會觸發關機 |
| ★★★ `RB` | Replace Battery | UPS 自我測試判定**電池該換了** | 見 [[040-02-07-guide-機房-UPS電池維護與更換]] |
| ★★ `CHRG` | Charging | 充電中 | 正常（剛復電或剛換電池） |
| ★★ `DISCHRG` | Discharging | 放電中 | 通常與 `OB` 一起出現 |
| ★★★ `OVER` | Overloaded | **過載** | 立刻減載，見 [[040-02-05-guide-機房-UPS選型與容量計算]] |
| ★★★ `BYPASS` | Bypass | 走旁路，**電池不保護** | 查為什麼進旁路 |
| ★★★★★ `FSD` | Forced Shutdown | primary 已下令強制關機 | 所有 secondary 立刻關機 |
| ★★ `TRIM` / `BOOST` | 降壓／升壓 | AVR 正在調壓 | 市電品質不佳，記錄下來 |

★★★★ 狀態會**組合出現**，例如 `OB DISCHRG`（停電放電中）、`OL CHRG`（市電正常充電中）、
`OB LB`（停電且低電量 —— **這就是觸發關機的條件**）。

## 安裝或基礎操作

### 第一步：UPS 上架與接線 ★★★★

> [!danger] 帶電作業風險
> ★★★★★ **UPS 內部即使拔掉市電，電池端仍然帶電**，而且是低阻抗大電流源。
> 一支金屬工具跨過電池端子會直接產生電弧。
>
> - 上架、接線一律**兩人作業**，一人操作一人監護
> - 脫下手錶、戒指、金屬手鍊
> - 使用**絕緣柄工具**
> - ★★★★★ **不要自己拆開 UPS 主機殼** —— 電池更換走前面板電池匣，
>   拆機殼是原廠維修範圍，詳見 [[040-02-07-guide-機房-UPS電池維護與更換]]

**上架位置**（詳細機櫃規劃見 [[040-02-03-guide-機房-機櫃規劃與設備上架]]）：

| 項目 | 做法 | 理由 |
| --- | --- | --- |
| ★★★★★ **垂直位置** | **機櫃最底部**（U1 起算） | UPS 是全櫃最重的東西，重心必須壓低，否則整櫃有翻覆風險 |
| ★★★★ **滑軌／層板** | 一定要用**原廠滑軌或承重層板** | 一般設備滑軌承重不足，機架式 UPS 常見數十公斤起跳 |
| ★★★ **前後間距** | 前後留出散熱間距，不要緊貼盲板 | UPS 逆變器與電池會發熱 |
| ★★★★ **與電池匣的關係** | 電池匣要能**從前面抽出**，前方不可被理線槽擋住 | 換電池時不用拆整台 |
| ★★★ **輸入線** | 由櫃底走線，走**電力側線槽**，與網路線分槽 | 避免電磁干擾，見 [[040-02-08-guide-機房-結構化佈線與標籤規範]] |

**輸出插座分配 ★★★★★**：

```
UPS 輸出（假設 8 個 IEC C13 + 2 個 C19）
 ├─ C19 ×2 ──► 兩台 PDU（不同 PDU 帶不同 A/B 側設備）
 ├─ C13 ×4 ──► 核心交換器、防火牆、核心路由器、機房監控主機
 ├─ C13 ×2 ──► 主要伺服器（單電源機型）
 └─ C13 ×2 ──► 保留（★★★ 一定要留，臨時要接東西時不用拔別人）

★★★★★ 絕對不准接上 UPS 的東西：
 ✗ 雷射印表機（加熱器瞬間電流極大，會直接讓 UPS 過載）
 ✗ 除濕機、冷氣、電暖器、飲水機（電感／大功率負載）
 ✗ 吸塵器、電鑽等施工工具（機房施工時最常犯）
 ✗ 任何「不是 IT 設備」的東西
```

> [!warning] ★★★★ 接線後務必量一次實際負載
> 接完之後看 UPS 面板或 `upsc` 的 `ups.load`（百分比）。
> ★★★★ **持續負載建議壓在標稱容量的合理餘裕之下**，
> 具體門檻依機型規格與你算出來的 runtime 需求而定 —— 計算方法在
> [[040-02-05-guide-機房-UPS選型與容量計算]]，本篇不重複。
> 重點是：**接完線的當下就要量，不要等到停電才知道過載。**

**USB 線的接法 ★★★**：

```
UPS 背面「USB」埠（通常是方形 Type-B）
        │
        │  ★★★ 用 UPS 原廠附的那條線，不要用手機充電線
        │  ★★★★ 線材不要拉超過機櫃範圍；要跨櫃請改用 SNMP 卡
        ▼
nut-pri 主機的 USB 埠（★★★ 建議接「主機背板」的埠，不要接前面板）
```

接好之後在 primary 主機上確認系統有看到裝置：

```bash
lsusb
```

```text
Bus 002 Device 003: ID 051d:0002 American Power Conversion Uninterruptible Power Supply
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
```

★★★ 看到廠商名稱（American Power Conversion／Eaton／CyberPower…）就代表**實體層通了**。
沒看到的話：換一條線、換一個 USB 埠、`dmesg -T | tail -30` 看有沒有掉線訊息。

```bash
sudo dmesg -T | grep -i -E 'usb|hid' | tail -10
```

```text
[Wed Sep  2 09:14:22 2026] usb 2-1: new full-speed USB device number 3 using xhci_hcd
[Wed Sep  2 09:14:22 2026] hid-generic 0003:051D:0002.0001: hiddev0,hidraw1: USB HID v1.10 Device
```

### 第二步：安裝 NUT ★★★

**Ubuntu / Debian（主線）**：

```bash
sudo apt update

### 第三步：`/etc/nut/nut.conf` — 決定這台機器的角色 ★★★★★

這個檔只有一行有意義，**但它決定哪些服務會啟動**，是最常被漏掉的一步。

```ini
# /etc/nut/nut.conf   —— primary（有接 USB 線、要對外提供服務）
#
# MODE 可用值：
#   none      不啟用任何 NUT 功能（套件預設值）
#   standalone 本機自己接 UPS、自己監控，不對外開放
#   netserver  本機接 UPS，並對外提供 upsd 服務  ← primary 用這個
#   netclient  本機沒接 UPS，只跑 upsmon 連到別台  ← secondary 用這個
MODE=netserver
```

```ini
# /etc/nut/nut.conf   —— secondary（web01 / db01 / file01）
MODE=netclient
```

> [!danger] ★★★★★ MODE 忘了改是頭號災難
> 套件安裝後 `MODE=none`，此時：
> - `systemctl start nut-server` 看起來會成功（或立刻結束），
> - **但 upsd 根本沒起來**，`upsc` 一定連不上。
>
> ★★★★★ **裝完 NUT 第一件事就是改 `nut.conf`**，
> 不是先去改 `ups.conf`。順序錯了會浪費一小時排錯。

### 第四步：`/etc/nut/ups.conf` — 告訴 driver 怎麼跟 UPS 講話 ★★★★★

**先讓 NUT 自己掃**（比手動猜 driver 準得多）：

```bash
sudo nut-scanner -U
```

```text
Scanning USB bus.
[nutdev1]
        driver = "usbhid-ups"
        port = "auto"
        vendorid = "051D"
        productid = "0002"
        product = "Smart-UPS 1500"
        vendor = "American Power Conversion"
        bus = "002"
```

★★★★ **把掃出來的內容當骨架**，改成有意義的名字（下面用 `ups1`）：

```ini
# /etc/nut/ups.conf   ——【primary 專用；secondary 不需要這個檔的內容】
#
# ★★★ 全域區（沒有中括號的部分）必須寫在所有 [區段] 之前

# driver 起不來時最多重試幾次（秒）
maxretry = 3
retrydelay = 5

# ★★★★ 這裡的 [名稱] 就是日後 upsc / upsmon 要用的 UPS 識別名
#      建議命名規則：<機房>-<機櫃>-ups<序號>，例如 dc1-r03-ups1
#      本篇為了範例簡短，用 ups1
[ups1]
    # ★★★★★ driver 名稱是「跟哪一款 UPS 講話」的關鍵，寫錯就完全連不上
    #   usbhid-ups   → 大多數支援 USB HID Power Device 的 UPS（APC/Eaton/多數品牌）
    #   nutdrv_qx    → Megatec/Q1 協定的 UPS（很多平價機種）
    #   blazer_usb   → 舊版 Megatec USB（已被 nutdrv_qx 取代，舊系統可能還在用）
    #   apcsmart     → APC 的序列埠 Smart 協定（RS-232）
    #   snmp-ups     → 透過 SNMP 管理卡（見「進階應用」）
    #   ★★★★ 不確定用哪個，跑 nut-scanner，或查 NUT 官方硬體相容清單（HCL）
    driver = usbhid-ups

    # port：USB 驅動一律寫 auto；序列埠寫 /dev/ttyS0；snmp-ups 寫 IP
    port = auto

    # ★★★ 有多台同型 UPS 接在同一主機時，靠 serial 或 bus 區分，否則會抓錯台
    # serial = "AS1234567890"

    # ★★ 純描述，會出現在 upsc 的 device.description
    desc = "DC1 R03 主機櫃 UPS"

    # ★★★ 輪詢間隔（秒）。太短沒必要、太長會延遲偵測到停電
    pollinterval = 2
```

> [!tip] ★★★ 命名一旦決定就不要改
> `ups1` 這個名字會出現在：`upsd.users`、`upsmon.conf`（primary 與**所有** secondary）、
> 監控平台的 item key、告警訊息、巡檢表。
> 改名要同步改一整圈，**上線前想清楚，上線後不要改**。

**先手動測 driver 能不能起來（不要直接 `systemctl start`）**：

```bash
sudo upsdrvctl start ups1
```

成功：

```text

Network UPS Tools - Generic HID driver 0.47 (2.8.0)
USB communication driver (libusb 1.0) 0.43
Using subdriver: APC HID 0.96
```

失敗（★★★★ 最常見的兩種）：

```text

No matching HID UPS found
Driver failed to start (exit status=1)
```
→ USB 沒接好、driver 選錯、或 UPS 沒開機。

```text

```
→ ★★★★ 權限問題，見「常見錯誤與排錯」的 udev 那一列。

```bash

```

### 第五步：`/etc/nut/upsd.conf` — upsd 監聽在哪裡 ★★★★★

```ini
# /etc/nut/upsd.conf   ——【primary 專用】
#
# ★★★★★ 這是本篇最重要的資安設定：LISTEN 決定誰連得到你的 UPS 服務

# 本機一定要有（primary 自己的 upsmon 與 upsc 走這條）
LISTEN 127.0.0.1 3493

# ★★★★★ 只監聽「管理網段」的那張介面的 IP，不要寫 0.0.0.0
#        寫 0.0.0.0 = 對所有介面開放，包含可能對外的那張網卡
LISTEN 10.20.30.10 3493

# ★★★ 同時服務的最大連線數。secondary 台數 + 監控系統 + 手動查詢，抓寬一點
MAXCONN 64

# ★★★★ 資料超過幾秒沒更新就視為「陳舊」，upsd 會回報 data stale
#      預設 15 秒。設太小會在 driver 忙碌時誤報
MAXAGE 15

# ★★★ 如果要跑 TLS（NUT 內建 SSL 支援，需編譯時有帶），才需要下面兩行
# CERTFILE /etc/nut/upsd.pem
```

> [!danger] ★★★★★ 不要寫 `LISTEN 0.0.0.0 3493`
> 這會讓 UPS 服務出現在**每一張網卡**上，包含 DMZ 或對外那張。
>
> 攻擊者連上 3493 之後即使沒有帳號，也能：
> - 列舉你有幾台 UPS、機型、`desc` 欄位（等於送出機房拓樸資訊）
> - 對帳號做暴力猜測
>
> ★★★★★ **正確做法：`LISTEN` 綁死管理網段的 IP，再用防火牆限制來源。**

搭配防火牆（ufw 的完整用法見 [[090-02-02-guide-防火牆-ufw基礎與實務]]）：

```bash
# ★★★★ 只允許管理網段內的 secondary 與監控主機連 3493
sudo ufw allow from 10.20.30.0/24 to any port 3493 proto tcp comment 'NUT upsd'
sudo ufw status numbered | grep 3493
```

```text
[ 7] 3493/tcp                   ALLOW IN    10.20.30.0/24              # NUT upsd
```

### 第六步：`/etc/nut/upsd.users` — 帳號與權限 ★★★★★

```ini
# /etc/nut/upsd.users   ——【primary 專用】
# ★★★★★ 這個檔含明文密碼，權限必須是 root:nut 0640

# ── 管理帳號：人用的，可以下指令（測試電池、關蜂鳴器、改變數）──
[nutadmin]
    # ★★★★★ 換成你自己的高強度密碼，不要用範例密碼
    password = CHANGE-ME-admin-9f2b7d41
    # actions = SET  允許用 upsrw 修改 UPS 上的可寫變數
    actions = SET
    # instcmds = ALL 允許用 upscmd 下所有立即指令
    # ★★★★ 想更嚴的話改成白名單，例如：
    #   instcmds = test.battery.start.quick
    #   instcmds = beeper.disable
    instcmds = ALL

# ── primary 自己的 upsmon 用的帳號 ──
[monpri]
    password = CHANGE-ME-monpri-4c8e1a06
    # ★★★★★ 這一行是 primary/secondary 機制的核心
    #        primary 才有權限得知「還有哪些 secondary 連著」
    upsmon primary

# ── 所有 secondary 共用的唯讀監控帳號 ──
[monsec]
    password = CHANGE-ME-monsec-7b3d9e52
    upsmon secondary

# ── 監控平台（Zabbix / Prometheus exporter）專用唯讀帳號 ──
# ★★★ 給監控用的帳號「不要」給 upsmon 角色，也不要給 actions/instcmds
[zbxro]
    password = CHANGE-ME-zbxro-2a6f8c13
```

### 第七步：`/etc/nut/upsmon.conf`（primary 端）★★★★★

這是最長也最關鍵的一個檔。

```ini
# /etc/nut/upsmon.conf   ——【primary：nut-pri, 10.20.30.10】

# ═══════════════════════════════════════════════════════════
#  MONITOR <ups名>@<主機> <電源數> <帳號> <密碼> <角色>
# ═══════════════════════════════════════════════════════════
# ★★★★★ <電源數> 是「這台 UPS 供應本機幾顆電源供應器」，不是 UPS 台數！
#        單電源主機 → 1
#        雙電源主機但兩顆都插同一台 UPS → 2
#        雙電源主機分插兩台 UPS → 兩行 MONITOR，各寫 1
MONITOR ups1@localhost 1 monpri CHANGE-ME-monpri-4c8e1a06 primary

# ★★★★★ 本機至少要有幾顆電源「有電」才算安全
#        單電源機器 = 1
#        雙電源分插兩台 UPS 的機器：寫 1 表示「掛一台還能撐」
MINSUPPLIES 1

# ═══════════════════════════════════════════════════════════
#  關機指令
# ═══════════════════════════════════════════════════════════
# ★★★★ 這是「時間到了」真正執行的指令。
#      +0 = 立刻關機。不要寫 -r（重開機），停電時重開機沒有意義
SHUTDOWNCMD "/sbin/shutdown -h +0"

# ★★★★★ killpower 旗標檔。upsmon 決定關機時會建立它，
#        關機流程末段的 NUT 腳本看到它就會叫 UPS 斷電
POWERDOWNFLAG /etc/killpower

# ═══════════════════════════════════════════════════════════
#  輪詢與逾時
# ═══════════════════════════════════════════════════════════
# ★★★ 正常狀態下幾秒問一次 upsd
POLLFREQ 5
# ★★★★ 已經在 OB（放電）狀態時改成幾秒問一次 —— 要比 POLLFREQ 短或相等
POLLFREQALERT 5

# ★★★★★ primary 在下令關機前，最多等 secondary 斷線幾秒
#        設太短 → secondary 還沒關完 primary 就切電
#        設太長 → 電池可能先耗盡
#        ★★★★ 依「最慢那台 secondary 關機需要多久」決定，並在演練中實測
HOSTSYNC 30

# ★★★ 幾秒收不到 upsd 回應就判定「失聯」
DEADTIME 15

# ★★★ 執行 SHUTDOWNCMD 前的緩衝秒數（讓通知訊息有時間送出去）
FINALDELAY 5

# ═══════════════════════════════════════════════════════════
#  告警節流
# ═══════════════════════════════════════════════════════════
# ★★★ 出現 RB（該換電池）之後，每隔幾秒重複提醒一次。43200 = 12 小時
RBWARNTIME 43200
# ★★★★ 與 upsd 失聯幾秒後開始告警。300 = 5 分鐘
NOCOMMWARNTIME 300

# ═══════════════════════════════════════════════════════════
#  通知：訊息內容
# ═══════════════════════════════════════════════════════════
# %s 會被代換成 "ups1@localhost"
NOTIFYMSG ONLINE    "[UPS] %s 已恢復市電供電"
NOTIFYMSG ONBATT    "[UPS] %s 停電，改由電池供電中"
NOTIFYMSG LOWBATT   "[UPS] %s 電池電量過低，即將關機"
NOTIFYMSG FSD       "[UPS] %s 已進入強制關機程序（FSD）"
NOTIFYMSG COMMOK    "[UPS] %s 通訊恢復"
NOTIFYMSG COMMBAD   "[UPS] %s 通訊中斷"
NOTIFYMSG SHUTDOWN  "[UPS] %s 本機即將關機"
NOTIFYMSG REPLBATT  "[UPS] %s 回報電池需要更換（RB）"
NOTIFYMSG NOCOMM    "[UPS] %s 完全無法通訊"
NOTIFYMSG NOPARENT  "[UPS] upsmon 的父行程已消失，無法執行關機"

# ═══════════════════════════════════════════════════════════
#  通知：怎麼送
# ═══════════════════════════════════════════════════════════
# 可用旗標（用 + 串接）：
#   SYSLOG  寫入 syslog          ← ★★★★ 一律都要開，這是事後查證的依據
#   WALL    廣播給所有已登入終端
#   EXEC    執行 NOTIFYCMD
#   IGNORE  完全忽略（★★★ 不要用在 ONBATT / LOWBATT / FSD）
NOTIFYFLAG ONLINE    SYSLOG+WALL+EXEC
NOTIFYFLAG ONBATT    SYSLOG+WALL+EXEC
NOTIFYFLAG LOWBATT   SYSLOG+WALL+EXEC
NOTIFYFLAG FSD       SYSLOG+WALL+EXEC
NOTIFYFLAG COMMOK    SYSLOG+EXEC
NOTIFYFLAG COMMBAD   SYSLOG+WALL+EXEC
NOTIFYFLAG SHUTDOWN  SYSLOG+WALL+EXEC
NOTIFYFLAG REPLBATT  SYSLOG+WALL+EXEC
NOTIFYFLAG NOCOMM    SYSLOG+WALL+EXEC
NOTIFYFLAG NOPARENT  SYSLOG+WALL+EXEC

# ★★★★★ 把通知交給 upssched 處理（依序關機的關鍵，見「進階應用」）
NOTIFYCMD /usr/sbin/upssched

# ═══════════════════════════════════════════════════════════
#  執行身分
# ═══════════════════════════════════════════════════════════
# ★★★ upsmon 以 root 啟動，網路那半會降權到這個使用者
RUN_AS_USER nut
```

## 進階應用

### secondary 端設定（每一台受保護的主機）★★★★★

secondary **不需要** `ups.conf`、`upsd.conf`、`upsd.users`，只要兩個檔：

```ini
# /etc/nut/nut.conf   ——【secondary：web01 / db01 / file01】
MODE=netclient
```

```ini
# /etc/nut/upsmon.conf   ——【secondary：web01, 10.20.30.21】

# ★★★★★ 注意三個不同點：
#   ① @ 後面是 primary 的 IP，不是 localhost
#   ② 帳號用 monsec（secondary 專用）
#   ③ 角色寫 secondary
MONITOR ups1@10.20.30.10 1 monsec CHANGE-ME-monsec-7b3d9e52 secondary

MINSUPPLIES 1
SHUTDOWNCMD "/sbin/shutdown -h +0"
POWERDOWNFLAG /etc/killpower

POLLFREQ 5
POLLFREQALERT 5
# ★★★ secondary 的 HOSTSYNC 不影響關機順序（是 primary 在等它），保留預設即可
HOSTSYNC 15
DEADTIME 15
FINALDELAY 5

### 用 upssched 做「多主機依序關機」★★★★★

**問題**：預設行為是所有 secondary 在 `LB` 時**同時**關機。
但實務上你要的順序通常是：

```
停電後 T+2 分鐘   ★★  關掉「可以先犧牲」的：測試機、報表機
停電後 T+6 分鐘   ★★★ 關掉前端：web01（先讓使用者看到維護頁）
停電後 T+9 分鐘   ★★★★ 關掉檔案伺服器：file01
停電後 T+12 分鐘  ★★★★★ 關掉資料庫：db01（★ 一定是最後才關的服務）
低電量 LB 時      ★★★★★ 關掉 primary 本身 → killpower
```

**做法**：在每台主機上用 `upssched` 的 `START-TIMER`，各設不同秒數。

```ini
# /etc/nut/upssched.conf   ——【web01：停電後 6 分鐘關機】

# ★★★ CMDSCRIPT 是計時器到期時要執行的腳本
CMDSCRIPT /etc/nut/upssched-cmd

# ★★★★ upssched 的 daemon 用的 socket 與鎖檔，目錄要存在且 nut 使用者可寫
PIPEFN /run/nut/upssched.pipe
LOCKFN /run/nut/upssched.lock

# ── 事件對應 ────────────────────────────────────────────
# 語法：AT <事件> <ups識別> <動作>
#   START-TIMER <名稱> <秒數>   啟動計時器，時間到執行 CMDSCRIPT <名稱>
#   CANCEL-TIMER <名稱>         取消計時器
#   EXECUTE <名稱>              立刻執行 CMDSCRIPT <名稱>

# ★★★★★ 停電開始 → 啟動 360 秒（6 分鐘）計時器
AT ONBATT * START-TIMER shutdown-web 360

# ★★★★★ 這一行不可以漏！復電時要取消計時器，
#        否則「停電 10 秒又復電」的瞬斷會在 6 分鐘後把機器關掉
AT ONLINE * CANCEL-TIMER shutdown-web

# ★★★ 停電滿 60 秒先發一次告警（給人反應時間）
AT ONBATT * START-TIMER warn-ops 60
AT ONLINE * CANCEL-TIMER warn-ops

# ★★★★ 低電量時不等計時器，立刻走 upsmon 原本的關機流程
#      （LOWBATT 由 upsmon 自己處理，這裡只補一則通知）
AT LOWBATT * EXECUTE lowbatt-notice

# ★★★ 與 upsd 失聯超過 NOCOMMWARNTIME
AT NOCOMM * EXECUTE nocomm-notice
```

```bash
#!/bin/bash
# /etc/nut/upssched-cmd  ——【web01】
# 權限：sudo chmod 750 /etc/nut/upssched-cmd && sudo chown root:nut /etc/nut/upssched-cmd
set -u

LOGGER="/usr/bin/logger -t upssched-cmd"

case "$1" in
    warn-ops)
        $LOGGER "停電已持續 60 秒，web01 將於停電後 6 分鐘關機"
        # ★★★ 這裡接你的告警管道（下一節有完整範例）
        /usr/local/sbin/notify-ops "UPS 停電 60 秒" "web01 將於 T+6min 關機"
        ;;
    shutdown-web)
        $LOGGER "計時器到期，web01 開始關機"
        /usr/local/sbin/notify-ops "web01 關機中" "UPS 停電達 6 分鐘，依計畫關機"
        # ★★★★ 先停服務再關機，讓 Nginx 有機會送出 503 而不是直接斷線
        systemctl stop nginx
        sleep 5
        /sbin/shutdown -h +0 "UPS 停電，依計畫關機"
        ;;
    lowbatt-notice)
        $LOGGER "UPS 進入低電量狀態（LB）"
        ;;
    nocomm-notice)
        $LOGGER "無法與 upsd 通訊，請檢查 primary 或網路"
        /usr/local/sbin/notify-ops "UPS 通訊中斷" "web01 連不上 ups1@10.20.30.10"
        ;;
    *)
        $LOGGER "收到未知的 upssched 事件：$1"
        ;;
esac
```

同一套檔案在 `db01` 上只要改兩個數字與名稱：

```ini
# /etc/nut/upssched.conf   ——【db01：停電後 12 分鐘才關，最後才走】
CMDSCRIPT /etc/nut/upssched-cmd
PIPEFN /run/nut/upssched.pipe
LOCKFN /run/nut/upssched.lock

AT ONBATT * START-TIMER shutdown-db 720
AT ONLINE * CANCEL-TIMER shutdown-db
AT ONBATT * START-TIMER warn-ops 60
AT ONLINE * CANCEL-TIMER warn-ops

```

```bash
    shutdown-db)
        $LOGGER "計時器到期，db01 開始關機"
        # ★★★★★ 資料庫關機一定要走正常停止流程，不可以直接 shutdown
        #        直接斷電會讓 InnoDB 需要 crash recovery，大表可能跑很久
        systemctl stop mysql
        # ★★★ 等 mysqld 真的收尾完（依資料量調整，並在演練中實測）
        for i in $(seq 1 60); do
            systemctl is-active --quiet mysql || break
            sleep 2
        done
        /sbin/shutdown -h +0 "UPS 停電，資料庫已安全停止"
        ;;
```

> [!danger] ★★★★★ `AT ONLINE * CANCEL-TIMER` 漏掉的後果
> 這是 upssched 最經典的坑：
>
> ```
> 14:00:00  瞬斷 3 秒 → ONBATT → 啟動 360 秒計時器
> 14:00:03  復電       → ONLINE → 【沒有 CANCEL-TIMER】
> 14:06:00  ★★★★★ 計時器到期 → 主機在市電正常的情況下自己關機
> ```
>
> 使用者只會知道「網站中午莫名其妙掛了」，而你查不到任何硬體錯誤。
> ★★★★★ **每一個 `START-TIMER` 都必須有對應的 `CANCEL-TIMER`。**

### 通知腳本：把事件送出機房 ★★★★

```bash
#!/bin/bash
# /usr/local/sbin/notify-ops
# 用法：notify-ops "<主旨>" "<內容>"
# 權限：sudo chmod 750 /usr/local/sbin/notify-ops
set -u

SUBJECT="${1:-UPS 事件}"
BODY="${2:-}"
HOST="$(hostname -s)"
NOW="$(date '+%F %T')"

# ① 一律寫 syslog（★★★★ 這是事後稽核的唯一可靠來源）
/usr/bin/logger -t ups-notify "${SUBJECT} | ${BODY}"

# ② 寫一份本機檔案（★★★ 停電時網路可能也斷了，本機檔案是最後防線）
printf '%s [%s] %s | %s\n' "$NOW" "$HOST" "$SUBJECT" "$BODY" \
    >> /var/log/ups-events.log

# ③ 送 webhook（★★★ 依你的告警平台調整；停電時外網可能不通，設短逾時）
if [ -n "${UPS_WEBHOOK_URL:-}" ]; then
    curl -sS --max-time 5 -X POST "$UPS_WEBHOOK_URL" \
         -H 'Content-Type: application/json' \
         -d "$(printf '{"text":"[%s] %s\\n%s\\n%s"}' "$HOST" "$SUBJECT" "$BODY" "$NOW")" \
         >/dev/null 2>&1 || /usr/bin/logger -t ups-notify "webhook 送出失敗"
fi
```

> [!tip] ★★★★ 停電時的通知管道要想清楚
> 停電時很可能**網路也一起斷**（交換器沒接 UPS、對外光纖設備沒電、ISP 端也停電）。
>
> 可靠度排序：
> 1. ★★★★★ **簡訊 / 電話**（走行動網路，最不受機房停電影響）
> 2. ★★★★ **手機推播 / IM webhook**（要求核心交換器與對外設備都在 UPS 上）
> 3. ★★★ **Email**（郵件主機自己可能也在同一間機房，停電時送不出去）
> 4. ★★ **只寫 syslog**（事後查得到，但當下沒人知道）
>
> ★★★★★ **核心交換器與對外路由器一定要接 UPS**，否則所有網路告警都是空的。

### SNMP 管理卡：不用 USB 線的做法 ★★★★

當 UPS 與主機不在同一機櫃、或有多台 secondary 但不想依賴單一 primary 主機時，用 SNMP 卡。

```ini
# /etc/nut/ups.conf   ——【SNMP 卡版本】
maxretry = 3

[ups1]
    # ★★★★★ driver 改成 snmp-ups
    driver = snmp-ups
    # ★★★★ port 這時填的是「管理卡的 IP」，不是裝置路徑
    port = 10.20.30.50

    # ── SNMP v1/v2c（★★★ 只有社群字串，明文傳輸）────────
    # snmp_version = v2c
    # community = CHANGE-ME-readonly

    # ── SNMP v3（★★★★★ 有帳密與加密，正式環境用這個）────
    snmp_version = v3
    secName = upsmon-ro
    secLevel = authPriv
    authProtocol = SHA
    authPassword = CHANGE-ME-auth-pass
    privProtocol = AES
    privPassword = CHANGE-ME-priv-pass

    # ★★★ MIB 對應。auto 讓 driver 自己判斷；判斷失敗才手動指定
    #     常見值：auto / ietf / apcc / eaton_epdu ...（依 driver 版本而異）
    mibs = auto

    # ★★★ SNMP 查詢間隔，不要設太短，管理卡的 CPU 很弱
    pollfreq = 15

    desc = "DC1 R03 UPS via NMC"
```

sudo systemctl restart nut-server.service

```

> [!danger] ★★★★★ SNMP 管理卡的三條資安紅線
> 1. ★★★★★ **管理卡必須放在管理網段（獨立 VLAN），絕對不可以有對外 IP。**
>    UPS 管理卡的韌體更新頻率低、漏洞修補慢，是機房裡最脆弱的網路裝置之一。
> 2. ★★★★★ **一定要改預設帳密**（多數品牌出廠有公開的預設帳號），
>    並關掉 Telnet / HTTP，只留 SSH / HTTPS。
> 3. ★★★★ **SNMP 用 v3**；如果卡片只支援 v1/v2c，社群字串不可以是 `public`，
>    並且要在卡片上設定「只允許來自哪些 IP 查詢」。
>
> 這三條與 [[040-02-09-guide-機房-伺服器上架與初始設定]] 講的帶外管理介面原則完全一致。

### 與監控平台整合 ★★★★

**做法 A：Prometheus node_exporter textfile collector（最省事）**

```bash
#!/bin/bash
# /usr/local/sbin/ups-metrics
# 由 systemd timer 每分鐘跑一次，寫進 node_exporter 的 textfile 目錄
set -u
UPS="ups1@localhost"
OUT="/var/lib/node_exporter/textfile_collector/ups.prom"
TMP="${OUT}.$$"

status="$(upsc "$UPS" ups.status 2>/dev/null)" || { rm -f "$TMP"; exit 0; }

num() { upsc "$UPS" "$1" 2>/dev/null | head -1; }

{
  echo '# HELP ups_online UPS 是否在市電供電 (1=OL, 0=其他)'
  echo '# TYPE ups_online gauge'
  case "$status" in
      *OL*) echo 'ups_online{ups="ups1"} 1' ;;
      *)    echo 'ups_online{ups="ups1"} 0' ;;
  esac

  echo '# HELP ups_on_battery UPS 是否放電中 (1=OB)'
  echo '# TYPE ups_on_battery gauge'
  case "$status" in
      *OB*) echo 'ups_on_battery{ups="ups1"} 1' ;;
      *)    echo 'ups_on_battery{ups="ups1"} 0' ;;
  esac

  echo '# HELP ups_replace_battery UPS 回報需更換電池 (1=RB)'
  echo '# TYPE ups_replace_battery gauge'
  case "$status" in
      *RB*) echo 'ups_replace_battery{ups="ups1"} 1' ;;
      *)    echo 'ups_replace_battery{ups="ups1"} 0' ;;
  esac

  for v in battery.charge battery.runtime battery.voltage \
           input.voltage output.voltage ups.load; do
      val="$(num "$v")"
      [ -n "$val" ] || continue
      metric="ups_$(echo "$v" | tr '.' '_')"
      echo "# TYPE ${metric} gauge"
      echo "${metric}{ups=\"ups1\"} ${val}"
  done
} > "$TMP"

mv -f "$TMP" "$OUT"
```

```ini

[Timer]
OnBootSec=1min
OnUnitActiveSec=1min

[Install]

```

**該設哪些告警規則 ★★★★★**：

| 告警 | 條件 | 嚴重度 | 為什麼 |
| --- | --- | --- | --- |
| ★★★★★ 停電 | `ups_on_battery == 1` 持續 30 秒 | Critical | 瞬斷不告警、真停電要告警 |
| ★★★★★ 電量低 | `ups_battery_charge < 40` | Critical | 關機流程即將啟動 |
| ★★★★★ 該換電池 | `ups_replace_battery == 1` | High | 見 [[040-02-07-guide-機房-UPS電池維護與更換]] |
| ★★★★ 續航時間縮短 | `ups_battery_runtime` 比基準值低於一定比例 | High | **電池老化最早的徵兆** |
| ★★★★ 負載偏高 | `ups_ups_load` 超過你設定的門檻 | High | 有人偷接東西 |
| ★★★★ 資料失聯 | `ups_online` 指標消失超過 5 分鐘 | High | driver 或 upsd 掛了，**等於沒有監控** |
| ★★★ 輸入電壓異常 | `ups_input_voltage` 超出正常區間 | Medium | 市電品質問題 |

> [!danger] ★★★★★ 最容易被忽略的一條：「監控本身掛掉」
> 大多數人只設「停電要告警」，忘了設「**收不到 UPS 資料要告警**」。
>
> 結果是：driver 三個月前就掛了，儀表板一片綠（因為根本沒有新資料進來），
> 真的停電時**一則告警都沒有**，主機也不會關機。
>
> ★★★★★ **「沒有資料」必須是一個獨立的、會叫人的告警。**
> 這個原則對所有監控項目都成立，見 [[100-01-04-guide-日誌-健康檢查與可用性監控]]。

### apcupsd 對照 ★★★

> MINUTES 5
> # ★★★ 停電持續幾秒就關機。0 = 停用此條件
> #     ★★★★ 除非你確定，否則保持 0，靠上面兩個條件即可
> TIMEOUT 0
>
> # ── 網路資訊服務（讓 slave 或 apcaccess 遠端查詢）──
> NETSERVER on
> # ★★★★★ 綁管理網段 IP，不要用 0.0.0.0
> NISIP 10.20.30.10
> NISPORT 3551
>
> # 事件腳本目錄
> SCRIPTDIR /etc/apcupsd
> # ★★★ 關機後是否讓 UPS 也斷電（等同 NUT 的 killpower）
> KILLDELAY 0
> ```
>
> **slave 端**：
> ```ini
> UPSCABLE ether
> # ★★★★ UPSTYPE net + DEVICE 指向 master 的 <IP>:<port>
> UPSTYPE net
> DEVICE 10.20.30.10:3551
> NETSERVER off
> BATTERYLEVEL 25
> MINUTES 8
> ```
>
> **啟用**：`/etc/default/apcupsd` 裡把 `ISCONFIGURED=no` 改成 `yes`，
> ★★★★ 這一步等同 NUT 的 `nut.conf MODE=`，**忘了改服務不會正常運作**。
>
> **查狀態**：
> ```bash
> apcaccess status
> ```
> ```text
> APC      : 001,036,0879
> DATE     : 2026-09-02 10:41:03 +0800
> HOSTNAME : nut-pri
> UPSNAME  : ups1
> MODEL    : Smart-UPS 1500
> STATUS   : ONLINE
> LINEV    : 111.0 Volts
> LOADPCT  : 27.0 Percent
> BCHARGE  : 100.0 Percent
> TIMELEFT : 38.0 Minutes
> ```
>
> **事件腳本**：`/etc/apcupsd/apccontrol` 會依事件呼叫同目錄下的
> `onbattery`、`offbattery`、`powerout`、`commfailure` 等腳本。
>
> **NUT vs apcupsd 怎麼選 ★★★★**：
>
> | 面向 | NUT | apcupsd |
> | --- | --- | --- |
> | 支援品牌 | ★★★★★ 幾乎所有品牌 | 只有 APC |
> | 設定複雜度 | ★★ 四個檔，較繁瑣 | ★★★★ 一個檔，簡單 |
> | 多主機關機 | ★★★★★ primary/secondary 成熟 | ★★★ master/slave 可用但彈性較低 |
> | 依序關機 | ★★★★★ upssched 計時器 | ★★ 靠 slave 各自的門檻，較粗糙 |
> | SNMP 卡 | ★★★★★ snmp-ups driver | ★★ 支援有限 |
> | 監控整合 | ★★★★ upsc 好剖析 | ★★★★ apcaccess 也好剖析 |
> | 文件 | ★★★★ 官方手冊完整 | ★★★ 相對少 |
>
> ★★★★ **建議**：機關環境設備品牌會混雜（今年買 APC、明年標到 Eaton），
> **一律用 NUT**，不要為了省事在不同機房用不同工具 —— 維運人員要學兩套。
> 只有「單機 + 只有一台 APC + 永遠不會擴充」才考慮 apcupsd。

### 步驟 3：★★★★★ 拔電演練（本篇的重點）

> [!danger] ★★★★★ 演練前必做的六件事
> 1. **公告停機時間窗**，走 [[100-02-08-guide-維運-變更管理流程]] 的變更申請
> 2. **確認所有資料庫已備份且備份可還原**（不是「有備份檔」，是「還原過」）
> 3. **手上有機房鑰匙、UPS 面板密碼、伺服器實體開機能力**
> 4. **至少兩人在場**，一人操作一人記錄時間
> 5. ★★★★★ **先確認電池健康**（`ups.status` 沒有 `RB`、快速自我測試通過）

| --- | --- | --- | --- |
| 拔電到 `OB` 的偵測延遲 | 5 秒 | 5 秒 | ✅ |
| 滿載滿電的 `battery.runtime` | 2265 秒 | 2410 秒 | ⚠ 下降 6%，追蹤 |
| 實測 1 分鐘的 charge 掉幅 | 3% | 3% | ✅ |
| web01 關機耗時 | 30 秒 | 28 秒 | ✅ |
| db01（含 stop mysql）關機耗時 | 50 秒 | 45 秒 | ✅ |
| 全部 secondary 關完耗時 | 175 秒 | 160 秒 | ✅ |
| `HOSTSYNC 30` 是否足夠 | 是（秒數 > 175？否，見下） | — | ★★★★ 見備註 |
| primary 關機到 UPS 斷電 | 49 秒 | 52 秒 | ✅ |
| 復電後主機是否自動開機 | 是（4 台全部） | 是 | ✅ |
| 有無檔案系統錯誤 | 無 | 無 | ✅ |
| 有無資料庫 crash recovery | 無 | 無 | ✅ |

> [!danger] ★★★★★ 上表最重要的一列：`HOSTSYNC` 到底夠不夠
> 本例中 secondary 全部關完花了 175 秒，但 `HOSTSYNC` 只有 30 秒。
>
> **這樣不會出事，是因為關機是靠 `upssched` 計時器提早觸發的**（T+60/90/120 秒），
> 到 primary 進入 LB（T+19 分鐘）時 secondary 早就關完了。
>
> ★★★★★ **但如果你沒有用 upssched，全部靠 LB 同時關機**，
> 那 `HOSTSYNC 30` 就完全不夠 —— primary 只等 30 秒就會切電，
> db01 的 MySQL 可能還在 stop 中就被斷電。
>
> **判定原則**：
> - 有用 upssched 分時關機 → `HOSTSYNC` 只是保險，30～60 秒即可
> - ★★★★★ 沒用 upssched → `HOSTSYNC` 必須大於「最慢那台 secondary 的實測關機耗時」，
>   並且要留餘裕（例如實測 175 秒就設 240）

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ `upsc` 回 `Error: Connection failure: Connection refused` | upsd 沒起來，多半是 `nut.conf` 還是 `MODE=none` | 改 `MODE=netserver`（primary）或 `standalone`（單機），`systemctl restart nut-server` |
| ★★★★ `upsc` 回 `Error: Connection failure: Connection refused`（本機 OK，遠端不行） | `upsd.conf` 只有 `LISTEN 127.0.0.1` | 加一行 `LISTEN <管理網段IP> 3493`，重啟 `nut-server` |
| ★★★★ 遠端 `upsc` 卡住不回應（不是 refused） | 防火牆丟包（DROP 而非 REJECT） | `sudo ufw allow from <網段> to any port 3493 proto tcp`；RHEL 用 `firewall-cmd` |
| ★★★★★ `upsc` 回 `Error: Access denied` | `upsd.users` 帳號密碼與 `upsmon.conf` 的 `MONITOR` 那行不一致 | 兩邊逐字比對；★★★ 密碼裡有空白或特殊字元時整串加引號 |
| ★★★★ `upsc` 回 `Error: Unknown UPS` | `ups.conf` 的 `[區段名]` 與查詢用的名字不同 | `upsc -l localhost` 列出實際名稱，再用那個名字查 |
| ★★★★★ driver 起不來：`No matching HID UPS found` | UPS 沒開機／USB 沒接好／driver 選錯 | `lsusb` 確認裝置存在；`nut-scanner -U` 重掃；換 USB 埠與線 |
| ★★★★★ driver 起不來：`Can't claim USB device ...: Permission denied` | udev 規則沒讓 `nut` 使用者取得裝置權限 | 確認套件帶的 udev 規則存在（`ls /lib/udev/rules.d/*nut*`），`sudo udevadm control --reload && sudo udevadm trigger`，重插 USB |
| ★★★★ `upsc` 有輸出但值都不動、狀態顯示 `data stale` | driver 掛了但 upsd 還活著；或 `MAXAGE` 太小 | `systemctl restart nut-driver@ups1`；`journalctl -u nut-driver@ups1` 看原因 |
| ★★★★★ 停電時 secondary 有記錄 `on battery` 但**不關機** | `upsmon.conf` 角色寫成 `primary`，或 `MINSUPPLIES` 設成 0 | 角色改 `secondary`，`MINSUPPLIES 1`，重啟 `nut-monitor` |
| ★★★★★ 主機在市電正常時莫名關機 | `upssched.conf` 漏了 `AT ONLINE * CANCEL-TIMER`，瞬斷後計時器沒取消 | 補上每個 `START-TIMER` 對應的 `CANCEL-TIMER` |
| ★★★★★ 關機後 UPS 沒斷電，電池被榨乾、復電後主機不會自動開機 | 沒設 `POWERDOWNFLAG`，或 BIOS 的 AC Power Recovery 不是 `Power On` | 補 `POWERDOWNFLAG /etc/killpower`；BIOS 改 `Power On`（見 [[040-02-09-guide-機房-伺服器上架與初始設定]]） |
| ★★★★ 開機後 `/etc/killpower` 還在 | 上次關機流程沒跑完（例如中途被強制斷電） | `sudo rm -f /etc/killpower`，並檢查關機期的 NUT unit 是否 enable |
| ★★★★ `upssched` 完全沒作用，syslog 出現 `Can't connect to /run/nut/upssched.pipe` | `/run/nut` 目錄不存在或權限不對 | 建 `/etc/tmpfiles.d/nut-run.conf` 寫 `d /run/nut 0770 nut nut -`，跑 `systemd-tmpfiles --create` |
| ★★★ `upssched-cmd` 沒執行 | 腳本沒有執行權限，或第一行 shebang 錯 | `chmod 750 /etc/nut/upssched-cmd`、`chown root:nut`，確認 `#!/bin/bash` |
| ★★★★ 改了 `ups.conf` 但 `nut-driver@ups1` 找不到 | NUT 2.8 的 unit 由 enumerator 產生，沒重跑 | `sudo systemctl restart nut-driver-enumerator.service` |
| ★★★★ 監控平台抓不到值，但手動 `upsc` 正常 | 監控用的帳號在 `upsd.users` 裡沒建，或用了 `upsmon` 角色帳號被拒 | 建一個純唯讀帳號（不寫 `upsmon`、不寫 `actions`） |
| ★★★★★ 停電後**所有**主機同時關機，資料庫來不及收尾 | 沒用 upssched，全部靠 `LB` 同時觸發 | 導入 upssched 分時關機；或至少把 `HOSTSYNC` 加大到超過最慢主機的實測關機時間 |
| ★★★ `battery.runtime` 欄位不存在 | 該機型不回報估算續航（低階機種常見） | 改用 `battery.charge` 當門檻；並在演練中自行實測續航時間 |
| ★★★★ 一台主機接兩顆 UPS，停電一顆就關機 | `MINSUPPLIES` 設成 2（要求兩顆都有電） | 改成 `MINSUPPLIES 1`，並確認有兩行 `MONITOR`（各寫 1） |
| ★★★ SNMP driver 連不上：`Cannot connect to <IP>` | 管理卡 IP 錯、SNMP 服務未啟用、社群字串／v3 憑證錯、或卡片限制了來源 IP | 先用 `snmpwalk` 驗證卡片本身能查；再回頭改 `ups.conf` |

### 排錯的標準順序 ★★★★★

出問題時**永遠照這個順序**，不要跳步：

```
① 實體層       lsusb / ping <管理卡IP>
      │ 通過
      ▼
② driver 層    systemctl status nut-driver@ups1
               journalctl -u nut-driver@ups1 -n 50
      │ 通過
      ▼
③ upsd 層      upsc ups1@localhost
               ss -tlnp | grep 3493
      │ 通過（本機）
      ▼
④ 網路層       從 secondary 跑 upsc ups1@<primary IP>
               不通就查防火牆與 LISTEN
      │ 通過
      ▼
⑤ upsmon 層    journalctl -u nut-monitor -n 50
               找 "Communications with UPS ... established"
      │ 通過
      ▼
⑥ 行為層       ★★★★★ 只能靠拔電演練驗證，看不出來的部分都在這裡
```

## 安全性注意事項

### ★★★★★ 三個絕對不可以

| # | 不可以 | 為什麼 | 正確做法 |
| --- | --- | --- | --- |
| ① | ★★★★★ `LISTEN 0.0.0.0 3493` | 3493 沒有加密，帳密與機房資訊在網路上明文傳輸；暴露在對外介面等於送出攻擊面 | `LISTEN` 綁管理網段 IP + 防火牆限制來源 |
| ② | ★★★★★ `upsd.users` 用預設／範例密碼，或 commit 進 git | 有了 `nutadmin` 帳號就能下 `load.off`，**等於遠端拔掉整櫃的插頭** | 每台環境獨立高強度密碼；密碼放 Ansible Vault／Secret Manager |
| ③ | ★★★★★ SNMP 管理卡有對外 IP／留著預設帳密／用 `public` 社群字串 | UPS 管理卡韌體修補慢，是機房最容易被打下來的裝置 | 管理 VLAN、改帳密、關 Telnet/HTTP、SNMP v3、限制來源 IP |

### 權限與檔案

```bash
# ★★★★ 一次檢查所有 NUT 設定檔的權限
ls -l /etc/nut/
```
```text
-rw-r----- 1 root nut  1834 Sep  2 11:02 nut.conf
-rw-r----- 1 root nut   210 Sep  2 11:02 ups.conf
-rw-r----- 1 root nut    98 Sep  2 11:02 upsd.conf
-rw-r----- 1 root nut   342 Sep  2 11:02 upsd.users
-rw-r----- 1 root nut  1024 Sep  2 11:02 upsmon.conf
-rw-r----- 1 root nut   312 Sep  2 11:02 upssched.conf
-rwxr-x--- 1 root nut  1180 Sep  2 11:02 upssched-cmd
```

★★★★ 檢查腳本：

```bash
#!/bin/bash
# /usr/local/sbin/nut-perm-check —— 放進每日巡檢
fail=0
for f in /etc/nut/upsd.users /etc/nut/upsmon.conf /etc/nut/upsd.conf; do
    [ -e "$f" ] || continue
    perm="$(stat -c '%a %U:%G' "$f")"
    case "$perm" in
        "640 root:nut") ;;
        *) echo "★ 權限異常：$f → $perm（應為 640 root:nut）"; fail=1 ;;
    esac
done
grep -q '^LISTEN 0\.0\.0\.0' /etc/nut/upsd.conf 2>/dev/null && \
    { echo "★★★★★ upsd.conf 監聽 0.0.0.0，必須改掉"; fail=1; }
exit "$fail"
```

### 演練本身的風險 ★★★★★

> [!danger] 拔電演練是一次「刻意製造的故障」
> ★★★★★ 演練期間你的機房**真的沒有市電保護**。如果這時候：
> - 電池已經老化 → UPS 可能撐不到你預期的時間就斷電
> - 上游斷路器有問題 → 復電時可能跳脫，變成真的停電
>
> **控管方式**：
> 1. 走變更管理流程，有核准、有時間窗、有回復計畫（[[100-02-08-guide-維運-變更管理流程]]）
> 2. ★★★★★ 演練前先做**快速自我測試**確認電池狀態，`RB` 沒亮才做
> 3. 第一次一定先做「演練 A（只觀察不關機）」，確認偵測正常再做完整演練
> 4. 演練全程兩人在場，一人隨時可以恢復市電
> 5. ★★★★★ 演練頻率：**至少每年一次**，且**換完電池後必做一次**

### 日誌保存 ★★★

UPS 事件是停電事故調查的關鍵證據，必須送到集中日誌：

```text
需要保留的事件：ONBATT / ONLINE / LOWBATT / FSD / SHUTDOWN / REPLBATT / NOCOMM
保存年限：★★★★ 依機關的稽核要求，通常至少一年
集中方式：syslog → 集中日誌伺服器（見 [[100-01-02-guide-日誌-日誌集中與輪替]]）
★★★★★ 不要只留在本機 —— 停電就是主機關機的時候，本機日誌可能不完整
```

## 練習題

> [!question]- 練習 1：從零建立一台 standalone NUT（★★★ 入門）
> **題目**：在一台測試機上（可以是 VM + 一顆 USB UPS，或用 `dummy-ups` driver 模擬），
> 完成 `nut.conf` → `ups.conf` → `upsd.conf` → `upsd.users` → `upsmon.conf`，
> 讓 `upsc` 能查到狀態。
>
> **參考解答**：
> 1. `sudo apt install -y nut nut-server nut-client`
> 2. `/etc/nut/nut.conf` → `MODE=standalone`
> 3. `/etc/nut/ups.conf`：
>    ```ini
>    [ups1]
>        driver = usbhid-ups
>        port = auto
>        desc = "測試機 UPS"
>    ```
> 4. `sudo upsdrvctl start ups1` 確認 driver 起得來
> 5. `/etc/nut/upsd.conf` → `LISTEN 127.0.0.1 3493`
> 6. `/etc/nut/upsd.users` → 建 `[monpri] ... upsmon primary`
> 7. `/etc/nut/upsmon.conf` → `MONITOR ups1@localhost 1 monpri <密碼> primary`
> 8. 三個服務依序啟動，最後 `upsc ups1@localhost ups.status` 應回 `OL`
>
> ★★★★ **驗收標準**：`journalctl -u nut-monitor` 出現
> `Communications with UPS ups1@localhost established`。

> [!question]- 練習 2：把一台 secondary 接上來（★★★★）
> **題目**：在第二台主機上把它設成 secondary，並在 primary 上證明它連上了。
>
> **參考解答**：
> - secondary：`MODE=netclient`，`upsmon.conf` 只有一行
>   `MONITOR ups1@<primary IP> 1 monsec <密碼> secondary`
> - primary：`upsd.conf` 要有 `LISTEN <primary IP> 3493`，防火牆放行 3493
> - primary：`upsd.users` 要有 `[monsec] ... upsmon secondary`
>
> **證明連上的方法（三選一，★★★★ 建議三個都做）**：
> 1. secondary 上 `upsc ups1@<primary IP> ups.status` 有輸出
> 2. secondary 上 `journalctl -u nut-monitor` 出現 `Communications ... established`
> 3. ★★★★★ primary 上 `ss -tn state established '( sport = :3493 )'` 看得到那台的 IP

> [!question]- 練習 3：設計並實作依序關機（★★★★★）
> **題目**：三台 secondary（web／file／db），要求停電後 6／9／12 分鐘依序關機，
> 且瞬斷不可誤觸發。寫出三台的 `upssched.conf`。
>
> **參考解答重點**：
> - 三台的差別只有 `START-TIMER shutdown-host <360|540|720>`
> - ★★★★★ **每台都必須有 `AT ONLINE * CANCEL-TIMER shutdown-host`**，
>   這是「瞬斷不誤觸發」的唯一保證
> - db01 的 `upssched-cmd` 要先 `systemctl stop mysql` 並等它停完再 `shutdown`
> - 三台都要建 `/run/nut` 目錄，`upssched-cmd` 權限 `750 root:nut`
>
> ★★★★ **驗證方式**：先把秒數改成 20／30／40，做一次短演練，
> 用 `ss` 觀察 primary 上的連線數 3 → 2 → 1 → 0，然後**記得改回來**。

> [!question]- 練習 4：故意做壞再修好（★★★★）
> **題目**：依序製造下列四個故障並修復，每個都要說出「你是靠哪一個指令的哪一行判斷出來的」。
> ① `nut.conf` 改回 `MODE=none`
> ② `upsd.conf` 只留 `LISTEN 127.0.0.1`
> ③ `upsd.users` 的 `monsec` 密碼改錯一個字
> ④ `upssched.conf` 刪掉 `AT ONLINE * CANCEL-TIMER`
>
> **參考解答**：
> | 故障 | 判斷依據 | 修法 |
> | --- | --- | --- |
> | ① | `upsc ups1@localhost` → `Connection refused`；`ss -tlnp \| grep 3493` 沒東西 | 改回 `netserver`，重啟 `nut-server` |
> | ② | 本機 `upsc` 正常，secondary 上 `Connection refused`；`ss -tlnp` 只看到 127.0.0.1 | 加回 `LISTEN <IP> 3493` |
> | ③ | secondary 的 `journalctl -u nut-monitor` 出現 `Access denied` | 兩邊密碼逐字比對 |
> | ④ | ★★★★★ **平常完全看不出來**，只有做短暫拔電再插回、等計時器到期才會發現主機自己關機 | 補回 `CANCEL-TIMER` |
>
> ★★★★★ ④ 是本題的重點：**有一類設定錯誤只有靠演練才驗得出來**，
> 這就是為什麼演練不能省。

> [!question]- 練習 5：把 UPS 接進監控並設告警（★★★★）
> **題目**：用 `ups-metrics` 腳本 + systemd timer 輸出指標，
> 並設計「停電」「低電量」「該換電池」「資料失聯」四個告警。
>
> **參考解答重點**：
> - 建一個**唯讀帳號** `[zbxro]`（不寫 `upsmon`、不寫 `actions`／`instcmds`）
> - 腳本用 `mv -f` 原子寫入，避免 node_exporter 讀到寫到一半的檔
> - ★★★★★ 「資料失聯」的告警條件是 **指標消失**（例如
>   `absent(ups_online)` 或時間戳超過 5 分鐘），不是某個值超標
> - ★★★ 停電告警要加「持續 30 秒」條件，避免瞬斷洗版

> [!question]- 練習 6：寫出你自己機房的關機時序表（★★★★★）
> **題目**：列出你機房所有接 UPS 的主機，決定每一台的關機順序與延遲秒數，
> 並說明理由。
>
> **參考解答框架**：
> | 順序 | 主機 | 延遲 | 理由 |
> | --- | --- | --- | --- |
> | 1 | 測試機、報表機 | T+120s | 停掉沒有服務影響 |
> | 2 | 前端 web | T+360s | 先讓使用者看到維護頁，比連線逾時好 |
> | 3 | 應用伺服器 | T+480s | 讓佇列中的工作跑完 |
> | 4 | 檔案伺服器 | T+540s | 等前面的機器都不再寫入 |
> | 5 | 資料庫 | T+720s | ★★★★★ 一定最後關，且要走正常 stop 流程 |
> | 6 | NUT primary | LB 觸發 | 最後一個，負責 killpower |
> | ★ | 核心交換器 | **不關** | 關掉就失去所有網路告警與遠端能力 |
>
> ★★★★★ 最後一列是最容易被忘記的：**網路設備通常不做自動關機**，
> 它們功耗低、且要留到最後讓你能遠端看狀況。

## 小測驗

**Q1.** `/etc/nut/nut.conf` 中 `MODE=` 的四個可用值分別是什麼？primary 與 secondary 各該用哪一個？

**Q2.** （是非）secondary 主機也需要設定 `ups.conf` 和 `upsd.users`。

**Q3.** 下面這行 `MONITOR` 設定中，數字 `1` 代表什麼？
```text
MONITOR ups1@10.20.30.10 1 monsec secret secondary
```
（A）監控 1 台 UPS （B）這台 UPS 供應本機 1 顆電源供應器 （C）優先權為 1 （D）1 秒輪詢一次

**Q4.** `ups.status` 顯示 `OB DISCHRG LB` 時，系統處於什麼狀態？upsmon 接下來會做什麼？

**Q5.** （這行指令會發生什麼）
```bash
upscmd -u nutadmin -p 'xxx' ups1@localhost load.off
```

**Q6.** `POWERDOWNFLAG /etc/killpower` 這一行如果漏掉，平常看不出任何問題。
請說明它在什麼情境下才會顯現後果，以及後果是什麼。

**Q7.** 某機房設定了 upsmon，secondary 在停電低電量時會關機，但 primary 的 `HOSTSYNC` 設為 15 秒，
而實測 db01 的 MySQL 停止加關機需要 90 秒。停電時會發生什麼？

**Q8.** （是非）`upsd.conf` 寫 `LISTEN 0.0.0.0 3493` 比較方便，因為不用管網卡 IP 變動，
而且反正有帳號密碼保護，是安全的。

**Q9.** `upssched.conf` 中只寫了 `AT ONBATT * START-TIMER shutdown-host 360`
而沒寫對應的 `CANCEL-TIMER`。請描述一個「市電完全正常卻導致主機關機」的完整時間序列。

**Q10.** 拔電演練結束、主機開機後，你要跑哪三個檢查來證明「這次是乾淨關機而不是被斷電」？

> [!question]- 測驗答案
>
> **A1.** `none`（預設，什麼都不啟動）／`standalone`（單機自保護）／
> `netserver`（接 UPS 且對外提供服務）／`netclient`（只跑 upsmon 連別台）。
> ★★★★★ **primary 用 `netserver`，secondary 用 `netclient`**。
> 裝完套件預設是 `none`，忘了改是最常見的第一個坑。
> → 見「安裝或基礎操作 / 第三步」與「速查表 / `MODE=` 對照」。
>
> **A2.** ✗ 錯。★★★★ secondary **只需要** `nut.conf`（設 `netclient`）與 `upsmon.conf`
> （再加上要分時關機時的 `upssched.conf` 與 `upssched-cmd`）。
> `ups.conf`／`upsd.conf`／`upsd.users` 都只在 primary 上。
> → 見「進階應用 / secondary 端設定」。
>
> **A3.** （B）。★★★★★ 這個數字是「**這台 UPS 供應本機幾顆電源供應器**」，
> 不是 UPS 台數也不是優先權。雙電源主機兩顆都插同一台 UPS 就寫 2；
> 分插兩台 UPS 則寫兩行 `MONITOR`、各寫 1，再把 `MINSUPPLIES` 設成 1。
> → 見「安裝或基礎操作 / 第七步」的 `MONITOR` 註解。
>
> **A4.** `OB` = 市電中斷、靠電池供電；`DISCHRG` = 電池正在放電；
> `LB` = 電量已低於 `battery.charge.low` 門檻。
> ★★★★★ **這三個一起出現就是關機觸發條件**：
> secondary 會立刻執行 `SHUTDOWNCMD`；primary 會先等 secondary 斷線（最多 `HOSTSYNC` 秒），
> 再建立 `POWERDOWNFLAG` 並關機，關機末段叫 UPS 斷電。
> → 見「觀念說明 / `ups.status` 的狀態碼」。
>
> **A5.** ★★★★★ **會立刻切斷 UPS 的輸出，等同拔掉整櫃設備的插頭。**
> 所有靠這顆 UPS 供電的主機會被硬斷電（沒有關機流程），
> 可能造成檔案系統損毀與資料庫需要 crash recovery。
> 這就是為什麼 `instcmds` 建議用白名單而不是 `ALL`。
> → 見「安全性注意事項 / `instcmds` 要不要給 `ALL`」。
>
> **A6.** ★★★★★ 只有在「**停電時間長到主機已關完、但電池還沒耗盡**」時才顯現。
> 後果有兩個：① UPS 繼續帶著已關機的主機放電，電池被**深度放電**，壽命大幅縮短；
> ② 電池耗盡後 UPS 硬斷電，復電時主機處於「關機」狀態且 UPS 輸出可能沒有正確循環，
> **主機不會自動開機**，必須有人跑一趟機房。
> → 見「觀念說明 / killpower」。
>
> **A7.** ★★★★★ primary 只會等 15 秒，等不到 db01 斷線就會執行自己的關機並叫 UPS 切電，
> **db01 的 MySQL 可能還在 stop 過程中就被硬斷電** → 下次啟動要跑 crash recovery，
> 大資料表可能花很久，最壞情況資料損毀。
> 修法二選一：把 `HOSTSYNC` 加大到超過實測值（例如 120～180），
> 或改用 upssched 讓 db01 在停電後固定時間就先關（推薦）。
> → 見「完整實戰範例 / 步驟 4」的 danger callout。
>
> **A8.** ✗ 錯，而且是 ★★★★★ 等級的錯。理由：
> ① NUT 的 3493 預設**沒有加密**，帳密與 UPS 資訊明文傳輸；
> ② 綁 `0.0.0.0` 會讓服務出現在**每一張網卡**上，包含可能對外的那張；
> ③ 未驗證的連線也能列舉 UPS 數量、機型與 `desc`，等於洩漏機房拓樸。
> 正確做法是 `LISTEN` 綁管理網段 IP，再用防火牆限制來源網段。
> → 見「安全性注意事項 / 三個絕對不可以」。
>
> **A9.** ★★★★★ 例如：
> ```
> 14:00:00  市電瞬斷 3 秒 → upsmon 發出 ONBATT → upssched 啟動 360 秒計時器
> 14:00:03  市電恢復     → upsmon 發出 ONLINE → 【沒有 CANCEL-TIMER，計時器繼續跑】
> 14:06:00  計時器到期   → 執行 CMDSCRIPT → 主機在市電完全正常的情況下自己關機
> ```
> 現場看到的是「網站中午莫名其妙掛了」，而硬體與市電都查不到任何異常。
> ★★★★★ **每個 `START-TIMER` 都必須有對應的 `CANCEL-TIMER`。**
> → 見「進階應用 / 用 upssched 做多主機依序關機」的 danger callout。
>
> **A10.** ★★★★★ 三個檢查：
> ① `last -x | head` → 要看到 `shutdown system down` 那一行
>    （只有 `reboot system boot` 而沒有 shutdown = 被硬斷電）；
> ② `journalctl -b -1 | grep -i -E 'unclean|recovering journal|EXT4-fs error'` → 應無輸出；
> ③ `ls -l /etc/killpower` → 應為 `No such file`（開機時已清掉）；
> 資料庫主機再加一項：`journalctl -u mysql -b | grep -i 'crash recovery'` → 應無輸出。
> → 見「完整實戰範例 / 步驟 3 演練 B」的 B-4～B-7。
