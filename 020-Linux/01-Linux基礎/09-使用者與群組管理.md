# 使用者與群組管理

> [!abstract] 這篇你會學到
> - 逐欄讀懂 `/etc/passwd`、`/etc/shadow`、`/etc/group` 三個檔案
> - 分清楚**主要群組**與**附加群組**，以及為什麼 `usermod -aG` 的 `-a` 不能少
> - 為服務建立正確的系統帳號（不能登入、沒有家目錄）
> - 用 `/etc/sudoers.d/` 安全地授權，而不是把整個 sudoers 檔改壞
> - 設定密碼政策與帳號稽核，達到 TWGCB 這類基準的要求

## 觀念說明

### 使用者的本質是一個數字

系統其實不認得「mike」這個名字，它認得的是 **UID**（User ID）。
檔案的擁有者欄位儲存的是數字，`ls -l` 顯示名稱是查表翻譯的結果。

```bash
id mike
```

```
uid=1000(mike) gid=1000(mike) groups=1000(mike),27(sudo),4(adm)
```

> [!tip] 這解釋了「刪掉使用者後檔案顯示成數字」
> ```bash
> ls -l /home/olduser/
> ```
> ```
> -rw-r--r-- 1 1003 1003 4096  8月 20 10:00 data.txt
> ```
> UID 1003 已經沒有對應的名稱了。
> 更危險的是：**如果之後建立的新使用者剛好拿到 UID 1003，
> 他就自動「繼承」了這些檔案的所有權**。
>
> 這是刪除使用者時必須處理遺留檔案的原因：
> ```bash
> sudo find / -xdev -uid 1003 2>/dev/null      # 先找出來
> ```

### UID 的分區

| UID 範圍 | 用途 | 設定於 |
| --- | --- | --- |
| `0` | **root** | 固定 |
| `1`–`999` | 系統帳號（服務用） | `/etc/login.defs` 的 `SYS_UID_MIN/MAX` |
| `1000`+ | 一般使用者 | `UID_MIN/UID_MAX` |
| `65534` | `nobody` | 慣例 |

```bash
grep -E "^UID_MIN|^UID_MAX|^SYS_UID" /etc/login.defs
```

> [!danger] UID 0 就是 root，名字叫什麼不重要
> ```bash
> sudo useradd -o -u 0 -g 0 backdoor      # 建立第二個 UID 0 的帳號
> ```
> 這個 `backdoor` 帳號**擁有完整的 root 權限**，
> 但在 `/etc/passwd` 裡看起來只是個普通名字。
>
> 這是入侵者常見的後門手法。稽核方式：
> ```bash
> awk -F: '$3 == 0 {print $1}' /etc/passwd
> ```
> **正常系統上這個指令只該輸出 `root` 一行。**

### 主要群組 vs 附加群組

每個使用者有**一個主要群組**（primary group，記在 `/etc/passwd` 的 GID 欄位）
和**零到多個附加群組**（supplementary groups，記在 `/etc/group`）。

```bash
id mike
```

```
uid=1000(mike) gid=1000(mike) groups=1000(mike),27(sudo),4(adm),1001(devs)
                └─────┬─────┘        └──────────────┬──────────────────┘
                  主要群組                      所有群組（含主要）
```

| | 主要群組 | 附加群組 |
| --- | --- | --- |
| 數量 | 剛好一個 | 0 到多個 |
| 新建檔案的群組 | **用這個** | 不影響 |
| 儲存位置 | `/etc/passwd` 第 4 欄 | `/etc/group` 第 4 欄 |
| 修改指令 | `usermod -g` | `usermod -aG` |

> [!warning] Debian 系與 RHEL 系的預設主要群組不同
> - **Debian/Ubuntu**：`USERGROUPS_ENAB yes` → 建立 `mike` 時自動建立同名群組 `mike`
> - **RHEL 系**：同樣是 UPG（User Private Group）機制，行為相同
>
> 但有些發行版或設定會讓所有使用者共用 `users` 群組（GID 100），
> 那樣所有人建立的檔案群組都一樣，權限隔離就失效了。
> 用 `id` 確認。

## 基礎操作

### 三個核心檔案

#### `/etc/passwd`（所有人可讀）

```bash
grep -E "^(root|mike|www-data):" /etc/passwd
```

```
root:x:0:0:root:/root:/bin/bash
mike:x:1000:1000:Mike Chen,,,:/home/mike:/bin/bash
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

七個欄位，用 `:` 分隔：

```
mike : x : 1000 : 1000 : Mike Chen,,, : /home/mike : /bin/bash
 │     │    │      │         │              │           └─ 7. 登入 shell
 │     │    │      │         │              └───────────── 6. 家目錄
 │     │    │      │         └──────────────────────────── 5. 備註（GECOS）
 │     │    │      └────────────────────────────────────── 4. 主要群組 GID
 │     │    └───────────────────────────────────────────── 3. UID
 │     └────────────────────────────────────────────────── 2. 密碼佔位（x = 在 shadow）
 └──────────────────────────────────────────────────────── 1. 使用者名稱
```

> [!tip] 第 7 欄是安全控制點
> `/usr/sbin/nologin` 或 `/bin/false` 代表**這個帳號不能互動登入**。
> 所有服務帳號都該是這樣。稽核：
> ```bash
> awk -F: '$3 >= 1000 && $7 !~ /nologin|false/ {print $1, $7}' /etc/passwd
> ```
> 這會列出所有「可以登入的一般使用者」，應該與你的名單相符。

#### `/etc/shadow`（只有 root 可讀）

```bash
sudo grep "^mike:" /etc/shadow
```

```
mike:$y$j9T$AbC...xyz:19962:0:99999:7:::
 │         │            │    │   │   │└┴┴─ 8-9. 帳號到期日、保留
 │         │            │    │   │   └──── 7. 到期前幾天開始警告
 │         │            │    │   └──────── 6. 密碼最長有效天數
 │         │            │    └──────────── 5. 密碼最短使用天數
 │         │            └───────────────── 4. 最後改密碼的日期（自 1970-01-01 起的天數）
 │         └────────────────────────────── 3. 密碼雜湊
 └──────────────────────────────────────── 1. 使用者名稱
```

密碼雜湊欄位的前綴代表演算法：

| 前綴 | 演算法 | 評價 |
| --- | --- | --- |
| `$y$` | yescrypt | **現代預設（Ubuntu 22.04+）** |
| `$6$` | SHA-512 | 可接受 |
| `$1$` | MD5 | **過時，應更換** |
| `!` 或 `!!` 開頭 | **帳號已鎖定** | |
| `*` | 無法用密碼登入（服務帳號） | |
| 空白 | **無密碼可直接登入** ← 極度危險 | |

> [!danger] 稽核空密碼帳號
> ```bash
> sudo awk -F: '$2 == "" {print $1 " 沒有密碼！"}' /etc/shadow
> ```
> 這是 TWGCB、CIS 等基準必檢項目，正常應該沒有任何輸出。

#### `/etc/group`

```bash
grep -E "^(sudo|devs):" /etc/group
```

```
sudo:x:27:mike,alice
devs:x:1001:mike,bob
 │   │  │   └─ 4. 附加成員清單（不含以此為主要群組的使用者！）
 │   │  └───── 3. GID
 │   └──────── 2. 密碼佔位
 └──────────── 1. 群組名稱
```

> [!warning] 第 4 欄不包含「以此為主要群組」的使用者
> `devs` 群組的成員清單裡沒有列出主要群組是 `devs` 的人。
> 要看完整成員：
> ```bash
> getent group devs                     # 只看附加成員
> awk -F: '$4 == 1001 {print $1}' /etc/passwd   # 以此為主要群組的
> ```
> 或用 `members` 指令（需安裝 `members` 套件）。

### 建立使用者

**Debian 系有兩個指令**，行為差很多：

```bash
sudo adduser mike        # 互動式高階工具：建家目錄、問密碼、問備註
sudo useradd mike        # 低階工具：不建家目錄、不設密碼、shell 是 /bin/sh
```

> [!warning] `useradd mike` 建出來的帳號幾乎不能用
> 預設不建家目錄、沒有密碼（帳號鎖定）、shell 是 `/bin/sh`。
> 要用 `useradd` 就得把參數補齊：
> ```bash
> sudo useradd -m -s /bin/bash -c "Mike Chen" mike
> sudo passwd mike
> ```
> | 參數 | 意義 |
> | --- | --- |
> | `-m` | 建立家目錄 |
> | `-s /bin/bash` | 指定 shell |
> | `-c "..."` | 備註 |
> | `-G devs,adm` | 附加群組 |
> | `-g devs` | 主要群組 |
> | `-u 1500` | 指定 UID |
> | `-e 2026-12-31` | 帳號到期日 |
>
> **腳本裡用 `useradd`**（跨發行版一致、非互動），
> **手動操作用 `adduser`**（Debian 系才有）。

### 建立服務帳號

服務帳號不該能登入、不該有家目錄（除非服務需要）：

```bash
sudo useradd --system --no-create-home --shell /usr/sbin/nologin myapp
```

或指定家目錄但仍不可登入：

```bash
sudo useradd --system --home-dir /var/lib/myapp --create-home \
             --shell /usr/sbin/nologin myapp
```

驗證：

```bash
grep myapp /etc/passwd
sudo -u myapp whoami          # 應該成功（sudo 不經過 shell 檢查）
su - myapp                    # 應該失敗：This account is currently not available.
```

> [!tip] `nologin` 和 `/bin/false` 的差別
> - `/usr/sbin/nologin` — 會印出友善訊息（可自訂 `/etc/nologin.txt`）並拒絕
> - `/bin/false` — 直接以退出碼 1 結束，什麼都不印
>
> 兩者都能擋登入，`nologin` 較常用。
> **注意兩者都不能擋 `sudo -u`**，那是刻意的（讓管理員能以該身分測試）。

### 修改使用者

```bash
sudo usermod -aG docker mike        # 加入附加群組（-a 必加！）
sudo usermod -g devs mike           # 改主要群組
sudo usermod -s /usr/sbin/nologin mike   # 改 shell（停用登入）
sudo usermod -l newname oldname     # 改名（不會改家目錄名稱）
sudo usermod -d /new/home -m mike   # 改家目錄並搬移內容
sudo usermod -L mike                # 鎖定密碼（在雜湊前加 !）
sudo usermod -U mike                # 解鎖
sudo usermod -e 2026-12-31 mike     # 設定帳號到期日
```

> [!danger] `-a` 不能省，這是最常見的災難
> ```bash
> sudo usermod -G docker mike       # ✗ mike 現在「只在」docker 群組
> sudo usermod -aG docker mike      # ✓ 追加到現有群組
> ```
> 沒有 `-a` 時，`-G` 會用你給的清單**取代**所有附加群組。
> mike 原本在 `sudo`、`adm`、`devs`，執行第一行後**全部消失**，
> 而且不會有任何警告。
>
> 最糟的情況是把自己踢出 `sudo` 群組，然後就再也不能提權了。
>
> **保命習慣**：改群組前先記錄現況
> ```bash
> id mike > /tmp/mike-groups-before.txt
> sudo usermod -aG docker mike
> id mike
> ```

> [!warning] 群組變更需要重新登入才生效
> 群組資訊在登入時載入到 session，`usermod` 之後現有的終端機仍是舊的。
> ```bash
> id mike        # 顯示新群組（從 /etc/group 讀）
> groups         # 顯示舊群組（從目前 session 讀）
> ```
> 解法：完全登出再登入，或
> ```bash
> newgrp docker      # 開一個帶新群組的子 shell（暫時性）
> exec su - $USER    # 重新載入 session
> ```

### 刪除使用者

```bash
sudo userdel mike             # 保留家目錄
sudo userdel -r mike          # 連家目錄與郵件佇列一起刪
sudo deluser --remove-home mike       # Debian 系的高階指令
```

> [!warning] 刪除前先盤點該使用者的檔案
> ```bash
> # 1. 找出全系統屬於這個 UID 的檔案
> sudo find / -xdev -uid $(id -u mike) 2>/dev/null | head -50
>
> # 2. 檢查有沒有正在執行的程序
> ps -u mike
>
> # 3. 檢查 cron 排程
> sudo crontab -u mike -l
>
> # 4. 確認沒有服務依賴這個帳號
> sudo grep -rn "mike" /etc/systemd/system/ /etc/sudoers.d/ 2>/dev/null
> ```
> 直接 `userdel -r` 而不檢查，會留下一堆孤兒檔案，
> 或讓某個服務突然啟動失敗。
>
> **實務建議**：離職處理先「停用」而不是「刪除」，
> 觀察一段時間確認沒問題再刪：
> ```bash
> sudo usermod -L -e 1 mike        # 鎖定密碼 + 帳號設為已到期
> ```

### 群組操作

```bash
sudo groupadd devs
sudo groupadd -g 1500 devs        # 指定 GID
sudo groupmod -n newname oldname  # 改名
sudo groupdel devs
sudo gpasswd -a mike devs         # 加成員（等同 usermod -aG）
sudo gpasswd -d mike devs         # 移除成員
```

### 查詢

```bash
id mike                 # 完整身分資訊
groups mike             # 所屬群組
getent passwd mike      # 查使用者（含 LDAP/AD 等外部來源）
getent group devs       # 查群組
who                     # 目前登入的使用者
w                       # 目前登入者 + 在做什麼
last -n 20              # 登入歷史
lastlog                 # 每個帳號的最後登入時間
sudo lastb -n 20        # 失敗的登入嘗試
```

> [!tip] 用 `getent` 而不是 `grep /etc/passwd`
> 當機器加入 AD 網域或使用 LDAP 時（見 [[05-TWGCB-Linux網域導入]]），
> 使用者資訊不在 `/etc/passwd` 裡。`getent` 會查詢所有設定的來源
> （`/etc/nsswitch.conf` 定義），`grep` 則只看本機檔案。
>
> ```bash
> getent passwd            # 列出所有來源的使用者
> getent passwd mike       # 有輸出代表存在
> ```

## 進階用法：sudo 授權

### `sudo` 與 `su` 的差別

| | `su -` | `sudo` |
| --- | --- | --- |
| 需要什麼密碼 | **目標使用者（root）的密碼** | **自己的密碼** |
| 稽核紀錄 | 只記錄「切換了」 | **記錄每一條執行的指令** |
| 權限粒度 | 全有或全無 | 可精確到單一指令 |
| root 密碼 | 必須存在 | **可以完全停用 root 密碼** |

> [!tip] 現代做法：停用 root 密碼，全部走 sudo
> Ubuntu 預設就是這樣（root 密碼為 `!`，無法直接登入）。
> 好處是**沒有共用密碼**，每個人用自己的帳號提權，稽核軌跡完整。
>
> ```bash
> sudo passwd -l root         # 鎖定 root 密碼
> sudo passwd -S root         # 確認狀態
> ```
> ```
> root L 2026-08-27 0 99999 7 -1
>      ^ L = locked
> ```

### 永遠用 `visudo`，不要直接編輯

```bash
sudo visudo                              # 編輯 /etc/sudoers
sudo visudo -f /etc/sudoers.d/deploy     # 編輯自訂檔案
```

`visudo` 會在存檔時**檢查語法**，語法錯誤時給你機會修正。

> [!danger] 直接 `nano /etc/sudoers` 改壞 = 所有人都不能 sudo
> sudoers 語法錯誤時，`sudo` 會直接拒絕所有請求：
> ```
> sudo: /etc/sudoers:12:23: syntax error
> sudo: no valid sudoers sources found, quitting
> ```
> 這時你**不能用 sudo 去修它**，形成死鎖。
>
> 救援方式：
> 1. 如果還有一個開著的 root session → 直接修
> 2. `pkexec visudo`（如果有 polkit）
> 3. 開機進入 recovery mode / single user mode
> 4. 從 Live USB 或 VPS 主控台掛載修復
>
> **所以：永遠用 `visudo`。**

### 用 `/etc/sudoers.d/` 而不是改主檔

```bash
sudo visudo -f /etc/sudoers.d/10-deploy
```

```sudoers
# 讓 deploy 使用者可以重載 Web 服務，不需密碼
deploy ALL=(root) NOPASSWD: /usr/bin/systemctl reload nginx, \
                            /usr/bin/systemctl reload php8.3-fpm

# 讓 devs 群組成員可以看日誌
%devs ALL=(root) /usr/bin/journalctl, /usr/bin/tail -F /var/log/*
```

檔案權限必須是 `440`（`visudo -f` 會自動處理）：

```bash
sudo ls -l /etc/sudoers.d/
```

```
-r--r----- 1 root root 245  8月 27 14:02 10-deploy
```

> [!tip] 為什麼要用 `sudoers.d/`
> 1. **系統升級不會覆蓋**你的設定（主 `/etc/sudoers` 可能被套件更新替換）
> 2. 每個用途一個檔案，好管理、好稽核、好用組態管理工具派送
> 3. 檔名前綴數字控制載入順序（後載入的覆蓋先載入的）
>
> **注意**：檔名不能包含 `.`（會被忽略），
> 所以 `10-deploy.conf` 不會生效，要叫 `10-deploy`。

### sudoers 語法

```
使用者   主機 = (可切換成誰) 標籤: 指令
mike     ALL  = (ALL:ALL)    ALL
%sudo    ALL  = (ALL:ALL)    ALL
deploy   ALL  = (root)       NOPASSWD: /usr/bin/systemctl reload nginx
```

| 元素 | 說明 |
| --- | --- |
| `%群組` | 群組（前面加 `%`） |
| `ALL` | 任意 |
| `(root)` | 可以切換成 root |
| `(ALL:ALL)` | 可切換成任意使用者:任意群組 |
| `NOPASSWD:` | 不需要輸入密碼 |
| `NOEXEC:` | 禁止該指令再開子程序 |

> [!danger] `NOPASSWD` 加上萬用字元 = 等同給 root
> ```sudoers
> deploy ALL=(root) NOPASSWD: /usr/bin/systemctl *          # ✗ 危險
> deploy ALL=(root) NOPASSWD: /bin/chmod                    # ✗ 可 chmod 任何檔案
> deploy ALL=(root) NOPASSWD: /usr/bin/find                 # ✗ find -exec 可執行任意指令
> deploy ALL=(root) NOPASSWD: /usr/bin/vi                   # ✗ vi 裡可以 :!sh
> ```
> 很多常見指令都能「逃逸」成 shell。授權時：
> - **寫完整指令與參數**，不要用 `*`
> - 避開 `find`、`vi/vim`、`less`、`awk`、`tar`、`env`、`nmap` 等可執行外部指令的工具
> - 參考 <https://gtfobins.github.io> 確認你要授權的指令有沒有逃逸手法
>
> 稽核目前的 sudo 規則：
> ```bash
> sudo -ll                       # 列出詳細規則
> sudo -l -U deploy              # 查某個使用者能做什麼
> ```

### sudo 的其他實用設定

```sudoers
# 記錄所有 sudo 指令的輸入輸出（稽核用）
Defaults log_input, log_output
Defaults iolog_dir=/var/log/sudo-io

# 每次都要輸入密碼（預設 15 分鐘內免再輸入）
Defaults timestamp_timeout=0

# 輸入錯誤密碼時的訊息
Defaults badpass_message="密碼錯誤，這次操作已被記錄。"

# 保留特定環境變數
Defaults env_keep += "http_proxy https_proxy no_proxy"
```

> [!warning] `sudo` 會重設 `PATH`
> ```bash
> which mytool          # /opt/tools/bin/mytool
> sudo mytool           # sudo: mytool: command not found
> ```
> `sudo` 用 `secure_path`（定義在 `/etc/sudoers`）取代你的 `PATH`，
> 這是防止「執行到使用者目錄下的惡意同名程式」的安全設計。
>
> 解法（由好到壞）：
> ```bash
> sudo /opt/tools/bin/mytool                 # ✓ 完整路徑
> sudo env "PATH=$PATH" mytool               # △ 保留 PATH
> # 或在 sudoers 的 secure_path 加入該目錄
> ```
> 見 [[20-環境變數與設定檔]]。

## 完整實戰範例

### 情境一：新進人員開帳號的標準流程

```bash
#!/usr/bin/env bash
# add-user.sh — 依標準流程建立使用者
set -euo pipefail

USERNAME="${1:?用法: $0 <帳號> <全名>}"
FULLNAME="${2:?用法: $0 <帳號> <全名>}"
PUBKEY_FILE="${3:-}"

# 1. 建立帳號
sudo useradd -m -s /bin/bash -c "$FULLNAME" "$USERNAME"

# 2. 加入需要的群組（adm 讓他能看日誌而不用 sudo）
sudo usermod -aG adm "$USERNAME"

# 3. 密碼政策：首次登入強制改密碼
sudo passwd "$USERNAME"
sudo chage -d 0 "$USERNAME"

# 4. 密碼有效期：90 天，到期前 14 天警告，最短 1 天才能再改
sudo chage -M 90 -W 14 -m 1 "$USERNAME"

# 5. 部署 SSH 公鑰（如果提供）
if [ -n "$PUBKEY_FILE" ]; then
    sudo install -d -m 700 -o "$USERNAME" -g "$USERNAME" "/home/$USERNAME/.ssh"
    sudo install -m 600 -o "$USERNAME" -g "$USERNAME" \
         "$PUBKEY_FILE" "/home/$USERNAME/.ssh/authorized_keys"
fi

# 6. 收緊家目錄權限（預設 755，其他使用者看得到內容）
sudo chmod 750 "/home/$USERNAME"

# 7. 驗證
echo "── 建立結果 ──"
id "$USERNAME"
sudo chage -l "$USERNAME"
sudo ls -la "/home/$USERNAME/.ssh" 2>/dev/null || echo "（未部署公鑰）"
```

### 情境二：離職處理

```bash
USER=bob

# 1. 先盤點，不要急著刪
sudo -l -U "$USER"                              # 有什麼 sudo 權限
sudo crontab -u "$USER" -l 2>/dev/null          # 有什麼排程
ps -u "$USER"                                   # 有什麼在跑
sudo find / -xdev -uid "$(id -u $USER)" 2>/dev/null | head -50
sudo grep -rn "$USER" /etc/sudoers.d/ /etc/ssh/ 2>/dev/null

# 2. 停用（不刪除）
sudo usermod -L "$USER"                         # 鎖定密碼
sudo usermod -s /usr/sbin/nologin "$USER"       # 禁止登入
sudo usermod -e 1 "$USER"                       # 帳號設為已到期
sudo mv "/home/$USER/.ssh/authorized_keys" \
        "/home/$USER/.ssh/authorized_keys.disabled"   # 停用金鑰登入

# 3. 踢掉現有連線
sudo pkill -KILL -u "$USER"

# 4. 移除 sudo 權限
sudo gpasswd -d "$USER" sudo

# 5. 記錄處理時間，觀察 30 天後再考慮刪除
echo "$(date +%F) 停用 $USER" | sudo tee -a /var/log/account-changes.log
```

> [!warning] 別忘了 SSH 金鑰
> 鎖定密碼（`usermod -L`）**不會阻止金鑰登入**！
> 這是很常見的疏漏——以為鎖了帳號，結果對方還是能用金鑰進來。
>
> 完整停用必須同時處理：密碼、shell、帳號到期日、`authorized_keys`。
> 更好的做法是在 `sshd_config` 用 `AllowUsers` / `AllowGroups` 白名單，
> 見 [[04-sshd-伺服器端設定]]。

### 情境三：帳號安全稽核

```bash
#!/usr/bin/env bash
# audit-accounts.sh — 帳號安全稽核
set -uo pipefail

echo "═══ 1. UID 0 的帳號（應只有 root）═══"
awk -F: '$3 == 0 {print $1}' /etc/passwd

echo "═══ 2. 空密碼帳號（應為空）═══"
sudo awk -F: '$2 == "" {print $1}' /etc/shadow

echo "═══ 3. 可互動登入的一般使用者 ═══"
awk -F: '$3 >= 1000 && $3 < 65534 && $7 !~ /nologin|false/ {print $1, $7}' /etc/passwd

echo "═══ 4. 有 sudo 權限的帳號 ═══"
getent group sudo wheel 2>/dev/null
sudo grep -rhE "^[^#%].*ALL" /etc/sudoers /etc/sudoers.d/ 2>/dev/null

echo "═══ 5. 密碼從未過期的帳號 ═══"
for u in $(awk -F: '$3>=1000 && $3<65534 {print $1}' /etc/passwd); do
    max=$(sudo chage -l "$u" | awk -F': ' '/Maximum/ {print $2}')
    [ "$max" = "99999" ] && echo "$u（無密碼期限）"
done

echo "═══ 6. 90 天未登入的帳號 ═══"
lastlog -b 90 | grep -v "Never logged in" | tail -n +2

echo "═══ 7. 從未登入過的帳號 ═══"
lastlog | awk '$2 == "**Never" {print $1}' | grep -vE "^(root|daemon|bin|sys)"

echo "═══ 8. 最近的登入失敗 ═══"
sudo lastb -n 10 2>/dev/null || echo "（無 btmp 紀錄）"

echo "═══ 9. 孤兒檔案（擁有者已刪除）═══"
sudo find / -xdev \( -nouser -o -nogroup \) 2>/dev/null | head -20
```

> [!tip] 把稽核腳本排進每月維護
> 這些檢查項目大多是 TWGCB、CIS Benchmark 的必檢項。
> 把輸出存檔並與上個月比對，**新增的項目就是要調查的**：
> ```bash
> ./audit-accounts.sh > "/var/log/audit/accounts-$(date +%Y%m).txt"
> diff "/var/log/audit/accounts-$(date -d '1 month ago' +%Y%m).txt" \
>      "/var/log/audit/accounts-$(date +%Y%m).txt"
> ```
> 見每月維護作業與 [[08-系統強化與稽核]]。

> [!info]- Rocky / AlmaLinux（RHEL 系）對照
>
> | 項目 | Debian / Ubuntu | RHEL 系 |
> | --- | --- | --- |
> | **提權群組** | `sudo` | **`wheel`** |
> | 互動建立使用者 | `adduser`（高階） | **只有 `useradd`** |
> | 互動刪除 | `deluser` | 只有 `userdel` |
> | 預設 shell | `/bin/bash` | `/bin/bash` |
> | nologin 路徑 | `/usr/sbin/nologin` | **`/sbin/nologin`** |
> | 密碼品質模組 | `pam_pwquality` / `pam_unix` | `pam_pwquality` |
> | 密碼品質設定 | `/etc/security/pwquality.conf` | 同左 |
> | 認證日誌 | `/var/log/auth.log` | **`/var/log/secure`** |
>
> RHEL 的 sudoers 預設是：
> ```sudoers
> %wheel ALL=(ALL) ALL
> ```
> 所以加人要用：
> ```bash
> sudo usermod -aG wheel mike
> ```
>
> 另外 RHEL 系有 `authselect` 管理 PAM 設定，直接改 `/etc/pam.d/` 可能被覆蓋：
> ```bash
> sudo authselect current
> sudo authselect select sssd with-mkhomedir --force
> ```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| `usermod -G` 之後失去所有原有群組 | 少了 `-a` | 用 `-aG`；事前先 `id user` 備份 |
| 加了群組但 `groups` 沒變 | session 未重新載入 | 登出再登入 / `newgrp <群組>` |
| `user is not in the sudoers file` | 不在 `sudo`（RHEL：`wheel`）群組 | `usermod -aG sudo user` 後重新登入 |
| 改壞 sudoers，所有人不能 sudo | 沒用 `visudo` | recovery mode 修復；以後一律 `visudo` |
| `/etc/sudoers.d/xxx.conf` 沒生效 | **檔名含 `.` 會被忽略** | 改名為不含點的檔名 |
| `sudo cmd` 說 command not found | `secure_path` 取代了 `PATH` | 用完整路徑 |
| 鎖了帳號對方還是能 SSH 進來 | `usermod -L` 不影響金鑰登入 | 一併停用 `authorized_keys` |
| `useradd` 建的帳號無法登入 | 沒有密碼（帳號鎖定） | `passwd <user>` 設定密碼 |
| 刪除使用者後檔案顯示成數字 | UID 沒有對應名稱 | 刪除前先 `find -uid` 盤點處理 |
| `su - user` 說帳號無法使用 | shell 是 `nologin` | 用 `sudo -u user -s /bin/bash` |
| `getent passwd user` 有但 `/etc/passwd` 沒有 | 使用者來自 LDAP/AD | 正常，查 `/etc/nsswitch.conf` |
| 新建檔案群組不是預期的 | 主要群組不對，或目錄缺 setgid | `id user` 確認；`chmod g+s <目錄>` |

## 安全性注意事項

> [!danger] 定期稽核 UID 0
> ```bash
> awk -F: '$3 == 0 {print $1}' /etc/passwd
> ```
> 只該有 `root`。多出來的任何帳號都是完整 root 權限的後門。

> [!danger] `NOPASSWD` 要極度謹慎
> 每一條 `NOPASSWD` 都是一個潛在的提權路徑。授權前問自己：
> - 這個指令能不能開子 shell？（`vi`、`less`、`find`、`awk`、`tar`…）
> - 能不能寫入任意檔案？（`tee`、`dd`、`cp`、`chmod`…）
> - 參數有沒有用萬用字元？
>
> 查詢逃逸手法：<https://gtfobins.github.io>

> [!warning] 密碼政策要用 PAM 強制，不能只靠宣導
> 編輯 `/etc/security/pwquality.conf`：
> ```ini
> minlen = 12          # 最短長度
> dcredit = -1         # 至少 1 個數字
> ucredit = -1         # 至少 1 個大寫
> lcredit = -1         # 至少 1 個小寫
> ocredit = -1         # 至少 1 個特殊字元
> difok = 5            # 與舊密碼至少 5 個字元不同
> maxrepeat = 3        # 同一字元最多連續 3 次
> enforce_for_root     # 對 root 也生效
> ```
> 帳號鎖定政策（`/etc/security/faillock.conf`）：
> ```ini
> deny = 5             # 連續 5 次失敗
> unlock_time = 900    # 鎖定 15 分鐘
> fail_interval = 900
> ```
> 這些都是 TWGCB Linux 基準的必檢項目，見 [[04-TWGCB-Linux本機導入]]。

> [!tip] 服務帳號的最小權限原則
> 每個服務都該有自己的專屬帳號，而不是共用 `nobody` 或用 root 跑：
> ```bash
> sudo useradd --system --no-create-home --shell /usr/sbin/nologin myapp
> ```
> 這樣萬一該服務被入侵，攻擊者只拿到那個帳號的權限，
> 而不是整台機器。搭配 systemd 的 `User=`、`ProtectSystem=`、
> `PrivateTmp=` 等強化選項效果更好，見 [[17-systemd服務管理]]。

## 練習題

> [!question]- 練習 1：安全地實驗 `usermod -G` 的陷阱
> 在練習機上建立測試帳號，驗證少了 `-a` 的後果，並示範如何救回來。
>
> **解答**
>
> ```bash
> # 準備
> sudo useradd -m -s /bin/bash testuser
> sudo usermod -aG sudo,adm,audio testuser
> id testuser
> ```
> ```
> uid=1002(testuser) gid=1002(testuser) groups=1002(testuser),4(adm),27(sudo),29(audio)
> ```
>
> ```bash
> # 先備份（實務上一定要做這步）
> id testuser > /tmp/testuser-groups.txt
>
> # 模擬錯誤
> sudo usermod -G docker testuser
> id testuser
> ```
> ```
> uid=1002(testuser) gid=1002(testuser) groups=1002(testuser),988(docker)
> ```
> **sudo、adm、audio 全部消失了。**
>
> 救回來：
> ```bash
> sudo usermod -G sudo,adm,audio,docker testuser
> id testuser
> ```
>
> 如果沒有備份，就只能靠記憶或稽核紀錄。
> 這也是為什麼組態管理工具（Ansible）宣告式管理群組比手動改安全。

> [!question]- 練習 2：建立一個受限的部署帳號
> 建立 `deploy` 帳號，要求：
> 1. 不能用密碼登入，只能用 SSH 金鑰
> 2. 可以免密碼 reload nginx 和 php-fpm，但不能做其他事
> 3. 可以讀 `/var/log/nginx/`
> 4. 驗證它**不能**執行 `sudo su` 或 `sudo bash`
>
> **解答**
>
> ```bash
> # 1. 建立帳號（無密碼，只能金鑰登入）
> sudo useradd -m -s /bin/bash -c "Deploy account" deploy
> sudo passwd -l deploy                    # 鎖定密碼
> sudo install -d -m 700 -o deploy -g deploy /home/deploy/.ssh
> sudo install -m 600 -o deploy -g deploy ~/deploy.pub /home/deploy/.ssh/authorized_keys
>
> # 3. 讀日誌權限（透過 adm 群組）
> sudo usermod -aG adm deploy
>
> # 2. sudo 規則
> sudo visudo -f /etc/sudoers.d/20-deploy
> ```
> ```sudoers
> deploy ALL=(root) NOPASSWD: /usr/bin/systemctl reload nginx
> deploy ALL=(root) NOPASSWD: /usr/bin/systemctl reload php8.3-fpm
> deploy ALL=(root) NOPASSWD: /usr/bin/systemctl status nginx
> ```
>
> ```bash
> # 4. 驗證
> sudo -l -U deploy
> ```
> ```
> User deploy may run the following commands on lab01:
>     (root) NOPASSWD: /usr/bin/systemctl reload nginx
>     (root) NOPASSWD: /usr/bin/systemctl reload php8.3-fpm
>     (root) NOPASSWD: /usr/bin/systemctl status nginx
> ```
>
> ```bash
> sudo -u deploy sudo systemctl reload nginx      # ✓ 成功
> sudo -u deploy sudo bash                        # ✗ Sorry, user deploy is not allowed
> sudo -u deploy sudo systemctl restart nginx     # ✗ 拒絕（只授權 reload）
> ```
>
> **注意**：`systemctl reload nginx` 與 `systemctl restart nginx` 是不同的規則字串，
> 授權 reload 不會意外允許 restart。這就是精確授權的價值。

> [!question]- 練習 3：找出這台機器的安全風險
> 執行「情境三」的稽核腳本，說明每一項如果出現非預期結果代表什麼風險。
>
> **解答**
>
> | 檢查項 | 非預期結果 | 代表的風險 |
> | --- | --- | --- |
> | UID 0 不只 root | 有隱藏的 root 後門 | **最高風險**，可能已被入侵 |
> | 有空密碼帳號 | 任何人知道帳號名就能登入 | 極高，且違反所有資安基準 |
> | 可登入使用者多於名單 | 有未經授權建立的帳號 | 高，需追查來源 |
> | sudo 規則含萬用字元或危險指令 | 可被提權到 root | 高，見 GTFOBins |
> | 密碼無期限（99999） | 密碼可能已外洩多年 | 中，TWGCB 必檢項 |
> | 90 天未登入的帳號 | 離職未處理、共用帳號 | 中，應停用 |
> | 從未登入的一般帳號 | 建了沒用，或是後門預留 | 中，應確認來源 |
> | 大量登入失敗 | 正在被暴力破解 | 中高，應啟用 Fail2ban |
> | 孤兒檔案 | 刪帳號沒清乾淨；UID 可能被重用 | 中，應處理擁有權 |
>
> 處理優先序：**UID 0 → 空密碼 → 危險 sudo 規則 → 其他**。
> 前三項若有異常，應視為潛在入侵事件處理，見 [[04-備份災難復原與入侵應變]]。

Q7. `usermod -L bob` 之後 bob 還能用 SSH 金鑰登入嗎？完整停用要處理哪四件事？
Q8. 為什麼要用 `visudo` 而不是直接編輯 `/etc/sudoers`？改壞了怎麼救？
Q9. `/etc/sudoers.d/deploy.conf` 為什麼沒生效？
Q10. `deploy ALL=(root) NOPASSWD: /usr/bin/vim` 有什麼風險？

> [!question]- 測驗答案
> **Q1.** UID；新使用者可能拿到相同 UID 而自動繼承那些檔案的所有權。刪除前先 `find / -xdev -uid N`（見「使用者的本質是一個數字」）。
> **Q2.** `awk -F: '$3 == 0 {print $1}' /etc/passwd`；只該有 `root`，其他都是完整 root 權限的後門。
> **Q3.** `!` 帳號鎖定、`*` 無法用密碼登入（服務帳號）、空白 = 無密碼可直接登入，最危險。
> **Q4.** 不會，只列附加成員；`getent group` 加上 `awk -F: '$4 == GID' /etc/passwd`。
> **Q5.** 不建家目錄、無密碼（鎖定）、shell 是 `/bin/sh`；腳本用 `useradd -m -s /bin/bash -c "名字"` 再 `passwd`。
> **Q6.** `useradd --system --no-create-home --shell /usr/sbin/nologin name`；不能，`sudo -u` 不經 shell 檢查（刻意的，方便管理員測試）。
> **Q7.** 能——鎖密碼不影響金鑰登入。要處理：密碼（`-L`）、shell（`nologin`）、到期日（`-e 1`）、`authorized_keys`。
> **Q8.** `visudo` 存檔時檢查語法；語法錯會讓所有人無法 sudo 且無法用 sudo 修，只能靠 root session、`pkexec` 或 recovery mode。
> **Q9.** 檔名含 `.` 會被忽略；改成 `deploy`。
> **Q10.** `vim` 可用 `:!sh` 開 shell，等同給 root。授權前查 GTFOBins，避開能執行外部指令的工具。
