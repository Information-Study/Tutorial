# 新機建置標準流程

> [!abstract] 這篇你會學到
> - 把「裝一台伺服器」拆成**七個階段**，每階段有明確的**產出物**，而不是憑印象做完
> - 設計一張**建置申請單**，逼業務單位在開機之前就把 IP、備份、監控、除役日講清楚
> - ★★★★★ 用**不會鎖門的順序**做帳號初始化：先驗證公鑰能登入，才關 root 與密碼登入
> - ★★★★ 執行**納管四件事**（監控／日誌／備份／盤點），任一缺項即驗收不通過
> - 寫出一支 `/usr/local/sbin/server-build-verify`，**自動跑完 22 項驗收並輸出可貼進交付單的表格**
> - 產出一份**有簽核欄位、有紅線項、可以印出來歸檔**的交付文件
> - 在交付當下就寫好**除役計畫**（資料清除、憑證撤銷、IP 回收）

> [!warning] 未實機驗證
> 本篇 Ubuntu／RHEL 側的指令依官方文件與常見發行版行為撰寫。
> **Proxmox VE（`qm`、`pvesh`）與交換器側的指令未在實機環境驗證**，
> 實作前請對照你手上 PVE 版本的官方文件，並先在測試 VM 上演練一次。

## 觀念說明

### 這篇要回答的不是「怎麼裝 Ubuntu」

裝 Ubuntu 誰都會。機關真正的問題是另外三個：

```
① 怎麼「證明」這台機器裝好了？        → 驗收檢查表（可執行、可重跑）
② 怎麼把它「簽名交出去」？             → 簽核欄位（建置人／覆核人／主管）
③ 三年後別人接手，怎麼查得到           → 建置紀錄三載體
   「誰在什麼時候做了什麼」？             （script 側錄 + build-record.md + etckeeper）
```

★★★★★ **一台沒有簽核的機器不是「交付」，只是「裝好了」。**
出事時「裝好了」沒有任何法律與稽核意義 —— 沒有人能說出這台機器上線時是什麼狀態、
誰核准的、當時的例外項是誰同意的。

### ★★★★ 沒有 SOP 的六種典型災難

這六種都是機關真實會發生、且**事後很難補救**的：

| # | 災難 | 發生原因 | 事後代價 |
| --- | --- | --- | --- |
| ① | ★★★★★ **root 密碼登入忘了關** | 裝完急著上線，「之後再改」 | 上線 48 小時內被暴力破解；`/var/log/auth.log` 每分鐘上百筆 |
| ② | ★★★★ **時區／NTP 沒設** | 預設 UTC，沒人注意 | 日誌時間對不上，**資安事件無法關聯、日誌不具稽核證據力** |
| ③ | ★★★★ **IP 隨手挑** | 「ping 不到就是沒人用」 | 與印表機／冷氣監控主機衝突；兩台機器同時斷線 |
| ④ | ★★★★★ **忘了接備份** | 備份是另一組人做的，沒交接 | 硬碟壞掉才發現這台從來沒被備份過，資料全失 |
| ⑤ | ★★★★ **忘裝監控 agent** | 監控是「上線後再說」 | 機器掛了三天沒人知道，使用者打電話來才發現 |
| ⑥ | ★★★★ **交接時沒有任何建置紀錄** | 全部在建置人腦子裡 | 建置人離職／調職，這台機器變成「不敢動的黑盒子」 |

> [!danger] 這六種災難有一個共同點
> **它們全都不會在建置當天出事。**
>
> 忘關 root 登入，當天機器跑得好好的；忘接備份，當天資料也在。
> 它們會在**三個月後、由不同的人、在最糟的時間點**爆炸。
>
> 這就是為什麼驗收檢查表必須在**交付當下**跑完 ——
> 那是唯一一個「所有資訊都還在建置人腦子裡」的時刻。

### 七階段流程與產出物

```
【0】受理與建置申請單
      產出：簽好的建置申請單（電子表單或 PDF）
        │   ★★★★ 沒填完不要開機
        ▼
【1】虛擬／實體資源與網路配發
      產出：VM 規格單、IP 配發紀錄（寫回盤點表）、VLAN／防火牆開通單
        ▼
【2】OS 安裝與磁碟分割
      產出：安裝側錄 log、分割配置表、安裝完成快照（snapshot）
        ▼
【3】基準設定
      hostname／時區／NTP／locale／套件來源／首次更新
      產出：/root/build-record.md 前半段、etckeeper 初始 commit
        ▼
【4】角色套件安裝
      產出：安裝的套件清單、服務埠清單、設定檔位置清單
        ▼
【5】納管與加固
      納管四件事 + 加固八項
      產出：監控儀表板連結、日誌到站證明、備份首次成功紀錄、盤點編號
        ▼
【6】驗收簽核與文件歸檔
      產出：server-build-verify 輸出、22 項驗收表、簽核頁、歸檔位置
        │
        ▼
    ★ 交付（此刻起變更走 [[08-變更管理流程]]）
```

> [!note] 階段之間是「閘門」不是「順序建議」
> ★★★ **前一階段的產出物沒生出來，下一階段不准開始。**
>
> 最常被跳過的是【0】與【6】—— 因為它們是**文書工作**，
> 而文書工作正是三年後唯一還留下來的東西。

### 機器的三個身分

一台伺服器在機關裡同時有三個身分，**建置流程就是把這三個身分同時建立起來**：

| 身分 | 誰在乎 | 建立於 | 沒建立的後果 |
| --- | --- | --- | --- |
| **技術身分**（hostname、IP、OS） | 維運人員 | 階段【2】【3】 | 找不到機器 |
| **業務身分**（用途、負責人、資料等級） | 業務單位、稽核 | 階段【0】 | ★★★★ 出事時找不到人決策 |
| **管理身分**（資產編號、保固、除役日） | 財產管理、資安 | 階段【5】【6】 | ★★★★ 盤點對不上、EOL 機器沒人汰換 |

★★★ 很多人只做技術身分，所以機器「存在但沒人管」。
本篇的價值就在強迫另外兩個身分同時完成。

## 環境準備與安裝

### 【0】受理與建置申請單

★★★★ **建置申請單沒填完不要開機。** 理由很直接：

> [!danger] 事後補的資訊，90% 補不齊
> 開機之後再去問「這台的資料分類等級是什麼？RTO 幾小時？」，
> 得到的答案永遠是「都可以」「你決定就好」。
>
> **開機之前問，業務單位會認真回答**，因為那時候他還需要你幫他開機。

#### 必填欄位（缺一不受理）

| 欄位 | 為什麼一定要在開機前決定 |
| --- | --- |
| **用途／承載服務** | ★★★ 決定角色附加驗收項（Web／DB／工具機做的事不同） |
| **業務負責人（姓名／分機／單位）** | ★★★★ 停機、資安事件、變更都要找他核准 |
| **技術負責人** | 誰在維運這台（可能不是建置人） |
| **資料分類等級**（公開／內部／敏感／個資） | ★★★★★ 決定加密、備份保存、日誌保留與除役時的抹除方式 |
| **對外或純內網** | ★★★★ 決定防火牆政策、WAF、憑證、弱點掃描頻率 |
| **IP / VLAN / DNS / 閘道 / 網段遮罩** | ★★★★ 一律從盤點表配發，**禁止自行挑選** |
| **CPU / RAM / 磁碟容量與成長預估** | 決定 LVM 要留多少白 |
| **備份保留天數 / RPO / RTO** | ★★★★ RPO 決定備份頻率，RTO 決定要不要做快照或 HA |
| **監控門檻與通知對象** | ★★★★ 沒有通知對象的監控＝沒有監控 |
| **維護時段（可停機時間）** | 未來所有更新與重開都靠這欄 |
| **預定除役日** | ★★★ 沒有除役日的機器會活到硬體壞掉為止 |
| **例外需求與理由** | 需要開的特殊埠、需要保留的密碼登入等，**這裡不寫，驗收就過不了** |

> [!tip] 把申請單做成「不填不能送出」的電子表單
> 用 n8n、Google 表單或內部 OA 都行，重點是**必填欄位驗證**。
> 紙本表單最大的問題不是紙，是**可以留白送出**。

### 【1】資源配發與網路

#### 命名規範：角色-環境-序號

```
web-prd-01        對外網站，正式環境，第 1 台
db-prd-01         資料庫，正式
web-uat-01        測試環境
tool-int-01       內部工具機
```

★★★ **主機名稱三條紅線**（違反者現在改比上線後改便宜一百倍）：

| 規則 | 原因 |
| --- | --- |
| ★★★ **不用底線 `_`** | RFC 1123 主機名稱只允許 `a-z`、`0-9`、`-`。底線在 **TLS SNI 比對**、部分 HTTP 中介與反向代理、以及某些 DNS 解析器上會直接失敗 |
| ★★★ **不用中文、不用大寫** | 中文在 syslog／監控標籤／檔名會亂碼；大寫在不同工具間比對不一致 |
| ★★ **不用序號以外的流水編碼** | `srv-a3f2` 這種名字，三年後沒人記得代表什麼 |

驗證命名是否合規：

```bash
hostname
```

預期輸出：

```text
web-prd-01
```

```bash
hostname -f
```

預期輸出：

```text
web-prd-01.example.gov.tw      # ★★★ 這裡沒吐 FQDN 就是 /etc/hosts 沒寫對
```

#### FQDN 與 `/etc/hosts` 的正確寫法

★★★ `hostname -f` 能不能回傳 FQDN，取決於 `/etc/hosts` 裡**第一個**對應到本機 IP 的那一行，
而且 **FQDN 必須排在短名前面**：

```text
127.0.0.1       localhost
127.0.1.1       web-prd-01.example.gov.tw web-prd-01     # ★★★ FQDN 在前，短名在後
10.20.30.41     web-prd-01.example.gov.tw web-prd-01     # 有固定 IP 時再加這行

::1             localhost ip6-localhost ip6-loopback
ff02::1         ip6-allnodes
ff02::2         ip6-allrouters
```

順序寫反（短名在前）的後果：`hostname -f` 只回 `web-prd-01`，
連帶影響 **Kerberos 票證、憑證 CN 比對、郵件通知的來源標示、部分監控 agent 的自我註冊**。

#### IP 一律從盤點表配發

> [!danger] 「ping 不通就代表沒人用」是錯的
> ★★★★ 會 ping 不通但**確實被佔用**的情況至少有四種：
> - 機器關機中（冷備、季節性使用的機器）
> - 防火牆擋 ICMP（多數加固過的主機都擋）
> - 保留給 DHCP pool 或 VIP（VRRP／keepalived）的位址
> - 網路設備管理介面（交換器、UPS、冷氣監控、門禁）
>
> **唯一合法的取得方式是從 [[11-資訊設備盤點]] 的位址表配發，並當場登記回去。**

配發後立刻驗證該位址真的沒被佔用（在同網段的機器上執行）：

```bash
sudo arping -c 3 -I ens18 10.20.30.41
```

預期輸出（**沒人用**應該長這樣）：

```text
ARPING 10.20.30.41
Sent 3 probes (3 broadcast(s))
Received 0 response(s)              # ★★★★ 有任何 response 就代表位址已被佔用，停手回報
```

### 【2】OS 安裝與磁碟分割

#### ★★★★ 分割決策準則（不是分割操作）

實際的 `parted` / `pvcreate` / `lvcreate` 步驟看 [[15-磁碟分割與掛載]]。
這裡只回答**要不要分開**：

| 掛載點 | 什麼情況要獨立分割 | 不分割的後果 |
| --- | --- | --- |
| `/var/log` | ★★★★ **只要這台會產生日誌就分**（等於一定要分） | 日誌暴增塞爆 `/`，**整台服務停擺**，連 ssh 登入都會失敗 |
| `/var` | ★★★ 跑 Docker、資料庫、郵件佇列、大量 apt 快取時分 | 容器映像檔塞爆 `/` |
| `/tmp` | ★★★ 多人共用、跑不受信任的程式時分（並掛 `nosuid,nodev,noexec`） | 使用者上傳大檔塞爆 `/`；`/tmp` 可執行成為提權跳板 |
| `/home` | ★★ 有一般使用者帳號時分 | 使用者資料塞爆 `/` |
| `/boot` | ★★★ UEFI／需要獨立 `/boot/efi`；LVM 或加密根目錄時必分 | 開不了機 |
| `swap` | ★★ 依用途決定（DB 通常關 swap 或設極低 `swappiness`） | 記憶體不足時整台卡死 |

★★★★ **LVM 不要一次分完。** 建議只配發 **60～70%** 的 VG 容量，剩下留白：

```text
VG: vg0  (200 GiB)
├─ lv_root    30 GiB   /
├─ lv_var     40 GiB   /var
├─ lv_varlog  20 GiB   /var/log     ← ★★★★ 獨立
├─ lv_tmp      8 GiB   /tmp
└─ 未配發     102 GiB               ← ★★★★ 留白，出事時能線上擴充
```

檢查留白比例：

```bash
sudo vgs --units g -o vg_name,vg_size,vg_free
```

預期輸出：

```text
  VG  VSize    VFree
  vg0 <200.00g 102.00g            # ★★★★ VFree / VSize 應 >= 20%
```

> [!example] 日誌塞爆根目錄的真實走向與事後擴充
> **走向**：某支程式開了 debug 模式 → `/var/log/app/debug.log` 兩天長到 40 GiB →
> `/` 100% → **journald 停止寫入、sshd 無法建立 session、nginx 無法寫 access log 而回 500** →
> 遠端登入不進去，只能去機房或開 PVE console。
>
> **有留白時的線上擴充（不需停機、不需重開）**：
>
> ```bash
> # ★★★ 先確認 VG 還有空間
> sudo vgs vg0
> # 線上加大 LV 並同步擴充檔案系統（ext4 / xfs 都支援線上擴大）
> sudo lvextend -L +20G /dev/vg0/lv_varlog
> sudo resize2fs /dev/vg0/lv_varlog          # ext4
> # sudo xfs_growfs /var/log                 # ★★★ xfs 用這個，且 xfs 不能縮小
> df -h /var/log
> ```
>
> **沒留白時**：只能刪日誌（湮滅稽核證據）或關機加磁碟（服務中斷）。
> ★★★★★ 這就是留白 20% 的價值。

#### 安裝過程全程側錄

★★★ 從按下電源那一刻起就開始側錄，這是建置紀錄三載體的第一個：

```bash
sudo script -q -a -c "bash" /root/build-$(hostname -s)-$(date +%Y%m%d).log
```

預期輸出：

```text
Script started, output log file is '/root/build-web-prd-01-20260828.log'
```

★★★ 之後所有指令都在這個 shell 裡執行，`exit` 結束側錄。
**離開時記得把 log 的權限收緊**（裡面可能含有暫時貼上的密碼或 token）：

```bash
sudo chmod 600 /root/build-web-prd-01-20260828.log
```

> [!info]- Rocky / AlmaLinux（RHEL 系）對照 —— 安裝與分割
> - 安裝方式：`kickstart`（`/root/anaconda-ks.cfg` 就是這台的安裝答案檔，**務必歸檔**）
> - ★★★ RHEL 預設檔案系統是 **XFS**，`xfs_growfs` 可以線上擴大但 **XFS 無法縮小**，
>   所以留白比 Ubuntu(ext4) 更重要
> - 預設分割：`/`、`/boot`、`/boot/efi`、`swap`、`/home`（RHEL 預設會分 `/home`）
> - ★★★ `/var/log/audit` 在 RHEL 上另有 auditd 專屬考量，塞滿時 auditd 可能依
>   `disk_full_action` 設定**讓系統停機**，分割時務必一併規劃

## 基礎設定

### 【3】基準設定：六件事一次做完

★★★★ 這六件事**必須在納管（階段【5】）之前完成**，理由在下一小節。

#### ① hostname

```bash
sudo hostnamectl set-hostname web-prd-01.example.gov.tw
hostnamectl
```

預期輸出：

```text
 Static hostname: web-prd-01.example.gov.tw
       Icon name: computer-vm
         Chassis: vm
Operating System: Ubuntu 24.04.2 LTS
          Kernel: Linux 6.8.0-51-generic
    Architecture: x86-64
```

★★★ 改完 hostname 後**一定要同步改 `/etc/hosts`**，否則 `sudo` 每次都會慢 5～10 秒
（因為 sudo 解析不到自己的主機名稱要等 DNS timeout）。

#### ② ★★★★ 時區

```bash
sudo timedatectl set-timezone Asia/Taipei
timedatectl show -p Timezone --value
```

預期輸出：

```text
Asia/Taipei
```

#### ③ ★★★★ NTP 來源

#### ④ ★★★★ 硬體時鐘一律 UTC

```bash

```

★★★★ Linux 的慣例是 **RTC 存 UTC**。設成 local time 會在
夏令時間變更、雙開機、虛擬機遷移時造成**時間跳躍**，
而時間跳躍在 SIEM 上會被判成「事件亂序」而丟棄。

> [!danger] ★★★★ 為什麼時間三件事必須在納管之前完成
> 一旦機器開始把日誌送到集中平台，**時間戳就變成證據**。
>
> | 沒設好會壞掉的東西 | 具體症狀 |
> | --- | --- |
> | **SIEM 事件關聯** | 這台的登入事件比防火牆事件早 8 小時 → 關聯規則永遠不觸發 |
> | **Kerberos / AD 加入網域** | ★★★★ 時間差超過 **5 分鐘**（預設 `MaxClockSkew`）直接拒絕認證 |
> | **憑證驗證** | 時間跑到憑證 `notBefore` 之前 → `certificate is not yet valid` |
> | **稽核軌跡的證據力** | ★★★★★ 時間不可信的日誌，在資安事件調查與稽核時**等同沒有日誌** |
>
> 事後修正時間，**已經送出去的日誌無法回溯修正**。那段期間等於沒有紀錄。

### 【5】納管四件事 —— 缺一不可驗收

> [!danger] ★★★★ 沒納管的機器等於不存在的機器
> 它不會出現在監控儀表板上（掛了沒人知道）、
> 不會出現在 SIEM 裡（被入侵沒人知道）、
> 不會出現在備份清單裡（資料沒了沒得救）、
> 不會出現在盤點表裡（保固到期沒人換、除役時沒人記得回收 IP）。

> Ubuntu Server 24.04 從 ISO 安裝後會有一個 `/etc/ssh/sshd_config.d/50-cloud-init.conf`，

### ★★★★★ 驗收腳本：`/usr/local/sbin/server-build-verify`

```bash
#!/usr/bin/env bash
# /usr/local/sbin/server-build-verify —— 新機建置驗收自動檢查（22 項）
# 用法： sudo server-build-verify            人眼閱讀模式
#        sudo server-build-verify --table    只輸出可貼進交付單的 Markdown 表格
# 退出碼： 0=全數通過  1=有一般項失敗  2=★有紅線項失敗（絕不得上線）
set -euo pipefail

CONF=/etc/server-build/role.conf
ADMIN_USER="${ADMIN_USER:-sysadm}"
EXPECTED_TZ="${EXPECTED_TZ:-Asia/Taipei}"
ROLE=generic; EXPECTED_PORTS="22"; ASSET_ID=""
# ★★★ 角色參數獨立成檔，讓同一支腳本能驗 Web / DB / 工具機
# shellcheck source=/dev/null
[[ -r "$CONF" ]] && source "$CONF"

PASS=0; FAILED=0; RED_FAILED=0
declare -a ROWS
MODE="${1:---human}"

die() { echo "致命錯誤：$*" >&2; exit 3; }
[[ $EUID -eq 0 ]] || die "必須以 root 執行（sshd -T、passwd -S 都需要 root）"

# record <編號> <檢查項> <紅線> <預期> <實際> <PASS|FAIL>
record() {
  local no="$1" item="$2" red="$3" want="$4" got="$5" res="$6"
  got="${got//|/／}"; got="${got//$'\n'/ }"          # ★★★ 防止實際值裡的 | 打壞表格
  ROWS+=("| ${no} | ${item} | ${red} | ${want} | \`${got}\` | ${res} |")
  if [[ "$res" == "PASS" ]]; then
    PASS=$((PASS+1))
    [[ "$MODE" == "--table" ]] || printf '  \033[32mPASS\033[0m %s %-34s %s\n' "$no" "$item" "$got"
  else
    FAILED=$((FAILED+1))
    # ★★★★ 不要寫成 [[ ... ]] && x —— set -e 下當條件為假時函式會以非零結束
    if [[ "$red" == "紅線" ]]; then RED_FAILED=$((RED_FAILED+1)); fi
    [[ "$MODE" == "--table" ]] || printf '  \033[31mFAIL\033[0m %s %-34s 實際=%s 預期=%s\n' \
        "$no" "$item" "$got" "$want"
  fi
}

# 把「取值可能失敗」統一包起來，避免 set -e 直接中斷整份檢查
safe() { "$@" 2>/dev/null || echo "N/A"; }

section() { [[ "$MODE" == "--table" ]] || echo -e "\n\033[1m$*\033[0m"; }

# ───────────────────────── A 身分與時間 ─────────────────────────
section "A 身分與時間"

HN=$(safe hostname)
if [[ "$HN" =~ ^[a-z0-9]([a-z0-9-]*[a-z0-9])?$ ]]; then
  record 01 "hostname 命名合規" "紅線" "小寫/無底線/RFC1123" "$HN" PASS
else
  record 01 "hostname 命名合規" "紅線" "小寫/無底線/RFC1123" "$HN" FAIL
fi

FQDN=$(safe hostname -f)
if [[ "$FQDN" == *.*.* ]]; then
  record 02 "FQDN 可解析" "—" "含網域的完整名稱" "$FQDN" PASS
else
  record 02 "FQDN 可解析" "—" "含網域的完整名稱" "$FQDN" FAIL
fi

if grep -qE "^[0-9.]+[[:space:]]+${FQDN}[[:space:]]" /etc/hosts; then
  record 03 "/etc/hosts 有 FQDN 且在短名前" "—" "FQDN 排在短名之前" "已設定" PASS
else
  record 03 "/etc/hosts 有 FQDN 且在短名前" "—" "FQDN 排在短名之前" "缺少或順序錯誤" FAIL
fi

TZ=$(safe timedatectl show -p Timezone --value)
[[ "$TZ" == "$EXPECTED_TZ" ]] \
  && record 04 "時區" "紅線" "$EXPECTED_TZ" "$TZ" PASS \
  || record 04 "時區" "紅線" "$EXPECTED_TZ" "$TZ" FAIL

SYNCED=$(safe timedatectl show -p NTPSynchronized --value)
[[ "$SYNCED" == "yes" ]] \
  && record 05 "NTP 已同步" "紅線" "yes" "$SYNCED" PASS \
  || record 05 "NTP 已同步" "紅線" "yes" "$SYNCED" FAIL

LRTC=$(safe timedatectl show -p LocalRTC --value)
[[ "$LRTC" == "no" ]] \
  && record 06 "硬體時鐘為 UTC" "—" "LocalRTC=no" "$LRTC" PASS \
  || record 06 "硬體時鐘為 UTC" "—" "LocalRTC=no" "$LRTC" FAIL

# ───────────────────────── B 儲存 ─────────────────────────
section "B 儲存"

if findmnt -no TARGET /var/log >/dev/null 2>&1; then
  record 07 "/var/log 為獨立掛載點" "—" "獨立分割" "$(findmnt -no SOURCE /var/log)" PASS
else
  record 07 "/var/log 為獨立掛載點" "—" "獨立分割" "併在 / 之下" FAIL
fi

VGPCT=$(vgs --noheadings --nosuffix --units b -o vg_size,vg_free 2>/dev/null \
        | awk 'NR==1{printf "%d", ($2/$1)*100}' || echo 0)
VGPCT=${VGPCT:-0}
if [[ "$VGPCT" -ge 20 ]]; then
  record 08 "LVM 留白比例" "—" ">= 20%" "${VGPCT}%" PASS
else
  record 08 "LVM 留白比例" "—" ">= 20%" "${VGPCT}%" FAIL
fi

ROOTPCT=$(df --output=pcent / | tail -1 | tr -dc '0-9')
if [[ "$ROOTPCT" -lt 70 ]]; then
  record 09 "根目錄使用率" "—" "< 70%" "${ROOTPCT}%" PASS
else
  record 09 "根目錄使用率" "—" "< 70%" "${ROOTPCT}%" FAIL
fi

# ───────────────────────── C 帳號與 SSH ─────────────────────────
section "C 帳號與 SSH"

if id "$ADMIN_USER" >/dev/null 2>&1 && id -nG "$ADMIN_USER" | grep -qwE 'sudo|wheel'; then
  record 10 "管理帳號存在且具 sudo" "紅線" "$ADMIN_USER 屬 sudo/wheel" "$(id -nG "$ADMIN_USER")" PASS
else
  record 10 "管理帳號存在且具 sudo" "紅線" "$ADMIN_USER 屬 sudo/wheel" "不存在或無 sudo" FAIL
fi

AK="/home/${ADMIN_USER}/.ssh/authorized_keys"
AKPERM=$(safe stat -c '%a' "$AK")
if [[ -s "$AK" && "$AKPERM" == "600" ]]; then
  record 11 "公鑰已部署且權限正確" "紅線" "存在且為 600" "$AKPERM" PASS
else
  record 11 "公鑰已部署且權限正確" "紅線" "存在且為 600" "${AKPERM}/檔案不存在或為空" FAIL
fi

SSHD_T=$(sshd -T 2>/dev/null || true)
PRL=$(echo "$SSHD_T" | awk '/^permitrootlogin/{print $2}')
[[ "$PRL" == "no" ]] \
  && record 12 "PermitRootLogin" "紅線" "no" "${PRL:-N/A}" PASS \
  || record 12 "PermitRootLogin" "紅線" "no" "${PRL:-N/A}" FAIL

PWA=$(echo "$SSHD_T" | awk '/^passwordauthentication/{print $2}')
KBI=$(echo "$SSHD_T" | awk '/^kbdinteractiveauthentication/{print $2}')
if [[ "$PWA" == "no" && "$KBI" == "no" ]]; then
  record 13 "密碼登入已關閉" "紅線" "password=no 且 kbdint=no" "pwd=$PWA kbd=$KBI" PASS
else
  record 13 "密碼登入已關閉" "紅線" "password=no 且 kbdint=no" "pwd=${PWA:-N/A} kbd=${KBI:-N/A}" FAIL
fi

if sshd -t 2>/dev/null; then
  record 14 "sshd 設定語法" "—" "sshd -t 無錯誤" "OK" PASS
else
  record 14 "sshd 設定語法" "—" "sshd -t 無錯誤" "$(sshd -t 2>&1 | head -1)" FAIL
fi

ROOTPW=$(safe passwd -S root | awk '{print $2}')
if [[ "$ROOTPW" == "L" || "$ROOTPW" == "NP" ]]; then
  record 15 "root 密碼已鎖定" "紅線" "L 或 NP" "$ROOTPW" PASS
else
  record 15 "root 密碼已鎖定" "紅線" "L 或 NP" "$ROOTPW" FAIL
fi

# ───────────────────────── D 網路暴露面 ─────────────────────────
section "D 網路暴露面"

if command -v ufw >/dev/null 2>&1; then
  FWDEF=$(ufw status verbose 2>/dev/null | awk -F'Default: ' '/^Default:/{print $2}')
  FWACT=$(ufw status 2>/dev/null | awk '/^Status:/{print $2}')
else
  FWDEF=$(safe firewall-cmd --get-default-zone); FWACT="firewalld"
fi
if [[ "$FWACT" == "active" && "$FWDEF" == deny* ]] || [[ "$FWACT" == "firewalld" && "$FWDEF" != "N/A" ]]; then
  record 16 "防火牆啟用且預設拒絕" "紅線" "active + deny(incoming)" "$FWACT / $FWDEF" PASS
else
  record 16 "防火牆啟用且預設拒絕" "紅線" "active + deny(incoming)" "$FWACT / $FWDEF" FAIL
fi

# ★★★★ 只看綁在 0.0.0.0 / :: 的埠 —— 綁 127.0.0.1 的不算對外暴露
LISTEN=$(ss -tlnH 2>/dev/null | awk '{print $4}' \
         | grep -E '^(0\.0\.0\.0|\*|\[::\]):' | sed 's/.*://' | sort -un | tr '\n' ' ')
UNEXPECTED=""
for p in $LISTEN; do
  case " $EXPECTED_PORTS " in *" $p "*) : ;; *) UNEXPECTED="$UNEXPECTED $p";; esac
done
if [[ -z "$UNEXPECTED" ]]; then
  record 17 "對外監聽埠與申請單一致" "紅線" "$EXPECTED_PORTS" "$LISTEN" PASS
else
  record 17 "對外監聽埠與申請單一致" "紅線" "$EXPECTED_PORTS" "未申請:$UNEXPECTED" FAIL
fi

# ───────────────────────── E 套件與更新 ─────────────────────────
section "E 套件與更新"

if systemctl is-enabled unattended-upgrades >/dev/null 2>&1 \
   || systemctl is-enabled dnf-automatic.timer >/dev/null 2>&1; then
  record 18 "自動安全更新已啟用" "—" "enabled" "enabled" PASS
else
  record 18 "自動安全更新已啟用" "—" "enabled" "disabled" FAIL
fi

BADREPO=""
if [[ -d /etc/apt/sources.list.d ]]; then
  # ★★★★ 第三方庫必須有 Signed-By（見 03-第三方APT套件庫實務）
  while IFS= read -r f; do
    grep -qiE 'signed-by' "$f" || BADREPO="$BADREPO $(basename "$f")"
  done < <(find /etc/apt/sources.list.d -type f \( -name '*.list' -o -name '*.sources' \))
fi
if [[ -z "$BADREPO" ]]; then
  record 19 "第三方套件來源皆有金鑰綁定" "—" "全部含 Signed-By" "合規" PASS
else
  record 19 "第三方套件來源皆有金鑰綁定" "—" "全部含 Signed-By" "未綁定:$BADREPO" FAIL
fi

# ───────────────────────── F 納管四件事 ─────────────────────────
section "F 納管四件事"

MONSVC=$(systemctl list-units --type=service --state=running --no-legend 2>/dev/null \
         | grep -oE '(node_exporter|prometheus-node-exporter|zabbix-agent2?|wazuh-agent)' | head -1)
if [[ -n "$MONSVC" ]]; then
  record 20 "監控 agent 執行中" "紅線" "agent 服務 running" "$MONSVC" PASS
else
  record 20 "監控 agent 執行中" "紅線" "agent 服務 running" "找不到任何 agent" FAIL
fi

TAG="BUILD-VERIFY-$(date +%s)"
logger -p local0.notice "$TAG" 2>/dev/null || true
sleep 2
if journalctl --since '-1 min' 2>/dev/null | grep -q "$TAG" \
   && grep -rqE '@@?[a-z0-9.-]+:' /etc/rsyslog.d/ 2>/dev/null; then
  record 21 "日誌轉送已設定且本機可寫入" "紅線" "有轉送設定 + journal 收得到" "OK" PASS
else
  record 21 "日誌轉送已設定且本機可寫入" "紅線" "有轉送設定 + journal 收得到" "缺轉送設定或寫入失敗" FAIL
fi

BK=$(systemctl show backup.service -p ExecMainStatus --value 2>/dev/null || echo "N/A")
BKTS=$(systemctl show backup.service -p ExecMainStartTimestamp --value 2>/dev/null || echo "")
if [[ "$BK" == "0" && -n "$BKTS" ]]; then
  record 22 "備份已執行且最近一次成功" "紅線" "ExecMainStatus=0 且曾執行" "status=$BK @ $BKTS" PASS
else
  record 22 "備份已執行且最近一次成功" "紅線" "ExecMainStatus=0 且曾執行" "status=$BK 未曾執行" FAIL
fi

if [[ -n "$ASSET_ID" && -f /root/build-record.md ]]; then
  record 23 "資產已登錄 + 建置紀錄存在" "紅線" "ASSET_ID + build-record.md" "$ASSET_ID" PASS
else
  record 23 "資產已登錄 + 建置紀錄存在" "紅線" "ASSET_ID + build-record.md" "缺 ASSET_ID 或紀錄檔" FAIL
fi

# ───────────────────────── 輸出交付單表格 ─────────────────────────
echo
echo "### 驗收檢查表 —— $(hostname -f)  角色=${ROLE}  $(date '+%Y-%m-%d %H:%M %Z')"
echo
echo "| # | 檢查項 | 紅線 | 預期結果 | 實際值 | 判定 |"
echo "| --- | --- | --- | --- | --- | --- |"
printf '%s\n' "${ROWS[@]}"
echo
echo "**通過 ${PASS} 項／失敗 ${FAILED} 項（其中紅線項失敗 ${RED_FAILED} 項）**"

if [[ "$RED_FAILED" -gt 0 ]]; then
  echo; echo "★★★★★ 有紅線項未通過 —— 本機**不得上線**，修正後重跑本腳本。"
  exit 2
elif [[ "$FAILED" -gt 0 ]]; then
  echo; echo "★★★ 有一般項未通過 —— 須於交付單「例外項」欄位載明理由並取得核准。"
  exit 1
fi
echo; echo "★ 全數通過，可進入簽核程序。"
exit 0
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ 關閉密碼登入後**所有人都登不進去** | 公鑰沒驗證就關密碼；權限錯／貼錯家目錄／多了換行 | 從 PVE console 或 IPMI 進入，`chmod 600 authorized_keys`、`chmod 700 ~/.ssh`、`chown` 給對的使用者；★★★★★ 下次嚴格照【1】～【6】順序 |
| ★★★★★ `sshd_config` 改成 `PasswordAuthentication no` **卻沒生效** | Ubuntu 24.04 的 `/etc/ssh/sshd_config.d/50-cloud-init.conf` 排在前面，**先出現的設定值獲勝** | 改 50 那個檔，或新增 `10-hardening.conf`；★★★★ 一律用 `sshd -T` 驗證，不要 grep 設定檔 |
| ★★★★ `/` 100% 導致 **ssh 登不進、nginx 回 500** | 日誌暴增而 `/var/log` 沒獨立分割 | 進 console → `du -xh / \| sort -h \| tail`；有 LVM 留白就 `lvextend`+`resize2fs`；沒有就先 `truncate -s 0` 最大那支 log（★★★ 不要 `rm`，程式還開著檔案不會釋放空間） |
| ★★★★ 日誌送到 SIEM **時間差 8 小時**、事件關聯規則不觸發 | 時區未設或 RTC 設成 local time | `timedatectl set-timezone Asia/Taipei; timedatectl set-local-rtc 0`；★★★★★ **已送出的日誌無法回溯修正**，該區間須在事件報告中註記 |
| ★★★★ 加入 AD 網域失敗 `Clock skew too great` | 時間差超過 Kerberos 預設 5 分鐘容忍值 | `chronyc makestep` 強制對時，再 `realm join`；★★★★ 確認 NTP 來源與網域控制站一致 |
| ★★★★ 新機一開機就**與既有設備 IP 衝突** | 用 ping 判斷位址空閒；對方擋 ICMP 或關機中 | 立刻 `ip link set ens18 down`，回頭查盤點表；★★★★ 位址一律從 [[11-資訊設備盤點]] 配發 |
| ★★★★ 機器掛了三天沒人知道 | 監控 agent 裝了但**沒有通知對象**，或平台端沒把這台加進群組 | 到監控平台確認資料點與告警路由；★★★★ 驗收時必須實際觸發一次告警確認收得到 |
| ★★★★★ 硬碟壞掉才發現**這台從沒被備份** | 備份是另一組人做的，建置時沒納管 | 立即納入備份並做還原測試；★★★★★ 把「備份首次成功 + 還原測試」列為紅線項 |
| ★★★ `sudo` 每次都卡 5～10 秒 | 改了 hostname 但 `/etc/hosts` 沒同步，sudo 解析主機名稱等 DNS timeout | 在 `/etc/hosts` 的 `127.0.1.1` 加上新的 FQDN 與短名 |
| ★★★ `hostname -f` 只回短名，憑證與郵件通知的來源名稱不對 | `/etc/hosts` 把短名寫在 FQDN 前面 | 調整順序為 `127.0.1.1 web-prd-01.example.gov.tw web-prd-01` |
| ★★★ 建置人離職後這台變成「不敢動的黑盒子」 | 沒有 build-record，決策全在腦子裡 | 補做 `/root/build-record.md` 與 `etckeeper init`；★★★★ 之後所有新機列為必要產出物 |
| ★★★ 驗收腳本在某一項就整支中斷 | `set -e` 下某個取值指令回傳非零（例如沒有 LVM 時 `vgs` 失敗） | 用 `safe()` 包裝取值、用 `if` 取代 `cond && x`；★★★ 這是 `set -e` 最常見的踩雷點 |

### 排查步驟

情境：**驗收腳本回傳退出碼 2（有紅線項失敗），要在 10 分鐘內定位。**

**【1】先看是哪幾項失敗，不要一項一項猜**

```bash
sudo /usr/local/sbin/server-build-verify | grep FAIL
```

預期輸出：

```text
  FAIL 13 密碼登入已關閉      實際=pwd=yes kbd=no 預期=password=no 且 kbdint=no
  FAIL 21 日誌轉送已設定      實際=缺轉送設定或寫入失敗
```

★★★ 看到 **13** 代表問題在 sshd 設定覆蓋順序；看到 **21** 代表問題在 rsyslog 或網路；
兩者同時出現通常是**不同原因**，要分開查。

**【2】針對 13：確認「誰贏了」**

```bash
sudo grep -rn -iE 'passwordauthentication|kbdinteractive' /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
```

預期輸出：

```text
/etc/ssh/sshd_config:58:PasswordAuthentication no
/etc/ssh/sshd_config.d/50-cloud-init.conf:1:PasswordAuthentication yes
```

★★★★ 看到 `sshd_config.d/` 底下有值，就是它贏（Include 在 sshd_config 開頭）。
★★★ 如果**只有 sshd_config 有值而 `sshd -T` 仍回 yes**，代表你改完沒 reload。

**【3】修正後先驗語法，再 reload，最後複驗**

```bash
sudo sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/' \
  /etc/ssh/sshd_config.d/50-cloud-init.conf
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -iE 'passwordauth|kbdinter'
```

預期輸出：

```text
passwordauthentication no
kbdinteractiveauthentication no
```

★★★★★ **修改 sshd 期間不要關掉現有的 SSH 連線**，並另開一個 session 複驗登入。

**【4】針對 21：先確認本機寫得進 journal**

```bash
logger -p local0.notice "PROBE-$$"; sleep 1; journalctl --since '-1 min' | grep "PROBE-$$"
```

預期輸出：

```text
Aug 28 16:02:11 web-prd-01 root: PROBE-31245
```

★★★ **有輸出**代表本機寫入正常，問題在轉送（跳到【5】）；
**沒輸出**代表 journald 有問題，先查 `systemctl status systemd-journald` 與 `/var/log` 是否寫滿。

**【5】確認轉送設定與 TCP 連通性**

```bash
grep -rn '@' /etc/rsyslog.d/ ; sudo ss -tnp | grep 6514
```

預期輸出：

```text
/etc/rsyslog.d/90-forward.conf:1:*.* @@log.example.gov.tw:6514
ESTAB 0 0 10.20.30.41:51234 10.20.1.50:6514 users:(("rsyslogd",pid=812,fd=7))
```

★★★ 看到 `ESTAB` 代表連線已建立，問題在**對端沒收到或沒索引**（找日誌平台管理員）；
沒有任何連線就是**防火牆或路由**問題（跳到【6】）。

**【6】從這台測對端的埠**

```bash
timeout 5 bash -c 'cat < /dev/null > /dev/tcp/log.example.gov.tw/6514' && echo OPEN || echo BLOCKED
```

預期輸出：

```text
BLOCKED
```

★★★★ `BLOCKED` 代表 DMZ 到日誌網段的防火牆規則沒開 ——
這通常是階段【1】的「VLAN／防火牆開通單」漏了一條，回去補開通單，**不要自己在主機上繞路**。

**【7】全部修完重跑，退出碼必須是 0**

```bash
sudo /usr/local/sbin/server-build-verify --table > /root/verify-final.md; echo "退出碼：$?"
```

預期輸出：

```text
退出碼：0
```

★★★★★ **退出碼不是 0 就不要拿去簽核。** 若確實有無法修正的項目，
必須填進交付單的「例外項目與核准依據」，並取得核准人簽名 —— 而不是把那一行從表格裡刪掉。

## 安全性注意事項

> [!danger] ★★★★★ 絕對禁止的六件事
> 1. **先關密碼登入、再測公鑰。** 順序顛倒＝把自己和所有人鎖在門外，
>    遠端機房開工單少則兩小時。★★★★★ 一定要「另開 session 實測成功」才動 sshd。
> 2. **把 `/etc` 的 etckeeper repo push 到外部或公開儲存庫。**
>    裡面有 `/etc/shadow`（密碼雜湊，可離線暴力破解）與
>    `/etc/ssh/ssh_host_ed25519_key`（★★★★★ 主機私鑰，外洩即可被中間人冒充這台主機）。
> 3. **把建置側錄 log 交給非授權者。** `script` 會忠實記錄你貼上去的**所有內容**，
>    包含臨時貼入的資料庫密碼、API token、憑證私鑰。交付前務必 `chmod 600` 並人工檢閱一次。
> 4. **為了通過驗收而修改檢查表。** ★★★★★ 把 FAIL 的那一列刪掉是**偽造稽核紀錄**，
>    在機關內屬於行政責任範疇。正確做法是填「例外項目」並取得核准。
> 5. **用 `rm` 刪除正在被寫入的日誌來救磁碟空間。** 檔案被程式開著，空間不會釋放，
>    而且★★★★ **稽核軌跡被銷毀**。用 `truncate -s 0` 或正常的 logrotate。
> 6. **在申請單之外自行開放對外埠。** 每一個對外埠都是攻擊面，
>    ★★★★ 而且沒登記的埠不會被納入弱點掃描範圍（見 [[03-弱點與修補管理流程]]）。

> [!danger] ★★★★★ 第 4 步與第 8 步最常被忘記
> **憑證沒撤銷**：機器不在了，但那張憑證還有效 ——
> 誰拿到那份私鑰就能冒充你的網域（見 [[13-憑證常見問題排查]]）。
>

> 造成「新機莫名其妙被擋」或「舊告警一直來」。

## 練習題

> [!question]- 練習 1：把一台既有的「野生機器」補做建置紀錄
> 挑一台你手上**沒有任何建置文件**的既有主機（測試機即可），在不中斷服務的前提下：
> 1. 執行 `server-build-verify`（先把腳本放上去），記錄失敗項與退出碼
> 2. 補寫 `/root/build-record.md`，把「決策紀錄」欄位盡量填滿
> 3. `etckeeper init` 並做第一次 commit
> 4. 列出你**查不到答案**的欄位（例如：這台是誰申請的？資料分類等級？）
>
> **參考解答**：
> 典型結果是驗收 23 項中失敗 5～9 項，退出碼 2，最常失敗的是
> 第 19（第三方 repo 沒有 `signed-by`，因為當年用 `apt-key add`）、
> 第 22（備份從來沒跑過）、第 23（沒有資產編號）。
>
> ★★★★ 練習的重點在第 4 步 —— **查不到的欄位就是 SOP 存在的理由**。
> 「業務負責人」與「資料分類等級」幾乎一定查不到，因為當年沒人問過。
> 這些欄位事後只能靠問人補，而問到的人通常已經換過兩輪。
>
> etckeeper 補做時注意：`etckeeper init` 之後的第一個 commit 是「現況」而不是「基準」，
> 要在 commit message 註明 `補做於 2026-08-28，此前變更無紀錄`，
> 否則三年後的人會誤以為這台從建置起就有軌跡。

> [!question]- 練習 2：設計一份 DB 主機的角色附加檢查表
> 依本篇「共通 20 項 + 角色附加項」的做法，替一台 MariaDB 主機設計 5 條附加驗收項。
> 每條要寫出：檢查項 / 是否紅線 / 驗證指令 / 預期結果。
>
> **參考解答**（可接受的版本之一）：
>
> | # | 檢查項 | 紅線 | 驗證指令 | 預期結果 |
> | --- | --- | --- | --- | --- |
> | D1 | ★★★★★ 未綁 `0.0.0.0` | 紅線 | `ss -tlnH \| grep 3306` | 只有 `127.0.0.1:3306` 或內網 IP |
> | D2 | ★★★★★ 無匿名帳號與空密碼 | 紅線 | `SELECT user,host FROM mysql.user WHERE authentication_string='';` | 0 rows |
> | D3 | ★★★★★ 邏輯備份可還原 | 紅線 | 還原 dump 到暫存 DB 並 `SELECT COUNT(*)` | 筆數與來源一致 |
> | D4 | ★★★★ 資料目錄獨立分割 | — | `findmnt -no SOURCE /var/lib/mysql` | 有獨立裝置 |
> | D5 | ★★★ 慢查詢日誌開啟 | — | `SHOW VARIABLES LIKE 'slow_query_log';` | `ON` |
>
> ★★★★ 評分重點在 **D3**。很多人會寫「備份排程存在」——
> 那不是驗收，那只是「設定過」。DB 主機的還原測試必須做到**比對筆數**，
> 因為 `mysqldump` 在權限不足時會**產生一個語法正確但內容不完整的檔案而不報錯**。
>
> ★★★ 另一個常見錯誤是把 D1 寫成「防火牆有擋 3306」。
> 防火牆規則會被人改，綁定位址不會 —— **深度防禦要求兩者都做**，但驗收要驗較底層的那個。

> [!question]- 練習 3：判斷這五個「例外申請」該不該核准
> 交付單上出現以下五個例外項，你是覆核人，逐一判斷「核准／退回」並寫理由：
> 1. 「第 13 項未通過：廠商維護需要密碼登入，請保留 PasswordAuthentication yes」
> 2. 「第 07 項未通過：`/var/log` 未獨立分割，因磁碟只有 40G」
> 3. 「第 22 項未通過：備份系統本週維護中，下週補做」
> 4. 「第 18 項未通過：自動更新關閉，因應用程式對套件版本敏感」
> 5. 「第 05 項未通過：NTP 未同步，因本機在隔離網段無法連外」
>
> **參考解答**：
> 1. ★★★★★ **退回**。紅線項。廠商需求應改為「配發廠商專用帳號 + 公鑰 + 限來源 IP +
>    到期自動停用」，而不是為單一廠商全域開放密碼登入。這是把整台機器的攻擊面
>    換取一個廠商的方便。
> 2. ★★★ **可核准，但須加補償措施**：logrotate 縮短保留天數 +
>    監控 `/` 使用率 80% 告警，並在 build-record 記錄「磁碟擴充為既定改善項」。
>    這一項非紅線，且成因是硬體限制而非疏忽。
> 3. ★★★★★ **退回**。紅線項，且理由是「時程」不是「技術限制」。
>    正確做法是**延後交付日期**，而不是先交付再補 ——
>    「下週補做」在實務上有極高機率變成「永遠沒做」。
> 4. ★★★ **可核准**，但須改為「自動下載不自動安裝 + 每月人工套用 + 指定負責人與時限」，
>    並納入 [[03-弱點與修補管理流程]] 的例外追蹤清單。單純關掉不追蹤則退回。
> 5. ★★★★ **有條件核准**：隔離網段應**架設內部 NTP server**（可由網域控制站或防火牆提供）。
>    若確實無任何時間來源，須在交付單載明「本機日誌時間不具跨系統關聯效力」，
>    並取得資安承辦與單位主管雙簽 —— 因為這直接影響稽核證據力。

## 小測驗

Q1. 為什麼「先關閉 `PasswordAuthentication`、再測試公鑰登入」是嚴重錯誤？正確順序是什麼？

Q2. 在 Ubuntu 24.04 上，你已經把 `/etc/ssh/sshd_config` 的 `PasswordAuthentication` 改成 `no` 並 reload 了 sshd，但 `sshd -T` 仍然顯示 `passwordauthentication yes`。原因是什麼？

Q3. （是非題）「監控 agent 的 systemd 服務顯示 `active`」就代表監控納管驗收通過。

Q4. 這行指令會發生什麼事？為什麼在磁碟寫滿的救援情境要用它而不是 `rm`？
```
sudo truncate -s 0 /var/log/app/debug.log
```

Q5. 為什麼時區與 NTP 必須在「納管」之前完成？舉出兩個會因此失效的機制。

Q6. 主機名稱為什麼不能用底線（`web_prd_01`）？至少說出一個會實際壞掉的地方。

Q7. 驗收腳本裡為什麼要寫成 `if [[ "$red" == "紅線" ]]; then RED_FAILED=$((RED_FAILED+1)); fi`，而不是更短的 `[[ "$red" == "紅線" ]] && RED_FAILED=$((RED_FAILED+1))`？

Q8. 一台 200 GiB 的伺服器，LVM 全部配發完（VFree = 0）。三個月後 `/var/log` 滿了。此時你能做什麼、不能做什麼？

Q9. 交付單上「例外項目與核准依據」欄位存在的意義是什麼？為什麼不能直接把未通過的那一列從檢查表刪掉？

Q10. 除役流程中，「憑證撤銷」與「IP 回收」各自漏掉會造成什麼具體後果？

> [!question]- 測驗答案
> **Q1.** ★★★★★ 因為公鑰登入有太多會靜默失敗的地方：`~/.ssh` 權限不是 700、
> `authorized_keys` 不是 600、公鑰貼進了錯的使用者家目錄、複製時被編輯器加了換行。
> 這些情況 sshd **不會給你任何錯誤訊息**，只會拒絕連線。
> 一旦密碼登入已經關掉，你就完全沒有備援路徑，只能去機房或開虛擬化平台的 console。
> 正確順序是：建帳號 → 加 sudo → 部署公鑰 →
> ★★★★★ **另開一個新 session 實測 `ssh user@host 'id && sudo -n true'` 成功**
> （原本的 session 絕對不關）→ 才停用 root 與密碼登入 → `sshd -t` → `reload` → 開第三個 session 複驗。
> 見〈進階設定與調校〉的「帳號初始化的順序」。
>
> **Q2.** ★★★★★ 因為 `/etc/ssh/sshd_config` 開頭有 `Include /etc/ssh/sshd_config.d/*.conf`，
> 而 Ubuntu 24.04 從 ISO 安裝會產生 `50-cloud-init.conf`，裡面寫著 `PasswordAuthentication yes`。
> **sshd 的規則是「第一個出現的設定值獲勝」**，Include 在檔案開頭，所以 50 那個檔先被讀到、它贏。
> ```bash
> sudo grep -rn -i passwordauth /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
> ```
> 修法：改 `50-cloud-init.conf`，或新增排序更前的 `10-hardening.conf`。
> ★★★★ 通則是：**永遠以 `sshd -T` 的輸出為準，不要相信你剛編輯的那個檔案**。
> 這也是驗收腳本第 12、13 項檢查 `sshd -T` 而不是 grep 設定檔的原因。
> 見〈進階設定與調校〉的 `50-cloud-init.conf` 陷阱。
>
> **Q3.** ★★★★ **錯。** `active` 只證明「程序在跑」，不證明「監控有效」。
> 真正的驗收要滿足三件事：
> ① 監控平台上**看得到這台的最新資料點**（時間差 < 5 分鐘，證明資料真的送到了）；
> ② 這台被加進了正確的**主機群組與告警規則**（不然有資料也不會告警）；
> ③ ★★★★ **實際觸發一次告警，確認通知送到申請單上填的那個人手上**。
> 常見失敗是 agent 跑得好好的，但防火牆擋了 9100，或平台端根本沒把這台加進 targets。
> 「機器掛了三天沒人知道」的災難，多半發生在 agent 顯示 `active` 的機器上。
> 見〈進階設定與調校〉的「納管四件事」。
>
> **Q4.** 這行把檔案內容截斷成 0 位元組，但**保留 inode 與已開啟的檔案描述子**。
> 因為 Linux 只有在「檔案沒有目錄項 **且** 沒有任何程序開著它」時才釋放空間，
> ★★★★ 用 `rm` 刪掉一個程式正在寫的日誌檔，**磁碟空間完全不會釋放**——
> `df` 還是 100%，但 `du` 找不到那個檔，你會查到懷疑人生，
> 而且要等到那支程式重啟或關閉檔案才會釋放。
> `truncate -s 0` 則是立刻釋放，程式繼續寫也不會出錯（只是 offset 會造成稀疏檔）。
> ★★★★ 但兩者都會**銷毀稽核軌跡**，救援前應先確認那段日誌已轉送到集中平台。
> 見〈常見錯誤與排錯〉第 3 列。
>
> **Q5.** ★★★★ 因為納管的那一刻起，這台機器的**時間戳就變成證據**，
> 而**已經送出去的日誌無法回溯修正** —— 那段期間等於沒有紀錄。
> 會失效的機制（任選兩個）：
> ① **SIEM 事件關聯**：這台的登入事件比防火牆事件早 8 小時，關聯規則永遠不觸發；
> ② **Kerberos／加入 AD 網域**：時間差超過預設 5 分鐘容忍值直接拒絕認證，
>    錯誤訊息是 `Clock skew too great`；
> ③ **憑證驗證**：時間跑到 `notBefore` 之前會出現 `certificate is not yet valid`；
> ④ ★★★★★ **稽核證據力**：時間不可信的日誌，在資安事件調查與外部稽核時等同沒有日誌。
> 三件事是：`set-timezone Asia/Taipei`、NTP 同步（`NTPSynchronized=yes`）、`set-local-rtc 0`。
> 見〈基礎設定〉的時間三件事。
>
> **Q6.** ★★★ 因為 RFC 1123 的主機名稱只允許 `a-z`、`0-9`、`-`，底線不合法。
> 實際會壞掉的地方（任一即可）：
> ① **TLS SNI 比對**：部分 TLS 函式庫會拒絕含底線的名稱，導致 HTTPS 交握失敗；
> ② **HTTP 中介與反向代理**：某些 proxy 對含底線的 Host 標頭直接回 400；
> ③ **DNS 解析器**：嚴格模式的解析器（含部分企業 DNS）拒絕查詢；
> ④ **憑證簽發**：公信 CA 不會替含底線的名稱簽發憑證。
> ★★★ 而且這個錯誤的代價很不對稱：建置時改名成本 30 秒，
> 上線後改名要動 DNS、憑證、監控標籤、日誌來源、防火牆規則、AD 電腦帳戶。
> 見〈環境準備與安裝〉的命名規範。
>
> **Q7.** ★★★★ 因為腳本用了 `set -e`。
> `cond && cmd` 這個複合指令在 `cond` 為假時，**整個複合指令的退出碼是非零**；
> 如果它剛好是**函式的最後一行**，函式就以非零結束，
> 在 `set -e` 下會讓呼叫端整支腳本**當場中斷**。
> 症狀是：驗收跑到某個非紅線項的 FAIL 就無聲無息停住，後面的檢查全都沒跑。
> ★★★ 這是 `set -e` 最常見的踩雷點。安全寫法有三種：
> 用 `if ... fi`（本篇採用）、寫成 `cond && cmd || true`、或把該行移到函式中間而非最後。
> 同理，腳本裡所有「取值可能失敗」的指令都用 `safe()` 包成 `"$@" 2>/dev/null || echo "N/A"`。
> 見〈常見錯誤與排錯〉最後一列與驗收腳本的 `record()`。
>
> **Q8.** ★★★★ **不能做**的是「線上擴充」——VG 沒有空間，`lvextend` 會直接失敗：
> ```text
> Insufficient free space: 5120 extents needed, but only 0 available
> ```
> **能做**的（由輕到重）：
> ① 立即：`truncate -s 0` 最大的日誌檔爭取時間（先確認已轉送到集中平台）；
> ② 短期：調整 logrotate 縮短保留天數、開啟壓縮；
> ③ 中期：加一顆新磁碟 → `pvcreate` → `vgextend` → `lvextend`
>    （★★★ VM 上加磁碟通常不需停機，實體機要看熱插拔支援）；
> ④ 最後手段：關機擴大虛擬磁碟再擴 PV（服務中斷）。
> ★★★★★ 這題的真正答案是「當初就該留 20% 白」——
> 選項 ③ 需要走變更管理排維護時段，選項 ④ 直接就是服務中斷。
> 見〈環境準備與安裝〉的分割決策準則。
>
> **Q9.** ★★★★★ 例外欄位的意義是：把「未達標準」這件事從**技術問題**轉成
> **有人負責的管理決定**。它記錄了三件事——未通過什麼、補償措施是什麼、誰在什麼時候核准的。
> 三年後出事時，這一欄是唯一能回答「當初為什麼這樣放行」的東西。
> 直接刪掉那一列的問題有三個：
> ① ★★★★★ 那是**偽造稽核紀錄**，在機關內屬行政責任範疇；
> ② 覆核人與主管在不知情的狀況下簽了名，責任被轉嫁給他們；
> ③ 這個缺口從此**不存在於任何清單上**，永遠不會被追蹤、不會被修。
> ★★★★ 對照練習 3：例外可以核准（如磁碟不足未分割 `/var/log`），
> 但紅線項（如保留密碼登入、備份未做）一律退回，理由是「時程」的更要退回。
> 見〈完整實戰範例〉的簽核欄位與〈安全性注意事項〉。
>
> **Q10.** ★★★★★ **憑證沒撤銷**：機器已經不在了，但那張憑證在有效期內仍然被
> 所有瀏覽器與用戶端視為有效。任何人拿到那份私鑰（舊硬碟、舊備份、舊快照）
> 就能架一台伺服器**冒充你的網域**，做中間人攻擊而不會有任何憑證警告。
> 撤銷方式是通知 CA 進 CRL / OCSP，並驗證：
> ```bash
> openssl ocsp -issuer chain.pem -cert old.crt -url http://ocsp.ca.example -resp_text
> ```
> 應看到 `Cert Status: revoked`。
> ★★★★ **IP 沒回收**：半年後新機被配到同一個 IP，卻繼承了舊機殘留的
> 防火牆規則、監控 target、日誌來源對應與 DNS 記錄，症狀是
> 「新機莫名其妙被防火牆擋」「舊主機的告警一直來」「日誌被歸到錯的主機」，
> 而且這類問題極難查，因為沒人會想到是半年前的除役沒做完。
> 見〈安全性注意事項〉的除役表第 4、8 項。
