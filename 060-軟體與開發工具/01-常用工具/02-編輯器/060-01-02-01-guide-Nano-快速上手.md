## 觀念說明

```
★★ 為什麼維運人員一定要會一個終端機編輯器？

  · SSH 進伺服器改設定檔 → 沒有 GUI
  · 系統壞掉進救援模式 → 只有文字介面
  · 容器裡面 → 通常只有最小環境

★★ 兩個主要選擇：

  nano  ★ 好上手，快捷鍵直接顯示在畫面下方
        → 改個設定檔、寫個小腳本，五分鐘就會用
        → ★★ 這篇的主題

  vim   ★★ 功能強大，但要學一段時間
        → 幾乎所有系統都有（★ 救援模式常常只有 vi）
        → 見 [[060-01-02-02-cmd-Vim-基礎操作]]

★★★ 建議：兩個都要會一點
  · 日常改設定 → nano（快）
  · 系統救援 / 只有 vi 的環境 → vim（★ 一定要會離開！）
```

### 畫面組成

```
$ nano /etc/nginx/nginx.conf

  GNU nano 7.2            /etc/nginx/nginx.conf              ← ① 標題列
                                                                （檔名、是否修改過）
user www-data;
worker_processes auto;                                       ← ② 編輯區
pid /run/nginx.pid;

[ Read 87 lines ]                                            ← ③ 狀態列（訊息）

^G Help     ^O Write Out  ^W Where Is   ^K Cut               ← ④ 快捷鍵列
^X Exit     ^R Read File  ^\ Replace    ^U Paste                （★ 隨時看得到）
```

> [!note] `^` 與 `M-` 的意思 ★★
> ```
> ★★ nano 的說明用兩種表示法：
>
>   ^X   = Ctrl + X          （★ 「^」就是 Ctrl）
>   ^O   = Ctrl + O
>
>   M-U  = Alt + U           （★ 「M-」是 Meta 鍵 = 大多數鍵盤的 Alt）
>          → ★ Mac 上通常是 Esc 然後按 U
>          → ★ 有些終端機要設定「Alt 當作 Meta」才生效
>
> ★★ 注意大小寫：文件寫 ^O 但你【不用按 Shift】
>   → 直接 Ctrl + o 就可以
> ```

## 安裝與基礎操作

### 安裝

```bash
# ★ Ubuntu / Debian（通常已內建）
$ sudo apt install -y nano
$ nano --version
 GNU nano, version 7.2
```

> [!info]- Rocky / AlmaLinux（RHEL 系）對照
> ```bash
> $ sudo dnf install -y nano
>
> # ★★ RHEL 系的最小安裝【可能沒有 nano】，只有 vi
> #   → 這也是為什麼要學一點 vim
> ```

### 開檔

```bash
$ nano notes.txt                # 開檔（不存在就是新檔）
$ nano +25 /etc/nginx/nginx.conf   # ★ 直接跳到第 25 行
$ nano +/worker_processes f.conf   # ★ 跳到第一個符合的位置
$ sudo nano /etc/hosts          # ★ 系統檔案要 sudo
$ nano -v /var/log/syslog       # ★ 唯讀模式（★ 看大檔案時避免誤改）
```

### ★★★ 最重要的三個鍵

| 鍵 | 作用 | 說明 |
| --- | --- | --- |
| **`Ctrl+O`** | **存檔** | Write **O**ut ★ 按完要按 **Enter** 確認檔名 |
| **`Ctrl+X`** | **離開** | 有未存的變更會問你要不要存 |
| **`Ctrl+G`** | 說明 | 完整的快捷鍵清單 |

```
★★★ 存檔離開的完整流程：

  ① 改完內容
  ② Ctrl + O           → 下方出現「File Name to Write: notes.txt」
  ③ Enter              → ★★ 這一步很多人漏掉！
                          顯示「[ Wrote 12 lines ]」才是真的存好
  ④ Ctrl + X           → 離開

★ 或是直接 Ctrl + X：
  → 問「Save modified buffer?」
  → 按 Y → 問檔名 → Enter → 存好並離開
  → 按 N → ★★ 不存檔直接離開（★ 改壞了想放棄時用這個）
  → 按 Ctrl + C → 取消，回到編輯
```

> [!warning] 三個新手最常卡住的地方 ★★
> ```
> ① ★★★ 按了 Ctrl+O 之後沒按 Enter
>    → 檔案【沒有存到】
>    → ★ 一定要看到「[ Wrote N lines ]」
>
> ② ★★ Ctrl+S 沒反應 / 終端機卡住
>    → ★★★ Ctrl+S 是終端機的「暫停輸出」（XOFF）
>    → 畫面會像當掉一樣
>    → ★ 解法：按 Ctrl + Q 解除
>    → ★ nano 2.6+ 其實有支援 Ctrl+S 存檔，但終端機可能先攔截
>
> ③ ★★ Ctrl+Z 把 nano 丟到背景
>    → ★ 用 fg 叫回來
>    → ★ 或在 nanorc 加 set nozap（新版）／用 -z 停用
> ```

### 移動游標

| 鍵 | 作用 |
| --- | --- |
| `↑ ↓ ← →` | 上下左右 |
| `Ctrl+A` / `Home` | 行首 |
| `Ctrl+E` / `End` | 行尾 |
| `Ctrl+Y` / `PgUp` | 上一頁 |
| `Ctrl+V` / `PgDn` | 下一頁 |
| **`Alt+\`** | **檔案開頭** |
| **`Alt+/`** | **檔案結尾** |
| **`Ctrl+_`**（或 `Alt+G`） | **★ 跳到指定行**（輸入行號） |
| `Ctrl+Space` | 下一個字 |
| `Alt+Space` | 上一個字 |
| **`Alt+U`** | **★★ 復原**（undo） |
| **`Alt+E`** | **★★ 重做**（redo） |

```
★★ Ctrl+_ 跳行是排錯的關鍵技巧：

$ sudo nginx -t
nginx: [emerg] unknown directive "prox_pass" in /etc/nginx/sites-enabled/app:24

$ sudo nano +24 /etc/nginx/sites-enabled/app     # ★ 直接跳到第 24 行
  → 或開啟後按 Ctrl+_ 輸入 24
```

## 進階應用

### 搜尋與取代

```
★★ Ctrl+W  搜尋（Where Is）
  → 輸入關鍵字 → Enter
  → ★ Alt+W 找下一個
  → ★ 在搜尋提示下按 Alt+C 切換「區分大小寫」
  → ★ 按 Alt+R 切換「正規表示式模式」

★★ Ctrl+\  取代（Replace）
  → 輸入要找的字 → Enter
  → 輸入要換成的字 → Enter
  → 每一處問你：
      Y  = 換這個
      N  = 跳過
      ★ A = 全部換（All）
      Ctrl+C = 取消
```

```
★★ 實例：把設定檔裡所有 8080 換成 3000

  Ctrl + \
  Search (to replace): 8080          [Enter]
  Replace with: 3000                 [Enter]
  Replace this instance? A           ← ★ 全換
  [ Replaced 4 occurrences ]
```

> [!tip] 正規表示式取代 ★★
> ```
> ★ 先按 Ctrl+\，再按 Alt+R 開啟 regex 模式
>   （狀態列會出現 [Regexp]）
>
> ★ 例：把所有註解行前面多加一個 #
>   Search:  ^#
>   Replace: ##
>
> ★★ 但複雜的取代建議用 sed（見 [[020-01-12-cmd-Linux-文字處理三劍客]]）
>   → nano 的 regex 功能有限
> ```

### 複製、剪下、貼上

| 鍵 | 作用 |
| --- | --- |
| **`Ctrl+K`** | **剪下整行**（連續按可剪多行） |
| **`Ctrl+U`** | **貼上** |
| **`Alt+6`** | **★ 複製整行**（不刪除） |
| `Ctrl+^`（`Alt+A`） | 開始選取（Mark） |
| `Alt+3` | ★ 註解 / 取消註解選取的行 |
| `Alt+}` / `Alt+{` | ★ 縮排 / 反縮排選取的行 |

```
★★★ 選取一段再操作的流程：

  ① 游標移到起點
  ② Ctrl + ^          → 狀態列顯示「Mark Set」
  ③ 移動游標到終點     → 選取的部分反白
  ④ Ctrl+K 剪下  或  Alt+6 複製
  ⑤ 移到目標位置 → Ctrl+U 貼上

★★ 取消選取：再按一次 Ctrl+^
```

> [!warning] nano 的剪貼簿與系統剪貼簿是分開的 ★★
> ```
> ★★ Ctrl+K / Ctrl+U 用的是【nano 內部的緩衝區】
>   → 貼不到瀏覽器、貼不到其他視窗
>
> ★★ 要跨程式複製：
>   · 用【終端機本身】的複製貼上
>     → 通常是 Ctrl+Shift+C / Ctrl+Shift+V
>     → ★ Windows Terminal / WSL 是滑鼠選取即複製、右鍵貼上
>   · ★★ 貼進 nano 時注意【自動縮排】會讓格式跑掉
>     → 見下方「貼上 YAML 跑掉」
> ```

### ★★★ 貼上 YAML / Python 格式跑掉

```
★★★ 現象：從網頁複製一段 YAML 貼進 nano，縮排變成階梯狀

services:
  web:
    image: nginx
      ports:              ← ★★ 每行多縮排一次
        - "80:80"

★★ 原因：nano 的【自動縮排（autoindent）】把每一行的縮排疊加上去
  → 終端機的貼上等同於「逐字輸入」
  → nano 以為你在打字，自動幫你縮排

★★★ 三個解法：

  ① ★ 貼上前按 Alt+I 關掉自動縮排（再按一次開啟）
     → 狀態列會顯示 Auto-indent disabled

  ② ★★ 用「括號貼上模式」（bracketed paste）
     → nano 5.7+ 預設支援，會自動偵測貼上並停用 autoindent
     → ★ 舊版沒有，要用 ①

  ③ ★★★ 根本解法：不要用貼上，用 heredoc 或 scp
     $ cat > docker-compose.yml <<'EOF'
     services:
       web:
         image: nginx
     EOF
     → ★ 'EOF' 加單引號 = 不做變數展開（★ 原樣寫入）
```

### 多檔案編輯

```bash
$ nano file1.conf file2.conf file3.conf

# ★★ 在 nano 內切換：
#   Alt + >   下一個檔案
#   Alt + <   上一個檔案
#   ★ 狀態列會顯示 [ Switched to file2.conf ]

# ★ Ctrl+R 讀入另一個檔案的內容到目前位置
#   → 在提示下按 Alt+F 可改成「開成新的緩衝區」
```

## ★★★ 改設定檔的三個保命習慣

```
★★★★ 這三件事會救你很多次：

  ① 【先備份】
     $ sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.$(date +%F-%H%M)
     → ★ 加時間戳，不會覆蓋掉上一次的備份

  ② 【存檔後立刻驗證語法】
     $ sudo nginx -t              # nginx
     $ sudo sshd -t               # sshd
     $ sudo visudo -c             # sudoers
     $ php -l script.php          # PHP
     $ python3 -c 'import yaml,sys; yaml.safe_load(open("f.yml"))'   # YAML
     $ jq . f.json >/dev/null     # JSON
     → ★★★ 驗證過才 reload / restart

  ③ 【改 SSH 設定時保留一個連線】
     → ★★★★ 改 sshd_config 前，【開第二個 SSH 連線並保持登入】
     → 改完 restart 後用第二個視窗測試能不能新連線
     → 進不去的話，原本那個連線還在，可以改回來
     → ★ 否則把自己鎖在門外，只能去機房或用 console
```

```bash
# ★★ 改 sudoers 一定要用 visudo（不要直接 nano）
$ sudo visudo                    # ★ 離開時會【自動檢查語法】
$ sudo visudo -f /etc/sudoers.d/deploy    # ★ 編輯附加檔

# ★ 讓 visudo 用 nano（預設可能是 vi）
$ sudo EDITOR=nano visudo
$ sudo update-alternatives --config editor    # ★ Debian/Ubuntu 永久設定
```

> [!danger] 為什麼 sudoers 一定要 visudo ★★★★
> ```
> ★★★★ /etc/sudoers 寫錯 = 【所有人都不能用 sudo】
>   → 包括你自己
>   → 沒有 root 密碼的話（Ubuntu 預設就沒有）
>     → ★ 只能重開機進 recovery mode 修
>
> ★★ visudo 會：
>   ① 鎖定檔案（避免兩個人同時改）
>   ② ★★★ 離開時檢查語法，有錯會問你要不要回去改
>
> ★★ 已經改壞了的緊急處理：
>   · 有其他 root shell 開著 → 直接改回來
>   · pkexec visudo（如果有 polkit）
>   · ★ 重開機 → GRUB 選 recovery → root shell → 改
> ```

## 完整實戰範例：安全地修改 SSH 設定

```bash
# ═══ ★★★【0】先開第二個 SSH 連線並保持登入 ═══
#   （在另一個終端機視窗）
$ ssh admin@server.example.gov.tw
#   ★★★★ 這個視窗【不要關】

# ═══【1】備份 ═══
$ sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.$(date +%F-%H%M)
$ ls -l /etc/ssh/sshd_config*
-rw------- 1 root root 3264 Aug 28 14:30 /etc/ssh/sshd_config
-rw------- 1 root root 3264 Aug 28 14:32 /etc/ssh/sshd_config.2026-08-28-1432

# ═══【2】編輯 ═══
$ sudo nano /etc/ssh/sshd_config

#   ★ Ctrl+W 搜尋 PermitRootLogin  → Enter
#   ★ 修改成：
#       PermitRootLogin no
#       PasswordAuthentication no
#       MaxAuthTries 3
#   ★ Ctrl+O → Enter → 看到 [ Wrote 128 lines ]
#   ★ Ctrl+X 離開

# ═══ ★★★【3】驗證語法（★ 這一步不能跳）═══
$ sudo sshd -t
$ echo $?
0                                    # ★ 0 = 語法正確

#   ★ 有錯的話會這樣：
#   /etc/ssh/sshd_config: line 34: Bad configuration option: PermitRootLgin
#   → ★ 回去改，不要 restart

# ═══【4】看看實際生效的設定 ═══
$ sudo sshd -T | grep -Ei 'permitrootlogin|passwordauth|maxauthtries'
permitrootlogin no
passwordauthentication no
maxauthtries 3
#   ★★ sshd -T 顯示【合併所有設定後】的最終值
#      → 包含 /etc/ssh/sshd_config.d/*.conf
#      → ★★★ Ubuntu 22.04+ 有這個目錄，可能覆蓋你改的值！

# ═══【5】重啟 ═══
$ sudo systemctl restart ssh          # Ubuntu 24.04+ 是 ssh
$ sudo systemctl status ssh --no-pager | head -5

# ═══ ★★★【6】用第三個視窗測試新連線 ═══
$ ssh admin@server.example.gov.tw 'echo OK'
OK                                    # ★ 成功

#   ★★★ 失敗的話：回到【步驟 0 保留的那個連線】
$ sudo cp /etc/ssh/sshd_config.2026-08-28-1432 /etc/ssh/sshd_config
$ sudo sshd -t && sudo systemctl restart ssh

# ═══【7】確認沒問題後才關掉保留的連線 ═══
```

> [!danger] Ubuntu 22.04+ 的 `sshd_config.d` 陷阱 ★★★
> ```bash
> $ head -3 /etc/ssh/sshd_config
> Include /etc/ssh/sshd_config.d/*.conf     # ★★★ 在檔案【最上面】
>
> $ ls /etc/ssh/sshd_config.d/
> 50-cloud-init.conf
>
> $ cat /etc/ssh/sshd_config.d/50-cloud-init.conf
> PasswordAuthentication yes                # ★★★★ 覆蓋了你的設定！
>
> ★★★ SSH 的規則是【第一個出現的值生效】
>   → Include 在最上面 → sshd_config.d 的值【優先】
>   → ★ 你在主檔改的 PasswordAuthentication no 【完全沒作用】
>
> ★★ 正確做法：
>   ① 改 /etc/ssh/sshd_config.d/ 裡的檔案，或
>   ② 建一個排序更前面的：/etc/ssh/sshd_config.d/00-hardening.conf
>   ③ ★★★ 一律用 sshd -T 確認最終值
> ```

## nanorc 設定 ★★

```bash
# ★ 個人設定
$ nano ~/.nanorc

# ★ 全系統設定
$ sudo nano /etc/nanorc
```

```ini
# ~/.nanorc —— 實用設定

# ═══ ★★ 顯示 ═══
set linenumbers              # ★★ 顯示行號（★ 排錯必備）
set constantshow             # ★ 隨時顯示游標位置
set titlecolor brightwhite,blue
set numbercolor cyan
set selectedcolor brightwhite,magenta

# ═══ ★★ 編輯行為 ═══
set tabsize 4                # Tab 寬度
set tabstospaces             # ★★ Tab 轉成空白（★ YAML/Python 必開）
set autoindent               # ★ 自動縮排（★ 貼上時用 Alt+I 暫時關掉）
set smarthome                # ★ Home 先跳到第一個非空白字元
set softwrap                 # ★ 長行自動折行顯示（不改變檔案內容）
set nowrap                   # ★★ 不要自動【插入】斷行（★ 設定檔一定要開）
set mouse                    # ★ 滑鼠可以移動游標（★ 但會影響終端機選取）

# ═══ ★★ 搜尋 ═══
set casesensitive            # 搜尋區分大小寫
set historylog               # ★ 記住搜尋歷史
set positionlog              # ★★ 記住上次離開的游標位置

# ═══ ★★ 備份 ═══
set backup                   # ★ 存檔時建立 filename~ 備份
set backupdir "~/.cache/nano-backups"    # ★ 備份放這裡（★ 要先 mkdir）

# ═══ ★★★ 語法高亮 ═══
include "/usr/share/nano/*.nanorc"
# ★ Ubuntu 額外的語法定義
include "/usr/share/nano-syntax-highlighting/*.nanorc"
```

```bash
# ★ 建立備份目錄
$ mkdir -p ~/.cache/nano-backups

# ★★ 安裝更多語法高亮（Ubuntu）
$ sudo apt install -y nano       # ★ 內建的已在 /usr/share/nano/
$ ls /usr/share/nano/ | head
nginx.nanorc  php.nanorc  python.nanorc  sh.nanorc  yaml.nanorc ...

# ★★ 第三方的完整語法集
$ git clone https://github.com/scopatz/nanorc.git ~/.nano
$ echo 'include "~/.nano/*.nanorc"' >> ~/.nanorc
```

> [!tip] `set nowrap` 為什麼重要 ★★★
> ```
> ★★★ nano 舊版預設會【自動在第 N 欄插入換行】（hard wrap）
>   → ★★★★ 改設定檔時這會【破壞檔案】
>     例如一行很長的 nginx proxy_set_header 被折成兩行 → 語法錯誤
>
> ★★ 兩個容易搞混的設定：
>   set nowrap    → ★★★ 不【插入】換行字元（★ 改檔案時必開）
>                    ★ nano 2.7+ 已改為預設不折行
>   set softwrap  → ★ 只是【顯示上】折行，不改變檔案內容
>                    → ★ 這個可以開，很方便
>
> ★ 命令列臨時指定：
>   $ nano -w /etc/nginx/nginx.conf     # -w = nowrap
> ```

## ★★★ sudoedit 與 sudo nano 的差別

```bash
# ★ 方法一：sudo nano
$ sudo nano /etc/nginx/nginx.conf
#   → ★★ 以【root 身分】執行 nano
#   → ★★★ nano 的所有功能都是 root 權限
#     · Ctrl+R 可以讀任何檔案
#     · ★★★★ Ctrl+T 可以【叫出 shell】→ root shell！
#     · 讀取的是 root 的 ~/.nanorc

# ★★★ 方法二：sudoedit（推薦）
$ sudo -e /etc/nginx/nginx.conf
$ sudoedit /etc/nginx/nginx.conf         # ★ 同一件事
#   → ★★★ 流程：
#     ① 用 root 權限【複製】檔案到 /tmp
#     ② 用【你自己的身分】開編輯器編輯那個副本
#     ③ 存檔離開後，用 root 權限【複製回去】
#   → ★★ 編輯器【不是 root】→ 逃逸出去也只是你自己的權限
```

```bash
# ★★ sudoedit 要指定編輯器
$ export SUDO_EDITOR=nano                    # ★ 優先度最高
$ export EDITOR=nano
$ sudoedit /etc/hosts

# ★ 寫進 ~/.bashrc
$ echo 'export SUDO_EDITOR=nano' >> ~/.bashrc

# ★★ sudoers 中授權 sudoedit（★ 比給 nano 安全太多）
$ sudo visudo -f /etc/sudoers.d/webadmin
webadmin ALL=(root) NOPASSWD: sudoedit /etc/nginx/*
#   ★★★ 不要寫：
#   webadmin ALL=(root) NOPASSWD: /usr/bin/nano /etc/nginx/*
#   → ★★★★ 使用者可以在 nano 裡按 Ctrl+T 開 root shell
#     → 等同於給了完整的 root
```

> [!danger] 把編輯器放進 sudoers 等於給 root ★★★★
> ```
> ★★★★ 這是一個經典的權限提升漏洞：
>
>   webadmin ALL=(root) NOPASSWD: /usr/bin/vim /etc/nginx/nginx.conf
>
> ★★ 攻擊方式（vim）：
>   $ sudo vim /etc/nginx/nginx.conf
>   :!/bin/bash                    ← ★★★★ 直接開 root shell
>   # id
>   uid=0(root) ...
>
> ★★ nano 也一樣：
>   Ctrl+T（檔案瀏覽器）或 Ctrl+R 然後 Ctrl+X 執行指令
>   → ★ 視版本與 set locking 設定而異，但【不能假設安全】
>
> ★★★ less、more、find、awk、tar 都有類似問題
>   → ★ 參考 GTFOBins（https://gtfobins.github.io）
>
> ★★★★ 正確做法：
>   ① 用 sudoedit（★ 這就是它存在的理由）
>   ② 或包一層【專用腳本】，腳本只做該做的事
> ```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| **改了但檔案沒變** ★★★ | `Ctrl+O` 後沒按 Enter | 看到 `[ Wrote N lines ]` 才算存好 |
| **`Ctrl+S` 後畫面卡住** ★★ | 終端機的 XOFF 流量控制 | **`Ctrl+Q`** 解除 |
| **貼上的 YAML 縮排跑掉** ★★★ | autoindent 疊加 | 貼上前 **`Alt+I`**；或用 heredoc |
| **`Permission denied` 存不了** ★★ | 沒有寫入權限 | `sudo nano` 或 `sudoedit`；存成別的檔名再 `sudo mv` |
| **長行被切成兩行** ★★★ | 舊版的 hard wrap | `nano -w` 或 `set nowrap` |
| **游標亂跳 / 選不到字** ★ | `set mouse` 開著 | 關掉 mouse；或按住 Shift 用終端機選取 |
| **中文顯示成亂碼** ★★ | locale 不對 | `sudo locale-gen zh_TW.UTF-8`；`export LANG=zh_TW.UTF-8` |
| **`Ctrl+Z` 後不見了** ★ | 丟到背景 | `fg` 叫回來 |
| **檔案變成 `filename~`** ★ | `set backup` | 正常，那是備份檔 |
| **設定檔有 `^M`** ★★ | Windows 換行（CRLF） | `dos2unix f.conf`；nano 狀態列會顯示 `[DOS Format]` |
| **`nano: command not found`** ★★ | RHEL 最小安裝 | `dnf install nano`；或用 `vi` |

## 安全性注意事項

> [!danger] 四個要點 ★★★
> ```
> ① ★★★★ 不要把 nano/vim 直接寫進 sudoers
>      → 使用者可以從編輯器逃逸出 root shell
>      → ★ 用 sudoedit
>
> ② ★★★ 改關鍵設定前一定要備份 + 保留連線
>      → sshd_config、sudoers、fstab、網路設定
>      → ★ 這四個改壞了都可能讓你進不去機器
>
> ③ ★★ nano 的備份檔可能含敏感資料
>      → set backup 會產生 filename~
>      → ★★ 編輯 .env、私鑰時要注意
>      → ★ 備份目錄設在 ~/.cache 並確認權限 700
>
> ④ ★★ 編輯 .env / 私鑰後檢查權限
>      $ ls -l .env
>      -rw-r--r--     ← ★★★ 錯！其他人讀得到
>      $ chmod 640 .env && chown deploy:www-data .env
>      → ★★ 有些編輯器存檔時會【重建檔案】導致權限重置
> ```

```bash
# ★★ 編輯敏感檔案時停用備份與歷史
$ nano -I --nonewlines /path/to/.env    # ★ -I 忽略 nanorc（不會有 backup）

# ★★ 確認沒有留下備份
$ ls -la ~/.cache/nano-backups/ 2>/dev/null
$ find / -name '*~' -newermt '-1 hour' 2>/dev/null | head

# ★★★ 編輯私鑰後檢查
$ ls -l ~/.ssh/id_ed25519
-rw------- 1 admin admin 411 Aug 28 15:00 /home/admin/.ssh/id_ed25519   # ★ 600 正確
$ chmod 600 ~/.ssh/id_ed25519
```

## 小測驗

Q1. **`Ctrl+O` 之後還要做什麼才算真的存檔**？怎麼確認？

Q2. **在 nano 按 `Ctrl+S` 畫面卡住了，怎麼辦**？為什麼？

Q3. **貼一段 YAML 進 nano 縮排全跑掉，原因與三個解法**？

Q4. **`set nowrap` 和 `set softwrap` 的差別**？哪個改設定檔時必開？

Q5. **改 `sshd_config` 前後應該做哪四件事**？

Q6. **Ubuntu 22.04+ 改了 `sshd_config` 卻沒生效，最可能的原因**？怎麼確認？

Q7. **`sudo nano` 與 `sudoedit` 的差別**？為什麼後者比較安全？

Q8. **為什麼「`webadmin ALL=(root) NOPASSWD: /usr/bin/nano /etc/nginx/*`」是危險的**？

Q9. **`/etc/sudoers` 為什麼一定要用 `visudo` 改**？改壞了怎麼救？

Q10. **設定檔裡出現 `^M` 是什麼？怎麼看出來、怎麼修**？

> [!question]- 測驗答案
> **Q1.** **★★★ 按 `Ctrl+O` 之後還要按 `Enter` 確認檔名**。
> `Ctrl+O`（Write **O**ut）只是**開啟「存成什麼檔名」的提示**，
> 下方會顯示 `File Name to Write: notes.txt`，
> **這時候按 Enter 才真的寫入**。
> **確認方式**：狀態列出現 **`[ Wrote 12 lines ]`**。
> 這是新手最常見的錯誤 —— 以為存好了，離開時 nano 又問一次
> 「Save modified buffer?」就直接按 N，結果**改的東西全部不見**。
> 另一條路是**直接 `Ctrl+X`** → 問要不要存 → `Y` → 檔名 → Enter，一樣可以。
>
> **Q2.** **★★ 按 `Ctrl+Q` 解除**。
> 原因：**`Ctrl+S` 是終端機的 XOFF（暫停輸出）流量控制訊號**，
> 是終端機驅動層攔截的，比 nano 更早看到這個按鍵 ——
> 終端機停止顯示任何輸出，看起來就像整個當掉了
> （其實你打的字都還在，只是畫面不更新）。
> **`Ctrl+Q` 是 XON（恢復輸出）**，按下去畫面就會把積壓的內容一次刷出來。
> 補充：**nano 2.6+ 其實支援 `Ctrl+S` 存檔**，
> 但要先在 shell 停用流量控制才會生效：
> ```bash
> stty -ixon        # ★ 放進 ~/.bashrc
> ```
>
> **Q3.** **原因：nano 的 autoindent 把縮排疊加了**。
> 終端機的「貼上」等同於**逐字模擬鍵盤輸入** ——
> nano 以為你在打字，每按一次 Enter 就**自動幫你補上跟上一行相同的縮排**，
> 而貼上的內容**本身也帶著縮排**，兩者相加就變成階梯狀。
> **三個解法**：
> ①**★ 貼上前按 `Alt+I`** 切換掉 autoindent（狀態列顯示 `Auto-indent disabled`）；
> ②**★★ 用支援「括號貼上模式」的環境** ——
> nano 5.7+ 會偵測 bracketed paste 並自動停用 autoindent；
> ③**★★★ 根本解法：不要用貼上**，改用 heredoc：
> ```bash
> cat > docker-compose.yml <<'EOF'    # ★ 'EOF' 加單引號 = 不做變數展開
> ...
> EOF
> ```
> 或用 `scp` 把檔案傳上去。
>
> **Q4.** **`set nowrap`** = **不在檔案中【插入】換行字元**（hard wrap）——
> 舊版 nano 會在第 N 欄自動斷行，**這會實際改變檔案內容**，
> 把一行很長的 `proxy_set_header` 折成兩行 → **設定檔語法錯誤**。
> **★★★ 改設定檔時必開**（或用 `nano -w`）。
> 好消息是 **nano 2.7+ 已經改成預設不折行**。
> **`set softwrap`** = **只是「顯示上」折行**，
> 檔案內容完全不變，只是長行在畫面上換行顯示而不是水平捲動。
> **這個很方便，可以放心開**。
> 兩者名字像但作用完全不同：一個改檔案，一個只改顯示。
>
> **Q5.** **四件事**：
> ①**★★★ 先開第二個 SSH 連線並保持登入** ——
> 這是保命符，改壞了還有一條路進得去；
> ②**★★ 備份並加時間戳**：
> `sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.$(date +%F-%H%M)`；
> ③**★★★ 存檔後用 `sudo sshd -t` 驗證語法**，
> 並用 **`sudo sshd -T`** 看合併後的最終值（不只是語法對，值也要對）；
> ④**★★★ restart 後用第三個視窗測試新連線**，
> 成功了才關掉步驟①保留的連線。
> 失敗就從保留的連線把備份複製回去。
>
> **Q6.** **★★★ 被 `/etc/ssh/sshd_config.d/*.conf` 覆蓋了**。
> Ubuntu 22.04+ 的 `sshd_config` **最上面**有一行：
> ```
> Include /etc/ssh/sshd_config.d/*.conf
> ```
> 而 **SSH 的規則是「第一個出現的值生效」** ——
> Include 在最前面，所以 `sshd_config.d/` 裡的設定**優先於**你在主檔改的值。
> 常見的是 cloud-init 產生的 `50-cloud-init.conf` 裡有
> `PasswordAuthentication yes`，把你的 `no` 蓋掉。
> **確認方式**：
> ```bash
> sudo sshd -T | grep -i passwordauth      # ★★★ 看合併後的最終值
> ls /etc/ssh/sshd_config.d/
> ```
> **正確做法**：改 `sshd_config.d/` 裡的檔案，
> 或建一個排序更前面的 `00-hardening.conf`。
>
> **Q7.** **`sudo nano`** = **以 root 身分執行 nano** ——
> 編輯器的**所有功能都帶著 root 權限**：
> `Ctrl+R` 能讀任何檔案、`Ctrl+T` 的檔案瀏覽器、以及各種可能的 shell 逃逸。
> **`sudoedit`（`sudo -e`）** 的流程是：
> ①用 root 權限**把檔案複製到 `/tmp`** →
> ②**用你自己的身分**（不是 root）開編輯器編輯那個副本 →
> ③存檔離開後，**用 root 權限複製回原位**。
> **安全的關鍵在第②步：編輯器行程不是 root** ——
> 就算使用者從編輯器逃逸出 shell，也只是**他自己的權限**，不是 root。
> 用法：`export SUDO_EDITOR=nano; sudoedit /etc/nginx/nginx.conf`。
>
> **Q8.** 因為**編輯器可以逃逸出 shell，等於直接給了完整的 root**。
> 以 vim 為例：
> ```
> $ sudo vim /etc/nginx/nginx.conf
> :!/bin/bash                      ← ★★★★ 直接開 root shell
> # id → uid=0(root)
> ```
> nano 也有類似路徑（`Ctrl+T` 檔案瀏覽器、`Ctrl+R` 的外部指令），
> **不能假設它安全**。
> 而且就算編輯器本身沒有逃逸功能，**檔案路徑用萬用字元也是漏洞** ——
> `/etc/nginx/*` 配合符號連結可能繞到其他檔案。
> **`less`、`more`、`find`、`awk`、`tar`、`git` 都有同類問題**，
> 可以在 **GTFOBins**（gtfobins.github.io）查到各指令的提權方式。
> **正確做法**：用 `sudoedit`，或包一層只做特定事情的專用腳本。
>
> **Q9.** 因為 **`/etc/sudoers` 語法寫錯 = 所有人（包括你自己）都不能用 `sudo`**。
> Ubuntu 預設**沒有設 root 密碼**，所以連 `su -` 都進不去，
> 這台機器就**完全失去管理權限**了。
> **`visudo` 做兩件事**：
> ①**鎖定檔案**，避免兩個人同時編輯互相覆蓋；
> ②**★★★ 離開時自動檢查語法**，有錯會提示並問你要不要回去改，
> **語法不對就不會寫入**。
> 也適用於附加檔：`sudo visudo -f /etc/sudoers.d/deploy`；
> 純檢查用 `sudo visudo -c`。
> **已經改壞了的救法**：
> ①還有其他 root shell 開著 → 直接改回來；
> ②`pkexec visudo`（如果裝了 polkit）；
> ③**★ 重開機 → GRUB 選 recovery mode → root shell → 修正**。
>
> **Q10.** **`^M` 是 CR（carriage return, `\r`, 0x0D）**，
> 代表這個檔案用的是 **Windows 的 CRLF 換行**（`\r\n`），
> 而 Linux 用的是 **LF**（`\n`）——
> 多出來的 `\r` 會被程式當成**設定值的一部分**，
> 造成 `unknown directive`、路徑找不到、shell 腳本 `bad interpreter` 等各種怪錯誤。
> **怎麼看出來**：
> ```bash
> file f.conf
> # → ASCII text, with CRLF line terminators      ★★ 就是它
> cat -A f.conf | head        # ★ ^M$ = CRLF；單純的 $ = LF
> ```
> nano 開啟時**狀態列也會顯示 `[DOS Format]`**。
> **怎麼修**：
> ```bash
> sudo dos2unix f.conf
> sudo sed -i 's/\r$//' f.conf     # ★ 沒有 dos2unix 時
> ```
> **預防**：不要用 Windows 的記事本編輯 Linux 設定檔；
> VSCode 右下角可以把 CRLF 切成 LF；
> git 設 `core.autocrlf=input`。
