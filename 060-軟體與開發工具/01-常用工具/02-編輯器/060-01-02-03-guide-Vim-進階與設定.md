## ★★★ 一份維運用的 .vimrc

```vim
" ~/.vimrc —— 維運用設定（★ 不依賴任何外掛）
" ═══════════════════════════════════════════════

" ═══ ★★★ 基本 ═══
set nocompatible               " ★★★ 不相容 vi（★ 方向鍵才會正常）
filetype plugin indent on      " ★ 依副檔名載入設定
syntax on                      " ★★ 語法高亮
set encoding=utf-8
set fileencodings=utf-8,big5,gbk,latin1   " ★★ 開檔時的偵測順序
set backspace=indent,eol,start " ★★ Backspace 可以刪過行首（★ 不設會很痛苦）

" ═══ ★★★ 顯示 ═══
set number                     " ★★ 行號
set relativenumber             " ★★ 相對行號（★ 配合 5dd 這種指令）
set ruler                      " 右下角顯示行/欄
set showcmd                    " ★ 右下角顯示正在打的指令
set showmode                   " ★ 左下角顯示模式
set laststatus=2               " ★★ 永遠顯示狀態列
set cursorline                 " ★ 標示游標所在行
set scrolloff=5                " ★★ 游標上下至少保留 5 行（★ 很實用）
set sidescrolloff=8
set wildmenu                   " ★★ 指令列 Tab 補全選單
set wildmode=longest:full,full
set list                       " ★★ 顯示不可見字元
set listchars=tab:▸\ ,trail:·,extends:›,precedes:‹,nbsp:␣
"                    ↑ Tab      ↑ 行尾空白（★★ 很容易踩雷）

" ═══ ★★★ 搜尋 ═══
set hlsearch                   " ★ 高亮所有符合
set incsearch                  " ★★ 邊打邊找
set ignorecase                 " 忽略大小寫
set smartcase                  " ★★★ 但打了大寫就區分（★ 很聰明）
nnoremap <silent> <Esc><Esc> :nohlsearch<CR>   " ★★ Esc Esc 清高亮

" ═══ ★★ 縮排 ═══
set expandtab                  " ★★★ Tab 轉空白（★ YAML/Python 必開）
set tabstop=4                  " Tab 顯示成 4 格
set softtabstop=4              " ★ 按 Tab/Backspace 移動 4 格
set shiftwidth=4               " ★ >> << 縮排 4 格
set autoindent
set smartindent

" ★★ 依檔案類型調整
autocmd FileType yaml,yml   setlocal ts=2 sts=2 sw=2 expandtab
autocmd FileType json       setlocal ts=2 sts=2 sw=2 expandtab
autocmd FileType html,css,javascript,vue setlocal ts=2 sts=2 sw=2 expandtab
autocmd FileType make,go    setlocal noexpandtab ts=4 sw=4   " ★★★ Makefile 一定要 Tab！
autocmd FileType python     setlocal ts=4 sts=4 sw=4 expandtab
autocmd FileType nginx      setlocal ts=4 sw=4 expandtab

" ═══ ★★ 檔案處理 ═══
set autoread                   " ★ 外部改動時自動重載
set hidden                     " ★★ 允許切換到別的檔案而不強制存檔
set noswapfile                 " ★ 見下方說明（★ 或改成集中管理）
set undofile                   " ★★★ 持久化 undo（★ 關掉 vim 再開還能 u）
set undodir=~/.vim/undo//
set backupdir=~/.vim/backup//
set directory=~/.vim/swap//
set updatetime=300

" ═══ ★★★ 安全 ═══
set nomodeline                 " ★★★ 停用 modeline（★ 有 CVE 紀錄）
set noexrc                     " ★ 不載入目前目錄的 .vimrc
set viminfo='100,<50,s10,h,n~/.vim/viminfo

" ═══ ★★ 實用對應 ═══
" ★★★ 忘記 sudo 的救場（打 :w!! 就好）
cnoremap w!! w !sudo tee % > /dev/null

" ★★ 用 jk 離開 Insert 模式（手不用離開主鍵盤區）
inoremap jk <Esc>

" ★★ 視窗切換
nnoremap <C-h> <C-w>h
nnoremap <C-j> <C-w>j
nnoremap <C-k> <C-w>k
nnoremap <C-l> <C-w>l

" ★★ Y 改成複製到行尾（★ 跟 D、C 一致）
nnoremap Y y$

" ★★ 保持搜尋結果置中
nnoremap n nzzzv
nnoremap N Nzzzv

" ★★ Visual 模式縮排後保持選取
vnoremap < <gv
vnoremap > >gv

" ★★★ 記住上次離開的位置
autocmd BufReadPost * if line("'\"") > 0 && line("'\"") <= line("$")
  \| exe "normal! g`\"" | endif

" ★★ 存檔時自動移除行尾空白（★ 但排除 Markdown）
autocmd BufWritePre * if &ft !~# 'markdown\|diff' | %s/\s\+$//e | endif

" ═══ ★★ 狀態列 ═══
set statusline=%f\ %m%r%h%w
set statusline+=\ [%{&ff}/%{strlen(&fenc)?&fenc:'none'}]
set statusline+=\ [%Y]
set statusline+=%=
set statusline+=\ %l/%L:%c\ (%p%%)
```

```bash
# ★★ 建立需要的目錄
$ mkdir -p ~/.vim/{swap,backup,undo}
$ chmod 700 ~/.vim ~/.vim/{swap,backup,undo}

# ★ 驗證設定有載入
$ vim -c ':scriptnames' -c ':q'
$ vim +':verbose set expandtab?' +q
  expandtab
        Last set from ~/.vimrc line 45         # ★★ 顯示在哪設的
```

> [!danger] `noexpandtab` 對 Makefile 是必要的 ★★★
> ```
> ★★★★ Makefile 的指令行【一定要用真正的 Tab】開頭
>   → 用空白會得到：
>     Makefile:4: *** missing separator.  Stop.
>
> ★★ 所以 .vimrc 一定要有：
>   autocmd FileType make setlocal noexpandtab
>
> ★ 同樣要注意的還有：
>   · Go（gofmt 用 Tab）
>   · 某些舊的設定檔格式
>
> ★★ 檢查方式：
>   :set list          → Tab 會顯示成 ▸
>   $ cat -A Makefile  → Tab 顯示成 ^I
> ```

> [!tip] `undofile` 是被低估的功能 ★★★
> ```
> ★★★ set undofile 讓 undo 歷史【存到磁碟】
>   → 關掉 vim、隔天再開同一個檔案
>   → ★★ 還是可以按 u 一路復原到昨天的狀態
>
> ★★ 實務價值：
>   「昨天改了 nginx 設定，今天發現有問題，但忘記改了什麼」
>   → 開檔按 u 幾次就看得到
>   → ★ 配合 :earlier 10m（回到 10 分鐘前）更強
>
> ★★ 相關指令：
>   :undolist        列出 undo 分支
>   :earlier 5m      ★★ 回到 5 分鐘前
>   :later 5m        往後
>   :earlier 10f     回到 10 次存檔前
> ```

## 多檔案與視窗 ★★

### 緩衝區（buffer）

```
★★ 一個「檔案」載入 vim 就是一個 buffer

  :e file.conf         開啟另一個檔案（★ edit）
  :ls  /  :buffers     ★★ 列出所有 buffer
  :b 3                 切到第 3 個
  :b nginx             ★ 切到檔名含 nginx 的（★ 可以只打部分）
  :bn  /  :bp          下一個 / 上一個
  :bd                  ★ 關掉目前的 buffer
  :bd!                 強制關（有未存的修改）

★★ :ls 的輸出：
  1  h   "nginx.conf"       line 24      ← h = hidden（背景）
  2 %a   "app.conf"         line 1       ← ★ % = 目前, a = active
  3  #+  "sites.conf"       line 8       ← ★ # = 上一個, + = ★★ 有未存的修改

★★★ set hidden 很重要：
  → 沒開的話，切到別的 buffer 前【一定要存檔】
  → 開了就可以先放著
```

### 分割視窗 ★★

```
★★ 分割
  :sp file          水平分割（split）
  :vs file          ★★ 垂直分割（vsplit）★ 比對設定檔時最好用
  Ctrl+w s          分割目前檔案
  Ctrl+w v          垂直分割目前檔案

★★ 切換
  Ctrl+w h/j/k/l    ★★ 往左/下/上/右的視窗
  Ctrl+w w          循環
  Ctrl+w q          關閉目前視窗
  Ctrl+w o          ★ 只留目前這個（only）

★★ 調整大小
  Ctrl+w =          ★ 平均分配
  Ctrl+w +/-        高度增減
  Ctrl+w </>        寬度增減
  Ctrl+w _          ★ 目前視窗最大化（高度）
  Ctrl+w |          最大化（寬度）
  :resize 20        指定高度
  :vertical resize 80

★★ 移動視窗
  Ctrl+w H/J/K/L    ★ 把目前視窗移到最左/下/上/右
  Ctrl+w r          ★ 旋轉
```

### 分頁（tab）★

```
  :tabe file        開新分頁
  :tabn / :tabp     下/上一個（★ 或 gt / gT）
  :tabc             關閉
  :tabo             只留這個
  3gt               ★ 跳到第 3 個分頁
  :tabs             列出

★★ buffer / window / tab 的關係（★ 很多人搞混）：
  buffer = 【載入記憶體的檔案】
  window = 【顯示 buffer 的框】（一個 buffer 可以在多個 window 顯示）
  tab    = 【window 的排列組合】（★ 不是「一個檔案一個分頁」）

★ 維運場景：通常 buffer + 分割視窗就夠了，分頁用得少
```

## ★★★ 巨集（macro）

```
★★★★ 巨集 = 錄下一連串按鍵，然後重複播放
  → 處理「格式一樣的 50 行」時，比寫 sed 還快

★★★ 錄製與播放：
  q<字母>       開始錄製到暫存器（★ 通常用 q，即 qq）
  ...操作...
  q             停止錄製
  @<字母>       播放一次（★ @q）
  @@            ★★ 重複上一次播放
  10@q          ★★★ 播放 10 次
  100@q         ★ 播到檔尾（超過就會停）
```

### 實例：把 access log 整理成 CSV

```
★★ 原始資料（50 行）：
  192.168.1.10 - - [28/Aug/2026:10:00:01] "GET /api/users HTTP/1.1" 200
  192.168.1.22 - - [28/Aug/2026:10:00:03] "POST /api/login HTTP/1.1" 401
  ...

★★ 目標：
  192.168.1.10,GET,/api/users,200
  192.168.1.22,POST,/api/login,401

★★★ 錄製（游標放第一行行首）：

  qq                ← 開始錄到暫存器 q（左下角顯示 recording @q）
  0                 ← 確保在行首（★★ 巨集一定要從固定位置開始）
  f-                ← 跳到第一個 -
  d/"<Enter>        ← 刪到第一個引號
  x                 ← 刪掉引號
  i,<Esc>           ← 插入逗號
  f <Space>         ← 跳到空白
  ...（依實際格式調整）
  j                 ← ★★★ 移到下一行（★ 這一步不能忘！）
  q                 ← 停止錄製

★★★ 播放：
  49@q              ← 對剩下 49 行執行
  或
  100@q             ← 播到檔尾自然停止
```

> [!tip] 巨集的三個關鍵 ★★★
> ```
> ★★★ ① 【從固定位置開始】
>      → 錄製前先按 0（行首）或 gg
>      → ★ 否則第二次播放時起點就跑掉了
>
> ★★★ ② 【最後要移到下一行】
>      → 巨集結尾按 j 或 j0
>      → ★ 不然 10@q 會在同一行做 10 次
>
> ★★★ ③ 【用相對移動，不要用絕對行號】
>      → 用 f, / w / $ 這種「找下一個」的動作
>      → ★ 不要用 :15 這種絕對跳轉
>
> ★★ 巨集出錯會自動停止
>   → 例如 f, 找不到逗號 → 剩下的次數不會執行
>   → ★ 這其實是保護機制
> ```

```
★★ 檢視與編輯巨集：

  :reg q            ★★ 看暫存器 q 的內容（就是你錄的按鍵）
  "qp               ★★★ 把巨集內容【貼到檔案裡】→ 可以直接編輯文字
  （改完後）
  0"qy$             ★★ 把這一行重新複製回暫存器 q
  → ★ 這是修正巨集的標準做法

★★ 遞迴巨集（進階）：
  qqq               清空暫存器 q
  qq  ...操作... @q q     ← ★ 巨集最後呼叫自己
  @q                ← ★★ 會一直執行到出錯為止（自動處理整個檔案）
```

## 暫存器（register）★★

```
★★★ vim 有【很多個剪貼簿】，叫做暫存器

  "" 　　　 預設暫存器（★ dd yy p 用的就是這個）
  "0 　　　 ★★ 最近一次 yank（複製）的內容
  "1~"9 　　★ 最近 9 次【刪除】的內容（★ 像資源回收筒）
  "a~"z 　　★★ 具名暫存器（自己指定）
  "A~"Z 　　★ 大寫 = 【附加】到該暫存器
  "+ 　　　 ★★★ 系統剪貼簿（clipboard）
  "* 　　　 ★★ X11 的 primary selection（滑鼠選取）
  "% 　　　 目前檔名
  ". 　　　 上次插入的文字
  ": 　　　 上次的指令
  "/ 　　　 上次的搜尋
  "_ 　　　 ★★★ 黑洞（★ 刪除但不進暫存器）
```

```
★★★ 最常遇到的問題：「複製後貼上，貼出來的是剛剛刪掉的東西」

  yy                ← 複製 A 行（進 "" 和 "0）
  dd                ← ★★★ 刪掉 B 行（★ 覆蓋了 "" ！）
  p                 ← ★★ 貼出來的是 B 行，不是 A 行！

★★★ 三個解法：
  ① "0p             ← ★★★ 用 "0（最近一次 yank）
  ② "_dd            ← ★★ 刪除時丟進黑洞，不覆蓋暫存器
  ③ "ayy … "ap      ← 複製到具名暫存器 a
```

```
★★ 實用範例：

  "ayy              把這行複製到暫存器 a
  "Ayy              ★ 把下一行【附加】到 a（★ 收集多行）
  "ap               貼出暫存器 a

  "_dd              ★★ 刪除但不影響剪貼簿
  "+yy              ★★★ 複製到系統剪貼簿
  "+p               從系統剪貼簿貼上

  :reg              ★★ 列出所有暫存器的內容
  :reg a 0 +        只看這三個
```

### ★★ 與系統剪貼簿互通

```bash
# ★★★ 先確認 vim 有 clipboard 支援
$ vim --version | grep -o '[+-]clipboard\|[+-]xterm_clipboard'
+clipboard                      # ★ 有
-clipboard                      # ★★ 沒有 → 下面的 "+ 不能用

# ★★ 沒有的話裝完整版
$ sudo apt install -y vim-gtk3          # Ubuntu（★ 帶 clipboard）
$ sudo dnf install -y vim-X11           # RHEL
```

```
★★★ 三種情境的處理：

【① 本機的圖形環境】
  "+yy / "+p         ★ 直接可用
  或 set clipboard=unnamedplus  → ★★ yy 直接就是系統剪貼簿

【② SSH 到遠端伺服器】★★★ 最常見
  → ★★ 遠端的 vim 【沒辦法】直接存取你本機的剪貼簿
  → 三個做法：
    a. ★★★ 用終端機本身的選取複製
       → 但會把行號、分割線一起選進去
       → ★ 先 :set nonumber nolist 再選
    b. ★★ 把內容寫到檔案再 scp
       :w /tmp/snippet.txt
       $ scp server:/tmp/snippet.txt .
    c. ★★★ SSH 的 X11 forwarding（ssh -X）+ vim-gtk3
       → ★ 慢，而且要伺服器允許 X11Forwarding

【③ WSL】★★
  → ★★ WSL2 的 vim 可以透過 clip.exe 寫入 Windows 剪貼簿
```

```vim
" ★★ WSL：把 "+y 導向 Windows 剪貼簿
if system('uname -r') =~? 'microsoft'
  augroup WSLYank
    autocmd!
    autocmd TextYankPost * if v:event.operator ==# 'y' && v:event.regname ==# '+'
      \| call system('clip.exe', @+) | endif
  augroup END
endif
```

```bash
# ★★ WSL 手動用法
$ vim file.txt
  :w !clip.exe                  # ★★ 整個檔案送到 Windows 剪貼簿
  :'<,'>w !clip.exe             # ★ 只送選取的部分

# ★★ 反向：Windows 剪貼簿 → vim
$ powershell.exe -c Get-Clipboard | vim -
```

## 差異比對 ★★

```bash
# ★★★ 比對兩個設定檔
$ vimdiff /etc/nginx/nginx.conf /etc/nginx/nginx.conf.bak
$ vim -d file1 file2                       # ★ 同上

# ★ 三向比對（合併衝突）
$ vimdiff base.conf mine.conf theirs.conf
```

```
★★ vimdiff 內的操作：

  ]c                ★★ 下一個差異
  [c                上一個差異
  do                ★★★ diff obtain —— 把【對方的】改到這邊
  dp                ★★★ diff put —— 把【這邊的】推到對方
  zo / zc           展開 / 收合摺疊
  zR                ★ 展開全部
  :diffupdate       ★ 重新計算差異
  Ctrl+w w          切換視窗

★★ 記法：
  do = 拿過來（obtain）
  dp = 推過去（put）
```

```
★★ 在已開啟的 vim 中比對：
  :vs otherfile      垂直分割開另一個檔
  :windo diffthis    ★★ 對所有視窗啟用 diff
  :diffoff!          ★ 關掉 diff 模式

★★★ 比對「修改中的緩衝區」與「磁碟上的版本」：
  :w !diff % -       ★★ 看自己改了什麼（★ 存檔前很有用）
  或
  :DiffOrig          （需要在 .vimrc 定義，見下方）
```

```vim
" ★★ 加到 .vimrc：比較緩衝區與磁碟版本
command! DiffOrig vert new | set bt=nofile | r ++edit # | 0d_
  \ | diffthis | wincmd p | diffthis
```

## 外掛 ★★

> [!warning] 維運場景該不該裝外掛？★★★
> ```
> ★★★ 分兩種情境：
>
> 【你自己的工作機】★ 隨便裝
>   → 開發、寫腳本、看程式碼 → 外掛很有幫助
>
> 【伺服器（尤其是正式環境）】★★★ 不要裝
>   理由：
>   ① ★★ 伺服器上編輯的是設定檔，不需要 LSP / 自動補全
>   ② ★★★ 外掛 = 額外的程式碼 = 額外的攻擊面
>   ③ ★★ 多台伺服器同步外掛很麻煩

## ★★ 遠端與 root 環境的設定策略

```
★★★ 三個常見的困擾：

  ① 「SSH 到伺服器，vim 沒有我的設定」
  ② 「sudo vim 用的是 root 的設定，不是我的」
  ③ 「新機器每次都要重設一次」
```

```bash
# ═══ ★★★ 解法一：一份最小可攜設定 ═══
# ★ 把這段記起來，到任何機器都能快速設定
$ cat > ~/.vimrc <<'EOF'
set nocompatible number relativenumber ruler showcmd laststatus=2
set encoding=utf-8 backspace=indent,eol,start
set expandtab tabstop=4 softtabstop=4 shiftwidth=4 autoindent
set hlsearch incsearch ignorecase smartcase
set list listchars=tab:>-,trail:.
set nomodeline noswapfile
syntax on
filetype plugin indent on
autocmd FileType yaml,json setlocal ts=2 sts=2 sw=2
autocmd FileType make setlocal noexpandtab
cnoremap w!! w !sudo tee % > /dev/null
EOF

# ═══ ★★ 解法二：sudo 沿用自己的設定 ═══
$ sudo vim -u ~/.vimrc /etc/nginx/nginx.conf

# ★ 或設定 sudo 保留 HOME（★★ 有安全考量，見下）
$ sudo -E vim /etc/nginx/nginx.conf       # ★ 需要 sudoers 允許

# ★★★ 更好的做法：用 sudoedit
$ export SUDO_EDITOR=vim
$ sudoedit /etc/nginx/nginx.conf          # ★ 用你自己的身分和設定

# ═══ ★★ 解法三：放進設定管理 ═══
# ★ 用 Ansible / 或簡單的 dotfiles repo
$ git clone https://github.com/you/dotfiles ~/dotfiles
$ ln -sf ~/dotfiles/vimrc ~/.vimrc
```

> [!danger] `sudo -E` 的風險 ★★★
> ```
> ★★★ sudo -E 會把【你的所有環境變數】帶進 root 環境
>   → 包含 VIMINIT、VIMRUNTIME、LD_PRELOAD…
>   → ★★★★ 攻擊者若能改你的 ~/.vimrc，就能在 root 下執行任意程式碼
>
> ★★ sudoers 預設有 env_reset 就是為了防這個
>
> ★★★ 正確的做法排序：
>   ① sudoedit（★★★ 最安全，編輯器不是 root）
>   ② sudo vim -u ~/.vimrc（★ 明確指定，比 -E 可控）
>   ③ ★ 直接用 root 的 /root/.vimrc（★ 幫 root 也放一份）
>      $ sudo cp ~/.vimrc /root/.vimrc
> ```

Q10. **`:%s/old/new/g` 和 `sed -i 's/old/new/g'` 各適合什麼情境**？

> [!question]- 測驗答案
> **Q1.** **三個坑**：
> ①**★★★ 沒有 `set hidden`** ——
> `:argdo` 切換到下一個檔案時，如果目前檔案有未存的修改，
> vim 會拒絕切換並**中斷整個 argdo**；
> ②**★★★ 取代沒加 `e` 旗標** ——
> 某個檔案裡找不到 `a` 時會噴 `E486: Pattern not found`，
> **一樣中斷整批處理**，而且你不會知道它做到第幾個檔案；
> ③**★★ 忘記存檔** —— `:argdo` 只在記憶體裡改，沒有 `update` 就不會寫入磁碟。
> **正確寫法**：
> ```vim
> :set hidden
> :argdo %s/8080/3000/ge | update
> ```
> **用 `update` 而不是 `w`**，因為 `update` **只有真的改過才寫入**，
> 不會動到沒被修改的檔案的 mtime。
>
> **Q2.** **三個關鍵**：
> ①**★★★ 從固定位置開始** —— 錄製前先按 `0`（行首）或 `gg`，
> 漏掉的話**第二次播放時起點就跑掉了**，結果一團亂；
> ②**★★★ 結尾要移到下一行**（`j` 或 `j0`），
> 漏掉的話 `10@q` 會**在同一行做 10 次**，而不是處理 10 行；
> ③**★★★ 用相對移動，不要用絕對行號** ——
> 用 `f,`、`w`、`$` 這種「找下一個」的動作，
> 用 `:15` 這種絕對跳轉的話播放第二次就完全錯位。
> 補充：**巨集出錯會自動停止**（例如 `f,` 找不到逗號），
> 這其實是保護機制 —— 所以可以放心打 `100@q` 讓它自然停在檔尾。
>
> **Q3.** **貼出來的是剛剛 `dd` 刪掉的那一行**，不是 `yy` 複製的。
> 原因：**`dd` 也會把內容放進「預設暫存器 `""`」**，把 `yy` 的內容覆蓋掉了
> （vim 的「刪除」其實是「剪下」）。
> **三個解法**：
> ①**★★★ `"0p`** —— 暫存器 `"0` **只存最近一次 yank**，
> 刪除操作不會動到它，所以 `"0p` 一定貼得到你複製的東西；
> ②**★★ `"_dd`** —— `"_` 是**黑洞暫存器**，刪除的內容直接丟掉，不覆蓋 `""`；
> ③**`"ayy` … `"ap`** —— 複製到具名暫存器 `a`，完全不受影響。
> 順帶一提 `"1`~`"9` 存的是最近 9 次**刪除**的內容，像資源回收筒。
>
> **Q4.** 因為 **Makefile 的指令行必須用「真正的 Tab 字元」開頭**，
> 用空白會直接失敗：
> ```
> Makefile:4: *** missing separator.  Stop.
> ```
> 而維運用的 `.vimrc` 通常會設 `set expandtab`（Tab 轉空白），
> 這對 YAML 和 Python 是必要的，**但對 Makefile 是災難**。
> `autocmd FileType make setlocal noexpandtab` 讓 vim **只對 Makefile 例外**。
> 注意用 **`setlocal`** 而不是 `set` —— 只影響這個 buffer，不會污染其他檔案。
> 同樣需要真 Tab 的還有 **Go**（gofmt 的規範）和某些舊格式的設定檔。
> **檢查方式**：`:set list`（Tab 顯示成 `▸`）或 `cat -A Makefile`（顯示 `^I`）。
>
> **Q5.** **好處：★★★ undo 歷史存到磁碟，關掉 vim 再開還能繼續 undo**。
> 實務價值很高：「昨天改了 nginx 設定，今天發現有問題，但忘記改了什麼」——
> 開檔按 `u` 就能一路回溯，配合 **`:earlier 30m`**（回到 30 分鐘前）
> 或 `:earlier 10f`（回到 10 次存檔前）更強，`:undolist` 可以看分支。
> **風險：★★★ undo 檔裡有檔案的完整歷史內容**。
> 編輯過 `.env` 或私鑰之後，`~/.vim/undo/` 裡**留著明文的密碼和金鑰**，
> 而且權限如果沒設好，同機器的其他使用者讀得到。
> **防護**：
> ```vim
> autocmd BufReadPre *.env,*.pem,*.key setlocal noundofile noswapfile viminfo=
> ```
> 加上 `chmod 700 ~/.vim/undo`，以及一個 `svim` alias 用於敏感檔案。
>
> **Q6.** 因為 **`"+` 存取的是「vim 執行所在那台機器」的剪貼簿** ——
> 你 SSH 到遠端，vim 跑在**伺服器上**，
> 它能存取的是伺服器的 X11 剪貼簿（通常根本沒有圖形環境），
> **不是你本機的剪貼簿**。而且多數伺服器的 vim 是 `-clipboard` 編譯的。
> **三個替代做法**：
> ①**★★ 用終端機本身的選取複製**（`Ctrl+Shift+C`）——
> 但會把行號和分割線一起選進去，先 `:set nonumber nolist` 再選；
> ②**★★ 寫到檔案再傳**：vim 內 `:w /tmp/snippet.txt`，本機 `scp` 抓回來；
> ③**★ X11 forwarding**（`ssh -X` + 伺服器裝 `vim-gtk3`）——
> 可行但很慢，而且要伺服器開 `X11Forwarding`。
> **WSL 是特例**：可以用 `:w !clip.exe` 送進 Windows 剪貼簿。
>
> **Q7.** **`do` = diff obtain =「把對方的內容拿過來」**（改動目前這一邊）；
> **`dp` = diff put =「把這邊的內容推過去」**（改動另一邊）。
> **記法**：**o**btain 是拿、**p**ut 是推。
> 搭配 **`]c`（下一個差異）** 和 **`[c`（上一個差異）** 逐一處理。
> 常見用途：`vimdiff nginx.conf nginx.conf.bak` 比對備份與現行設定，
> 一邊 `]c` 跳、一邊決定 `do` 還是 `dp`。
> 其他：`zR` 展開所有摺疊、`:diffupdate` 重算差異、
> `:diffoff!` 關閉 diff 模式、`Ctrl+w w` 切換視窗。
> 也可以在已開的 vim 裡 `:vs otherfile` 再 `:windo diffthis`。
>
> **Q8.** **至少五個理由**：
> ①**★★ 伺服器上編輯的是設定檔**，不需要 LSP、自動補全、git 整合這些功能；
> ②**★★★ 外掛是別人的程式碼 = 額外的攻擊面** ——
> vimscript 可以執行任意指令，供應鏈風險是真的；
> ③**★★ 多台伺服器同步外掛很麻煩**，版本不一致更麻煩；
> ④**★★★★ 救援模式、剛裝好的機器、容器內都沒有你的外掛** ——
> 依賴外掛的人在最需要用 vim 的時候反而不會用了；
> ⑤**★ 啟動變慢** —— SSH 進去只想改一行設定，卻要等 vim 載入兩秒。
> **建議**：**伺服器上用純 `.vimrc`，不裝外掛**；
> 工作機隨便裝（vim-surround、vim-commentary、fzf.vim 都很好用）。
> 註解和模糊搜尋其實不裝外掛也做得到（自訂函式 + `set path+=**`）。
>
> **Q9.** **安全性由高到低：`sudoedit` > `sudo vim -u ~/.vimrc` > `sudo -E vim`**。
> **`sudoedit`（`sudo -e`）最安全** ——
> 它用 root 權限把檔案複製到 `/tmp`，**用「你自己的身分」開編輯器**編輯副本，
> 存檔後再用 root 複製回去。**編輯器行程不是 root**，
> 就算從編輯器逃逸出 shell 也只是你自己的權限。
> **`sudo vim -u ~/.vimrc`** —— vim 是 root，但**明確指定只載入這一個設定檔**，
> 範圍可控。
> **`sudo -E vim` 最危險** —— `-E` 把**你的所有環境變數帶進 root 環境**，
> 包含 `VIMINIT`、`VIMRUNTIME`、`LD_PRELOAD` 等；
> **攻擊者只要能改你的 `~/.vimrc` 或設一個環境變數，就能在 root 下執行任意程式碼**。
> sudoers 預設有 `env_reset` 就是為了防這個，`-E` 等於把防護關掉。
>
> **Q10.** **`sed -i` 適合：規則明確、不需要看內容的機械式批次修改**。
> 例如「所有設定檔的 8080 改成 3000」、「移除行尾空白」——
> 一行指令處理 100 個檔案，快而且可以寫進腳本重複執行：
> ```bash
> sudo sed -i.bak 's/8080/3000/g' *.conf
> ```
> **`:%s` / `:argdo` 適合：需要「看著改」、每個地方情況不同**。
> 例如 8 處 `8080` 其中 3 處是註解不該動 ——
> 用 `:%s/8080/3000/gc` 逐一確認，或用 `/8080` + `cw` + `n` + `.` 更靈活。
> **判斷準則**：
> **「你能不能一句話描述規則，而且確定沒有例外？」**
> 能 → `sed`；不能 → vim。
> 兩者都要**先備份**（`sed -i.bak` 或 `cp -a`），改完**跑語法驗證**（`nginx -t`）。
