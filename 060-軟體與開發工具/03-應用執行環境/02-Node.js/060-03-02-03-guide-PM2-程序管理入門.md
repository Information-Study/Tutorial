## PM2 vs systemd：先想清楚

| | **PM2** | **systemd** |
| --- | --- | --- |
| **安裝** | `npm i -g pm2` | 系統內建 |
| **cluster 模式** | **★ 內建，一行搞定** | 需要自己處理（或用 socket activation） |
| **零停機重載** | **★ `pm2 reload`** | 需要自己設計 |
| **日誌** | 自己管理（要裝 logrotate 模組） | **★ journald（統一、可查詢）** |
| **監控介面** | **★ `pm2 monit`、`pm2 plus`** | `systemctl status`、`journalctl` |
| **開機自啟** | **★ 要跑 `pm2 startup` + `pm2 save`（易錯）** | **`systemctl enable`（單純）** |
| **安全加固** | 有限 | **★★ 完整（沙箱、命名空間、能力限制）** |
| **資源限制** | `max_memory_restart` | **★ `MemoryMax`、`CPUQuota`（cgroup 層級）** |
| **多語言** | 主要是 Node | **★ 任何程式** |
| **相依** | **★ 依賴 Node 與 PM2 本身** | 無 |
| **維運熟悉度** | Node 開發者熟悉 | **★ 系統管理員熟悉** |

> [!tip] 選擇建議
> ```
> ★ 用 systemd：
>   · 單一程序（Nuxt SSR、API server）
>   · 機關的正式環境（維運人員熟悉 systemd）
>   · 需要嚴格的安全加固
>   · 不想多一層相依
>
> ★ 用 PM2：
>   · 需要 cluster 模式（多核心 CPU、CPU 密集的應用）
>   · 需要零停機重載（pm2 reload）
>   · 開發者自行維運、習慣 PM2 的工具鏈
>   · 同一台機器上有多個 Node 應用要管理
>
> ★★ 最佳實務：【用 systemd 管理 PM2】
>   → 取得 PM2 的 cluster 與 reload，同時保有 systemd 的可靠性
>   （見下方「systemd + PM2」）
> ```

> [!danger] PM2 最常見的事故：重開機後服務沒起來
> ```
> 只做了 pm2 start，沒做 pm2 startup + pm2 save
>   → 重開機 → 【服務完全消失】
>     → 而且不會有任何錯誤訊息
>       → 通常是使用者回報「網站掛了」才發現
> ```
> **這是 PM2 相對 systemd 最大的風險。**
> 見下方「開機自啟」章節。

## 安裝與基本操作

```bash
# ═══ 安裝 ═══
$ sudo npm install -g pm2
$ pm2 --version
5.4.3

# ★ 或用專用使用者（更好）
$ sudo useradd -r -m -d /var/lib/nodeapp -s /bin/bash nodeapp
$ sudo -u nodeapp npm install -g pm2 --prefix /var/lib/nodeapp/.npm-global
```

```bash
# ═══ 啟動應用 ═══
$ pm2 start app.js
$ pm2 start app.js --name my-api
$ pm2 start npm --name my-app -- run start          # ★ 執行 npm script
$ pm2 start .output/server/index.mjs --name nuxt    # Nuxt
$ pm2 start "node --max-old-space-size=2048 app.js" --name big-app

# ★ 傳環境變數
$ HOST=127.0.0.1 PORT=3000 NODE_ENV=production pm2 start app.js --name api

# ═══ 檢視 ═══
$ pm2 list
$ pm2 ls                    # 同義
$ pm2 status                # 同義
┌────┬────────────┬─────────┬─────────┬──────┬────────┬──────┬──────────┬──────────┐
│ id │ name       │ mode    │ pid     │ ↺    │ status │ cpu  │ mem      │ user     │
├────┼────────────┼─────────┼─────────┼──────┼────────┼──────┼──────────┼──────────┤
│ 0  │ my-api     │ fork    │ 12345   │ 0    │ online │ 0.3% │ 78.2mb   │ nodeapp  │
│ 1  │ nuxt       │ cluster │ 12350   │ 2    │ online │ 1.2% │ 142.5mb  │ nodeapp  │
└────┴────────────┴─────────┴─────────┴──────┴────────┴──────┴──────────┴──────────┘

# ═══ 控制 ═══
$ pm2 restart my-api        # ★ 完整重啟（會中斷）
$ pm2 reload my-api         # ★★ 零停機重載（只在 cluster 模式有效）
$ pm2 stop my-api
$ pm2 delete my-api         # ★ 從清單中移除
$ pm2 restart all
$ pm2 stop all

# ═══ 日誌 ═══
$ pm2 logs                  # 所有應用
$ pm2 logs my-api           # 特定應用
$ pm2 logs my-api --lines 100
$ pm2 logs --err            # 只看錯誤
$ pm2 flush                 # ★ 清空所有日誌

# ═══ 監控 ═══
$ pm2 monit                 # ★ 即時儀表板
$ pm2 describe my-api       # ★ 詳細資訊
$ pm2 show my-api           # 同義
```

### 狀態判讀

| 狀態 | 意義 | 該做什麼 |
| --- | --- | --- |
| **`online`** | 正常執行中 | ✓ |
| `stopping` | 正在停止 | 等待 |
| `stopped` | 已停止 | `pm2 start` |
| **`errored`** | **啟動失敗或崩潰太多次** | **★ 看 `pm2 logs`** |
| `launching` | 啟動中 | 等待 |
| `one-launch-status` | 一次性任務執行中 | — |

```bash
# ★ 重啟次數（↺ 欄位）是重要指標
$ pm2 list
│ 0  │ my-api │ fork │ 12345 │ 847 │ online │  ← ★★ 重啟 847 次！

# → 表示應用一直在崩潰重啟
$ pm2 logs my-api --err --lines 50
$ pm2 describe my-api | grep -A5 'restarts'
```

> [!warning] 高重啟次數是最重要的警訊
> ```
> ↺ 欄位持續增加 = 應用不斷崩潰
>   → PM2 會自動重啟，所以「看起來是 online」
>     → ★ 但使用者會間歇性遇到 502
>       → 而且【可能一直沒被發現】
> ```
> ```bash
> # ★ 加進監控
> $ pm2 jlist | jq -r '.[] | "\(.name): \(.pm2_env.restart_time) 次重啟"'
> ```

## 開機自啟（★ 最容易出錯的地方）

```bash
# ═══ 步驟一：產生 systemd service ═══
$ pm2 startup
[PM2] Init System found: systemd
[PM2] To setup the Startup Script, copy/paste the following command:
sudo env PATH=$PATH:/usr/bin /usr/lib/node_modules/pm2/bin/pm2 startup systemd \
  -u nodeapp --hp /var/lib/nodeapp

# ★ 複製並執行它給你的那一行
$ sudo env PATH=$PATH:/usr/bin /usr/lib/node_modules/pm2/bin/pm2 startup systemd \
    -u nodeapp --hp /var/lib/nodeapp
[PM2] Writing init configuration in /etc/systemd/system/pm2-nodeapp.service
[PM2] Making script booting at startup...
[PM2] [-] Executing: systemctl enable pm2-nodeapp...
[PM2] [v] Command successfully executed.

# ═══ ★★ 步驟二：儲存當前的程序清單（★ 最常被忘記）═══
$ pm2 save
[PM2] Saving current process list...
[PM2] Successfully saved in /var/lib/nodeapp/.pm2/dump.pm2

# ═══ 驗證 ═══
$ systemctl status pm2-nodeapp
● pm2-nodeapp.service - PM2 process manager
     Loaded: loaded (/etc/systemd/system/pm2-nodeapp.service; enabled; ...)
     Active: active (running)

$ sudo systemctl is-enabled pm2-nodeapp
enabled
```

> [!danger] `pm2 save` 是最常被忘記的一步 ★★★
> ```
> pm2 startup  → 建立 systemd service（開機時執行 pm2 resurrect）
> pm2 save     → ★★ 把【當前的程序清單】寫進 dump.pm2
>
> 只做 startup 沒做 save：
>   → 開機時 pm2 resurrect 讀 dump.pm2
>     → 【檔案是空的或是舊的】
>       → 【什麼都沒啟動】或【啟動了舊的設定】
> ```
>
> **★ 每次改動程序清單後都要 `pm2 save`**：
> ```bash
> $ pm2 start new-app.js --name new-app
> $ pm2 save                          # ★★ 不要忘記
>
> $ pm2 delete old-app
> $ pm2 save                          # ★★ 這裡也要
> ```
>
> **驗證是否真的會在開機後啟動**：
> ```bash
> # ★ 模擬重開機
> $ pm2 kill                          # 完全停掉 PM2 daemon
> $ pm2 resurrect                     # 從 dump.pm2 還原
> $ pm2 list                          # ★ 應用回來了嗎？
>
> # ★★ 或直接測試（維護時段）
> $ sudo reboot
> # 開機後
> $ pm2 list
> ```

```bash
# ★ 查看 dump.pm2 的內容
$ cat /var/lib/nodeapp/.pm2/dump.pm2 | jq '.[] | {name, script, exec_mode, instances}'

# ★ 檢查是否與當前執行的一致
$ diff <(pm2 jlist | jq -S '[.[] | {name, script: .pm2_env.pm_exec_path}]') \
       <(jq -S '[.[] | {name, script}]' /var/lib/nodeapp/.pm2/dump.pm2)
```

### 移除開機自啟

```bash
$ pm2 unstartup systemd
$ sudo systemctl disable pm2-nodeapp
$ sudo rm -f /etc/systemd/system/pm2-nodeapp.service
$ sudo systemctl daemon-reload
```

## ★ 更好的方式：用 systemd 直接管理 PM2

> [!tip] 這個做法結合兩者的優點
> ```
> ✓ 取得 PM2 的 cluster 模式與 pm2 reload
> ✓ 取得 systemd 的可靠開機自啟（不需要 pm2 save）
> ✓ 取得 systemd 的安全加固與資源限制
> ✓ 日誌統一進 journald
> ✓ 【設定即程式碼】—— ecosystem.config.js 進 git
> ```

```javascript
// ═══ /var/www/app/ecosystem.config.cjs ═══
module.exports = {
  apps: [{
    name: 'nuxt-app',
    script: '.output/server/index.mjs',
    cwd: '/var/www/app/current',

    // ★ cluster 模式
    exec_mode: 'cluster',
    instances: 2,                    // 或 'max'（= CPU 核心數）

    env: {
      NODE_ENV: 'production',
      HOST: '127.0.0.1',             // ★ 只監聽本機
      PORT: 3000,
    },

    // ★ 資源
    max_memory_restart: '512M',

    // ★ 日誌交給 systemd/journald
    out_file: '/dev/stdout',
    error_file: '/dev/stderr',
    merge_logs: true,
    time: false,                     // journald 自己會加時間戳

    // 重啟策略
    autorestart: true,
    max_restarts: 10,
    min_uptime: '10s',
    restart_delay: 3000,

    // ★ 優雅關閉
    kill_timeout: 5000,
    listen_timeout: 8000,
    wait_ready: false,
  }]
};
```

```ini
# ═══ /etc/systemd/system/pm2-app.service ═══
[Unit]
Description=PM2 managed Nuxt app
Documentation=https://pm2.keymetrics.io/
After=network.target

[Service]
Type=forking
User=nodeapp
Group=nodeapp
WorkingDirectory=/var/www/app/current

Environment="NODE_ENV=production"
Environment="PATH=/usr/bin:/usr/local/bin:/var/lib/nodeapp/.npm-global/bin"
Environment="PM2_HOME=/var/lib/nodeapp/.pm2"
EnvironmentFile=-/var/www/app/shared/.env

# ★ 用 ecosystem 檔案啟動（設定即程式碼）
ExecStart=/usr/bin/pm2 start /var/www/app/ecosystem.config.cjs --no-daemon
ExecReload=/usr/bin/pm2 reload /var/www/app/ecosystem.config.cjs
ExecStop=/usr/bin/pm2 kill

Restart=on-failure
RestartSec=5

StandardOutput=journal
StandardError=journal
SyslogIdentifier=pm2-app

# ★ 安全加固
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=/var/lib/nodeapp/.pm2 /var/www/app/shared/storage /var/www/app/shared/tmp
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictNamespaces=true
LockPersonality=true
RestrictSUIDSGID=true
MemoryDenyWriteExecute=false      # ★★ Node 必須 false

# ★ 資源限制（cgroup 層級，比 PM2 的 max_memory_restart 更可靠）
LimitNOFILE=65535
MemoryMax=1500M
CPUQuota=200%

[Install]
WantedBy=multi-user.target
```

```bash
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now pm2-app
$ sudo systemctl status pm2-app
$ sudo journalctl -u pm2-app -f

# ★ 零停機重載
$ sudo systemctl reload pm2-app
# 或直接
$ sudo -u nodeapp pm2 reload nuxt-app
```

> [!warning] `--no-daemon` 搭配 `Type=forking` 的注意事項
> ```
> pm2 start --no-daemon
>   → PM2 在前景執行（不 fork 成 daemon）
>     → ★ 應該搭配 Type=simple 而非 Type=forking
>
> 但 PM2 的行為在不同版本略有差異，
> ★ 部署後一定要實測：
>   · systemctl start 後 status 是 active (running) 嗎？
>   · systemctl stop 後程序真的都停了嗎？
>   · 重開機後會自動啟動嗎？
> ```
>
> **保險的做法是用 `Type=simple` + `pm2-runtime`**：
> ```ini
> Type=simple
> ExecStart=/usr/bin/pm2-runtime start /var/www/app/ecosystem.config.cjs
> ```
> `pm2-runtime` 是專為容器與 systemd 設計的前景模式。

## 日誌管理

```bash
# ═══ 預設的日誌位置 ═══
$ pm2 describe my-api | grep -E 'out log|error log'
   out log path      │ /var/lib/nodeapp/.pm2/logs/my-api-out.log
   error log path    │ /var/lib/nodeapp/.pm2/logs/my-api-error.log

$ ls -lh /var/lib/nodeapp/.pm2/logs/
-rw-rw-r-- 1 nodeapp nodeapp 1.2G my-api-out.log        # ★★ 沒有輪替會爆掉
-rw-rw-r-- 1 nodeapp nodeapp 340M my-api-error.log
```

> [!danger] PM2 的日誌預設【不會輪替】★★
> ```
> 高流量的應用
>   → 日誌檔持續成長
>     → 幾週後【磁碟滿了】
>       → 所有服務掛掉
> ```
>
> **兩種解法**：

```bash
# ═══ 解法一：pm2-logrotate 模組 ═══
$ pm2 install pm2-logrotate

$ pm2 set pm2-logrotate:max_size 50M
$ pm2 set pm2-logrotate:retain 14              # 保留 14 個檔案
$ pm2 set pm2-logrotate:compress true          # ★ 壓縮
$ pm2 set pm2-logrotate:dateFormat YYYY-MM-DD_HH-mm-ss
$ pm2 set pm2-logrotate:rotateInterval '0 0 * * *'    # 每天午夜
$ pm2 set pm2-logrotate:workerInterval 30
$ pm2 set pm2-logrotate:rotateModule true

# 檢視設定
$ pm2 conf pm2-logrotate
```

```bash
# ═══ 解法二：★ 日誌交給 journald（推薦）═══
# ecosystem.config.cjs
out_file: '/dev/stdout',
error_file: '/dev/stderr',
merge_logs: true,
time: false,
```
```bash
# ★ 用 journalctl 統一查詢
$ sudo journalctl -u pm2-app -f
$ sudo journalctl -u pm2-app --since '1 hour ago'
$ sudo journalctl -u pm2-app -p err
$ sudo journalctl -u pm2-app --since today | grep -i error

# ★ journald 有內建的大小限制與輪替
$ sudo journalctl --disk-usage
$ sudo nano /etc/systemd/journald.conf
# SystemMaxUse=2G
# MaxRetentionSec=30day
$ sudo systemctl restart systemd-journald
```

```bash
# ═══ 解法三：系統的 logrotate ═══
$ sudo tee /etc/logrotate.d/pm2 >/dev/null <<'EOF'
/var/lib/nodeapp/.pm2/logs/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    copytruncate            # ★ 重要：PM2 不會重開檔案，所以用 copytruncate
    create 0640 nodeapp nodeapp
    su nodeapp nodeapp
}
EOF

$ sudo logrotate -d /etc/logrotate.d/pm2      # 測試
```

> [!warning] PM2 的 logrotate 要用 `copytruncate`
> ```
> 一般的 logrotate：改名 → 送訊號讓程式重開檔案
>   → ★ PM2 【不會】處理這個訊號
>     → 繼續寫進已改名的檔案
>       → 新檔案永遠是空的，磁碟一直被佔著
>
> copytruncate：複製內容 → 【截斷原檔案】
>   → PM2 的 fd 還指向同一個檔案（只是被清空了）
>     → ✓ 正常運作
>   → 代價：截斷的瞬間可能遺失幾行日誌
> ```

### 結構化日誌

```javascript
// ★ 用 pino 輸出 JSON 日誌（方便給 ELK / Loki 解析）
import pino from 'pino';

const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
  formatters: {
    level: (label) => ({ level: label }),
  },
  timestamp: pino.stdTimeFunctions.isoTime,
  redact: {                          // ★★ 遮蔽敏感欄位
    paths: ['req.headers.authorization', 'req.headers.cookie',
            '*.password', '*.token', '*.apiKey', '*.secret'],
    censor: '[REDACTED]',
  },
});

logger.info({ userId: 123, action: 'login' }, '使用者登入');
// {"level":"info","time":"2026-08-28T10:15:32.123Z","userId":123,"action":"login","msg":"使用者登入"}
```

```bash
# 查詢 JSON 日誌
$ pm2 logs my-api --raw | jq 'select(.level == "error")'
$ sudo journalctl -u pm2-app -o cat | jq -r 'select(.level=="error") | "\(.time) \(.msg)"'
```

```bash
#!/usr/bin/env bash
# /usr/local/bin/pm2-health —— PM2 健康檢查
FAIL=0
echo "═══ PM2 健康檢查 $(date '+%F %T') ═══"

command -v pm2 >/dev/null || { echo "  ✗ PM2 未安裝"; exit 1; }

echo -e "\n【1】PM2 daemon"
pm2 ping >/dev/null 2>&1 && echo "  ✓ daemon 執行中" || { echo "  ✗✗ daemon 未執行"; FAIL=1; }

echo -e "\n【2】★ 程序狀態"
pm2 jlist 2>/dev/null | jq -r '.[] |
  "  \(if .pm2_env.status == "online" then "✓" else "✗" end) \(.name)  \
狀態=\(.pm2_env.status)  重啟=\(.pm2_env.restart_time)  \
不穩定重啟=\(.pm2_env.unstable_restarts)  \
記憶體=\((.monit.memory/1048576)|floor)MB  CPU=\(.monit.cpu)%  \
運行=\(((now - (.pm2_env.pm_uptime/1000))/3600)|floor)小時"'

echo -e "\n【3】★★ 高重啟次數（可能一直在崩潰）"
pm2 jlist 2>/dev/null | jq -r '.[] | select(.pm2_env.restart_time > 20) |
  "  ⚠⚠ \(.name) 重啟 \(.pm2_env.restart_time) 次【檢查 pm2 logs \(.name) --err】"' || echo "  ✓ 正常"

echo -e "\n【4】★★ 開機自啟設定"
if systemctl list-unit-files 2>/dev/null | grep -q '^pm2-'; then
    U=$(systemctl list-unit-files | grep '^pm2-' | awk '{print $1}')
    for u in $U; do
        E=$(systemctl is-enabled "$u" 2>/dev/null)
        A=$(systemctl is-active "$u" 2>/dev/null)
        echo "  $u: enabled=$E active=$A"
        [ "$E" != "enabled" ] && { echo "    ✗✗ 未設定開機自啟"; FAIL=1; }
    done
else
    echo "  ✗✗ 【沒有 PM2 的 systemd service】"
    echo "     → 重開機後服務不會自動啟動！"
    echo "     → 執行 pm2 startup 並照它的指示做"
    FAIL=1
fi

echo -e "\n【5】★★ dump.pm2 是否與當前一致"
PM2_HOME="${PM2_HOME:-$HOME/.pm2}"
DUMP="$PM2_HOME/dump.pm2"
if [ ! -f "$DUMP" ]; then
    echo "  ✗✗ 【找不到 $DUMP】→ 執行 pm2 save"
    FAIL=1
else
    CUR=$(pm2 jlist 2>/dev/null | jq -S '[.[] | .name] | sort')
    SAVED=$(jq -S '[.[] | .name] | sort' "$DUMP" 2>/dev/null)
    if [ "$CUR" = "$SAVED" ]; then
        echo "  ✓ 一致（$(echo "$CUR" | jq -r 'join(", ")')）"
    else
        echo "  ✗✗ 【不一致 —— 重開機後會啟動錯誤的程序清單】"
        echo "    當前：$(echo "$CUR" | jq -r 'join(", ")')"
        echo "    儲存：$(echo "$SAVED" | jq -r 'join(", ")')"
        echo "    → 執行 pm2 save"
        FAIL=1
    fi
    echo "  dump 最後更新：$(stat -c '%y' "$DUMP" | cut -d. -f1)"
fi

echo -e "\n【6】★ 日誌大小"
LOGDIR="$PM2_HOME/logs"
if [ -d "$LOGDIR" ]; then
    TOTAL=$(du -sm "$LOGDIR" 2>/dev/null | cut -f1)
    echo "  總大小：${TOTAL} MB"
    [ "$TOTAL" -gt 1000 ] && { echo "  ⚠⚠ 日誌超過 1GB【檢查輪替設定】"; FAIL=1; }
    ls -lhS "$LOGDIR"/*.log 2>/dev/null | head -5 | awk '{printf "    %-50s %s\n", $NF, $5}'
fi

echo -e "\n【7】日誌輪替"
pm2 list 2>/dev/null | grep -q 'pm2-logrotate' && echo "  ✓ pm2-logrotate 已安裝" \
  || { [ -f /etc/logrotate.d/pm2 ] && echo "  ✓ 系統 logrotate 已設定" \
       || { echo "  ⚠⚠ 【沒有日誌輪替】→ 日誌會無限成長"; FAIL=1; } }

echo -e "\n【8】★ 監聽的 port"
sudo ss -tlnp 2>/dev/null | grep -i node | while read -r _ _ _ _ addr _; do
    [[ "$addr" == 127.0.0.1:* ]] || [[ "$addr" == "[::1]":* ]] \
      && echo "  ✓ $addr" || echo "  ⚠⚠ $addr【應該只監聽 127.0.0.1】"
done

echo -e "\n【9】記憶體用量"
pm2 jlist 2>/dev/null | jq -r '[.[] | .monit.memory] | add / 1048576 | floor |
  "  PM2 管理的程序共用 \(.) MB"'
free -m | awk '/^Mem:/{printf "  系統可用：%d MB %s\n", $7, ($7 < 500 ? "⚠⚠" : "✓")}'

echo -e "\n【10】近期錯誤"
pm2 logs --err --lines 20 --nostream 2>/dev/null | grep -v '^$' | tail -10 | sed 's/^/  /'

exit $FAIL
```

## PM2 的五個坑

> [!danger] 坑一：忘記 `pm2 save` → 重開機後服務消失
> **見上方「開機自啟」章節。**
> ```bash
> # ★ 每次改動後都要
> $ pm2 save
> # ★ 定期驗證
> $ diff <(pm2 jlist | jq -S '[.[].name]|sort') <(jq -S '[.[].name]|sort' ~/.pm2/dump.pm2)
> ```

> [!danger] 坑二：用 nvm 安裝 Node → 開機後找不到
> ```
> pm2 startup 產生的 service 中：
>   Environment=PATH=/home/user/.nvm/versions/node/v22.11.0/bin:...
>
> → ★ 升級 Node 版本後，這個路徑就不存在了
>   → 【重開機後 PM2 完全起不來】
> ```
> **解法**：用 NodeSource 裝在 `/usr/bin/node`（見 [[060-03-02-01-guide-Node-安裝與版本管理]]）。

> [!danger] 坑三：日誌沒有輪替 → 磁碟被灌滿
> ```bash
> $ du -sh ~/.pm2/logs/
> 12G     /var/lib/nodeapp/.pm2/logs/       # ★★
> ```
> **解法**：`pm2 install pm2-logrotate` 或改用 journald。

> [!danger] 坑四：`pm2 restart` 不是零停機
> ```
> pm2 restart  → ★ 【殺掉舊程序 → 啟動新程序】→ 期間服務中斷
> pm2 reload   → ★★ 【逐一替換 worker】→ 零停機
>
> ★★ 但 reload 【只在 cluster 模式有效】
>    fork 模式下 reload 等同 restart
> ```
> **解法**：正式環境用 `exec_mode: 'cluster'` + `pm2 reload`。
> 見 [[060-03-02-04-guide-PM2-進階設定與部署]]。

> [!danger] 坑五：`--watch` 用在正式環境
> ```javascript
> // ❌❌ 正式環境絕對不要
> { watch: true }
> ```
> ```
> · 部署過程中檔案陸續變更 → 【PM2 瘋狂重啟】
> · 日誌檔變更也可能觸發重啟（若沒排除）
> · 消耗 inotify 資源
> ```
> **`--watch` 只用於開發環境。**

### 從零建立 PM2 管理的 Nuxt 應用

```bash
#!/usr/bin/env bash
set -euo pipefail
APP_NAME="${1:-nuxt-app}"
APP_DIR="/var/www/$APP_NAME"
USER="nodeapp"

echo "═══ 【1】建立使用者與目錄 ═══"
id "$USER" >/dev/null 2>&1 || sudo useradd -r -m -d /var/lib/$USER -s /bin/bash "$USER"
sudo mkdir -p "$APP_DIR"/{releases,shared/{storage,tmp,logs}}
sudo chown -R "$USER:$USER" "$APP_DIR"

echo -e "\n═══ 【2】安裝 PM2 ═══"
command -v pm2 >/dev/null || sudo npm install -g pm2
pm2 --version

echo -e "\n═══ 【3】建立 ecosystem 設定（★ 進 git）═══"
sudo -u "$USER" tee "$APP_DIR/ecosystem.config.cjs" >/dev/null <<EOF
module.exports = {
  apps: [{
    name: '$APP_NAME',
    script: '.output/server/index.mjs',
    cwd: '$APP_DIR/current',

    exec_mode: 'cluster',
    instances: 2,

    env: {
      NODE_ENV: 'production',
      HOST: '127.0.0.1',
      PORT: 3000,
    },

    max_memory_restart: '512M',
    autorestart: true,
    max_restarts: 10,
    min_uptime: '10s',
    restart_delay: 3000,
    kill_timeout: 5000,
    listen_timeout: 8000,

    out_file: '$APP_DIR/shared/logs/out.log',
    error_file: '$APP_DIR/shared/logs/error.log',
    merge_logs: true,
    time: true,

    watch: false,
  }]
};
EOF

echo -e "\n═══ 【4】★ 日誌輪替 ═══"
sudo -u "$USER" pm2 install pm2-logrotate 2>/dev/null || true
sudo -u "$USER" pm2 set pm2-logrotate:max_size 50M
sudo -u "$USER" pm2 set pm2-logrotate:retain 14
sudo -u "$USER" pm2 set pm2-logrotate:compress true

echo -e "\n═══ 【5】啟動 ═══"
cd "$APP_DIR"
sudo -u "$USER" pm2 start ecosystem.config.cjs
sudo -u "$USER" pm2 list

echo -e "\n═══ 【6】★★ 開機自啟 ═══"
STARTUP_CMD=$(sudo -u "$USER" pm2 startup systemd -u "$USER" --hp "/var/lib/$USER" 2>&1 | \
              grep '^sudo' || true)
if [ -n "$STARTUP_CMD" ]; then
    echo "  執行：$STARTUP_CMD"
    eval "$STARTUP_CMD"
fi
sudo -u "$USER" pm2 save                    # ★★ 不要忘記

echo -e "\n═══ 【7】★ 驗證開機自啟 ═══"
systemctl is-enabled "pm2-$USER" >/dev/null 2>&1 && echo "  ✓ service 已啟用" \
  || echo "  ✗✗ service 未啟用"
[ -f "/var/lib/$USER/.pm2/dump.pm2" ] && echo "  ✓ dump.pm2 存在" \
  || echo "  ✗✗ dump.pm2 不存在"

echo -e "\n  ★ 模擬重開機測試："
sudo -u "$USER" pm2 kill
sleep 2
sudo -u "$USER" pm2 resurrect
sleep 3
sudo -u "$USER" pm2 list

echo -e "\n═══ 【8】Nginx 反向代理 ═══"
cat <<'EOF'
  upstream nuxt_backend {
      least_conn;
      server 127.0.0.1:3000;
      keepalive 32;
  }

  server {
      listen 443 ssl;
      http2 on;
      server_name app.example.gov.tw;
      # ... TLS 設定 ...

      # ★ 靜態資源由 Nginx 直接處理
      location /_nuxt/ {
          alias /var/www/nuxt-app/current/.output/public/_nuxt/;
          expires 1y;
          add_header Cache-Control "public, immutable" always;
          access_log off;
      }

      location / {
          proxy_pass http://nuxt_backend;
          proxy_http_version 1.1;
          proxy_set_header Connection "";
          proxy_set_header Host              $host;
          proxy_set_header X-Real-IP         $remote_addr;
          proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_set_header Upgrade           $http_upgrade;
          proxy_set_header Connection        $connection_upgrade;
      }
  }
EOF

echo -e "\n✓ 完成"

## 常見錯誤與排錯

| 現象／錯誤 | 原因 | 解法 |
| --- | --- | --- |
| **重開機後服務消失** ★★★ | **忘記 `pm2 save`** | `pm2 startup` + **`pm2 save`**；驗證 `dump.pm2` |
| **重開機後 PM2 起不來** ★★ | **用 nvm 的 node，路徑變了** | 用 NodeSource 的 `/usr/bin/node` |
| **磁碟被日誌灌滿** ★★ | **PM2 預設不輪替日誌** | `pm2 install pm2-logrotate`；或用 journald |
| `status: errored` | 應用啟動失敗 | `pm2 logs <name> --err --lines 50` |
| **重啟次數持續增加** ★ | 應用不斷崩潰 | 看錯誤日誌；檢查記憶體、port 衝突 |
| **`pm2 restart` 造成服務中斷** ★ | restart 不是零停機 | **cluster 模式 + `pm2 reload`** |
| `pm2 reload` 沒有零停機效果 | **fork 模式下 reload = restart** | 改用 `exec_mode: 'cluster'` |
| **正式環境瘋狂重啟** ★ | **用了 `--watch`** | **正式環境設 `watch: false`** |
| `EADDRINUSE` | port 被佔用 | `ss -tlnp \| grep 3000`；`pm2 delete` 舊的 |
| **PM2 佔用大量記憶體** | daemon 累積 / 日誌 buffer | `pm2 update`；重啟 daemon |
| 環境變數沒生效 | PM2 快取了舊的 env | `pm2 restart <name> --update-env` |
| **logrotate 後日誌不再寫入** | 沒用 `copytruncate` | logrotate 設定加 `copytruncate` |
| `pm2 list` 是空的 | 不同使用者有不同的 PM2 daemon | `sudo -u nodeapp pm2 list`；檢查 `PM2_HOME` |
| **兩個 PM2 daemon 同時跑** | 不同使用者各自啟動 | 統一用一個使用者；`ps aux \| grep PM2` |

## 安全性注意事項

> [!danger] 不要用 root 執行 PM2
> ```bash
> # ❌ 危險
> $ sudo pm2 start app.js
> # → 應用以 root 執行 → 任何漏洞都是 root 級的
>
> # ✅ 用專用使用者
> $ sudo useradd -r -m -d /var/lib/nodeapp -s /bin/bash nodeapp
> $ sudo -u nodeapp pm2 start app.js
> ```
> ```bash
> # ★ 檢查
> $ pm2 jlist | jq -r '.[] | "\(.name): \(.pm2_env.username // "?")"'
> $ ps -o user=,args= -C node | head
> ```

> [!warning] 應用只監聽 127.0.0.1
> ```javascript
> // ecosystem.config.cjs
> env: {
>   HOST: '127.0.0.1',        // ★ 必須
>   PORT: 3000,
> }
> ```
> ```bash
> $ sudo ss -tlnp | grep node
> LISTEN 0 511 127.0.0.1:3000     # ★ 必須是 127.0.0.1
> $ sudo ufw deny 3000/tcp
> ```
> **否則使用者可以繞過 Nginx** —— 繞過 TLS、限流、WAF、安全標頭。

> [!warning] PM2 的 Web 介面與 API
> ```bash
> # ★ pm2-web / pm2-gui 這類模組會開一個 HTTP 介面
> #   它可以【啟動、停止、重啟任何程序，甚至看到環境變數】
> $ pm2 list | grep -i 'web\|gui\|api'
>
> # 若真的需要，一定要：
> #   ① 只監聽 127.0.0.1
> #   ② 用 Nginx 反向代理並加上認證
> #   ③ 限制來源 IP
> ```
>
> **PM2 Plus（keymetrics）** 會把資料送到雲端 ——
> **機關環境要先確認是否符合資料外洩的規範**。

> [!tip] 日誌中的敏感資料
> ```javascript
> // ★ 用 pino 的 redact 遮蔽敏感欄位
> const logger = pino({
>   redact: {
>     paths: ['req.headers.authorization', 'req.headers.cookie',
>             '*.password', '*.token', '*.apiKey', '*.creditCard'],
>     censor: '[REDACTED]',
>   },
> });
> ```
> ```bash
> # ★ 檢查現有日誌中有沒有洩漏
> $ grep -iE 'password|token|secret|api[_-]?key' ~/.pm2/logs/*.log | head
> ```
> **日誌檔的權限也要限制**：
> ```bash
> $ chmod 640 ~/.pm2/logs/*.log
> $ chown nodeapp:adm ~/.pm2/logs/*.log
> ```

## 速查表

### PM2 vs systemd

```
★ systemd：單一程序 · 機關正式環境 · 需要安全加固 · 不想多相依
★ PM2    ：需要 cluster · 需要零停機 reload · 多個 Node 應用
★★ 最佳：【用 systemd 管理 PM2】（取兩者優點）
```

### 基本操作

```bash

pm2 start ecosystem.config.cjs        # ★ 設定即程式碼

pm2 restart api                        # ★ 會中斷
pm2 reload api                         # ★★ 零停機（僅 cluster 模式）
pm2 stop api / pm2 delete api
pm2 logs api --err --lines 100
pm2 flush
pm2 jlist | jq                         # ★ JSON 給監控用

## 小測驗

Q1. **PM2 與 systemd 各適合什麼場景？「systemd + PM2」的組合有什麼優點**？

Q2. **開機自啟需要哪兩個步驟？哪一個最常被忘記？後果是什麼**？

Q3. **怎麼驗證「重開機後服務真的會起來」**？

Q4. **`pm2 list` 中的 `↺`（重啟次數）為什麼是重要指標**？

Q5. **`pm2 restart` 與 `pm2 reload` 的差別？reload 的前提是什麼**？

Q6. **PM2 的日誌預設會輪替嗎？有哪三種解法**？

Q7. **用系統 logrotate 處理 PM2 日誌時，為什麼要用 `copytruncate`**？

Q8. **用 nvm 安裝 Node 對 PM2 開機自啟會造成什麼問題**？

Q9. **正式環境為什麼不能用 `--watch`**？

Q10. **PM2 的五個常見坑是什麼**？

> [!question]- 測驗答案
> **Q1.** **systemd 適合**：單一程序、機關的正式環境（維運人員熟悉）、
> 需要嚴格的安全加固（沙箱、命名空間、cgroup 資源限制）、不想多一層相依。
> **PM2 適合**：需要 **cluster 模式**（多核心）、需要**零停機 reload**、
> 同一台機器有多個 Node 應用要管理、開發者自行維運。
> **「systemd 管理 PM2」的優點**：
> **取得 PM2 的 cluster 與 reload，同時保有 systemd 的可靠開機自啟
> （不需要 `pm2 save`）、安全加固、cgroup 資源限制，
> 日誌統一進 journald，而且 `ecosystem.config.cjs` 進 git（設定即程式碼）**。
>
> **Q2.** ①**`pm2 startup`** —— 產生 systemd service（開機時執行 `pm2 resurrect`）；
> ②**`pm2 save`** —— **把當前的程序清單寫進 `dump.pm2`**。
> **最常被忘記的是 `pm2 save`**。
> **後果**：開機時 `pm2 resurrect` 讀取 `dump.pm2`，
> **檔案是空的或是舊的 → 什麼都沒啟動，或啟動了錯誤的舊設定** ——
> 而且**不會有任何錯誤訊息**，通常是使用者回報「網站掛了」才發現。
> **★ 每次改動程序清單（start / delete）後都要重新 `pm2 save`。**
>
> **Q3.** **三個層次的驗證**：
> ①**檢查 systemd service**：
> ```bash
> systemctl is-enabled pm2-nodeapp    # 應為 enabled
> ```
> ②**比對 `dump.pm2` 與當前的程序清單**：
> ```bash
> diff <(pm2 jlist | jq -S '[.[].name]|sort') \
>      <(jq -S '[.[].name]|sort' ~/.pm2/dump.pm2)
> ```
> ③**模擬重開機**：
> ```bash
> pm2 kill && pm2 resurrect && pm2 list     # 應用回來了嗎？
> ```
> ④**最可靠：在維護時段真的重開機一次**。
> 建議把①與②寫成排程的健康檢查。
>
> **Q4.** 因為**應用崩潰後 PM2 會自動重啟，所以 `pm2 list` 顯示的狀態
> 仍然是 `online`「看起來一切正常」** ——
> 但**重啟次數持續增加就代表應用一直在崩潰**，
> 使用者會**間歇性遇到 502 或請求失敗**，
> 而這個問題**可能一直沒被發現**（因為監控只看「服務是否 online」）。
> ```bash
> pm2 jlist | jq -r '.[] | select(.pm2_env.restart_time > 20) |
>   "⚠ \(.name) 重啟 \(.pm2_env.restart_time) 次"'
> ```
> **應該把重啟次數加進監控告警。**
>
> **Q5.** **`pm2 restart`**：**殺掉舊程序 → 啟動新程序**，
> 期間**服務中斷**（幾秒到十幾秒）。
> **`pm2 reload`**：**逐一替換 worker**（啟動新的 → 等它 ready → 關掉舊的），
> **零停機**。
> **★★ reload 的前提是 `exec_mode: 'cluster'`** ——
> **在 fork 模式下 `reload` 等同於 `restart`，沒有零停機效果**。
> 所以正式環境應該設定：
> ```javascript
> exec_mode: 'cluster',
> instances: 2,          // 至少 2 個才有意義
> ```
>
> **Q6.** **PM2 的日誌預設「不會」輪替** ——
> 高流量的應用日誌會持續成長，**幾週後磁碟就滿了，所有服務掛掉**。
> **三種解法**：
> ①**`pm2 install pm2-logrotate`** 模組：
> ```bash
> pm2 set pm2-logrotate:max_size 50M
> pm2 set pm2-logrotate:retain 14
> pm2 set pm2-logrotate:compress true
> ```
> ②**★ 把日誌交給 journald**（推薦）——
> ecosystem 中設 `out_file: '/dev/stdout'`、`error_file: '/dev/stderr'`，
> journald 有內建的大小限制與保留期，且可以用 `journalctl` 統一查詢；
> ③**系統的 logrotate**（★ 必須用 `copytruncate`，見 Q7）。
>
> **Q7.** 因為**一般的 logrotate 流程是「把檔案改名 → 送訊號讓程式重新開啟檔案」，
> 但 PM2 不會處理這個訊號** ——
> 結果是 PM2 **繼續寫進已經改名的檔案**，
> **新的日誌檔永遠是空的，而磁碟空間一直被舊的 fd 佔著**
> （即使檔案被刪除也不會釋放）。
> **`copytruncate` 的做法是「複製內容出去 → 截斷原檔案」** ——
> PM2 的 file descriptor 還指向同一個 inode（只是內容被清空了），所以能正常繼續寫。
> **代價**：截斷的瞬間可能遺失幾行日誌。
>
> **Q8.** `pm2 startup` 產生的 systemd service 中會寫入**當時的 PATH**：
> ```ini
> Environment=PATH=/home/user/.nvm/versions/node/v22.11.0/bin:...
> ```
> **升級 Node 版本後（例如換到 v22.12.0），這個路徑就不存在了** →
> **重開機後 PM2 完全起不來**，
> 而且錯誤訊息在 `journalctl -u pm2-user` 中，容易被忽略。
> 另外 nvm 本身依賴 shell function，**systemd 環境中不會載入 `~/.bashrc`**。
> **解法**：正式環境用 **NodeSource 裝在 `/usr/bin/node`**，
> 或用官方 tarball + `/opt/node/current` 符號連結。
>
> **Q9.** ①**部署過程中檔案會陸續變更**（`git pull`、`npm ci`、`npm run build`）
> → **PM2 會瘋狂重啟**，可能重啟數十次，服務長時間不穩定；
> ②**日誌檔的變更也可能觸發重啟**（若沒有正確排除），造成無窮迴圈；
> ③**消耗大量 inotify watch 資源**（大型專案的 `node_modules` 有數萬個檔案），
> 可能達到系統的 `fs.inotify.max_user_watches` 上限。
> **`--watch` / `watch: true` 只用於開發環境。**
>
> **Q10.** ①**忘記 `pm2 save`** → 重開機後服務消失（★★★ 最常見）；
> ②**用 nvm 安裝的 Node** → 升級版本後開機起不來；
> ③**日誌沒有輪替** → 磁碟被灌滿導致全部服務掛掉；
> ④**`pm2 restart` 不是零停機** → 要用 `cluster` 模式 + `pm2 reload`；
> ⑤**正式環境用 `--watch`** → 部署時瘋狂重啟。
> **加上兩個安全相關的**：用 root 執行 PM2、應用監聽 `0.0.0.0` 而非 `127.0.0.1`。
