# PHP 安裝與多版本管理

> [!abstract] 這篇你會學到
> - 用 **ondrej PPA**（Debian 系）與 **Remi**（RHEL 系）安裝任意 PHP 版本
> - 讓**多個 PHP 版本在同一台機器共存**
> - 分清 **CLI 與 FPM 用的是不同的 `php.ini`**（最常踩的坑）
> - 安裝 Laravel / Nuxt 專案需要的**完整擴充套件清單**
> - 用 **`update-alternatives`** 切換 CLI 的預設版本
> - 規劃**安全的 PHP 版本升級流程**

  Selection    Path             Priority   Status
------------------------------------------------------------

> [!danger] CLI 的版本與 FPM 的版本是【獨立】的 ★★
> ```
> php -v                    → 顯示【CLI】的版本
> curl 網站/phpinfo.php     → 顯示【FPM】的版本
>
> ★ 這兩個【可以不同】，而且經常不同！
> ```
>
> **這造成的真實問題**：
> ```
> ① composer install 用 CLI（8.1）→ 產生的 vendor/ 相依於 8.1
>    網站用 FPM（8.3）執行        → 【可能出現相容性錯誤】
>
> ② php artisan migrate 用 CLI（8.1）
>    網站用 FPM（8.3）
>    → 兩者的擴充套件可能不同 → 【CLI 可以跑，網頁不行】
>
> ③ cron 中的 `php artisan schedule:run` 用的是【CLI 預設版本】
>    → 與網站不同版本 → 難以察覺的問題
> ```
>
> **解法：在 cron 與部署腳本中明確指定版本**：
> ```bash
> # ❌ 依賴預設版本
> * * * * * cd /var/www/app && php artisan schedule:run
>
> # ✅ 明確指定
> * * * * * cd /var/www/app && /usr/bin/php8.3 artisan schedule:run
> ```
> ```bash
> # composer 也要
> $ /usr/bin/php8.3 /usr/local/bin/composer install --no-dev
> ```

```bash
#!/usr/bin/env bash
# 檢查 CLI 與 FPM 的版本是否一致
echo "═══ PHP 版本檢查 ═══"

echo -e "\n【CLI】"
echo "  預設：$(php -v 2>/dev/null | head -1)"
echo "  路徑：$(readlink -f "$(which php)")"

echo -e "\n【已安裝的版本】"
ls -1 /etc/php/ 2>/dev/null | sed 's/^/  /'

echo -e "\n【FPM 服務】"
systemctl list-units --type=service --all 2>/dev/null | grep -oP 'php[0-9.]*-fpm\.service' | \
  sort -u | while read -r s; do
    v="${s#php}"; v="${v%-fpm.service}"
    printf '  %-22s %s\n' "$s" "$(systemctl is-active "$s")"
done

echo -e "\n【★ 各站台使用的 FPM 版本】"
if command -v nginx >/dev/null; then
    sudo nginx -T 2>/dev/null | grep -oP 'fastcgi_pass\s+unix:\K\S+' | tr -d ';' | sort -u | \
      sed 's/^/  Nginx → /'
fi
if command -v apache2ctl >/dev/null; then
    sudo apache2ctl -t -D DUMP_CONFIG 2>/dev/null | \
      grep -oP 'SetHandler "proxy:unix:\K[^|]+' | sort -u | sed 's/^/  Apache → /'
fi

echo -e "\n【★ cron 中使用的版本】"
{ crontab -l 2>/dev/null; sudo cat /etc/cron.d/* 2>/dev/null; } | grep -E '\bphp\b' | \
  sed 's/^/  /' || echo "  （無）"
echo "  ★ 應該明確寫成 /usr/bin/php8.3 而非 php"

echo -e "\n【★ CLI 與 FPM 的擴充套件差異】"
CLI_EXT=$(php -m 2>/dev/null | grep -v '^\[' | sort)
V=$(php -r 'echo PHP_MAJOR_VERSION.".".PHP_MINOR_VERSION;' 2>/dev/null)
FPM_INI="/etc/php/$V/fpm/php.ini"
if [ -f "$FPM_INI" ]; then
    FPM_EXT=$(php -c "$FPM_INI" -m 2>/dev/null | grep -v '^\[' | sort)
    diff <(echo "$CLI_EXT") <(echo "$FPM_EXT") | sed 's/^/  /' || echo "  ✓ 一致"
fi
```

### 擴充的啟用與停用

```bash
# 已載入的擴充
$ php -m
[PHP Modules]

Core
ctype
curl
...

# 擴充的設定檔
$ ls -l /etc/php/8.3/mods-available/
redis.ini

imagick.ini

$ ls -l /etc/php/8.3/fpm/conf.d/
20-curl.ini -> /etc/php/8.3/mods-available/curl.ini
20-mbstring.ini -> ...

# ★ 啟用／停用（Debian 系）
$ sudo phpenmod -v 8.3 -s fpm redis
$ sudo phpdismod -v 8.3 -s cli xdebug        # ★ 只停 CLI 的
$ sudo systemctl restart php8.3-fpm

# -s 的可選值：cli / fpm / apache2 / ALL
```

> [!warning] Xdebug 絕對不要裝在正式環境
> ```
> Xdebug 會讓 PHP 慢【2-5 倍】
>   → 即使沒有啟用 profiler 也一樣
>
> 而且 xdebug.remote_connect_back = 1（舊版預設）
>   → ★ 任何人都能連進來執行程式碼
> ```
> ```bash
> # ★ 檢查正式環境
> $ php -m | grep -i xdebug && echo "⚠⚠ 正式環境有 Xdebug！"
> $ curl -s https://網站/phpinfo.php | grep -i xdebug
>
> # 移除
> $ sudo phpdismod -v 8.3 -s ALL xdebug
> $ sudo apt remove -y php8.3-xdebug
> $ sudo systemctl restart php8.3-fpm
> ```

## `php.ini`：CLI 與 FPM 是分開的 ★★

```bash
# ═══ 找出各自的設定檔 ═══
$ php --ini
Configuration File (php.ini) Path: /etc/php/8.3/cli
Loaded Configuration File:         /etc/php/8.3/cli/php.ini      ★ CLI 的
Scan for additional .ini files in: /etc/php/8.3/cli/conf.d
Additional .ini files parsed:      /etc/php/8.3/cli/conf.d/10-opcache.ini, ...

# ★ FPM 的要從 phpinfo() 看
$ echo '<?php phpinfo();' | sudo tee /var/www/html/_i.php
$ curl -s http://127.0.0.1/_i.php | grep -A1 'Loaded Configuration File'
/etc/php/8.3/fpm/php.ini      ★ FPM 的（不同！）
$ sudo rm /var/www/html/_i.php
```

```
/etc/php/8.3/
├── cli/
│   ├── php.ini              ★ CLI 用（artisan、composer、cron）
│   └── conf.d/
├── fpm/
│   ├── php.ini              ★ FPM 用（網頁請求）★ 改這個
│   ├── php-fpm.conf
│   ├── pool.d/
│   │   └── www.conf         ★ pool 設定
│   └── conf.d/
└── mods-available/
```

> [!danger] 「改了 php.ini 沒生效」的三個原因
> ```
> ① ★ 改到 CLI 的 php.ini（要改 fpm/php.ini）
> ② ★ 沒有重啟 FPM（systemctl restart php8.3-fpm）
> ③ ★ 被 pool 設定的 php_admin_value[] 覆蓋
> ```
>
> **正確的驗證方式**：
> ```bash
> # ★ 從網頁確認（不是用 php -i）
> $ echo '<?php echo ini_get("upload_max_filesize");' | \
>     sudo tee /var/www/html/_v.php
> $ curl -s http://127.0.0.1/_v.php
> 100M
> $ sudo rm /var/www/html/_v.php
> ```
>
> **三處設定的優先順序（後面覆蓋前面）**：
> ```
> ① /etc/php/8.3/fpm/php.ini
> ② /etc/php/8.3/fpm/conf.d/*.ini
> ③ /etc/php/8.3/fpm/pool.d/www.conf 的 php_value[] / php_admin_value[]  ★ 最高
> ```

## 完整實戰範例

### 一鍵安裝 LXMP 的 PHP 環境

```bash
#!/usr/bin/env bash
# 安裝 PHP 環境（Laravel + Nuxt 專案適用）
set -euo pipefail
PHPV="${1:-8.3}"

echo "═══ 安裝 PHP $PHPV ═══"

echo -e "\n【1】套件庫"
if ! grep -rq 'ondrej/php' /etc/apt/sources.list.d/ 2>/dev/null; then
    sudo apt update
    sudo apt install -y software-properties-common
    sudo add-apt-repository -y ppa:ondrej/php
    sudo apt update
fi

echo -e "\n【2】安裝"
sudo apt install -y \
    "php${PHPV}-cli" "php${PHPV}-fpm" "php${PHPV}-common" \
    "php${PHPV}-mbstring" "php${PHPV}-xml" "php${PHPV}-curl" \
    "php${PHPV}-zip" "php${PHPV}-bcmath" "php${PHPV}-intl" \
    "php${PHPV}-mysql" "php${PHPV}-pgsql" "php${PHPV}-sqlite3" \
    "php${PHPV}-gd" "php${PHPV}-opcache" "php${PHPV}-redis" \
    "php${PHPV}-igbinary" "php${PHPV}-soap" "php${PHPV}-ldap"

echo -e "\n【3】Composer"
if ! command -v composer >/dev/null; then
    EXPECTED=$(curl -sS https://composer.github.io/installer.sig)
    curl -sS https://getcomposer.org/installer -o /tmp/composer-setup.php
    ACTUAL=$(php -r "echo hash_file('sha384', '/tmp/composer-setup.php');")
    if [ "$EXPECTED" != "$ACTUAL" ]; then
        echo "  ✗✗ Composer 安裝程式的雜湊不符，中止"; exit 1
    fi
    sudo "php${PHPV}" /tmp/composer-setup.php --install-dir=/usr/local/bin --filename=composer
    rm -f /tmp/composer-setup.php
fi
composer --version

echo -e "\n【4】設定 CLI 預設版本"
sudo update-alternatives --set php "/usr/bin/php${PHPV}"
php -v | head -1

echo -e "\n【5】基本的 php.ini 調整（FPM）"
INI="/etc/php/${PHPV}/fpm/php.ini"
sudo cp "$INI" "$INI.bak.$(date +%Y%m%d)"
sudo tee "/etc/php/${PHPV}/fpm/conf.d/99-custom.ini" >/dev/null <<'EOF'
; ═══ 基本 ═══
memory_limit = 512M
max_execution_time = 60
max_input_time = 60
max_input_vars = 3000

; ═══ 上傳 ═══
upload_max_filesize = 50M
post_max_size = 64M          ; ★ 要比 upload_max_filesize 大
max_file_uploads = 20

; ═══ 錯誤（★ 正式環境）═══
display_errors = Off
display_startup_errors = Off
log_errors = On
error_log = /var/log/php/fpm-error.log
error_reporting = E_ALL & ~E_DEPRECATED & ~E_STRICT

; ═══ 安全 ═══
expose_php = Off
cgi.fix_pathinfo = 0         ; ★★ 極重要
allow_url_fopen = On
allow_url_include = Off      ; ★★ 極重要
session.cookie_httponly = 1
session.cookie_secure = 1
session.cookie_samesite = Lax
session.use_strict_mode = 1

; ═══ 時區與編碼 ═══
date.timezone = Asia/Taipei
default_charset = UTF-8

; ═══ OPcache（見 05 篇）═══
opcache.enable = 1
opcache.memory_consumption = 256
opcache.max_accelerated_files = 20000
opcache.validate_timestamps = 0    ; ★ 正式環境；部署後要 reload FPM
EOF

sudo mkdir -p /var/log/php
sudo chown www-data:www-data /var/log/php

echo -e "\n【6】重啟"
sudo systemctl restart "php${PHPV}-fpm"
sudo systemctl enable "php${PHPV}-fpm"

echo -e "\n【7】驗證"
echo "  CLI：$(php -v | head -1)"
echo "  FPM：$(systemctl is-active "php${PHPV}-fpm")"
echo "  Socket：$(ls -l "/run/php/php${PHPV}-fpm.sock" 2>/dev/null || echo '★ 不存在')"

echo -e "\n  ── Laravel 必要擴充 ──"
for e in bcmath ctype curl dom fileinfo mbstring openssl pdo tokenizer xml zip; do
    php -m | grep -qi "^$e$" && printf '  ✓ %s\n' "$e" || printf '  ✗ %s\n' "$e"
done

echo -e "\n  ── 安全檢查 ──"
for k in expose_php cgi.fix_pathinfo allow_url_include display_errors; do
    printf '  %-22s %s\n' "$k" "$(php -r "echo ini_get('$k') ?: '0';")"
done
php -m | grep -qi xdebug && echo "  ⚠⚠ 有 Xdebug（正式環境應移除）"

echo -e "\n✓ 完成"
```

### 版本升級流程

```bash
#!/usr/bin/env bash
# PHP 版本升級（★ 漸進式，可隨時回退）
set -euo pipefail
OLD="${1:?舊版本，例如 8.1}"
NEW="${2:?新版本，例如 8.3}"

echo "═══ PHP $OLD → $NEW 升級 ═══"

echo -e "\n【1】★ 安裝新版（舊版繼續跑）"
EXTS=$(dpkg -l | grep -oP "php${OLD}-\K\S+" | grep -vE '^(cli|fpm|common)$' | sort -u)
echo "  舊版的擴充：$(echo "$EXTS" | tr '\n' ' ')"
PKGS="php${NEW}-cli php${NEW}-fpm php${NEW}-common"
for e in $EXTS; do
    apt-cache show "php${NEW}-$e" >/dev/null 2>&1 && PKGS="$PKGS php${NEW}-$e" \
      || echo "  ⚠ php${NEW}-$e 不存在（可能已內建或改名）"
done
echo "  將安裝：$PKGS"
sudo apt install -y $PKGS

echo -e "\n【2】★ 複製設定"
sudo cp -a "/etc/php/${OLD}/fpm/conf.d/99-custom.ini" \
           "/etc/php/${NEW}/fpm/conf.d/99-custom.ini" 2>/dev/null || \
  echo "  （沒有自訂設定，請手動比對 php.ini）"
sudo diff "/etc/php/${OLD}/fpm/php.ini" "/etc/php/${NEW}/fpm/php.ini" | head -30

echo -e "\n【3】★ 複製 pool 設定"
for p in /etc/php/${OLD}/fpm/pool.d/*.conf; do
    [ -e "$p" ] || continue
    n=$(basename "$p")
    [ "$n" = "www.conf" ] && continue
    sudo cp -n "$p" "/etc/php/${NEW}/fpm/pool.d/$n"
    # ★ socket 路徑要改
    sudo sed -i "s/php${OLD}-fpm/php${NEW}-fpm/g" "/etc/php/${NEW}/fpm/pool.d/$n"
    echo "  複製 $n"
done

echo -e "\n【4】啟動新版"
sudo systemctl enable --now "php${NEW}-fpm"
sudo systemctl status "php${NEW}-fpm" --no-pager -n 5

echo -e "\n【5】★ 檢查專案相容性"
if [ -f /var/www/app/composer.json ]; then
    cd /var/www/app
    "/usr/bin/php${NEW}" /usr/local/bin/composer check-platform-reqs 2>&1 | sed 's/^/  /'
fi

echo -e "\n【6】★ 建立測試站台（不影響正式）"
cat <<EOF
  在 Nginx 加一個測試站台：

  server {
      listen 8443 ssl;
      server_name test.example.local;
      root /var/www/app/current/public;
      location ~ \.php\$ {
          try_files \$uri =404;
          fastcgi_pass unix:/run/php/php${NEW}-fpm.sock;   # ★ 新版
          include snippets/php-fpm.conf;
      }
  }

  然後：
    ① 跑完整的測試套件
    ② 人工驗收所有主要功能
    ③ 檢查 error log 有沒有 Deprecated / Warning
       sudo tail -f /var/log/php/fpm-error.log
EOF

echo -e "\n【7】★ 切換正式站台（確認測試通過後）"
cat <<EOF
  # Nginx
  sudo sed -i 's/php${OLD}-fpm.sock/php${NEW}-fpm.sock/g' /etc/nginx/sites-available/*
  sudo nginx -t && sudo systemctl reload nginx

  # Apache
  sudo sed -i 's/php${OLD}-fpm.sock/php${NEW}-fpm.sock/g' /etc/apache2/sites-available/*
  sudo apache2ctl configtest && sudo systemctl reload apache2

  # CLI 與 cron
  sudo update-alternatives --set php /usr/bin/php${NEW}
  sudo sed -i 's|/usr/bin/php${OLD}|/usr/bin/php${NEW}|g' /etc/cron.d/*

  # ★ 回退（只要改回去 + reload，秒級）
  sudo sed -i 's/php${NEW}-fpm.sock/php${OLD}-fpm.sock/g' /etc/nginx/sites-available/*
  sudo systemctl reload nginx
EOF

echo -e "\n【8】穩定後移除舊版（★ 至少觀察兩週）"
echo "  sudo systemctl disable --now php${OLD}-fpm"
echo "  sudo apt remove -y 'php${OLD}-*'"
```

## 常見錯誤與排錯

| 現象／錯誤 | 原因 | 解法 |
| --- | --- | --- |
| **改了 `php.ini` 沒生效** ★★ | 改到 CLI 的 / 沒重啟 FPM / 被 pool 覆蓋 | 改 `fpm/php.ini`；`restart php8.3-fpm`；檢查 `pool.d/` |
| **`php -v` 與網頁的版本不同** ★ | **CLI 與 FPM 是獨立的** | 這是正常的；用 `update-alternatives` 切 CLI |
| **cron 用錯版本** ★ | 依賴 `php` 的預設連結 | **明確寫 `/usr/bin/php8.3`** |
| `Class "X" not found`（擴充相關） | 擴充沒裝或沒啟用 | `php -m`；`phpenmod`；`restart` |
| **CLI 可以跑但網頁不行** | 兩者的擴充不同 | 比對 `php -m` 與 `phpinfo()` |
| `composer install` 說缺擴充 | CLI 的擴充不足 | 裝對應的 `php8.3-xxx` |
| **正式環境很慢（2-5 倍）** ★ | **有 Xdebug** | `phpdismod -s ALL xdebug` + 移除套件 |
| 上傳大檔失敗 | 三處限制不一致 | Nginx `client_max_body_size` + PHP `upload_max_filesize` + `post_max_size` |
| `post_max_size` 比 `upload_max_filesize` 小 | 設定順序錯 | **`post_max_size` 要比較大** |
| RHEL 只能裝一個版本 | 模組串流限制 | 用 Remi 的 `phpXX-php-*` 套件（`/opt/remi/`） |
| `add-apt-repository` 失敗 | 缺套件 | `apt install software-properties-common` |
| 升級後大量 Deprecated | 新版的行為變更 | 看 error log；調 `error_reporting`；修正程式碼 |
| **socket 路徑改了但沒改 Web 設定** | 升級時漏改 | `nginx -T \| grep fastcgi_pass` 確認 |

## 安全性注意事項

> [!danger] 四個必須的 php.ini 設定
> ```ini
> ; ① ★★ 防 PathInfo 攻擊（上傳的 jpg 被當 PHP 執行）
> cgi.fix_pathinfo = 0
>
> ; ② ★★ 防遠端檔案包含（RFI）
> allow_url_include = Off
>
> ; ③ ★ 不要洩漏 PHP 版本
> expose_php = Off
>
> ; ④ ★ 不要把錯誤訊息顯示給使用者
> display_errors = Off
> display_startup_errors = Off
> log_errors = On
> error_log = /var/log/php/fpm-error.log
> ```
>
> ```bash
> # ★ 驗證（從網頁，不是 CLI）
> $ curl -sI https://網站/ | grep -i x-powered-by     # 應該沒有
> $ echo '<?php echo ini_get("cgi.fix_pathinfo");' > public/_c.php
> $ curl -s https://網站/_c.php                        # 應該是 0 或空
> ```

> [!warning] 不要在正式環境放 `phpinfo.php`
> ```
> phpinfo() 洩漏：
>   · PHP 版本與所有擴充版本（→ 查對應的 CVE）
>   · 完整的檔案系統路徑
>   · 所有環境變數（★ 可能含資料庫密碼）
>   · 已載入的設定檔路徑
>   · 伺服器軟體與版本
> ```
> ```bash
> # ★ 檢查
> $ sudo find /var/www -name '*.php' -exec grep -l 'phpinfo' {} \; 2>/dev/null
> $ for p in /phpinfo.php /info.php /i.php /test.php /php.php /_i.php; do
>     curl -sk -o /dev/null -w "$p %{http_code}\n" https://網站$p
>   done      # ★ 全部應該是 404
> ```
> **需要時用 CLI**：`php -i | grep xxx`

> [!tip] 及早規劃版本升級
> ```
> PHP 的支援週期：
>   主動支援 2 年 → 只修安全性 1 年 → 完全結束
>
> 建議節奏：
>   · 每年檢視一次版本狀態
>   · 【安全性支援結束前 6 個月】開始規劃升級
>   · 用多版本共存做漸進式升級（見上方腳本）
>   · 升級後【觀察兩週】再移除舊版
> ```
> ```bash
> # 加進例行巡檢
> $ php -v | head -1
> $ php -r 'echo PHP_VERSION_ID < 80200 ? "⚠ 版本過舊\n" : "✓\n";'
> ```

## 小測驗

Q1. **怎麼查詢一個 PHP 版本的支援狀態？跑 EOL 版本有什麼風險**？

Q2. **Debian 系與 RHEL 系各用什麼套件庫安裝新版 PHP？RHEL 的多版本共存有什麼限制**？

Q3. **CLI 與 FPM 的 PHP 版本是同一個嗎？這會造成哪三種問題**？

Q4. **`update-alternatives --set php` 之後，網頁的 PHP 版本會跟著變嗎？為什麼**？

Q5. **「改了 `php.ini` 沒生效」有哪三個原因？怎麼正確驗證**？

Q6. **PHP 設定的三處來源與優先順序是什麼**？

Q7. **Laravel 的必要擴充有哪些？怎麼檢查專案實際需要什麼**？

Q8. **Xdebug 為什麼絕對不能裝在正式環境**？

Q9. **上傳大檔需要哪三處設定一致？`post_max_size` 與 `upload_max_filesize` 誰要大**？

Q10. **漸進式的 PHP 版本升級流程是什麼？回退成本多高**？

> [!question]- 測驗答案
> **Q1.** 到 **<https://www.php.net/supported-versions.php>** 查詢，
> 或 `curl -s 'https://www.php.net/releases/index.php?json'`。
> PHP 的支援週期是**主動支援 2 年 → 只修安全性 1 年 → 完全結束**。
> **跑 EOL 版本的風險**：**之後發現的所有漏洞都不會修補**，
> 而這些漏洞往往有**公開的 exploit**，掃描器每天都在尋找這種目標。
> **絕大多數的入侵不是因為設定不精巧，而是因為跑著沒更新的軟體。**
> 建議「安全性支援結束前 6 個月」就開始規劃升級。
>
> **Q2.** **Debian / Ubuntu 用 `ppa:ondrej/php`**
> （Debian 用 `packages.sury.org`）：
> ```bash
> sudo add-apt-repository -y ppa:ondrej/php && sudo apt update
> ```
> **RHEL / Rocky 用 EPEL + Remi**：
> ```bash
> sudo dnf install -y epel-release
> sudo dnf install -y https://rpms.remirepo.net/enterprise/remi-release-9.rpm
> sudo dnf module reset php -y && sudo dnf module enable php:remi-8.3 -y
> ```
> **RHEL 多版本的限制**：**模組串流（module stream）一次只能啟用一個版本** ——
> 要多版本共存必須改用 Remi 的獨立套件（`php81-php-fpm`、`php83-php-fpm`），
> 它們安裝在 **`/opt/remi/phpXX/`** 下，可以並存。
>
> **Q3.** **不是同一個** —— CLI 與 FPM 是**完全獨立的執行環境**，
> 各自有自己的版本、自己的 `php.ini`、自己的擴充清單。
> **三種問題**：
> ①**`composer install` 用 CLI（8.1）產生的 `vendor/` 相依於 8.1，
> 但網站用 FPM（8.3）執行 → 可能出現相容性錯誤**；
> ②**`php artisan migrate` 用 CLI，網站用 FPM，
> 兩者的擴充可能不同 → CLI 可以跑，網頁不行**；
> ③**cron 中的 `php artisan schedule:run` 用的是 CLI 的預設版本**，
> 與網站不同版本，產生難以察覺的問題。
> **解法：在 cron 與部署腳本中明確指定 `/usr/bin/php8.3`。**
>
> **Q4.** **不會**。
> `update-alternatives --set php` 只是改變 **`/usr/bin/php` 這個符號連結**
> 指向哪一個版本的 CLI 執行檔 ——
> 它**完全不影響 FPM**。
> **網頁用的是哪個版本，取決於 Web 伺服器的設定指向哪個 FPM socket**：
> ```nginx
> fastcgi_pass unix:/run/php/php8.3-fpm.sock;    # ★ 這裡決定
> ```
> ```apache
> SetHandler "proxy:unix:/run/php/php8.3-fpm.sock|fcgi://localhost"
> ```
> 要切換網頁的版本，必須改這一行並 reload Web 伺服器。
>
> **Q5.** ①**改到了 CLI 的 `php.ini`**（`/etc/php/8.3/cli/php.ini`），
> 網頁用的是 `/etc/php/8.3/fpm/php.ini`；
> ②**沒有重啟 FPM**（`sudo systemctl restart php8.3-fpm`）；
> ③**被 pool 設定的 `php_admin_value[]` 覆蓋**
> （`/etc/php/8.3/fpm/pool.d/*.conf` 的優先權最高）。
> **正確的驗證方式是從網頁看，不是用 `php -i`**：
> ```bash
> echo '<?php echo ini_get("memory_limit");' > /var/www/html/_v.php
> curl -s http://127.0.0.1/_v.php
> rm /var/www/html/_v.php
> ```
> 找出設定在哪被設的：`grep -rn 'memory_limit' /etc/php/8.3/fpm/`。
>
> **Q6.** 由低到高（後面覆蓋前面）：
> ①**`/etc/php/8.3/fpm/php.ini`**（主設定檔）→
> ②**`/etc/php/8.3/fpm/conf.d/*.ini`**（額外設定，依檔名順序載入）→
> ③**`/etc/php/8.3/fpm/pool.d/*.conf` 中的
> `php_value[]` / `php_admin_value[]`**（**優先權最高**）。
> 另外 `php_admin_value[]` 與 `php_value[]` 的差別是：
> **`php_admin_*` 不能被應用程式的 `ini_set()` 覆蓋**，
> 所以**安全設定一律用 `php_admin_*`**。
>
> **Q7.** **Laravel 必要**：`bcmath`、`ctype`、`curl`、`dom`、`fileinfo`、
> `json`、`mbstring`、`openssl`、`pcre`、`pdo`、`session`、`tokenizer`、`xml`。
> **實務常加**：`zip`（Composer）、`intl`（國際化）、`gd`/`imagick`（圖片）、
> `opcache`（效能必備）、`redis`+`igbinary`（session/cache/queue）、
> `mysql`/`pgsql`、`soap`、`ldap`（AD 整合）。
> **檢查專案實際需要什麼**：
> ```bash
> cd /var/www/app
> composer check-platform-reqs
> ```
> 它會列出所有相依套件宣告的平台需求，並標示 success / missing。
>
> **Q8.** 因為 **Xdebug 會讓 PHP 慢 2-5 倍** ——
> **即使沒有啟用 profiler 或 step debugger 也一樣**
> （它會在每個函式呼叫插入 hook）。
> 另外還有安全問題：舊版的 `xdebug.remote_connect_back = 1` 設定
> **會讓任何人都能連進來執行程式碼**。
> ```bash
> # 檢查
> php -m | grep -i xdebug && echo "⚠⚠ 正式環境有 Xdebug"
> # 移除
> sudo phpdismod -v 8.3 -s ALL xdebug
> sudo apt remove -y php8.3-xdebug
> sudo systemctl restart php8.3-fpm
> ```
>
> **Q9.** **三處**：
> ①**Web 伺服器**：Nginx 的 `client_max_body_size 50m;`
> 或 Apache 的 `LimitRequestBody`；
> ②**PHP**：`upload_max_filesize = 50M` 與 `post_max_size = 64M`；
> ③**應用程式**：Laravel 的驗證規則 `max:51200`。
> **`post_max_size` 必須比 `upload_max_filesize` 大** ——
> 因為 POST 的整個請求體除了檔案本身，還包含表單的其他欄位與 multipart 的邊界資料。
> **任何一處不夠都會失敗，而錯誤訊息各不相同**：
> Web 伺服器不夠 → **413 Request Entity Too Large**；
> PHP 不夠 → **上傳「成功」但 `$_FILES` 是空的**（最難察覺）；
> 應用不夠 → 422 驗證失敗。
>
> **Q10.** **流程**：
> ①**安裝新版（舊版繼續跑，互不影響）**；
> ②複製 `php.ini` 與 pool 設定（★ **socket 路徑要改成新版**）；
> ③`composer check-platform-reqs` 檢查相依性；
> ④**建立測試站台指向新版的 socket**；
> ⑤跑完整測試 + **檢查 error log 的 Deprecated / Warning**；
> ⑥**改正式站台的 `fastcgi_pass` + reload**；
> ⑦改 CLI 預設（`update-alternatives`）與 cron 中的路徑；
> ⑧**觀察兩週後**才移除舊版。
> **回退成本極低** ——
> **只要把 `fastcgi_pass` 改回舊版的 socket 再 reload，
> 秒級生效，且不中斷服務**（舊版的 FPM 一直都還在跑）。
> 這比「一次全部升級然後祈禱」安全太多。
