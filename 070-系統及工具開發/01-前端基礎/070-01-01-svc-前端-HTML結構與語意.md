## 觀念說明

### ★★★ 一份 HTML 的骨架

```html
<!DOCTYPE html>                          <!-- ★★★ 一定要有，見下方說明 -->
<html lang="zh-Hant-TW">                 <!-- ★★★★ lang 影響無障礙與搜尋 -->
<head>
    <meta charset="UTF-8">               <!-- ★★★★ 一定要放在最前面 -->
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>公告事項 - 某某機關</title>    <!-- ★★★ 瀏覽器分頁與搜尋結果的標題 -->
    <link rel="stylesheet" href="/css/app.css">   <!-- ★★ 樣式 -->
</head>
<body>
    <!-- ★★★ 看得見的內容全部在這裡 -->
    <header>…</header>
    <main>…</main>
    <footer>…</footer>

    <script src="/js/app.js"></script>   <!-- ★★★ 通常放最後 -->
</body>
</html>
```

```
★★★★ 三十秒讀懂一份 HTML 的方法：

  ① 看 <head> → 這頁載入了哪些 CSS / JS？
     → ★★★ 版面壞掉時，先看 CSS 的路徑對不對

  ② 看 <body> 的第一層標籤 → 頁面分成哪幾塊？
     → header / nav / main / aside / footer

  ③ 用瀏覽器的【檢查元素】點在畫面上要改的地方
     → ★★★★ 這比從頭讀原始碼快一百倍
```

> [!danger] `<!DOCTYPE html>` 不能少 ★★★
> ```
> ★★★★ 少了 DOCTYPE，瀏覽器會進入【怪異模式（quirks mode）】
>   → 用 1990 年代的規則來排版
>   → ★★★ 症狀：版面整個跑掉、盒模型計算不同、
>     在 Chrome 正常但在別的瀏覽器爛掉
>
> ★★★ 怎麼確認：
>   瀏覽器 Console 輸入：
>   > document.compatMode
>   "CSS1Compat"    ★★★ 標準模式（正確）
>   "BackCompat"    ★★★★ 怪異模式（★ 少了 DOCTYPE）
>
> ★★ 常見成因：
>   · 樣板檔案第一行有空行或 BOM
>   · ★★★ PHP 在 DOCTYPE 之前輸出了東西（★ 見下方）
> ```

```bash
# ★★★★ PHP 在 DOCTYPE 前輸出東西的排查
$ curl -s https://app.example.gov.tw/ | head -c 200 | xxd | head -3
00000000: efbb bf3c 2144 4f43 5459 5045 2068 746d  ...<!DOCTYPE htm
#          ↑↑↑↑↑↑
#   ★★★★ EF BB BF = UTF-8 BOM！在 DOCTYPE 之前
#   → 造成怪異模式，而且可能讓 header() 失效

# ★★★ 找出有 BOM 的 PHP 檔案
$ find /var/www/app -name '*.php' -exec sh -c \
    'head -c3 "$1" | grep -q $"\xef\xbb\xbf" && echo "$1"' _ {} \;

# ★★★ 移除 BOM
$ sed -i '1s/^\xEF\xBB\xBF//' 檔案.php
```

### ★★★ 標籤、屬性、巢狀

```html
<!-- ★★★ 一個標籤的組成 -->
<a href="/news" class="link" target="_blank" rel="noopener noreferrer">公告</a>
 ↑  └────────┘ └──────────┘ └──────────────────────────────────┘  ↑    ↑
標籤名   屬性        屬性              屬性                      內容  結束標籤

<!-- ★★ 自我關閉的標籤（沒有內容，不需要結束標籤）-->
<img src="/logo.png" alt="機關標誌">
<br>
<hr>
<input type="text" name="q">
<meta charset="UTF-8">
```

```
★★★★ 巢狀規則：後開的先關

  ✓ 正確：<p><strong>重要</strong>公告</p>
  ✗ 錯誤：<p><strong>重要</p></strong>
                            ↑ ★★★★ p 在 strong 之前關了

★★★ 巢狀錯誤的症狀：
  · 版面從某一段開始整個歪掉
  · ★★ 某個區塊的樣式「傳染」到後面所有內容
  · 瀏覽器會自動「修正」，但每家修的方式不同 → ★★★ 跨瀏覽器不一致
```

## 環境準備與驗證工具

```bash
# ═══ ★★★ 語法驗證（★ 改完一定要驗）═══
# 方法一：線上驗證
#   https://validator.w3.org/

# ★★★ 方法二：命令列（可以放進 CI）
$ sudo apt install -y tidy
$ tidy -qe index.html
line 42 column 5 - Warning: <div> missing </div>
line 88 column 1 - Error: <p> isn't allowed in <span> elements

# ★★★ 只看錯誤不看警告
$ tidy -qe --show-warnings no index.html

# ★★★ 驗證整個目錄
$ find /var/www/app/current/resources/views -name '*.blade.php' | \
    while read -r f; do
      out=$(tidy -qe --show-warnings no "$f" 2>&1)
      [ -n "$out" ] && { echo "── $f"; echo "$out"; }
    done

# ★★★ 從網址驗證（★ 驗證的是實際輸出，含後端產生的部分）
$ curl -s https://app.example.gov.tw/ | tidy -qe --show-warnings no -
```

> #   ★★ 或用 npm：sudo npm install -g html-validate
> $ html-validate index.html
> ```

```bash

$ npm install -D html-validate

# ★★ 無障礙檢測

### ★★★★ 用開發者工具找到要改的地方

```
★★★★ 這是維運改網頁最重要的技能，比讀原始碼快一百倍：

  ① 在網頁上【對著要改的文字按右鍵】→「檢查」（或 F12）
  ② ★★★ 開發者工具會直接跳到那段 HTML
  ③ 看它的 class / id → ★★ 用這個去原始碼裡搜尋

  例：要改「最新公告」四個字
     檢查 → 看到 <h2 class="section-title">最新公告</h2>
     → ★★★ 在專案裡搜尋 "最新公告" 或 "section-title"

★★★ 找到檔案的技巧：
  · 靜態網站 → grep -rn "最新公告" /var/www/
  · ★★★ Laravel → grep -rn "最新公告" resources/views/
  · ★★ 從資料庫來的 → 那要改資料庫不是改 HTML
```

```bash
# ★★★★ 在伺服器上找出那段文字在哪個檔案
$ cd /var/www/app/current
$ grep -rn "最新公告" resources/views/ 2>/dev/null
resources/views/home.blade.php:42:        <h2 class="section-title">最新公告</h2>

# ★★★ 找不到 → 可能是從資料庫或語系檔來的
$ grep -rn "最新公告" resources/lang/ lang/ 2>/dev/null
$ mysql -e "SELECT * FROM settings WHERE value LIKE '%最新公告%'" app

# ★★★★ 改之前一定要備份
$ cp -a resources/views/home.blade.php{,.bak-$(date +%F-%H%M)}
$ sudoedit resources/views/home.blade.php

# ★★★ 改完清快取（★ Laravel 的 view cache）
$ php artisan view:clear
$ curl -s https://app.example.gov.tw/ | grep -o '<h2[^>]*>[^<]*</h2>' | head
```

### ★★★ 常用標籤速覽

| 分類 | 標籤 | 用途 |
| --- | --- | --- |
| **結構** | `<header>` `<nav>` `<main>` `<aside>` `<footer>` | **★★★ 語意化的區塊** |
| | `<section>` `<article>` | 有標題的段落 / 獨立的內容 |
| | `<div>` | **★★ 沒有語意的容器**（★ 能用語意標籤就別用它） |
| **文字** | `<h1>`~`<h6>` | **★★★★ 標題階層**（★ 見下） |
| | `<p>` | 段落 |
| | `<strong>` `<em>` | **★★★ 重要 / 強調**（★ 有語意） |
| | `<b>` `<i>` | 粗體 / 斜體（**★★ 純外觀，無語意**） |
| | `<span>` | 行內的無語意容器 |
| **清單** | `<ul><li>` `<ol><li>` | 無序 / 有序清單 |
| | `<dl><dt><dd>` | ★★ 定義清單（★ 適合名詞解釋） |
| **表格** | `<table><thead><tbody><tr><th><td>` | **★★★ 表格必須有 `<th>`** |
| | `<caption>` | ★★★ 表格標題（★ 無障礙需要） |
| **連結** | `<a href>` | **★★★★ 見下方安全性** |
| **圖片** | `<img src alt>` | **★★★★ `alt` 不可少** |
| **表單** | `<form><input><select><textarea><button>` | 見下一節 |

> [!danger] 標題階層不能跳 ★★★★
> ```
> ★★★★ h1 → h2 → h3 必須【逐級遞降】，不能跳
>
>   ✗ 錯誤：<h1>公告</h1> 然後直接 <h3>詳細內容</h3>
>   ✓ 正確：<h1>公告</h1> → <h2>詳細內容</h2>
>
> ★★★ 為什麼重要：
>   ① ★★★★ 【螢幕閱讀器靠標題階層導覽】
>      → 視障使用者用「跳到下一個標題」瀏覽整頁
>      → 階層跳號 = 導覽結構壞掉
>   ② ★★★ 無障礙檢測會直接判定不合格
>      → 機關網站有法規要求（見下方無障礙一節）
>   ③ ★★ 搜尋引擎用它理解頁面結構
>
> ★★★ 一頁應該只有【一個 h1】（★ 通常是頁面主標題）
>
> ★★ 檢查方式（瀏覽器 Console）：
>   > $$('h1,h2,h3,h4,h5,h6').map(h => h.tagName + ' ' + h.textContent.trim().slice(0,30))
> ```

## 進階應用：表單

```html
<!-- ★★★★ 一個完整的表單 -->
<form action="/contact" method="post" enctype="multipart/form-data">
    <!-- ★★★★ Laravel 的 CSRF token，少了會 419 -->
    @csrf

    <!-- ★★★ label 的 for 要對應 input 的 id -->
    <label for="name">姓名<span aria-hidden="true">*</span></label>
    <input type="text" id="name" name="name"
           required maxlength="50" autocomplete="name">

    <label for="email">電子郵件</label>
    <input type="email" id="email" name="email"
           required autocomplete="email"
           aria-describedby="email-hint">
    <small id="email-hint">我們不會公開您的信箱</small>

    <label for="topic">主題</label>
    <select id="topic" name="topic">
        <option value="">請選擇</option>
        <option value="apply">申請案件</option>
        <option value="complain">陳情</option>
    </select>

    <label for="content">內容</label>
    <textarea id="content" name="content" rows="6"
              required maxlength="2000"></textarea>

    <!-- ★★★ 檔案上傳需要 enctype="multipart/form-data" -->
    <label for="file">附件（PDF，10MB 以內）</label>
    <input type="file" id="file" name="file" accept=".pdf,application/pdf">

    <button type="submit">送出</button>
</form>
```

```
★★★★ 表單的四個關鍵屬性：

  ① action  → 送到哪個網址
     ★★★ 空的或省略 = 送到目前的網址

  ② method  → get 還是 post
     ★★★★ get  參數在網址上（★ 會被記錄在 access log 和瀏覽器歷史）
     ★★★★ post 參數在 body（★ 送敏感資料一定要用 post）

  ③ ★★★★ enctype → 有檔案上傳時【一定要】multipart/form-data
     → 少了的話後端收不到檔案（★ 而且沒有錯誤訊息）

  ④ ★★★★ name → 【後端靠這個取值】
     → 沒有 name 的 input 【不會被送出】
     → ★★★ 這是「表單少了一個欄位」最常見的原因
```

### ★★★★ 表單送不出去的排查順序

```bash
# ═══ ★★★★ 由前到後六層排查 ═══

# ★★★【1】前端：欄位有沒有 name？
#   瀏覽器 Console：
#   > new FormData(document.querySelector('form'))
#   → 展開看有哪些欄位
#   ★★★★ 少了某個欄位 = 那個 input 沒有 name 屬性

#   ★★ 或看送出的內容
#   > [...new FormData(document.forms[0])].map(([k,v]) => k+'='+v)

# ★★★【2】前端：required 擋住了？
#   → 瀏覽器會顯示「請填寫這個欄位」的泡泡
#   → ★★ 但如果欄位被 CSS 藏起來，泡泡也看不到 → 表單像是「沒反應」
#   Console：
#   > document.forms[0].checkValidity()
#   false
#   > [...document.forms[0].elements].filter(e => !e.checkValidity())
#   → ★★★ 列出哪些欄位沒過驗證

# ★★★★【3】網路：請求真的送出去了嗎？
#   開發者工具 → Network → 送出表單 → 看有沒有新的請求
#   ★★★ 沒有請求 = 卡在前端（JS 錯誤或驗證沒過）
#   ★★★ 有請求但 4xx/5xx = 後端問題

# ★★★★【4】419 Page Expired（Laravel）
$ curl -sI -X POST https://app.example.gov.tw/contact | head -1
HTTP/2 419
#   ★★★★ 缺 CSRF token，或 session 過期
#   → 表單裡要有 @csrf
#   → ★★★ 或 session 的 cookie 沒帶到（見 [[130-01-05-04-guide-認證串接-Sanctum與JWT]]）

# ★★★★【5】413 Request Entity Too Large
#   → 上傳的檔案超過限制
#   ★★★ 四層都要檢查：
$ grep client_max_body_size /etc/nginx/nginx.conf     # nginx
$ php -i | grep -E 'upload_max_filesize|post_max_size' # PHP
#   ★★★★ post_max_size 一定要比 upload_max_filesize 大
#   → 太小的話 $_POST 整個變空 → 送出後像是「什麼都沒填」

# ★★★【6】後端驗證失敗
$ tail -50 /var/www/app/current/storage/logs/laravel-$(date +%F).log
```

> [!danger] `<input>` 沒有 `name` 就不會被送出 ★★★★
> ```html
> <!-- ★★★★ 這個欄位【永遠收不到】 -->
> <input type="text" id="phone" placeholder="電話">
>
> <!-- ★★★ 正確 -->
> <input type="text" id="phone" name="phone" placeholder="電話">
> ```
> ```
> ★★★★ 症狀：使用者說「我明明填了電話」但資料庫是空的
> ★★★ 排查：Console 執行
>   > [...new FormData(document.forms[0]).keys()]
>   → ★★★★ 沒看到 "phone" 就是這個問題
>
> ★★ 同類陷阱：
>   · disabled 的欄位【不會送出】（★ 用 readonly 才會送）
>   · ★★★ 沒有勾選的 checkbox【不會送出】（★ 不是送 false，是完全沒有）
>   · 同名的 checkbox 要寫成 name="tags[]" 才會收成陣列
> ```

### 五個最常被檢測出來的問題

```html
<!-- ★★★★ ① 圖片缺 alt -->
<img src="/logo.png">                        <!-- ✗ 螢幕閱讀器唸不出來 -->
<img src="/logo.png" alt="某某機關標誌">      <!-- ✓ -->
<img src="/divider.png" alt="">              <!-- ✓ ★★★ 純裝飾用空 alt -->
<!--   ★★★★ 注意：裝飾性圖片要用 alt=""（空字串），不是省略 alt -->

<!-- ★★★★ ② 表單缺 label -->
<input type="text" name="q" placeholder="搜尋">   <!-- ✗ placeholder 不算 label -->
<label for="q">搜尋</label>                        <!-- ✓ -->
<input type="text" id="q" name="q">
<!-- ★★ 不想顯示 label 時用 aria-label -->
<input type="text" name="q" aria-label="搜尋" placeholder="搜尋">

<!-- ★★★★ ③ 連結文字沒有意義 -->
<a href="/doc.pdf">請點此</a>                              <!-- ✗ -->
<a href="/doc.pdf">下載 114 年度預算書（PDF，2MB）</a>      <!-- ✓ -->
<!--   ★★★ 螢幕閱讀器可以「列出所有連結」，
       滿頁的「請點此」對使用者完全沒有意義 -->

<!-- ★★★ ④ 表格缺 th 與 caption -->
<table>                                       <!-- ✗ -->
    <tr><td>項目</td><td>金額</td></tr>
</table>
<table>                                       <!-- ✓ -->
    <caption>114 年度預算分配</caption>
    <thead>
        <tr><th scope="col">項目</th><th scope="col">金額</th></tr>
    </thead>
    <tbody>
        <tr><td>人事費</td><td>1,200,000</td></tr>
    </tbody>
</table>

<!-- ★★★ ⑤ 只用顏色表達資訊 -->
<span style="color:red">必填</span>                    <!-- ✗ 色盲看不出來 -->
<span style="color:red">必填<span aria-hidden="true">*</span></span>  <!-- ✓ -->
```

```bash
# ★★★★ 自動化檢測
$ npx pa11y https://app.example.gov.tw/
Results for https://app.example.gov.tw/:

 • Error: Img element missing an alt attribute.
   ── html > body > header > img
   ── <img src="/logo.png">

 • Error: This form field should be labelled in some way.
   ── html > body > main > form > input

# ★★★ 檢測整站
$ npx pa11y-ci --sitemap https://app.example.gov.tw/sitemap.xml

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| **中文全部變亂碼** ★★★★ | 缺 `<meta charset="UTF-8">` 或它不在最前面 | 放進 `<head>` 第一行；檢查檔案本身的編碼 |
| **版面整個跑掉** ★★★★ | 缺 DOCTYPE（怪異模式）或標籤沒關 | `document.compatMode`；`tidy -qe` |
| **某段之後樣式全歪** ★★★ | **標籤沒關或巢狀錯誤** | `tidy` 找出未關閉的標籤 |
| **表單少一個欄位** ★★★★ | **`<input>` 沒有 `name`** | `[...new FormData(form).keys()]` |
| **checkbox 沒勾就收不到** ★★★ | 未勾選的 checkbox 不送出 | 後端用 `$request->boolean('x')` |
| **`disabled` 欄位收不到** ★★★ | disabled 不送出 | 改用 `readonly` |
| **上傳檔案收不到** ★★★★ | **缺 `enctype="multipart/form-data"`** | 加上去 |
| **419 Page Expired** ★★★★ | 缺 CSRF token | 表單加 `@csrf` |
| **413 錯誤** ★★★ | 檔案超過限制 | nginx / PHP 四層都要調 |
| **手機上字很小** ★★ | 缺 viewport meta | 加 `<meta name="viewport" …>` |
| **無障礙檢測不過** ★★★★ | alt / label / 標題階層 | `pa11y`；用上面的 Console 腳本 |
| **`header()` 失效** ★★★ | **PHP 檔案有 BOM** | `sed -i '1s/^\xEF\xBB\xBF//'` |

## 安全性注意事項

> [!danger] 四個會造成資安問題的 HTML 寫法 ★★★★
> ```

> ★★★★ ② 直接輸出使用者的輸入（XSS）
> ★★★ ③ 表單缺 CSRF token
> ★★★ ④ autocomplete 沒關（敏感欄位）

<a href="https://外部網站.com" target="_blank" rel="noopener noreferrer">連結</a>
<!--  ★★★ noopener   切斷 window.opener
      ★★ noreferrer  不送 Referer（★ 避免洩漏來源網址）
      ★★★ 現代瀏覽器對 target=_blank 已隱含 noopener，

> [!question]- 測驗答案
> **Q1.** **★★★★ 瀏覽器會進入「怪異模式（quirks mode）」** ——
> 改用 1990 年代的排版規則來渲染，
> 最明顯的是**盒模型的計算方式不同**（`width` 是否包含 padding 與 border），
> 造成**版面整個跑掉**，而且**每家瀏覽器的怪異模式行為都不一樣**，
> 出現「Chrome 正常但別的瀏覽器爛掉」的情況。
> **確認方式**（瀏覽器 Console）：
> ```javascript
> document.compatMode
> // "CSS1Compat"  ★★★ 標準模式（正確）
> // "BackCompat"  ★★★★ 怪異模式（少了 DOCTYPE）
> ```
> **常見成因**：樣板檔案第一行有空行、
> **檔案有 UTF-8 BOM**、或 **PHP 在 DOCTYPE 之前 echo 了東西**。
> 後兩者用 `head -c3 檔案 | xxd` 檢查（`efbbbf` 就是 BOM）。
>
> **Q2.** 因為 **瀏覽器必須先知道編碼才能正確解讀後面的位元組**。
> 在讀到 `charset` 宣告之前，瀏覽器只能**猜測**編碼；
> 如果宣告出現得太晚（例如在一堆 `<meta>` 或 `<title>` 之後），
> 瀏覽器可能已經用錯誤的編碼解讀了前面的內容，
> 這時它必須**丟棄已解析的部分重新來過**，或乾脆維持錯誤的解讀 ——
> 結果就是**中文變成亂碼**。
> **規範建議 `charset` 出現在檔案的前 1024 個位元組內**，
> 實務上就是放在 `<head>` 的第一行。
> **補充**：HTTP 回應標頭的 `Content-Type: text/html; charset=UTF-8`
> **優先權高於 meta 標籤**，所以伺服器端設定正確的話更保險：
> ```bash
> curl -sI URL | grep -i content-type
> ```
>
> **Q3.** **★★★★ 那個 `<input>` 沒有 `name` 屬性**。
> 只有 `id` 或 `placeholder` 是不夠的 —— **後端靠 `name` 取值**，
> 沒有 `name` 的欄位**根本不會被瀏覽器送出**，
> 而且**不會有任何錯誤訊息**，使用者以為填了、後端收到空的。
> **確認方式**（Console）：
> ```javascript
> [...new FormData(document.forms[0]).keys()]
> // ★★★★ 沒看到那個欄位名就是這個問題
> ```
> **同類的三個陷阱**：
> ①**`disabled` 的欄位不會送出**（要用 `readonly`）；
> ②**未勾選的 checkbox 不會送出**（不是送 `false`，是完全沒有這個 key）；
> ③多個同名 checkbox 要寫成 `name="tags[]"` 才會被收成陣列。
>
> **Q4.** **`disabled`** —— 欄位**無法操作、樣式變灰、
> ★★★★ 而且不會被送出**（不在 FormData 裡）。
> **`readonly`** —— 欄位**無法編輯但可以選取複製、
> ★★★ 會正常被送出**、可以被 focus、樣式通常不變灰。
> **什麼時候用哪個**：
> **要顯示一個不可改但需要送到後端的值**（例如帶入的申請編號）→ **`readonly`**；
> **要暫時停用一個按鈕或選項**（例如未選擇縣市前不能選鄉鎮）→ **`disabled`**。
> **常見錯誤**：用 `disabled` 顯示唯讀的表單欄位，
> 結果送出後那個值變成空的 —— 而且因為沒有錯誤訊息，很難察覺。
> **安全提醒**：兩者都是**前端的限制**，
> 攻擊者可以用開發者工具移除，**後端一定要重新驗證**。
>
> **Q5.** **★★★★ `enctype="multipart/form-data"`**：
> ```html
> <form action="/upload" method="post" enctype="multipart/form-data">
>     <input type="file" name="file">
> </form>
> ```
> **少了的話後端完全收不到檔案**（`$_FILES` 是空的），
> 而且**通常沒有錯誤訊息** —— 表單看起來送出成功了。
> 原因：預設的 `enctype` 是 `application/x-www-form-urlencoded`，
> 那個格式**無法承載二進位資料**，瀏覽器只會送出檔名字串。
> **同時要注意 `method` 必須是 `post`**（GET 無法上傳檔案）。
> **上傳失敗還有其他四層限制要檢查**：
> nginx 的 `client_max_body_size`、
> PHP 的 `upload_max_filesize`、
> **PHP 的 `post_max_size`（必須大於 upload_max_filesize，
> 太小會讓 `$_POST` 整個變空 → Laravel 回 419）**、
> 以及應用層的驗證規則。
>
> **Q6.** ①**★★★★ 螢幕閱讀器靠標題階層導覽** ——
> 視障使用者的主要瀏覽方式是「跳到下一個標題」或「列出所有標題」來建立頁面的心智地圖。
> 階層跳號（h1 直接到 h3）等於**導覽結構出現斷層**，
> 使用者會以為漏掉了什麼內容。
> ②**★★★ 無障礙檢測會直接判定不合格** ——
> 台灣的「網站無障礙規範 2.0」依據 WCAG，
> **機關網站需通過無障礙標章檢測，這是驗收條件不是加分項**。
> ③**★★ 搜尋引擎用標題階層理解頁面的內容結構與重要性**。
> **另外一頁應該只有一個 `<h1>`**（頁面主標題）。
> **檢查**：
> ```javascript
> [...document.querySelectorAll('h1,h2,h3,h4,h5,h6')].map(h => h.tagName)
> ```
>
> **Q7.** 因為 **`target="_blank"` 開啟的新頁面可以透過 `window.opener`
> 存取並竄改原本的分頁**。
> **攻擊情境**：
> 使用者從你的網站點了一個外部連結 → 新分頁開啟惡意網站 →
> 惡意網站執行 `window.opener.location = '釣魚網站'` →
> **原本那個分頁被偷偷換成釣魚頁面** →
> 使用者關掉新分頁回到原分頁，看到「登入逾時請重新登入」，
> **以為還在你的網站上就把帳密輸進去了**。
> **`rel="noopener"` 切斷 `window.opener` 的參照**；
> **`rel="noreferrer"` 額外不送 `Referer` 標頭**（避免洩漏來源網址）。
> **現代瀏覽器對 `target="_blank"` 已隱含 `noopener`**，
> 但**舊瀏覽器與機關常見的 IE 相容模式沒有**，所以一律要寫。
> **掃描**：`grep -rn 'target="_blank"' views/ | grep -v 'rel='`。
>
> **Q8.** **`{{ $x }}` 會自動跳脫 HTML** ——
> `<` 變成 `&lt;`、`>` 變成 `&gt;`、`"` 變成 `&quot;`，
> 使用者送的 `<script>alert(1)</script>` 會**原樣顯示成文字**而不執行。
> **`{!! $x !!}` 不跳脫，直接輸出原始 HTML** ——
> **★★★★ 使用者送什麼就執行什麼，這是 XSS 的直接管道**。
> **其他樣板引擎的對應**：
> ```
> Twig：      {{ x }} 跳脫  /  {{ x|raw }}   ★★★★ 不跳脫
> Vue：       {{ x }} 跳脫  /  v-html        ★★★★ 不跳脫
> Nunjucks：  {{ x }} 跳脫  /  {{ x|safe }}  ★★★★ 不跳脫
> Django：    {{ x }} 跳脫  /  {{ x|safe }}  ★★★★ 不跳脫
> React：     {x} 跳脫      /  dangerouslySetInnerHTML ★★★★
> ```
> **真的需要輸出 HTML 時**（富文本編輯器的內容），
> 必須先用 **HTMLPurifier 之類的過濾器**清洗，再用不跳脫的方式輸出。
> **稽核**：`grep -rn '{!!\|v-html\||raw\||safe' resources/ src/`。
>
> **Q9.** **★★★ 裝飾性圖片要用 `alt=""`（空字串），不是省略 `alt`**。
> ```html
> <img src="/divider.png" alt="">        <!-- ✓ 正確 -->
> <img src="/divider.png">               <!-- ✗ 錯誤 -->
> ```
> **為什麼有差**：
> **`alt=""` 明確告訴螢幕閱讀器「這張圖沒有資訊，請跳過」** ——
> 閱讀器會完全忽略它，使用者的閱讀流程不被打斷。
> **完全省略 `alt`** 時，螢幕閱讀器**不知道這是不是遺漏**，
> 多數會**改唸出檔名**（「divider 點 png」）或「圖片」——
> 對使用者是純粹的噪音，一整頁裝飾圖就是一連串無意義的朗讀。
> **判斷準則**：**「如果把這張圖拿掉，讀者會漏掉資訊嗎？」**
> 會 → 寫描述性的 alt；不會 → `alt=""`。
> 圖片本身就是連結時，`alt` 要描述**連結的目的地**而不是圖片外觀。
>
> **Q10.** **BOM（Byte Order Mark，`EF BB BF`）會被當成檔案的實際輸出內容**，
> 造成兩個問題：
> ①**★★★ `header()` 與 `setcookie()` 失效** ——
> PHP 規定這些函式必須在**任何輸出之前**呼叫，
> BOM 已經是輸出了，於是報
> `Cannot modify header information - headers already sent`，
> **重導向、設 cookie、下載檔案全部壞掉**；
> ②**★★★★ BOM 出現在 `<!DOCTYPE>` 之前** →
> 瀏覽器進入怪異模式，版面跑掉。
> **找出來**：
> ```bash
> find /var/www/app -name '*.php' -exec sh -c \
>   'head -c3 "$1" | grep -q $"\xef\xbb\xbf" && echo "$1"' _ {} \;
> ```
> **移除**：
> ```bash
> sed -i '1s/^\xEF\xBB\xBF//' 檔案.php
> ```
> **預防**：編輯器存檔時選「UTF-8」而不是「UTF-8 with BOM」；
> Windows 的記事本預設會加 BOM，**不要用它編輯 PHP 檔案**。
