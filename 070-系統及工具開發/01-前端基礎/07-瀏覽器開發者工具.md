## 基礎操作

### ★★★★★ 六步標準排錯流程

接到「網頁怪怪的」，依序做這六件事。**大部分問題在第三步以前就水落石出**。

**【1】F12 → Console → 有沒有紅字？**

```
有紅字 → 讀第一條（後面的常是連鎖反應）→ 對照下方判讀表
沒紅字 → 進入第 2 步
```

★★★★ **只看第一條紅字**。JS 出錯後常引發一連串後續錯誤，
從最後一條往回看只會被誤導。

**【2】Network → 重整（`Ctrl+Shift+R`）→ 有沒有紅色的請求？**

```
紅色 / 狀態 4xx 5xx → 這是伺服器或路徑問題，不是前端 bug
狀態 (failed) 或 0  → 網路層問題（DNS、CORS、憑證、連線被拒）
全部 200            → 進入第 3 步
```

**【3】確認拿到的是不是新版**

```
Network → Disable cache 打勾 → 重整
問題消失了 → ★★★★ 這是快取問題，不是程式 bug
問題還在   → 進入第 4 步
```

★★★★ 這一步能篩掉大量的假 bug。使用者說「我這邊是壞的」而你這邊正常，
九成是這個。

**【4】換個環境確認範圍**

```
無痕視窗還壞嗎？   → 不壞 = 快取 / Cookie / 擴充套件問題
換一個瀏覽器？     → 只有某瀏覽器壞 = 相容性問題
換一台電腦 / 手機？ → 只有某人壞 = 他的環境（網路、DNS、防毒軟體）
```

**【5】把問題搬到終端機**

Network → 右鍵那個請求 → **Copy → Copy as cURL** → 貼進終端機執行。

★★★★★ 這一步是分水嶺：**如果 curl 也重現，問題就與前端無關**，
可以直接交給後端或網路。反之則是前端。

**【6】縮小到具體那一行**

Elements 改樣式、Sources 下中斷點、Console 直接呼叫函式試。

### Console

**判讀紅字**

| 訊息 | 意義 | 通常是誰的問題 |
| --- | --- | --- |
| ★★★★ `Cannot read properties of null (reading 'x')` | 抓不到元素／物件是空的 | 前端（script 沒 defer） |
| ★★★★ `Unexpected token '<', "<!DOCTYPE"...` | 把 HTML 錯誤頁當 JSON 解析 | ★★★★ **後端或 Nginx**（502/404/登入頁） |
| ★★★★ `blocked by CORS policy` | 跨來源被擋 | ★★★★ **伺服器設定** |
| ★★★ `Failed to load resource: 404` | 檔案路徑錯或沒部署 | 部署／Nginx |
| ★★★ `Failed to load resource: 502` | 上游服務掛了 | ★★★★ **後端** |
| ★★★ `Mixed Content` | HTTPS 頁面載入 http 資源 | 前端寫死了 http |
| ★★★ `Refused to execute inline script ... CSP` | CSP 擋掉行內腳本 | 伺服器 CSP 設定 |
| ★★★ `net::ERR_CERT_...` | 憑證有問題 | ★★★★ **憑證／PKI** |
| ★★ `ERR_CONNECTION_REFUSED` | 服務沒在跑 | 伺服器 |

> [!tip] 哪些紅字可以先無視
> ★★★ **來自瀏覽器擴充套件的錯誤**（訊息裡有 `chrome-extension://` 或 `moz-extension://`）、
> 廣告攔截器擋掉第三方追蹤造成的 `net::ERR_BLOCKED_BY_CLIENT`、
> 以及 React DevTools 之類的提示訊息。
> 排錯時先在無痕視窗（預設關閉擴充套件）確認一次，可以省掉很多雜訊。

**Console 的實用指令**

```javascript
// ★★★ 陣列用 table 印，比 log 好讀十倍
console.table(主機清單);

// 分組
console.group('主機檢查'); console.log('web01 ok'); console.groupEnd();

// 計時
console.time('查詢'); await 取得資料(); console.timeEnd('查詢');
// 輸出：查詢: 342.15 ms

// 條件斷言
console.assert(主機.length > 0, '主機清單是空的！');

// ★★★★ $0 = 目前在 Elements 選中的元素（超好用）
$0.classList
$0.getBoundingClientRect()

// $ 與 $$ 是 querySelector / querySelectorAll 的簡寫（僅在 Console 可用）
$('#app')
$$('a[target="_blank"]')                     // 回傳真陣列，可直接 map

// 上一個運算式的結果
$_

// ★★★ 查函式定義在哪
console.dir(某函式)
```

**幾個立刻能用的檢查片段**

```javascript
// 找出所有超出視窗寬度的元素（手機版跑版元凶）
$$('*').filter(el => el.getBoundingClientRect().right > innerWidth)
        .map(el => ({ 標籤: el.tagName, class: el.className, 右緣: Math.round(el.getBoundingClientRect().right) }))
        .slice(0, 10);

// 找出缺少 alt 的圖片（無障礙自查）
$$('img:not([alt])').map(i => i.src);

// 找出有 target=_blank 卻沒 rel=noopener 的連結（資安）
$$('a[target="_blank"]:not([rel*="noopener"])').map(a => a.href);

// 看目前頁面載入了哪些 JS
performance.getEntriesByType('resource')
  .filter(r => r.name.endsWith('.js'))
  .map(r => ({ 檔案: r.name.split('/').pop(), 毫秒: Math.round(r.duration) }));
```

### Network ★★★★★

這是維運人員最該熟練的分頁。

**必做的三個設定**

```
☑ Disable cache        ★★★★ 排錯期間全程勾著
☑ Preserve log         ★★★ 跨頁面轉址時保留紀錄（查登入流程必開）
  Throttling: No throttling → 改 Slow 4G 可重現「只有外面的人會遇到」的問題
```

**欄位怎麼看**

| 欄位 | 意義 | 注意 |
| --- | --- | --- |
| **Status** | 狀態碼 | ★★★★ `(failed)` 或 `0` = 沒送到／被擋，不是伺服器回的 |
| **Type** | 資源類型 | ★★★★ 預期 JSON 卻是 `document` = 回了 HTML 錯誤頁 |
| **Size** | 大小 | ★★★ 顯示 `(disk cache)` = 沒真的去要，是快取 |
| **Time** | 總耗時 | 慢的話看 Timing 分頁細分 |
| **Waterfall** | 時間瀑布圖 | 看是等待久還是下載久 |

**點開一個請求的五個分頁**

```
Headers   → ★★★★ Request/Response 標頭。查 CORS、快取、Content-Type 都在這
Payload   → 送出去的資料（POST body、查詢參數）
Preview   → 格式化後的回應（JSON 會變成可展開的樹）
Response  → ★★★★ 原始回應。「預期 JSON 卻是 HTML」在這裡一眼看穿
Timing    → 時間細分（見下方）
```

**Timing 的判讀 ★★★**

```
Queueing / Stalled     ← 排隊（同網域併發連線數上限、或優先權低）
DNS Lookup             ← ★★★ 慢 = DNS 問題
Initial connection     ← TCP 握手
SSL                    ← ★★★ 慢 = 憑證鏈太長或 OCSP 查詢卡住
Request sent           ← 幾乎瞬間
★★★★ Waiting (TTFB)   ← 伺服器思考時間。慢 = 後端或資料庫慢
Content Download       ← ★★★ 慢 = 檔案太大或頻寬不足
```

★★★★ **TTFB 慢就是後端的事，Content Download 慢就是檔案／網路的事** ——
這一條分界能省下大量互推責任的時間。

**Copy as cURL ★★★★★**

```bash
# 右鍵請求 → Copy → Copy as cURL，貼上後加 -v 看細節
curl -v 'https://dash.example.tw/api/hosts' \
  -H 'Accept: application/json' \
  -H 'Cookie: session=abc123' \
  --compressed

# ★★★ 只想看狀態碼與耗時
curl -s -o /dev/null -w 'code=%{http_code} type=%{content_type} ttfb=%{time_starttransfer}s total=%{time_total}s\n' \
  'https://dash.example.tw/api/hosts'
```

> [!danger] Copy as cURL 會包含你的 Cookie 與 Authorization 標頭
> ★★★★★ 那等同於**你的登入憑證**。貼進工單、Slack、GitHub issue 前，
> 一定要把 `-H 'Cookie: ...'` 與 `-H 'Authorization: ...'` 整行刪掉或改成假值。
> Chrome 有「Copy as cURL (bash)」與 Firefox 的「Copy as cURL」都不會幫你遮蔽。

**匯出 HAR 檔 ★★★★**

要請別人幫忙查、或要保存現場證據時：

```
Network → 右上角 ⤓（Export HAR）→ 存檔
```

> [!danger] HAR 檔含有完整的請求與回應內容
> ★★★★★ 包含 Cookie、token、POST 送出的表單資料、API 回傳的個資。
> **HAR 檔等同機敏資料**，不可以貼到公開的網站或聊天群組。
> Chrome 新版提供「Export HAR (sanitized)」會移除 Cookie 與 Authorization，
> 優先用那個；沒有的話請用內部檔案傳輸並註明保存期限。

### Elements

**看真正生效的樣式 ★★★★**

選中元素後，右側 Styles 面板由上而下就是**優先權由高到低**：

```
element.style { }              ← 行內樣式（優先權 1000）
.card.warning { color: red }   ← 有效
.card { color: blue }          ← 被劃掉 = 被上面的蓋掉
```

★★★★ **被劃掉的樣式就是「你改了卻沒生效」的答案**，
把游標移上去可以看到是被哪條規則蓋掉的。原理見 [[02-CSS版面與排版]]。

**Computed 分頁**：顯示所有屬性的**最終計算值**，
並可展開看它來自哪個檔案的第幾行 —— 找「這個 padding 到底哪來的」最快。

**即時實驗（★★★ 不會改到伺服器）**

```
· 雙擊屬性值 → 直接改，Enter 生效
· 方向鍵 ↑↓ → 數值 ±1（配合 Shift ±10）
· 勾選框    → 暫時停用某條規則
· :hov 按鈕 → 強制觸發 :hover / :focus / :active 狀態，才看得到 hover 樣式
· 右鍵元素 → Force state / Hide element / Delete element
```

★★★★ **這是驗證假設最快的方式**：懷疑是 `overflow: hidden` 造成的？
直接取消勾選看看，兩秒就知道。確認後再回去改原始碼。

**其他實用功能**

| 功能 | 用途 |
| --- | --- |
| 右鍵 → **Break on** → attribute modifications | ★★★ 抓「誰把這個元素改掉了」 |
| 右鍵 → Copy → **Copy selector** | 取得該元素的 CSS 選擇器 |
| 右鍵 → **Store as global variable** | 存成 `temp1`，可在 Console 操作 |
| `Ctrl+F` | 在 DOM 裡搜尋文字或選擇器 |

### Application

| 項目 | 用途 | 星級 |
| --- | --- | --- |
| **Storage → Clear site data** | ★★★★ 一鍵清掉這個網站的所有快取／Cookie／storage | ★★★★ |
| **Local Storage / Session Storage** | 看前端存了什麼（★★★ 檢查有沒有不該存的 token） | ★★★★ |
| **Cookies** | 檢查 `HttpOnly` / `Secure` / `SameSite` 三個旗標 | ★★★★ |
| **Cache Storage** | Service Worker 快取（PWA 的頑固快取在這） | ★★★ |
| **Service Workers** → Unregister | ★★★★ 「怎麼清都還是舊版」的元凶 | ★★★★ |
| **Manifest** | PWA 設定 | ★ |

> [!warning] Service Worker 是最頑固的快取
> ★★★★ 一般的 `Ctrl+F5` **清不掉 Service Worker 快取**。
> 症狀是「明明已經部署新版、也清了快取，使用者還是看到舊畫面」。
> 處理：Application → Service Workers → **Unregister** → 再重整。
> 給使用者的指引則是：Application → Storage → **Clear site data**。

**Cookie 旗標檢查（資安巡檢常用）**

```
Name      Value   HttpOnly  Secure  SameSite
session   abc…    ✓         ✓       Lax        ← ★★★★ 正確
token     xyz…    ✗         ✗       None       ← ★★★★★ 有問題，JS 讀得到且不限 HTTPS
```

## 進階應用

### Sources：下中斷點

```
1. Sources → 左側檔案樹找到 .js
2. 點行號 → 藍色標記 = 中斷點
3. 觸發那段程式 → 執行會停住
4. 滑鼠移到變數上 → 看當下的值
```

| 快捷鍵 | 動作 |
| --- | --- |
| `F8` | 繼續執行到下一個中斷點 |
| `F10` | 執行下一行（不進入函式） |
| `F11` | 進入函式內部 |
| `Shift+F11` | 跳出目前函式 |

★★★ **條件中斷點**：右鍵行號 → Add conditional breakpoint →
輸入 `主機.name === 'web02'`，只有符合時才停 —— 迴圈裡除錯必備。

★★★ **XHR/fetch 中斷點**：右側 XHR/fetch Breakpoints → 加上網址片段，
該請求送出時自動停住，可以看到是誰發的、帶了什麼參數。

> [!tip] 程式碼看起來是一團亂碼？
> 正式環境的 JS 經過壓縮。點左下角的 `{}`（Pretty print）可以重新排版。
> 若伺服器有提供 source map，Sources 會直接顯示原始的 `.ts` 檔
> —— 這也是為什麼 [[06-前端建置工具與套件管理]] 要求**正式環境關閉 source map**。

### Performance 與 Lighthouse

```
Performance → 錄製 → 操作 → 停止
   看 Main 執行緒有沒有「長條」（Long Task，>50ms 會標紅）
   ★★★ 卡頓幾乎都來自：大量 DOM 操作、同步的大迴圈、未節流的 scroll 事件
```

```
Lighthouse → 選 Performance / Accessibility → Analyze
   ★★★ Accessibility 分數對「機關網站無障礙規範」有參考價值，
   但它只能自動檢出約三成的問題，不能取代人工檢測。見 [[01-HTML結構與語意]]
```

### 手機版與遠端偵錯

```
Ctrl+Shift+M → 裝置模擬
  · 上方可選裝置尺寸、旋轉方向
  · ★★★ 模擬的是「螢幕尺寸與 UA」，不是真的手機瀏覽器核心
```

★★★★ **真機偵錯**（模擬器測不出的問題）：

```
Android + Chrome：
  手機開啟「開發人員選項 → USB 偵錯」→ USB 接電腦
  電腦 Chrome 開 chrome://inspect → 選裝置 → inspect

iOS + Safari：
  iPhone 設定 → Safari → 進階 → 網頁檢閱器 開啟
  Mac Safari → 開發 → 選裝置
```

## 完整實戰範例

### 情境：使用者說「儀表板打不開，一片空白」

**第 0 步：先問三個問題（不用開電腦）**

```
1. 所有人都這樣，還是只有你？        → 縮小範圍
2. 什麼時候開始的？剛剛有部署嗎？    → ★★★★ 最近的改動最可疑
3. 換一台電腦或手機也一樣嗎？        → 分辨環境問題
```

**第 1 步：Console**

```
GET https://dash.example.tw/assets/index-A1b2C3.js  net::ERR_ABORTED 404
Uncaught SyntaxError: Unexpected token '<'
```

判讀：JS 檔 404，伺服器回了 HTML（多半是 index.html 或 404 頁），
瀏覽器把它當 JS 解析 → 語法錯誤 → 整個應用沒啟動 → 空白畫面。

**第 2 步：Network 確認**

```
名稱                     Status  Type       Size
index-A1b2C3.js          404     document   1.2 kB    ← ★★★★ Type 是 document 不是 script
```

點 Response 分頁 → 內容是 `<!DOCTYPE html>` → 確認伺服器沒有這支檔案。

**第 3 步：確認伺服器上實際有什麼**

```bash
ls /var/www/dashboard/current/assets/ | head
# index-C7mR9tYb.js       ← ★★★★ 雜湊不一樣！
# vendor-Dp3nQz1a.js
# index-BvK2xQ8p.css

curl -s https://dash.example.tw/ | grep -o 'assets/[^"]*\.js'
# assets/index-C7mR9tYb.js  ← 伺服器現在給的 HTML 指向新檔
```

**結論**：使用者的瀏覽器快取了**舊的 `index.html`**，它指向的舊 JS 已被新版部署刪除。

**第 4 步：驗證假設**

```
Network → ☑ Disable cache → Ctrl+Shift+R
→ 頁面正常顯示  ✓ 假設成立
```

**第 5 步：確認根因並修正**

```bash
curl -sI https://dash.example.tw/ | grep -i cache-control
# cache-control: public, max-age=31536000    ← ★★★★★ index.html 被長期快取，這就是根因
```

```nginx
# 修正
location = /index.html {
    add_header Cache-Control "no-cache, must-revalidate" always;
    expires -1;
}
```

```bash
nginx -t && systemctl reload nginx
curl -sI https://dash.example.tw/ | grep -i cache-control
# cache-control: no-cache, must-revalidate    ✓
```

**第 6 步：處理已經受影響的使用者**

```
短期：請使用者按 Ctrl+Shift+R（或 Application → Clear site data）
中期：把上一版的 assets 一併保留在伺服器上，讓卡住的瀏覽器還載得到
長期：把快取標頭檢查寫進部署驗收清單（見 [[06-前端建置工具與套件管理]]）
```

**第 7 步：留下紀錄**

```markdown
## 事件：儀表板空白（2026-08-28 14:30 ~ 15:05）
- 影響：曾在前一版造訪過的使用者，約 40 人
- 現象：白畫面，Console `Unexpected token '<'`，JS 檔 404
- 根因：Nginx 對 index.html 設了 max-age=31536000，
        使用者快取的舊 HTML 指向已被刪除的舊雜湊 JS
- 處置：index.html 改為 no-cache；請使用者強制重整
- 預防：部署腳本加入快取標頭驗收；保留前一版 assets 一週
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| ★★★★ 清了快取還是舊版 | Service Worker 快取 | Application → Service Workers → Unregister |
| ★★★★ 「我這邊正常，使用者那邊壞」 | 你的瀏覽器已載入新版 | 用無痕視窗 + Disable cache 重現 |
| ★★★★ 轉址流程看不到請求 | 沒勾 Preserve log | 勾起來重測 |
| ★★★ Console 一堆看不懂的紅字 | 瀏覽器擴充套件造成 | 無痕視窗重測（預設停用擴充） |
| ★★★ Network 空的 | 開 DevTools 之前就載入完了 | DevTools 開著再重整 |
| ★★★ 看不到某些請求 | 分頁上方的類型篩選器沒選對 | 點 All，或用 Fetch/XHR 只看 API |
| ★★★ JS 是一團壓縮過的字 | 正式環境壓縮 | 左下角 `{}` Pretty print |
| ★★★ 改了 Elements 的樣式重整就沒了 | ★★★★ DevTools 的修改**只在記憶體**，不會寫回伺服器 | 確認後回去改原始碼 |
| ★★ 手機模擬正常但真機壞 | 模擬只換尺寸與 UA，核心仍是桌面版 | 用 `chrome://inspect` 真機偵錯 |
| ★★ Performance 錄不到東西 | 錄製時間太短或沒有互動 | 錄製期間實際操作頁面 |

### 排查步驟：分辨「誰的問題」

**【1】前端還是後端？**

```
Console 有 JS 錯誤但 Network 全 200  → 前端
Network 有 4xx/5xx                   → ★★★★ 後端或 Nginx
Network 有 (failed)                   → 網路層（DNS / CORS / 憑證）
```

**【2】用 curl 從伺服器本機測一次，排除網路與 CDN**

```bash
# 在 web 主機上直接打自己
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' http://127.0.0.1/api/health
# 200 0.012s  → 服務本身正常，問題在前面（Nginx / CDN / 網路）
# 502 0.003s  → 服務本身有問題
```

**【3】比對瀏覽器與 curl 的差異**

★★★★ 如果 curl 正常但瀏覽器不正常，差別通常是這四項之一：

```
Cookie（登入狀態）
Origin / Referer 標頭（CORS）
Accept-Encoding（壓縮）
User-Agent（伺服器針對瀏覽器的特殊處理）
```

用 Copy as cURL 就能保留這些標頭，逐一刪掉來二分定位。

**【4】是不是快取層的問題**

```bash
curl -sI https://dash.example.tw/api/hosts | grep -iE 'age|x-cache|cf-cache-status|via'
# age: 3600            ← ★★★ 這是快取回來的，不是即時的
# x-cache: HIT
```

**【5】留下可交接的證據**

```
1. Network → Export HAR（★★★★ 注意去識別化）
2. Console → 右鍵 → Save as... 存下完整訊息
3. 螢幕截圖含網址列與時間
4. 記錄：發生時間、使用者、瀏覽器版本、是否可重現
```

## 安全性注意事項

> [!danger] 開發者工具會暴露機敏資料
> ★★★★★ Network 分頁裡有完整的 Cookie、Authorization token、POST 表單內容、
> API 回傳的個資。截圖、HAR 檔、Copy as cURL 都會把這些原封不動帶走。
> **交出去之前一定要去識別化。**

| 動作 | 風險 | 處理 |
| --- | --- | --- |
| 截圖給廠商 | Cookie／token 可能在畫面上 | ★★★★ 遮蔽 Headers 區塊，或只截 Console |
| 匯出 HAR | ★★★★★ 含完整請求與回應（含個資） | 用 sanitized 版本；視為機敏檔案傳輸 |
| Copy as cURL 貼工單 | ★★★★★ 含 `Cookie:` 與 `Authorization:` | 刪掉那兩行 |
| 在使用者電腦上操作 | 可能看到他的個資 | 事先告知並取得同意 |

### 「按 F12 貼這段程式碼」= 詐騙 ★★★★★

> [!danger] 自我 XSS（Self-XSS）
> 近年常見的手法：騙受害者「按 F12 → Console → 貼上這段程式碼就能解鎖功能」。
> 貼上的程式碼會用**受害者自己的登入身分**竊取 Cookie、發出轉帳請求、或建立後門。
> Facebook、Discord 等網站因此在 Console 開啟時顯示大字警告。
>
> ★★★★★ **教育使用者：任何人叫你在瀏覽器 Console 貼程式碼，都是詐騙。**
> 這一條建議寫進機關的資安宣導。

### 其他

- ★★★★ **正式環境關閉 source map**，否則 Sources 分頁會顯示完整原始碼與註解
  （見 [[06-前端建置工具與套件管理]]）
- ★★★★ **檢查 Application → Local Storage 有沒有 token**
  —— 有的話是設計缺陷，見 [[03-JavaScript基礎]]
- ★★★ **檢查 Cookie 的三個旗標** `HttpOnly` / `Secure` / `SameSite`，
  這是最快的資安自查之一
- ★★★ **DevTools 的修改不會影響伺服器**，但**會影響你自己的判斷** ——
  改完記得重整回原狀再做結論
- ★★ **不要在 Console 執行來路不明的程式碼**，包括從搜尋結果複製來的「解法」

## 練習題

> [!question]- 練習 1：三十秒判斷歸屬
> 對你負責的一個網站，用 DevTools 在三十秒內回答：
> ① 首頁載入了幾個 JS 檔、總共多大（gzip 後）？
> ② TTFB 是多少？
> ③ Cookie 有沒有設 `HttpOnly` 與 `Secure`？
> ④ localStorage 裡有沒有不該存的東西？
>
> **提示**：①② 在 Network（底部有總計），③④ 在 Application。
> 這四題就是一次基本的前端健檢。

> [!question]- 練習 2：把瀏覽器請求搬到終端機
> 挑一個需要登入才看得到的 API 請求，用 Copy as cURL 在終端機重現，
> 然後**逐一刪掉標頭**，找出哪一個是不可或缺的。
>
> **提示**：通常是 `Cookie` 或 `Authorization`。
> 做完記得把含有 token 的指令從 shell 歷史清掉：
> `history -d <行號>`，或事前用空格開頭的指令避免記錄。

> [!question]- 練習 3：寫一份「請使用者提供的資訊」清單
> 假設你要請非技術背景的同事回報前端問題，寫出五個步驟的操作指引，
> 要能讓他把足夠的資訊帶回來，同時**不會外洩他的個資**。
>
> **參考解答**：
> ① 按 `F12` → 點 Console → 螢幕截圖（含網址列）；
> ② 點 Network → 按 `Ctrl+Shift+R` 重整 → 截圖整個清單（不要點開個別請求）；
> ③ 記下發生時間與你正在做什麼操作；
> ④ 試試無痕視窗還會不會發生；
> ⑤ 回報瀏覽器版本（網址列輸入 `chrome://version`）。
> **刻意不要求 HAR 檔與請求細節**，因為那含有 Cookie 與個資；
> 需要時再由資訊人員在旁協助擷取。

## 小測驗

Q1. Console 出現一長串紅字，該從哪一條開始看？為什麼？

Q2. Network 分頁裡某請求的 Status 顯示 `(failed)` 而不是數字，這代表什麼？

Q3. 一個預期回 JSON 的請求，Type 欄顯示 `document`，最可能發生什麼事？

Q4. 「我這邊正常，使用者說壞掉」，用 DevTools 怎麼快速重現使用者的情況？

Q5. Timing 分頁裡 Waiting (TTFB) 佔了 3 秒，Content Download 只有 20ms。問題在誰身上？

Q6. 已經部署新版、也按了 `Ctrl+F5`，使用者還是看到舊畫面。還有哪個地方要檢查？

Q7. Elements 面板裡某條 CSS 規則被劃掉了，代表什麼？

Q8. Copy as cURL 出來的指令可以直接貼進工單嗎？

Q9. HAR 檔為什麼要當作機敏資料處理？

Q10. 有人在網路上教你「按 F12，把這段程式碼貼進 Console 就能解鎖功能」，該怎麼反應？

> [!question]- 測驗答案
> **Q1.** ★★★★ 從**第一條**開始看。
> JavaScript 一旦出錯，後續依賴它的程式碼會連鎖失敗，
> 產生大量「衍生」錯誤 —— 例如第一條是「設定檔載入失敗」，
> 後面十條都是「找不到設定」。從最後一條往回看只會被誤導到完全無關的地方。
> 另外要先排除**瀏覽器擴充套件**造成的錯誤（訊息含 `chrome-extension://`），
> 用無痕視窗重測一次可以濾掉這類雜訊。
>
> **Q2.** 代表**請求根本沒有拿到 HTTP 回應** —— 不是伺服器回了錯誤，
> 而是連「伺服器的答覆」都沒收到。★★★★ 四個常見原因：
> DNS 解析失敗、TCP 連線被拒（服務沒在跑或防火牆擋）、
> TLS 憑證驗證失敗、以及被 CORS 或瀏覽器擴充套件攔截。
> 判斷方向完全不同於 4xx/5xx：後者代表請求有送達、伺服器有回應，
> 是應用層問題；`(failed)` 是**網路層或瀏覽器策略**問題。
>
> **Q3.** ★★★★ 伺服器回的是 **HTML 而不是 JSON**。
> Type 欄反映的是 `Content-Type` 標頭，`document` = `text/html`。
> 三個典型情境：API 路徑錯導致 Nginx 回了 404 頁、
> 上游服務掛掉回了 502 錯誤頁、或 session 過期被導向登入頁。
> 前端會接著在 Console 報 `Unexpected token '<', "<!DOCTYPE"... is not valid JSON`
> —— 這個訊息極具誤導性，真正該看的是 Network 的 **Response 分頁**，
> 一眼就能看到伺服器實際回了什麼。
>
> **Q4.** ★★★★ 三個動作：
> ① Network → 勾 **Disable cache** 再重整（模擬「拿到不同版本資源」的狀況，
> 或反過來，取消勾選以保留快取來重現使用者的舊快取）；
> ② 開**無痕視窗**（沒有你累積的 Cookie、localStorage 與擴充套件）；
> ③ 用**裝置模擬**或真機測試對方的螢幕尺寸與瀏覽器。
> 最關鍵的觀念是：你的瀏覽器已經載入過新版，**你本身就不是有效的測試環境**。
>
> **Q5.** ★★★★ **在後端（或後端依賴的資料庫／外部服務）身上。**
> TTFB（Time To First Byte）是「請求送達後，伺服器產生第一個位元組所花的時間」，
> 也就是**伺服器的思考時間**。3 秒的 TTFB 代表後端在做很慢的事
> —— 通常是沒有索引的資料庫查詢、N+1 查詢、或等待外部 API。
> Content Download 只有 20ms 表示網路與檔案大小都沒問題。
> 這條分界很重要：**TTFB 慢找後端，Content Download 慢找檔案大小與頻寬**，
> 能省掉大量前後端互推責任的時間。
>
> **Q6.** ★★★★ **Service Worker**。
> Application → Service Workers → 看有沒有註冊中的 worker → **Unregister**。
> Service Worker 是一層攔在網路之前的程式化快取，
> `Ctrl+F5` 的強制重整**清不掉它**，因為請求根本沒走到網路層就被它接管了。
> 症狀就是「明明部署了、也清了快取，還是舊版」。
> 給使用者的標準指引是 Application → Storage → **Clear site data**（會一併清掉）。
> 另外也要順便檢查 CDN 快取（回應標頭的 `age`、`x-cache`）。
>
> **Q7.** 代表這條規則**被優先權更高的規則蓋掉了**，沒有實際生效。
> ★★★★ 這正是「我明明改了 CSS 為什麼沒反應」的答案。
> Styles 面板由上而下就是優先權由高到低，把游標移到被劃掉的規則上，
> 可以看到是被哪一條蓋掉的。
> 若要看最終結果，用 **Computed** 分頁 —— 它顯示每個屬性的最終計算值，
> 並可展開看來源檔案與行號。優先權的計算方式見 [[02-CSS版面與排版]]。
>
> **Q8.** ★★★★★ **不可以直接貼。** Copy as cURL 會完整複製瀏覽器送出的所有標頭，
> 其中 `-H 'Cookie: session=...'` 與 `-H 'Authorization: Bearer ...'`
> **等同於你的登入憑證** —— 拿到的人可以直接冒用你的身分操作系統。
> 貼進工單、Slack、GitHub issue 之前務必刪掉這兩行（或改成 `<REDACTED>`）。
> 順帶一提，執行過含 token 的 curl 之後，shell 歷史裡也留著同樣的東西，
> 記得清掉或事前用空格開頭的指令避免被記錄。
>
> **Q9.** 因為 HAR 檔是**整個 Network 分頁的完整存檔** ——
> 包含每一個請求的所有標頭（Cookie、Authorization）、
> POST 送出的表單內容（可能有密碼）、以及 API 回傳的完整內容（可能有個資、身分證號、聯絡方式）。
> ★★★★★ 它的敏感程度往往高於資料庫的單筆查詢結果，卻因為「只是個除錯檔案」而被隨手上傳到公開平台。
> 處理原則：優先使用 Chrome 的 **Export HAR (sanitized)**（會移除 Cookie 與 Authorization）；
> 必須用完整版時，以機敏檔案的規格傳輸與保存，並明訂刪除期限。
>
> **Q10.** ★★★★★ **這是詐騙，一律拒絕。** 這種手法叫 **Self-XSS（自我 XSS）**：
> 攻擊者無法直接入侵網站，就改為騙使用者**用自己的登入身分**執行惡意程式碼。
> 貼上的那段程式可以讀走 Cookie、以你的身分發出請求（轉帳、改密碼、發訊息）、
> 或留下持久的後門。因為是你自己貼的，所有的資安防護都無法阻止。
> Facebook、Discord 等網站會在 Console 開啟時顯示大字警告，就是為了這個。
> **正確反應**：不執行、保留對方的訊息作為證據、通報資安窗口。
> 這一條非常值得寫進機關的資安宣導教材。
