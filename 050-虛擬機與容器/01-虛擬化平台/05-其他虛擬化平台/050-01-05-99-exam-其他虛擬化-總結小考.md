## 是非題（50 題）

### Q1～Q25：VirtualBox

Q1. VirtualBox 屬於 Type 1（裸機型）hypervisor，它直接跑在硬體上，不需要宿主作業系統。

Q2. VirtualBox 的安裝檔其實包含兩個授權條件不同的東西：基礎套件與 Extension Pack。

Q3. Extension Pack 既然可以從官網免費下載，就代表機關可以免費在公務設備上使用它。

Q4. Extension Pack 安裝時不需要輸入序號、也不會被技術手段擋下來，它屬於「事後稽核制」而非「事前技術管制」。

Q5. 如果評估後確認不需要 USB 2.0／3.0 直通與 VRDE 遠端桌面，選擇不安裝 Extension Pack，可以把授權風險限制在基礎套件那一層。

Q6. 判斷「機關內部使用算不算條款所稱的個人用途」，應該由熟悉技術的工程師直接決定，不必麻煩採購或法務單位。

Q7. VirtualBox 是 Vagrant 生態中最成熟的 provider，這是選它最有說服力的單一理由。

Q8. VirtualBox 具備叢集、高可用（HA）與線上遷移功能，因此小型機關可以拿它承載正式服務。

Q9. 「先用 VirtualBox 開一台跑一下，之後再搬」是安全的做法，因為之後一定會搬。

Q10. Guest Additions 沒有安裝時，共享資料夾功能完全不能用，因為 guest 裡沒有 `vboxsf` 驅動。

Q11. Linux guest 上沒有安裝 `dkms`，核心更新之後 Guest Additions 的模組不會自動重新編譯，典型症狀是「共享資料夾突然掛不上」。

Q12. NAT 與 NAT Network 這兩種模式的關鍵差別，在於 VM 之間能不能互相通訊。

Q13. Host-only 模式的 VM 可以直接連上網際網路，所以只要設 host-only 就能同時滿足「宿主連得進來」與「VM 能 `apt update`」兩個需求。

Q14. `192.168.56.x` 是 VirtualBox host-only 介面的傳統網段，在 `VBoxManage list hostonlyifs` 的輸出裡看到它就知道是 host-only。

Q15. 設定 NAT 的 port forwarding 時，把來源位址留空與綁定 `127.0.0.1` 效果相同，兩種寫法都只有宿主自己連得到。

Q16. 執行 `usermod -aG vboxsf $USER` 之後，同一個終端機視窗立刻就能存取 `/media/sf_share`，不需要重新登入。

Q17. 共享資料夾適合當成 guest 內資料庫的資料目錄，因為這樣宿主也能直接看到資料檔。

Q18. `VBoxManage createmedium disk --size 40960` 的 `40960` 單位是 MB，也就是 40 GB。

Q19. `VBoxManage controlvm <VM> poweroff` 等同直接拔掉電源，guest 中未寫入的資料會遺失，檔案系統可能需要修復。

Q20. `VBoxManage controlvm <VM> acpipowerbutton` 相當於按下電源鍵，是 guest 還有回應時應該優先使用的關機方式。

Q21. 連結複製（linked clone）出來的子機不依賴母機，母機可以隨時刪除或修改。

Q22. 用 `cp` 直接複製一份 `.vdi` 檔案再註冊，會因為磁碟 UUID 重複而失敗，因為 VirtualBox 是用 UUID 而不是檔名來識別磁碟。

Q23. 宿主磁碟被快照塞爆時，直接用 `rm` 刪掉 VM 目錄底下 `Snapshots/` 裡的 `.vdi` 檔案，是最快也最安全的釋放空間方式。

Q24. 在 Windows 上執行 `Get-ComputerInfo -Property HyperVisorPresent` 得到 `True`，代表 Windows 自己已經在跑 hypervisor（Hyper-V、WSL2、Windows 沙箱或 VBS 都可能造成）。

Q25. 就磁碟 I/O 與圖形流暢度而言，VirtualBox 普遍優於 VMware Workstation。

### Q26～Q50：VMware ESXi

Q26. ESXi 是 Type 1 裸機 hypervisor，開機之後跑的只有 VMkernel 與虛擬機，沒有一般意義上的宿主桌面環境。

Q27. ESXi 是一套 Linux 發行版，所以可以直接在上面 `apt install` 想要的工具。

Q28. ESXi 與 VMware Workstation 一樣提供「共享資料夾」功能，可以把主機的目錄直接掛給 VM。

Q29. 只買單機 ESXi 授權、裝三台主機，就能做出「主機故障時虛擬機自動在其他主機重啟」的高可用效果。

Q30. vMotion（不停機的線上遷移）需要 vCenter，而且還需要共用儲存，這通常是另外一筆預算。

Q31. VMware 生態內建了排程式的完整與增量備份，所以採購時不需要另外編列備份軟體的預算。

Q32. Proxmox VE 的叢集集中管理、線上遷移、HA 與備份排程都是內建的，不必另外購買元件。

Q33. HCL（硬體相容性清單）要查的是「未來要用的目標 ESXi 版本」，而不是只查目前手上這一版。

Q34. 某張網卡在舊版 ESXi 的相容性清單上，就可以推論它在新版也一定支援。

Q35. 升級 ESXi 主機之前，應該先備份主機設定（例如 `vim-cmd hostsvc/firmware/backup_config`），並準備好回退用的舊版 ISO。

Q36. 主機出現紫色畫面（PSOD）時，應該立刻重新開機讓服務盡快恢復，畫面上的訊息之後再從日誌裡找就好。

Q37. datastore 空間耗盡時，上面的虛擬機會失去寫入能力並被暫停，可能造成整批服務同時停擺。

Q38. 精簡配置（thin provisioning）超賣本身不必然是錯誤，真正的錯誤是「超賣了卻沒有把用量納入監控告警」。

Q39. 把 ESXi 主機升級到新版本之後，datastore 上的 VMFS 檔案系統版本會自動跟著升級。

Q40. 在 ESXi 上「刪除快照」會讓虛擬機的資料回到拍快照的那一刻。

Q41. 快照可以當成備份長期保留，因為它完整記錄了虛擬機某一刻的狀態。

Q42. 管理介面顯示某台主機「失聯（disconnected）」，就代表這台主機上的虛擬機一定已經停止服務了。

Q43. DCUI 的 `Restart Management Agents` 會重啟主機的管理服務，但不會影響正在執行的虛擬機。

Q44. DCUI 的 `Test Management Network` 可以逐項測試 ping 閘道、ping DNS 與主機名稱解析，是管理網路設錯時的第一個工具。

Q45. 一台虛擬機的虛擬硬體版本比目標主機的 ESXi 版本還新時，搬過去會開不起來。

Q46. 虛擬硬體版本升級之後可以隨時降回舊版本，所以升級前不必特別考慮環境中其他主機的版本。

Q47. Linux guest 上建議直接安裝發行版套件庫提供的 `open-vm-tools`，而不是用手動掛載映像的方式安裝，這樣核心升級時比較不會出問題。

Q48. 從 ESXi 遷移到 Proxmox VE 之後，Linux guest 的網卡介面名稱通常會改變，是「開機正常但完全沒有網路」最常見的原因。

Q49. 遷移到 PVE 並完成切換之後，舊 ESXi 上的原始虛擬機應該保留、不刪除、只關機，作為最快的回退方案。

Q50. 機關採購規格書上寫「須支援 vMotion」比寫「須支援不停機的虛擬機線上遷移」更精確，因此是比較好的寫法。

## 選擇題（50 題）

### Q51～Q75：VirtualBox

Q51. 關於 Type 1 與 Type 2 的根本差異，下列敘述何者**最正確**？
- (A) Type 1 效能比較好，Type 2 比較差，差別只在效能
- (B) Type 2 的宿主作業系統握有實體資源的最終決定權，hypervisor 只是它的一個程式
- (C) Type 1 只能跑 Linux guest，Type 2 什麼都能跑
- (D) 兩者只是行銷名詞，技術上沒有實質差異

Q52. 為什麼「Type 2」這三個字就足以決定 VirtualBox 不該進機房承載正式服務？
- (A) 因為它是免費的，免費軟體不能用在正式環境
- (B) 因為它不支援 64 位元 guest
- (C) 因為宿主作業系統的更新重開機、防毒、休眠、使用者登出都會直接影響 VM，無法做到「無人值守、可預期」
- (D) 因為它的圖形介面太簡單

Q53. VirtualBox 的授權為什麼在機關環境特別需要注意？
- (A) 因為基礎套件要付費，Extension Pack 免費
- (B) 因為它有兩層結構：基礎套件屬開源授權，Extension Pack 屬原廠專有授權，兩者條款不同
- (C) 因為它每年都要重新啟用序號
- (D) 因為它只授權給教育機構使用

Q54. 要確認一台機器上有沒有安裝需要另外說明授權依據的元件，應該執行下列哪一個指令？
- (A) `VBoxManage --version`
- (B) `VBoxManage list vms`
- (C) `VBoxManage list extpacks`
- (D) `VBoxManage showvminfo <VM>`

Q55. 稽核人員問「這套虛擬化軟體的授權依據是什麼」，下列處置何者**最恰當**？
- (A) 回答「這是免費軟體，不需要授權依據」
- (B) 先逐台執行查詢並截圖存證，把基礎套件與 Extension Pack 分開陳述，並由採購或法務單位向原廠或授權經銷取得書面確認
- (C) 立刻把所有 VirtualBox 移除，避免麻煩
- (D) 引用網路論壇上的說法作為依據

Q56. 教育訓練教室要一次鋪二十台 VirtualBox 練習環境，課程只教 Linux 指令與 Nginx，不需要 USB 裝置與遠端桌面。最合適的做法是？
- (A) 每台都裝 Extension Pack，功能齊全比較保險
- (B) 不安裝 Extension Pack，把授權問題限制在基礎套件那一層，並把「Extension Packs: 0」的查詢結果存進稽核資料夾
- (C) 改用 VMware Workstation，每台買一份授權
- (D) 隨便，反正是教學用途不會被查

Q57. 【判斷題】某單位的十五台開發桌機都裝了 VirtualBox 與 Extension Pack，用了三年，沒有任何書面授權說明。現在要做資產盤點，下列風險評估何者**最貼近事實**？
- (A) 沒有風險，因為安裝時系統沒有阻擋，代表原廠允許
- (B) 風險很低，因為是內部使用不對外提供服務
- (C) 風險存在且會隨部署台數放大：安裝不擋是事後稽核制而非事前管制，「機關以組織名義在公務設備上為公務目的使用」不必然等同條款所稱的個人用途，應由採購或法務單位向原廠確認並取得書面回覆；在取得依據之前，最快歸零風險的動作是移除 Extension Pack
- (D) 只要把軟體改名就沒事了

Q58. 下列哪一個情境**最適合**選用 VirtualBox？
- (A) 機關對外網站的正式主機
- (B) 需要高可用與線上遷移的核心系統
- (C) 團隊成員的桌機作業系統不一致，要用 Vagrant 做可重現、可拋棄的實驗環境
- (D) 需要 GPU 直通做 AI 推論的伺服器

Q59. 下列哪一個情境**絕對不應該**選用 VirtualBox？
- (A) 驗證一份 OVA 檔能不能正常開機
- (B) 錄製教學影片，讓讀者不必買授權就能照做
- (C) 承載一個會有使用者打電話來詢問的內部系統
- (D) 實習生的短期練習環境

Q60. VirtualBox 與 VMware Workstation 相比，下列哪一項是 **VirtualBox 明顯勝出**的地方？
- (A) 磁碟 I/O 效能
- (B) 3D／圖形加速
- (C) 原生的 headless 無頭執行模式與 Vagrant 生態成熟度
- (D) 與 Windows Hyper-V 的共存體驗

Q61. 「VirtualBox 免費，所以對機關來說行政成本一定比商業授權低」——這個推論的問題在哪裡？
- (A) 沒有問題，免費就是成本最低
- (B) 軟體費用是零，但授權說明、稽核回覆、風險評估的行政工時不是零；商業授權在稽核時只要出示一份文件
- (C) 問題在於 VirtualBox 其實要付費
- (D) 問題在於商業授權可以退款

Q62. 在 Windows 桌機上，VirtualBox 的 VM 能開機但慢到幾乎不能用，CPU 使用率看起來卻不高。最應該先確認的是？
- (A) VM 分配的記憶體是不是太少
- (B) 虛擬磁碟是不是放在機械硬碟上
- (C) `Get-ComputerInfo -Property HyperVisorPresent` 是不是 `True`，也就是 Windows 自己是否已經在跑 hypervisor
- (D) Guest Additions 有沒有安裝

Q63. 承上題，確認 Windows 端確實開著 Hyper-V／WSL2／核心隔離。下列處置何者**最恰當**？
- (A) 直接執行 `bcdedit /set hypervisorlaunchtype off` 並重開機，效能最重要
- (B) 先釐清這台機器主要要服務誰：若團隊依賴 WSL2 或機關資安政策要求開啟記憶體完整性，就不應為了跑 VM 關閉這些機制，而應改用其他平台或把 VM 搬到 PVE
- (C) 重新安裝 VirtualBox
- (D) 把 VM 的 CPU 核心數調高一倍

Q64. 錯誤訊息中出現 `VERR_VMX_NO_VMX` 這一類字樣，最直接的意義是？
- (A) 虛擬磁碟損毀
- (B) 宿主的硬體虛擬化（Intel VT-x／AMD-V）不可用，通常是 BIOS／UEFI 沒開啟或被其他 hypervisor 佔用
- (C) Guest Additions 版本太舊
- (D) 網路模式設定錯誤

Q65. 要在 VirtualBox 的 VM 裡面再跑 KVM 或 Proxmox VE，必須先做什麼？
- (A) 把 VM 的記憶體設為宿主的兩倍
- (B) 安裝 Extension Pack
- (C) 在 VM 關機狀態下開啟巢狀虛擬化：`VBoxManage modifyvm <VM> --nested-hw-virt on`
- (D) 把網路模式改成 Bridged
