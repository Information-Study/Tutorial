## 是非題（50 題）

Q1. Type 1 與 Type 2 的分界就是「有沒有裝在一般作業系統上面」，所以只要底層看得到一個完整的 OS，那一定是 Type 2。

Q2. KVM 雖然只是 Linux 的一個核心模組，但載入後 Linux 核心本身就直接決定 vCPU 何時上實體核心，因此實務上一律當 Type 1 看待。

Q3. Type 2 最致命的問題是效能比 Type 1 差一截，只要桌機規格買夠好，放正式服務也沒關係。

Q4. VM 與容器的分界線只有一條：VM 每台有自己的核心，容器共用宿主機的核心；啟動速度、隔離強度、能不能跑不同 OS 都是從這條線推導出來的。

Q5. LXC 系統容器比 Docker 更像一台完整機器，有 init、可以 SSH 進去，所以也可以在 Linux 宿主機上用 LXC 跑 Windows。

Q6. 這台 VM 每天都有做快照，所以就算沒有另外做備份，資料也還原得回來。

Q7. 快照的正確用法是「動手前開、確認正常後立刻刪」，保留超過數天的快照是問題，不是保險。

Q8. 叢集的 HA 會在節點故障時自動於其他節點把 VM 開起來，這個過程等同於「被拔電源後重新開機」，服務一定會中斷。

Q9. 虛擬化最主要的效益是省錢，因為實體機台數變少，總成本一定會下降。

Q10. 把管理叢集所需要的 DNS 與 AD 網域控制站全部開在該叢集自己的節點上是合理的，因為 HA 會在停電復電後自動把它們拉起來。

Q11. 評估整併時記憶體需求要看 `free -h` 的 `free` 那一欄，因為 `available` 把可回收的 buff/cache 也算進去，會嚴重低估需求。

Q12. 一台有安裝程式、有設定文件、廠商也還在的老伺服器，建議直接重建成新 VM，而不是整台 P2V 搬過去。

Q13. 整併比通常卡在 CPU，所以採購虛擬化主機時應該先把核心數衝到頂，記憶體不夠日後再加就好。

Q14. x86 早年做不到虛擬化，是因為有一票「敏感但不會 trap」的指令 —— 例如 `POPF` 在 ring 3 執行時不會報錯，它只是安靜地不做那件事，於是 hypervisor 攔不到。

Q15. 有了 VT-x／AMD-V 之後，客體核心仍然必須先被降到 ring 1 才能執行，硬體只是把這個降級與轉譯的動作做得比較快。

Q16. 所有虛擬化的效能調校，本質上都在做同一件事：減少 VM Exit 的次數。

Q17. EPT／NPT 二階分頁最大的好處是「客體愛怎麼改自己的頁表都不會產生 VM Exit」，代價是 TLB 沒命中時的 page walk 變長。

Q18. Ballooning 是由 hypervisor 直接決定要收回 VM 裡的哪些記憶體頁，所以反應非常快，可以擋住突發的記憶體暴衝。

Q19. 資料庫與 Java 應用的 VM 應該把 balloon 最小值設成等於配置值（等於關閉 ballooning），否則氣球把記憶體抽走時它們不會縮小，只會瘋狂 swap 或被 OOM killer 殺掉。

Q20. KSM 在「很多台相同 OS、相同版本的 VM」時效果最好；但在多租戶或有機密資料分級要求的環境，因為記憶體去重複側通道的疑慮，應該關掉。

Q21. 發現 host 開始持續 swap 時，正確處置是去調整 hypervisor 的記憶體參數、或把 host 的 swap 關掉。

Q22. VirtIO 之所以快，是因為它把「很多次昂貴的同步暫存器存取」換成「共用環形佇列上的一次非同步批次通知」，所以在高負載下的優勢比低負載時更明顯。

Q23. Windows 安裝程式看不到 VirtIO 磁碟時，最省事也最正確的做法是改用 IDE/SATA 全模擬把系統裝完，之後也不用再處理。

Q24. 直通與 SR-IOV 都能讓 I/O 效能接近實體機，而 SR-IOV 因為是把一張卡切成多個 VF，所以恢復了線上遷移的能力。

Q25. 沒有 IOMMU 就直通 PCIe 裝置，等於讓 VM 裡的驅動可以叫那張卡 DMA 到任意實體位址，可以直接改寫 hypervisor 的記憶體。

Q26. 在 Proxmox VE 上，虛擬磁碟該用 raw 還是 qcow2，主要是由儲存後端決定的，不是在下拉選單裡憑喜好挑。

Q27. 給一台 VM 更多 vCPU 一定不會更慢，反正用不到的 vCPU 就是閒著而已。

Q28. `cache=unsafe` 會忽略客體發出的 flush 要求，只能用在「壞了就重灌」的批次安裝流程，任何有資料的正式服務一律禁止。

Q29. Proxmox VE 的訂閱一旦到期，既有 VM 會停止運作，所以預算空窗期絕對不能發生。

Q30. Proxmox VE 的叢集、HA、線上遷移、排程備份與 LXC 容器都是內建的，不需要另外採購一台集中管理伺服器的授權。

Q31. Proxmox VE 有成熟的 DRS 等價物，平常就會依負載持續把 VM 自動搬到最適合的節點上。

Q32. 舊伺服器要再利用時，ESXi 很可能因為硬體不在 HCL 上而根本裝不起來，而 Debian 基底的 Proxmox VE 通常裝得上 —— 這一列在機關實務上常是決定性的。

Q33. 只有兩台伺服器時，做「兩節點無仲裁」的 PVE 叢集就可以了，反正兩台都正常運作時不會有問題。

Q34. 要把 ESXi 上的 Windows VM 搬到 PVE，正確順序是先在 ESXi 上開機安裝 virtio-win 驅動，關機後才轉換磁碟並匯入。

Q35. `virsh destroy` 是把 VM 的定義與磁碟一起刪除，所以下這個指令之前一定要先確認備份。

Q36. Windows AD 網域控制站跨平台遷移時，用磁碟映像整台複製過去最快也最完整，是建議做法。

Q37. 換平台的六層成本中，量級最高的是磁碟映像轉換，因為資料量大又必須停機。

Q38. VMware Workstation 之所以是本手冊的桌機主線，關鍵在共享資料夾、剪貼簿與 3D 加速這三列 —— 機房平台完全不需要它們，但桌機上沒有會難用到不行。

Q39. 選型的產出就是「選了哪一套」，把技術比較做完、挑出效能最好的那一個就可以結案。

Q40. 採購前十問的第一題是人力：現有人力會什麼、下一個接手的人會什麼；這一題也是最常被跳過的一題。

Q41. 使用單位一開口就說「不能停」時，正確的處理是把成本一起講出來（要三台不是一台、五年多出多少錢、從哪個科目出）再問一次。

Q42. 「每 socket」計價下買核心數多的 CPU 反而划算；「每核心」計價下，三年後換上核心數更多的 CPU，授權費會自己漲而功能一項都沒多。

Q43. 免費版通常是把功能隨機閹割掉一部分，跟機關實際最需要的功能沒有什麼關聯，所以能不能用要靠試。

Q44. 盤點時 `lscpu` 顯示的 `CPU(s)` 就是實體核心總數，可以直接拿來算「每核心」授權的份數。

Q45. 伺服器保固通常隨機出廠三年，設備卻要服役五年，因此第 4、5 年的保固延長是編列預算時最常被漏掉的一筆。

Q46. 規格書寫「應支援 vMotion」不算綁標，因為它描述的是一項功能而不是產品名稱。

Q47. 只要加上等效品條款，即使功能需求本身只有一家做得到，也不會構成綁標。

Q48. 「開源＝免費」在選型會議上站不住腳；正確論述是「這個方案把授權支出換成人力投入，但前提是要編列 X 人天教育訓練，並簽維護合約承接原廠角色」。

Q49. 服務等級分級表要請使用單位主管簽名，這樣事後停機時討論的是「當初約定的等級是 C」，而不是「資訊室為什麼沒做 HA」。

Q50. TCO 只要算首年就好，因為後面幾年的價格無法預測，算了也不準。

Q55. 下列哪一種情況最「不該」虛擬化？
