# PVE 網路設定

> [!abstract] 這篇你會學到
> - 看懂 PVE 的 `/etc/network/interfaces`：**ifupdown2 與 `ifreload -a`** 跟一般 Debian 的差別
> - Linux Bridge 到底是什麼、`vmbr0` 為什麼要「把實體網卡的 IP 搬到橋接上」
> - ★★★★ **VLAN aware bridge**：一張橋接吃下所有 VLAN，VM／CT 用 `tag=` 決定自己在哪個 VLAN
> - ★★★★★ **把 PVE 端與交換器端串起來**：VLAN aware bridge 對應到
>   [[040-01-06-guide-Juniper-VLAN與Trunk設定]] 的 trunk 設定（Cisco 對照另附）
> - ★★★★ **Bond**：`active-backup` 與 `802.3ad`（LACP）怎麼選，**以及交換器端一定要做的對應設定**
> - 多網段規劃：管理／服務／儲存／備份要不要分開、怎麼分
> - ★★★★ PVE **三層防火牆**（資料中心 → 節點 → VM/CT）的套用順序與不要把自己鎖在門外的做法
> - SDN 概覽：什麼時候才需要它

> [!warning] 未實機驗證
> 本篇**以 Proxmox VE 8 為例**（`ifupdown2`、`pve-firewall`、內建 SDN）。
>
> ★★★★★ **網卡名稱（`enp1s0`、`eno1`、`ens18`…）每台機器都不一樣**，
> 本篇一律用 `enp1s0`／`enp2s0` 當代稱，你必須用 `ip -br link` 查出自己的實際名稱再套用。
> 交換器端的設定以 JunOS ELS 與 Cisco IOS 的通用寫法為準，
> **實際指令依機型與軟體版本可能不同**，請以你手上設備的手冊為準。
>
> ★★★★★ **改網路設定會斷線。** 本篇所有設定變更都假設你有
> **IPMI／iDRAC／iLO 或實體 console 可以救援**。沒有的話請先讀「不要把自己鎖在門外」那一節。

## 觀念說明

### PVE 的網路長什麼樣子 ★★★★

```
                    ┌──────────────── 交換器 ────────────────┐
                    │  ge-0/0/10  設定成 trunk               │
                    │  允許 VLAN 10（服務）、20（測試）      │
                    │  native VLAN = 99（管理）              │
                    └───────────────┬────────────────────────┘
                                    │ 一條實體線
════════════════════════════════════╪═══════════════════════════════ PVE 節點
                                    ▼
                          ┌──────────────────┐
                          │ enp1s0（實體網卡）│  ★★★★ 它自己沒有 IP
                          └────────┬─────────┘
                                   │ bridge-ports
                    ┌──────────────▼───────────────────────────┐
                    │  vmbr0   （Linux Bridge，VLAN aware）     │
                    │  bridge-vlan-aware yes                    │
                    │  bridge-vids 2-4094                       │
                    │  ★ 節點的管理 IP 掛在這裡（untagged）      │
                    └──┬──────────┬──────────┬──────────┬───────┘
                       │          │          │          │
                  tag=10     tag=10     tag=20    （無 tag）
                       │          │          │          │
                   ┌───▼──┐  ┌───▼──┐  ┌────▼─┐  ┌─────▼────┐
                   │ VM101│  │ CT201│  │VM102 │  │ 節點自己 │
                   │ web  │  │ db   │  │ test │  │ 管理介面 │
                   └──────┘  └──────┘  └──────┘  └──────────┘
```

★★★★★ 三件事先記住：

1. **實體網卡不帶 IP**，IP 掛在 `vmbr0` 上。這是 PVE 安裝時就幫你做好的。
2. **`vmbr0` 是一台軟體交換器**，VM 與 CT 的虛擬網卡（`tap` 與 `veth`）插在上面。
3. **VLAN 標籤由 VM／CT 的 `tag=` 決定**（在 VLAN aware 模式下）。

### Linux Bridge 是什麼 ★★★

它就是核心裡的一台二層交換器：學 MAC、建 FDB、依目的 MAC 轉送。

```bash
# 看橋接與它的成員
brctl show 2>/dev/null || bridge link show
```

```text
2: enp1s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 master vmbr0 state forwarding priority 32 cost 4
9: tap101i0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 master vmbr0 state forwarding priority 32 cost 100
11: veth201i0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 master vmbr0 state forwarding priority 32 cost 2
```

| 介面名稱 | 是什麼 | 重要度 |
| --- | --- | --- |
| `enp1s0` | ★★★ 實體網卡（uplink） | ★★★ |
| `tap101i0` | ★★★ **VM** 101 的第 0 張虛擬網卡（`tap<VMID>i<N>`） | ★★★★ |
| `veth201i0` | ★★★ **CT** 201 的第 0 張虛擬網卡（`veth<VMID>i<N>`） | ★★★★ |
| `fwbr101i0`、`fwln`、`fwpr` | ★★★★ **開了防火牆（`firewall=1`）之後多出來的中間橋接** | ★★★★ |

> [!note] ★★★★ 看到 `fwbr101i0` 不要以為壞掉了
> 當 VM 的網卡有 `firewall=1`，PVE 不會把 `tap` 直接插上 `vmbr0`，
> 而是插到一個**每張網卡專屬的小橋接 `fwbr<VMID>i<N>`**，
> 再用一對 veth（`fwln`／`fwpr`）接回 `vmbr0`，
> 因為 iptables 規則要掛在那個小橋接上才能精準過濾這張網卡。
>
> ★★★ 排錯時看到多出一堆介面是**正常的**，不是設定壞掉。

### ★★★★★ ifupdown2 與 `ifreload -a`

PVE 用的不是 Debian 原本的 `ifupdown`，而是 **`ifupdown2`**。差別很關鍵：

| | 傳統 `ifupdown` | ★★★★ PVE 的 `ifupdown2` |
| --- | --- | --- |
| 套用設定 | `ifdown x && ifup x`，或重開機 | ★★★★ **`ifreload -a`**，比對差異只改變動的部分 |
| 改一個 VLAN 要不要斷全部 | 常常要 | ★★★★ **通常不用**，只重建有變的介面 |
| 語法檢查 | 幾乎沒有 | ★★★★ `ifreload -a -n`（dry-run）會先驗 |
| 對 bridge/bond/VLAN 的支援 | 靠 `bridge-utils`、`vlan` 套件拼湊 | 原生支援，語法統一 |

★★★★★ **PVE 特有的「pending 機制」**：

```
你在 Web 介面改網路
        ↓
PVE 把新設定寫到 /etc/network/interfaces.new   ← ★★★★ 還沒生效
        ↓
Web 介面出現黃色橫幅「Pending changes」與「Apply Configuration」按鈕
        ↓
按下 Apply（或指令列 ifreload -a）
        ↓
interfaces.new 覆蓋到 interfaces，執行 ifreload
```

```bash
# 有沒有待套用的變更？
ls -l /etc/network/interfaces*
```

```text
-rw-r--r-- 1 root root  542 Sep  2 09:10 /etc/network/interfaces
-rw-r--r-- 1 root root  688 Sep  2 14:22 /etc/network/interfaces.new
```

```bash
# 看差異（★★★★ 套用前一定要看）
diff -u /etc/network/interfaces /etc/network/interfaces.new
```

> [!tip] ★★★★★ 這個 pending 機制是你的朋友
> 它讓你可以**慢慢改、改完一起套用**，而不是每改一行就斷一次線。
> ★★★★ 但也代表：**在 Web 介面改完卻忘了按 Apply，設定是不會生效的**。
> 很多人「明明改了 IP 卻沒變」就是卡在這裡。

### ★★★★★ VLAN aware bridge vs 傳統 VLAN bridge

PVE 有兩種做法，**選一種，不要混用**。

#### 做法 A：VLAN aware bridge（★★★★ 建議）

一張 `vmbr0` 打開 `bridge-vlan-aware yes`，所有 VLAN 都從它走，
VM／CT 在自己的網卡上填 `tag=<VLAN ID>`。

```ini
auto vmbr0
iface vmbr0 inet static
    address 192.168.99.11/24
    gateway 192.168.99.254
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094
```

```
交換器 trunk ──► enp1s0 ──► vmbr0（VLAN aware）
                               ├─ VM101 tag=10
                               ├─ VM102 tag=20
                               └─ CT201 tag=10
```

| 優點 | 缺點 |
| --- | --- |
| ★★★★ 新增 VLAN **不用改主機設定**，VM 上填 tag 就好 | 需要交換器端配合設 trunk |
| ★★★★ 介面數量少，`ip link` 乾淨 | 觀念上要理解 tagged／untagged |
| ★★★ 遷移到其他節點時，只要對面 `vmbr0` 也是 VLAN aware 就通 | 舊版本／特殊需求偶有相容性議題 |

#### 做法 B：傳統做法（每個 VLAN 一張橋接）

```ini
auto enp1s0.10
iface enp1s0.10 inet manual

auto vmbr10
iface vmbr10 inet manual
    bridge-ports enp1s0.10
    bridge-stp off
    bridge-fd 0

auto enp1s0.20
iface enp1s0.20 inet manual

auto vmbr20
iface vmbr20 inet manual
    bridge-ports enp1s0.20
    bridge-stp off
    bridge-fd 0
```

```
交換器 trunk ──► enp1s0 ──┬─ enp1s0.10 ──► vmbr10 ──► VM101（不用填 tag）
                          └─ enp1s0.20 ──► vmbr20 ──► VM102（不用填 tag）
```

| 優點 | 缺點 |
| --- | --- |
| ★★★ VM 設定單純（選橋接就好，不用懂 tag） | ★★★★ **每加一個 VLAN 就要改主機設定並 `ifreload`** |
| ★★★ 權限上可以「只讓某人用 vmbr20」 | 介面暴增，`ip link` 很亂 |
| 相容性最好 | ★★★★ 遷移時每個節點的橋接名稱都要一致 |

> [!tip] ★★★★★ 該選哪個
> - **VLAN 數量會成長、或你希望 VM 建立時自助決定網段** → ★★★★ **做法 A（VLAN aware）**。
> - **VLAN 固定就那兩三個、而且要用 PVE 權限限制某群使用者只能接某個網段** → 做法 B。
>
> ★★★★★ **不要在同一張實體網卡上同時做 A 和 B**（例如 `vmbr0` 是 vlan-aware，
> 又另外做 `enp1s0.30 → vmbr30`）。兩套機制搶同一張網卡的 VLAN 過濾，
> 症狀是某個 VLAN 時通時不通，非常難查。

### tagged 與 untagged：PVE 端與交換器端的對照 ★★★★★

這張表是本篇的核心，**兩邊的名詞不一樣但講的是同一件事**。

| 概念 | PVE 端 | ★★★★ Juniper JunOS | Cisco IOS |
| --- | --- | --- | --- |
| 這條線要帶多個 VLAN | `bridge-vlan-aware yes` | `interface-mode trunk` | `switchport mode trunk` |
| 允許哪些 VLAN | `bridge-vids 2-4094` | `vlan members [ v10 v20 ]` | `switchport trunk allowed vlan 10,20` |
| 不帶標籤的那個 VLAN | ★★★★ vmbr0 上的 IP（不填 tag） | `native-vlan-id 99` | `switchport trunk native vlan 99` |
| 這台 VM 屬於哪個 VLAN | VM 網卡的 `tag=10` | 交換器不管，由 PVE 打標 | 同左 |
| 只接一個 VLAN 的線 | 不用 vlan-aware，直接 bridge | `interface-mode access` + `vlan members v10` | `switchport mode access` + `switchport access vlan 10` |

> [!warning] ★★★★★ native VLAN 是最容易對錯的一格
> PVE 節點的**管理 IP 掛在 `vmbr0` 本身**（沒有 tag），
> 那些封包送出去時是 **untagged**，交換器會把它歸到 **native VLAN**。
>
> 所以：★★★★★ **交換器 trunk 的 native VLAN 必須就是你的管理網段所在的 VLAN**，
> 否則你的節點管理 IP 會跑到錯誤的網段，**你就連不上 PVE 了**。
>
> 若你希望管理 IP 也帶標籤，做法是在 `vmbr0` 上再開一個 `vmbr0.99`（見「進階應用」）。

### Bond：兩張網卡當一張用 ★★★★

| 模式 | PVE 寫法 | ★★★★ 交換器端要做什麼 | 頻寬 | 容錯 |
| --- | --- | --- | --- | --- |
| ★★★★ **active-backup** | `bond-mode active-backup` | ★★★★★ **什麼都不用做**（兩個埠獨立設 trunk 即可） | 只用一張的頻寬 | 有 |
| ★★★★ **802.3ad（LACP）** | `bond-mode 802.3ad` | ★★★★★ **必須設 LAG／port-channel 並啟用 LACP** | 多條流可分擔 | 有 |
| `balance-rr` | `bond-mode balance-rr` | 需靜態 LAG | 單一連線可分擔但會亂序 | 有 |
| `balance-xor` | `bond-mode balance-xor` | 需靜態 LAG（無 LACP 協商） | 多條流可分擔 | 有 |
| `balance-tlb` / `balance-alb` | 同名 | 不用 | 部分分擔 | 有 |
| `broadcast` | `bond-mode broadcast` | 特殊用途 | 無 | 有 |

> [!danger] ★★★★★ 最常見的災難：主機設 LACP，交換器沒設
> 主機端 `bond-mode 802.3ad`，交換器端兩個埠卻是各自獨立的一般埠 →
> **同一個 MAC 在兩個埠之間跳來跳去**，交換器 MAC table 抖動，
> 症狀是**網路時通時不通、ping 掉封包、SSH 一直斷**，而且兩邊看起來都「設定正常」。
>
> ★★★★★ **規則：LACP 一定是兩邊一起設，而且要一起改。**
> 不確定交換器端能不能配合時，**先用 `active-backup`** ——
> 它單邊就能運作，容錯效果一樣有，只是沒有頻寬疊加。

> [!tip] ★★★★ 機關環境的務實建議
> | 情況 | 建議 |
> | --- | --- |
> | 網管與系統管理是**同一個人／同一組** | ★★★★ LACP（`802.3ad`），效益最好 |
> | 網管是另一個單位、改交換器要跑流程 | ★★★★ `active-backup`，你單邊就能完成 |
> | 兩張網卡接到**兩台不同的交換器**（無堆疊／無 MC-LAG） | ★★★★★ **只能 `active-backup`**，LACP 跨兩台獨立交換器不會成立 |
> | 兩台交換器有堆疊（Virtual Chassis／VSS／MC-LAG） | ★★★★ 可以 LACP，且同時有交換器層級容錯 |

### 多網段規劃 ★★★★

中大型節點建議把流量分開：

| 用途 | 為什麼要分開 | 建議 | 重要度 |
| --- | --- | --- | --- |
| ★★★★★ **管理**（Web 8006、SSH） | 被服務流量塞住時你會連不進去救援 | 獨立 VLAN，只開放給管理網段 | ★★★★★ |
| ★★★★★ **叢集 corosync** | ★★★★★ **對延遲極度敏感**，抖動會造成節點被 fence | ★★★★★ **專用網段、專用實體網卡** | ★★★★★ |
| ★★★★ **儲存**（Ceph、NFS、iSCSI） | 頻寬需求大，且會被大檔案傳輸吃滿 | 獨立網段，能 10G 就 10G | ★★★★ |
| ★★★ **備份** | 每晚大流量 | 可與儲存共用，或獨立 | ★★★ |
| ★★★ **VM 服務流量** | 面向使用者 | 走 trunk，用 VLAN 分 | ★★★ |

> [!danger] ★★★★★ corosync 千萬不要跟備份流量走同一條線
> 叢集心跳對延遲的容忍度是**毫秒級**。
> 每晚備份把那條線塞滿時，corosync 會判定節點失聯 →
> ★★★★★ **HA 觸發 fence，好好的節點被重開機**，而且是在你睡覺的時候。
> 詳見 [[050-01-03-07-svc-PVE-叢集與高可用]]。

### 2. 看預設的 `/etc/network/interfaces` ★★★★

PVE 安裝完的典型內容：

```ini
auto lo
iface lo inet loopback

iface enp1s0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.99.11/24
    gateway 192.168.99.254
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0

source /etc/network/interfaces.d/*
```

**逐行解釋**：

| 行 | 意義 | 重要度 |
| --- | --- | --- |
| `auto lo` | 開機自動啟用 | ★ |
| `iface enp1s0 inet manual` | ★★★★ **實體網卡不配 IP**，只是被橋接使用 | ★★★★ |
| `auto vmbr0` | 開機自動啟用橋接 | ★★★ |
| `address 192.168.99.11/24` | ★★★★ 節點的管理 IP（CIDR 寫法） | ★★★★ |
| `gateway` | ★★★★ **整台機器只能有一個預設閘道** | ★★★★★ |
| `bridge-ports enp1s0` | 橋接的成員；`none` 代表沒有 uplink（純內部網路） | ★★★★ |

> [!danger] ★★★★★ `gateway` 只能有一個
> 在第二張橋接上再寫一次 `gateway` → `ifreload` 會失敗或路由表錯亂：

> **不是**多寫幾個 `gateway`。

## 進階應用

### ★★★★★ VLAN aware bridge 與交換器 Trunk 對接（完整對照）

這一節把 PVE 端與交換器端**一步一步串起來**。

#### 情境

| 項目 | 值 |
| --- | --- |
| 節點 | `pve01`，實體網卡 `enp1s0` |
| 交換器埠 | Juniper `ge-0/0/10`（Cisco `GigabitEthernet0/10`） |
| 管理 VLAN | ★★★★ **99**（native／untagged），網段 `192.168.99.0/24` |
| 服務 VLAN | 10（Web），網段 `192.168.10.0/24` |
| 測試 VLAN | 20，網段 `192.168.20.0/24` |
| 節點管理 IP | `192.168.99.11/24`，GW `192.168.99.254` |

#### 步驟 1：PVE 端

    gateway 192.168.99.254
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094

```

```bash
ifreload -a -n && ifreload -a
```

```bash

```text

enp1s0            1 PVID Egress Untagged
                  2-4094
vmbr0             1 PVID Egress Untagged
```

★★★★ `1 PVID Egress Untagged` 這行的意思是：
**沒有標籤的封包在橋接內部屬於 VLAN 1**（這是 Linux bridge 的內部編號，
跟交換器上的 native VLAN 99 是**兩件事** —— 節點送出去時本來就不帶標籤，
交換器收到後才把它歸到 native VLAN 99）。

#### 步驟 2：Juniper 交換器端（★★★★ 本手冊主線）

```junos

commit complete

> `commit confirmed 5` 表示「5 分鐘內沒有再下 `commit` 確認，就自動回滾」。
> 設定生效後你確認還連得上，再下一次 `commit` 定案。
>
> ★★★★★ **在正式環境改 trunk，沒有用 `commit confirmed` 是不專業的。**
> 完整說明見 [[040-01-06-guide-Juniper-VLAN與Trunk設定]]。

> 的漸進做法。

### ★★★★ Bond：兩張網卡與交換器端的完整對應

#### 做法一：active-backup（★★★★ 交換器端零設定）

```ini
iface enp1s0 inet manual
iface enp2s0 inet manual

auto bond0
iface bond0 inet manual
    bond-slaves enp1s0 enp2s0
    bond-mode active-backup
    bond-primary enp1s0
    bond-miimon 100

auto vmbr0
iface vmbr0 inet static
    address 192.168.99.11/24
    gateway 192.168.99.254
    bridge-ports bond0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094

| 參數 | 意義 | 重要度 |
| --- | --- | --- |
| `bond-slaves` | 成員網卡 | ★★★★ |
| `bond-mode active-backup` | 主備模式 | ★★★★ |
| `bond-primary enp1s0` | ★★★ 指定偏好的主用網卡（恢復後會切回來） | ★★★ |
| `bond-miimon 100` | ★★★★ 每 100 ms 檢查一次鏈路狀態 | ★★★★ |

#### 做法二：802.3ad LACP（★★★★ 效益最好，兩邊都要設）

```ini

iface bond0 inet manual
    bond-slaves enp1s0 enp2s0
    bond-mode 802.3ad
    bond-miimon 100
    bond-lacp-rate 1
    bond-xmit-hash-policy layer2+3

auto vmbr0
iface vmbr0 inet static
    address 192.168.99.11/24
    gateway 192.168.99.254
    bridge-ports bond0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094
```

| 參數 | 意義 | 重要度 |
| --- | --- | --- |
| `bond-mode 802.3ad` | LACP | ★★★★★ |
| `bond-lacp-rate 1` | ★★★ **fast**（每秒送 LACPDU），對應交換器的 `periodic fast` | ★★★★ |
| `bond-xmit-hash-policy layer2+3` | ★★★★ 用「來源+目的 MAC 與 IP」決定走哪條線 | ★★★★ |

| 策略 | 依據 | 適合 | 重要度 |
| --- | --- | --- | --- |

| ★★★★ `layer2+3` | MAC + IP | ★★★★ 一般用途最平衡，**PVE 建議值** | ★★★★ |
| `layer3+4` | IP + 埠號 | ★★★ 分散最好，但**嚴格說不完全符合 802.3ad**（同一連線可能亂序） | ★★★ |

> [!danger] ★★★★★ Jumbo Frame 是「全鏈路」設定
> **主機、交換器每一個埠、對端主機，任何一環沒改就會出問題**，
> 而且症狀很惡劣：小封包（ping、SSH）正常，大量傳輸（NFS、備份、Ceph）卡住或超慢。
>
> ★★★★ 只在**專用的儲存／備份網段**開 Jumbo，
> **管理網段與 VM 服務網段維持 1500**，這是最不容易出事的做法。

### SDN 概覽 ★★★

PVE 8 內建 SDN（Software Defined Network），設定放在 `/etc/pve/sdn/`，
套用後產生 `/etc/network/interfaces.d/sdn`。

| Zone 類型 | 做什麼 | 什麼時候需要 | 重要度 |
| --- | --- | --- | --- |
| **Simple** | 在節點內建一個隔離的 L3 網段，可帶 NAT 與 DHCP | ★★★ 單節點實驗、給 VM 一個內部網段 | ★★★ |
| **VLAN** | 把既有的 VLAN 集中管理，跨節點統一命名 | ★★★★ **多節點且 VLAN 很多時最實用** | ★★★★ |
| **QinQ** | 雙層 VLAN 標籤（service tag + customer tag） | 多租戶、VLAN ID 不夠用 | ★★ |
| **VXLAN** | L2 over UDP 疊加網路 | ★★★ 跨機房延伸 L2、VLAN 4094 上限不夠 | ★★★ |
| **EVPN** | VXLAN + BGP 控制平面，含分散式路由 | 大型多租戶環境 | ★★ |

> [!tip] ★★★★★ 什麼時候「不需要」SDN
> **絕大多數機關環境不需要。**
> 只有一台或兩三台節點、VLAN 就那幾個 → ★★★★
> **直接用 VLAN aware bridge + 交換器 trunk 就好**，
> 簡單、直接、出事時看得懂。
>
> 考慮 SDN 的訊號：
> - 節點數超過五台，而且**每台的橋接設定要保持一致**很痛苦 → VLAN zone 有價值
> - 需要跨機房延伸 L2、或 VLAN ID 不夠用 → VXLAN／EVPN
> - 需要每個網段自動配 DHCP、自動 NAT → Simple zone
>
> ★★★★ SDN 多一層抽象，**排錯難度也多一層**。沒有明確需求不要導入。

```bash

```

```text

```

```bash

```

★★★ 沒有檔案代表沒啟用 SDN，這是乾淨的預設狀態。

## 完整實戰範例

**目標**：把一台只有單網卡、單一網段的 PVE 節點，
改造成 **雙網卡 LACP bond + VLAN aware bridge + 交換器 trunk 對接**，
並開啟 PVE 防火牆保護管理介面。全程有驗證，最後做完整檢查。

### 環境與規劃

| 項目 | 改造前 | ★★★★ 改造後 |
| --- | --- | --- |
| 網卡 | `enp1s0` 單張 | `enp1s0` + `enp2s0` → `bond0`（LACP） |
| 橋接 | `vmbr0`（非 VLAN aware） | `vmbr0`（VLAN aware，vids 2-4094） |
| 管理 IP | `192.168.99.11/24` on vmbr0 | 不變（走 native VLAN 99） |
| 交換器 | `ge-0/0/10` access VLAN 99 | `ae0`（`ge-0/0/10` + `ge-0/0/11`）trunk |
| VLAN | 只有 99 | 99（native／管理）、10（服務）、20（測試） |
| 防火牆 | 關閉 | 資料中心層啟用 + VM 層規則 |

★★★★★ **前置條件：你必須有 IPMI／iDRAC／iLO 或能接實體螢幕鍵盤。**
這個流程中間**一定會斷線**。

### 步驟 2：交換器端先建好 LAG（★★★★ 先做交換器）

> [!tip] ★★★★★ 為什麼先做交換器端
> Juniper 的 `ae0` 在 PVE 端還沒跑 LACP 時，**成員埠會維持 down 或 detached**，
> 不會影響現有流量走 `ge-0/0/10`……**但這正是問題所在**。
> 實務上最安全的順序是：
> 1. 先建 `ae0` 只放**尚未使用**的 `ge-0/0/11`，
> 2. 再改 PVE 端做 bond（此時只有 `enp2s0` 這條會 up），
> 3. 確認通了之後，才把 `ge-0/0/10` 也加進 `ae0`。

set interfaces ae0 unit 0 family ethernet-switching interface-mode trunk
set interfaces ae0 unit 0 family ethernet-switching vlan members [ mgmt svc test ]
set interfaces ae0 native-vlan-id 99
```

### 步驟 3：PVE 端改成 bond + VLAN aware

```bash

auto lo
iface lo inet loopback

iface enp2s0 inet manual

auto bond0
iface bond0 inet manual
    bond-slaves enp2s0
    bond-mode 802.3ad
    bond-miimon 100
    bond-lacp-rate 1
    bond-xmit-hash-policy layer2+3

auto vmbr0
iface vmbr0 inet static
    address 192.168.99.11/24
    gateway 192.168.99.254
    bridge-ports bond0
    bridge-stp off
    bridge-fd 0
    bridge-vlan-aware yes
    bridge-vids 2-4094

source /etc/network/interfaces.d/*
EOF
```

## 常見錯誤與排錯

| 現象（原文訊息） | 原因 | 解法 |
| --- | --- | --- |
| ★★★★★ 在 Web 介面改完網路卻沒生效 | 忘了按「Apply Configuration」，設定還在 `interfaces.new` | 按 Apply，或指令列 `ifreload -a` |
| ★★★★ `error: bond0: bond-slaves: enp1s0: unsupported bond mode` 之類語法錯 | `/etc/network/interfaces` 拼字錯或縮排錯 | ★★★★ `ifreload -a -n` dry-run 先驗；縮排要用空白且一致 |
| ★★★★★ 改完 `ifreload -a` 就完全斷線 | 管理 IP 掛錯介面、native VLAN 對不上、或 bond 模式與交換器不一致 | 從 IPMI console 進去，`cp /root/interfaces.*.bak /etc/network/interfaces && ifreload -a` |
| ★★★★★ 主機設 `802.3ad`、交換器沒設 LAG → 網路時通時不通 | ★★★★★ MAC 在兩個埠之間跳動 | 立刻改回 `active-backup`，或把交換器 LAG 設好 |
| ★★★★ `/proc/net/bonding/bond0` 顯示 `Partner Mac Address: 00:00:00:00:00:00` | 交換器沒回 LACPDU（沒設 LAG、或設成 `mode on` 靜態） | 交換器端改成 `lacp active`（Cisco `channel-group N mode active`） |
| ★★★★ Cisco `show etherchannel summary` 顯示 `Gi0/10(I)` | 兩個成員埠的 trunk 設定不一致，或對面不是 LACP | 讓兩埠設定完全相同；確認 PVE 是 `802.3ad` |
| ★★★★★ VM 設了 `tag=10` 卻完全不通 | ① `bridge-vlan-aware` 沒開；② 交換器 trunk 沒放行 VLAN 10；③ VLAN 10 在交換器上不存在 | 依序檢查 `bridge vlan show`、`show ethernet-switching interface`、`show vlans` |
| ★★★★★ 節點管理 IP ping 不到閘道，但 VM 的 VLAN 都正常 | ★★★★★ 交換器 trunk 的 **native VLAN 設錯** | 把 `native-vlan-id` 改成管理 VLAN（Cisco `switchport trunk native vlan`） |
| ★★★★★ Cisco 上多打一次 `switchport trunk allowed vlan 30` 之後全斷 | 該指令是**取代**不是附加 | 用 `switchport trunk allowed vlan add 30`；已斷線時從 console 補回原本清單 |
| ★★★★ `ifreload` 報 `RTNETLINK answers: File exists`（route replace default） | 設定了兩個 `gateway` | 只保留一個 `gateway`，其餘用 `post-up ip route add` |
| ★★★★ 開了防火牆之後連不上 8006／22 | 規則寫在 enable 之後，或 `local_network` 偵測錯誤 | IPMI 進去把 `enable` 改回 `0`；先寫規則再 enable；用 Alias 明確指定 `local_network` |
| ★★★★ VM 層防火牆規則寫了卻不生效 | 網卡沒有 `firewall=1`，或資料中心層總開關沒開 | `qm set`／`pct set` 加 `firewall=1`；`ip -br link \| grep fwbr` 確認中間橋接存在 |
| ★★★★ 大檔案傳輸卡死，小封包正常 | MTU 不一致（單邊開了 Jumbo） | `ping -M do -s 8972` 測；全鏈路統一 MTU，或退回 1500 |
| ★★★ `ip -br link` 出現一堆 `fwbr`／`fwln`／`fwpr` | ★★★ **正常**，防火牆的中間橋接 | 不用處理 |
| ★★★ 兩台 VM 在同一個 VLAN 卻互通不了 | 交換器上有 port isolation／private VLAN；或兩台不在同一橋接 | 檢查交換器埠隔離設定與 `bridge link show` |
| ★★★★ 節點重開機後網路沒起來 | 缺 `auto` 行，或網卡名稱因硬體變動而改變 | ★★★★ 每個要開機啟用的介面都要有 `auto`；用 `ip -br link` 對名稱 |
| ★★★★ 遷移 VM 到另一節點後網路不通 | ★★★★ 目標節點沒有同名的橋接，或該橋接不是 VLAN aware | 所有節點的橋接命名與 VLAN aware 設定要一致 |
| ★★★ SDN 設定套用後 `/etc/network/interfaces.d/sdn` 沒產生 | 沒按「Apply」，或 zone/vnet 設定不完整 | 在 SDN 頁面按 Apply；檢查 vnet 是否綁到 zone |
| ★★★★★ 叢集節點隨機被 fence 重開 | ★★★★★ corosync 與備份／儲存流量共用網段被塞爆 | 把 corosync 移到專用網段；見 [[050-01-03-07-svc-PVE-叢集與高可用]] |
| ★★★ `bridge-stp on` 打開之後某些埠不轉送 | STP 與上游交換器互動，埠進入 blocking | ★★★★ PVE 上**保持 `bridge-stp off`**，迴圈防護交給交換器 |

> [!tip] ★★★★ 排錯的固定順序
> ```
> 1. ip -br link          → 介面在不在、up 不 up
> 2. ip -br addr          → IP 對不對、掛在哪個介面
> 3. ip route             → 預設路由對不對
> 4. bridge vlan show     → VLAN 標籤對不對
> 5. cat /proc/net/bonding/bond0 → bond 協商成功沒
> 6. 交換器端 show 指令   → 對面看到什麼
> 7. pve-firewall status  → 是不是被防火牆擋
> ```
> ★★★★ **由近而遠、由下而上**。不要一開始就懷疑交換器。

## 安全性注意事項

### ★★★★★ 管理平面與服務平面要分開

```
❌ 危險做法                          ✅ 建議做法
┌──────────────────┐              ┌──────────────────┐
│ vmbr0            │              │ VLAN 99 管理     │ ← 只有資訊室網段連得到
│ 管理 IP 8006     │              │  - PVE Web 8006  │
│ VM 服務也在這裡  │              │  - SSH 22        │
│ 全部同一個網段   │              ├──────────────────┤
└──────────────────┘              │ VLAN 10 服務     │ ← 使用者連這裡
   ★★★★★ 一台 VM 被打進去          │  - VM 的服務     │
   就能直接掃到 8006 管理介面      └──────────────────┘
```

| 措施 | 說明 | 重要度 |
| --- | --- | --- |
| ★★★★★ 管理介面**不對 Internet 開放** | 8006 埠不做 port forward、不進 DMZ | ★★★★★ |
| ★★★★★ 管理走獨立 VLAN | 用交換器 ACL 或 PVE 防火牆限制來源 | ★★★★★ |
| ★★★★ 需要遠端管理就走 VPN | 不要用「換 port」當安全措施 | ★★★★ |
| ★★★★ VM 網卡一律 `firewall=1` | 才能做每台的規則 | ★★★★ |
| ★★★ 用 Alias／IPSet 管理來源 | 規則可讀、改一處生效 | ★★★ |

### ★★★★ VLAN 不是安全邊界，但是很好的第一層

★★★★ VLAN 能擋住「同網段隨便亂掃」，但：

- ★★★★ **VLAN hopping**（double tagging、switch spoofing）在設定不當的交換器上是可能的。
  防範：★★★★★ **native VLAN 不要用 VLAN 1，也不要拿來承載使用者流量**；
  access 埠關掉 DTP（Cisco `switchport nonegotiate`）。
- ★★★★ **跨 VLAN 的管制要靠三層設備**（防火牆／L3 交換器 ACL），
  不是靠 VLAN 本身。

### ★★★★ 不要關掉的東西

| 項目 | 為什麼不要動 | 重要度 |
| --- | --- | --- |
| `bridge-stp off` | ★★★★ PVE 預設 off 是對的。打開反而可能跟上游 STP 互相干擾造成埠 blocking | ★★★★ |
| 交換器上的 BPDU Guard／Root Guard | ★★★★★ 這是防止「有人把小 switch 接進來造成迴圈」的最後防線 | ★★★★★ |
| `source /etc/network/interfaces.d/*` | SDN 靠它，刪掉會讓 SDN 網段全部消失 | ★★★★ |

### ★★★★ 防火牆規則的紀律

- ★★★★ **預設 DROP，明確放行**（`policy_in: DROP`）。
- ★★★★ 規則要**寫來源**，不要 `IN ACCEPT -p tcp -dport 22` 就放全世界。
- ★★★ 用 `-log info` 在導入期收集，穩定後再改回 `nolog`（避免日誌爆量）。
- ★★★★ ★ **每次改防火牆前先確認 IPMI 可用**，並開著第二個 SSH 連線不要關。
- ★★★ 規則檔在 `/etc/pve/`（pmxcfs），叢集同步，★★★★ 改資料中心層會**立刻影響所有節點**。

### ★★★ 其他

- ★★★★ 節點的 `enp*` 實體介面**不要配 IP**，保持 `manual`，減少非預期的暴露面。
- ★★★ 不用的網卡就**不要接線**，接了就是攻擊面。
- ★★★★ VM 的 `net0` 若用 `bridge=vmbr1`（無 uplink），確認那是刻意的隔離網段，
  不是「以為接得到外面」。
- ★★★ 管理網段的存取紀錄要送到集中日誌，見 [[100-01-02-guide-日誌-日誌集中與輪替]]。

## 練習題

1. **讀懂現況**：在你的 PVE 節點上跑 `ip -br link`、`ip -br addr`、`bridge vlan show`、
   `cat /etc/network/interfaces`，畫出一張圖說明「實體網卡 → 橋接 → VM 網卡」的路徑，
   並標出管理 IP 掛在哪裡。

2. **★★★★ 開啟 VLAN aware**：把 `vmbr0` 加上 `bridge-vlan-aware yes` 與 `bridge-vids 2-4094`。
   先用 `ifreload -a -n` 看它打算做什麼，再套用，最後用 `bridge vlan show` 驗證。
   （★★★★★ 有 IPMI 再做，或在練習環境做，見 [[050-01-03-13-guide-PVE-建立練習環境]]）

3. **★★★★★ 交換器對照練習**：假設你的管理網段是 VLAN 50、服務網段是 VLAN 60。
   寫出 (a) PVE 的 `vmbr0` 設定、(b) Juniper 的 trunk 設定、(c) Cisco 的 trunk 設定。
   特別注意 native VLAN 要設哪一個、為什麼。

4. **Bond 選型判斷**：下列三個情境各該用哪一種 bond 模式？寫出理由。
   (a) 兩張網卡接到兩台**沒有堆疊**的獨立交換器；
   (b) 兩張網卡接到同一台交換器，網管願意配合設 LAG；
   (c) 兩張網卡接到同一台交換器，但改交換器要跑三個星期的流程。

5. **★★★★ 防火牆演練**：在練習環境開啟資料中心防火牆。
   ★★★★★ 依照本篇「正確順序」操作：先 `pve-firewall localnet` → 寫規則 →
   `pve-firewall compile` 驗語法 → 最後才 `enable: 1`。
   驗證 SSH 與 8006 都還通，然後刻意把某個 VM 的 80 埠擋掉再放行，觀察差異。

6. **★★★★★ 拔線容錯驗收**：如果你的環境已經有 bond，
   從管理電腦開一個持續 `ping`，實體拔掉其中一條線，記錄掉了幾個封包、
   `/proc/net/bonding/bond0` 的 `Number of ports` 與 `Link Failure Count` 怎麼變。
   插回去之後再記錄一次。

> [!question]- 練習解答
>
> **1.** 典型答案（單網卡預設安裝）：
> ```
> enp1s0（無 IP，manual）
>    └─ vmbr0（192.168.99.11/24，gateway 192.168.99.254）
>         ├─ tap101i0  → VM 101
>         └─ veth201i0 → CT 201
> ```
> ★★★★ 重點：**管理 IP 掛在 `vmbr0`，不是 `enp1s0`**。
>
> **2.**
> ```bash
> cp -a /etc/network/interfaces /root/interfaces.bak
> # 在 vmbr0 區塊加入兩行
> #     bridge-vlan-aware yes
> #     bridge-vids 2-4094
> ifreload -a -n     # 會看到 bridge vlan add vid 2-4094 dev enp1s0
> ifreload -a
> bridge vlan show
> ```
> 通過條件：`enp1s0`（或 `bond0`）那一列出現 `2-4094`。
>
> **3.**
> (a) PVE：
> ```ini
> auto vmbr0
> iface vmbr0 inet static
>     address 192.168.50.11/24
>     gateway 192.168.50.254
>     bridge-ports enp1s0
>     bridge-stp off
>     bridge-fd 0
>     bridge-vlan-aware yes
>     bridge-vids 2-4094
> ```
> (b) Juniper：
> ```junos
> set vlans mgmt vlan-id 50
> set vlans svc vlan-id 60
> set interfaces ge-0/0/10 unit 0 family ethernet-switching interface-mode trunk
> set interfaces ge-0/0/10 unit 0 family ethernet-switching vlan members [ mgmt svc ]
> set interfaces ge-0/0/10 native-vlan-id 50
> ```
> (c) Cisco：
> ```cisco
> interface GigabitEthernet0/10
>  switchport trunk encapsulation dot1q
>  switchport mode trunk
>  switchport trunk native vlan 50
>  switchport trunk allowed vlan 50,60
> ```
> ★★★★★ **native VLAN 必須是 50（管理）**，因為 PVE 節點的管理 IP 掛在 `vmbr0` 本身、
> 送出去是 untagged，交換器要把它歸到管理 VLAN 才連得上。
>
> **4.**
> (a) ★★★★★ **`active-backup`**。LACP 無法跨兩台獨立（未堆疊）的交換器成立。
> (b) ★★★★ **`802.3ad`（LACP）**，效益最好，兩邊一起設。
> (c) ★★★★ **`active-backup`**。交換器端零設定，你自己就能完成，容錯效果一樣有，
>     只是沒有頻寬疊加。等流程跑完再升級成 LACP。
>
> **5.** 關鍵在順序：
> ```bash
> pve-firewall localnet                      # 確認網段
> vi /etc/pve/firewall/cluster.fw            # enable: 0，先寫好 RULES
> pve-firewall compile > /dev/null           # 驗語法
> sed -i 's/^enable: 0$/enable: 1/' /etc/pve/firewall/cluster.fw
> pve-firewall status                        # enabled/running
> ssh root@<節點IP> 'echo ok'                # 立刻驗證
> ```
> VM 層擋 80：在 `/etc/pve/firewall/<VMID>.fw` 的 `[RULES]` 拿掉那行 ACCEPT
> （或改成 `IN DROP -p tcp -dport 80`），並確認網卡有 `firewall=1`。
>
> **6.** 預期結果：
> - LACP fast rate：掉 0～2 個封包。
> - `active-backup` 搭 `bond-miimon 100`：通常掉 1～3 個。
> - `Number of ports` 從 2 → 1（LACP）；`Currently Active Slave` 換人（active-backup）。
> - `Link Failure Count` 該成員 +1。
> ★★★★★ 掉超過 5 個封包、或根本沒切過去，代表 bond 設定有問題，
> 最常見的是交換器端與主機端模式不一致。

## 小測驗

**Q1.**（是非）在 PVE 的 Web 介面改完網路設定按下 OK，設定就已經生效了。

**Q2.** 為什麼 PVE 預設把管理 IP 掛在 `vmbr0` 而不是 `enp1s0`？

**Q3.**（選擇）`bridge-vlan-aware yes` 開啟之後，一台 VM 要屬於 VLAN 20，該怎麼做？
(A) 在主機建一個 `vmbr20` 橋接　(B) 在 VM 網卡填 `tag=20`
(C) 在 VM 的作業系統裡設 VLAN 子介面　(D) 交換器把該埠設成 access VLAN 20

**Q4.** 這段設定有什麼問題？
```ini
auto bond0
iface bond0 inet manual
    bond-slaves enp1s0 enp2s0
    bond-mode 802.3ad
```
（提示：交換器端）

**Q5.**（簡答）節點的管理 IP 是 `192.168.99.11/24`，掛在 VLAN aware 的 `vmbr0` 上、沒有 tag。
交換器的 trunk 埠 native VLAN 設成 1。會發生什麼事？怎麼修？

**Q6.**（選擇）`cat /proc/net/bonding/bond0` 看到 `Partner Mac Address: 00:00:00:00:00:00`，
最可能的原因是？
(A) 網路線壞了　(B) 交換器端沒有設定 LACP
(C) `bond-miimon` 設太小　(D) MTU 不一致

**Q7.** 在 Cisco 交換器的 trunk 埠上，已經有 `switchport trunk allowed vlan 10,20,99`。
現在直接下 `switchport trunk allowed vlan 30` 會發生什麼事？正確的做法是什麼？

**Q8.**（是非）在 PVE 資料中心防火牆按下 enable 之後，如果被鎖在外面，
可以從其他節點的 Web 介面把它關掉。

**Q9.**（簡答）VM 的防火牆規則寫好了、`/etc/pve/firewall/101.fw` 也 `enable: 1`，
但規則完全沒作用。請說出兩個要檢查的地方。

**Q10.**（簡答）什麼情況下才值得導入 PVE 的 SDN？什麼情況下用 VLAN aware bridge 就夠？

> [!question]- 測驗答案
>
> **A1.** ★★★★★ **否。** Web 介面的變更會先寫到 `/etc/network/interfaces.new`，
> 必須再按「**Apply Configuration**」（或指令列 `ifreload -a`）才會生效。
> 這是 PVE 特有的 pending 機制，見「ifupdown2 與 `ifreload -a`」。
>
> **A2.** 因為 ★★★★ **`vmbr0` 是一台軟體交換器，VM 與 CT 的虛擬網卡插在它上面**。
> 實體網卡只是這台軟體交換器的 uplink，所以保持 `manual`（不配 IP），
> 讓主機自己也「插」在同一台軟體交換器上（IP 掛 `vmbr0`）。
> 這樣主機與 VM 才在同一個二層域裡。
>
> **A3.** **(B) 在 VM 網卡填 `tag=20`**。
> 這正是 VLAN aware bridge 的好處：★★★★ **新增 VLAN 不用改主機設定**。
> (A) 是傳統做法（不用 vlan-aware 時才這樣做）；(D) 會讓 trunk 失效。
>
> **A4.** ★★★★★ **`802.3ad` 需要交換器端也設 LAG 並啟用 LACP**，
> 這段設定本身語法沒錯，但如果交換器端沒有對應的 `ae0`／`Port-channel`，
> 就會出現「同一個 MAC 在兩個埠之間跳動」→ **網路時通時不通**。
> 不確定交換器能不能配合時，★★★★ **先用 `active-backup`**。
>
> **A5.** ★★★★★ 節點送出的管理封包是 **untagged**，
> 交換器會把它歸到 native VLAN **1**，而不是管理網段所在的 VLAN 99 →
> **節點的管理 IP 落在錯誤的網段，你連不上 PVE**。
> 修法：把交換器 trunk 的 `native-vlan-id`（Cisco `switchport trunk native vlan`）
> 改成管理 VLAN 99；或反過來在 PVE 端改用 `vmbr0.99` 讓管理流量也帶標籤。
>
> **A6.** **(B) 交換器端沒有設定 LACP**。
> Partner MAC 全 0 代表**沒有收到對面的 LACPDU**。
> 可能是交換器沒建 LAG，或建成了靜態 LAG（Cisco `mode on`）而不是 `mode active`。
>
> **A7.** ★★★★★ 該指令是**取代**而不是附加 —— VLAN 10、20、99 全部被踢掉，
> 只剩 VLAN 30 →**trunk 上的所有現有流量瞬間中斷，包含管理網段**。
> 正確做法是 `switchport trunk allowed vlan add 30`。
> ★★★★ 這是 Cisco 上最經典的斷線意外，見速查表「交換器對照」。
>
> **A8.** ★★★★★ **否（不可靠）。** `/etc/pve/firewall/cluster.fw` 在 pmxcfs 上，
> 是**叢集共用**的 —— 資料中心層的規則會同時套用到**所有節點**，
> 所以你很可能是被**全部節點**一起鎖在外面。
> ★★★★★ 這就是為什麼「開防火牆前必須確認 IPMI／console 可用」。
>
> **A9.** 兩個要檢查的地方：
> 1. ★★★★★ **VM 網卡有沒有 `firewall=1`**（`qm config 101 | grep net0`），
>    沒有的話 PVE 不會建 `fwbr101i0` 中間橋接，規則掛不上去；
> 2. ★★★★ **資料中心層的總開關 `enable` 是不是 1**，三層是疊加的，
>    上層沒開，下層規則不會被編譯進去。
> 驗證方式：`ip -br link | grep fwbr` 應該看得到中間橋接。
>
> **A10.** ★★★★ **絕大多數機關環境用 VLAN aware bridge + 交換器 trunk 就夠**：
> 節點少、VLAN 固定、網管與系統管理都在同一個單位。
> 值得導入 SDN 的訊號是：
> - 節點數多（五台以上）且要**保證每台橋接設定一致**；
> - 需要**跨機房延伸 L2** 或 VLAN ID 不夠用（VXLAN／EVPN）；
> - 需要每個網段**自動 DHCP／NAT**（Simple zone）。
> ★★★★ SDN 多一層抽象，排錯難度也多一層，沒有明確需求不要導入。
