## 是非題（50 題）

Q1. KVM 這一層只負責 CPU 與記憶體的虛擬化，硬碟、網卡、顯示卡等裝置的模擬是 QEMU 在做。

Q2. 一台 libvirt 管理的 VM 在主機上就是一個 `qemu-system-x86_64` 程序，所以要關掉它時，
在主機上 `kill -9` 那個 PID 是安全且乾淨的做法。

Q3. domain XML 是設定的唯一真相來源，因此直接用編輯器改 `/etc/libvirt/qemu/web01.xml`
再重啟 VM，修改就會生效。

Q4. 在新版 Ubuntu 上找不到 `libvirtd.service` 是正常的 —— 守護行程已經模組化，
管 VM 的是 `virtqemud`，網路與儲存另有 `virtnetworkd`、`virtstoraged`。

Q5. `<domain type='qemu'>` 與 `<domain type='kvm'>` 只是兩種寫法，跑起來的效能是一樣的。

Q6. Proxmox VE 底層用的就是 KVM 與 QEMU，所以在 PVE 主機上可以直接用 `virsh list` 管理它的 VM。

Q7. libvirt 不是只能管 KVM，它還有 LXC、Xen、bhyve 等驅動，`qemu:///system` 只是其中一種連線。

Q8. `virsh dominfo` 顯示的 `Used memory` 就是客體目前實際使用的記憶體量。

Q9. `/dev/kvm` 的正確權限是 `root:kvm 660`；把它 `chmod 666` 可以省掉群組設定，
是常見而且安全的簡化做法。

Q10. `virt-host-validate` 的 IOMMU 檢查顯示 WARN 時，一般用途的 VM 仍可正常運作，
因為 IOMMU 只影響 PCI 直通。

Q11. `qemu:///system` 與 `qemu:///session` 是兩個互相看不到對方 VM 的獨立世界，
連 VM 定義與磁碟的預設存放位置都不同。

Q12. session 模式一樣可以用 `virsh autostart` 設定 VM 在主機開機時自動啟動。

Q13. session 模式的 VM 可以接到 `virbr0` 這個 NAT 網路上。

Q14. 跑完 `sudo usermod -aG libvirt $USER` 之後，目前這個 shell 立刻就擁有 libvirt 群組權限。

Q15. `newgrp libvirt` 之後 `virsh` 可以用，但開一個新的終端分頁又不行 —— 這是預期行為，不是 bug。

Q16. `sudo usermod -G libvirt ops`（少了 `-a`）會在保留 ops 原有附加群組的前提下加入 libvirt。

Q17. `libvirt` 群組是一個低權限群組，把使用者加進去比給他 sudo 安全得多。

Q18. 在 BIOS 打開 Intel VT-x 之後，只要下 `reboot` 就一定會生效。

Q19. 要在 VMware Workstation 的 VM 裡面安裝 KVM，必須先把那台 VM 關機，
才能勾選 `Virtualize Intel VT-x/EPT`。

Q20. QEMU 的執行身分在 Ubuntu／Debian 上是 `libvirt-qemu`，在 RHEL 系上是 `qemu`。

Q21. `virsh destroy web01` 會刪除 web01 的 domain 定義與磁碟檔。

Q22. libvirt 的 `virsh destroy` 對應到 PVE 的 `qm stop`，而 PVE 的 `qm destroy` 對應到 `virsh undefine`。

Q23. `virsh create vm.xml` 與 `virsh define vm.xml` 都會把定義寫進 `/etc/libvirt/qemu/`，
差別只在前者會順便啟動。

Q24. `virsh undefine web01` 預設會一併刪掉這台 VM 的磁碟檔。

Q25. `virsh list` 不加 `--all` 時只列出執行中的 VM，關機的不會出現。

Q26. `virsh reboot` 會重建 QEMU 程序，所以改完 XML 用 `reboot` 就能套用硬體變更。

Q27. 改完 XML、完整 `shutdown` 再 `start` 仍然沒生效時，要檢查這台 VM 是不是有 managedsave 狀態。

Q28. 內部快照存在 qcow2 檔案內部，只支援 qcow2 格式；raw 格式的磁碟做不了內部快照。

Q29. `virsh snapshot-revert` 對內部快照與外部快照都適用。

Q30. 刪掉外部快照的 overlay 檔之後，VM 會照樣開機，只是回到快照當時的狀態。

Q31. `virsh console` 的退出鍵是 `Ctrl + ]`；按 `Ctrl + C` 只會把中斷訊號送進客體。

Q32. `virsh migrate --live` 沒有帶 `--persistent` 時，目的端拿到的是暫態 domain，
主機重開機後這台 VM 就消失了。

Q33. 在腳本裡用 domain 的 Id 來指定 VM 是可靠的做法，因為 Id 是固定不變的。

Q34. libvirt 的 storage pool 就是「一個 libvirt 認得的儲存位置」，
pool 裡的每一個磁碟檔或 LV 稱為 volume。

Q35. 把一片新的 ISO `cp` 進 pool 的目錄之後，`virsh vol-list` 立刻就會看到它。

Q36. `virsh pool-destroy vmstore` 會刪掉 vmstore 這個 pool 裡的所有磁碟檔。

Q37. `virsh pool-delete` 是不可逆操作 —— 它刪的是 pool 的**內容**，不是定義。

Q38. `virsh pool-build` 對 `logical` 與 `fs` 型式的 pool 會格式化目標裝置。

Q39. 跑完 `qemu-img resize disk.qcow2 +20G` 之後，客體裡的分割區與檔案系統會跟著自動變大。

Q40. 對一台執行中的 VM 跑 `qemu-img convert` 是安全的，因為 `qemu-img` 只是讀取磁碟。

Q41. `virbr0` 的 NAT 網路是由 libvirt 起的 dnsmasq 發 DHCP；
`/var/lib/libvirt/dnsmasq/*.conf` 是自動產生的，不應該手動編輯。

Q42. 在 KVM 主機上手動跑 `iptables -F` 會把 libvirt 插入的 `LIBVIRT_*` 規則一起清掉，
VM 的 NAT 立刻失效。

Q43. 主機的 `ufw` 預設會過濾橋接到 `br0` 的 VM 封包，所以橋接的 VM 受主機防火牆保護。

Q44. cloud-init 只在「第一次開機、對一個新的 instance」執行完整設定；
判斷是不是新 instance 靠的是 `instance-id`。

Q45. seed ISO 的 volume label 可以隨便取，cloud-init 會自動掃描所有光碟找設定。

Q46. `user-data` 的第一行必須是 `#cloud-config`；前面多一個空白行或有 BOM，
整份設定就會被安靜地忽略。

Q47. 範本沒有清掉 `machine-id` 時，複製出來的多台 VM 可能會向 DHCP 要到同一個 IP。

Q48. 清 `machine-id` 的正確做法是 `sudo rm /etc/machine-id`，讓系統下次開機重新產生。

Q49. `virt-sysprep` 可以對執行中的 VM 直接操作，因為它只是讀取客體檔案系統。

Q50. 用 `qemu-img create -f qcow2 -F qcow2 -b base.qcow2 child.qcow2` 建的連結複製，
一旦 base 被刪掉或改名，child 就開不起來。

## 選擇題（50 題）

Q51. 關於 KVM、QEMU、libvirt 三層的分工，下列敘述何者最正確？
(A) KVM 是完整的 hypervisor，QEMU 只是它的圖形介面
(B) KVM 是核心模組，讓 CPU 進入客體模式並處理記憶體虛擬化；QEMU 是使用者空間程序，負責裝置模擬與 I/O；libvirt 是管理層，把設定寫成 XML 並展開成 QEMU 命令列
(C) libvirt 取代了 QEMU，現在的 VM 由 libvirt 直接執行
(D) 三者是可以互相替換的三種 hypervisor

Q52. 主機上有一個 `qemu-system-x86_64` 程序吃掉大量 CPU，你確認它屬於 `web01`。
下列處置何者正確？
(A) `kill -9 <pid>` 最快
(B) `pkill qemu` 一次解決
(C) 先 `virsh shutdown web01` 優雅關機，逾時未關才 `virsh destroy`；`kill -9` 等同對這台 VM 拔插頭，客體檔案系統與資料庫可能損毀
(D) 直接 `virsh destroy web01`，反正 destroy 比 kill 安全

Q53. 你在一台 Ubuntu 24.04 上下 `sudo systemctl restart libvirtd`，得到
`Unit libvirtd.service could not be found`。最正確的判斷是？
(A) libvirt 沒裝好，重裝套件
(B) 這台是模組化守護行程架構，沒有 `libvirtd` 這個單元；要重啟的是 `virtqemud`（網路是 `virtnetworkd`、儲存是 `virtstoraged`），先用 `systemctl list-units 'virt*' 'libvirt*'` 確認實際有哪些
(C) 需要先 `systemctl daemon-reload`
(D) 要改用 `service libvirtd restart`

Q54. 同事說他改了 `/etc/libvirt/qemu/web01.xml` 把記憶體從 2 GB 改成 4 GB，
重開 VM 卻沒有生效。原因與正解是？
(A) 記憶體不能超過 2 GB
(B) 檔案要 `chmod 644` 才會被讀
(C) 直接編輯該檔案無效 —— 守護行程記憶體裡有一份定義會覆蓋回去；一律用 `virsh edit web01`（或 `virt-xml --edit ... --config`），改記憶體還要完整停機再開機
(D) 要先 `systemctl restart virtqemud` 才會讀檔

Q55. 一台 VM 慢到客體開機要五分鐘。你該先查什麼？
(A) 加大 vCPU 數量
(B) `virsh dumpxml <vm> | grep "domain type"` 與 `ps -ef | grep qemu-system | grep -o '\-accel [a-z]*'`；出現 `type='qemu'` 或 `-accel tcg` 代表掉回純軟體模擬，效能差十倍以上，這件事沒有任何警告訊息
(C) 換一顆更快的主機磁碟
(D) 把記憶體加到兩倍

Q56. 關於 Proxmox VE 與 KVM 的關係，下列何者正確？
(A) PVE 是另一套 hypervisor，跟 KVM 無關
(B) PVE 底層就是 KVM／QEMU，但它**不使用 libvirt**：VM 定義在 `/etc/pve/qemu-server/<vmid>.conf`，管理指令是 `qm`；在 PVE 主機上安裝 libvirt 會建出 `virbr0` 與衝突的防火牆規則
(C) PVE 是 libvirt 的圖形前端
(D) PVE 上的 VM 可以用 `virsh` 管理，只是要加 `-c qemu:///system`

Q57. `virsh start web01` 回 `Could not access KVM kernel module: Permission denied`。
最可能的原因與處置是？
(A) 使用者不在 `libvirt` 群組
(B) QEMU 的執行身分沒有 `/dev/kvm` 的權限；確認 `ls -l /dev/kvm` 是 `crw-rw---- root kvm`、
`libvirt-qemu`（RHEL 是 `qemu`）在 `kvm` 群組，必要時重啟守護行程
(C) 磁碟權限不對
(D) 把 `/dev/kvm` 改成 666 是標準解法

Q58. 一台橋接到 `br0` 的 VM，用 `virsh domifaddr web01` 查不到 IP。原因與正解是？
(A) VM 真的沒有 IP
(B) `domifaddr` 預設查的是 `virbr0` 的 DHCP 租約，橋接網路當然查不到；改用 `--source agent`（客體需裝 `qemu-guest-agent`）或 `--source arp`
(C) 要先 `virsh net-dhcp-leases br0`
(D) 橋接網路不支援查 IP，只能進客體看

Q59. 一台主機有 64 GB 實體記憶體，主機本身（OS、libvirt、監控代理）需保留 8 GB。
現在要開 6 台各配 8 GB 的 VM，每台 QEMU 程序另有約 200 MB 的額外開銷。
下列判斷何者正確？
(A) 可行：6 × 8 GB ＝ 48 GB，加上 6 × 0.2 GB ≈ 1.2 GB 開銷與主機的 8 GB，
總需求約 57.2 GB，還剩約 6.8 GB 緩衝
(B) 不可行：總需求已超過 64 GB
(C) 可行，但一定要另外開 32 GB 的 swap 才安全
(D) 記憶體可以像 CPU 一樣超賣，所以開 12 台也沒問題

Q60. 主機 load average 很高，但 `top` 只看到一堆 `qemu-system-x86_64`，
分不出是哪一台 VM。最有效的做法是？
(A) 逐台 `virsh shutdown` 試
(B) 用 `pgrep -a -f 'guest='` 或看 QEMU 命令列裡的 `-name guest=<名稱>`，
把 PID 對到 VM 名稱，再用 `virsh domstats` 看那台的 vCPU 與 I/O
(C) 重啟 `virtqemud`
(D) 直接重開主機

Q61. 你在伺服器上打 `virsh list --all`，輸出是空的，但 `virt-manager` 裡明明有三台 VM。
第一個要下的指令與最可能的原因是？
(A) `systemctl restart virtqemud`，守護行程掛了
(B) `virsh uri` —— 你很可能連到 `qemu:///session`，而 VM 定義在 `qemu:///system`，
兩者是完全獨立、互相看不見的兩個世界
(C) `virsh list --inactive`，因為它們都關機了
(D) 重新安裝 libvirt

Q62. 你已經跑過 `sudo usermod -aG libvirt $USER`，但 `virsh` 仍回
`Failed to connect socket ... Permission denied`。最正確的診斷與處置是？
(A) 用 `sudo virsh` 就好
(B) 比對 `id -nG $USER`（檔案裡寫的）與 `id -nG`（目前 shell 持有的）；
不一致就是群組憑證在登入那一刻才載入，**登出重新登入**即可，`newgrp` 只影響單一子 shell
(C) `chmod 777 /run/libvirt/virtqemud-sock`
(D) 重新跑一次 `usermod`

Q63. 伺服器上為什麼一定要用 `qemu:///system` 而不是 `qemu:///session`？
(A) session 模式比較慢
(B) session 模式不支援 qcow2
(C) session 模式**不能開機自動啟動**（使用者沒登入就沒有 daemon），
也**不能用 `virbr0` 這類需要 root 建 bridge／TAP 的網路** —— 正式服務這兩點都不能少
(D) session 模式無法安裝 Windows 客體

Q64. 你在 VMware Workstation 的 Ubuntu VM 裡想裝 KVM，`kvm-ok` 回
`INFO: Your CPU does not support KVM extensions`。正確處置是？
(A) 換一顆 CPU
(B) 在 Ubuntu 裡 `modprobe kvm_intel`
(C) **關掉那台 Workstation VM**，在 Settings → Processors 勾選
`Virtualize Intel VT-x/EPT or AMD-V/RVI`，再開機重測；這個選項不能在 VM 執行中修改
(D) 在 Ubuntu 的 BIOS 裡開啟虛擬化

Q65. VM 啟動失敗，log 顯示 `Could not open '/srv/vmstore/web01.qcow2': Permission denied`，
但 `ls -l` 看起來擁有者與權限都正常。下列處置何者最正確？
(A) `sudo aa-complain /usr/sbin/libvirtd`，關掉 AppArmor 就好
(B) `chmod 777 /srv/vmstore`
(C) 這是 AppArmor（Ubuntu）／SELinux（RHEL）擋住預設目錄以外的路徑；
把該目錄**定義成 libvirt pool**（`virt-aa-helper` 才會替它加規則），
RHEL 系則用 `semanage fcontext -a -t virt_image_t` ＋ `restorecon`
(D) 把磁碟改成 raw 格式

Q66. 要從工作機遠端管理另一台 KVM 主機，最正確的連線方式是？
(A) 在主機的 `libvirtd.conf` 開 `listen_tcp = 1` 與 `auth_tcp = "none"`，用 16509 埠連
(B) 用 `qemu+ssh://user@host/system` —— 加密與認證都由 SSH 負責；
搭配 `ssh-copy-id` 免密碼，遠端建 VM 時 ISO 必須放在**遠端**的儲存池裡
(C) 開 VNC 到 0.0.0.0 讓大家都連得到
(D) 用 X11 forwarding 長期執行遠端的 `virt-manager`

Q67. 下列 Ubuntu 與 Rocky/AlmaLinux 的套件對照，何者正確？
(A) Ubuntu 的 `qemu-system-x86` ↔ RHEL 的 `qemu-kvm`；`libvirt-daemon-system` ↔ `libvirt`；
`libvirt-clients` ↔ `libvirt-client`；`virtinst` ↔ `virt-install`；`qemu-utils` ↔ `qemu-img`

> ★★★★★ 這條規則涵蓋整個 libguestfs 工具鏈與 `qemu-img`：
> 對執行中的磁碟做任何操作，得到的都是「某個瞬間的不一致快照」。
> `virsh suspend` 只是暫停 vCPU，**磁碟快取還沒 flush**，所以也不等價於關機。
> (A) 錯：這是保護機制不是 bug。(C) 錯：suspend 不保證磁碟一致。
> (D) 錯：`cp` 一樣會拿到不一致的檔案，而且可能撞上寫入鎖。
> → 詳見 [[050-01-04-05-guide-KVM-自動化與範本]] 的〈virt-clone：完整複製〉
>
> **Q99. (B)**
> ★★★★★ libvirt 用 UUID 認 domain，名字只是標籤。範本化 XML 時要刪掉三樣東西：
> `<uuid>`（否則撞名）、`<mac address=>`（否則兩台 MAC 相同，網路會亂）、
> 以及指向舊磁碟的 `<source file=>`（要改成新路徑）。刪掉之後 libvirt 會自動產生新的。
> (A) 錯：訊息明講是 uuid 衝突。(C) 錯：不該為了建新 VM 而刪掉舊的。
> (D) 錯：`create` 會建出暫態 domain，更糟。
> → 詳見 [[050-01-04-05-guide-KVM-自動化與範本]] 的〈XML 範本化與 virsh define〉
>
> **Q100. (C)**
> ★★★★★ 量產腳本的兩大安全面向：**冪等**（中斷後重跑只補缺的，不會重來或覆蓋）
> 與**破壞範圍限制**（前綴保護 ＋ 明確確認）。
> ★★★★★ 前綴保護的紅線：**絕對不要把前綴改成空字串或 `*`**，
> 那會把主機上所有 VM 一起刪掉。
> 機密處理同樣重要：seed ISO 不是加密的，任何讀得到它的人都拿得到內容 ——
> 只放**公鑰**與**密碼 hash**（`mkpasswd -m sha-512`），seed 目錄設 `0700`。
> (A) 錯：這會刪掉主機上所有 VM 與磁碟，是災難級的寫法。
> (B) 錯：無條件 `destroy` 等於對每台 VM 拔插頭。
> (D) 錯：密碼會留在 shell history 與 `ps` 輸出裡，應改用 `--root-password file:/root/.rootpw`（`0600`）。
> → 詳見 [[050-01-04-05-guide-KVM-自動化與範本]] 的〈安全性注意事項〉
