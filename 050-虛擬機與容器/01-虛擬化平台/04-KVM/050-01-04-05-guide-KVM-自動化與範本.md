# KVM 自動化與範本

> [!abstract] 這篇你會學到
> - `virt-install` 的**完整參數表**，以及三種安裝模式：ISO 互動安裝、`--location` 網路安裝、
>   ★★★★ **`--import` 直接匯入 cloud image**
> - ★★★★★ **cloud image ＋ cloud-init 量產**：用 `cloud-localds` 做出 seed ISO，
>   開機就自動設好**主機名稱、固定 IP、SSH 金鑰、套件**
> - `user-data`／`meta-data`／`network-config` 三個檔案各管什麼，寫錯會怎樣
> - ★★★★ **範本 VM 的正確做法**：`virt-sysprep` 一鍵清乾淨，以及它到底清了什麼
> - ★★★★★ **手動清範本的四件事**：`machine-id`、`ssh_host_*`、cloud-init 狀態、netplan 還原
> - `virt-customize` 離線改映像：改主機名稱、塞 SSH 公鑰、預裝套件
> - `virt-clone` 完整複製 vs ★★★★ **backing file 連結複製**，差在哪、什麼時候用哪個
> - ★★★★★ **一支腳本一次開出三台**已設好主機名稱與固定 IP 的 Ubuntu VM（含拆除腳本）
> - XML 範本化：`virsh dumpxml` → 換名字／UUID／MAC → `virsh define`
> - ★★★★ 跟 [[050-01-03-13-guide-PVE-建立練習環境]] 的 PVE 做法**逐項對照**

> [!warning] 未實機驗證
> 本篇**以 Ubuntu Server 24.04 LTS（noble）＋ libvirt 10.x ＋ virt-install 4.x ＋
> cloud-init 24.x 為例**。
>
> ★★★★★ **cloud image 的檔名會隨版本改變**，本篇用的
> `noble-server-cloudimg-amd64.img` 請動手前到 Ubuntu 官方 cloud images 站台
> （`https://cloud-images.ubuntu.com/noble/current/`）確認當前檔名與校驗碼。
>
> ★★★★★ **`virt-install` 與 `virt-customize` 的參數在不同版本有增減**，
> 尤其 `--cloud-init` 系列選項在較舊的 virt-install（3.0 以前）不存在。
> 跑之前先 `virt-install --version` 與 `man virt-install` 確認。
>
> ★★★★★ 文中的 **IP、網段、主機名稱、SSH 公鑰、VM 名稱都是示意值**，請換成你環境的值。
> 本篇的腳本會**建立與刪除 VM**，一律使用 `lab-` 前綴的名稱，
> ★★★★★ **不要在有正式服務的主機上直接跑**，也不要把前綴改成跟正式 VM 撞名。

> [!note] 本章在手冊裡的定位
> 本手冊的虛擬化**主線是 VMware Workstation（單機桌面）與 Proxmox VE（機房叢集）**。
> KVM／libvirt 章是**輔助線**，供**單機 Linux 虛擬化**與**理解 PVE 底層**之用。

> 只是 PVE 用 `qm set --cicustom` 把它包成選單，KVM 這邊要自己做 seed ISO ——
> ★★★★ **看懂這一篇，PVE 的 cloud-init 出問題時你才知道要去哪裡看。**

## 觀念說明

### 三種「開一台 VM」的方式 ★★★★

```
① 手動安裝（最慢，但最直覺）
   下載 ISO → virt-install --cdrom → 在畫面上點下一步 → 20~40 分鐘
   適合：第一次、要客製分割區、要看安裝程式在做什麼

② 自動安裝（Autoinstall / Kickstart）
   ISO + 一份 answer file → virt-install --location + --extra-args → 全自動
   適合：要從乾淨 ISO 裝、需要客製分割區與加密

③ ★★★★★ cloud image + cloud-init（最快，本篇主軸）
   下載官方 cloud image（已經裝好的系統）
        ↓ 複製一份、放大
   qemu-img create -b / qemu-img resize
        ↓ 準備 seed ISO（主機名稱、IP、SSH 金鑰、套件）
   cloud-localds seed.iso user-data meta-data --network-config net.yaml
        ↓ 直接匯入，不跑安裝程式
   virt-install --import
        ↓ 30 秒~2 分鐘
   一台已經可以 SSH 進去的機器
```

| 方式 | 一台要多久 | 可重複性 | 適合場合 | 重要度 |
| --- | --- | --- | --- | --- |
| ① 手動 ISO | 20～40 分 | ★ 差 | 第一次、特殊需求 | ★★ |
| ② Autoinstall | 10～20 分 | ★★★★ 好 | 要客製分割區／LUKS 加密／裸機同一套流程 | ★★★ |
| ③ ★★★★★ cloud image | **30 秒～2 分** | ★★★★★ 極好 | **實驗環境、量產、CI** | ★★★★★ |

★★★★ 本篇主力寫 ③，因為維運上 90% 的需求都是「我要三台一模一樣的 Ubuntu 來測東西」。

### cloud-init 是什麼、它什麼時候動作 ★★★★

**cloud image 是「已經裝好但還沒設定過」的系統映像**，裡面預裝了 cloud-init。
第一次開機時 cloud-init 會去找「資料來源（datasource）」，把裡面的設定套上去。

```
VM 第一次開機
    ↓
cloud-init 掃描 datasource
    ↓  在 KVM 上最實用的是 NoCloud：
    ↓  掛在 VM 上的一片 CD-ROM，label 是 "cidata"
    ↓
讀到三個檔案：
    ┌─────────────────┬──────────────────────────────────────────┐
    │ user-data       │ ★★★★★ 使用者、SSH 金鑰、套件、runcmd     │
    │ meta-data       │ ★★★★ instance-id 與 local-hostname       │
    │ network-config  │ ★★★★ 網路（IP／閘道／DNS）               │
    └─────────────────┴──────────────────────────────────────────┘
    ↓
依序執行：local → network → config → final 四個階段
    ↓
寫下 /var/lib/cloud/instances/<instance-id>/
    ↓
第二次開機：instance-id 沒變 → ★★★★ 只跑 per-boot 的部分，不重跑 per-instance
```

★★★★★ **`instance-id` 是 cloud-init 判斷「這是不是同一台機器」的依據。**
你改了 `user-data` 卻沒改 `instance-id`，重開機**不會重跑**。
要重跑必須：改 `instance-id`，或在 VM 內 `sudo cloud-init clean --logs && sudo reboot`。

### seed ISO 是怎麼回事 ★★★★

`cloud-localds` 做的事很單純：**把 `user-data`、`meta-data`、`network-config`
包成一片 label 為 `cidata` 的 ISO 9660 光碟映像**。

```bash
cloud-localds -v --network-config=net.yaml seed.iso user-data.yaml meta-data.yaml
```

```text
wrote seed.iso with filesystem=iso9660 and diskformat=raw
```

```bash
isoinfo -i seed.iso -l 2>/dev/null | tail -6
```

```text
-r-xr-xr-x   1    0    0             84 Sep  2 2026 [     28 00]  meta-data;1
-r-xr-xr-x   1    0    0            213 Sep  2 2026 [     29 00]  network-config;1
-r-xr-xr-x   1    0    0            487 Sep  2 2026 [     30 00]  user-data;1
```

★★★ 把這片 ISO 當成 CD-ROM 掛給 VM，cloud-init 就找得到。
`cloud-localds` 來自 `cloud-image-utils` 套件。

### 「範本」到底要清掉什麼 ★★★★★

把一台裝好的 VM 拿來當範本複製，**不清乾淨會出這些事**：

| 沒清的東西 | 後果 | 重要度 |
| --- | --- | --- |
| `/etc/machine-id` | ★★★★★ **所有複製出來的機器 machine-id 相同** → systemd-journald 混亂、DHCP 全部拿到同一個 IP（現代 DHCP client 用它當 DUID）、監控系統把它們當成同一台 | ★★★★★ |
| `/etc/ssh/ssh_host_*` | ★★★★★ **所有機器的 SSH host key 一樣** → 中間人攻擊防護形同虛設，`known_hosts` 也會亂 | ★★★★★ |
| `/var/lib/cloud/` | ★★★★ cloud-init 認為「已經設定過了」，新的 user-data 不生效 | ★★★★ |
| `/etc/netplan/50-cloud-init.yaml` | ★★★ 帶著舊 IP，開機就跟原機衝突 | ★★★★ |
| `/etc/hostname`、`/etc/hosts` | ★★★ 名字都一樣 | ★★★ |
| `~/.bash_history`、`/var/log/*` | ★★★ 洩漏原機的操作紀錄與 IP | ★★★ |
| `/etc/udev/rules.d/70-persistent-net.rules` | ★★ 舊系統會把網卡改名成 `eth1` | ★★ |
| SSH 授權金鑰、`/root/.ssh` | ★★★★ 把原機的存取權一起複製出去 | ★★★★ |

★★★★★ **不要自己一條一條記，用 `virt-sysprep`** —— 它把上面這些（還有更多）都包好了。

## 安裝或基礎操作

### 準備工具

```bash
sudo apt update
sudo apt install -y virtinst cloud-image-utils libguestfs-tools genisoimage
```

| 套件 | 提供 | 重要度 |
| --- | --- | --- |
| `virtinst` | ★★★★ `virt-install`、`virt-clone`、`virt-xml` | ★★★★★ |
| `cloud-image-utils` | ★★★★★ `cloud-localds` | ★★★★★ |
| `libguestfs-tools` | ★★★★ `virt-sysprep`、`virt-customize`、`virt-cat`、`guestfish` | ★★★★ |
| `genisoimage` | `cloud-localds` 的後端（也可能是 `xorriso`） | ★★★ |

驗證：

```bash
virt-install --version && cloud-localds --help 2>&1 | head -2 && virt-sysprep --version
```

```text
4.1.0
Usage: cloud-localds [ options ] output user-data [meta-data]
virt-sysprep 1.52.0
```

> [!warning] ★★★ `libguestfs` 第一次跑可能很久或直接失敗
> 它需要一個 appliance（一個小型 kernel + initrd）。首次執行會建它或下載它。
> 失敗時先跑診斷：
>
> ```bash
> libguestfs-test-tool 2>&1 | tail -20
> ```
>
> 最常見的原因是**沒有 `/dev/kvm` 存取權**（把使用者加進 `kvm` 群組）
> 或**核心映像檔沒有讀取權限**（Debian 系有時要 `sudo chmod 0644 /boot/vmlinuz-*`）。

### virt-install 完整參數 ★★★★

```bash
sudo virt-install \
  --name lab-web01 \
  --memory 4096 \
  --vcpus 2 \
  --cpu host-passthrough \
  --os-variant ubuntu24.04 \
  --disk path=/srv/vmstore/lab-web01.qcow2,format=qcow2,bus=virtio,cache=none,discard=unmap \
  --disk path=/srv/vmstore/seed/lab-web01-seed.iso,device=cdrom \
  --network bridge=br0,model=virtio \
  --graphics none \
  --console pty,target_type=serial \
  --import \
  --noautoconsole
```

| 參數 | 意義 | 重要度 |
| --- | --- | --- |
| `--name` | VM 名稱（libvirt 內唯一） | ★★★★ |
| `--memory` | 記憶體 MB；也可寫 `--memory 4096,maxmemory=8192` 支援熱增加 | ★★★★ |
| `--vcpus` | vCPU 數；`--vcpus 2,maxvcpus=8` 支援熱增加 | ★★★★ |
| `--cpu host-passthrough` | ★★★★ 把主機 CPU 特性直接給 VM，效能最好；**代價是不能遷移到 CPU 不同的主機** | ★★★★ |
| `--cpu host-model` | ★★★ 折衷，可遷移到同世代主機 | ★★★ |
| `--os-variant` | ★★★★ 決定預設的裝置型號與最佳化。**寫錯會拿到很爛的預設值** | ★★★★ |
| `--disk path=...` | 磁碟。也可寫 `--disk vol=vmstore/lab-web01.qcow2` 用 pool | ★★★★ |
| `--disk size=40` | 沒有現成檔案時，在預設 pool 建一顆 40 GiB | ★★★ |
| `--disk ...,device=cdrom` | ★★★★★ **掛 seed ISO 就是靠這個** | ★★★★★ |
| `--network bridge=br0` | 接主機的 `br0`；也可 `--network network=default` 接 libvirt 網路 | ★★★★★ |
| `--network ...,mac=52:54:00:xx:xx:xx` | ★★★★ 指定 MAC，量產時搭配 DHCP 保留很好用 | ★★★★ |
| `--graphics none` | ★★★★ 伺服器不要 VNC；配 `--console` 走序列埠 | ★★★★ |
| `--graphics vnc,listen=127.0.0.1` | 要圖形安裝時用；★★★★ **一定要 listen 127.0.0.1** | ★★★★ |
| `--console pty,target_type=serial` | ★★★★ 讓 `virsh console` 能用 | ★★★★ |
| `--import` | ★★★★★ **不跑安裝程式，直接從第一顆磁碟開機**（cloud image 就用這個） | ★★★★★ |
| `--cdrom <iso>` | 從 ISO 開機做互動安裝 | ★★★ |
| `--location <iso 或 url>` | ★★★ 網路／自動安裝用，會抽出 kernel+initrd | ★★★ |
| `--extra-args "..."` | ★★★ 傳核心參數（autoinstall 用） | ★★★ |
| `--noautoconsole` | ★★★★ 建完不自動接 console（寫在腳本裡一定要加） | ★★★★★ |
| `--autostart` | 主機開機時自動啟動這台 VM | ★★★ |
| `--boot uefi` | 用 UEFI（OVMF）而非 BIOS | ★★★ |
| `--print-xml` | ★★★★ **只印 XML 不真的建立**，很適合先看看再決定 | ★★★★ |
| `--dry-run` | 走一遍流程但不落地 | ★★★ |

★★★★ `--os-variant` 查法：

```bash
osinfo-query os | grep -i 'ubuntu24\|ubuntu22'
```

```text
 ubuntu22.04 | Ubuntu 22.04 | 22.04 | http://ubuntu.com/ubuntu/22.04
 ubuntu24.04 | Ubuntu 24.04 | 24.04 | http://ubuntu.com/ubuntu/24.04
```

> [!warning] ★★★★ 找不到 `ubuntu24.04` 怎麼辦
> 你的 `osinfo-db` 太舊。三個選項：
> 1. `sudo apt install --only-upgrade osinfo-db`（或 `osinfo-db-tools` ＋ 手動匯入新的 db）
> 2. 退而求其次用 `--os-variant ubuntu22.04`（裝置型號幾乎一樣）
> 3. ★★★ 用 `--osinfo detect=on,require=off` 讓它自己猜、猜不到也不擋
>
> ★★★ 不指定 `--os-variant` 會看到警告：
> `WARNING  No operating system detected, VM performance may suffer.`

### 三種安裝模式的指令長相 ★★★

**模式 ① ISO 互動安裝**

```bash
sudo virt-install \
  --name lab-manual \
  --memory 2048 --vcpus 2 --os-variant ubuntu24.04 \
  --disk size=20,format=qcow2,bus=virtio \
  --cdrom /srv/vmstore/iso/ubuntu-24.04-live-server-amd64.iso \
  --network bridge=br0,model=virtio \
  --graphics vnc,listen=127.0.0.1 \
  --noautoconsole
```

```text
Starting install...
Allocating 'lab-manual.qcow2'                            | 20 GB  00:00:00
Domain is still running. Installation may be in progress.
You can reconnect to the console to complete the installation process.
```

接畫面（SSH 隧道後用 `virt-viewer`）：

```bash
virt-viewer --connect qemu:///system lab-manual
```

**模式 ② 網路／自動安裝（`--location`）**

```bash
sudo virt-install \
  --name lab-auto \
  --memory 2048 --vcpus 2 --os-variant ubuntu24.04 \
  --disk size=20,format=qcow2,bus=virtio \
  --location /srv/vmstore/iso/ubuntu-24.04-live-server-amd64.iso,kernel=casper/vmlinuz,initrd=casper/initrd \
  --network bridge=br0,model=virtio \
  --graphics none \
  --console pty,target_type=serial \
  --extra-args 'console=ttyS0 autoinstall ds=nocloud-net;s=http://192.168.10.20:8000/' \
  --noautoconsole
```

★★★★ 這條的關鍵是 `--extra-args`：
- `console=ttyS0` → 把安裝過程輸出到序列埠，`virsh console` 看得到
- `autoinstall` → 告訴 Ubuntu 安裝程式跑自動安裝
- `ds=nocloud-net;s=http://...` → 去哪裡抓 `user-data`

★★★ 網址結尾的斜線不能少，安裝程式會去抓 `<url>user-data` 與 `<url>meta-data`。

> [!warning] ★★★★ Ubuntu live server ISO 的 `--location` 路徑會隨版本變
> `kernel=casper/vmlinuz,initrd=casper/initrd` 是 Ubuntu live server 的擺法，
> Debian 的 netinst 則不用指定（virt-install 認得）。
> 版本一改路徑就可能不同，**先掛起來 `ls` 確認**：
>
> ```bash
> sudo mount -o loop /srv/vmstore/iso/ubuntu-24.04-live-server-amd64.iso /mnt
> ls /mnt/casper/ | head
> sudo umount /mnt
> ```

**模式 ③ cloud image ＋ `--import`（★★★★★ 本篇主力）**

見下一節的完整流程。

### cloud image 的取得與準備 ★★★★

```bash
sudo mkdir -p /srv/vmstore/base /srv/vmstore/seed
cd /srv/vmstore/base
sudo curl -fLO https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
sudo curl -fLO https://cloud-images.ubuntu.com/noble/current/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing 2>/dev/null | grep noble-server-cloudimg-amd64.img
```

```text
noble-server-cloudimg-amd64.img: OK
```

★★★★★ **校驗碼一定要對。** 一個被動過手腳的 base 映像會污染你之後開出來的每一台機器。

```bash
qemu-img info noble-server-cloudimg-amd64.img
```

```text
image: noble-server-cloudimg-amd64.img
file format: qcow2
virtual size: 3.5 GiB (3758096384 bytes)
disk size: 588 MiB
cluster_size: 65536
Format specific information:
    compat: 0.10
    compression type: zlib
    refcount bits: 16
```

★★★ 注意 `compat: 0.10`（qcow2 v2）。要拿它當 backing file 用得順一點，
★★★★ **先轉成 v3 並設成唯讀**：

```bash
sudo qemu-img convert -p -O qcow2 -o compat=1.1 \
  noble-server-cloudimg-amd64.img ubuntu-24.04-base.qcow2
sudo chmod 0444 ubuntu-24.04-base.qcow2
ls -l ubuntu-24.04-base.qcow2
```

```text
-r--r--r-- 1 root root 649068544 Sep  2 13:07 ubuntu-24.04-base.qcow2
```

> [!danger] ★★★★★ base 映像設成唯讀不是潔癖，是保命
> 之後每一台 VM 的磁碟都會**用 backing file 指向這個檔案**。
> 只要有人（或某個腳本）改到它，**所有子磁碟同時損毀**，而且救不回來。
> `chmod 0444` ＋ 放在獨立目錄 ＋ 定期備份，三件事都要做。

### cloud-init 三個檔案怎麼寫 ★★★★★

**`user-data`（★★★★★ 最重要，第一行必須是 `#cloud-config`）**

```yaml
#cloud-config
hostname: lab-web01
fqdn: lab-web01.lab.local
manage_etc_hosts: true

users:
  - name: ops
    groups: [sudo, adm]
    shell: /bin/bash
    sudo: "ALL=(ALL) NOPASSWD:ALL"
    lock_passwd: true
    ssh_authorized_keys:
      - ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIExamplePublicKeyReplaceMe ops@admin

ssh_pwauth: false
disable_root: true

package_update: true
package_upgrade: false
packages:
  - qemu-guest-agent
  - vim
  - curl
  - chrony

timezone: Asia/Taipei

write_files:
  - path: /etc/motd
    content: |
      ==== 實驗環境 lab-web01，資料隨時可能被清掉 ====

runcmd:
  - [ systemctl, enable, --now, qemu-guest-agent ]
  - [ systemctl, enable, --now, chrony ]

final_message: "cloud-init 完成，開機共花 $UPTIME 秒"
```

★★★★ 逐項重點：

| 欄位 | 說明 | 重要度 |
| --- | --- | --- |
| `#cloud-config` | ★★★★★ **第一行，不能有空白行在前面**，寫錯整份被忽略 | ★★★★★ |
| `hostname` / `fqdn` | 設主機名稱 | ★★★★ |
| `manage_etc_hosts: true` | ★★★★ 讓 cloud-init 維護 `/etc/hosts`，避免 `sudo` 卡住解析 | ★★★★ |
| `ssh_authorized_keys` | ★★★★★ **貼公鑰（`.pub`），絕對不要貼私鑰** | ★★★★★ |
| `lock_passwd: true` | ★★★★ 這個帳號不能用密碼登入，只能用金鑰 | ★★★★ |
| `sudo: "ALL=(ALL) NOPASSWD:ALL"` | ★★★ 實驗環境方便；**正式環境請要求密碼** | ★★★★ |
| `ssh_pwauth: false` | ★★★★ 關掉 SSH 密碼認證 | ★★★★ |
| `packages` | 第一次開機自動裝；★★★ **需要對外網路** | ★★★★ |
| `qemu-guest-agent` | ★★★★ 裝了 `virsh domifaddr`／`virsh shutdown` 才好用 | ★★★★ |
| `runcmd` | ★★★ 在 final 階段執行，**用陣列形式比較安全**（不經 shell 解析） | ★★★ |

**`meta-data`（★★★★ 兩行就夠）**

```yaml
instance-id: lab-web01-20260902
local-hostname: lab-web01
```

★★★★★ `instance-id` **每次要重跑 cloud-init 就要換一個新的**。
習慣做法是加日期或流水號。

**`network-config`（★★★★ v2 格式，跟 Netplan 幾乎一樣）**

```yaml
version: 2
ethernets:
  enp1s0:
    dhcp4: false
    dhcp6: false
    addresses:
      - 192.168.10.51/24
    routes:
      - to: default
        via: 192.168.10.254
    nameservers:
      addresses: [192.168.10.1, 1.1.1.1]
      search: [lab.local]
```

★★★★★ **網卡名稱是最大的坑。** cloud image 開出來的第一張 virtio 網卡在
Ubuntu 24.04 上通常是 `enp1s0`，但**會隨 machine type 與 PCI 位置改變**。
★★★★ 更保險的寫法是**用 MAC 比對**，不寫死名稱：

```yaml
version: 2
ethernets:
  primary:
    match:
      macaddress: "52:54:00:1a:3b:51"
    set-name: eth0
    dhcp4: false
    addresses: [192.168.10.51/24]
    routes:
      - to: default
        via: 192.168.10.254
    nameservers:
      addresses: [192.168.10.1]
```

搭配 `virt-install --network bridge=br0,model=virtio,mac=52:54:00:1a:3b:51` 指定同一個 MAC。

> [!tip] ★★★ 用 DHCP 就不用煩惱網卡名稱
> 實驗環境如果網段上有 DHCP，`network-config` 直接省略（或全部 `dhcp4: true`），
> 再用 [[050-01-04-04-guide-KVM-儲存池與網路]] 教的
> `virsh net-update ... add ip-dhcp-host` 做 MAC 綁 IP，效果一樣而且更不容易錯。

### virt-customize：離線改映像 ★★★★

不用開機就能改一個 qcow2 裡面的內容 —— 適合「做一個已經預裝好東西的 base」。

```bash
sudo cp /srv/vmstore/base/ubuntu-24.04-base.qcow2 /srv/vmstore/base/ubuntu-24.04-nginx.qcow2
sudo chmod 0644 /srv/vmstore/base/ubuntu-24.04-nginx.qcow2

sudo virt-customize -a /srv/vmstore/base/ubuntu-24.04-nginx.qcow2 \
  --timezone Asia/Taipei \
  --install nginx,qemu-guest-agent,vim,curl \
  --run-command 'systemctl enable nginx qemu-guest-agent' \
  --ssh-inject root:file:/root/.ssh/id_ed25519.pub \
  --write '/etc/motd:=== 預裝 Nginx 的實驗範本 ===' \
  --selinux-relabel
```

### 手動清範本（沒有 libguestfs 時） ★★★★

在 VM 內、關機前執行：

```bash
#!/usr/bin/env bash
# 在「要變成範本的 VM 內」執行，最後會關機
set -euo pipefail
[[ $EUID -eq 0 ]] || { echo "請用 root 執行"; exit 1; }

echo "== 1. cloud-init 狀態歸零 ★★★★★"
if command -v cloud-init >/dev/null; then
  cloud-init clean --logs --seed
  rm -rf /var/lib/cloud/instances/* /var/lib/cloud/instance
fi

echo "== 2. machine-id 清空（★★★★★ 用 truncate，不要 rm）"
truncate -s 0 /etc/machine-id
rm -f /var/lib/dbus/machine-id
ln -s /etc/machine-id /var/lib/dbus/machine-id

echo "== 3. SSH host key 刪除 ★★★★★"
rm -f /etc/ssh/ssh_host_*
# ★★★★ 沒有 cloud-init 的話，補一個開機自動重產的 unit
cat > /etc/systemd/system/regen-ssh-hostkeys.service <<'UNIT'
[Unit]
Description=Regenerate SSH host keys if missing
Before=ssh.service
ConditionPathExists=!/etc/ssh/ssh_host_ed25519_key

[Service]
Type=oneshot
ExecStart=/usr/bin/ssh-keygen -A

[Install]
WantedBy=multi-user.target
UNIT
systemctl enable regen-ssh-hostkeys.service

echo "== 4. 網路設定還原 ★★★★"
rm -f /etc/netplan/50-cloud-init.yaml
rm -f /etc/udev/rules.d/70-persistent-net.rules

echo "== 5. 主機名稱歸零 ★★★"
echo "localhost" > /etc/hostname
sed -i '/^127\.0\.1\.1/d' /etc/hosts

echo "== 6. 使用者痕跡與日誌 ★★★★"
rm -rf /root/.ssh /home/*/.ssh
rm -f /root/.bash_history /home/*/.bash_history
journalctl --rotate --vacuum-time=1s || true
find /var/log -type f \( -name '*.gz' -o -name '*.1' -o -name '*.old' \) -delete
: > /var/log/wtmp; : > /var/log/btmp; : > /var/log/lastlog

echo "== 7. 套件快取 ★★★"
apt-get clean || true
rm -rf /var/lib/apt/lists/*

echo "== 8. 清空未使用空間，讓 qcow2 縮得下來 ★★★"
fstrim -av || dd if=/dev/zero of=/EMPTY bs=1M 2>/dev/null || true
rm -f /EMPTY
sync

echo "完成，關機。"
poweroff
```

★★★★★ 三個最關鍵的地方：

| 步驟 | 為什麼要這樣做 |
| --- | --- |
| `truncate -s 0 /etc/machine-id`（**不是 `rm`**） | ★★★★★ systemd 看到「存在但是空的」才會在開機時產生新的；檔案不存在的話某些版本的初始化會出錯 |
| `/var/lib/dbus/machine-id` 做成 symlink | ★★★★ 兩個檔案必須一致，做成連結最保險 |
| 加 `regen-ssh-hostkeys.service` | ★★★★ Ubuntu 的 `openssh-server` 是在**安裝套件時**產生 host key，開機不會自動補；有 cloud-init 的話 cloud-init 會處理，沒有的話就必須自己補這個 unit |

3. ★★★★ **產生新的 MAC 位址**

★★★★★ **但它不會動 VM 裡面的內容** —— 主機名稱、machine-id、SSH host key
統統還是原來那台的。所以**複製前一定要先 `virt-sysprep`**，複製後再用 cloud-init
或 `virt-customize` 設定新身分。

`--auto-clone` 讓它自動取名與配路徑：

```bash

```

`virt-clone` **不做連結複製**，要自己用 `qemu-img`：

```bash
  -b /srv/vmstore/base/ubuntu-24.04-tpl.qcow2 \
```

### XML 範本化與 virsh define ★★★

有時候你要的是「同一份硬體規格，換不同名字開一堆」：

```bash
# 1. 匯出一台調好的 VM 當範本
virsh dumpxml lab-web01 > /srv/vmstore/tpl/vm-template.xml

# 2. ★★★★ 把「必須唯一」的欄位拿掉，讓 libvirt 自己產生
sed -i -e '/<uuid>/d' \
       -e "/<mac address=/d" \
       /srv/vmstore/tpl/vm-template.xml
```

```bash
# 3. 用 sed 換掉名字與磁碟路徑
NEW=lab-web04
sed -e "s|<name>lab-web01</name>|<name>${NEW}</name>|" \
    -e "s|/srv/vmstore/lab-web01.qcow2|/srv/vmstore/${NEW}.qcow2|" \
    -e "s|/srv/vmstore/seed/lab-web01-seed.iso|/srv/vmstore/seed/${NEW}-seed.iso|" \
    /srv/vmstore/tpl/vm-template.xml > /tmp/${NEW}.xml

sudo virsh define /tmp/${NEW}.xml
```

```text

```

```bash
sudo virsh start lab-web04
```

```text
Domain 'lab-web04' started
```

> [!warning] ★★★★★ 一定要刪掉 `<uuid>` 與 `<mac address=>`
> 沒刪的話 `virsh define` 會報：
>
> ```text

> ```
>
> 就算勉強改掉 UUID，**MAC 重複**會讓兩台 VM 在同一個網段上互相干擾
> （ARP 表打架、DHCP 拿到同一個 IP），症狀是「網路時好時壞」而且極難查。

★★★★ 比 `sed` 更安全的做法是用 `virt-xml`：

```bash
virt-xml lab-web01 --edit --disk path=/srv/vmstore/lab-web01-data.qcow2 --print-xml
sudo virt-xml lab-web01 --add-device --disk path=/srv/vmstore/lab-web01-data.qcow2,bus=virtio
```

```bash

#!/usr/bin/env bash
#
# lab-up.sh — 一次開出三台已設好主機名稱與固定 IP 的 Ubuntu 實驗機
# ★★★★★ 只在實驗主機上執行；所有 VM 名稱一律 lab- 開頭
#
set -euo pipefail

### ─── 可調參數 ────────────────────────────────────────────────
BASE="/srv/vmstore/base/ubuntu-24.04-base.qcow2"   # 唯讀母映像

DNS2="1.1.1.1"

PUBKEY_FILE="${PUBKEY_FILE:-/home/ops/.ssh/id_ed25519.pub}"

# name : ip : mac
MACHINES=(
  "lab-web01:192.168.10.51:52:54:00:1a:3b:51"
  "lab-db01:192.168.10.52:52:54:00:1a:3b:52"

### ────────────────────────────────────────────────────────────

die() { echo "錯誤：$*" >&2; exit 1; }

### 前置檢查 ★★★★

  IP="${rest%%:*}"
  MAC="${rest#*:}"

  echo "  建立 ${NAME}  IP=${IP}  MAC=${MAC}"
  echo "==================================================="

  ### ★★★★ 撞名保護：已存在就跳過，不覆蓋

    echo "  ！ ${NAME} 已存在，跳過。要重建請先跑 lab-down.sh"
    continue
  fi

  ### 1. user-data
  cat > "${SEEDDIR}/${NAME}-user-data.yaml" <<EOF
#cloud-config
hostname: ${NAME}
fqdn: ${NAME}.${SEARCH}
manage_etc_hosts: true
prefer_fqdn_over_hostname: false

users:
  - name: ops
    groups: [sudo, adm]
    shell: /bin/bash
    sudo: "ALL=(ALL) NOPASSWD:ALL"
    lock_passwd: true
    ssh_authorized_keys:
      - ${PUBKEY}

ssh_pwauth: false
disable_root: true
timezone: Asia/Taipei

package_update: true
packages:
  - qemu-guest-agent
  - chrony
  - curl
  - vim

runcmd:
  - [ systemctl, enable, --now, qemu-guest-agent ]
  - [ systemctl, enable, --now, chrony ]

final_message: "cloud-init 完成：\$hostname 開機共 \$UPTIME 秒"
EOF

  ### 2. meta-data ★★★★★ instance-id 每次重建都要換
  cat > "${SEEDDIR}/${NAME}-meta-data.yaml" <<EOF
instance-id: ${NAME}-${STAMP}
local-hostname: ${NAME}
EOF

  ### 3. network-config ★★★★ 用 MAC 比對，不寫死網卡名稱
  cat > "${SEEDDIR}/${NAME}-net.yaml" <<EOF
version: 2
ethernets:
  primary:
    match:
      macaddress: "${MAC}"
    set-name: eth0
    dhcp4: false
    dhcp6: false
    addresses: [${IP}/${NETMASK}]
    routes:
      - to: default
        via: ${GATEWAY}
    nameservers:
      addresses: [${DNS1}, ${DNS2}]
      search: [${SEARCH}]
EOF

  ### 4. seed ISO
  cloud-localds \
    --network-config="${SEEDDIR}/${NAME}-net.yaml" \
    "${SEEDDIR}/${NAME}-seed.iso" \
    "${SEEDDIR}/${NAME}-user-data.yaml" \
    "${SEEDDIR}/${NAME}-meta-data.yaml"

  ### 5. 磁碟：★★★★★ 連結複製，秒建
  qemu-img create -f qcow2 -F qcow2 -b "$BASE" \
    "${DISKDIR}/${NAME}.qcow2" "$DISK_SIZE" >/dev/null

  ### 6. 建立並啟動 VM
  virt-install \
    --name "$NAME" \
    --memory "$MEM_MB" \
    --vcpus "$VCPUS" \
    --cpu host-passthrough \
    --os-variant "$OSVARIANT" \
    --disk "path=${DISKDIR}/${NAME}.qcow2,format=qcow2,bus=virtio,cache=none,discard=unmap" \
    --disk "path=${SEEDDIR}/${NAME}-seed.iso,device=cdrom" \
    --network "bridge=${BRIDGE},model=virtio,mac=${MAC}" \
    --graphics none \
    --console pty,target_type=serial \
    --import \
    --noautoconsole

  virsh autostart "$NAME" >/dev/null
  echo "  ✔ ${NAME} 已建立並啟動"
done

    if ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new \
           -o ConnectTimeout=3 "ops@${IP}" 'cloud-init status' 2>/dev/null \
           | grep -q 'status: done'; then
      echo "  ✔ ${NAME} (${IP}) 就緒"
      break
    fi
    sleep 3
    [[ $i -eq 60 ]] && echo "  ！ ${NAME} (${IP}) 超時，請用 virsh console ${NAME} 查看"
  done
done

echo
virsh list --all | grep '^ *[0-9-]* *lab-' || true
SCRIPT
```

### ★★★★ 跟 PVE 做法的逐項對照

[[050-01-03-13-guide-PVE-建立練習環境]] 做的是同一件事，比較如下：

| 步驟 | ★★★★ KVM／libvirt（本篇） | ★★★★ Proxmox VE |
| --- | --- | --- |
| 取得 cloud image | `curl -fLO https://cloud-images.ubuntu.com/...` | 一樣，放到 `/var/lib/vz/template/iso/` |
| 建立範本 | `qemu-img convert` ＋ `chmod 0444` 當 backing file | `qm create` ＋ `qm importdisk` ＋ `qm template <vmid>` |
| 設主機名稱／IP | ★★★★★ **自己寫 user-data／network-config ＋ `cloud-localds` 做 seed ISO** | ★★★★ `qm set <vmid> --ciuser --sshkeys --ipconfig0 ip=...,gw=...` |
| cloud-init 的載體 | ★★★ 你自己掛的 CD-ROM（label `cidata`） | ★★★ PVE 自動產生的 `cloudinit` 磁碟（同樣是 NoCloud） |
| 連結複製 | `qemu-img create -f qcow2 -F qcow2 -b base.qcow2 child.qcow2` | ★★★★ `qm clone <tpl> <newid> --full 0` |
| 完整複製 | `virt-clone --original ... --name ...` | `qm clone <tpl> <newid> --full 1` |
| 開機 | `virt-install --import` 或 `virsh start` | `qm start <vmid>` |
| 批次量產 | 本篇的 `lab-up.sh`（bash 迴圈 ＋ `virt-install`） | PVE 章的腳本（bash 迴圈 ＋ `qm clone` ＋ `qm set`） |
| 拆除 | `virsh undefine --remove-all-storage` | `qm destroy <vmid> --purge` |
| 網路 | 主機的 `br0` | 主機的 `vmbr0` |
| 快照 | `virsh snapshot-create-as`（需 qcow2） | `qm snapshot <vmid> <name>` |

★★★★★ **底層完全一樣** —— PVE 的 `qm` 只是把 QEMU 參數與 cloud-init 檔案的產生
包成一組指令與 Web 介面。你在本篇手做過一次，PVE 的 cloud-init 出問題時
（例如 VM 開機沒拿到 IP），你就知道要去 VM 裡看 `/var/log/cloud-init.log`、
確認 datasource 是不是 NoCloud、`instance-id` 有沒有變。

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| VM 開機了但**主機名稱還是 `ubuntu`、IP 也沒設** | ★★★★★ cloud-init 沒讀到 seed ISO（沒掛 CD-ROM、ISO label 不是 `cidata`） | `virsh domblklist <vm>` 確認 cdrom 有掛；用 `isoinfo -d -i seed.iso \| grep -i volume` 確認 label 是 `cidata`；用 `genisoimage` 自製時 `-volid cidata` 不能少 |
| 改了 `user-data` 重開機，設定沒生效 | ★★★★★ `instance-id` 沒變，cloud-init 認為「這台已經設定過了」 | 換一個新的 `instance-id` 重做 seed ISO；或在 VM 內 `sudo cloud-init clean --logs && sudo reboot` |
| `user-data` 整份被忽略 | ★★★★★ 第一行不是 `#cloud-config`，或前面有空白行／BOM | `head -1 user-data.yaml \| cat -A` 檢查；`sudo cloud-init schema --system` 驗語法 |
| `cloud-init status` 顯示 `error` | user-data YAML 縮排錯、或 `runcmd` 寫法錯 | `sudo cloud-init schema --system`；`sudo tail -80 /var/log/cloud-init-output.log` 看實際錯在哪一段 |
| VM 拿到 IP 了但**網卡名稱對不上**，`network-config` 沒作用 | ★★★★★ `network-config` 寫死 `enp1s0`，實際開出來是 `ens3`／`enp0s2` | 改用 `match: macaddress:` ＋ `set-name:`，並在 `virt-install` 指定同一個 `mac=` |
| `virt-install` 報 `ERROR Guest name 'lab-web01' is already in use` | 同名 VM 已定義 | `virsh undefine lab-web01 --remove-all-storage`，或換名字 |
| `virt-install` 報 `WARNING No operating system detected` | 沒給 `--os-variant` | 加 `--os-variant ubuntu24.04`；找不到該值時用 `--osinfo detect=on,require=off` |
| `virt-install --import` 之後 VM 一直卡在 `Booting from Hard Disk...` | ★★★★ 磁碟不是可開機的 cloud image（例如你建了一顆空的 qcow2），或 backing file 路徑錯 | `qemu-img info --backing-chain <disk>` 確認鏈完整；`virsh console <vm>` 看它停在哪 |
| `Could not open backing file: Could not open '...': No such file or directory` | ★★★★★ base 映像被移動、改名或刪掉 | 把它放回**原本的絕對路徑**；或用 `qemu-img rebase -u -F qcow2 -b <新路徑> child.qcow2` 改指向 |
| `qemu-img create -b` 報 `Backing file specified without backing format` | ★★★★ 新版 qemu 要求明示 backing 格式 | 加 `-F qcow2` |
| `virt-clone` 報 `ERROR Domain with devices to clone must be paused or shutoff` | ★★★★★ 來源 VM 還在跑 | `virsh shutdown <vm>` 等到 `shut off` 再複製 |
| 複製出來的三台 VM **拿到同一個 IP** | ★★★★★ 沒清 `machine-id`，現代 DHCP client 拿它當 DUID | 範本先 `virt-sysprep`；已經開出來的在每台跑 `sudo truncate -s 0 /etc/machine-id && sudo rm -f /var/lib/dbus/machine-id && sudo reboot` |
| SSH 進去看到 `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | ★★★★ VM 重建，host key 換了（**這是正確行為**） | `ssh-keygen -R <ip>`。★★★★★ 如果**不同的機器 host key 相同**，那才是嚴重問題，代表範本沒清乾淨 |
| `virt-customize --install nginx` 卡住或報網路錯誤 | ★★★★ libguestfs appliance 沒有對外網路，或 DNS 不通 | 確認主機能上網；必要時 `export LIBGUESTFS_BACKEND=direct` 再試；離線環境改成先 `--copy-in` deb 檔再 `--run-command 'dpkg -i ...'` |
| `libguestfs` 相關指令一律失敗 | ★★★★ 沒有 `/dev/kvm` 權限，或 kernel 映像不可讀 | `libguestfs-test-tool 2>&1 \| tail -20` 看真正的原因；把使用者加進 `kvm` 群組；Debian 系試 `sudo chmod 0644 /boot/vmlinuz-*` |
| `virsh define` 報 `domain 'x' already exists with uuid ...` | ★★★★★ XML 範本裡的 `<uuid>` 沒刪 | `sed -i '/<uuid>/d' tpl.xml` 後重試；`<mac address=>` 也要一併刪 |
| `virsh undefine` 之後磁碟檔案還在 | ★★★ `undefine` 預設不刪儲存 | 加 `--remove-all-storage`；UEFI 開機的 VM 另外要 `--nvram` |
| 量產腳本跑到一半中斷，再跑一次全部重來 | ★★★ 腳本沒有冪等保護 | 本篇腳本用 `virsh dominfo "$NAME" >/dev/null 2>&1 && continue` 做撞名跳過，重跑只會補缺的 |
| 主機重開後 VM 沒有自動起來 | ★★★★ 忘了 `virsh autostart` | `sudo virsh autostart <vm>`；批次：`for v in $(virsh list --all --name); do virsh autostart "$v"; done` |

## 安全性注意事項

- ★★★★★ **`user-data` 裡放的是公鑰，不是私鑰。**
  `ssh_authorized_keys` 要貼 `~/.ssh/id_ed25519.pub` 的內容。
  貼成私鑰＝把主控權寫進一片人人可讀的 ISO。
- ★★★★★ **seed ISO 不是加密的。** 任何能讀到 `/srv/vmstore/seed/*.iso` 的人
  都拿得到裡面的所有內容。**不要在 `user-data` 裡放密碼、API token、資料庫密碼**。
  真的需要密碼就：

  ```bash
  # 產一個 hash，只把 hash 放進 user-data
  mkpasswd -m sha-512
  ```

  ```yaml
  users:
    - name: ops
      passwd: $6$rounds=4096$Example$HashedValueGoesHere...
      lock_passwd: false
  ```

  ★★★★ 並把 seed 目錄權限收起來：

  ```bash
  sudo chmod 0700 /srv/vmstore/seed
  ```

- ★★★★ **不要用 `--root-password password:xxx`。** 密碼會留在 shell history、
  留在 `ps` 的輸出裡。改用 `--root-password file:/root/.rootpw`（檔案設 `0600`）。
- ★★★★★ **範本一定要 `virt-sysprep`。** 沒清 SSH host key 的範本量產出去，
  等於整個網段的機器共用一把 host key —— 中間人攻擊的偵測機制直接失效。
- ★★★★ **範本不要內建可登入的憑證。** 範本裡如果留著某個帳號的 `~/.ssh/authorized_keys`
  或已知密碼，那把鑰匙就開得了之後所有複製出來的機器。
  `virt-sysprep --operations defaults,ssh-userdir` 會清掉 `~/.ssh`。
- ★★★★ **base 映像要驗校驗碼、設唯讀、定期備份。**
  base 被污染 = 之後所有 VM 都被污染，而且非常難察覺。
- ★★★ **`sudo: "ALL=(ALL) NOPASSWD:ALL"` 只適合實驗環境。**
  正式環境改成 `ALL=(ALL) ALL`（要求密碼），並考慮限定可執行的指令。
- ★★★★ **量產腳本要有前綴保護與確認機制。** 本篇的 `lab-down.sh` 要求
  完整輸入 `DELETE` 才動作，而且只處理 `lab-` 開頭的 VM ——
  ★★★★★ **不要把前綴改成空字串或 `*`**，那會刪掉主機上所有 VM。
- ★★★ **量產出來的機器要納管。** 三台開得很快，但監控、備份、
  修補（見 [[020-02-03-01-svc-標準化-新機建置標準流程]]）也要跟上，
  否則就是三台沒人管的殭屍主機。
- ★★★ **實驗網段要跟正式網段隔離。** 本篇用 `br0` 直接橋接到實體網段，
  正式環境請用 VLAN 切出獨立的實驗網段（見 [[040-01-03-guide-網路設備-VLAN概念與規劃]]）。

## 練習題

> [!question]- 練習 1：用 cloud image 開出第一台 VM
> 下載 Ubuntu 24.04 cloud image，做一份 seed ISO（主機名稱 `lab-t01`、DHCP 取得 IP、
> 塞你自己的 SSH 公鑰），用 `virt-install --import` 開起來，SSH 進去確認主機名稱。
>
> **參考答案**
>
> ```bash
> sudo mkdir -p /srv/vmstore/{base,seed}
> cd /srv/vmstore/base
> sudo curl -fLO https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
>
> cd /srv/vmstore/seed
> sudo tee user-data >/dev/null <<EOF
> #cloud-config
> hostname: lab-t01
> manage_etc_hosts: true
> users:
>   - name: ops
>     groups: [sudo]
>     shell: /bin/bash
>     sudo: "ALL=(ALL) NOPASSWD:ALL"
>     lock_passwd: true
>     ssh_authorized_keys:
>       - $(cat ~/.ssh/id_ed25519.pub)
> ssh_pwauth: false
> EOF
> printf 'instance-id: lab-t01-001\nlocal-hostname: lab-t01\n' | sudo tee meta-data
> sudo cloud-localds lab-t01-seed.iso user-data meta-data
>
> sudo qemu-img create -f qcow2 -F qcow2 \
>   -b /srv/vmstore/base/noble-server-cloudimg-amd64.img \
>   /srv/vmstore/lab-t01.qcow2 20G
>
> sudo virt-install --name lab-t01 --memory 2048 --vcpus 2 \
>   --os-variant ubuntu24.04 \
>   --disk path=/srv/vmstore/lab-t01.qcow2,format=qcow2,bus=virtio \
>   --disk path=/srv/vmstore/seed/lab-t01-seed.iso,device=cdrom \
>   --network bridge=br0,model=virtio \
>   --graphics none --console pty,target_type=serial \
>   --import --noautoconsole
>
> sleep 45
> virsh domifaddr lab-t01 --source agent 2>/dev/null || virsh net-dhcp-leases default
> ```
>
> ★★★★ `--source agent` 需要 VM 裡有 `qemu-guest-agent`；沒有的話從 DHCP 租約查 IP。

> [!question]- 練習 2：故意寫錯 user-data，看 cloud-init 怎麼抱怨
> 把 `user-data` 的第一行 `#cloud-config` 拿掉，重做 seed ISO 開一台，
> 用 `cloud-init status --long` 與日誌找出問題。
>
> **參考答案**
>
> VM 內：
>
> ```bash
> cloud-init status --long
> ```
>
> ```text
> status: done
> extended_status: done
> detail: DataSourceNoCloud [seed=/dev/sr0][dsmode=net]
> ```
>
> ★★★★ **狀態是 `done`，但你的設定完全沒生效** —— 這是最坑的地方。
> 沒有 `#cloud-config` 開頭，cloud-init 不認得那是 cloud-config，
> 就當成一份無法辨識的 user-data 略過（日誌裡會有
> `Unhandled non-multipart (text/x-not-multipart) userdata`）。
>
> ```bash
> sudo grep -i 'unhandled\|not-multipart' /var/log/cloud-init.log
> ```
>
> ★★★★★ **教訓：`cloud-init status` 顯示 done 不代表你的設定跑過了。**
> 要驗證的是「主機名稱／IP／使用者是不是真的變了」。

> [!question]- 練習 3：比較完整複製與連結複製的建立時間與空間
> 對同一個 40 GiB 範本，分別做 `virt-clone` 與 `qemu-img create -b`，
> 用 `time` 量時間、`ls -lh` 看空間。
>
> **參考答案**
>
> ```bash
> sudo virsh shutdown lab-template; sleep 20
>
> time sudo virt-clone --original lab-template --name lab-full --file /srv/vmstore/lab-full.qcow2
> ```
>
> ```text
> Allocating 'lab-full.qcow2'                               |  40 GB  00:00:39
> Clone 'lab-full' created successfully.
>
> real	0m41.882s
> ```
>
> ```bash
> time sudo qemu-img create -f qcow2 -F qcow2 \
>   -b /srv/vmstore/base/ubuntu-24.04-tpl.qcow2 /srv/vmstore/lab-link.qcow2 40G
> ```
>
> ```text
> real	0m0.031s
> ```
>
> ```bash
> ls -lh /srv/vmstore/lab-full.qcow2 /srv/vmstore/lab-link.qcow2
> ```
>
> ```text
> -rw------- 1 root root 2.4G Sep  2 15:02 /srv/vmstore/lab-full.qcow2
> -rw-r--r-- 1 root root 193K Sep  2 15:03 /srv/vmstore/lab-link.qcow2
> ```
>
> ★★★★★ 差距是**41 秒 vs 0.03 秒**、**2.4 GB vs 193 KB**。
> 代價是連結複製的 VM **完全依賴母映像**，母映像不能刪也不能改。

> [!question]- 練習 4：證明沒清範本會出什麼事
> 拿一台 VM 直接 `virt-clone` 兩份（**不做 `virt-sysprep`**），開起來比對
> `machine-id` 與 SSH host key。
>
> **參考答案**
>
> ```bash
> for h in lab-bad1 lab-bad2; do
>   ssh ops@$h 'cat /etc/machine-id; sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub'
> done
> ```
>
> ```text
> b1d4f0e2c7a94f5e8d3b6a17c2905e41
> 256 SHA256:kQ7v...9xTc root@lab-tpl (ED25519)
> b1d4f0e2c7a94f5e8d3b6a17c2905e41
> 256 SHA256:kQ7v...9xTc root@lab-tpl (ED25519)
> ```
>
> ★★★★★ 兩台**完全一樣**。後果：
> - 現代 DHCP client 用 `machine-id` 當 DUID → 兩台會搶同一個 IP
> - SSH host key 相同 → 中間人偵測失效、`known_hosts` 亂掉
> - `journald` 的 `_MACHINE_ID` 相同 → 集中式日誌分不出是哪一台
>
> 修法：範本先 `virt-sysprep`，或已開出來的每台跑
> `sudo truncate -s 0 /etc/machine-id; sudo rm -f /etc/ssh/ssh_host_* /var/lib/dbus/machine-id; sudo ssh-keygen -A; sudo reboot`。

> [!question]- 練習 5：把量產腳本改成五台，並加上第二張隔離網卡
> 修改 `lab-up.sh` 的 `MACHINES` 陣列，開五台（`.51`～`.55`），
> 並讓每台多接一張 `lab-isolated` 網路的網卡。
>
> **參考答案**
>
> ```bash
> MACHINES=(
>   "lab-web01:192.168.10.51:52:54:00:1a:3b:51"
>   "lab-web02:192.168.10.52:52:54:00:1a:3b:52"
>   "lab-db01:192.168.10.53:52:54:00:1a:3b:53"
>   "lab-app01:192.168.10.54:52:54:00:1a:3b:54"
>   "lab-mon01:192.168.10.55:52:54:00:1a:3b:55"
> )
> ```
>
> `virt-install` 那段多加一行：
>
> ```bash
>     --network "bridge=${BRIDGE},model=virtio,mac=${MAC}" \
>     --network "network=lab-isolated,model=virtio" \
> ```
>
> ★★★★ 兩件事要注意：
> 1. `network-config` 只設定了第一張網卡（靠 MAC 比對），第二張會保持未設定；
>    要給它 IP 就在 `network-config` 裡多寫一組（同樣用 MAC 比對，
>    並在 `virt-install` 指定第二張的 MAC）。
> 2. `lab-isolated` 網路要先存在，建法見 [[050-01-04-04-guide-KVM-儲存池與網路]]。

> [!question]- 練習 6：做一個預裝 Nginx 的 base 映像
> 用 `virt-customize` 在 base 映像裡預裝 Nginx，然後用它開一台 VM，
> 確認開機後 Nginx 已經在跑。
>
> **參考答案**
>
> ```bash
> sudo cp /srv/vmstore/base/ubuntu-24.04-base.qcow2 /srv/vmstore/base/ubuntu-nginx.qcow2
> sudo chmod 0644 /srv/vmstore/base/ubuntu-nginx.qcow2
> sudo virt-customize -a /srv/vmstore/base/ubuntu-nginx.qcow2 \
>   --install nginx \
>   --run-command 'systemctl enable nginx' \
>   --timezone Asia/Taipei
> sudo chmod 0444 /srv/vmstore/base/ubuntu-nginx.qcow2
> ```
>
> 用它當 backing file 開機後：
>
> ```bash
> ssh ops@192.168.10.51 'systemctl is-active nginx; curl -sI localhost | head -1'
> ```
>
> ```text
> active
> HTTP/1.1 200 OK
> ```
>
> ★★★★ 注意最後把它改回 `0444` —— 當 backing file 的映像必須唯讀。

## 小測驗

Q1. `user-data` 的第一行必須是什麼？寫錯的話 `cloud-init status` 會顯示什麼？
這為什麼特別危險？

Q2. （是非）改了 `user-data` 之後重做 seed ISO、重開 VM，設定一定會重新套用。

Q3. 這行指令會發生什麼事？少了什麼會出問題？

```bash
qemu-img create -f qcow2 -b /srv/vmstore/base/tpl.qcow2 /srv/vmstore/new.qcow2 40G
```

Q4. （選擇）下列哪一項**不是** `virt-clone` 會幫你做的？
（A）複製磁碟檔案 （B）產生新的 UUID （C）產生新的 MAC （D）清掉 VM 裡的 `machine-id`

Q5. 為什麼清範本時 `/etc/machine-id` 要用 `truncate -s 0` 而不是 `rm`？

Q6. 你把三台 VM 從同一個沒清過的範本複製出來，開機後發現三台搶同一個 IP。
說明原因與修法。

Q7. `virt-install` 的 `--import` 跟 `--cdrom` 差在哪？用 cloud image 時該用哪一個？

Q8. （是非）seed ISO 是加密的，所以在 `user-data` 裡放資料庫密碼是安全的。

Q9. 用 `virsh dumpxml` 匯出 XML 當範本時，一定要刪掉哪兩個欄位？不刪會怎樣？

Q10. 對照 PVE：本篇的 `cloud-localds` ＋ `virt-install --import` 這一組，
在 PVE 上對應到哪些指令？兩者底層是同一件事嗎？

> [!question]- 測驗答案
> **Q1.** ★★★★★ 第一行必須是 **`#cloud-config`**（前面不能有空白行或 BOM）。
> 寫錯時 `cloud-init status` **仍然顯示 `done`** —— 因為 cloud-init 順利跑完了，
> 只是把那份 user-data 當成無法辨識的內容略過（日誌會有
> `Unhandled non-multipart ... userdata`）。
> ★★★★★ **危險就在這裡：狀態顯示成功，設定卻完全沒生效。**
> 驗證要看「主機名稱／IP／使用者是不是真的變了」。見〈練習 2〉。
>
> **Q2.** ★★★★★ **非。** cloud-init 用 `meta-data` 裡的 **`instance-id`** 判斷
> 「這是不是同一台機器」。`instance-id` 沒變的話，per-instance 的設定**不會重跑**。
> 要重跑就換一個新的 `instance-id`（本篇腳本用日期時間戳），
> 或在 VM 內 `sudo cloud-init clean --logs && sudo reboot`。見〈cloud-init 是什麼〉。
>
> **Q3.** ★★★★ 它會建立一個以 `tpl.qcow2` 為 backing file 的連結複製磁碟。
> **少了 `-F qcow2`**（明示 backing 檔的格式）。新版 `qemu-img` 會警告
> `Backing file specified without backing format`，某些情境下 VM 會開不起來
> （`Could not open backing file`）。★★★★★ **`-b` 一定要配 `-F`。**
> 見〈backing file 連結複製〉。
>
> **Q4.** ★★★★★ **（D）。** `virt-clone` 只動 libvirt 層的東西（磁碟檔、UUID、MAC），
> **完全不碰 VM 檔案系統裡面的內容** —— 主機名稱、`machine-id`、SSH host key
> 統統跟原機一樣。所以複製前必須先 `virt-sysprep`。見〈virt-clone：完整複製〉。
>
> **Q5.** ★★★★★ systemd 的行為是：`/etc/machine-id` **存在但是空的** → 開機時產生新的；
> **檔案不存在** → 某些版本的初始化流程會出錯或以 read-only 方式處理。
> 所以正確做法是 `truncate -s 0 /etc/machine-id`，
> 並把 `/var/lib/dbus/machine-id` 做成指向它的 symlink（兩者必須一致）。
> 見〈手動清範本〉。
>
> **Q6.** ★★★★ **原因**：範本沒清 `/etc/machine-id`，三台的 machine-id 相同。
> 現代的 DHCP client（systemd-networkd／NetworkManager）用 machine-id 衍生 DUID／
> client identifier，DHCP 伺服器就把三台當成同一台，配同一個 IP。
> **修法**：範本先 `virt-sysprep`；已經開出來的每台跑
> `sudo truncate -s 0 /etc/machine-id && sudo rm -f /var/lib/dbus/machine-id && sudo reboot`
> （順便把 `/etc/ssh/ssh_host_*` 也刪掉重產）。見〈範本到底要清什麼〉。
>
> **Q7.** ★★★★ `--cdrom` 是**從光碟開機跑安裝程式**（要 20～40 分鐘）；
> `--import` 是**不跑安裝程式，直接把既有磁碟拿來開機**。
> cloud image 已經是裝好的系統，★★★★★ **一定要用 `--import`**。
> 用 `--cdrom` 會變成從光碟開機而不是從 cloud image 開機。見〈virt-install 完整參數〉。
>
> **Q8.** ★★★★★ **非。** seed ISO 就是一片普通的 ISO 9660 映像，**沒有任何加密**，
> 任何能讀到檔案的人都拿得到內容（`isoinfo` 或 `mount -o loop` 就能看）。
> 密碼要放的話請放 **`mkpasswd -m sha-512` 產生的 hash**，
> 並把 seed 目錄權限收成 `0700`。真正的機密應該用外部 secret 管理，
> 開機後才去取。見〈安全性注意事項〉。
>
> **Q9.** ★★★★★ 必須刪掉 **`<uuid>`** 與 **`<mac address=...>`**。
> - 不刪 `<uuid>`：`virsh define` 直接報
>   `operation failed: domain 'xxx' already exists with uuid ...`
> - 不刪 `<mac>`：★★★★★ 兩台 VM **MAC 相同**，在同一網段會造成 ARP 表打架、
>   DHCP 拿到同一個 IP，症狀是「網路時好時壞」而且極難查。
>
> 刪掉之後 libvirt 會自動產生新的。見〈XML 範本化與 virsh define〉。
>
> **Q10.** ★★★★ 對應關係：
>
> | 本篇（KVM） | PVE |
> | --- | --- |
> | 寫 `user-data`／`network-config` ＋ `cloud-localds` 做 seed ISO | `qm set <vmid> --ciuser --sshkeys --ipconfig0 ip=...,gw=...`（PVE 自動產生 cloudinit 磁碟） |
> | `qemu-img create -f qcow2 -F qcow2 -b base child` | `qm clone <tpl> <newid> --full 0`（連結複製） |
> | `virt-install --import` / `virsh start` | `qm start <vmid>` |
>
> ★★★★★ **底層是同一件事** —— 兩邊的 cloud-init datasource 都是 **NoCloud**
> （一片 label 為 `cidata` 的虛擬光碟），PVE 只是把「產生那三個檔案並包成 ISO」
> 這段包成 `qm set --ipconfig0` 之類的選項。所以 PVE 上 cloud-init 出問題時，
> 排查的地方完全一樣：VM 內的 `/var/log/cloud-init.log`、datasource 是不是 NoCloud、
> `instance-id` 有沒有變。見〈跟 PVE 做法的逐項對照〉與
> [[050-01-03-13-guide-PVE-建立練習環境]]。
