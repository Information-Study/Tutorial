# KVM 儲存池與網路

> [!abstract] 這篇你會學到
> - libvirt 的**儲存模型**：pool（池）與 volume（磁碟區）到底是什麼、跟「一個資料夾」差在哪
> - ★★★★ 四種最常用的 pool 型式：**dir／logical（LVM）／netfs（NFS）／zfs**，各自適合什麼場合
> - `virsh pool-define-as` → `pool-build` → `pool-start` → `pool-autostart` **四步完整流程**
> - ★★★★ **qcow2 與 raw 怎麼選**：快照、精簡配置、效能、備份四個面向的取捨
> - `qemu-img` 六個一定要會的動作：**create／info／convert／resize／check／snapshot**
> - ★★★★★ **不要對執行中的 VM 動 `qemu-img`**（會直接毀掉磁碟）
> - 預設 NAT 網路 `virbr0` 的**封包路徑**：dnsmasq 從哪裡發 IP、NAT 規則長在哪
> - ★★★★ **橋接網路完整設定**：用 Netplan 建 `br0`、把 VM 接上去、讓 VM 跟實體網段同層
> - ★★★★★ **改網路設定不要把自己鎖在門外**：先備援、後動手、`netplan try` 的自動回滾
> - 隔離網路（isolated）怎麼建，做出「只有 VM 之間互通、對外完全不通」的實驗網段
> - `virsh net-*` 全套指令與 DHCP 固定配發（`net-update add ip-dhcp-host`）

> [!warning] 未實機驗證
> 本篇**以 Ubuntu Server 24.04 LTS ＋ libvirt 10.x ＋ QEMU 8.x 為例**。
>
> ★★★★★ **網卡名稱（`enp1s0`、`eno1`、`ens18`…）每台機器都不一樣**，
> 本篇一律用 `enp1s0` 當代稱，你必須先用 `ip -br link` 查出自己的實際名稱再套用。
>
> ★★★★★ 文中的 **IP、網段、閘道、磁碟路徑、儲存池名稱都是示意值**，
> 請換成你環境實際的值。`qemu-img info` 之類指令的輸出欄位會隨 QEMU 版本增減，
> 以你機器上實際跑出來的為準。
>
> ★★★★★ 本篇「橋接網路」那一節會**改掉主機的網路設定**。
> 沒有 IPMI／iDRAC／iLO 或實體 console 可以救援的話，**先讀完
> 〈不要把自己鎖在門外〉那一小節再動手**。

> [!note] 本章在手冊裡的定位
> 本手冊的虛擬化**主線是 VMware Workstation（單機桌面）與 Proxmox VE（機房叢集）**。
> KVM／libvirt 章是**輔助線**，用途有兩個：
> 一是**單機 Linux 虛擬化** —— 一台 Ubuntu 伺服器要跑幾台 VM，不想為它裝整套 PVE；
> 二是**理解 PVE 的底層** —— PVE 的 `qm`、儲存、`vmbr0` 底下就是本篇這些東西，
> 看懂這一章，PVE 出問題時你才知道要往哪一層找。

## 觀念說明

### libvirt 的儲存模型：pool 與 volume ★★★★

libvirt 不直接管「檔案」，它管兩層抽象：

```
┌─────────────────────────────────────────────────────────────┐
│  storage pool（儲存池）                                      │
│  「VM 磁碟要放在哪裡」的一個容器                              │
│                                                              │
│   type=dir      → 一個目錄            /srv/vmstore           │
│   type=logical  → 一個 LVM VG         vgvm                   │
│   type=netfs    → 一個 NFS 掛載點     nas:/export/vm         │
│   type=zfs      → 一個 ZFS dataset    tank/vm                │
│   type=iscsi    → 一個 iSCSI target                          │
│   type=rbd      → 一個 Ceph pool                             │
│                                                              │
│   ┌──────────────┐ ┌──────────────┐ ┌──────────────┐        │
│   │ volume       │ │ volume       │ │ volume       │        │
│   │ web01.qcow2  │ │ db01.qcow2   │ │ base.qcow2   │        │
│   └──────────────┘ └──────────────┘ └──────────────┘        │
└─────────────────────────────────────────────────────────────┘
                      ▲
                      │ 被 domain（VM）的 XML 引用
              <disk><source file='/srv/vmstore/web01.qcow2'/></disk>
```

★★★★ 三個必須先想清楚的觀念：

| 觀念 | 說明 | 重要度 |
| --- | --- | --- |
| pool 只是**中繼資料** | libvirt 記著「這個目錄／VG／掛載點是我的儲存」，並提供統一的 API 去列出、建立、刪除裡面的 volume | ★★★ |
| VM 的 XML 記的是**絕對路徑**，不是 pool 名稱 | 所以你就算刪掉 pool，VM 還是找得到磁碟；反過來說，**改了 pool 的 target 路徑不會自動改 VM 的 XML** | ★★★★ |
| pool 是**每台主機各自定義**的 | 跟 PVE 的儲存設定是叢集共用不同，libvirt 的 pool 只存在於本機 `/etc/libvirt/storage/` | ★★★★ |

> [!note] ★★★ 不用 pool 行不行？
> 行。你完全可以自己 `qemu-img create` 一個檔案，然後在 VM 的 XML 裡指路徑。
> 但**用 pool 有兩個實際好處**：
> 1. `virt-manager` 與 `virt-install` 的磁碟選單直接看得到，不用每次打路徑。
> 2. ★★★★ **AppArmor／SELinux 的標籤會自動處理**。你把 qcow2 丟在 `/srv/` 底下
>    卻沒定義成 pool，很容易踩到「Permission denied」，這是新手第一名的坑
>    （詳見〈常見錯誤與排錯〉）。

### 預設的 default pool ★★

裝好 libvirt 之後通常已經有一個 `default` pool：

```bash
virsh pool-list --all
```

```text
 Name      State    Autostart
-------------------------------
 default   active   yes
```

```bash
virsh pool-info default
```

```text
Name:           default
UUID:           7f8e2c14-3a91-4c6b-9d05-2e1f8a6b4c33
State:          running
Persistent:     yes
Autostart:      yes
Capacity:       195.86 GiB
Allocation:     41.02 GiB
Available:      154.84 GiB
```

它的 target 就是 `/var/lib/libvirt/images`。★★★ **正式環境不要一直堆在這裡** ——
`/var` 通常跟系統同一個分割區，VM 磁碟長大會把根目錄塞爆，
連 `apt` 都跑不動、log 也寫不進去。**另外開一個獨立的分割區／VG／dataset 給 VM。**

### 四種 pool 型式怎麼選 ★★★★

| 型式 | libvirt type | volume 實體是什麼 | 支援 qcow2 | 適合場合 | 重要度 |
| --- | --- | --- | --- | --- | --- |
| 目錄 | `dir` | 目錄下的檔案 | ✅ | ★★★★ **絕大多數單機情境的預設選擇**；操作最直覺，備份就是 copy 檔案 | ★★★★ |
| 檔案系統 | `fs` | 指定一個 block device 掛起來當目錄 | ✅ | 想把一顆專用硬碟掛成 VM 儲存又懶得自己寫 fstab | ★★ |
| LVM | `logical` | VG 底下的 LV（**裸區塊**） | ❌ | ★★★ 要**效能**、要 LVM 快照、不需要單一檔案可攜性 | ★★★ |
| NFS | `netfs` | NFS 掛載點下的檔案 | ✅ | ★★★ 多台主機共用、想做**遷移**；效能受網路限制 | ★★★ |
| ZFS | `zfs` | dataset 底下的 **zvol**（裸區塊） | ❌ | ★★★★ 已經在跑 ZFS，要 ZFS 的快照／壓縮／send-recv | ★★★ |
| iSCSI | `iscsi` | LUN | ❌ | 接 SAN；libvirt 只能**用**既有 LUN，不能建 | ★★ |
| Ceph | `rbd` | RBD image | ❌ | 分散式儲存；單機情境用不到 | ★ |

★★★★★ **最關鍵的一條**：`logical`、`zfs`、`iscsi`、`rbd` 這幾種**裸區塊**型式的 volume
**沒有 qcow2**，所以：

- **libvirt 層級的磁碟快照做不了**（`virsh snapshot-create-as` 的 disk-only 快照要 qcow2）
- 快照要用**下層機制**：LVM snapshot、`zfs snapshot`、Ceph snapshot
- 換來的是**少一層檔案系統**，隨機 I/O 比較快

### qcow2 與 raw 的取捨 ★★★★

| 面向 | `raw` | `qcow2` | 說明 |
| --- | --- | --- | --- |
| 效能 | ★★★★ 較快 | 略慢 | qcow2 有 L1/L2 表要查、有 refcount 要維護；差距在多數維運場景其實不大 |
| 精簡配置（thin） | ⚠️ 靠檔案系統的 sparse file | ★★★★ **原生支援** | raw 在 ext4/XFS 上其實也能 sparse，但在裸區塊上就是實打實佔滿 |
| 快照 | ❌ 不支援 | ★★★★ **內部快照＋外部快照都行** | 這是 qcow2 最大的賣點 |
| backing file（連結複製） | ❌ | ★★★★★ **支援** | 做範本／量產實驗機的關鍵，見 [[050-01-04-05-guide-KVM-自動化與範本]] |
| 壓縮 | ❌ | ✅（`-c`） | 適合封存，讀取時要解壓縮，不建議拿來跑 |
| 加密 | ❌ | ✅（LUKS） | |
| 備份／搬移 | ★★★ 直接 `dd`／`cp` | ★★★ 直接 `cp`，但要先關機或先 flush | 兩者都是「一個檔案」 |
| 出事時的救援 | ★★★★ **可以直接 `mount -o loop` 或 `kpartx`** | 要先 `qemu-nbd` 掛起來 | 這點 raw 完勝 |

> [!tip] ★★★★ 一句話的選法
> - **一般 VM、實驗機、要用範本量產** → **qcow2**，不用猶豫。
> - **資料庫 VM、I/O 吃很重、且下層已經有 LVM／ZFS 快照** → **raw on LVM／zvol**。
> - **不確定** → qcow2。它可以隨時 `qemu-img convert` 成 raw，反過來也行。

### 網路模型總覽 ★★★★

libvirt 提供四種「VM 怎麼連上網」的作法：

```
                        實體交換器
                             │
  ┌──────────────────────────┼──────────────────────────────────┐
  │  KVM 主機                │                                   │
  │                     ┌────┴─────┐                             │
  │                     │  enp1s0  │                             │
  │                     └──┬────┬──┘                             │
  │        ┌───────────────┘    └───────────────┐                │
  │        │ ① NAT                              │ ② 橋接         │
  │   ┌────▼─────┐  iptables MASQUERADE    ┌────▼────┐           │
  │   │ virbr0   │  ←─ 主機幫 VM 做 NAT    │   br0   │ 主機 IP   │
  │   │192.168.  │  dnsmasq 發 DHCP        │ 掛這裡  │           │
  │   │  122.1   │                         └──┬───┬──┘           │
  │   └──┬────┬──┘                            │   │              │
  │      │    │                               │   │              │
  │   ┌──▼─┐┌─▼──┐                        ┌───▼┐┌─▼──┐           │
  │   │VM A││VM B│  對外看到的是主機 IP   │VM C││VM D│ 有自己的  │
  │   └────┘└────┘                        └────┘└────┘ 實體網段IP│
  │                                                              │
  │   ┌──────────┐ ③ 隔離（isolated）                            │
  │   │ virbr10  │  沒有 <forward>，對外完全不通                 │
  │   └──┬────┬──┘                                               │
  │   ┌──▼─┐┌─▼──┐                                               │
  │   │VM E││VM F│  只有彼此看得到                                │
  │   └────┘└────┘                                               │
  └──────────────────────────────────────────────────────────────┘
```

| 模式 | libvirt 寫法 | VM 的 IP 來源 | 外面連得進來嗎 | 適合 | 重要度 |
| --- | --- | --- | --- | --- | --- |
| ① NAT | `<forward mode='nat'/>` | libvirt 的 dnsmasq | ❌ 要另外做埠轉發 | ★★★★ 桌機、筆電、只需要 VM 上網 | ★★★★ |
| ② 橋接 | `<forward mode='bridge'/>` ＋ 主機的 `br0` | ★★★★ **公司內網的 DHCP／你手動指定** | ✅ **跟實體機一樣** | ★★★★★ **伺服器上跑服務的標準做法** | ★★★★★ |
| ③ 隔離 | 不寫 `<forward>` | libvirt 的 dnsmasq（或完全不發） | ❌ 連主機都出不去 | ★★★ 資安演練、雙網卡實驗、惡意程式分析 | ★★★ |
| ④ 路由 | `<forward mode='route'/>` | libvirt 的 dnsmasq | ✅ 但**上游路由器要加路由** | 少見；要保留來源 IP 又不想橋接時 | ★★ |
| ⑤ macvtap | `<interface type='direct'>` | 實體網段 | ✅ | 想省一層 bridge；★★★★ **但 VM 連不到主機本身** | ★★ |

> [!warning] ★★★★ macvtap 的致命限制
> `type='direct'`（macvtap）在 `mode='bridge'` 下，**VM 與主機本身互相 ping 不到**。
> 因為封包直接進實體網卡，不回頭經過主機的網路堆疊。
> 需要 VM ↔ 主機互通（例如主機跑監控要抓 VM）就**不要用 macvtap，用 `br0`**。

### 預設 NAT 網路 `virbr0` 的封包路徑 ★★★★

VM 開一個網頁時，封包實際走過的路：

```
 VM 內的 eth0（192.168.122.51）
        │  ① 封包丟出，目的 8.8.8.8
        ▼
 主機上的 vnet0（tap 裝置）        ← virsh domiflist 看得到
        │  ② 插在 virbr0 上
        ▼
 virbr0（192.168.122.1）           ← 這是 VM 的預設閘道
        │  ③ 進入主機的 IP forwarding
        │     net.ipv4.ip_forward=1  ← ★★★★ libvirt 啟動網路時會自動打開
        ▼
 nftables / iptables
        │  ④ filter：LIBVIRT_FWO 允許 virbr0 → 外面
        │  ⑤ nat POSTROUTING：LIBVIRT_PRT 做 MASQUERADE
        │     來源 IP 被改寫成主機的 IP
        ▼
 enp1s0 → 實體網路 → 8.8.8.8
```

★★★★ 三個你一定要知道的落點：

| 東西 | 位置 | 用途 |
| --- | --- | --- |
| dnsmasq 設定檔 | `/var/lib/libvirt/dnsmasq/default.conf` | ★★★ **libvirt 自動產生，不要手改** —— 改了會被覆蓋，要改請用 `virsh net-edit` |
| DHCP 租約 | `/var/lib/libvirt/dnsmasq/virbr0.status` | ★★★ 查 VM 拿到什麼 IP（也可用 `virsh net-dhcp-leases`） |
| 防火牆規則鏈 | `LIBVIRT_INP`／`LIBVIRT_OUT`／`LIBVIRT_FWI`／`LIBVIRT_FWO`／`LIBVIRT_FWX`／`LIBVIRT_PRT` | ★★★★ libvirt 自己插的規則，**不要手動刪** |

```bash
sudo nft list table ip libvirt_network 2>/dev/null | head -30
# 舊版或 iptables 後端則看：
sudo iptables -t nat -S | grep LIBVIRT
```

```text
-N LIBVIRT_PRT
-A POSTROUTING -j LIBVIRT_PRT
-A LIBVIRT_PRT -s 192.168.122.0/24 -d 224.0.0.0/24 -j RETURN
-A LIBVIRT_PRT -s 192.168.122.0/24 -d 255.255.255.255/32 -j RETURN
-A LIBVIRT_PRT -s 192.168.122.0/24 ! -d 192.168.122.0/24 -p tcp -j MASQUERADE --to-ports 1024-65535
-A LIBVIRT_PRT -s 192.168.122.0/24 ! -d 192.168.122.0/24 -p udp -j MASQUERADE --to-ports 1024-65535
-A LIBVIRT_PRT -s 192.168.122.0/24 ! -d 192.168.122.0/24 -j MASQUERADE
```

## 安裝或基礎操作

### 建立第一個 dir 儲存池：四步流程 ★★★★

假設你另外掛了一顆碟到 `/srv/vmstore`（怎麼掛見 [[020-01-15-cmd-Linux-磁碟分割與掛載]]）。

**步驟 1／4：定義（define）**

```bash
sudo virsh pool-define-as vmstore dir --target /srv/vmstore
```

```text
Pool vmstore defined
```

★★★ `pool-define-as` 只是**寫下定義**，存到 `/etc/libvirt/storage/vmstore.xml`，
此時目錄可能還不存在、pool 也還沒啟動。

**步驟 2／4：建置（build）**

```bash
sudo virsh pool-build vmstore
```

```text
Pool vmstore built
```

★★★ 對 `dir` 型式來說，`pool-build` 就是「把目錄建出來並設好權限」。
對 `logical` 是「建 VG」、對 `fs` 是「格式化」—— ★★★★★ **所以在 logical／fs 上
`pool-build` 是會毀資料的操作，用之前確認目標裝置是空的。**

**步驟 3／4：啟動（start）**

```bash
sudo virsh pool-start vmstore
```

```text
Pool vmstore started
```

**步驟 4／4：設定開機自動啟動（autostart）**

```bash
sudo virsh pool-autostart vmstore
```

```text
Pool vmstore marked as autostarted
```

★★★★ **第 4 步最常被忘記。** 沒設 autostart，主機重開之後 pool 是 inactive，
`virt-manager` 找不到磁碟、`virt-install` 會噴錯。

**確認結果**

```bash
virsh pool-list --all --details
```

```text
 Name      State    Autostart  Persistent  Capacity   Allocation  Available
---------------------------------------------------------------------------
 default   running  yes        yes         195.86 GiB   41.02 GiB  154.84 GiB
 vmstore   running  yes        yes         916.89 GiB    2.14 GiB  914.75 GiB
```

### pool 的生命週期指令 ★★★

| 動作 | 指令 | 會不會動到資料 |
| --- | --- | --- |
| 定義 | `virsh pool-define-as <name> <type> ...` | 否 |
| 建置 | `virsh pool-build <name>` | ★★★★★ **logical／fs 會格式化** |
| 啟動 | `virsh pool-start <name>` | 否（netfs 會 mount） |
| 停止 | `virsh pool-destroy <name>` | 否（netfs 會 umount）★★★ 名字嚇人但只是「停用」 |
| 刪定義 | `virsh pool-undefine <name>` | 否，**檔案還在** |
| 刪內容 | `virsh pool-delete <name>` | ★★★★★ **會刪掉底層資料** |
| 重新掃描 | `virsh pool-refresh <name>` | 否 |
| 自動啟動 | `virsh pool-autostart <name>` / `--disable` | 否 |

> [!tip] ★★★★ `pool-refresh` 什麼時候要跑
> 你**用 `cp`／`wget`／`qemu-img` 直接在 pool 目錄裡放了新檔案**時，
> libvirt 不會自己發現。跑一次：
>
> ```bash
> sudo virsh pool-refresh vmstore
> ```
>
> ```text
> Pool vmstore refreshed
> ```
>
> 之後 `virsh vol-list vmstore` 才看得到新檔案。
> 這是「我明明把 ISO 丟進去了，virt-manager 卻選不到」的第一名解法。

> [!danger] ★★★★★ 絕對不要對「執行中的 VM」的磁碟跑 qemu-img


| 旗標 | 意義 | 重要度 |
| --- | --- | --- |
| `-p` | 顯示進度 | ★★★ 大檔一定要加，不然你不知道它死了沒 |
| `-f` | **來源**格式 | ★★★ 不加會自動偵測，但明寫比較安全 |
| `-O` | **目標**格式（大寫 O） | ★★★★ 大小寫寫反是最常見的手誤 |
| `-c` | 壓縮（僅 qcow2 目標） | ★★ 封存用，跑起來會變慢 |
| `-o preallocation=falloc` | 預先配置空間 | ★★ 要效能穩定時用 |

★★★★ **convert 也是「壓縮 qcow2 檔案大小」的正規做法** ——
qcow2 用久了實體檔案只會長不會縮，`convert` 到新檔可以把已釋放的空間丟掉：

```bash

ls -lh web01.qcow2 web01-new.qcow2
```

```text
-rw------- 1 libvirt-qemu kvm  38G Sep  2 10:12 web01.qcow2
-rw-r--r-- 1 root         root 12G Sep  2 10:31 web01-new.qcow2
```

**④ resize — 改大小**

```bash
qemu-img resize /srv/vmstore/web01.qcow2 +20G
```

```text
Image resized.
```

> [!danger] ★★★★★ 縮小（shrink）幾乎一定會毀資料
> `qemu-img resize --shrink disk.qcow2 20G` 是**直接把後面的區塊切掉**，
> 它不知道檔案系統在哪裡。要縮小的正確順序是：
> **先在 VM 裡把檔案系統與分割區縮小 → 關機 → 才 `--shrink`**。
> 沒把握就別縮，改成「建一顆新的小磁碟，把資料搬過去」。

★★★★ 放大之後 **VM 裡面不會自動變大**，還要在 VM 內做：

```bash

sudo resize2fs /dev/vda1          # ext4；XFS 用 xfs_growfs /
```

```bash
sudo lvcreate -s -n db01-snap -L 20G /dev/vgvm/db01
```

> `virsh pool-build vgvm` 對 logical pool 的意思是「用 `--source-dev` 指定的裝置**建立 VG**」，
> 也就是 `pvcreate` + `vgcreate`。**裝置上原有的資料會沒有。**
> 已經有 VG 的情況（上面的例子）**跳過 `pool-build`，直接 `pool-start`**。

### NFS 儲存池（netfs） ★★★

適合：兩三台 KVM 主機想共用磁碟、要做遷移。

```bash
sudo virsh pool-define-as nfsvm netfs \
  --source-host 192.168.10.30 \
  --source-path /export/vmstore \
  --target /mnt/nfsvm
sudo virsh pool-build nfsvm      # 只是建 /mnt/nfsvm 這個掛載點目錄
sudo virsh pool-start nfsvm      # ★★★ 這一步會真的去 mount
sudo virsh pool-autostart nfsvm
```

```bash
mount | grep nfsvm
```

```text
192.168.10.30:/export/vmstore on /mnt/nfsvm type nfs4 (rw,relatime,vers=4.2,...)
```

★★★★ NFS 端的匯出參數要注意：

```text
# NAS 上的 /etc/exports
/export/vmstore 192.168.10.0/24(rw,sync,no_root_squash,no_subtree_check)
```

`no_root_squash` 幾乎是必要的（QEMU 要能改檔案擁有者），
★★★★ 但這代表**任何能掛載這個匯出的機器都等同 root** ——
**一定要用專屬的儲存網段並限制來源 IP**。

★★★★★ **NFS 上跑 VM 磁碟最怕的是「NFS 斷線」**：
預設 `hard` 掛載會讓 VM 的 I/O 整個卡住（看起來像當機但其實在等）。
這是**刻意的設計**，因為 `soft` 掛載會讓 I/O 直接失敗，那才會真的損毀檔案系統。
★★★★ **不要為了「不要卡住」而改成 `soft`。**

### ZFS 儲存池 ★★★

```bash
# 前提：已有 zpool tank
sudo zfs create tank/vm
sudo virsh pool-define-as zfsvm zfs --source-name tank/vm
sudo virsh pool-start zfsvm
sudo virsh pool-autostart zfsvm
sudo virsh vol-create-as zfsvm web01 40G
zfs list -t volume
```

```text
NAME            USED  AVAIL  REFER  MOUNTPOINT
tank/vm/web01  41.3G  1.42T    56K  -
```

★★★★ ZFS pool 的 volume 是 **zvol（裸區塊裝置）**，路徑在 `/dev/zvol/tank/vm/web01`。
所以一樣沒有 qcow2、沒有 libvirt 快照，快照用 ZFS：

```bash
sudo zfs snapshot tank/vm/web01@before-upgrade
sudo zfs rollback tank/vm/web01@before-upgrade   # ★★★★★ 會丟掉快照之後的所有變更
```

★★★ 建 zvol 時值得指定 `volblocksize`（常見 8K～16K，配合 VM 內的檔案系統），
libvirt 的 `vol-create-as` 不提供這個參數，要精細調的話**直接用 `zfs create -V` 建好，
再 `virsh pool-refresh zfsvm`**。

### ★★★★★ 橋接網路完整設定（Netplan 建 br0）

這是本篇最重要、也**最容易把自己鎖在門外**的一節。

#### 為什麼要橋接

NAT 網路的 VM 對外看起來是主機的 IP，**外面連不進來**。
只要 VM 上要跑「別人會來連」的服務（Web、資料庫、SSH 給同事用），
就必須讓 VM 有**實體網段上的 IP** —— 這就是橋接。

#### 不要把自己鎖在門外 ★★★★★

> [!danger] ★★★★★ 這一節的操作會斷線，先做完這五件事再動手
> 建 `br0` 的過程中，**實體網卡的 IP 會被搬到 `br0` 上**。
> 中間有一小段時間主機是沒有 IP 的；設定寫錯的話就是**永久沒有 IP**。
>
> **1. 先確認有備援連線** —— 至少要有下列其中一個：
>    - IPMI／iDRAC／iLO 的遠端 console
>    - 接得到鍵盤螢幕的實體 console
>    - ★★★★ **第二張網卡**，設一個獨立的管理 IP，這次不動它
>
>    ```bash
>    ip -br addr
>    ```
>
>    ```text
>    lo               UNKNOWN        127.0.0.1/8
>    enp1s0           UP             192.168.10.20/24
>    enp2s0           UP             192.168.99.20/24     ← ★★★★ 這張留著當備援
>    ```
>
> **2. 備份現有設定**
>
>    ```bash
>    sudo cp -a /etc/netplan /root/netplan-backup-$(date +%F-%H%M)
>    ls /root/netplan-backup-*
>    ```
>
> **3. ★★★★★ 先排一個「五分鐘後自動還原」的保險**
>
>    ```bash
>    sudo apt install -y at
>    echo 'cp -a /root/netplan-backup-*/. /etc/netplan/ && netplan apply' \
>      | sudo at now + 5 minutes
>    ```
>
>    ```text
>    warning: commands will be executed using /bin/sh
>    job 1 at Wed Sep  2 11:05:00 2026
>    ```
>
>    確認新設定沒問題之後，記得把它取消：
>
>    ```bash
>    atq            # 看 job 編號
>    sudo atrm 1    # 取消
>    ```
>


★★★★ **不要直接改 `50-cloud-init.yaml`** —— cloud-init 可能會覆寫它。
新增一個編號更大的檔案，後者優先：

```bash
sudo tee /etc/netplan/99-kvm-bridge.yaml >/dev/null <<'YAML'
network:
  version: 2
  renderer: networkd
  ethernets:
    enp1s0:
      dhcp4: false
      dhcp6: false

    br0:
      interfaces: [enp1s0]

        search: [lab.local]
      parameters:
        stp: false
        forward-delay: 0
YAML

```

★★★★ 逐行解釋：

| 設定 | 為什麼 | 重要度 |
| --- | --- | --- |
| `enp1s0: dhcp4: false` | ★★★★★ **實體網卡不能有 IP**，IP 要在 `br0` 上。忘了關 DHCP 會兩邊都拿到 IP，路由打架 | ★★★★★ |
| `interfaces: [enp1s0]` | 把實體網卡當成橋接的一個 port | ★★★★ |
| `addresses` / `routes` | ★★★ 照抄步驟 1 查到的值 | ★★★★ |
| `stp: false` | ★★★ 只有一個 uplink 時關掉，開機少等 30 秒 | ★★★ |
| `forward-delay: 0` | 同上，避免橋接剛起來的靜默期 | ★★★ |
| 檔案權限 `600` | ★★★ Netplan 會抱怨全域可讀的設定檔 | ★★ |

★★★ 如果原本是 DHCP 取得 IP，`br0` 也可以寫 `dhcp4: true` ——
但**伺服器建議用固定 IP**，因為橋接後 MAC 會沿用實體網卡，DHCP 保留仍有效。

★★★ 舊教學裡的 `gateway4: 192.168.10.254` 已經**被 Netplan 標為棄用**，
會看到 `Warning: `gateway4` has been deprecated`，請改用上面的 `routes:` 寫法。

### 隔離網路（isolated） ★★★

做一個「VM 之間互通、對外完全不通」的實驗網段（資安演練、雙網卡實驗常用）：

```bash
cat > /tmp/lab-isolated.xml <<'XML'
<network>
  <name>lab-isolated</name>
  <bridge name='virbr10' stp='on' delay='0'/>
  <ip address='10.90.90.1' netmask='255.255.255.0'>
    <dhcp>
      <range start='10.90.90.100' end='10.90.90.200'/>
    </dhcp>
  </ip>
</network>
XML
sudo virsh net-define /tmp/lab-isolated.xml
sudo virsh net-start lab-isolated
sudo virsh net-autostart lab-isolated
```

★★★★ **關鍵在「沒有 `<forward>` 元素」** —— 有 `<forward>` 就會做 NAT 或橋接，沒有就是隔離。

| 想要的效果 | XML 怎麼寫 | 重要度 |
| --- | --- | --- |
| VM 互通、VM 連得到主機、對外不通 | 有 `<ip>`、沒有 `<forward>` | ★★★★ |
| ★★★★★ VM 只跟彼此互通，**連主機都碰不到** | ★★★★ **連 `<ip>` 也拿掉**，變成純二層交換器 | ★★★★★ |
| VM 對外 NAT | `<forward mode='nat'/>` | ★★★★ |
| VM 在實體網段 | `<forward mode='bridge'/>` ＋ `<bridge name='br0'/>` | ★★★★★ |

完全隔離（分析惡意程式時的正確寫法）：

```xml
<network>
  <name>lab-airgap</name>
  <bridge name='virbr11' stp='on' delay='0'/>
</network>
```

★★★★ 這樣主機上的 `virbr11` 沒有 IP，主機的網路堆疊碰不到裡面的 VM，
VM 也得自己設靜態 IP（沒有 DHCP）。

### DHCP 固定配發：讓 VM 每次都拿到同一個 IP ★★★★

不要停掉網路，用 `net-update` 線上加：

```bash
sudo virsh net-update default add ip-dhcp-host \
  "<host mac='52:54:00:1a:3b:5c' name='web01' ip='192.168.122.51'/>" \
  --live --config
```

```text
Updated network default live state, persistent config
```

| 旗標 | 意義 | 重要度 |
| --- | --- | --- |
| `--live` | 立刻對執行中的網路生效 | ★★★★ |
| `--config` | ★★★★★ **寫進定義檔，重開才不會不見** | ★★★★★ |
| 兩個都不加 | 只改 live，重啟就消失 | ★★★ 常見的「怎麼又跑掉了」 |

刪除：

```bash
sudo virsh net-update default delete ip-dhcp-host \
  "<host mac='52:54:00:1a:3b:5c'/>" --live --config
```

★★★ VM 那邊要**重新取得租約**才會換 IP：

```bash
# VM 內
sudo dhclient -r ; sudo dhclient       # 或直接 reboot
```

### 磁碟在 XML 裡的關鍵屬性 ★★★★

```xml
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2' cache='none' io='native' discard='unmap'/>
      <source file='/srv/vmstore/web01.qcow2'/>
      <target dev='vda' bus='virtio'/>
      <address type='pci' domain='0x0000' bus='0x04' slot='0x00' function='0x0'/>
    </disk>
```

| 屬性 | 值 | 意義 | 重要度 |
| --- | --- | --- | --- |
| `bus` | ★★★★ `virtio` | 半虛擬化磁碟，比 `sata`／`ide` 快非常多。**Windows 客體要先裝 virtio 驅動才認得** | ★★★★★ |
| `cache` | `none` | ★★★★ 繞過主機 page cache，資料一致性最好，正式環境的預設選擇 | ★★★★ |
| `cache` | `writeback` | 快，但主機突然斷電**可能掉資料**。實驗機可以用 | ★★★ |
| `cache` | `writethrough` | 慢且安全；現在很少用 | ★★ |
| `io` | `native` | 搭配 `cache='none'` 用；raw on block 效果最好 | ★★★ |
| `io` | `threads` | qcow2 on 檔案系統時常見 | ★★★ |
| `discard` | ★★★★ `unmap` | 讓 VM 內的 `fstrim` 能把空間**真的還給主機**，qcow2 才會縮 | ★★★★ |
| `detect_zeroes` | `unmap` | 把全 0 的寫入轉成 discard，省空間 | ★★ |

★★★★ 設好 `discard='unmap'` 之後，VM 內定期跑：

```bash
# VM 內
sudo fstrim -av
```

```text
/: 12.3 GiB (13207306240 bytes) trimmed on /dev/vda1
```

主機上 `qemu-img info` 的 `disk size` 就會變小。

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| `error: Failed to start domain 'web01'` ＋ `Could not open '/srv/vmstore/web01.qcow2': Permission denied` | ★★★★ AppArmor 沒放行自訂路徑，或檔案擁有者不對 | 把目錄**定義成 libvirt pool**（`virt-aa-helper` 才會加規則）；或 `sudo chown libvirt-qemu:kvm /srv/vmstore/*.qcow2`。RHEL 系改用 `semanage fcontext` ＋ `restorecon` |
| `error: internal error: process exited while connecting to monitor: ... Failed to get "write" lock` | ★★★★★ **同一個磁碟被兩個 QEMU 開著**（重複定義的 VM，或你在 VM 執行中跑了 `qemu-img`） | `virsh list --all` 找出誰在用；`sudo lsof /srv/vmstore/web01.qcow2` 確認 PID。**不要用 `--force-share` 硬繞過** |
| `virsh vol-list` 看不到剛剛 `cp` 進去的 ISO | ★★★ libvirt 沒有重新掃描 | `sudo virsh pool-refresh vmstore` |
| 主機重開之後 `virt-manager` 說找不到磁碟、pool 是 `inactive` | ★★★★ 忘了 `pool-autostart` | `sudo virsh pool-autostart vmstore`；netfs pool 另外確認 NFS 伺服器開機時已就緒 |
| `error: Failed to build pool vgvm` ＋ `Device /dev/sdc is already in use` | logical pool 的 `pool-build` 要空裝置 | 已有 VG 就**跳過 `pool-build`**，直接 `pool-start` |
| `qemu-img resize` 之後 VM 裡面容量沒變 | ★★★★ 這是正常的，磁碟變大 ≠ 分割區與檔案系統變大 | VM 內 `sudo growpart /dev/vda 1` ＋ `sudo resize2fs /dev/vda1`（XFS 用 `xfs_growfs /`） |
| qcow2 檔案越來越大，VM 裡明明刪了東西 | ★★★★ 沒開 `discard='unmap'`，或沒跑 `fstrim` | XML 加 `discard='unmap'` → 重開 VM → VM 內 `sudo fstrim -av`；已經很大的用 `qemu-img convert` 重建一份 |
| `netplan try` 之後主機完全連不上，兩分鐘也沒回來 | ★★★★★ `netplan try` 沒能回滾（設定牽涉太多），或你 SSH 進來的那條線本身被改掉 | 走 IPMI／實體 console 進去，`cp -a /root/netplan-backup-*/. /etc/netplan/ && netplan apply` |
| `br0` 起來了但主機上不了網 | ★★★★ 實體網卡的 `dhcp4` 忘了設 `false`，兩邊搶路由；或閘道打錯 | `ip -br addr` 確認 `enp1s0` 沒有 IP；`ip route` 確認 default 走 `br0` |
| VM 接了 `br0` 但拿不到 IP | ★★★ 交換器埠設成 access + port-security 只允許一個 MAC；或該網段沒有 DHCP | 交換器端放寬 MAC 數量限制（見 [[040-01-08-guide-Juniper-埠設定與安全]]）；或給 VM 固定 IP |
| VM 之間通、VM 連不到主機（用了 macvtap） | ★★★★ macvtap 的先天限制 | 改用 `br0` 橋接 |
| 橋接後 VM 網路時通時不通、有大量重傳 | ★★★ 交換器端啟用了 STP portfast 以外的收斂延遲；或 MTU 不一致 | 交換器埠設 edge port；主機與 VM 的 MTU 對齊（有 jumbo frame 時整條路徑都要設） |
| `virsh net-start default` 失敗，`Error while activating network: internal error: Failed to apply firewall rules` | ★★★★ nftables／iptables 後端衝突，或防火牆服務把 libvirt 的鏈清掉了 | `sudo systemctl restart libvirtd`；檢查是否有腳本在跑 `iptables -F`（★★★★★ 這會把 libvirt 的規則一起清掉） |
| VM 在 NFS pool 上，NAS 重啟後 VM 全部卡死不回應 | ★★★★ NFS `hard` 掛載在等伺服器回來（這是正確行為） | 把 NAS 救回來，VM 通常會自己恢復。**不要為此改成 `soft`**，那會真的損毀檔案系統 |
| `virsh net-edit` 改完 DHCP 範圍，VM 還是拿舊 IP | ★★★★ 只改定義沒重啟網路，或 VM 的租約還沒到期 | `virsh net-destroy` ＋ `net-start`（會斷線），或改用 `net-update ... --live --config`；VM 內 `sudo dhclient -r && sudo dhclient` |
| 刪掉 base 映像後，用連結複製開的 VM 全部開不起來 | ★★★★★ backing file 被刪 | 從備份還原 base 檔案到**原本的絕對路徑**；`qemu-img info --backing-chain` 查它在找哪個路徑 |

## 安全性注意事項

### 儲存

- ★★★★★ **VM 磁碟目錄不要開全域可讀。** qcow2 裡面就是整台機器的檔案系統，
  任何能讀到檔案的人 = 拿到那台 VM 的所有資料（含 `/etc/shadow`、私鑰、資料庫）。

  ```bash
  sudo chmod 0711 /srv/vmstore
  sudo chmod 0600 /srv/vmstore/*.qcow2
  ls -ld /srv/vmstore
  ```

  ```text
  drwx--x--x 2 root root 4096 Sep  2 11:42 /srv/vmstore
  ```

- ★★★★ **不要關掉 AppArmor／SELinux 來「解決」權限問題。**
  正確做法是把路徑定義成 pool、或加對應的 SELinux 標籤。
  關掉之後，任何一個被打下來的 VM 就有機會去讀別台 VM 的磁碟。
- ★★★★ **NFS 儲存一定要走專屬網段。** `no_root_squash` 等同把 root 權限交給網段上的任何機器。
  搭配 `/etc/exports` 的來源 IP 限制，以及交換器上的 VLAN 隔離。
- ★★★ **備份的 qcow2 要加密或放在受控儲存。** 一份 VM 磁碟備份外流跟整台伺服器被搬走一樣嚴重。
- ★★★ 刪 VM 時記得 `--remove-all-storage`，或事後手動確認磁碟真的刪了；
  ★★★★ 高機敏環境要**覆寫**而不只是刪檔（`shred` 或依儲存型式的 secure erase）。

### 網路

- ★★★★★ **橋接 = VM 直接暴露在你的實體網段上。**
  一台被打下來的 VM 可以直接掃描、攻擊同網段的印表機、NAS、其他伺服器。
  ★★★★ **不要把實驗 VM 橋接到辦公網段**，用 VLAN 切出實驗網段
  （做法見 [[040-01-03-guide-網路設備-VLAN概念與規劃]]）。
- ★★★★ **VM 自己也要有防火牆。** 主機的 `ufw` 預設**不會過濾橋接的封包**
  （除非開了 `br_netfilter`），所以橋接的 VM 只受它自己的防火牆保護。
- ★★★★ **NAT 網路不是安全機制。** 它只是「外面主動連不進來」，
  VM 依然可以主動對外連線 —— 惡意程式的 C2 通道照樣通。
  分析可疑檔案要用**完全隔離的網路**（連 `<ip>` 都拿掉那種）。
- ★★★ **VNC 一定要 `listen=127.0.0.1`。** 預設監聽 `0.0.0.0` 且**沒有密碼**，
  等於把 VM 的螢幕跟鍵盤送給整個網段。要遠端看畫面請走 SSH 隧道：

  ```bash
  ssh -L 5901:127.0.0.1:5900 ops@192.168.10.20
  ```

- ★★★★ **不要手動 `iptables -F`。** 這會把 libvirt 插的 `LIBVIRT_*` 規則一起清掉，
  VM 的 NAT 立刻壞掉；更糟的是主機的轉送規則變成沒有限制。
  要清規則請 `sudo systemctl restart libvirtd` 讓 libvirt 重建。
- ★★★ **`virsh net-update` 記得帶 `--config`**，否則重開機後 DHCP 保留全部消失，
  VM 換 IP 會讓防火牆規則、監控目標、DNS 記錄全部對不上。

## 練習題

> [!question]- 練習 1：建一個 dir 儲存池並確認 thin provisioning
> 在 `/srv/lab-pool` 建一個名為 `labpool` 的 dir 儲存池，
> 在裡面建一個 100 GiB 的 qcow2，然後證明它實際只佔幾百 KB。
>
> **參考答案**
>
> ```bash
> sudo virsh pool-define-as labpool dir --target /srv/lab-pool
> sudo virsh pool-build labpool
> sudo virsh pool-start labpool

> sudo virsh vol-create-as labpool test.qcow2 100G --format qcow2

> ```
>
> ```text
>  Name         Path                        Type  Capacity    Allocation
> -------------------------------------------------------------------------
>  test.qcow2   /srv/lab-pool/test.qcow2    file  100.00 GiB  196.00 KiB
> ```
>
> `Capacity` 是 VM 看到的、`Allocation` 是實際佔的。
> ★★★★ 四步驟一步都不能少，尤其 `pool-autostart`。

> [!question]- 練習 2：qcow2 與 raw 互轉並比較
> 把練習 1 的 `test.qcow2` 轉成 raw，比較兩者的實際檔案大小，再轉回 qcow2。
>
> **參考答案**
>
> ```bash
> cd /srv/lab-pool
> sudo qemu-img convert -p -f qcow2 -O raw test.qcow2 test.raw
> sudo ls -lsh test.qcow2 test.raw
> ```
>
> ```text
>  196K -rw------- 1 root root 193K Sep  2 12:01 test.qcow2
>     0 -rw-r--r-- 1 root root 100G Sep  2 12:02 test.raw
> ```
>
> ★★★★ 注意第一欄（實際區塊數）跟第五欄（表面大小）：
> raw 在 XFS 上是 **sparse file**，`ls -lh` 顯示 100G 但實際佔 0。
> **這也是為什麼 `cp` 一個 raw 檔會突然變成 100G** —— 要用 `cp --sparse=always`。

> [!question]- 練習 3：建一個完全隔離的網路
> 建一個叫 `airgap` 的網路，讓掛在上面的 VM **連主機都碰不到**，

>
> **參考答案**
>
> ```bash
> cat > /tmp/airgap.xml <<'XML'
> <network>
>   <name>airgap</name>
>   <bridge name='virbr20' stp='on' delay='0'/>
> </network>
> XML
> sudo virsh net-define /tmp/airgap.xml
> sudo virsh net-start airgap
> ip -br addr show virbr20
> ```
>
> ```text
> virbr20          DOWN
> ```
>
> ★★★★ 關鍵是**同時省略 `<forward>` 與 `<ip>`**。
> 有 `<ip>` 的話主機在這個網段上會有 IP，就不是真正的 air-gap。

> [!question]- 練習 4：加一筆 DHCP 固定配發並驗證

> [!question]- 練習 5：把 br0 的設定寫好但不套用，只做語法驗證

> **Q1.** ★★★★ 會失敗（pool 不是 active）。漏了 **`virsh pool-build`**（建出目標目錄）
> 與 **`virsh pool-start`**（啟動）。四步流程是 define → build → start → autostart，
> 第四步雖然不影響當下使用，但漏了主機重開就完蛋。見〈建立第一個 dir 儲存池〉。
>
> **Q2.** ★★★★ **非。** `pool-destroy` 只是「停用」這個 pool，檔案完全不動。
> 會刪資料的是 `pool-delete`（★★★★★ 刪底層內容）；`pool-undefine` 則只刪定義、檔案還在。
> 這三個名字很容易搞混，見〈pool 的生命週期指令〉。
>
> **Q3.** ★★★★ libvirt 不會自動發現你用檔案層工具放進去的東西，要手動重新掃描：
> `sudo virsh pool-refresh vmstore`。這是「ISO 明明在那裡卻選不到」的第一名解法。
>
> **Q4.** ★★★★ **（C）logical。** LVM pool 的 volume 是裸 LV，格式永遠是 raw。
> 同理 `zfs`（zvol）、`iscsi`（LUN）、`rbd` 也都不行。
> 代價是**沒有 libvirt 層的磁碟快照**，要改用 LVM／ZFS 自己的快照機制。見〈四種 pool 型式怎麼選〉。
>
> **Q5.** ★★★★★ **它會直接把磁碟後面 80 GB 的區塊切掉，裡面的檔案系統極可能立刻損毀。**
> `qemu-img` 不知道檔案系統的邊界在哪。正確順序是：**先在 VM 內縮小檔案系統與分割區 →
> 關機 → 才 `--shrink`**。沒把握就建新磁碟搬資料。見〈qemu-img resize〉的 danger 區塊。
>
> **Q6.** ★★★★★ **不可以用。** VM 執行中 QEMU 正在寫同一個檔案，
> `qemu-img convert` 讀到的是一個「寫到一半」的不一致狀態，
> 轉出來的 raw 檔案系統會是壞的（就算能掛起來，資料也可能是舊的／半套的）。
> 而且新版 QEMU 通常會直接以 `Failed to get "write" lock` 擋下來。
> ★★★★★ **所有 `qemu-img` 的寫入類操作都要先關機。**
>
> **Q7.** ★★★★★ **非，而且是最常見的錯誤。** 實體網卡加入橋接後**必須沒有 IP**
> （`dhcp4: false` 且不寫 `addresses`），IP 一律掛在 `br0` 上。
> 兩邊都有 IP 會造成路由與 ARP 打架，症狀是「時通時不通」。見〈步驟 2：寫 Netplan 設定〉。
>
> **Q8.** ★★★★★ `netplan apply` **直接套用、沒有退路**；
> `netplan try` 套用後**倒數 120 秒，沒按 Enter 就自動還原**。
> 建網橋時實體網卡的 IP 會搬家，設定寫錯就是永久斷線；
> `try` 讓你「兩分鐘後主機自己救自己」。見〈不要把自己鎖在門外〉。
>
> **Q9.** ★★★★ 要 `virsh net-destroy default` 再 `virsh net-start default`。
> **風險**：這會中斷所有掛在該網路上的 VM，且執行中的 VM 可能因為 tap 被移除而
> **必須關機再開才會恢復網路**。
> **避開的方法**：用 `virsh net-update <net> <command> <section> <xml> --live --config`
> 線上改單一設定，不用重啟網路。見〈virsh net-edit 改完不會立刻生效〉。
>
> **Q10.** ★★★★ **原因**：VM 內刪檔只是把檔案系統的區塊標記為可用，
> 並沒有告訴下層的 qcow2「這些叢集可以回收」，所以 qcow2 只會長不會縮。
> **解法（兩端都要做）**：
> 1. **主機端**：VM 的 XML 磁碟加 `discard='unmap'`（`<driver ... discard='unmap'/>`），
>    磁碟匯流排要是 `virtio`（`virtio-blk` 需較新版本，`virtio-scsi` 支援最完整），**改完要關機再開**，熱插拔改不了。
> 2. **VM 端**：跑 `sudo fstrim -av`（或啟用 `fstrim.timer` 每週自動跑）。
>
> 已經肥掉的舊磁碟，最快的做法是關機後 `qemu-img convert -p -O qcow2 old.qcow2 new.qcow2`
> 重建一份。見〈磁碟在 XML 裡的關鍵屬性〉。
