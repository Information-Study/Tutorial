# 電腦規格與選購

> [!abstract] 這篇你會學到
> - 一行一行看懂規格表，知道每個數字代表什麼
> - 依**用途**決定哪個零件該花錢、哪個可以省
> - 判斷一台舊電腦「該升級哪個零件最有感」
> - 避開常見的行銷話術與規格陷阱
> - ★★★★ 會算**電源瓦數**與看懂 80 PLUS —— 這項算錯會燒掉整台機器裡的其他零件
> - 機關與企業採購時該注意的額外事項（保固、TCO、規格書撰寫）★★★
> - ★★★ 新機到貨時**逐台驗收**的步驟與指令 —— 簽收之後才發現規格不符，就很難主張了

## 觀念說明

### 核心原則：瓶頸決定體感

> [!example] 用「水桶理論」來理解
> 一個木桶能裝多少水，**取決於最短的那塊木板**，
> 不是最長的那塊。
>
> 電腦也一樣。一台配了頂級 CPU 但只有 8GB 記憶體、
> 還在用傳統硬碟的電腦，**體感會比配置均衡的中階機器差很多**。
>
> **買電腦的目標不是把某一項堆到最高，而是把每一塊木板拉到夠高。** ★★★

### 第一步永遠是：先問「要做什麼」

| 用途 | 最該花錢的 | 可以省的 |
| --- | --- | --- |
| ★★★ **文書、上網、公務系統** | **SSD、記憶體 16GB** | CPU 中階即可、不需獨顯 |
| ★★ 影片剪輯 | CPU 多核 + 記憶體 32GB+ + 快速 SSD + **獨顯** | — |
| ★★ 平面設計 | 記憶體 + 螢幕色準 + SSD | CPU 中階即可 |
| ★ 遊戲 | **獨顯** + CPU 單核效能 | 記憶體 16GB 夠 |
| ★★ 程式開發 | 記憶體 32GB + SSD + CPU 多核 | 獨顯（除非做 AI） |
| ★★★ **跑本地 AI／LLM** | **顯示卡 VRAM**（最關鍵） | — |
| ★★★★ **虛擬化主機** | **記憶體 + 核心數** | 顯示卡 |
| ★★★★ **資料庫伺服器** | 記憶體 + **NVMe SSD + RAID 10** | 顯示卡 |
| ★★★★ **檔案伺服器／NAS** | **大容量硬碟 + ECC 記憶體** | CPU 中低階即可 |

> ★★★★ 後面三列之所以是四顆星，是因為**買錯的後果不是「慢」而是「壞」**：
> 虛擬化主機記憶體不足會讓上面所有 VM 一起被 OOM 殺掉；
> 檔案伺服器沒有 ECC，記憶體位元翻轉會**靜默寫壞檔案而且沒有任何錯誤訊息**。

> [!warning] 最常見的採購錯誤 ★★★
> **買了 i7 的 CPU，卻只配 8GB 記憶體與傳統硬碟。**
>
> 這台機器的體感會比「i5 + 16GB + SSD」差很多，
> 但價格可能還比較貴。
>
> **順序永遠是：SSD > 記憶體 > CPU > 顯卡**（對一般辦公用途）。★★★

## 逐項規格解讀

### CPU

```text
一行規格表拆解

Intel Core i5-14400    2.5 GHz    10 核心 (6P+4E) / 16 執行緒    65W
      │    │      │       │              │                        └ TDP ★★★ 影響電源與散熱
      │    │      │       │              └ 核心與執行緒
      │    │      │       └ 基礎時脈（參考值，實際看 Turbo）
      │    │      └ 型號（數字越大通常越強）
      │    └ 等級
      └ 品牌
```

**Intel 的命名**：

| 等級 | 定位 |
| --- | --- |
| Celeron / Pentium / **Intel Processor** | 入門，效能有限 |
| **Core i3** | 基本文書 |
| ★★★ **Core i5** | **辦公主力，CP 值最高** |
| Core i7 | 進階應用 |
| Core i9 | 高階工作站 |
| ★★★ **Xeon** | **伺服器**（支援 ECC、多路） |

**AMD 的命名**：

| 等級 | 對應 |
| --- | --- |
| Athlon | 入門 |
| ★★★ **Ryzen 3 / 5 / 7 / 9** | 大致對應 i3 / i5 / i7 / i9 |
| ★★★ **EPYC** | **伺服器** |
| Ryzen Pro | 商用（支援 ECC 與管理功能） |

> [!warning] 三個 CPU 規格陷阱
> **一、不同世代不能只比型號數字。** ★★★
> 「i5-14400」的 14 是**第 14 代**。
> 一顆第 14 代的 i5，通常比第 8 代的 i7 還快。
> **要比就比同世代，或直接查跑分**（PassMark、Geekbench）。
>
> **二、筆電的後綴決定一切。** ★★★
> | 後綴 | 意思 |
> | --- | --- |
> | **U** | 超低功耗，**效能較弱**，續航好 |
> | **P** | 中等功耗 |
> | **H / HX** | **高效能**，通常是遊戲筆電或工作站 |
> | **T** | 桌機的低功耗版本 |
> | **K** | 桌機，可超頻（不鎖倍頻） |
> | ★★★★ **F** | **沒有內顯**，必須配獨立顯卡 |
>
> 「i7-1355U」的效能可能不如「i5-13500H」。
>
> **三、`F` 後綴沒有內顯。** ★★★★
> 買了 `i5-14400F` 卻沒買顯示卡 → **開機沒有畫面**。
> 這是實際會發生的採購失誤。

### 記憶體

```text
記憶體規格拆解

32GB (16GB × 2)    DDR5-5600    CL40
  │       │            │          └ 延遲（越小越好）
  │       │            └ 世代與速度（DDR4 與 DDR5 插槽不通用）
  │       └ 兩條 → 支援雙通道 ★★★ 同價位一定要拆兩條
  └ 總容量 ★★★ 這項不足時，其他規格再好都救不回來
```

| 用途 | 建議容量 |
| --- | --- |
| 純文書、單一應用 | 8 GB（**最低標準，不建議新購**） |
| ★★★ **一般辦公、多分頁瀏覽** | **16 GB** ✅ |
| 開發、設計、多工 | 32 GB |
| 影片剪輯、虛擬機 | 32～64 GB |
| ★★★★ 虛擬化主機、資料庫 | 64 GB 以上 |

> [!tip] 2026 年的建議是 16GB 起跳 ★★★
> 現代瀏覽器每個分頁就要 100～300 MB，
> 加上 Teams、防毒、公務系統，8GB 很快就會開始用 swap。
>
> 而且 **16GB 與 8GB 的價差很小，體感差異卻很大** ——
> 這是整台電腦中 CP 值最高的升級。★★★
>
> **買 16GB 請買 8GB × 2** 以啟用雙通道 ★★★
> （見 [[010-01-06-guide-計概-記憶體與儲存階層]]）。

> [!warning] 筆電要確認「能不能升級」★★★★
> 很多輕薄筆電的記憶體是**焊死在主機板上**的，
> 買了就不能加。這種機型**一定要一次買足**。
>
> 採購前確認規格表上有沒有寫「onboard」「soldered」，
> 或有幾個「SO-DIMM 插槽」。
> 這是**買下去就無法補救**的規格，所以是四顆星：
> 三年後同仁抱怨慢，你的選項只剩「整台換掉」。

### ★★★ 儲存

| 類型 | 速度 | 建議 |
| --- | --- | --- |
| ★★★ **NVMe SSD (PCIe 4.0)** | 3000～7000 MB/s | **系統碟首選** |
| NVMe SSD (PCIe 3.0) | 1500～3500 MB/s | 夠用 |
| SATA SSD | ~550 MB/s | 可接受 |
| ★★★ **HDD** | 100～200 MB/s | **絕對不要當系統碟** |

> [!danger] 2026 年還用 HDD 當系統碟是不可接受的 ★★★
> 這是造成「電腦好慢」最主要的原因。
> 開機兩分鐘、開軟體一直轉圈，換 SSD 立刻變 15 秒。
>
> **一顆 500GB 的 SSD 是最便宜、最有感的升級。**
> 機關若還有大量 HDD 系統碟的電腦，
> 換 SSD 的效益遠高於整台換新。

**容量建議**：

| 用途 | 建議 |
| --- | --- |
| 純文書（資料放檔案伺服器） | 256 GB |
| ★★★ **一般辦公** | **512 GB** ✅ |
| 有大量本機資料 | 1 TB |
| 影片剪輯 | 1TB NVMe（系統+工作）+ 大容量 HDD（素材） |
| ★★★ 檔案伺服器 | 大容量 HDD + RAID（見 [[010-01-07-guide-計概-磁碟格式化與RAID入門]]） |

> [!tip] SSD 不要用到滿 ★★★
> SSD 剩餘空間少於 **10～20%** 時效能會明顯下降
> （因為耗損平均與垃圾回收需要空間運作）。
> 選購時**留 20～30% 的餘裕**。

### 顯示卡

| 情況 | 建議 |
| --- | --- |
| ★★★ 文書、上網、公務系統 | **內顯就夠**，不要浪費錢 |
| 雙螢幕、4K 螢幕 | 內顯通常也夠（確認支援的輸出數量與解析度） |
| 影片剪輯、3D | 中階獨顯 |
| 遊戲 | 依目標解析度與畫質選 |
| ★★★ **本地 AI / LLM** | **看 VRAM 容量**，這是關鍵 |
| 伺服器 | **不需要**（除非跑 AI 或虛擬桌面） |

> [!note] 跑本地 LLM 時，VRAM 才是關鍵 ★★★
> 模型必須**整個載入顯示卡的記憶體（VRAM）**才跑得快。
> VRAM 不夠就會退回用 CPU 與系統記憶體 —— **慢十倍以上**。
>
> | VRAM | 大約能跑 |
> | --- | --- |
> | 8 GB | 7B 參數（量化後） |
> | 12～16 GB | 13B 參數 |
> | 24 GB | 30B 參數（量化後） |
> | 48 GB+ | 70B 參數 |
>
> **所以買來跑 AI 的顯卡，VRAM 容量比運算速度更重要。** ★★★
> 見 `80-AI服務` 章節。

### ★★★★ 電源供應器（最容易被算錯的一項）

規格表上的「450W」是**整台機器唯一一個算錯就會弄壞其他零件**的數字，
但它偏偏最常被當成隨便填的欄位。

```text
★★★★ 桌機瓦數估算法（抓「峰值」不是「平均」）

  CPU     TDP × 1.5     i5-14400   65W  →  約 100W   # ★★★ Turbo 時遠超過標示 TDP
  獨顯    TGP × 1.2     RTX 4060  115W  →  約 140W   # ★★★ 瞬時尖峰可達標示的兩倍
  主機板 + 記憶體 + 風扇                →  約  60W
  NVMe SSD ×1 / HDD ×2                  →  約  20W   # HDD 啟動瞬間電流最大
  ────────────────────────────────────────────────
  峰值合計                              ≈  320W
  ★★★★ 再留 30～40% 餘裕  →  450W ～ 550W
        （電源在 50% 負載時效率最高，抓剛好等於長期滿載）
```

| 80 PLUS 等級 | 50% 負載效率 | 建議場合 |
| --- | --- | --- |
| 無認證 | 低於 80%，且用料無保證 | **不要買** |
| 80 PLUS Bronze | 約 85% | 一般辦公機的最低標準 |
| 80 PLUS Gold | 約 90% | 長時間開機的主機、工作站 |
| ★★★ 80 PLUS Platinum / Titanium | 92%～94% | 7×24 伺服器（電費差額三年就回本） |

> [!danger] ★★★★ 電源是「自己壞掉還會拖死別人」的零件
> 其他零件壞掉通常只有自己壞；**電源不是**。
> 劣質或長期過載的電源在輸出電壓不穩時，會把不穩的電壓灌進主機板、
> 記憶體與硬碟 —— 實際發生過的結果是**主機板與系統碟一起燒掉，資料全失**。
>
> 三個實務上真的會出事的算錯：
> - ★★★★ **後來加裝獨顯，沒有重算瓦數** —— 原本 350W 的機器插上獨顯，
>   一跑重載就無預警關機或重開，看起來像「系統不穩」，其實是電源撐不住
> - ★★★ **只看總瓦數不看 +12V 那一路的輸出安培數** ——
>   標示 500W 但 +12V 只給 30A（360W）的電源，帶不動 CPU + 獨顯
> - ★★★ **獨顯的 PCIe 供電接頭數量不對** —— 買了要 2×8-pin 的顯卡，
>   電源只有 1 個 8-pin，用轉接線硬接是走火風險

> [!warning] ★★★★ 伺服器與機櫃的電源要看的是「另外三件事」
> 1. **雙電源供應器（Redundant PSU）**：壞一顆不用停機，但**兩條電源線要插在不同的 PDU／不同迴路**，
>    插在同一條排插上等於白買。★★★★
> 2. **機櫃迴路總量**：單一 20A/110V 迴路實務上只能持續用到約 1,760W，
>    塞滿伺服器很容易跳電，**跳的是整櫃**。★★★★
> 3. **UPS 的容量與電池年限**：電池是耗材，三年左右就該換，
>    沒換的 UPS 在停電時撐不到三十秒。★★★
>
> 計算方式見 [[010-01-15-guide-計概-電力基礎與用電安全]]。

### 螢幕

| 規格 | 說明 | 建議 |
| --- | --- | --- |
| **尺寸** | 對角線英吋 | 辦公 24"、繪圖 27"+ |
| **解析度** | 1920×1080 / 2560×1440 / 3840×2160 | 24" 用 1080p、27" 用 1440p 以上 |
| **面板** | TN / VA / **IPS** / OLED | **辦公用 IPS**（視角廣、色彩準） |
| **更新率** | 60 / 75 / 120 / 144 Hz | 辦公 60Hz 夠、遊戲要高 |
| **接頭** | HDMI / DisplayPort / USB-C | 確認與主機相符 |
| ★★★ 可調高度 | 有／無 | **對長時間辦公很重要**（人體工學） |

> [!tip] 機關採購最常忽略的一項：螢幕高度可調 ★★★
> 螢幕太低會造成長期低頭，是頸椎與肩膀問題的主因。
> 支架能調高度的機型只貴一點點，
> 但對每天用八小時的同仁差別很大。
>
> 若已買了不能調的，用**螢幕增高架**也可以。

## 完整實戰範例

### 情境一：機關文書電腦（預算 25,000）

> [!example] 需求
> Office 文書、瀏覽器開 10～20 個分頁、公文系統、視訊會議、雙螢幕。

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| CPU | **Core i5 / Ryzen 5** | 中階足夠。公務系統多為單執行緒，看單核效能 |
| ★★★ 記憶體 | **16GB (8×2)** | 雙通道；多分頁瀏覽器的實際需求 |
| ★★★ 儲存 | **512GB NVMe SSD** | 體感最關鍵 |
| 顯卡 | **內顯** | 文書不需要獨顯，還能省電費 |
| 電源 | 450W 80+ Bronze | 沒有獨顯，不需大瓦數 |
| 螢幕 | 24" IPS 1080p **可調高度** × 2 | 雙螢幕對文書效率提升明顯 |
| ★★★★ 作業系統 | Windows 11 Pro | Pro 才能加入網域、用 BitLocker、被 GPO 管理 |

> [!warning] 機關電腦一定要買 Windows **Pro** 版 ★★★★
> **家用版（Home）不能加入 Active Directory 網域**，
> 也不能用 BitLocker 加密、不能被群組原則（GPO）管理。
>
> 這意味著這台電腦**無法納入集中管理與資安政策**，
> 是機關資安的破口。採購規格書務必註明 **Pro 或 Enterprise**。

### 情境二：小型伺服器（跑 Web + 資料庫）

> [!example] 需求
> 內部網站、MySQL 資料庫、約 100 位使用者，7×24 運轉。

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 形式 | **機架式伺服器（1U/2U）** | 進機櫃、有導軌、方便維護 |
| CPU | Xeon 或 EPYC，8～16 核 | 支援 ECC；核心數應付並行請求 |
| ★★★★ 記憶體 | **64GB ECC** | 資料庫吃記憶體；ECC 避免靜默損毀 |
| ★★★ 儲存 | **2× NVMe SSD RAID 1**（系統+資料庫） | 資料庫要快且要容錯 |
| | + 4× HDD RAID 6（備份/檔案） | 大容量、可壞兩顆 |
| ★★★ 電源 | **雙電源供應器（備援）** | 壞一顆不用停機 |
| 網路 | 雙 1GbE 或 10GbE，做 bonding | 網路備援 |
| ★★★★ 遠端管理 | **iDRAC / iLO / IPMI** | 不必到機房就能開關機、看畫面 |
| ★★★★ 保固 | **原廠 5 年 NBD 到府** | 這是伺服器最重要的一項 |

> [!danger] ★★★★★ iDRAC / iLO / IPMI 管理埠**絕對不可以直接接上網際網路**
> 這張表裡唯一可能直接造成資安事件的就是最後那個遠端管理埠。
> BMC 韌體的漏洞史很長，而且它的權限**高於作業系統** ——
> 拿到 iDRAC 就等於拿到那台伺服器的實體存取權：可以掛載遠端 ISO 重灌、
> 可以看 console、可以直接關機。
>
> 三個必做的事：
> 1. ★★★★★ 管理埠放在**獨立的管理 VLAN**，不做對外 NAT、不開 port forwarding
> 2. ★★★★ 交機第一件事就是**改掉原廠預設帳密**（Dell `root/calvin`、
>    HP 是機殼標籤上的字串）
> 3. ★★★ 韌體納入更新排程，跟作業系統一樣要修補

> [!tip] 伺服器最重要的規格是「保固」不是「效能」★★★
> 一台伺服器故障時，你需要的是**明天就有工程師帶零件到府**，
> 而不是「效能多 10%」。
>
> 常見的保固等級：
> | 等級 | 意思 |
> | --- | --- |
> | ★★★ NBD（Next Business Day） | **下一個工作日**到府 |
> | ★★★ 4-hour / 8-hour | 4 或 8 小時內回應／到府 |
> | ★★★ 送修 | 你自己拆下來寄回原廠（**機關不要選這個**） |
>
> 機關採購伺服器，建議至少 **5 年 NBD 到府**。★★★

### 情境三：判斷舊電腦該升級哪裡

> [!example] 一台 2019 年的辦公電腦，使用者抱怨很慢
> **步驟 1：先量測，不要猜** ★★★
>
> ```
> Windows：工作管理員 → 效能，觀察 5 分鐘
> Linux：  htop、free -h、iostat -x 1
> ```
>
> **步驟 2：對照症狀**
>
> | 觀察到 | 瓶頸 | 升級建議 | 成本 |
> | --- | --- | --- | --- |
> | ★★★ 磁碟 100%、開機超久 | **HDD** | **換 NVMe/SATA SSD** | 低，**效果最大** |
> | ★★★ 記憶體 90%+、一直在用分頁檔 | **記憶體不足** | 加到 16GB | 低，效果大 |
> | ★★ CPU 長時間 100% | CPU | 換 CPU（要確認主機板支援）或整台換 | 高 |
> | 都不高但還是慢 | 可能是軟體問題 | 檢查開機啟動項、防毒設定、惡意程式 | 0 |
>
> **步驟 3：算划不划算**
>
> ```
> 換 SSD + 加記憶體 ≈ 3,000 元 → 體感接近新機
> 整台換新       ≈ 25,000 元
> ```
>
> **如果 CPU 還堪用（第 8 代以後），升級遠比換新划算。** ★★★
>
> 但要注意：**Windows 10 已經沒有安全更新**，★★★★
> 如果舊機不支援 Windows 11（需要 TPM 2.0 與較新的 CPU），
> 那就必須換機或改裝 Linux —— **這是資安問題，不是效能問題**。

### ★★★ 情境四：新機到貨的逐台驗收

買得對只是一半，**驗收沒做等於白買**。廠商送來的機器與規格書不符、
保固沒登錄、Secure Boot 沒開，都是簽收之後才發現就很難主張的事。
以下這套流程一台機器約十分鐘，二十台的批量進貨值得照做。

> [!example] 情境
> 採購案交貨 20 台文書電腦，規格書寫的是
> 「i5 同等級以上 / 16GB 雙通道 / 512GB 以上 NVMe SSD / Win11 Pro / 5 年到府」。

**【1】開箱前：核對出貨單與機身序號** ★★★

先不要拆封膜。核對外箱標籤的**機型與序號**是否與出貨單一致，
並拍照留存。序號是後面查保固與入財產帳的唯一依據，
**貼紙撕掉或被壓在機殼底部貼不到的位置，之後每次查保固都要搬機器**。

**【2】進 UEFI/BIOS：確認安全功能與韌體版本** ★★★

開機按 F2 / Del 進 UEFI，確認四件事：

| 檢查項 | 應該是 | 漏掉的後果 |
| --- | --- | --- |
| ★★★★ TPM (PTT / fTPM) | Enabled | 不能用 BitLocker，Win11 也裝不了 |
| ★★★★ Secure Boot | Enabled | 開機階段可被植入 bootkit |
| ★★★★ 管理員密碼 (Supervisor Password) | **已設定** | 任何人都能改開機順序、從 USB 開機讀走硬碟 |
| ★★★ 韌體 / BIOS 版本 | 與原廠網站最新版比對 | 已知韌體漏洞未修補 |

**【3】開機進 OS：用指令核對規格，不要只看廠商的估價單** ★★★

Windows（PowerShell 以系統管理員開啟）：

```powershell
# CPU 型號與核心／執行緒數
Get-CimInstance Win32_Processor |
  Select-Object Name, NumberOfCores, NumberOfLogicalProcessors

# ★★★ 記憶體「幾條、各多大」—— 這行才看得出是不是雙通道
Get-CimInstance Win32_PhysicalMemory |
  Select-Object BankLabel, DeviceLocator, Capacity, Speed

# ★★★ 磁碟是 SSD 還是 HDD，看 MediaType
Get-PhysicalDisk | Select-Object FriendlyName, MediaType, Size

# ★★★★ Secure Boot 與 TPM
Confirm-SecureBootUEFI
Get-Tpm | Select-Object TpmPresent, TpmReady

# 序號（入財產帳與查保固用）
(Get-CimInstance Win32_BIOS).SerialNumber
```

預期輸出（節錄）：

```text
Name                                  NumberOfCores NumberOfLogicalProcessors
----                                  ------------- -------------------------
Intel(R) Core(TM) i5-14400 @ 2.50GHz             10                        16

BankLabel  DeviceLocator    Capacity Speed
---------  -------------    -------- -----
BANK 0     DIMM_A1        8589934592  4800     # ★★★ 兩條各 8GB → 雙通道 OK
BANK 1     DIMM_B1        8589934592  4800     #      只出現一條 = 單通道，退貨理由

FriendlyName             MediaType            Size
------------             ---------            ----
KIOXIA KXG80ZNV512G      SSD         512110190592     # ★★★ MediaType 必須是 SSD

True                                                   # ★★★★ Confirm-SecureBootUEFI
TpmPresent TpmReady
---------- --------
      True     True                                    # ★★★★ 兩個都要 True
```

> [!info]- Linux（自建或改裝 Linux 的機器）對照
> ```bash
> lscpu | grep -E 'Model name|^CPU\(s\)|Thread'
> sudo dmidecode -t memory | grep -E 'Locator:|Size:|Configured Memory Speed'
> lsblk -d -o NAME,MODEL,SIZE,ROTA
> sudo dmidecode -s system-serial-number
> mokutil --sb-state
> ```
>
> 預期輸出：
>
> ```text
> NAME    MODEL                 SIZE ROTA
> nvme0n1 KIOXIA KXG80ZNV512G 476.9G    0   # ★★★ ROTA=0 → SSD；=1 就是傳統硬碟
>
> SecureBoot enabled                        # ★★★★ mokutil 的輸出
> ```
>
> `dmidecode` 需要 root；`Size: No Module Installed` 代表那個插槽是空的。

**【4】實測磁碟速度，用數字對規格書** ★★★

規格書若寫了「循序讀取 ≥ 2000 MB/s」，驗收就要真的量：
Windows 用 CrystalDiskMark（跑 SEQ1M Q8T1），Linux 用：

```bash
# ★★★ 測「讀」，寫入測試不要對著已有資料的碟做
sudo hdparm -t --direct /dev/nvme0n1
```

```text
 Timing O_DIRECT disk reads: 6042 MB in  3.00 seconds = 2013.11 MB/sec
                                                        ^^^^^^^ 對照規格書門檻
```

> [!warning] ★★★★ 不要在有資料的碟上跑寫入測試
> `dd if=/dev/zero of=/dev/nvme0n1` 這種指令會**直接覆蓋整顆磁碟**，
> 而且沒有任何確認提示。驗收階段的空機沒差，
> **但同一個指令打在線上機器就是災難**。寫入測試一律寫成檔案：
> `dd if=/dev/zero of=/tmp/testfile bs=1M count=2000 oflag=direct`，測完刪掉。

**【5】查保固並確認起算日** ★★★

拿序號到原廠保固查詢頁查，確認三件事：
**保固到期日、服務等級（是不是到府）、起算日是不是出貨日而非採購日**。
把查詢結果**截圖存檔**，這是規格書「提供保固查詢頁面截圖」那條的驗收證據。

> ★★★ 保固起算日常常是原廠**出貨給經銷商**的日期，不是你收到的日期。
> 庫存壓了半年的機器，你的五年保固到手時只剩四年半 —— 這要在驗收時就反映。

**【6】入清冊、貼財產標籤、才辦簽收**

```text
每一台都要進清冊，欄位至少這些
財產編號 / 序號 / 型號 / 購入日期 / 保固到期日 / 使用人 / 位置 / OS / IP / MAC
```

**驗收檢查表**（每台一份，全部通過才簽收）：

| 檢查項 | 指令／方式 | 預期結果 | 重要度 |
| --- | --- | --- | --- |
| 序號與出貨單相符 | 目視 + 拍照 | 完全一致 | ★★★ |
| CPU 等級符合 | `Get-CimInstance Win32_Processor` | 型號與跑分門檻相符 | ★★★ |
| 記憶體雙通道 | `Win32_PhysicalMemory` | 出現**兩條**且容量相同 | ★★★ |
| 系統碟是 NVMe SSD | `Get-PhysicalDisk` | MediaType = SSD、匯流排 NVMe | ★★★★ |
| 磁碟速度達標 | CrystalDiskMark / `hdparm -t` | ≥ 規格書門檻 | ★★★ |
| OS 版本正確 | `winver` | Windows 11 **Pro** | ★★★★ |
| TPM 已啟用 | `Get-Tpm` | TpmPresent / TpmReady 皆 True | ★★★★ |
| Secure Boot 已啟用 | `Confirm-SecureBootUEFI` | True | ★★★★ |
| BIOS 管理員密碼已設 | 進 UEFI 確認 | 已設定並登錄於密碼保管流程 | ★★★★ |
| 保固等級與起訖 | 原廠查詢頁 | 5 年到府，起算日合理 | ★★★★ |
| 已入資產清冊 | 清冊檔案 | 欄位齊全 | ★★★ |

> [!tip] ★★★ 有問題就「先不要簽收」
> 驗收流程唯一的力量來自**簽收之前**。
> 簽收之後才發現記憶體是單條 16GB、系統碟是 SATA SSD，
> 廠商已經沒有義務換，你只能自己吸收。

## 機關與企業採購的額外考量

### 總持有成本（TCO）

> [!warning] 採購價不等於總成本
> ```
> TCO = 採購價 + 電費 + 維護 + 授權 + 汰換處理
> ```
>
> **一台伺服器五年的電費可能超過採購價**
> （見 [[010-01-15-guide-計概-電力基礎與用電安全]] 的計算範例）。
>
> 所以選購時應該考慮：
> - **能源效率**（80 PLUS 認證等級）★★★
> - 保固年限（過保後的維修成本很高）★★★
> - 是否需要額外授權（Windows Server CAL、虛擬化授權）★★★

### ★★★ 規格書該怎麼寫

> [!tip] 寫規格書的三個原則
> **一、寫「效能指標」而非「特定型號」。** ★★★
> ```
> ❌ CPU：Intel Core i5-14400
> ✅ CPU：PassMark 單執行緒分數 ≥ 3500、多執行緒 ≥ 20000，
>        且支援 vPro 或同等遠端管理技術
> ```
> 綁定型號可能違反政府採購法的公平競爭原則，★★★
> 也讓你無法接受同等或更好的替代品。
>
> **二、把「不可妥協」的項目明確列出。** ★★★
> ```
> ✅ 作業系統：Windows 11 Pro（需支援加入 AD 網域與 BitLocker）
> ✅ 儲存：512GB 以上 NVMe SSD（不接受 HDD 或 SATA SSD）
> ✅ 記憶體：16GB 以上，且需為雙通道配置（如 8GB × 2）
> ✅ 保固：5 年原廠到府服務
> ```
>
> **三、寫入驗收方式。** ★★★
> ```
> ✅ 驗收時以 CrystalDiskMark 實測循序讀取 ≥ 2000 MB/s
> ✅ 提供原廠保固查詢頁面截圖，證明保固起訖日
> ```
> 沒有寫驗收方式的規格，等於沒有規格。★★★

### ★★★ 資安相關的採購要求

| 項目 | 為什麼 |
| --- | --- |
| ★★★★ **TPM 2.0** | Windows 11 必要條件；BitLocker 加密的基礎 |
| ★★★★ **Secure Boot** | 防止開機階段被植入惡意程式 |
| ★★★★ **Windows Pro/Enterprise** | 才能加入網域、被 GPO 管理 |
| ★★★ **vPro / AMT** 或同等 | 遠端管理與修復（但**須妥善設定，本身也是攻擊面**） |
| ★★★ **原廠韌體更新支援期限** | 韌體漏洞需要原廠修補 |
| ★★★ **供應鏈來源** | 部分機關對特定產地的設備有採購限制 |

> [!warning] 注意特定資通訊產品的採購限制 ★★★★
> 我國對公務機關使用特定廠牌的資通訊產品（尤其是網通與資安設備）
> 有相關規範與禁限用清單。
>
> **採購前務必確認最新的規定**，
> 可參考行政院與數位發展部發布的相關公告。
> 見 [[090-07-07-guide-資安實踐-台灣資安法規與個資法]]。

## 常見錯誤與排錯

| 錯誤 | 後果 | 正確做法 |
| --- | --- | --- |
| ★★★ 買了 i7 但配 8GB + HDD | 體感比 i5+16GB+SSD 差很多 | **順序：SSD > 記憶體 > CPU > 顯卡** |
| ★★★★ 買了 `F` 後綴的 CPU 沒配顯卡 | **開機沒畫面** | `F` = 無內顯，必須搭配獨顯 |
| ★★★ 只比型號數字，買到舊世代 | 花了錢效能卻不如預期 | 比同世代，或查 PassMark/Geekbench 跑分 |
| ★★★★ 筆電買了 8GB 想之後再加 | 發現記憶體焊死，**無法補救** | 採購前確認有無 SO-DIMM 插槽 |
| ★★★★ 機關電腦買 Windows 家用版 | **無法加入網域、無法被 GPO 管理** | 規格書註明 Pro 或 Enterprise |
| ★★★★ 買了不支援 Windows 11 的機器 | Windows 10 已無安全更新 | 確認 TPM 2.0 與 CPU 在支援清單內 |
| ★★★★ 伺服器選了「送修」保固 | 故障時要停機數天 | 至少 **NBD 到府**，關鍵系統選 4 小時 |
| ★★★ SSD 買剛好容量，用到滿 | 效能明顯下降 | 留 20～30% 餘裕 |
| ★★★ 只看採購價不看 TCO | 五年電費超過機器價格 | 計算 TCO；選 80 PLUS 高效電源 |
| ★★★ 規格書綁定特定型號 | 可能違反採購法、限縮競爭 | 寫效能指標與必要功能 |
| ★★★ 沒寫驗收方式 | 交來的東西不符預期也難主張 | 明確寫出實測項目與門檻 |
| ★★ 買了獨顯卻插錯螢幕孔 | 沒畫面或效能沒發揮 | 有獨顯時螢幕線要接**顯卡**上的孔 |
| ★★★★ 加裝獨顯沒重算電源瓦數 | 重載時**無預警關機**，久了拖壞主機板 | 依峰值估算再留 30～40% 餘裕 |
| ★★★ 買 16GB 卻收到單條 16GB | 單通道，內顯機種體感差一截 | 規格書寫明「雙通道配置」，驗收時查兩條 |
| ★★★ 買了 DDR5 主機板配 DDR4 記憶體 | **插不進去**，插槽防呆位置不同 | 下單前對照主機板規格的記憶體世代 |
| ★★★★★ iDRAC / iLO 管理埠接上網際網路 | 等同把伺服器實體存取權公開 | 放獨立管理 VLAN，改掉預設帳密 |
| ★★★★★ 舊機報廢前沒銷毀硬碟資料 | 個資／公務資料隨機器流出 | Secure Erase／實體破壞並留紀錄 |

### ★★★ 排查步驟：使用者說「這台電腦很慢」

抱怨「慢」不是一種診斷。下面七步照順序做，每一步都有明確的判讀依據，
**做完就會知道該花 3,000 元還是 25,000 元**。

**【1】先確認系統碟到底是不是 SSD** ★★★

這一步能解決一半以上的案例，**而且最便宜**，所以排第一。

```bash
lsblk -d -o NAME,MODEL,SIZE,ROTA
```

預期輸出：

```text
NAME    MODEL                  SIZE ROTA
sda     ST1000DM010-2EP102   931.5G    1    # ★★★ ROTA=1 → 機械硬碟，找到主因了
nvme0n1 KIOXIA KXG80ZNV512G  476.9G    0    # ROTA=0 → SSD
```

> [!info]- Windows 對照
> ```powershell
> Get-PhysicalDisk | Select-Object DeviceId, FriendlyName, MediaType
> ```
> `MediaType` 顯示 `HDD` 就是機械硬碟。★★★
> 工作管理員「效能」分頁的磁碟項目也會直接標示。

**判讀**：ROTA=1 且系統裝在上面 → **直接跳到結論：換 SSD**，後面幾步可以不用做。

**【2】看記憶體壓力：要看 available，不是 free** ★★★

```bash
free -h
```

```text
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       6.9Gi       160Mi        90Mi       700Mi       390Mi
Swap:          2.0Gi       1.6Gi       400Mi
                            ^^^^^ ★★★ swap 已用 1.6Gi = 記憶體真的不夠
```

> ★★★★ **不要看 `free` 那一欄**。Linux 會把閒置記憶體拿去當快取，
> `free` 很小是正常的；**`available` 才是「還能給程式用多少」**。
> `available` 長期低於總量的 10%、而且 swap 一直在用 → 記憶體不足成立。

**判讀**：`available` 見底 + swap 持續增長 → **加記憶體到 16GB**。

**【3】確認記憶體是不是只有一條（單通道）** ★★★

```bash
sudo dmidecode -t memory | grep -E 'Locator:|Size:'
```

```text
	Locator: DIMM_A1
	Size: 8192 MB
	Locator: DIMM_B1
	Size: No Module Installed     # ★★★ 只有一條 → 單通道
```

**判讀**：只有一條時，**加第二條同規格的記憶體**同時解決容量與頻寬，
對使用內顯的辦公機特別有感。

**【4】看磁碟是不是塞住：%util 與佇列長度** ★★★

```bash
iostat -x 1 3
```

```text
Device   r/s    w/s   rkB/s   wkB/s  r_await  w_await  aqu-sz  %util
sda     42.0   18.0  1680.0   720.0    38.5     52.1     3.20   99.6
                                       ^^^^     ^^^^     ^^^^   ^^^^
                            ★★★ await 數十毫秒 + %util 逼近 100 → 磁碟是瓶頸
```

**判讀**：`%util` 長時間 90% 以上、`aqu-sz` > 2 → 磁碟排隊。
若已經是 SSD 卻這樣，往下看第 6 步（SSD 快滿或壽命將盡）。

**【5】看 CPU 是真的滿載，還是在等 I/O** ★★★

```bash
mpstat 1 3
```

```text
CPU    %usr   %nice    %sys %iowait   %irq  %soft  %idle
all   12.30    0.00    4.10   61.20   0.00   0.40  22.00
                               ^^^^^ ★★★★ %iowait 很高 = CPU 在等磁碟，不是 CPU 不夠
```

> ★★★★ 這一步最常被誤判：工作管理員顯示 CPU 100% 就換 CPU，
> 結果換完一樣慢 —— 因為那 100% 裡大半是 `%iowait`。
> **`%usr` 持續高才是 CPU 真的不夠。**

**判讀**：`%iowait` 高 → 回到第 1／4 步處理磁碟；`%usr` 持續 90%+ → CPU 才是瓶頸。

**【6】檢查 SSD 的剩餘空間與健康度** ★★★

```bash
df -h /
sudo smartctl -a /dev/nvme0n1 | grep -E 'Percentage Used|Available Spare|Critical'
```

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/nvme0n1p2  468G  452G  8.5G  99% /        # ★★★ 用到 99% → 效能會明顯下降

Critical Warning:                   0x00
Available Spare:                    100%
Percentage Used:                    12%        # ★★★ 接近 100% 代表寫入壽命將盡
```

**判讀**：`Use%` 超過 85% → 先清空間或換大碟；
`Percentage Used` 逼近 100% 或 `Available Spare` 掉到 10% 以下 → **準備換碟並先備份**。

**【7】前六步都正常 → 問題在軟體** ★★★

```bash
systemd-analyze blame | head -10
```

```text
12.480s NetworkManager-wait-online.service   # 開機慢常見主因，與硬體無關
 3.201s snapd.service
```

Windows 則看工作管理員「啟動」分頁與防毒的**全碟掃描排程**。
★★★ 防毒設定成上班時間全碟掃描，是機關電腦「早上特別慢」的常見答案。

**結論怎麼下** ★★★

| 診斷結果 | 建議 | 成本 |
| --- | --- | --- |
| ★★★ 系統碟是 HDD | 換 NVMe/SATA SSD | 約 1,500 元，效果最大 |
| ★★★ 記憶體不足 | 加到 16GB（補成雙通道） | 約 1,500 元 |
| ★★ CPU 真的不夠（`%usr` 高） | 整台換新較實際 | 高 |
| ★★★★ 機器不支援 Windows 11 | **必須換機或改裝 Linux** | 這是資安決策，不是效能決策 |

## 安全性注意事項

> [!warning] 採購階段就要納入資安考量 ★★★
> 資安不是買回來之後才處理的事：
>
> | 階段 | 該做什麼 |
> | --- | --- |
> | ★★★ **規格**| 要求 TPM 2.0、Secure Boot、可加入網域的 OS 版本 |
> | ★★★ **驗收** | 確認韌體版本、Secure Boot 已啟用、預設密碼已更改 |
> | ★★★ **上線前** | 依標準流程建置（見 [[020-02-03-01-svc-標準化-新機建置標準流程]]） |
> | ★★★ **使用中** | 納入資產清冊、更新管理、防護軟體 |
> | ★★★★★ **汰除** | **硬碟資料銷毀並留存紀錄** |

### ★★★ 每個疏忽對應的實際後果

「要注意安全」是空話。下面這張表把每個常被跳過的動作，
對應到**它真的會導致什麼事**：

| 被跳過的動作 | 實際後果 | 嚴重度 |
| --- | --- | --- |
| 沒設 BIOS 管理員密碼 | 任何人重開機改開機順序，用 USB 開機掛載硬碟，**無需密碼就能複製整顆碟的檔案** | ★★★★★ |
| 沒啟用全碟加密 | 電腦失竊或報廢流出時，硬碟拆下來接上另一台就全部看得到 | ★★★★★ |
| 沒改 iDRAC/iLO 預設帳密 | 攻擊者取得**高於作業系統**的權限，可掛載 ISO 重灌整台伺服器 | ★★★★★ |
| Secure Boot 沒開 | 開機階段的 bootkit 可在 OS 與防毒載入前先取得控制權 | ★★★★ |
| 買到不支援 Win11 的機器 | Windows 10 已無安全更新，新漏洞**永遠不會被修補** | ★★★★ |
| 韌體從不更新 | UEFI/BMC 韌體漏洞重灌作業系統也清不掉 | ★★★★ |
| 沒入資產清冊 | 漏洞爆發時**答不出「我們有幾台受影響」**，也無法證明已完成盤點 | ★★★★ |
| 保固沒登錄／沒查起算日 | 故障當下才發現已過保，只能自費或停機等修 | ★★★ |

> [!danger] 汰除階段是最常被忽略的資安缺口 ★★★★★
> 舊電腦報廢、捐贈、或轉售時，**硬碟裡的資料還在**。
>
> 快速格式化完全不足 ★★★★★（見 [[010-01-07-guide-計概-磁碟格式化與RAID入門]]）——
> 它只是清掉檔案索引，資料區塊原封不動，
> **市面上的免費救援工具幾分鐘就能還原公文、人事與個資檔案**。
> 這已經構成個資法上的外洩事件，不是「內部疏失」而已。
>
> **機關的標準流程**：
> 1. ★★★ 拆下硬碟
> 2. ★★★★★ 執行資料銷毀（Secure Erase / 多次覆寫 / 實體破壞）
> 3. ★★★ **留存銷毀紀錄與照片**（稽核時要拿得出來）
> 4. ★★★ 主機才辦理報廢
>
> **最省事的做法**：從一開始就啟用 **BitLocker / LUKS 全碟加密** ★★★，
> 報廢時只要銷毀金鑰即可（crypto-erase）。

> [!warning] ★★★★ 拆硬碟前先確認拆的是「哪一顆」
> 這是實務上真的會出事的一步：多碟機器或 RAID 陣列上，
> **憑印象拔錯一顆磁碟**的代價是整組陣列降級，
> 若當下正在重建（rebuild），再拔錯一顆就是**資料全部沒了**。
>
> 動手前一定要用序號對應，不要靠位置記憶：
>
> ```bash
> lsblk -o NAME,SERIAL,SIZE,MOUNTPOINT      # ★★★ 先抄下序號
> sudo hdparm -I /dev/sdb | grep -i serial   # ★★★ 再與磁碟托架上的標籤核對
> ```
>
> 支援的機種可以用定位燈直接點亮那一顆的托架 LED，比人工核對更保險。

> [!tip] 資產盤點：你不知道有的東西，就沒辦法保護 ★★★
> 採購入庫時就要登錄：
> ```
> 財產編號 / 序號 / 型號 / 購入日期 / 保固到期日
> 使用人 / 位置 / 作業系統 / IP / MAC
> ```
>
> 這份清冊是：
> - 資安稽核的必要文件 ★★★
> - 漏洞爆發時判斷「我們有幾台受影響」的依據 ★★★
> - 汰換規劃的基礎 ★★★
>
> 見 [[040-01-18-guide-網路設備-網路設備盤點與文件化]] 與 `71-維運實務` 的盤點章節。

## 練習題

> [!question]- 練習 1：診斷該升級什麼
> 找一台你覺得慢的電腦，開工作管理員（或 `htop`）觀察五分鐘，記下：
> 1. CPU 使用率的最高與平均
> 2. 記憶體使用率
> 3. 磁碟使用率（%）
> 4. 系統碟是 SSD 還是 HDD
>
> 依照本篇的對照表判斷瓶頸在哪，估算升級成本，
> 並與「整台換新」比較划不划算。
>
> 進階：照「排查步驟」的【1】～【7】跑一遍，
> 特別注意第 5 步 —— 你看到的 CPU 高，是 `%usr` 還是 `%iowait`？

> [!question]- 練習 2：配一台機器
> 為以下三個情境各配一台，寫出 CPU/記憶體/儲存/顯卡的選擇與理由：
> 1. 機關承辦人的文書電腦，預算 25,000
> 2. 資訊室要跑 5 台虛擬機的測試主機，預算 80,000
> 3. 想在本機跑 13B 參數 LLM 做內部知識庫測試
>
> 參考方向：
> 1. i5 + 16GB + 512GB NVMe + 內顯 + Win11 Pro
> 2. 核心數與**記憶體優先**（64GB 起），SSD 要快，顯卡不重要 ★★★
> 3. **VRAM 至少 12～16GB** 是硬需求，其他都可以妥協 ★★★

> [!question]- 練習 3：寫一段規格書
> 為情境 1 的文書電腦寫一段採購規格，要符合三原則：
> - 用效能指標而非型號
> - 列出不可妥協的項目（OS 版本、SSD、記憶體、保固）
> - 寫出驗收方式
>
> 寫完後檢查：如果廠商拿一台「CPU 符合但用 HDD」的機器來，
> 你的規格書擋得住嗎？★★★

> [!question]- 練習 4：估電源瓦數
> 一台既有的文書機（i5-14400、無獨顯、450W 電源），
> 現在要加裝一張 TGP 115W 的顯示卡跑影像處理。
>
> 1. 依本篇的估算法算出加裝後的峰值瓦數
> 2. 450W 夠不夠？要不要換？換多少瓦？
> 3. 除了總瓦數，還要確認電源的哪兩件事？
>
> ★★★ 提示：答案不只是「瓦數夠就好」，
> 還要看 +12V 那一路的安培數與 PCIe 供電接頭數量。

## 小測驗

Q1. 用「水桶理論」說明為什麼「把某一項堆到最高」不是好的採購策略。

Q2. 對一般辦公用途，升級的優先順序是什麼？為什麼 SSD 排第一？

Q3. 「i5-13500H」與「i7-1355U」哪個效能可能比較好？為什麼？

Q4. CPU 型號後綴的 `F` 代表什麼？買了會發生什麼問題？

Q5. 為什麼買 16GB 記憶體建議買 8GB × 2 而不是 16GB × 1？

Q6. 機關電腦為什麼一定要買 Windows Pro 版而不是家用版？

Q7. 跑本地 LLM 時，顯示卡最關鍵的規格是什麼？為什麼？

Q8. 為什麼說「伺服器最重要的規格是保固不是效能」？常見的保固等級有哪些？

Q9. TCO 是什麼？為什麼採購價不等於總成本？

Q10. 寫採購規格書的三個原則是什麼？為什麼不該綁定特定型號？

> [!question]- 測驗答案
> **Q1.** ★★★ 木桶能裝多少水**取決於最短的那塊木板**。
> 一台配了頂級 CPU 但只有 8GB 記憶體、還用傳統硬碟的電腦，
> 體感會比配置均衡的中階機器差很多。
> **買電腦的目標不是把某一項堆到最高，而是把每一塊木板拉到夠高。**
> （對應「核心原則：瓶頸決定體感」）
>
> **Q2.** ★★★ **SSD > 記憶體 > CPU > 顯卡**。
> SSD 排第一是因為 HDD 與 SSD 的速度差距是**數十倍**
> （100～200 MB/s vs 3000～7000 MB/s），
> 而開機、開軟體、載入檔案這些日常操作全都受磁碟速度支配。
> 一顆 SSD 能讓開機從兩分鐘變 15 秒，是最便宜也最有感的升級。
> （對應「儲存」與速查表「升級優先順序」）
>
> **Q3.** ★★★ **`i5-13500H` 可能比較好。**
> 因為筆電 CPU 的**後綴決定一切**：
> **U = 超低功耗、效能較弱**；**H = 高效能**。
> 一顆 H 系列的 i5 效能常常超過 U 系列的 i7。
> 不能只看 i5/i7 的等級數字。
> （對應「三個 CPU 規格陷阱」之二）
>
> **Q4.** ★★★ `F` 代表**沒有內建顯示晶片（無內顯）**。
> 買了 `F` 後綴的 CPU 卻沒有搭配獨立顯示卡，
> **開機會完全沒有畫面**。這是實際會發生的採購失誤 ——
> 機器本身沒壞，但交機當天就是點不亮，而且無法用軟體補救。
> （對應「三個 CPU 規格陷阱」之三）
>
> **Q5.** ★★★ 因為主機板支援**雙通道（Dual Channel）**，
> 兩條記憶體可以同時讀寫，**頻寬加倍**。
> 價格幾乎相同，但效能較好，對使用內顯的機器影響尤其明顯
> （內顯要與系統共用記憶體頻寬）。
> 驗收時用 `Get-CimInstance Win32_PhysicalMemory` 看得出是一條還是兩條。
> （對應「記憶體」與情境四【3】）
>
> **Q6.** ★★★ 因為**家用版（Home）不能加入 Active Directory 網域**，
> 也不能使用 **BitLocker** 加密、**不能被群組原則（GPO）管理**。
> 這代表那台電腦**無法納入集中管理與資安政策**，是機關資安的破口。
> 採購規格書務必註明 Pro 或 Enterprise。
> （對應情境一的警告框）
>
> **Q7.** ★★★ 最關鍵的是 **VRAM（顯示卡記憶體）容量**。
> 因為模型必須**整個載入 VRAM** 才跑得快；
> VRAM 不夠就會退回用 CPU 與系統記憶體，**慢十倍以上**。
> 所以買來跑 AI 的顯卡，**VRAM 容量比運算速度更重要**。
> （對應「顯示卡」的 note）
>
> **Q8.** ★★★ 因為伺服器故障時，你需要的是**明天就有工程師帶零件到府**，
> 而不是「效能多 10%」—— 停機的損失遠大於效能差異。
> 常見等級：**NBD**（下一個工作日到府）、**4-hour / 8-hour**（快速回應）、
> **送修**（自己寄回原廠，**機關不應選擇**）。
> 建議至少 5 年 NBD 到府。
> ★★★ 補充：驗收時要查**保固起算日**，它常是原廠出貨日而非你收到的日期。
> （對應情境二與情境四【5】）
>
> **Q9.** ★★★ **TCO = 總持有成本 = 採購價 + 電費 + 維護 + 授權 + 汰換處理**。
> 採購價不等於總成本，因為**一台伺服器五年的電費可能超過它的採購價**，
> 加上過保後的維修成本、額外的軟體授權（如 Windows Server CAL）、
> 以及汰除時的資料銷毀成本。
> （對應「總持有成本（TCO）」）
>
> **Q10.** ★★★ ①寫「**效能指標**」而非特定型號；
> ②明確列出「**不可妥協**」的項目（OS 版本、SSD、記憶體、保固）；
> ③寫入「**驗收方式**」與實測門檻。
> 不該綁定特定型號，是因為這**可能違反政府採購法的公平競爭原則**，
> 也讓你無法接受同等或更好的替代品。
> ★★★ 三者之中最常被漏掉的是第③項 —— 沒有寫驗收方式的規格等於沒有規格，
> 東西送來不符預期時你沒有依據可以主張。
> （對應「規格書該怎麼寫」）
