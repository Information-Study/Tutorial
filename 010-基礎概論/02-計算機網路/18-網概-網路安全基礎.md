## 觀念說明

### 網路的原始設計沒有考慮安全

> [!warning] 這是理解所有網路資安問題的起點
> 網際網路的前身 ARPANET 是**學術研究網路**，
> 使用者都是彼此信任的研究機構。
>
> 所以原始的 TCP/IP：
> | 缺什麼 | 造成的問題 |
> | --- | --- |
> | **沒有加密** | 封包內容任何中間節點都看得到 |
> | **沒有身分驗證** | 來源 IP、MAC、ARP、DNS 回應都可以偽造 |
> | **沒有完整性保護** | 封包可以被竄改 |
>
> **所有的安全機制（TLS、VPN、防火牆、憑證、802.1X）
> 都是後來疊加上去的。**
>
> 這就是為什麼網路資安這麼複雜 ——
> 我們在一個「預設信任」的架構上，一層一層補上「不信任」的檢查。

### 攻擊的三大類

| 類別 | 破壞什麼 | 目標 | 例子 |
| --- | --- | --- | --- |
| **竊聽（Eavesdropping）** | **機密性** | 看到不該看的 | 封包監聽、中間人攻擊 |
| **偽冒（Spoofing/Tampering）** | **完整性** | 假裝成別人、竄改資料 | ARP 欺騙、DNS 劫持、IP 偽造 |
| **阻斷（Denial of Service）** | **可用性** | 讓服務不能用 | DDoS、廣播風暴、資源耗盡 |

**這正好對應資安的 CIA 三要素**（見 [[18-計概-資訊安全初步]]）。

## 分層的攻擊與防護（本章總整理）

> [!tip] 這張表把整章串起來
> 每一層的攻擊，都利用該層協定的設計弱點。

| 層 | 主要攻擊 | 為什麼可行 | 防護 |
| --- | --- | --- | --- |
| **L1 實體** | 剪線、接抓包設備、接閒置網路孔、USB 攻擊 | 有實體接觸就有一切 | **機房門禁**、**停用未使用的埠**、線槽保護 |
| **L2 鏈路** | **ARP 欺騙**、MAC 洪泛、**VLAN Hopping**、Rogue DHCP | ARP/DHCP **沒有身分驗證** | **DHCP Snooping + DAI**、Port Security、`nonegotiate`、802.1X |
| **L3 網路** | **IP 偽造**、ICMP Redirect、路由注入、BGP 劫持 | IP 標頭**可以任意填寫** | **uRPF**、關閉 redirect、路由協定驗證、ACL |
| **L4 傳輸** | **SYN Flood**、埠掃描、連線耗盡 | TCP 交握要先配置資源 | **SYN Cookie**、**防火牆**、限速、Fail2ban |
| **L7 應用** | **釣魚**、SQLi、XSS、DNS 劫持、憑證偽造 | 應用邏輯與人的弱點 | **WAF**、輸入驗證、**HTTPS/HSTS**、**使用者教育** |

> [!danger] 越底層的攻擊越難偵測
> **ARP 欺騙**發生在第 2 層，你的作業系統與應用程式**完全感覺不到**：
> - IP 位址沒變
> - 網路還是通的
> - HTTPS 的鎖頭還在
>
> 但**所有流量都經過攻擊者**。
>
> 這就是為什麼**第 2 層的防護（DHCP Snooping、DAI、Port Security）
> 這麼重要** —— 它們是唯一能在那一層攔截的機制。

## 中間人攻擊（MITM）：最經典的網路攻擊

```mermaid
graph LR
    A["受害者"] -->|"以為在跟閘道講話"| M["攻擊者<br/>（中間人）"]
    M -->|"轉發（並偷看/竄改）"| B["真正的閘道"]
    B --> M
    M --> A
```

**攻擊者能做什麼**：

| 能力 | 說明 |
| --- | --- |
| **看到所有未加密的流量** | HTTP、FTP、Telnet 的**帳號密碼**全都看得到 |
| **知道你連了哪些網站** | 即使用 HTTPS，目的 IP 與 SNI 仍是可見的 |
| **竄改未加密的內容** | 插入廣告、植入惡意 JavaScript |
| **SSL 剝離（SSL Stripping）** | 把你的 HTTPS 請求降級成 HTTP |
| **阻斷連線** | 直接不轉發 |

### 五種常見的 MITM 手法

| 手法 | 在哪一層 | 原理 |
| --- | --- | --- |
| **ARP 欺騙** | L2 | 謊稱「我是閘道」 |
| **Rogue DHCP** | L2/L3 | 發放假的閘道與 DNS |
| **DNS 劫持／毒化** | L7 | 讓網域解析到攻擊者的 IP |
| **Evil Twin（假 AP）** | L1/L2 | 架同名 Wi-Fi 誘導連線 |
| **BGP 劫持** | L3 | 錯誤宣告 IP 區段，把流量導過來 |

> [!tip] HTTPS 是對抗 MITM 最有效的單一措施
> 即使攻擊者成功站在中間：
> - **他看不到 HTTPS 的內容**（加密）
> - **他無法冒充網站**（沒有合法憑證，瀏覽器會警告）
> - **他無法竄改內容**（完整性檢查）
>
> **他只能看到「你連了哪個 IP」與 SNI 中的網域名稱。**
>
> 這就是為什麼「**全站 HTTPS**」是現代網站的基本要求，
> **內部系統也應該用 HTTPS**。

> [!danger] SSL 剝離與 HSTS
> **SSL Stripping** 的原理：
> ```
> 使用者輸入 example.com（沒打 https://）
>   → 瀏覽器送出 HTTP 請求
>   → 中間人攔截，不讓 301 導向 HTTPS 到達使用者
>   → 中間人自己用 HTTPS 連伺服器
>   → 使用者以為一切正常，但他與中間人之間是明文的
> ```
>
> **HSTS 的防護**：
> 伺服器回應 `Strict-Transport-Security: max-age=31536000`，
> 瀏覽器**記住這個網域一律用 HTTPS，連 HTTP 都不試**。
>
> 更徹底的是 **HSTS Preload 清單** ——
> 直接內建在瀏覽器裡，**第一次連線就強制 HTTPS**。
>
> 見 [[13-網概-HTTP與HTTPS]]。

## 防火牆：網路的第一道門

### 防火牆到底在做什麼

> [!example] 核心比喻：門口的警衛
> 防火牆依照**規則清單**，決定每一個封包**放行還是阻擋**。
>
> 規則長這樣：
> ```
> 允許：任何人 → 我的網站(443/TCP)
> 允許：辦公室網段 → 伺服器(22/TCP)
> 允許：已建立的連線的回應
> 拒絕：其他所有
> ```
>
> **警衛看什麼**：來源 IP、目的 IP、埠號、協定、連線狀態。

### 三代防火牆技術

| 世代 | 技術 | 看什麼 | 限制 |
| --- | --- | --- | --- |
| **第一代** | **封包過濾（Packet Filter）** | 來源/目的 IP、埠、協定 | **不記得連線狀態**，要手動開回應方向 |
| **第二代** | **狀態檢視（Stateful Inspection）** | 加上**連線狀態表** | **現代標準** |
| **第三代** | **應用層／NGFW** | 加上**應用程式辨識、使用者身分、內容檢查** | 較貴、較慢 |

> [!tip] 「狀態式」為什麼是關鍵進步
> **無狀態的封包過濾**：
> 你允許「內部 → 外部 443」，
> 但**回應封包是「外部 → 內部」**，
> 所以你必須**額外開放「外部 → 內部的所有高位埠」** ——
> 這等於開了一個大洞。
>
> **狀態式防火牆**：
> 它**記住每一條已建立的連線**（conntrack 表），
> 看到回應封包時知道「這是我剛剛放行出去的那條連線的回應」，
> **自動放行，不需要額外規則**。
>
> ```bash
> # iptables 的狀態規則（這一行是關鍵）
> iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
> ```
>
> **這讓你可以做到「只出不進」** ——
> 內部可以主動連出去，外部無法主動連進來。

### 防火牆的黃金原則

> [!warning] 預設拒絕（Default Deny）
> **先擋掉全部，再開放明確需要的。**
>
> ```bash
> # ✅ 正確：預設拒絕
> iptables -P INPUT DROP
> iptables -P FORWARD DROP
> iptables -A INPUT -i lo -j ACCEPT
> iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
> iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
> iptables -A INPUT -p tcp --dport 443 -j ACCEPT
> ```
>
> **不要用「先全部開放，遇到問題再擋」** ——
> 因為**你永遠不知道自己漏了什麼**。

> [!tip] `DROP` vs `REJECT`
> | | **DROP** | **REJECT** |
> | --- | --- | --- |
> | 做什麼 | **直接丟棄，不回應** | 回一個 RST 或 ICMP unreachable |
> | 對方感受 | **一直等到逾時** | **立刻知道被拒絕** |
> | 適合 | **對外**（讓掃描者浪費時間） | **內部**（讓使用者快速得到明確錯誤） |
>
> 對外用 DROP 能讓大規模掃描變得非常慢，是有效的阻擾手段。

### 出向規則：最常被忽略的一環

> [!danger] 大部分的入侵是「內部主動連出去」造成的
> 很多機關只設了**入向（inbound）規則**，
> **出向（outbound）完全放行**。
>
> 但現代攻擊的流程是：
> ```
> 使用者點了釣魚連結
>   → 下載惡意程式（正常的對外連線）
>   → 惡意程式主動連回 C&C 伺服器（正常的對外連線）
>   → 攻擊者透過這條通道進來
> ```
>
> **入向防火牆全程沒有攔到任何一步。**

**該做的出向管制**：

| 對象 | 建議 |
| --- | --- |
| **伺服器** | **只允許必要的對外連線**（更新來源、DNS、NTP），其他一律擋 |
| **資料庫** | **完全不能主動對外** |
| **IoT / 印表機** | 只能連內部的必要伺服器 |
| 使用者電腦 | 至少擋掉已知的惡意網域（DNS 過濾）與異常的埠 |

```bash
# 範例：伺服器只允許必要的對外連線
iptables -P OUTPUT DROP
iptables -A OUTPUT -o lo -j ACCEPT
iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -p udp --dport 53 -d 192.168.1.1 -j ACCEPT   # 內部 DNS
iptables -A OUTPUT -p udp --dport 123 -d 192.168.1.1 -j ACCEPT  # 內部 NTP
iptables -A OUTPUT -p tcp --dport 443 -d 內部更新伺服器 -j ACCEPT
```

> [!warning] NAT 不是防火牆
> 再次強調（見 [[08-網概-NAT與私有位址]]）：
>
> **NAT 只擋「未經請求的外部連線」，
> 完全不管內部連出去的流量，也不檢查內容。**
>
> 你仍然需要真正的防火牆（含出向規則）。

## 防火牆家族：誰負責什麼

| 設備 | 在哪一層 | 做什麼 | 比喻 |
| --- | --- | --- | --- |
| **封包過濾防火牆** | L3/L4 | 依 IP/埠放行或阻擋 | **門口警衛查證件** |
| **狀態式防火牆** | L3/L4 | 加上連線狀態追蹤 | 警衛記得誰進去了 |
| **NGFW**（次世代） | L3～L7 | 加上**應用辨識、使用者身分、IPS、防毒** | 警衛還會看你帶了什麼 |
| **IDS**（入侵偵測） | L2～L7 | **只看，發現異常就告警** | **監視器 + 警報器** |
| **IPS**（入侵防禦） | L2～L7 | **看到就擋** | 會自動鎖門的警報器 |
| **WAF**（Web 應用防火牆） | L7 | 專門擋 **SQLi、XSS** 等網站攻擊 | 針對特定招數的保鑣 |
| **UTM** | L3～L7 | 多合一（防火牆+IPS+防毒+過濾） | 全能保全（中小企業用） |

> [!note] 防火牆與 IDS 的分工
> - **防火牆**擋的是「**你預先知道不該通過**」的東西（不該開放的埠）
> - **IDS/IPS** 看的是「**通過防火牆的流量裡有沒有壞東西**」
>
> 打個比方：
> 防火牆是門口警衛檢查證件（有證件就放行）；
> **IDS 是館內的監視器，看有證件進來的人有沒有做壞事**。
>
> 「防火牆主要阻絕預想到的攻擊；
> IDS 阻絕預想不到、難以拒絕來源的攻擊。」

### IDS 的兩種偵測方式

| 方式 | 原理 | 優點 | 缺點 |
| --- | --- | --- | --- |
| **特徵式（Signature）** | 比對已知攻擊的特徵碼 | **準確，誤判少** | **只認得已知的攻擊** |
| **異常式（Anomaly）** | 建立正常行為基準，偏離就告警 | 可能發現**未知攻擊** | **誤判多**，需要調校 |
| 行為分析 | 監視使用者行為模式 | 可偵測內部威脅 | 需要學習期 |

### IDS 的兩種部署位置

| 類型 | 全名 | 裝在哪 | 看得到什麼 |
| --- | --- | --- | --- |
| **NIDS** | Network IDS | **網路上**（透過 SPAN/TAP） | 網路流量，但**看不到加密內容** |
| **HIDS** | Host IDS | **每一台主機上** | 檔案變更、程序、本機日誌、**解密後的內容** |

> [!tip] 兩者互補，不是二選一
> **NIDS** 能看到整體流量、發現橫向移動，
> 但**現在 90% 以上的流量都加密了**，能看到的內容有限。
>
> **HIDS** 能看到主機內部的細節（檔案被改、可疑程序），
> 但只看得到自己那一台。
>
> 現代做法是兩者都要，再把日誌集中到 **SIEM** 做關聯分析。
> 見 [[09-日誌集中與SIEM]]。

## VPN：在公開網路上建立私密通道

### VPN 在做什麼

> [!example] 核心比喻：公路上的裝甲運鈔車
> 你要在**公開的道路**（網際網路）上運送**貴重物品**（機密資料）。
>
> **沒有 VPN**：用普通貨車，路上任何人都看得到你載了什麼。
>
> **有 VPN**：用**裝甲運鈔車** ——
> 車子還是走同一條公路，但**外面的人看不到裡面裝什麼**。
>
> 技術上這叫 **隧道（Tunnel）**：
> **把原本的封包整個加密後，塞進另一個封包裡送出去。**

```
原始封包：  [IP: 10.0.1.5 → 10.0.2.8][資料]
                    ↓ 加密後包進新封包
VPN 封包：  [IP: 203.0.113.5 → 198.51.100.9][加密的原始封包]
             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 外面只看得到這一層
```

### VPN 的兩種用途

| 類型 | 用途 | 比喻 |
| --- | --- | --- |
| **遠端存取 VPN**（Remote Access） | **個人連回公司** | 員工從家裡「走進」公司的網路 |
| **站對站 VPN**（Site-to-Site） | **兩個辦公室互連** | 在兩棟大樓之間搭一座專用天橋 |

### 常見的 VPN 協定

| 協定 | 層 | 特點 |
| --- | --- | --- |
| **IPsec** | **L3** | 標準、企業常用；設定複雜；NAT 需要 NAT-T |
| **OpenVPN** | L4（走 TCP/UDP） | 彈性高、跨平台、可走 443 埠躲過封鎖 |
| **WireGuard** | L3 | **新、快、程式碼精簡**（約 4000 行 vs OpenVPN 的 10 萬行）、設定簡單 |
| SSL/TLS VPN | L7 | 瀏覽器就能用，適合簡單的應用存取 |
| PPTP | — | ❌ **已被破解，絕對不要用** |
| L2TP/IPsec | L2+L3 | 相容性好但效能較差 |

> [!tip] WireGuard 是目前的推薦選擇
> **優點**：
> - **程式碼極精簡**（更少的攻擊面、更容易稽核）
> - **效能好**（在核心中執行）
> - **設定簡單**（公私鑰 + 幾行設定）
> - 現代加密演算法
>
> **限制**：
> - 沒有內建的使用者管理（要搭配其他方案）
> - 每個 peer 的 IP 是固定的（設計如此）

### Split Tunnel vs Full Tunnel

| | **Split Tunnel（分割通道）** | **Full Tunnel（全通道）** |
| --- | --- | --- |
| 走 VPN 的流量 | **只有公司網段** | **全部流量** |
| 上網 | 直接從自己的網路出去 | **繞經公司再出去** |
| 效能 | 好 | 較差（多繞一趟） |
| 管控 | 弱 | **強**（所有流量都可監控與過濾） |
| 適合 | 一般使用、頻寬有限時 | **機關、需要完整監控與法遵時** |

> [!warning] 機關通常要求 Full Tunnel
> 因為：
> 1. **所有流量都可以套用機關的資安政策**（DNS 過濾、內容過濾、DLP）
> 2. **可以完整記錄**（法遵要求）
> 3. 避免「員工的家用網路成為攻擊跳板」
>
> 代價是頻寬與延遲，以及公司對外頻寬的壓力。

> [!danger] VPN 不是萬靈丹
> **VPN 保護的是「傳輸中的資料」，不保護其他東西**：
>
> | VPN **不能**防 | 說明 |
> | --- | --- |
> | 端點被入侵 | 你的電腦中毒了，VPN 只是幫惡意程式加密連進公司 |
> | 惡意網站 | VPN 不檢查你連到哪裡 |
> | 帳號被盜 | 攻擊者有你的帳密就能連 VPN |
> | 內部的橫向移動 | 連上 VPN 後就在內網了 |
>
> **所以 VPN 必須搭配**：
> - **MFA**（防止帳密外洩就被連入）
> - **端點健康檢查**（確認裝置有防毒、有更新）
> - **最小權限**（VPN 使用者只能存取必要的資源）
> - **完整日誌**
>
> 這也是 **零信任（Zero Trust）** 想解決的問題 ——
> 不因為「你在 VPN 裡面」就信任你。
> 見 [[12-零信任架構與微分段]]。

## 阻斷服務攻擊（DoS / DDoS）

| | **DoS** | **DDoS** |
| --- | --- | --- |
| 來源 | 單一來源 | **大量分散的來源**（殭屍網路） |
| 難度 | 容易封鎖 | **極難封鎖**（來源太多且分散） |

### 三種攻擊類型

| 類型 | 攻擊什麼 | 例子 | 規模 |
| --- | --- | --- | --- |
| **容量型（Volumetric）** | **把頻寬塞爆** | UDP Flood、**反射放大攻擊** | Gbps ～ Tbps |
| **協定型（Protocol）** | **耗盡連線資源** | **SYN Flood**、Ping of Death | 封包數 |
| **應用層（Application）** | **耗盡應用程式資源** | HTTP Flood、Slowloris、複雜查詢 | 較小但難防 |

> [!danger] 反射放大攻擊：為什麼能打出 Tbps
> **原理**：
> 1. 攻擊者用**受害者的 IP** 當來源（IP 偽造）
> 2. 向大量開放的 DNS/NTP/Memcached 伺服器發查詢
> 3. **回應全部湧向受害者**
>
> **放大倍率**：
> | 協定 | 倍率 |
> | --- | --- |
> | DNS | 28～54× |
> | NTP（monlist） | 高達 500× |
> | **Memcached** | **可達數萬×** |
>
> 攻擊者只要 1 Gbps 的頻寬，就能製造出數百 Gbps 的攻擊。
>
> **你的責任是「不要成為放大器」**：
> - DNS 伺服器**不要開放遞迴查詢給任意來源**
> - NTP **關閉 monlist**（`disable monitor`）
> - **Memcached 絕對不要對外開放**（11211）
> - 實作**出口過濾（BCP 38）** —— 不讓偽造來源的封包離開你的網路

### 防護方式

| 層級 | 做法 |
| --- | --- |
| **自己能做的** | SYN Cookie、限速、conntrack 調校、應用層快取 |
| **ISP** | 上游過濾、黑洞路由（RTBH） |
| **CDN / 清洗服務** | **把流量導到清洗中心**過濾後再送回來 |
| **事前準備** | **知道要打給誰**、有應變流程、有監控告警 |

> [!warning] 大規模 DDoS 你自己擋不住
> 如果攻擊流量是 100 Gbps，而你的對外頻寬只有 1 Gbps，
> **流量在到達你的防火牆之前，線路就已經滿了**。
>
> **這時候只有上游（ISP 或 CDN）能處理。**
>
> **事前該準備的**：
> 1. **知道 ISP 的緊急聯絡管道**（不要等出事才找）
> 2. 評估是否需要 **CDN 或 DDoS 清洗服務**
> 3. 有**流量監控與告警**（才知道被打了）
> 4. 有**應變流程**（誰負責、怎麼聯絡、怎麼決策）
>
> 見 [[11-DDoS防護與CDN]]。

## 完整實戰範例：基本的網路防護清單

### 主機層級（每一台伺服器都該做）

```bash
# ===== 1. 啟用防火牆，預設拒絕 =====
$ sudo ufw default deny incoming
$ sudo ufw default allow outgoing        # 伺服器建議也要收緊
$ sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
$ sudo ufw allow 443/tcp
$ sudo ufw enable
$ sudo ufw status verbose

# ===== 2. 核心參數加固 =====
$ sudo tee /etc/sysctl.d/99-netsec.conf <<'EOF'
# 防 SYN Flood
net.ipv4.tcp_syncookies = 1
net.ipv4.tcp_max_syn_backlog = 8192
net.ipv4.tcp_synack_retries = 2

# 反向路徑過濾（防來源 IP 偽造）
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1

# 不接受 ICMP Redirect（防路由劫持）
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.secure_redirects = 0
net.ipv6.conf.all.accept_redirects = 0

# 不送出 ICMP Redirect（非路由器不需要）
net.ipv4.conf.all.send_redirects = 0

# 關閉來源路由（幾乎沒有正當用途）
net.ipv4.conf.all.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0

# 忽略廣播 ping（防 Smurf 攻擊）
net.ipv4.icmp_echo_ignore_broadcasts = 1

# 記錄異常封包
net.ipv4.conf.all.log_martians = 1
EOF
$ sudo sysctl --system

# ===== 3. 只監聽必要的介面 =====
$ sudo ss -tulpn
#   資料庫等內部服務應該是 127.0.0.1 或內網 IP，不是 0.0.0.0

# ===== 4. 安裝 Fail2ban（自動封鎖暴力破解）=====
$ sudo apt install fail2ban
$ sudo systemctl enable --now fail2ban
$ sudo fail2ban-client status sshd

# ===== 5. 檢查對外暴露面 =====
$ sudo ss -tulpn | grep -E '0\.0\.0\.0|\*:|\[::\]'
#   逐一確認：這個真的需要對外嗎？
```

### 網路設備層級

```cisco
! ===== 交換器基本防護 =====

! 1. 未使用的埠：關閉 + 丟到黑洞 VLAN
interface range GigabitEthernet0/21 - 24
 description ** UNUSED **
 switchport access vlan 999
 shutdown

! 2. 使用者埠：防 VLAN Hopping、防迴圈、限制 MAC
interface range GigabitEthernet0/1 - 20
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate                 ! 防 DTP → VLAN Hopping
 spanning-tree portfast
 spanning-tree bpduguard enable         ! 防迴圈
 storm-control broadcast level 5.00     ! 防廣播風暴
 switchport port-security
 switchport port-security maximum 2     ! 防 MAC 洪泛
 switchport port-security violation restrict

! 3. Trunk：明確限制 + 改 Native VLAN
interface GigabitEthernet0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20,99
 switchport trunk native vlan 999
 switchport nonegotiate

! 4. DHCP Snooping + DAI（防 Rogue DHCP 與 ARP 欺騙）
ip dhcp snooping
ip dhcp snooping vlan 10,20,99
ip arp inspection vlan 10,20,99
!
interface GigabitEthernet0/24
 ip dhcp snooping trust
 ip arp inspection trust

! 5. 管理介面加固
no ip http server                       ! 關閉明文 HTTP 管理
ip ssh version 2                        ! 只用 SSH v2
line vty 0 15
 transport input ssh                    ! 禁用 Telnet
 access-class MGMT-ACL in               ! 限制管理來源
 exec-timeout 10 0
```

### 驗證你的防護

```bash
# 從外部檢查自己開了哪些埠（需要一台外部主機，且僅限自己的 IP）
$ nmap -Pn -p- 你的公有IP

# 檢查 sysctl 設定是否生效
$ sysctl net.ipv4.tcp_syncookies net.ipv4.conf.all.rp_filter \
         net.ipv4.conf.all.accept_redirects

# 檢查是否有異常的對外連線
$ sudo ss -tanp state established '( dport != :80 and dport != :443 )'

# 檢查 ARP 表有沒有異常（一個 MAC 對多個 IP）
$ ip neigh show | awk '{print $5}' | sort | uniq -c | sort -rn | head

# 檢查 DNS 設定有沒有被竄改
$ resolvectl status | grep -A3 'DNS Servers'
$ cat /etc/hosts

# 檢查 Fail2ban 擋了誰
$ sudo fail2ban-client status sshd
```

## 常見錯誤與排錯

| 錯誤觀念 | 為什麼錯 | 正確做法 |
| --- | --- | --- |
| **「有 NAT 就安全」** | NAT 不檢查內容，也不管出向流量 | 用真正的防火牆，**含出向規則** |
| **「內網很安全，不用設防」** | 一台中招就橫向擴散 | **網路分段 + 零信任** |
| 只設入向規則 | **大部分入侵是內部主動連出去** | **加上出向管制** |
| 「先全開，有問題再擋」 | 你不知道漏了什麼 | **預設拒絕** |
| 「HTTPS 就不用防火牆」 | 兩者防的是不同的事 | 縱深防禦，兩者都要 |
| 「有鎖頭就是安全網站」 | DV 憑證誰都能申請 | **看網域名稱本身** |
| 「有 VPN 就安全」 | VPN 只保護傳輸中的資料 | 搭配 MFA、端點檢查、最小權限 |
| 「切了 VLAN 就有資安」 | 沒有 ACL 等於沒隔離 | **VLAN + 存取控制規則** |
| 「有防毒就夠了」 | 擋不住釣魚、設定錯誤、零時差 | **縱深防禦** |
| 把 ICMP 全部擋掉 | **會造成 PMTU 黑洞** | 放行 Type 3 與 Type 11 |
| **未使用的網路孔沒關** | 任何人插線就進內網 | **`shutdown` + 黑洞 VLAN** |
| **管理介面能從網際網路存取** | 最高價值的攻擊目標 | 放**獨立管理 VLAN**，只允許跳板機 |
| 用 Telnet 管理設備 | **密碼明文傳輸** | **一律用 SSH**，禁用 Telnet |

## 安全性注意事項

> [!danger] 網路資安的十項基本功
> 這十件事做到，能擋掉絕大多數的常見攻擊。
>
> | # | 項目 | 對應章節 |
> | --- | --- | --- |
> | 1 | **全面 HTTPS + HSTS**，淘汰所有明文協定 | [[13-網概-HTTP與HTTPS]] |
> | 2 | **防火牆預設拒絕，含出向規則** | 本篇 |
> | 3 | **網路分段（VLAN + ACL）** | [[16-網概-VLAN與網路分段]] |
> | 4 | **停用未使用的交換器埠** | [[16-網概-VLAN與網路分段]] |
> | 5 | **DHCP Snooping + DAI + Port Security** | [[05-網概-MAC位址與交換器]] |
> | 6 | **管理介面放獨立 VLAN，絕不連外網** | [[12-Cisco-管理IP與遠端存取]] |
> | 7 | **VPN + MFA**，不對外開管理埠 | 本篇 |
> | 8 | **保持韌體與系統更新** | [[03-弱點與修補管理流程]] |
> | 9 | **日誌集中保存與監控告警** | [[09-日誌集中與SIEM]] |
> | 10 | **使用者資安教育**（釣魚是最大破口） | [[12-資安意識與社交工程防範]] |

> [!warning] 明文協定必須全面淘汰
> | 明文 | 加密替代 |
> | --- | --- |
> | **Telnet (23)** | **SSH (22)** |
> | **FTP (21)** | **SFTP (22)** |
> | **HTTP (80)** | **HTTPS (443)** |
> | **SNMP v1/v2c (161)** | **SNMP v3** |
> | LDAP (389) | LDAPS (636) |
> | POP3/IMAP | POP3S/IMAPS |
>
> **機關的網路設備與印表機尤其要檢查** ——
> 很多預設還開著 Telnet 與 SNMP v2c，
> 而那些設備的管理密碼一旦被監聽到，攻擊者就能接管整個網路。

> [!tip] 記錄保存是法定義務
> 依《資通安全管理法》與相關規範，
> **特定機關的連線紀錄需保存一定期間**。
>
> 該保存的網路日誌：
> | 日誌 | 為什麼重要 |
> | --- | --- |
> | **防火牆日誌** | 誰連了誰、被擋了什麼 |
> | **NAT 對應紀錄** | **沒有它，只知道一個公有 IP，不知道是內部哪一台** |
> | **DHCP 日誌** | **IP ↔ MAC ↔ 時間**的對應 |
> | **DNS 查詢日誌** | 每台機器試圖連到哪裡（**資安調查的黃金資料**） |
> | VPN 連線紀錄 | 誰在什麼時候從哪裡連入 |
> | 認證日誌 | 登入成功與失敗 |
>
> **這些日誌串起來，才能回答「6 月 3 日下午 2 點是誰做的」。**
> 見 [[09-日誌集中與SIEM]]。

> [!danger] 排錯時發現這些現象要往資安想
> | 發現 | 可能是 |
> | --- | --- |
> | DNS 指向不認識的 IP | **DNS 劫持** |
> | `hosts` 有奇怪的項目 | **惡意程式竄改** |
> | ARP 表中一個 MAC 對應多個 IP | **ARP 欺騙（MITM）** |
> | 對外流量異常大 | **資料外洩**或被當跳板 |
> | 出現不認識的 DHCP 伺服器 | **Rogue DHCP** |
> | 大量連到陌生 IP 的高位埠 | **惡意程式回連 C&C** |
> | 交換器 MAC 表暴增 | **MAC 洪泛攻擊** |
> | 大量 `SYN_RECV` | **SYN Flood** |
> | 半夜有大量對外連線 | **資料外洩**或挖礦 |
>
> **不要只把它當「網路問題」修掉就算了** ——
> 要循**資安事件應變流程**處理，保全證據。
> 見 [[04-資安事件應變流程]]。

## 速查表

### 攻擊三大類

| 類別 | 破壞 | 例子 |
| --- | --- | --- |
| **竊聽** | 機密性 | 封包監聽、MITM |
| **偽冒** | 完整性 | ARP 欺騙、DNS 劫持、IP 偽造 |
| **阻斷** | 可用性 | DDoS、廣播風暴 |

### 分層攻防

| 層 | 攻擊 | 防護 |
| --- | --- | --- |
| L1 | 剪線、接抓包器、接閒置孔 | 門禁、**關閉未用埠** |
| **L2** | **ARP 欺騙**、MAC 洪泛、VLAN Hopping、Rogue DHCP | **DHCP Snooping + DAI**、Port Security、`nonegotiate` |
| L3 | IP 偽造、ICMP Redirect | **uRPF**、關 redirect、ACL |
| L4 | **SYN Flood**、埠掃描 | **SYN Cookie**、防火牆、Fail2ban |
| L7 | 釣魚、SQLi、XSS | **WAF**、HTTPS、**使用者教育** |

### 防火牆三代

| 代 | 技術 | 看什麼 |
| --- | --- | --- |
| 1 | 封包過濾 | IP、埠、協定 |
| **2** | **狀態檢視** | **+ 連線狀態（現代標準）** |
| 3 | NGFW | + 應用、使用者、內容 |

### 設備分工

| 設備 | 做什麼 |
| --- | --- |
| **防火牆** | 擋「不該通過的」 |

| **IPS** | 同上但**會擋** |
| **WAF** | 專擋網站攻擊（SQLi、XSS） |
| NGFW/UTM | 多合一 |

Q3. 為什麼「越底層的攻擊越難偵測」？請用 ARP 欺騙為例說明。

Q4. HTTPS 對抗中間人攻擊時，能保護什麼？**不能**保護什麼？

Q5. 什麼是 SSL Stripping？HSTS 怎麼防它？

Q6. 「狀態式防火牆」比「封包過濾防火牆」進步在哪裡？為什麼這很重要？

Q7. 防火牆的 `DROP` 與 `REJECT` 有什麼差別？對外與對內各建議用哪一個？

Q8. 為什麼「只設入向規則、出向完全放行」是危險的？請描述一個典型的攻擊流程。

Q9. 防火牆與 IDS 的分工是什麼？請用「警衛與監視器」的比喻說明。

Q10. VPN 保護什麼？**不保護**什麼？為什麼機關通常要求 Full Tunnel？

> [!question]- 測驗答案
> **Q1.** 因為網際網路的前身 ARPANET 是**學術研究網路**，
> 使用者都是彼此信任的研究機構。
> **三個根本問題**：
> ①**沒有加密**（封包內容任何中間節點都看得到）；
> ②**沒有身分驗證**（來源 IP、MAC、ARP、DNS 回應都可以偽造）；
> ③**沒有完整性保護**（封包可以被竄改）。
> 所有安全機制都是**後來疊加上去**的，這就是網路資安複雜的根源。
>
> **Q2.** ①**竊聽（Eavesdropping）** → 破壞**機密性 C**；
> ②**偽冒（Spoofing/Tampering）** → 破壞**完整性 I**；
> ③**阻斷（Denial of Service）** → 破壞**可用性 A**。
>
> **Q3.** 因為底層的攻擊發生在上層「看不到」的地方。
> 以 **ARP 欺騙**為例：它發生在**第 2 層**，
> 你的作業系統與應用程式**完全感覺不到** ——
> **IP 位址沒變、網路還是通的、HTTPS 的鎖頭還在**，
> 但**所有流量都經過攻擊者**。
> 這就是為什麼第 2 層的防護（DHCP Snooping、DAI、Port Security）
> 這麼重要 —— 它們是唯一能在那一層攔截的機制。
>
> **Q4.** **能保護**：①**內容加密**（攻擊者看不到你傳什麼）；
> ②**身分驗證**（攻擊者沒有合法憑證，無法冒充網站，瀏覽器會警告）；
> ③**完整性**（內容被竄改會被偵測）。
> **不能保護**：**你連了哪個 IP，以及 SNI 中的網域名稱** ——
> 攻擊者仍然知道你在跟哪個網站通訊，只是看不到內容。
>
> **Q5.** **SSL Stripping**：使用者輸入 `example.com`（沒打 https），
> 瀏覽器送出 HTTP 請求，**中間人攔截並阻止 301 導向到達使用者**，
> 自己用 HTTPS 連伺服器 —— 使用者以為正常，
> 但**他與中間人之間是明文的**。
> **HSTS 的防護**：伺服器回應 `Strict-Transport-Security`，
> 瀏覽器**記住這個網域一律用 HTTPS，連 HTTP 都不試**；
> 更徹底的是 **HSTS Preload 清單**（內建在瀏覽器裡，**第一次連線就強制 HTTPS**）。
>
> **Q6.** **狀態式防火牆會記住每一條已建立的連線**（連線狀態表）。
> **無狀態的封包過濾**允許「內部→外部 443」時，
> 因為回應封包是「外部→內部」，**必須額外開放外部到內部的所有高位埠**，
> 等於開了一個大洞。
> **狀態式**看到回應封包時知道「這是我剛放行出去那條連線的回應」，
> **自動放行**。這讓你可以做到「**只出不進**」——
> 內部可主動連出，外部無法主動連入。
>
> **Q7.** **DROP** 直接丟棄不回應，對方**一直等到逾時**；
> **REJECT** 回一個 RST 或 ICMP unreachable，對方**立刻知道被拒絕**。
> **對外建議用 DROP**（讓大規模掃描變得非常慢，是有效的阻擾）；
> **對內建議用 REJECT**（讓使用者快速得到明確的錯誤訊息）。
>
> **Q8.** 因為**大部分的入侵是「內部主動連出去」造成的**，
> 而入向規則完全攔不到。
> **典型流程**：
> ①使用者點了釣魚連結 →
> ②下載惡意程式（**對防火牆而言是正常的對外連線**）→
> ③惡意程式**主動連回攻擊者的 C&C 伺服器**（也是正常的對外連線）→
> ④攻擊者透過這條「內部主動建立」的通道進來。
> **入向防火牆全程沒有攔到任何一步。**
>
> **Q9.** **防火牆擋的是「你預先知道不該通過」的東西**（不該開放的埠）；
> **IDS/IPS 看的是「通過防火牆的流量裡有沒有壞東西」**。
> 比喻：**防火牆是門口警衛檢查證件**（有證件就放行）；
> **IDS 是館內的監視器，看有證件進來的人有沒有做壞事**。
>
> **Q10.** **VPN 保護的是「傳輸中的資料」** ——
> 把原始封包整個加密後包進另一個封包（隧道），
> 讓公開網路上的人看不到內容。
> **不保護**：①**端點被入侵**（電腦中毒了，VPN 只是幫惡意程式加密連進公司）；
> ②**惡意網站**（VPN 不檢查你連到哪）；
> ③**帳號被盜**（有帳密就能連 VPN）；
> ④**內部橫向移動**（連上就在內網了）。
> **機關要求 Full Tunnel** 是因為：
> ①**所有流量都可以套用機關的資安政策**（DNS 過濾、內容過濾、DLP）；
> ②**可以完整記錄**（法遵要求）；
> ③避免員工的家用網路成為攻擊跳板。
