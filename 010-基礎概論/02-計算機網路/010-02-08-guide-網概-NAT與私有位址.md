## 觀念說明

### 問題：IPv4 位址不夠用

```
IPv4 總共只有 2³² ≈ 43 億個位址
但全世界的連網裝置早就遠超過這個數字
```

**NAT**（Network Address Translation，網路位址轉換）
是讓 IPv4 撐到今天的關鍵技術。

### 核心比喻：公司總機

> [!example] 一家公司只有一個對外電話號碼
> 你的公司有 200 位員工，但**對外只有一個總機號碼 `02-1234-5678`**。
>
> **打出去**：
> 員工小王（分機 105）要打電話給客戶。
> 電話從總機撥出，**客戶手機上顯示的是 `02-1234-5678`**，
> 不是小王的分機。
> **總機記下：「這通電話是分機 105 打的」。**
>
> **打回來**：
> 客戶回撥 `02-1234-5678`，總機看記錄，
> **知道要轉接給分機 105**。
>
> | 電話 | 網路 |
> | --- | --- |
> | 公司總機號碼 | **公有 IP** |
> | 分機號碼 | **私有 IP** |
> | 總機小姐 | **執行 NAT 的路由器** |
> | 總機的通話記錄本 | **NAT 轉換表** |

> [!note] 關鍵：外面的世界只看得到「總機號碼」
> 這解釋了兩件事：
> 1. **多台裝置可以共用一個公有 IP** → 解決位址不足
> 2. **外面的人無法主動找到內部的某一台**（除非事先設定）
>    → 這既是「安全性」也是「麻煩」

## NAT 怎麼運作

### 出去的時候：改寫來源

```
內部電腦 → 路由器 → 網際網路

原始封包：
  來源 IP: 192.168.1.10    來源埠: 54321
  目的 IP: 93.184.216.34   目的埠: 443

經過 NAT 後：
  來源 IP: 203.0.113.5     來源埠: 61000   ← 都被改了！
  目的 IP: 93.184.216.34   目的埠: 443
```

**同時，路由器在 NAT 表裡記一筆**：

| 內部 IP:埠 | 對外 IP:埠 | 目的 IP:埠 | 狀態 |
| --- | --- | --- | --- |
| 192.168.1.10:54321 | 203.0.113.5:**61000** | 93.184.216.34:443 | ESTABLISHED |
| 192.168.1.20:33445 | 203.0.113.5:**61001** | 8.8.8.8:53 | — |
| 192.168.1.10:52100 | 203.0.113.5:**61002** | 142.250.1.1:443 | ESTABLISHED |

### 回來的時候：查表還原

```
網際網路 → 路由器 → 內部電腦

回應封包：
  來源 IP: 93.184.216.34   來源埠: 443
  目的 IP: 203.0.113.5     目的埠: 61000

路由器查 NAT 表 → 「61000 對應到 192.168.1.10:54321」

還原後：
  目的 IP: 192.168.1.10    目的埠: 54321   ← 送回正確的機器
```

> [!tip] 「埠號」是 NAT 能運作的關鍵
> 光靠 IP 是不夠的 —— 200 台機器都轉成同一個公有 IP，
> 回來時怎麼分辨？
>
> **答案：用不同的「對外埠號」來區分。**
>
> 這就是為什麼精確的名稱是 **PAT**（Port Address Translation）
> 或 **NAPT**（Network Address Port Translation）。
> 大家口語上都叫 NAT，但實際在做的幾乎都是 PAT。
>
> 一個公有 IP 理論上可以有 65535 個埠，
> **所以一個公有 IP 可以支撐數千台裝置同時上網**。

## NAT 的三種類型

| 類型 | 全名 | 改什麼 | 用途 |
| --- | --- | --- | --- |
| **SNAT** | Source NAT | **改來源** | 內部 → 外部（**上網**） |
| **DNAT** | Destination NAT | **改目的** | 外部 → 內部（**埠轉發**） |
| **PAT / NAPT** | Port Address Translation | 改來源 IP **+ 埠** | 多對一（**最常見**） |
| Masquerade | — | SNAT 的一種 | 對外 IP 會變動時（撥接、DHCP）用這個 |

### 埠轉發（Port Forwarding）= DNAT

> [!example] 讓外面的人連到你內部的伺服器
> 你在內網 `192.168.1.50` 架了一台網站伺服器，
> 想讓外面的人連得到。
>
> **設定埠轉發規則**：
> ```
> 外部：203.0.113.5:443  →  內部：192.168.1.50:443
> ```
>
> 這樣當有人連 `https://203.0.113.5` 時，
> 路由器就會把封包的**目的 IP 改成 192.168.1.50** 送進來。
>
> **總機比喻**：
> 「以後打總機分機 0 的，一律轉給 105 號的小王。」

> [!warning] 埠轉發是把內部服務暴露在網際網路上
> 一旦設了埠轉發，**全世界都可以連到那台機器的那個埠**。
>
> **設定前務必確認**：
> 1. 那台服務**有沒有做好安全設定**（強密碼、更新、加密）
> 2. **只轉發必要的埠**，不要一次轉一大堆
> 3. 考慮**限制來源 IP**（如果只有特定地點需要連）
> 4. 開啟**日誌與監控**
>
> **絕對不要轉發**：
> - **3389（遠端桌面）** —— 全世界都在掃這個埠
> - **22（SSH）** 到弱密碼的機器
> - **3306（MySQL）、5432（PostgreSQL）** —— 資料庫不該直接對外
> - **445（SMB）** —— 勒索軟體的最愛
>
> **正確做法是走 VPN**，而不是開埠。

## NAT 造成的問題

### 一、外面無法主動連進來

> [!note] 這既是優點也是缺點
> **優點**：內部機器不會被隨機掃描到（但**這不等於安全**，見下文）。
>
> **缺點**：
> - 架不了對外服務（除非設埠轉發）
> - P2P 應用（BT、部分視訊軟體）需要額外的穿透技術
> - 線上遊戲的「主機」功能失效
> - 遠端桌面連不進來

**應用程式的解法**：

| 技術 | 說明 |
| --- | --- |
| **UPnP / NAT-PMP** | 應用程式**自動請求路由器開埠**（方便但**有資安風險**） |
| **STUN / TURN** | 視訊通話（WebRTC）用來發現與穿透 NAT |
| **打洞（hole punching）** | 雙方同時往外連，讓 NAT 表產生對應記錄 |
| **反向連線** | 內部主動連到外部的中繼伺服器（Cloudflare Tunnel、ngrok、Tailscale） |

> [!danger] UPnP 應該關閉
> **UPnP** 讓區網內**任何程式**都能自己叫路由器開埠，
> **完全不需要驗證**。
>
> 這代表：
> - 惡意程式可以自己開一個埠讓外面連進來
> - 使用者完全不知道有哪些埠被打開了
>
> **機關與企業環境一律關閉 UPnP。**
> 需要開埠就走正式的變更申請流程。

### 二、NAT 不是防火牆

> [!danger] 這是最常見也最危險的誤解
> 很多人以為「我在 NAT 後面所以很安全」。**不是。**
>
> | NAT 做的事 | NAT **不做**的事 |
> | --- | --- |
> | 隱藏內部 IP 結構 | ❌ **檢查封包內容** |
> | 阻擋「未經請求」的外部連線 | ❌ **阻擋內部主動連出去的惡意流量** |
> | | ❌ **防止惡意程式回連 C&C 伺服器** |
> | | ❌ **防止釣魚、下載惡意檔案** |
> | | ❌ **內部機器之間的攻擊**（同網段根本不經過 NAT） |
>
> **絕大多數的入侵是「內部主動連出去」造成的**：
> 使用者點了釣魚連結、下載了木馬 ——
> **這些流量對 NAT 來說完全是正常的對外連線**。
>
> **NAT 是位址轉換技術，不是安全機制。**
> 你仍然需要**真正的防火牆**（含出向規則）、
> 端點防護、網路分段。
> 見 [[090-05-02-guide-資安設備-防火牆與次世代防火牆]]。

### 三、破壞端對端原則

網際網路原始的設計是「**任何一台機器都能直接連到任何另一台**」
（end-to-end principle）。

NAT 打破了這個原則，造成：
- 某些協定需要特殊處理（FTP 的主動模式、SIP、IPsec）
- 增加了故障排除的複雜度
- 讓網路變成「不對稱」的（客戶端 vs 伺服器角色固定）

> [!note] 為什麼 FTP 在 NAT 後面常出問題
> FTP 的**主動模式（Active Mode）**：
> 控制連線用 21 埠，但**資料連線是伺服器主動連回客戶端**。
>
> 在 NAT 後面，伺服器根本連不進來 → **列目錄卡住、傳檔失敗**。
>
> **解法**：用**被動模式（Passive Mode）**，
> 讓客戶端主動連伺服器的資料埠。現代 FTP 客戶端預設都用被動模式。
>
> 這也是 **SFTP（走 SSH，單一埠 22）** 比 FTP 更適合的原因之一。

### 四、CGNAT：多一層 NAT

> [!danger] CGNAT 讓埠轉發完全失效
> **CGNAT**（Carrier-Grade NAT）是 ISP 在**他們那一層再做一次 NAT**，
> 讓好幾百個用戶共用同一個公有 IP。
>
> ```
> 你的電腦 (192.168.1.10)
>     ↓ 你家路由器 NAT（你控制得了）
> 你家 WAN (100.64.x.x)      ← 這仍是私有／CGNAT 範圍
>     ↓ ISP 的 CGNAT（你控制不了）
> 真實公有 IP (203.x.x.x)     ← 與其他幾百戶共用
> ```
>
> **後果**：
> - **就算你在自家路由器設了埠轉發也沒用**，
>   因為封包根本到不了你家路由器
> - DDNS 也救不了（DDNS 解決「IP 會變」，不解決 NAT）
>
> **判斷方法**：
> ```bash
> # 看你家路由器 WAN 口的 IP，與這個比對
> $ curl -s ifconfig.me
> ```
> 若 WAN 口 IP 在 `100.64.0.0/10`（或其他私有範圍）
> 且與 `ifconfig.me` 顯示的不同 → **你在 CGNAT 後面**。
>
> **解法**：向 ISP **申請固定 IP／真實 IP**（通常要加價）。

## 完整實戰範例

### 在 Linux 上設定 NAT（把 Linux 當路由器）

假設：
- `eth0` 接對外（WAN），IP 由 DHCP 取得
- `eth1` 接內網（LAN），`192.168.50.1/24`

```bash
# 步驟 1：啟用 IP 轉送
$ sudo sysctl -w net.ipv4.ip_forward=1
$ echo 'net.ipv4.ip_forward=1' | sudo tee /etc/sysctl.d/99-nat.conf
$ sudo sysctl --system

# 步驟 2：設定 SNAT（用 MASQUERADE，對外 IP 會變也沒問題）
$ sudo iptables -t nat -A POSTROUTING -o eth0 -s 192.168.50.0/24 -j MASQUERADE

# 步驟 3：允許轉送
$ sudo iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT
$ sudo iptables -A FORWARD -i eth0 -o eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT
#                                            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#                                只允許「回應」進來，不允許外部主動連入

# 步驟 4：儲存規則（重開機才不會消失）
$ sudo apt install iptables-persistent
$ sudo netfilter-persistent save
```

> [!note] `MASQUERADE` vs `SNAT`
> ```bash
> # SNAT：明確指定要轉成哪個 IP（對外 IP 固定時用）
> iptables -t nat -A POSTROUTING -o eth0 -j SNAT --to-source 203.0.113.5
>
> # MASQUERADE：自動用該介面當前的 IP（對外 IP 會變時用，如 DHCP、PPPoE）
> iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
> ```
> MASQUERADE 較方便但稍慢（每個封包都要查介面 IP）。
> **固定 IP 的環境建議用 SNAT。**

### 用 nftables（現代做法）

```bash
$ sudo nft add table ip nat
$ sudo nft add chain ip nat postrouting { type nat hook postrouting priority 100 \; }
$ sudo nft add rule ip nat postrouting oifname "eth0" ip saddr 192.168.50.0/24 masquerade
```

### 設定埠轉發（DNAT）

```bash
# 把外部的 8080 轉到內部 192.168.50.100 的 80
$ sudo iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 \
    -j DNAT --to-destination 192.168.50.100:80

# 允許這個轉送
$ sudo iptables -A FORWARD -i eth0 -o eth1 -p tcp -d 192.168.50.100 --dport 80 \
    -j ACCEPT

# 更安全：只允許特定來源
$ sudo iptables -t nat -A PREROUTING -i eth0 -s 203.0.113.0/24 -p tcp --dport 22 \
    -j DNAT --to-destination 192.168.50.100:22
#                            ^^^^^^^^^^^^^^^^ 只有這個網段能連
```

### 觀察 NAT 轉換表

```bash
# 看目前的連線追蹤表（這就是 NAT 表）
$ sudo conntrack -L | head -5
tcp 6 431999 ESTABLISHED src=192.168.50.100 dst=93.184.216.34 sport=54321 dport=443 \
    src=93.184.216.34 dst=203.0.113.5 sport=443 dport=61000 [ASSURED]
    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    這一行就是「原始」與「轉換後」的對應

# 統計目前有多少連線
$ sudo conntrack -C
1523

# 看 conntrack 表的上限
$ cat /proc/sys/net/netfilter/nf_conntrack_max
262144
```

> [!warning] conntrack 表爆滿會讓網路整個掛掉
> 每一條經過 NAT 的連線都要在 conntrack 表裡佔一格。
>
> 如果表滿了，**新的連線全部被丟棄**，
> 症狀是「網路突然完全不通，但 ping 閘道還通」，
> 且 `dmesg` 會出現：
> ```
> nf_conntrack: table full, dropping packet
> ```
>
> **常見原因**：
> - 使用者數量成長
> - **有人在跑 P2P**（每個連線都佔一格，BT 可以開幾千條）
> - **遭到 DDoS 或掃描攻擊**
> - 逾時設定太長
>
> **處理**：
> ```bash
> # 加大上限
> $ echo 'net.netfilter.nf_conntrack_max=524288' | sudo tee -a /etc/sysctl.d/99-nat.conf
>
> # 縮短 TCP 逾時（預設 5 天太長）
> $ echo 'net.netfilter.nf_conntrack_tcp_timeout_established=86400' | sudo tee -a /etc/sysctl.d/99-nat.conf
> $ sudo sysctl --system
> ```
> **並且要監控它**：
> ```bash
> # 納入監控告警：使用率超過 80% 就警告
> echo "$(sudo conntrack -C) / $(cat /proc/sys/net/netfilter/nf_conntrack_max)"
> ```

### 檢查自己是不是在 CGNAT 後面

```bash
#!/usr/bin/env bash
# 判斷是否處於 CGNAT 之後
echo "=== NAT 層級檢查 ==="

# 本機 IP
LOCAL=$(ip route get 8.8.8.8 2>/dev/null | grep -oP 'src \K\S+')
echo "本機 IP：        $LOCAL"

# 對外看到的 IP
PUBLIC=$(curl -s --max-time 5 ifconfig.me)
echo "網際網路看到的： $PUBLIC"

# 判斷
if [[ "$PUBLIC" =~ ^(10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[01])\.|100\.(6[4-9]|[7-9][0-9]|1[01][0-9]|12[0-7])\.) ]]; then
  echo "⚠ 對外 IP 仍在私有／CGNAT 範圍 → 無法從外部連入"
elif [[ "$LOCAL" != "$PUBLIC" ]]; then
  echo "ℹ 你在至少一層 NAT 後面（正常，這是家用/企業標準配置）"
  echo "  若路由器 WAN 口 IP 也不等於 $PUBLIC，則是 CGNAT"
else
  echo "✓ 本機直接持有公有 IP"
fi
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| 埠轉發設好了外面連不進來 | **在 CGNAT 後面** | 向 ISP 申請真實 IP |
| 埠轉發設好了但仍不通 | 防火牆沒放行、內部服務沒啟動、服務只聽 127.0.0.1 | 依序檢查：`ss -tulpn`、防火牆規則、NAT 規則 |
| 內部機器上不了網 | `ip_forward` 沒開、缺 MASQUERADE 規則 | `sysctl net.ipv4.ip_forward`；檢查 `iptables -t nat -L` |
| 網路突然完全不通，ping 閘道卻通 | **conntrack 表爆滿** | `dmesg \| grep conntrack`；加大上限、縮短逾時 |
| FTP 能登入但列不出目錄 | **主動模式在 NAT 後面失效** | 改用**被動模式**；或改用 SFTP |
| 視訊通話單向有聲音 | NAT 穿透失敗 | 確認 STUN/TURN 設定；檢查是否對稱式 NAT |
| VPN（IPsec）在 NAT 後面連不上 | IPsec 的 AH 模式與 NAT 不相容 | 啟用 **NAT-T**（NAT Traversal，走 UDP 4500） |
| 惡意程式自己開了埠 | **UPnP 被啟用** | **關閉 UPnP**；用防火牆日誌檢查有哪些埠被開過 |
| 兩個網段都是 192.168.1.0/24，VPN 通不了 | **網段衝突** | 改用不常見的網段（如 `10.87.x.x`）；或做 NAT 轉換 |
| 內部機器彼此攻擊，NAT 完全沒擋到 | **NAT 不管內部流量** | 用 VLAN 分段 + 防火牆；NAT 不是安全機制 |
| 遠端桌面開了埠轉發後被暴力破解 | 3389 是全世界掃描的目標 | **不要對外開 3389**，改走 VPN |

## 安全性注意事項

> [!danger] 再說一次：NAT 不是防火牆
> **NAT 只擋「未經請求的外部連線」，完全不管內部連出去的流量。**
>
> 現代攻擊幾乎都是這樣運作的：
> ```
> 使用者點了釣魚連結
>   → 下載惡意程式（對 NAT 而言是正常的對外連線）
>   → 惡意程式主動連回攻擊者的 C&C 伺服器（也是正常的對外連線）
>   → 攻擊者透過這條「內部主動建立」的通道進來
> ```
>
> **NAT 全程沒有攔到任何一步。**
>
> 你需要的是：
> | 防護 | 做什麼 |
> | --- | --- |
> | **出向防火牆規則** | 限制哪些機器可以連到哪裡（伺服器不該能連任意外網） |
> | **DNS 過濾** | 阻擋已知的惡意網域 |
> | **端點防護（EDR）** | 偵測異常行為 |
> | **網路分段** | 一台中招不會波及全網 |
> | **日誌與監控** | 發現異常的對外連線 |

> [!warning] 埠轉發的安全檢查清單
> 每開一個埠轉發，都要問自己：
> 1. **這個服務真的需要對全世界開放嗎？** 能不能改走 VPN？
> 2. 服務本身**有沒有做好加固**（強密碼、MFA、最新版本）？
> 3. 能不能**限制來源 IP**？
> 4. 有沒有**日誌與告警**？
> 5. 有沒有**登記在文件裡**？（半年後你還記得為什麼開這個埠嗎）
>
> **絕對不要對外開放的埠**：
> ```
> 22   SSH（除非有嚴格加固 + 金鑰認證 + Fail2ban）
> 23   Telnet（明文，絕對不要）
> 445  SMB（勒索軟體最愛）
> 3306 MySQL
> 3389 遠端桌面（全世界都在掃）
> 5432 PostgreSQL
> 5900 VNC
> 6379 Redis（歷史上大量未授權存取事件）
> 27017 MongoDB
> ```

> [!tip] 更好的替代方案：不開埠
> | 方案 | 說明 |
> | --- | --- |
> | **VPN** | 先驗證身分才進得來，所有服務都受保護 |
> | **Zero Trust 網路存取（ZTNA）** | 每次存取都驗證，比 VPN 更細緻 |
> | **反向隧道** | Cloudflare Tunnel、Tailscale —— **內部主動連出去**，不用開任何埠 |
> | **跳板機（Bastion）** | 只開一台加固過的機器，其他從它進去 |
>
> **機關的建議做法**：對外服務放 DMZ，
> 管理存取一律走 VPN，不對外開管理埠。

> [!warning] NAT 讓稽核與追查變困難
> 200 台機器共用一個公有 IP 時，
> 如果收到「你們的 IP 在攻擊別人」的通報，
> **你怎麼知道是哪一台？**
>
> **必須保留 NAT 日誌**（記錄「什麼時間、哪個內部 IP、
> 對應到哪個對外埠、連到哪裡」）。
>
> 依《資通安全管理法》與相關規範，
> **連線紀錄需保存一定期間**，NAT 對應紀錄是其中關鍵的一環。
>
> ```bash
> # iptables 記錄 NAT 連線
> iptables -t nat -A POSTROUTING -o eth0 -j LOG --log-prefix "NAT: " --log-level 6
> ```
> 但這個量非常大，**實務上通常用專門的設備或 NetFlow/IPFIX 收集**。
> 見 [[090-05-09-guide-資安設備-日誌集中與SIEM]]。

## 速查表

### NAT 類型

| 類型 | 改什麼 | 用途 |
| --- | --- | --- |
| **SNAT** | 來源 IP | 內部上網（固定對外 IP） |
| **MASQUERADE** | 來源 IP | 內部上網（對外 IP 會變） |
| **DNAT** | 目的 IP | **埠轉發**（讓外部連進來） |
| **PAT/NAPT** | 來源 IP + 埠 | 多對一（**最常見**） |

### 私有 IP 範圍

```
10.0.0.0/8        10.0.0.0    ～ 10.255.255.255
172.16.0.0/12     172.16.0.0  ～ 172.31.255.255
192.168.0.0/16    192.168.0.0 ～ 192.168.255.255
100.64.0.0/10     ← CGNAT 專用
```

### NAT 不做的事

| ❌ NAT **不會** |
| --- |
| 檢查封包內容 |
| 擋內部主動連出去的惡意流量 |
| 防止惡意程式回連 C&C |
| 防止釣魚與惡意下載 |
| 管內部機器之間的攻擊 |

### 不該對外開放的埠

```
23(Telnet)  445(SMB)  3306(MySQL)  3389(RDP)
5432(PostgreSQL)  5900(VNC)  6379(Redis)  27017(MongoDB)
```

### 常用指令

| 目的 | 指令 |
| --- | --- |
| 看 NAT 規則 | `sudo iptables -t nat -L -n -v` |
| 設定 SNAT | `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE` |
| 設定埠轉發 | `iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 內部IP:80` |
| 啟用轉送 | `sysctl -w net.ipv4.ip_forward=1` |
| **看 NAT 連線表** | `sudo conntrack -L` |
| 看連線數 | `sudo conntrack -C` |
| 看連線上限 | `cat /proc/sys/net/netfilter/nf_conntrack_max` |
| 查對外 IP | `curl -s ifconfig.me` |
| 儲存規則 | `sudo netfilter-persistent save` |

## 練習題

> [!question]- 練習 1：檢查你的 NAT 層級
> ```bash
> # 你的內部 IP
> ip route get 8.8.8.8 | grep -oP 'src \K\S+'
>
> # 網際網路看到的 IP
> curl -s ifconfig.me
> ```
> 1. 兩者相同嗎？
> 2. 登入你的路由器看 WAN 口 IP，它與 `ifconfig.me` 相同嗎？
> 3. 如果 WAN 口 IP 在 `100.64.x.x` 範圍 → 你在 CGNAT 後面
>
> 想想：如果你要在家架一台伺服器讓外面連進來，會遇到什麼問題？

> [!question]- 練習 2：觀察 NAT 轉換表
> ```bash
> # 需要 root
> sudo apt install conntrack
> sudo conntrack -L | head -10
> sudo conntrack -C     # 目前連線數
> cat /proc/sys/net/netfilter/nf_conntrack_max   # 上限
> ```
> 回答：
> 1. 目前有多少條連線？佔上限的百分之幾？
> 2. 從輸出中找出一條，指出「原始」與「轉換後」的位址各是什麼
> 3. 如果有人在跑 BT，這個數字會怎樣？

> [!question]- 練習 3：判斷該不該開埠轉發
> 四個情境，判斷該用埠轉發還是其他方案：
> 1. 內部的網站要讓民眾瀏覽
> 2. 資訊人員要從家裡管理伺服器
> 3. 廠商要遠端維護一台設備，為期兩週
> 4. 同仁要在外面存取內部檔案伺服器
>
> 參考答案：
> 1. **埠轉發（443）是合理的**，但應放 DMZ、前面加 WAF、
>    網站本身要加固
> 2. **不要開埠，走 VPN**。開 22 或 3389 到網際網路是高風險
> 3. **臨時 VPN 帳號 + 限制存取範圍 + 到期自動停用 + 全程記錄**。
>    絕對不要為此開埠轉發
> 4. **VPN**。檔案伺服器（445）絕對不能對外開放

## 小測驗

Q1. 用「公司總機」的比喻說明 NAT 在做什麼。分機、總機號碼、通話記錄本各對應什麼？

Q2. 為什麼精確的名稱應該是 PAT/NAPT 而不是 NAT？「埠號」在其中扮演什麼角色？

Q3. SNAT、DNAT、MASQUERADE 各在什麼情況下使用？

Q4. 「埠轉發」在技術上屬於哪一種 NAT？設定前該確認哪四件事？

Q5. 請說出至少五個「絕對不該對外開放埠轉發」的服務與埠號。

Q6. 為什麼說「NAT 不是防火牆」？請描述一個 NAT 完全擋不住的典型攻擊流程。

Q7. UPnP 為什麼有資安風險？機關環境該怎麼處理？

Q8. FTP 在 NAT 後面為什麼常出問題？怎麼解決？

Q9. 什麼是 CGNAT？為什麼它讓埠轉發完全失效？怎麼判斷自己在不在 CGNAT 後面？

Q10. conntrack 表爆滿會有什麼症狀？三個常見原因是什麼？該怎麼處理與預防？

> [!question]- 測驗答案
> **Q1.** 公司對外只有一個總機號碼，但內部有很多分機。
> 員工打出去時，對方看到的是**總機號碼**，總機記下「這通是分機 105 打的」；
> 對方回撥時，總機查記錄轉接給分機 105。
> **分機 = 私有 IP**；**總機號碼 = 公有 IP**；
> **通話記錄本 = NAT 轉換表**；**總機小姐 = 執行 NAT 的路由器**。
>
> **Q2.** 因為單靠 IP 無法區分 —— 200 台機器都轉成同一個公有 IP，
> 回應封包回來時分不出該給誰。
> **埠號是 NAT 能運作的關鍵**：每一條連線分配一個不同的**對外埠號**，
> 回來時靠埠號查表還原。
> 因為同時改了 IP **與埠**，所以精確名稱是
> **PAT（Port Address Translation）**或 **NAPT**。
>
> **Q3.** **SNAT**（改來源 IP）用於內部上網且**對外 IP 固定**時；
> **MASQUERADE**（SNAT 的一種）用於內部上網但**對外 IP 會變動**時
> （DHCP、PPPoE 撥接）；
> **DNAT**（改目的 IP）用於**埠轉發**，讓外部主動連進內部服務。
>
> **Q4.** 埠轉發屬於 **DNAT（Destination NAT）**。
> 設定前要確認：
> ①**這個服務真的需要對全世界開放嗎**（能不能改走 VPN）；
> ②服務本身**有沒有做好加固**（強密碼、MFA、最新版本）；
> ③能不能**限制來源 IP**；
> ④有沒有**日誌與告警**（另加：有沒有登記在文件裡）。
>
> **Q5.** 任五個：**23（Telnet，明文）**、**445（SMB，勒索軟體最愛）**、
> **3306（MySQL）**、**3389（遠端桌面，全世界都在掃）**、
> **5432（PostgreSQL）**、**5900（VNC）**、
> **6379（Redis，大量未授權存取事件）**、**27017（MongoDB）**。
> （22/SSH 除非有嚴格加固 + 金鑰認證 + Fail2ban，否則也不建議。）
>
> **Q6.** 因為 **NAT 只擋「未經請求的外部連線」，
> 完全不管內部主動連出去的流量**。
> 典型攻擊流程：
> ①使用者點了釣魚連結 →
> ②下載惡意程式（**對 NAT 而言是正常的對外連線**）→
> ③惡意程式**主動連回攻擊者的 C&C 伺服器**（也是正常的對外連線）→
> ④攻擊者透過這條「內部主動建立」的通道進來。
> **NAT 全程沒有攔到任何一步。**
>
> **Q7.** **UPnP 讓區網內任何程式都能自己叫路由器開埠，
> 完全不需要驗證**。
> 惡意程式可以自己開一個埠讓外面連進來，
> 而使用者完全不知道有哪些埠被打開了。
> **機關與企業環境應一律關閉 UPnP**，
> 需要開埠時走正式的變更申請流程。
>
> **Q8.** 因為 FTP 的**主動模式（Active Mode）**中，
> **資料連線是伺服器主動連回客戶端** ——
> 在 NAT 後面，伺服器根本連不進來，造成列目錄卡住、傳檔失敗。
> **解法**：改用**被動模式（Passive Mode）**，讓客戶端主動連伺服器；
> 或**改用 SFTP**（走 SSH，只需單一埠 22）。
>
> **Q9.** **CGNAT（Carrier-Grade NAT）** 是 ISP **在他們那一層再做一次 NAT**，
> 讓好幾百個用戶共用同一個公有 IP。
> 埠轉發失效是因為**封包根本到不了你家路由器** ——
> 你只控制得了自家那一層 NAT，控制不了 ISP 那一層。
> **判斷方法**：比對路由器 WAN 口的 IP 與 `curl ifconfig.me` 的結果；
> 若 WAN 口 IP 落在 **`100.64.0.0/10`** 或其他私有範圍、
> 且與對外看到的 IP 不同 → 在 CGNAT 後面。
>
> **Q10.** **症狀**：新連線全部被丟棄，
> 「**網路突然完全不通，但 ping 閘道還通**」，
> `dmesg` 出現 `nf_conntrack: table full, dropping packet`。
> **三個常見原因**：①使用者數量成長；
> ②**有人在跑 P2P**（BT 可以開幾千條連線）；
> ③**遭到 DDoS 或大量掃描**（另加：逾時設定太長）。
> **處理**：加大 `net.netfilter.nf_conntrack_max`、
> 縮短 `nf_conntrack_tcp_timeout_established`（預設 5 天太長），
> 並**納入監控告警**（使用率超過 80% 就警告）。
