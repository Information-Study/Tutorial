## 觀念說明

### 核心比喻：網路就是一套郵政系統

| 郵政 | 網路 |
| --- | --- |
| 一封信 | **一個封包（packet）** |
| 信封上的**收件地址** | **目的 IP 位址** |
| 信封上的**寄件地址** | **來源 IP 位址** |
| 信封裡的**信紙內容** | **酬載（payload）** |
| 郵局、轉運站 | **路由器（router）** |
| 郵差 | **交換器（switch）** |
| 「台北市信義路一段 7 號」 | IP 位址 |
| 「總統府」（好記的名字） | **網域名稱（domain name）** |
| 查電話簿把名字換成地址 | **DNS 查詢** |
| 郵局的作業規則 | **通訊協定（protocol）** |

> [!note] 一個關鍵事實：資料是「切開來」寄的
> 你傳一張 5MB 的照片，**不會**整張一次送出去。
>
> 它會被切成幾千個小包裹（每個約 1500 位元組），
> 每個包裹都貼上完整的收件與寄件地址，**各自出發**，
> 到目的地之後再**依編號重新拼回來**。
>
> 這叫 **封包交換（packet switching）**，是網際網路的基石。

### 為什麼要切開來寄？

想像兩種郵政系統：

| | **電路交換**（傳統電話） | **封包交換**（網際網路） |
| --- | --- | --- |
| 做法 | 通話期間**整條線路專屬給你**，沒人能用 | 大家的包裹**共用同一條路**，輪流走 |
| 比喻 | 包下整條高速公路只給你開 | 大家都在同一條路上開車 |
| 優點 | 品質穩定 | **效率極高**，一條線可以服務很多人 |
| 缺點 | **極度浪費**（你沉默時線路也閒著） | 塞車時會變慢 |
| 一段線路斷了 | 通話中斷 | **封包自動改走別條路** |

> [!tip] 網際網路的起源就是為了「斷了還能通」
> 網際網路的前身 **ARPANET**（1960 年代美國國防部研究計畫）
> 的設計目標之一，就是打造一個**部分節點被摧毀後仍能通訊**的網路。
>
> 封包交換正好符合：每個封包都自己帶著完整地址，
> 哪條路通就走哪條，不依賴單一固定線路。
>
> 這個特性至今仍在運作 —— 海底電纜斷了，你的封包會自動繞道。

## 三種「地址」，不要搞混

這是新手最容易混淆的地方。

| | **MAC 位址** | **IP 位址** | **網域名稱** |
| --- | --- | --- | --- |
| 長相 | `00:1A:2B:3C:4D:5E` | `192.168.1.10` | `www.gov.tw` |
| 比喻 | **身分證字號**（燒在網卡上） | **住址**（會隨你搬家而變） | **「總統府」**（好記的名字） |
| 誰指派 | 網卡製造商 | 網路管理員或 DHCP | 網域註冊商 |
| 會不會變 | **幾乎不變** | 換個網路就變 | 你買下來就是你的 |
| 用在哪 | **同一個區域網路內**找機器 | **跨網路**送封包 | 給人記的 |

```mermaid
graph LR
    A["你輸入<br/>www.gov.tw"] -->|DNS 查詢<br/>查電話簿| B["得到 IP<br/>203.x.x.x"]
    B -->|路由<br/>跨網路遞送| C["找到那台伺服器<br/>所在的網路"]
    C -->|ARP + MAC<br/>區網內遞送| D["精準送到<br/>那一台機器"]
```

> [!example] 用郵差送信來理解三者的分工
> 你要寄信給「總統府」：
> 1. **網域名稱 → IP**：查地址簿，知道總統府在「台北市重慶南路一段 122 號」
> 2. **IP → 一路轉送**：郵局依照地址，把信從你這裡送到台北市那個區的郵局
>    （中間可能經過好幾個轉運站，就是**路由器**）
> 3. **MAC → 最後一哩**：當地郵差拿著信，走到那一棟建築，**交到正確的人手上**
>
> 注意：**IP 決定「大方向」，MAC 決定「最後一步」。**
> 這個分工是理解網路最重要的觀念之一。

### 公有 IP 與私有 IP

> [!note] 為什麼你家的 IP 都是 192.168 開頭
> IPv4 位址只有約 **43 億個**（2³²），
> 但全世界的裝置早就超過這個數字。
>
> 解決方法：**大部分裝置用「私有 IP」，只有對外出口用「公有 IP」**。
>
> | | 公有 IP | 私有 IP |
> | --- | --- | --- |
> | 比喻 | **整棟大樓的門牌號碼** | **大樓內部的房號** |
> | 全世界唯一 | ✅ | ❌（每棟大樓都有 3 樓 5 號） |
> | 從外面連得到 | ✅ | ❌ |
> | 誰分配 | 網路管理機構／ISP | 你自己 |
>
> **私有 IP 的三個保留範圍**：
> ```
> 10.0.0.0    ～ 10.255.255.255      （最大，企業常用）
> 172.16.0.0  ～ 172.31.255.255
> 192.168.0.0 ～ 192.168.255.255     （家用最常見）
> ```
>
> 把私有 IP 轉換成公有 IP 出去的技術叫 **NAT** ——
> 就像大樓的總機幫所有住戶對外聯絡。
> 詳見 [[08-網概-NAT與私有位址]]。

## 從你家到全世界，會經過哪些設備

```mermaid
graph LR
    A["你的電腦<br/>192.168.1.10"] -->|網路線或 Wi-Fi| B["分享器 / 路由器<br/>192.168.1.1<br/>對外：203.x.x.x"]
    B --> C["數據機<br/>小烏龜"]
    C --> D["ISP 機房<br/>中華電信等"]
    D --> E["國際骨幹<br/>海底電纜"]
    E --> F["目標網站的<br/>伺服器"]
```

| 設備 | 做什麼 | 白話 |
| --- | --- | --- |
| **網路卡（NIC）** | 電腦的網路出入口 | 你家的信箱 |
| **交換器（Switch）** | 在**同一個區域網路內**轉送資料 | 社區的郵差 |
| **路由器（Router）** | 在**不同網路之間**轉送資料 | 郵局轉運站 |
| **數據機（Modem，小烏龜）** | 轉換訊號格式（光訊號 ↔ 網路訊號） | 翻譯機 |
| **無線基地台（AP）** | 把有線網路變成 Wi-Fi | 無線電廣播站 |
| **ISP** | 提供上網服務的業者 | 郵政總局 |

> [!tip] 家用「分享器」其實是三合一
> 你家那台小盒子通常同時是：
> - **路由器**（連接你家網路與網際網路）
> - **交換器**（讓家裡的裝置互通）
> - **無線基地台**（提供 Wi-Fi）
> - 有時還是**數據機**與**防火牆**
>
> 這就是為什麼設定它的介面上有那麼多選項。
> 在企業與機關，這些功能通常是**分開的獨立設備**，
> 因為每一項都需要更專業的功能與更高的效能。

### ISP 的三層結構

> [!note] 網際網路不是一個中央機構，而是「網路的網路」
> 沒有人「擁有」網際網路。它是**成千上萬個網路互相連接**而成。
>
> | 層級 | 說明 | 台灣的例子 |
> | --- | --- | --- |
> | **Tier 1** | 全球骨幹業者，彼此對等互連，不用付費給任何人 | 中華電信（國際部分） |
> | **Tier 2** | 區域性業者，向 Tier 1 購買頻寬 | 台灣大哥大、遠傳 |
> | **Access ISP** | 最後一哩，直接服務家庭與企業 | 各家的接取服務 |
>
> 你的封包從家裡出發，可能一路往上爬到 Tier 1，
> 跨過太平洋，再往下走到對方的 Access ISP，最後到達目標伺服器。
> 這整趟通常在 **0.1 秒內**完成。

### 常見的上網方式

| 方式 | 原理 | 速度 | 現況 |
| --- | --- | --- | --- |
| **ADSL** | 走電話銅線 | 慢（上下行不對稱） | 逐步淘汰 |
| **Cable** | 走有線電視同軸電纜 | 中 | 部分地區 |
| **光纖（FTTx）** | 光訊號 | **快** | **主流** |
| **行動網路（4G/5G）** | 無線基地台 | 中～快 | 行動與備援 |
| 專線 | 專屬線路，速率保證 | 依合約 | 企業／機關 |

> [!warning] 「300M」是下行還是上行？
> 家用方案通常是**非對稱**的：
> ```
> 300M/100M  ← 下載 300 Mbps、上傳只有 100 Mbps
> ```
>
> **如果你要架伺服器、開 VPN、做視訊會議主持端，上行才是關鍵。**
> 機關與企業應該選**對稱**線路（上下行相同），
> 或至少確認上行足夠。
>
> 換算實際速度：**Mbps ÷ 8 ≈ MB/s**
> （300 Mbps ≈ 37.5 MB/s，實務上約 30 MB/s）。
> 見 [[03-計概-0與1和資料單位]]。

## 完整實戰範例：你打開網頁的那十秒

現在把所有東西串起來。假設你在瀏覽器輸入 `www.gov.tw` 並按下 Enter。

### 第 1 步：查地址（DNS）

```
你的電腦：「www.gov.tw 的 IP 是多少？」
    ↓ 問 DNS 伺服器（通常是分享器或 ISP 提供的）
DNS：「是 203.x.x.x」
```

就像**查電話簿**：你只記得「總統府」，但郵局需要地址。

> [!tip] 這一步失敗會怎樣
> 瀏覽器會顯示「找不到伺服器」「DNS_PROBE_FINISHED_NXDOMAIN」。
> 這代表**網路可能是通的，只是查不到名字**。
> 測試方法：直接用 IP 連連看，或 `ping 8.8.8.8`（Google 的公用 DNS）。

### 第 2 步：包裝成封包

```
[目的 IP: 203.x.x.x][來源 IP: 192.168.1.10][目的埠: 443][我要看首頁...]
```

**埠號（port）** 是什麼？如果 IP 是「大樓地址」，
**埠號就是「幾樓幾號房」** —— 它告訴對方這封信要交給哪個服務。

| 埠 | 服務 |
| --- | --- |
| 80 | HTTP（網頁，未加密） |
| **443** | **HTTPS（網頁，加密）** |
| 22 | SSH（遠端管理） |
| 53 | DNS |
| 25 / 587 | 郵件寄送 |

### 第 3 步：交給分享器

你的電腦看到目的地不在自己的網段（192.168.1.x），
就把封包交給**預設閘道（default gateway）** —— 也就是分享器。

> [!note] 預設閘道 = 「不知道怎麼走就交給他」
> 就像你要寄一封到國外的信，
> 你不需要知道怎麼送到巴黎，只要投進**郵筒**就好。
> 預設閘道就是那個郵筒。

### 第 4 步：NAT 轉換

分享器把你的私有 IP 換成它的公有 IP，
並記下「這個回應要轉回給 192.168.1.10」。

### 第 5 步：一路轉送（路由）

封包經過 ISP、國內骨幹、可能還有海底電纜，
每一台路由器都看一眼目的地，決定「往哪個方向丟」。

```bash
# 用 traceroute 親眼看到這段旅程
$ traceroute www.gov.tw
 1  192.168.1.1        1.2 ms      ← 你家分享器
 2  10.x.x.x           8.5 ms      ← ISP 第一跳
 3  168.95.x.x        12.3 ms      ← 中華電信骨幹
 ...
 8  203.x.x.x         25.6 ms      ← 到達目的地
```

### 第 6 步：建立連線與加密（TCP + TLS）

到達之後，雙方先「握手」確認彼此都在，
然後交換金鑰建立加密通道 —— 這就是網址列那把**鎖**的來源。

### 第 7 步：伺服器回應

伺服器把網頁內容切成封包送回來，
沿著相反的路徑回到你的瀏覽器，瀏覽器把它畫成你看到的畫面。

> [!tip] 整段過程通常在 0.5 秒內完成
> 而且**每一張圖片、每一個 CSS 檔案、每一段 JavaScript 都要重複一次**。
> 一個現代網頁可能要發出 50～200 個這樣的請求。
>
> 這就是為什麼網站效能最佳化這麼重要 ——
> 見 [[14-網概-一個網頁請求的完整旅程]]。

## 三個一定要會的排錯指令

### 一、看自己的網路設定

```bash
# Linux
$ ip address show
$ ip route show                # 看預設閘道

# 簡化版
$ hostname -I                  # 只顯示 IP
```

```powershell
# Windows
ipconfig /all
```

**要確認四件事**：
1. **IP 位址**有沒有拿到？（`169.254.x.x` 代表**沒拿到**，DHCP 失敗）
2. **子網路遮罩**對不對？
3. **預設閘道**有沒有設定？
4. **DNS 伺服器**有沒有設定？

### 二、ping：測試連通性

`ping` 送一個小封包過去問「你在嗎」，看對方回不回應。

> [!tip] ping 的標準排查順序（由內而外）
> **這是網路排錯的黃金流程，請記起來：**
>
> ```bash
> ping 127.0.0.1          # 1. 測自己的 TCP/IP 軟體有沒有壞
> ping 192.168.1.10       # 2. 測自己的網路卡（自己的 IP）
> ping 192.168.1.1        # 3. 測到分享器／閘道通不通
> ping 8.8.8.8            # 4. 測對外網路通不通（用 IP，避開 DNS）
> ping www.google.com     # 5. 測 DNS 解析正不正常
> ```
>
> **哪一步開始失敗，問題就在那裡：**
>
> | 從哪步開始失敗 | 問題在哪 |
> | --- | --- |
> | 第 1 步就失敗 | 作業系統的網路軟體有問題（極罕見） |
> | 第 2 步失敗 | **網路卡或驅動程式**有問題 |
> | 第 3 步失敗 | **網路線、交換器、或 IP 設定錯誤** |
> | 第 4 步失敗 | **對外連線有問題**（ISP、分享器、防火牆） |
> | **只有第 5 步失敗** | **DNS 有問題**（網路是通的！） |
>
> 這五步能在一分鐘內把問題範圍縮到很小，
> 遠比「重開機試試看」有效率。

```bash
$ ping -c 4 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=8.42 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=118 time=8.31 ms
--- 8.8.8.8 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss
                                   ^^^^^^^^^^^^^^^
                                   這是重點：有沒有掉封包
```

| 看什麼 | 意義 |
| --- | --- |
| `time=8.42 ms` | **延遲**。國內應 < 20ms，國外 100～300ms |
| `packet loss` | **掉封包率**。應該是 **0%**，超過 1% 就有問題 |
| `Request timeout` | 完全不通，或對方擋掉了 ICMP |

> [!warning] ping 不通不一定代表壞掉
> 很多伺服器與防火牆**刻意封鎖 ICMP**（ping 用的協定），
> 這是常見的資安設定。
>
> 所以「ping 不通」可能是：
> - 真的不通
> - **對方故意不回應**
>
> 這時改用測試特定服務的方式：
> ```bash
> curl -I https://www.example.com     # 測 HTTPS
> nc -zv example.com 443              # 測某個埠通不通
> ```

### 三、nslookup：測試 DNS

```bash
$ nslookup www.gov.tw
Server:         192.168.1.1          ← 用哪台 DNS 查的
Address:        192.168.1.1#53

Non-authoritative answer:
Name:   www.gov.tw
Address: 203.x.x.x                   ← 查到的 IP

# 指定用 Google 的 DNS 查（排除自家 DNS 的問題）
$ nslookup www.gov.tw 8.8.8.8
```

> [!tip] 「網頁打不開但 LINE 可以用」的典型診斷
> LINE 通得表示**網路實體連線正常**，
> 問題八成在 **DNS**（因為 LINE 可能有自己的連線機制或快取）。
>
> ```bash
> ping 8.8.8.8            # 通 → 網路 OK
> nslookup www.google.com # 失敗 → 確認是 DNS 問題
> ```
> **解法**：把 DNS 改成 `8.8.8.8`（Google）或 `1.1.1.1`（Cloudflare）試試，
> 或清除 DNS 快取（Windows：`ipconfig /flushdns`）。

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| IP 顯示 `169.254.x.x` | **沒有從 DHCP 拿到 IP** | 檢查網路線、交換器；重新取得 IP（`dhclient -r && dhclient`／`ipconfig /renew`） |
| 有 IP 但上不了網 | 沒有預設閘道，或閘道不通 | `ip route` 確認閘道；`ping` 閘道 |
| 網頁打不開但 LINE 可以 | **DNS 問題** | `nslookup` 確認；換成 8.8.8.8 試試 |
| 打不開特定網站 | DNS 快取、該站故障、或被防火牆擋 | `ipconfig /flushdns`；用手機網路測試比對 |
| 網速比合約慢很多 | 混淆 Mbps 與 MB/s | Mbps ÷ 8 ≈ MB/s；300M ≈ 30MB/s 是正常的 |
| Wi-Fi 訊號滿格但很慢 | 訊號強度 ≠ 頻寬；可能是通道干擾或人太多 | 換通道、換 5GHz、或改用有線 |
| ping 不通但網頁打得開 | 對方**刻意封鎖 ICMP** | 改用 `curl -I` 或 `nc -zv` 測試特定埠 |
| 兩台電腦 IP 一樣 | **IP 衝突**（有人設了固定 IP 跟 DHCP 撞到） | 改用 DHCP，或在 DHCP 設定中保留該 IP |
| 換了網路環境就上不了網 | 設了固定 IP，換環境後網段不符 | 改回自動取得（DHCP） |
| 上傳檔案超慢但下載很快 | 家用線路**上下行不對稱** | 確認合約的上行速率；企業應用要選對稱線路 |

## 安全性注意事項

> [!danger] 公共 Wi-Fi 的風險
> 在咖啡廳、機場、飯店連上免費 Wi-Fi 時：
> - **同一個網路上的其他人可能監聽你的流量**
> - 可能有人架設**假的 Wi-Fi 熱點**（名字取得跟真的一樣），
>   讓你連上去之後看光你的所有連線
>
> **自保做法**：
> 1. **只用 HTTPS 網站**（網址列有鎖頭）。HTTPS 的內容是加密的，
>    別人看得到你連了哪個網站，但看不到內容
> 2. **重要操作（網銀、公務系統）不要在公共 Wi-Fi 上做**
> 3. 使用 **VPN** 把所有流量加密
> 4. 關閉「自動連接開放網路」
> 5. 公務筆電應由機關統一設定 VPN 政策

> [!warning] 家用分享器是被忽略的資安風險
> 你家或辦公室那台分享器，常常：
> - 用**原廠預設密碼**（`admin`/`admin`）
> - 韌體從買來就**沒更新過**
> - **開啟了 WAN 端的遠端管理**（等於把管理介面暴露在網際網路上）
>
> 被入侵的分享器可以：
> - **竄改 DNS 設定**，把你導向假網站（釣魚）
> - 監看所有流量
> - 成為殭屍網路的一員
>
> **必做的五件事**：
> 1. **改掉預設管理密碼**
> 2. **關閉 WAN 遠端管理**（除非真的需要且有做好防護）
> 3. **定期更新韌體**
> 4. Wi-Fi 用 **WPA3**（或至少 WPA2），密碼要夠長
> 5. 關閉 **WPS**（那個一鍵連線按鈕，有已知的安全問題）

> [!tip] 認出網址列的鎖頭是什麼意思
> **有鎖頭（HTTPS）代表**：
> - ✅ 你與網站之間的**連線是加密的**
> - ✅ 你連到的**確實是這個網域**（憑證驗證過）
>
> **不代表**：
> - ❌ 這個網站是**善良的**
>
> **釣魚網站也可以有 HTTPS。** 免費憑證人人可申請。
> `https://gov-tw-login.xyz` 可能有完美的鎖頭，但它不是政府網站。
>
> **關鍵是看網域名稱本身**，不是只看鎖頭。
> 見 [[13-網概-HTTP與HTTPS]] 與 [[18-計概-資訊安全初步]]。

## 速查表

### 三種地址

| 名稱 | 長相 | 比喻 | 範圍 |
| --- | --- | --- | --- |
| MAC | `00:1A:2B:3C:4D:5E` | 身分證 | 同一區網 |
| IP | `192.168.1.10` | 住址 | 跨網路 |
| 網域名稱 | `www.gov.tw` | 「總統府」 | 給人記的 |

### 私有 IP 範圍

```
10.0.0.0    ～ 10.255.255.255
172.16.0.0  ～ 172.31.255.255
192.168.0.0 ～ 192.168.255.255
```

### 常見埠號

| 埠 | 服務 |
| --- | --- |
| 22 | SSH |
| 53 | DNS |
| 80 | HTTP |
| **443** | **HTTPS** |
| 3389 | 遠端桌面 |

### 排錯五步驟（背起來）

```bash
ping 127.0.0.1        # 1. 自己的網路軟體
ping 自己的IP          # 2. 網路卡
ping 閘道IP            # 3. 到分享器
ping 8.8.8.8          # 4. 對外網路
ping www.google.com   # 5. DNS
```

### 常用指令

| 目的 | Linux | Windows |
| --- | --- | --- |
| 看 IP 設定 | `ip a`、`ip route` | `ipconfig /all` |
| 測連通 | `ping -c 4 目標` | `ping 目標` |
| 追蹤路徑 | `traceroute 目標` | `tracert 目標` |
| 測 DNS | `nslookup 網域`、`dig 網域` | `nslookup 網域` |
| 清 DNS 快取 | `resolvectl flush-caches` | `ipconfig /flushdns` |
| 重新取得 IP | `sudo dhclient -r && sudo dhclient` | `ipconfig /release` + `/renew` |
| 測特定埠 | `nc -zv 主機 443` | `Test-NetConnection 主機 -Port 443` |

## 練習題

> [!question]- 練習 1：認識你的網路環境
> 執行 `ipconfig /all`（Windows）或 `ip a && ip route`（Linux），記下：
> 1. 你的 IP 位址是多少？是私有 IP 嗎？（看是不是 10./172.16-31./192.168. 開頭）
> 2. 預設閘道是多少？
> 3. DNS 伺服器是哪一台？
> 4. 你的 MAC 位址是多少？前三組（OUI）代表網卡製造商，
>    可以到 <https://maclookup.app> 查查看是哪一家。

> [!question]- 練習 2：跑一次五步驟排錯
> 依序執行五個 ping，全部都應該成功。
> 然後**故意製造問題**來觀察：
> 1. 把 DNS 改成一個不存在的位址（如 `192.168.99.99`）
> 2. 再跑一次五步驟 → 你會看到**只有第 5 步失敗**
> 3. 改回來
>
> 這個實驗會讓你對「DNS 壞掉長什麼樣」有實感。

> [!question]- 練習 3：追蹤一個封包的旅程
> ```bash
> # Linux
> traceroute www.google.com
> # Windows
> tracert www.google.com
> ```
> 回答：
> 1. 總共經過幾跳（hop）？
> 2. 第一跳是誰？（應該是你的分享器）
> 3. 從哪一跳開始延遲明顯變高？（那通常是跨海的那一段）
> 4. 再 traceroute 一個國內網站（如 `www.gov.tw`），比較跳數與延遲

## 小測驗

Q1. 用郵政系統的比喻，說出封包、IP 位址、路由器、DNS 分別對應什麼。

Q2. 為什麼傳一張 5MB 的照片不是「整張一次送出去」？這個機制叫什麼？

Q3. 電路交換與封包交換的差別是什麼？網際網路為什麼選了封包交換？

Q4. MAC 位址、IP 位址、網域名稱三者的分工是什麼？「IP 決定大方向，MAC 決定最後一步」是什麼意思？

Q5. 為什麼你家的 IP 都是 192.168 開頭？私有 IP 的三個保留範圍是什麼？

Q6. 家用「分享器」其實同時扮演哪幾種角色？

Q7. 「300M/100M」的光纖方案是什麼意思？什麼情況下上行才是關鍵？

Q8. 請寫出網路排錯的五個 ping 步驟，並說明「只有第 5 步失敗」代表什麼。

Q9. ping 不通就一定代表網路壞掉嗎？為什麼？該怎麼改測？

Q10. 網址列有鎖頭（HTTPS）代表什麼？**不**代表什麼？

> [!question]- 測驗答案
> **Q1.** **封包 = 一封信**；**IP 位址 = 信封上的收件／寄件地址**；
> **路由器 = 郵局與轉運站**；**DNS = 查電話簿，把「總統府」這個名字換成實際地址**。
> （另外：交換器 = 郵差；通訊協定 = 郵局的作業規則。）
>
> **Q2.** 因為資料會被**切成幾千個小包裹**（每個約 1500 位元組），
> 每個包裹都貼上完整的收件與寄件地址、**各自出發**，
> 到目的地後再依編號重新拼回來。
> 這個機制叫 **封包交換（packet switching）**。
>
> **Q3.** **電路交換**（傳統電話）在通話期間**整條線路專屬給你**，
> 品質穩定但**極度浪費**（你沉默時線路也閒著），且線路斷了通話就中斷；
> **封包交換**讓大家共用線路輪流走，**效率極高**，
> 而且**一段路斷了封包會自動改走別條路**。
> 網際網路的前身 ARPANET 的設計目標就是「部分節點被摧毀後仍能通訊」，
> 封包交換正好符合。
>
> **Q4.** **網域名稱**是給人記的好名字；
> **IP 位址**用來**跨網路**把封包送到正確的網段；
> **MAC 位址**用來在**同一個區域網路內**找到正確的那一台機器。
> 「IP 決定大方向，MAC 決定最後一步」意思是：
> IP 像地址，讓郵局把信送到正確的區域；
> MAC 像收件人姓名，讓當地郵差**交到正確的人手上**。
>
> **Q5.** 因為 IPv4 位址只有約 **43 億個**，不夠全世界的裝置用。
> 解法是**大部分裝置用「私有 IP」，只有對外出口用「公有 IP」**，
> 中間用 NAT 轉換（像大樓的總機幫所有住戶對外聯絡）。
> **三個保留範圍**：
> `10.0.0.0～10.255.255.255`、`172.16.0.0～172.31.255.255`、
> `192.168.0.0～192.168.255.255`。
>
> **Q6.** 通常同時是：**路由器**（連接家用網路與網際網路）、
> **交換器**（讓家中裝置互通）、**無線基地台**（提供 Wi-Fi），
> 有時還是**數據機**與**防火牆**。
> 在企業與機關，這些功能通常是**分開的獨立設備**。
>
> **Q7.** 代表**下載 300 Mbps、上傳只有 100 Mbps**（非對稱）。
> **上行是關鍵的情況**：架設對外伺服器、開 VPN 讓外面連進來、
> 擔任視訊會議的主持端、上傳大量檔案到雲端。
> 機關與企業應選**對稱**線路。
>
> **Q8.** ①`ping 127.0.0.1`（自己的 TCP/IP 軟體）→
> ②`ping 自己的 IP`（網路卡）→ ③`ping 閘道 IP`（到分享器）→
> ④`ping 8.8.8.8`（對外網路，用 IP 避開 DNS）→
> ⑤`ping www.google.com`（DNS 解析）。
> **只有第 5 步失敗**代表**網路完全是通的，問題純粹在 DNS**。
>
> **Q9.** **不一定。** 很多伺服器與防火牆會**刻意封鎖 ICMP**（ping 用的協定），
> 這是常見的資安設定。
> 所以 ping 不通可能是「真的不通」，也可能是「對方故意不回應」。
> 改測方式：`curl -I https://網站` 測 HTTPS，
> 或 `nc -zv 主機 443`／`Test-NetConnection 主機 -Port 443` 測特定埠是否開放。
>
> **Q10.** **代表**：①你與網站之間的**連線是加密的**；
> ②你連到的**確實是這個網域**（憑證驗證過）。
> **不代表**：**這個網站是善良的**。
> 釣魚網站也可以申請免費憑證取得完美的鎖頭 ——
> `https://gov-tw-login.xyz` 有鎖頭但不是政府網站。
> **關鍵是看網域名稱本身，不是只看鎖頭。**
