# 電腦規格與選購

> [!abstract] 這篇你會學到
> - 一行一行看懂規格表，知道每個數字代表什麼
> - 依**用途**決定哪個零件該花錢、哪個可以省
> - 判斷一台舊電腦「該升級哪個零件最有感」
> - 避開常見的行銷話術與規格陷阱
> - 機關與企業採購時該注意的額外事項（保固、TCO、規格書撰寫）

## 觀念說明

### 核心原則：瓶頸決定體感

> [!example] 用「水桶理論」來理解
> 一個木桶能裝多少水，**取決於最短的那塊木板**，
> 不是最長的那塊。
>
> 電腦也一樣。一台配了頂級 CPU 但只有 8GB 記憶體、
> 還在用傳統硬碟的電腦，**體感會比配置均衡的中階機器差很多**。
>
> **買電腦的目標不是把某一項堆到最高，而是把每一塊木板拉到夠高。**

### 第一步永遠是：先問「要做什麼」

| 用途 | 最該花錢的 | 可以省的 |
| --- | --- | --- |
| **文書、上網、公務系統** | **SSD、記憶體 16GB** | CPU 中階即可、不需獨顯 |
| 影片剪輯 | CPU 多核 + 記憶體 32GB+ + 快速 SSD + **獨顯** | — |
| 平面設計 | 記憶體 + 螢幕色準 + SSD | CPU 中階即可 |
| 遊戲 | **獨顯** + CPU 單核效能 | 記憶體 16GB 夠 |
| 程式開發 | 記憶體 32GB + SSD + CPU 多核 | 獨顯（除非做 AI） |
| **跑本地 AI／LLM** | **顯示卡 VRAM**（最關鍵） | — |
| **虛擬化主機** | **記憶體 + 核心數** | 顯示卡 |
| **資料庫伺服器** | 記憶體 + **NVMe SSD + RAID 10** | 顯示卡 |
| **檔案伺服器／NAS** | **大容量硬碟 + ECC 記憶體** | CPU 中低階即可 |

> [!warning] 最常見的採購錯誤
> **買了 i7 的 CPU，卻只配 8GB 記憶體與傳統硬碟。**
>
> 這台機器的體感會比「i5 + 16GB + SSD」差很多，
> 但價格可能還比較貴。
>
> **順序永遠是：SSD > 記憶體 > CPU > 顯卡**（對一般辦公用途）。

## 逐項規格解讀

### CPU

```
Intel Core i5-14400    2.5 GHz    10 核心 (6P+4E) / 16 執行緒    65W
      │    │      │       │              │                        └ TDP
      │    │      │       │              └ 核心與執行緒
      │    │      │       └ 基礎時脈
      │    │      └ 型號（數字越大通常越強）
      │    └ 等級
      └ 品牌
```

**Intel 的命名**：

| 等級 | 定位 |
| --- | --- |
| Celeron / Pentium / **Intel Processor** | 入門，效能有限 |
| **Core i3** | 基本文書 |
| **Core i5** | **辦公主力，CP 值最高** |
| Core i7 | 進階應用 |
| Core i9 | 高階工作站 |
| **Xeon** | **伺服器**（支援 ECC、多路） |

**AMD 的命名**：

| 等級 | 對應 |
| --- | --- |
| Athlon | 入門 |
| **Ryzen 3 / 5 / 7 / 9** | 大致對應 i3 / i5 / i7 / i9 |
| **EPYC** | **伺服器** |
| Ryzen Pro | 商用（支援 ECC 與管理功能） |

> [!warning] 三個 CPU 規格陷阱
> **一、不同世代不能只比型號數字。**
> 「i5-14400」的 14 是**第 14 代**。
> 一顆第 14 代的 i5，通常比第 8 代的 i7 還快。
> **要比就比同世代，或直接查跑分**（PassMark、Geekbench）。
>
> **二、筆電的後綴決定一切。**
> | 後綴 | 意思 |
> | --- | --- |
> | **U** | 超低功耗，**效能較弱**，續航好 |
> | **P** | 中等功耗 |
> | **H / HX** | **高效能**，通常是遊戲筆電或工作站 |
> | **T** | 桌機的低功耗版本 |
> | **K** | 桌機，可超頻（不鎖倍頻） |
> | **F** | **沒有內顯**，必須配獨立顯卡 |
>
> 「i7-1355U」的效能可能不如「i5-13500H」。
>
> **三、`F` 後綴沒有內顯。**
> 買了 `i5-14400F` 卻沒買顯示卡 → **開機沒有畫面**。
> 這是實際會發生的採購失誤。

### 記憶體

```
32GB (16GB × 2)    DDR5-5600    CL40
  │       │            │          └ 延遲（越小越好）
  │       │            └ 世代與速度
  │       └ 兩條 → 支援雙通道
  └ 總容量
```

| 用途 | 建議容量 |
| --- | --- |
| 純文書、單一應用 | 8 GB（**最低標準，不建議新購**） |
| **一般辦公、多分頁瀏覽** | **16 GB** ✅ |
| 開發、設計、多工 | 32 GB |
| 影片剪輯、虛擬機 | 32～64 GB |
| 虛擬化主機、資料庫 | 64 GB 以上 |

> [!tip] 2026 年的建議是 16GB 起跳
> 現代瀏覽器每個分頁就要 100～300 MB，
> 加上 Teams、防毒、公務系統，8GB 很快就會開始用 swap。
>
> 而且 **16GB 與 8GB 的價差很小，體感差異卻很大** ——
> 這是整台電腦中 CP 值最高的升級。
>
> **買 16GB 請買 8GB × 2** 以啟用雙通道（見 [[06-計概-記憶體與儲存階層]]）。

> [!warning] 筆電要確認「能不能升級」
> 很多輕薄筆電的記憶體是**焊死在主機板上**的，
> 買了就不能加。這種機型**一定要一次買足**。
>
> 採購前確認規格表上有沒有寫「onboard」「soldered」，
> 或有幾個「SO-DIMM 插槽」。

### 儲存

| 類型 | 速度 | 建議 |
| --- | --- | --- |
| **NVMe SSD (PCIe 4.0)** | 3000～7000 MB/s | **系統碟首選** |
| NVMe SSD (PCIe 3.0) | 1500～3500 MB/s | 夠用 |
| SATA SSD | ~550 MB/s | 可接受 |
| **HDD** | 100～200 MB/s | **絕對不要當系統碟** |

> [!danger] 2026 年還用 HDD 當系統碟是不可接受的
> 這是造成「電腦好慢」最主要的原因。
> 開機兩分鐘、開軟體一直轉圈，換 SSD 立刻變 15 秒。
>
> **一顆 500GB 的 SSD 是最便宜、最有感的升級。**
> 機關若還有大量 HDD 系統碟的電腦，
> 換 SSD 的效益遠高於整台換新。

**容量建議**：

| 用途 | 建議 |
| --- | --- |
| 純文書（資料放檔案伺服器） | 256 GB |
| **一般辦公** | **512 GB** ✅ |
| 有大量本機資料 | 1 TB |
| 影片剪輯 | 1TB NVMe（系統+工作）+ 大容量 HDD（素材） |
| 檔案伺服器 | 大容量 HDD + RAID（見 [[07-計概-磁碟格式化與RAID入門]]） |

> [!tip] SSD 不要用到滿
> SSD 剩餘空間少於 **10～20%** 時效能會明顯下降
> （因為耗損平均與垃圾回收需要空間運作）。
> 選購時**留 20～30% 的餘裕**。

### 顯示卡

| 情況 | 建議 |
| --- | --- |
| 文書、上網、公務系統 | **內顯就夠**，不要浪費錢 |
| 雙螢幕、4K 螢幕 | 內顯通常也夠（確認支援的輸出數量與解析度） |
| 影片剪輯、3D | 中階獨顯 |
| 遊戲 | 依目標解析度與畫質選 |
| **本地 AI / LLM** | **看 VRAM 容量**，這是關鍵 |
| 伺服器 | **不需要**（除非跑 AI 或虛擬桌面） |

> [!note] 跑本地 LLM 時，VRAM 才是關鍵
> 模型必須**整個載入顯示卡的記憶體（VRAM）**才跑得快。
> VRAM 不夠就會退回用 CPU 與系統記憶體 —— **慢十倍以上**。
>
> | VRAM | 大約能跑 |
> | --- | --- |
> | 8 GB | 7B 參數（量化後） |
> | 12～16 GB | 13B 參數 |
> | 24 GB | 30B 參數（量化後） |
> | 48 GB+ | 70B 參數 |
>
> **所以買來跑 AI 的顯卡，VRAM 容量比運算速度更重要。**
> 見 `53-AI服務` 章節。

### 螢幕

| 規格 | 說明 | 建議 |
| --- | --- | --- |
| **尺寸** | 對角線英吋 | 辦公 24"、繪圖 27"+ |
| **解析度** | 1920×1080 / 2560×1440 / 3840×2160 | 24" 用 1080p、27" 用 1440p 以上 |
| **面板** | TN / VA / **IPS** / OLED | **辦公用 IPS**（視角廣、色彩準） |
| **更新率** | 60 / 75 / 120 / 144 Hz | 辦公 60Hz 夠、遊戲要高 |
| **接頭** | HDMI / DisplayPort / USB-C | 確認與主機相符 |
| 可調高度 | 有／無 | **對長時間辦公很重要**（人體工學） |

> [!tip] 機關採購最常忽略的一項：螢幕高度可調
> 螢幕太低會造成長期低頭，是頸椎與肩膀問題的主因。
> 支架能調高度的機型只貴一點點，
> 但對每天用八小時的同仁差別很大。
>
> 若已買了不能調的，用**螢幕增高架**也可以。

## 完整實戰範例

### 情境一：機關文書電腦（預算 25,000）

> [!example] 需求
> Office 文書、瀏覽器開 10～20 個分頁、公文系統、視訊會議、雙螢幕。

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| CPU | **Core i5 / Ryzen 5** | 中階足夠。公務系統多為單執行緒，看單核效能 |
| 記憶體 | **16GB (8×2)** | 雙通道；多分頁瀏覽器的實際需求 |
| 儲存 | **512GB NVMe SSD** | 體感最關鍵 |
| 顯卡 | **內顯** | 文書不需要獨顯，還能省電費 |
| 電源 | 450W 80+ Bronze | 沒有獨顯，不需大瓦數 |
| 螢幕 | 24" IPS 1080p **可調高度** × 2 | 雙螢幕對文書效率提升明顯 |
| 作業系統 | Windows 11 Pro | Pro 才能加入網域、用 BitLocker、被 GPO 管理 |

> [!warning] 機關電腦一定要買 Windows **Pro** 版
> **家用版（Home）不能加入 Active Directory 網域**，
> 也不能用 BitLocker 加密、不能被群組原則（GPO）管理。
>
> 這意味著這台電腦**無法納入集中管理與資安政策**，
> 是機關資安的破口。採購規格書務必註明 **Pro 或 Enterprise**。

### 情境二：小型伺服器（跑 Web + 資料庫）

> [!example] 需求
> 內部網站、MySQL 資料庫、約 100 位使用者，7×24 運轉。

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 形式 | **機架式伺服器（1U/2U）** | 進機櫃、有導軌、方便維護 |
| CPU | Xeon 或 EPYC，8～16 核 | 支援 ECC；核心數應付並行請求 |
| 記憶體 | **64GB ECC** | 資料庫吃記憶體；ECC 避免靜默損毀 |
| 儲存 | **2× NVMe SSD RAID 1**（系統+資料庫） | 資料庫要快且要容錯 |
| | + 4× HDD RAID 6（備份/檔案） | 大容量、可壞兩顆 |
| 電源 | **雙電源供應器（備援）** | 壞一顆不用停機 |
| 網路 | 雙 1GbE 或 10GbE，做 bonding | 網路備援 |
| 遠端管理 | **iDRAC / iLO / IPMI** | 不必到機房就能開關機、看畫面 |
| 保固 | **原廠 5 年 NBD 到府** | 這是伺服器最重要的一項 |

> [!tip] 伺服器最重要的規格是「保固」不是「效能」
> 一台伺服器故障時，你需要的是**明天就有工程師帶零件到府**，
> 而不是「效能多 10%」。
>
> 常見的保固等級：
> | 等級 | 意思 |
> | --- | --- |
> | NBD（Next Business Day） | **下一個工作日**到府 |
> | 4-hour / 8-hour | 4 或 8 小時內回應／到府 |
> | 送修 | 你自己拆下來寄回原廠（**機關不要選這個**） |
>
> 機關採購伺服器，建議至少 **5 年 NBD 到府**。

### 情境三：判斷舊電腦該升級哪裡

> [!example] 一台 2019 年的辦公電腦，使用者抱怨很慢
> **步驟 1：先量測，不要猜**
>
> ```
> Windows：工作管理員 → 效能，觀察 5 分鐘
> Linux：  htop、free -h、iostat -x 1
> ```
>
> **步驟 2：對照症狀**
>
> | 觀察到 | 瓶頸 | 升級建議 | 成本 |
> | --- | --- | --- | --- |
> | 磁碟 100%、開機超久 | **HDD** | **換 NVMe/SATA SSD** | 低，**效果最大** |
> | 記憶體 90%+、一直在用分頁檔 | **記憶體不足** | 加到 16GB | 低，效果大 |
> | CPU 長時間 100% | CPU | 換 CPU（要確認主機板支援）或整台換 | 高 |
> | 都不高但還是慢 | 可能是軟體問題 | 檢查開機啟動項、防毒設定、惡意程式 | 0 |
>
> **步驟 3：算划不划算**
>
> ```
> 換 SSD + 加記憶體 ≈ 3,000 元 → 體感接近新機
> 整台換新       ≈ 25,000 元
> ```
>
> **如果 CPU 還堪用（第 8 代以後），升級遠比換新划算。**
>
> 但要注意：**Windows 10 已經沒有安全更新**，
> 如果舊機不支援 Windows 11（需要 TPM 2.0 與較新的 CPU），
> 那就必須換機或改裝 Linux —— **這是資安問題，不是效能問題**。

## 機關與企業採購的額外考量

### 總持有成本（TCO）

> [!warning] 採購價不等於總成本
> ```
> TCO = 採購價 + 電費 + 維護 + 授權 + 汰換處理
> ```
>
> **一台伺服器五年的電費可能超過採購價**
> （見 [[15-計概-電力基礎與用電安全]] 的計算範例）。
>
> 所以選購時應該考慮：
> - **能源效率**（80 PLUS 認證等級）
> - 保固年限（過保後的維修成本很高）
> - 是否需要額外授權（Windows Server CAL、虛擬化授權）

### 規格書該怎麼寫

> [!tip] 寫規格書的三個原則
> **一、寫「效能指標」而非「特定型號」。**
> ```
> ❌ CPU：Intel Core i5-14400
> ✅ CPU：PassMark 單執行緒分數 ≥ 3500、多執行緒 ≥ 20000，
>        且支援 vPro 或同等遠端管理技術
> ```
> 綁定型號可能違反政府採購法的公平競爭原則，
> 也讓你無法接受同等或更好的替代品。
>
> **二、把「不可妥協」的項目明確列出。**
> ```
> ✅ 作業系統：Windows 11 Pro（需支援加入 AD 網域與 BitLocker）
> ✅ 儲存：512GB 以上 NVMe SSD（不接受 HDD 或 SATA SSD）
> ✅ 記憶體：16GB 以上，且需為雙通道配置（如 8GB × 2）
> ✅ 保固：5 年原廠到府服務
> ```
>
> **三、寫入驗收方式。**
> ```
> ✅ 驗收時以 CrystalDiskMark 實測循序讀取 ≥ 2000 MB/s
> ✅ 提供原廠保固查詢頁面截圖，證明保固起訖日
> ```
> 沒有寫驗收方式的規格，等於沒有規格。

### 資安相關的採購要求

| 項目 | 為什麼 |
| --- | --- |
| **TPM 2.0** | Windows 11 必要條件；BitLocker 加密的基礎 |
| **Secure Boot** | 防止開機階段被植入惡意程式 |
| **Windows Pro/Enterprise** | 才能加入網域、被 GPO 管理 |
| **vPro / AMT** 或同等 | 遠端管理與修復（但**須妥善設定，本身也是攻擊面**） |
| **原廠韌體更新支援期限** | 韌體漏洞需要原廠修補 |
| **供應鏈來源** | 部分機關對特定產地的設備有採購限制 |

> [!warning] 注意特定資通訊產品的採購限制
> 我國對公務機關使用特定廠牌的資通訊產品（尤其是網通與資安設備）
> 有相關規範與禁限用清單。
>
> **採購前務必確認最新的規定**，
> 可參考行政院與數位發展部發布的相關公告。
> 見 [[07-台灣資安法規與個資法]]。

## 常見錯誤與排錯

| 錯誤 | 後果 | 正確做法 |
| --- | --- | --- |
| 買了 i7 但配 8GB + HDD | 體感比 i5+16GB+SSD 差很多 | **順序：SSD > 記憶體 > CPU > 顯卡** |
| 買了 `F` 後綴的 CPU 沒配顯卡 | **開機沒畫面** | `F` = 無內顯，必須搭配獨顯 |
| 只比型號數字，買到舊世代 | 花了錢效能卻不如預期 | 比同世代，或查 PassMark/Geekbench 跑分 |
| 筆電買了 8GB 想之後再加 | 發現記憶體焊死 | 採購前確認有無 SO-DIMM 插槽 |
| 機關電腦買 Windows 家用版 | **無法加入網域、無法被 GPO 管理** | 規格書註明 Pro 或 Enterprise |
| 買了不支援 Windows 11 的機器 | Windows 10 已無安全更新 | 確認 TPM 2.0 與 CPU 在支援清單內 |
| 伺服器選了「送修」保固 | 故障時要停機數天 | 至少 **NBD 到府**，關鍵系統選 4 小時 |
| SSD 買剛好容量，用到滿 | 效能明顯下降 | 留 20～30% 餘裕 |
| 只看採購價不看 TCO | 五年電費超過機器價格 | 計算 TCO；選 80 PLUS 高效電源 |
| 規格書綁定特定型號 | 可能違反採購法、限縮競爭 | 寫效能指標與必要功能 |
| 沒寫驗收方式 | 交來的東西不符預期也難主張 | 明確寫出實測項目與門檻 |
| 買了獨顯卻插錯螢幕孔 | 沒畫面或效能沒發揮 | 有獨顯時螢幕線要接**顯卡**上的孔 |

## 安全性注意事項

> [!warning] 採購階段就要納入資安考量
> 資安不是買回來之後才處理的事：
>
> | 階段 | 該做什麼 |
> | --- | --- |
> | **規格**| 要求 TPM 2.0、Secure Boot、可加入網域的 OS 版本 |
> | **驗收** | 確認韌體版本、Secure Boot 已啟用、預設密碼已更改 |
> | **上線前** | 依標準流程建置（見 [[01-新機建置標準流程]]） |
> | **使用中** | 納入資產清冊、更新管理、防護軟體 |
> | **汰除** | **硬碟資料銷毀並留存紀錄** |

> [!danger] 汰除階段是最常被忽略的資安缺口
> 舊電腦報廢、捐贈、或轉售時，**硬碟裡的資料還在**。
>
> 快速格式化完全不足（見 [[07-計概-磁碟格式化與RAID入門]]）。
>
> **機關的標準流程**：
> 1. 拆下硬碟
> 2. 執行資料銷毀（Secure Erase / 多次覆寫 / 實體破壞）
> 3. **留存銷毀紀錄與照片**
> 4. 主機才辦理報廢
>
> **最省事的做法**：從一開始就啟用 **BitLocker / LUKS 全碟加密**，
> 報廢時只要銷毀金鑰即可（crypto-erase）。

> [!tip] 資產盤點：你不知道有的東西，就沒辦法保護
> 採購入庫時就要登錄：
> ```
> 財產編號 / 序號 / 型號 / 購入日期 / 保固到期日
> 使用人 / 位置 / 作業系統 / IP / MAC
> ```
>
> 這份清冊是：
> - 資安稽核的必要文件
> - 漏洞爆發時判斷「我們有幾台受影響」的依據
> - 汰換規劃的基礎
>
> 見 [[18-網路設備盤點與文件化]] 與 `71-維運實務` 的盤點章節。

## 速查表

### 升級優先順序（一般辦公）

```
1. SSD（如果還在用 HDD）    ← 效果最大
2. 記憶體到 16GB
3. CPU
4. 顯示卡（多數辦公用途不需要）
```

### 2026 年辦公電腦建議配置

| 項目 | 建議 |
| --- | --- |
| CPU | Core i5 / Ryzen 5 同世代 |
| 記憶體 | **16GB（8×2 雙通道）** |
| 儲存 | **512GB NVMe SSD** |
| 顯卡 | 內顯 |
| 作業系統 | **Windows 11 Pro** |
| 螢幕 | 24" IPS 1080p 可調高度 |

### CPU 後綴速查（Intel）

| 後綴 | 意思 |
| --- | --- |
| **U** | 筆電超低功耗（效能較弱） |
| P | 筆電中功耗 |
| **H / HX** | 筆電高效能 |
| K | 桌機可超頻 |
| **F** | **無內顯，必須配獨顯** |
| T | 桌機低功耗 |

### 記憶體容量建議

| 用途 | 容量 |
| --- | --- |
| 純文書 | 8 GB（最低） |
| **一般辦公** | **16 GB** |
| 開發、設計 | 32 GB |
| 虛擬化、資料庫 | 64 GB+ |

### 儲存速度對照

| 類型 | 速度 |
| --- | --- |
| NVMe PCIe 4.0 | 3000～7000 MB/s |
| NVMe PCIe 3.0 | 1500～3500 MB/s |
| SATA SSD | ~550 MB/s |
| HDD | 100～200 MB/s |

### 規格書三原則

1. 寫**效能指標**不寫特定型號
2. 明確列出**不可妥協**的項目
3. 寫入**驗收方式**與實測門檻

## 練習題

> [!question]- 練習 1：診斷該升級什麼
> 找一台你覺得慢的電腦，開工作管理員（或 `htop`）觀察五分鐘，記下：
> 1. CPU 使用率的最高與平均
> 2. 記憶體使用率
> 3. 磁碟使用率（%）
> 4. 系統碟是 SSD 還是 HDD
>
> 依照本篇的對照表判斷瓶頸在哪，估算升級成本，
> 並與「整台換新」比較划不划算。

> [!question]- 練習 2：配一台機器
> 為以下三個情境各配一台，寫出 CPU/記憶體/儲存/顯卡的選擇與理由：
> 1. 機關承辦人的文書電腦，預算 25,000
> 2. 資訊室要跑 5 台虛擬機的測試主機，預算 80,000
> 3. 想在本機跑 13B 參數 LLM 做內部知識庫測試
>
> 參考方向：
> 1. i5 + 16GB + 512GB NVMe + 內顯 + Win11 Pro
> 2. 核心數與**記憶體優先**（64GB 起），SSD 要快，顯卡不重要
> 3. **VRAM 至少 12～16GB** 是硬需求，其他都可以妥協

> [!question]- 練習 3：寫一段規格書
> 為情境 1 的文書電腦寫一段採購規格，要符合三原則：
> - 用效能指標而非型號
> - 列出不可妥協的項目（OS 版本、SSD、記憶體、保固）
> - 寫出驗收方式
>
> 寫完後檢查：如果廠商拿一台「CPU 符合但用 HDD」的機器來，
> 你的規格書擋得住嗎？

## 小測驗

Q1. 用「水桶理論」說明為什麼「把某一項堆到最高」不是好的採購策略。

Q2. 對一般辦公用途，升級的優先順序是什麼？為什麼 SSD 排第一？

Q3. 「i5-13500H」與「i7-1355U」哪個效能可能比較好？為什麼？

Q4. CPU 型號後綴的 `F` 代表什麼？買了會發生什麼問題？

Q5. 為什麼買 16GB 記憶體建議買 8GB × 2 而不是 16GB × 1？

Q6. 機關電腦為什麼一定要買 Windows Pro 版而不是家用版？

Q7. 跑本地 LLM 時，顯示卡最關鍵的規格是什麼？為什麼？

Q8. 為什麼說「伺服器最重要的規格是保固不是效能」？常見的保固等級有哪些？

Q9. TCO 是什麼？為什麼採購價不等於總成本？

Q10. 寫採購規格書的三個原則是什麼？為什麼不該綁定特定型號？

> [!question]- 測驗答案
> **Q1.** 木桶能裝多少水**取決於最短的那塊木板**。
> 一台配了頂級 CPU 但只有 8GB 記憶體、還用傳統硬碟的電腦，
> 體感會比配置均衡的中階機器差很多。
> **買電腦的目標不是把某一項堆到最高，而是把每一塊木板拉到夠高。**
>
> **Q2.** **SSD > 記憶體 > CPU > 顯卡**。
> SSD 排第一是因為 HDD 與 SSD 的速度差距是**數十倍**
> （100～200 MB/s vs 3000～7000 MB/s），
> 而開機、開軟體、載入檔案這些日常操作全都受磁碟速度支配。
> 一顆 SSD 能讓開機從兩分鐘變 15 秒，是最便宜也最有感的升級。
>
> **Q3.** **`i5-13500H` 可能比較好。**
> 因為筆電 CPU 的**後綴決定一切**：
> **U = 超低功耗、效能較弱**；**H = 高效能**。
> 一顆 H 系列的 i5 效能常常超過 U 系列的 i7。
> 不能只看 i5/i7 的等級數字。
>
> **Q4.** `F` 代表**沒有內建顯示晶片（無內顯）**。
> 買了 `F` 後綴的 CPU 卻沒有搭配獨立顯示卡，
> **開機會完全沒有畫面**。這是實際會發生的採購失誤。
>
> **Q5.** 因為主機板支援**雙通道（Dual Channel）**，
> 兩條記憶體可以同時讀寫，**頻寬加倍**。
> 價格幾乎相同，但效能較好，對使用內顯的機器影響尤其明顯
> （內顯要與系統共用記憶體頻寬）。
>
> **Q6.** 因為**家用版（Home）不能加入 Active Directory 網域**，
> 也不能使用 **BitLocker** 加密、**不能被群組原則（GPO）管理**。
> 這代表那台電腦**無法納入集中管理與資安政策**，是機關資安的破口。
> 採購規格書務必註明 Pro 或 Enterprise。
>
> **Q7.** 最關鍵的是 **VRAM（顯示卡記憶體）容量**。
> 因為模型必須**整個載入 VRAM** 才跑得快；
> VRAM 不夠就會退回用 CPU 與系統記憶體，**慢十倍以上**。
> 所以買來跑 AI 的顯卡，**VRAM 容量比運算速度更重要**。
>
> **Q8.** 因為伺服器故障時，你需要的是**明天就有工程師帶零件到府**，
> 而不是「效能多 10%」—— 停機的損失遠大於效能差異。
> 常見等級：**NBD**（下一個工作日到府）、**4-hour / 8-hour**（快速回應）、
> **送修**（自己寄回原廠，**機關不應選擇**）。
> 建議至少 5 年 NBD 到府。
>
> **Q9.** **TCO = 總持有成本 = 採購價 + 電費 + 維護 + 授權 + 汰換處理**。
> 採購價不等於總成本，因為**一台伺服器五年的電費可能超過它的採購價**，
> 加上過保後的維修成本、額外的軟體授權（如 Windows Server CAL）、
> 以及汰除時的資料銷毀成本。
>
> **Q10.** ①寫「**效能指標**」而非特定型號；
> ②明確列出「**不可妥協**」的項目（OS 版本、SSD、記憶體、保固）；
> ③寫入「**驗收方式**」與實測門檻。
> 不該綁定特定型號，是因為這**可能違反政府採購法的公平競爭原則**，
> 也讓你無法接受同等或更好的替代品。
