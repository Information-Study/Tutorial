# 資源診斷工具集

> [!abstract] 這篇你會學到
> - **★★★ `vmstat`** —— 一個指令看完 CPU / 記憶體 / swap / I/O
> - **★★★ `iostat -x`** —— 每一欄的意義與判斷磁碟瓶頸的門檻
> - **★★ `mpstat`** —— CPU 的七種分類
> - **★★★★ `sar`** —— 唯一能查「昨天下午三點」的工具
> - `pidstat` / `iotop` / `nethogs` / `iftop` —— **找出是「誰」**
> - `ncdu` / `du` / `df` —— 磁碟空間與 **★★★ 已刪除但沒釋放**
> - **★★ 每個工具的第一個數字為什麼要丟掉**

## 安裝

```bash
# ★★★ sysstat：vmstat 之外的核心工具（★ 每台伺服器都該裝）
$ sudo apt install -y sysstat            # iostat mpstat pidstat sar sadf
$ sudo apt install -y procps             # vmstat free ps（★ 通常已有）

# ★ 找出「誰」在用資源
$ sudo apt install -y iotop nethogs iftop nload ncdu

# ★★★ 啟用 sar 的歷史收集（★ 這一步最重要）
$ sudo sed -i 's/^ENABLED="false"/ENABLED="true"/' /etc/default/sysstat
$ sudo systemctl enable --now sysstat
$ systemctl status sysstat --no-pager | head -3
```

> [!info]- Rocky / AlmaLinux（RHEL 系）對照
> ```bash
> $ sudo dnf install -y sysstat procps-ng
> $ sudo dnf install -y epel-release && sudo dnf install -y iotop nethogs iftop ncdu
>
> # ★★★ RHEL 的 sar 收集是用 systemd timer
> $ sudo systemctl enable --now sysstat-collect.timer sysstat-summary.timer
> $ systemctl list-timers | grep sysstat
>
> # ★ 資料位置不同
> #   Ubuntu: /var/log/sysstat/sa<日>
> #   RHEL:   /var/log/sa/sa<日>
> ```

> [!warning] 第一個數字要丟掉 ★★★
> ```
> ★★★ vmstat / iostat / mpstat / sar 的【第一行輸出】
>      是「開機以來的平均值」，不是「現在」
>
> $ iostat -x
> Device  r/s   w/s  %util
> sda     2.1   8.4   1.2        ← ★★★ 開機 12 天以來的平均（沒用！）
>
> ★★★ 正確用法：加上「間隔 次數」，看【第二行以後】
> $ iostat -x 1 3               # ★ 每秒一次，共 3 次 → 看後兩次
> $ vmstat 1 5 | tail -4
> $ mpstat -P ALL 1 3 | tail -6
>
> ★★ 或直接丟掉第一次：
> $ iostat -xd 1 2 | tail -n +7
> ```

## ★★★ vmstat —— 最該先跑的一個

```bash
$ vmstat 1 5
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st
 2  0 131072 412000 210000 5300000   0    0     0    12  890 1420 32 12 48  8  0
 1  0 131072 408000 210000 5310000   0    0     0     8  850 1380 28 10 54  8  0
```

| 欄 | 意義 | **★ 判讀門檻** |
| --- | --- | --- |
| **`r`** | **等 CPU 的程序數** | **★★★ 持續 > 核心數 = CPU 不足** |
| **`b`** | **等 I/O（D 狀態）的程序數** | **★★★★ 持續 > 0 = I/O 瓶頸** |
| `swpd` | 已用的 swap（KB） | ★ 有數字不代表有問題（看 si/so） |
| `free` | 空閒記憶體 | ★★ 不重要（看 available） |
| `buff` `cache` | 緩衝 / 快取 | ★★ 被擠光 = 記憶體壓力 |
| **`si`** | **swap in（KB/s）** | **★★★★ 持續 > 0 = 記憶體真的不夠** |
| **`so`** | **swap out（KB/s）** | **★★★★ 同上** |
| `bi` `bo` | 從/往區塊裝置讀寫（KB/s） | ★★ 對照 iostat |
| `in` | 中斷數 / 秒 | ★ 網路大流量時會高 |
| **`cs`** | **context switch / 秒** | **★★★ 突然暴增 = 有問題**（見下） |
| `us` | 使用者 CPU% | ★ 應用在算 |
| **`sy`** | **系統 CPU%** | **★★ 持續 > 30% = syscall 太多** |
| `id` | 閒置% | |
| **`wa`** | **★★★★ I/O wait%** | **★★★ > 20% = I/O 瓶頸** |
| **`st`** | **steal%** | **★★★★ > 5% = 雲端超賣** |

```
★★★★ vmstat 的四個關鍵組合：

【① 記憶體真的不夠】
   si/so 持續 > 0  +  free 很低  +  cache 被擠光
   → ★★★ 這是唯一可靠的判斷（★ 不是看 free 的數字）

【② I/O 瓶頸】
   b > 0  +  wa 高  +  bi/bo 大
   → ★★★ 接著用 iostat -x 找是哪個磁碟

【③ CPU 不足】
   r 持續 > 核心數  +  us + sy 接近 100  +  wa 低
   → ★★ 真的需要加 CPU 或優化程式

【④ 雲端被超賣】
   st > 5  → ★★★★ 不是你的問題
```

```bash
# ★★ 常用選項
$ vmstat -w 1 5              # ★ 寬版（欄位對齊）
$ vmstat -SM 1 5             # ★★ 用 MB 顯示（★ 好讀很多）
$ vmstat -s                  # ★ 記憶體統計摘要
$ vmstat -d                  # ★★ 磁碟統計
$ vmstat -a 1 3              # ★ 顯示 active/inactive 記憶體
$ vmstat -t 1 5              # ★★ 加上時間戳（★ 記錄時很有用）

# ★★★ 記錄一段時間（排查間歇性問題）
$ vmstat -tw 5 720 > /tmp/vmstat-$(date +%F).log &    # ★ 每 5 秒，跑一小時
$ awk 'NR>2 && ($16>20 || $7>0)' /tmp/vmstat-*.log    # ★★ 找出 wa>20 或 si>0 的時刻
```

> [!tip] context switch 暴增代表什麼 ★★★
> ```
> ★★ cs（context switch）正常範圍：
>   · 一般伺服器：★ 每秒 1,000 ~ 20,000
>   · 高流量 web：★★ 可能到 50,000+
>
> ★★★ 突然暴增到 100,000+ 要注意：
>   ① ★★★ 執行緒/程序太多（★ pm.max_children 設太大）
>   ② ★★ 鎖競爭（★ 資料庫的 lock contention）
>   ③ ★★ 大量的網路小封包（★ 每個封包一次中斷）
>   ④ ★ 程式在忙碌等待（busy-wait）
>
> ★★ 對照 in（中斷）：
>   in 高 + cs 高  → ★★ 網路 I/O 密集
>   in 低 + cs 高  → ★★★ 程序/執行緒排程問題
>
> ★★ 找出是誰：
>   $ pidstat -w 1 3         # ★★★ 每個程序的 context switch
> ```

## ★★★ iostat —— 磁碟瓶頸

```bash
$ iostat -x 1 3
Device  r/s   w/s  rkB/s   wkB/s  rrqm/s wrqm/s r_await w_await aqu-sz %util
sda     8.0 520.0  320.0 68000.0    0.0   12.0    3.20   48.20   24.80  99.8
nvme0n1 2.1  42.0   84.0  1680.0    0.0    2.0    0.08    0.21    0.01   2.4
```

| 欄 | 意義 | **★ 門檻** |
| --- | --- | --- |
| `r/s` `w/s` | 每秒讀/寫次數（IOPS） | ★ 對照磁碟規格 |
| `rkB/s` `wkB/s` | 每秒讀/寫量 | ★ 對照頻寬 |
| `rrqm/s` `wrqm/s` | 被合併的請求 | ★ 高 = 循序存取 |
| **`r_await`** | **★★★ 讀取延遲（ms）** | **SSD < 1ms／HDD < 20ms** |
| **`w_await`** | **★★★ 寫入延遲（ms）** | **★★★★ > 50ms = 有問題** |
| **`aqu-sz`** | **★★★ 平均佇列長度** | **★★★★ > 2 就開始排隊** |
| **`%util`** | **★★★ 忙碌時間比例** | **HDD > 80% 滿載** |
| `svctm` | 服務時間（★ 新版已移除） | ★ 不要看，不準 |

```
★★★★ %util 的陷阱：

  【機械硬碟 HDD】
    %util 100% = ★★★ 真的滿載（★ 一次只能處理一個請求）

  【SSD / NVMe】★★★★
    %util 100% ≠ 滿載！
    → SSD 可以【平行處理多個請求】
    → ★★★ util 只是「有請求在處理的時間比例」
    → ★★★★ 應該看 aqu-sz 和 await

  ★★★ SSD 的正確判斷：
    aqu-sz > 4        → 開始排隊
    w_await > 10ms    → ★★ 太慢（★ 好的 NVMe 應該 < 1ms）
    ★ 對照規格的 IOPS 上限

  【RAID / 網路儲存】★★★
    → %util 完全不可靠（★ 多個實體磁碟）
    → ★★ 只看 await 和 aqu-sz
```

```bash
# ★★ 常用組合
$ iostat -xd 1 3                     # ★★★ 只看磁碟（★ 最常用）
$ iostat -xm 1 3                     # ★ 用 MB
$ iostat -xdp 1 3                    # ★★ 含分割區
$ iostat -xd sda nvme0n1 1 3         # ★ 只看特定磁碟
$ iostat -c 1 3                      # 只看 CPU
$ iostat -xdz 1 3                    # ★★ 排除沒有活動的裝置（★ 很好用）

# ★★★ 找出裝置對應
$ lsblk -o NAME,SIZE,TYPE,MOUNTPOINT,ROTA
NAME    SIZE TYPE MOUNTPOINT ROTA
sda     500G disk             1      # ★★ ROTA=1 → 機械硬碟
├─sda1    1G part /boot       1
└─sda2  499G part /           1
nvme0n1 1T   disk             0      # ★★ ROTA=0 → SSD
└─nvme0n1p1  1T part /var     0

$ df -h /var | tail -1               # ★ 這個掛載點在哪個裝置
$ findmnt -no SOURCE /var
/dev/nvme0n1p1
```

## ★★ mpstat —— CPU 的七種分類

```bash
$ mpstat -P ALL 1 3 | tail -6
CPU  %usr %nice %sys %iowait %irq %soft %steal %guest %gnice %idle
all  32.1  0.00 12.4    8.20 0.00  1.20   0.00   0.00   0.00  46.1
  0  45.2  0.00  8.1    2.10 0.00  0.50   0.00   0.00   0.00  44.1
  1  12.4  0.00  4.2    1.80 0.00  0.20   0.00   0.00   0.00  81.4
  2  88.7  0.00 45.2   12.40 0.00  3.20   0.00   0.00   0.00   0.5
  3   4.0  0.00  2.1    0.30 0.00  0.10   0.00   0.00   0.00  93.5
```

```
★★★ 七種 CPU 時間的意義與處理方向：

  %usr    ★ 使用者空間 → 應用程式在算
          → ★★ 高就是正常的忙碌，優化程式或加 CPU

  %nice   ★ nice > 0 的程序（低優先權）

  %sys    ★★★ 核心空間 → syscall、記憶體管理、排程
          → ★★★ 持續 > 30% 不正常
            · 大量小檔案 I/O（★ 每次都 open/read/close）
            · context switch 太多
            · ★★ 網路封包處理
            → ★ 用 strace -c 找出是哪個 syscall

  %iowait ★★★★ CPU 閒著等 I/O
          → ★★★ > 20% = I/O 瓶頸
          → ★ 加 CPU 完全沒用

  %irq    硬體中斷 → ★ 通常很低

  %soft   ★★ 軟體中斷 → 主要是【網路封包處理】
          → ★★★ 單一核心的 %soft 特別高
            = ★★ 網卡中斷都綁在同一顆 CPU
            → ★ 解法：開啟 RSS/RPS 或調整 IRQ affinity

  %steal  ★★★★ 被 hypervisor 搶走 → 雲端超賣

  %guest  ★ 這台機器跑虛擬機時，guest 用掉的
```

```
★★★ 單顆 CPU 特別忙的常見原因：

  CPU 2 的 %usr 88.7 + %sys 45.2  ← ★★ 加起來超過 100？
  → ★ 是因為這是不同時間點的取樣，不用擔心

  ★★★ 真正要注意的是【只有一顆很忙】：
    ① 單執行緒的程式（★ 只能用一顆）
    ② ★★★ 網卡中斷綁在同一顆（★ 看 %soft）
    ③ ★★ 程式沒有正確使用多核心
```

```bash
# ★★★ 檢查網卡中斷分布
$ cat /proc/interrupts | grep -E 'CPU|eth0|ens18' | head
           CPU0    CPU1    CPU2    CPU3
 128:  12489234       0       0       0   PCI-MSI  ens18-rx-0
#         ↑
#   ★★★★ 全部集中在 CPU0 → 那顆的 %soft 會很高

# ★★ 開啟 RPS（軟體層的分流）
$ echo f | sudo tee /sys/class/net/ens18/queues/rx-0/rps_cpus
#   f = 二進位 1111 = 使用 CPU 0~3

# ★★ 或用 irqbalance
$ sudo apt install -y irqbalance && sudo systemctl enable --now irqbalance

# ★★ 檢查網卡有幾個佇列
$ ethtool -l ens18
Combined:  4                     # ★ 支援 4 個佇列
$ sudo ethtool -L ens18 combined 4    # ★★ 啟用
```

## ★★★★ sar —— 查歷史

```
★★★★ sar 是【唯一】能回答這種問題的工具：
  「昨天下午三點網站很慢，那時候發生什麼事？」
  「上禮拜三半夜服務掛掉前的負載如何？」

★★★ htop / btop / vmstat 都只能看【現在】
```

```bash
# ═══ ★★★ 查今天的 ═══
$ sar -u                      # CPU（★ 從今天 00:00 開始）
$ sar -r                      # 記憶體
$ sar -b                      # I/O 整體
$ sar -d -p                   # ★★ 每個磁碟（-p 顯示裝置名）
$ sar -n DEV                  # ★★ 網路
$ sar -q                      # ★★★ load average + 執行佇列
$ sar -S                      # swap
$ sar -w                      # context switch

# ═══ ★★★★ 查特定日期 ═══
$ ls /var/log/sysstat/         # Ubuntu
sa01  sa02 ... sa27  sa28
$ ls /var/log/sa/              # RHEL

$ sar -u -f /var/log/sysstat/sa27           # ★★★ 27 號的 CPU
$ sar -r -f /var/log/sysstat/sa27           # 27 號的記憶體

# ═══ ★★★★ 查特定時段（★ 最實用）═══
$ sar -u -s 14:00:00 -e 16:00:00 -f /var/log/sysstat/sa27
Linux 6.8.0-45-generic (web01)   08/27/2026   _x86_64_   (4 CPU)

02:00:01 PM  CPU  %user %nice %system %iowait %steal %idle
02:10:01 PM  all  18.24  0.00   6.42   62.31   0.00  13.03    # ★★★★ 找到了！
02:20:01 PM  all  22.11  0.00   8.20   58.44   0.00  11.25
02:30:01 PM  all  19.88  0.00   7.10   61.02   0.00  12.00
02:40:01 PM  all  32.44  0.00  12.10    8.22   0.00  47.24    # ★ 恢復
Average:     all  23.17  0.00   8.46   47.50   0.00  20.87
#                                        ↑
#                            ★★★★ 14:00~14:30 的 iowait 高達 60%

# ★★★ 同一時段的記憶體
$ sar -r -s 14:00:00 -e 16:00:00 -f /var/log/sysstat/sa27
02:10:01 PM kbmemfree kbavail kbmemused %memused kbbuffers kbcached
02:10:01 PM    204800  614400  7549952    96.9      8192    716800
#                        ↑                   ↑
#              ★★★★ available 只剩 600M   ★★★ 用了 96.9%
#   → ★★★★ 結論：記憶體不夠 → cache 被擠光 → 狂讀磁碟 → iowait 爆

# ★★ 同一時段的磁碟
$ sar -d -p -s 14:00:00 -e 16:00:00 -f /var/log/sysstat/sa27 | grep -E 'DEV|sda'
```

```bash
# ★★ 匯出成 CSV / JSON（★ 做圖表或報告）
$ sadf -d /var/log/sysstat/sa27 -- -u | head -3
web01;600;2026-08-27 06:00:01 UTC;all;18.24;0.00;6.42;62.31;0.00;13.03

$ sadf -j /var/log/sysstat/sa27 -- -r > /tmp/mem.json     # ★★ JSON
$ sadf -g /var/log/sysstat/sa27 -- -u > /tmp/cpu.svg      # ★ SVG 圖表

# ★★★ 調整保留天數（預設 7 或 28 天）
$ sudo vim /etc/sysstat/sysstat
HISTORY=30                      # ★★ 保留 30 天
COMPRESSAFTER=10                # ★ 10 天後壓縮

# ★★ 調整收集頻率（預設 10 分鐘）
$ sudo systemctl edit sysstat-collect.timer      # RHEL
$ sudo vim /etc/cron.d/sysstat                   # Ubuntu
5-55/10 * * * * root command -v debian-sa1 > /dev/null && debian-sa1 1 1
#     ↑ ★★ 改成 /5 就是每 5 分鐘
```

> [!tip] sar 的價值無可取代 ★★★★
> ```
> ★★★★ 沒有 sar 的情況：
>   使用者：「昨天下午網站很慢」
>   你：「……現在看起來正常」  ← ★★ 完全查不到
>
> ★★★★ 有 sar 的情況：
>   $ sar -u -s 14:00 -e 16:00 -f /var/log/sysstat/sa27
>   → iowait 60% → 記憶體不夠 → 三分鐘定位
>
> ★★★ 所以：
>   【每一台伺服器裝機時就啟用 sysstat】
>   → 這是成本最低、回報最高的一件事
> ```

## 找出「誰」★★★

### pidstat ★★

```bash
# ★★★ 每個程序的 CPU
$ pidstat 1 3
   UID  PID  %usr %system %guest %wait %CPU  CPU  Command
  1001 1234  8.00    4.00   0.00  0.00 12.00    2  php-fpm
   110 5678  5.00    3.00   0.00  1.00  8.00    0  mysqld

# ★★★ 每個程序的磁碟 I/O（★ 比 iotop 好，不用 root 也能看部分）
$ sudo pidstat -d 1 3
   UID  PID   kB_rd/s  kB_wr/s kB_ccwr/s iodelay Command
   110 5678   2150.00  52300.00     0.00      12  mysqld     # ★★★ 就是它
     0 8901      0.00  12100.00     0.00       3  rsyslogd

# ★★★ context switch
$ pidstat -w 1 3
   UID  PID   cswch/s nvcswch/s  Command
  1001 1234    120.00   4520.00  php-fpm      # ★★ nvcswch 高 = 被搶佔
#   cswch   = 自願的（★ 等 I/O 或鎖）
#   nvcswch = ★★ 非自願（★ 時間片用完被搶佔 → CPU 競爭）

# ★★ 記憶體
$ pidstat -r 1 3
$ pidstat -rd -p $(pgrep -d, -x mysqld) 1 5     # ★ 只看 mysqld

# ★★ 執行緒層級
$ pidstat -t -p 5678 1 3

# ★★★ 綜合（★ 一次看完）
$ pidstat -urd 1 3
```

### iotop ★★

```bash
$ sudo iotop -oPa
#   -o  ★★★ 只顯示有 I/O 的（★ 必加，否則一堆 0）
#   -P  ★★ 只顯示程序（不顯示執行緒）
#   -a  ★★ 累計（★ 從啟動開始累加，比瞬時值好判斷）

Total DISK READ: 2.15 M/s | Total DISK WRITE: 64.32 M/s
  PID  PRIO USER   DISK READ  DISK WRITE  SWAPIN   IO>  COMMAND
 5678  be/4 mysql     2.10 M     52.30 M   0.00 % 89.2% mysqld
 8901  be/4 root      0.00 B     12.10 M   0.00 %  8.1% rsyslogd

# ★★ 批次模式（可寫進腳本）
$ sudo iotop -boPa -n 3 -d 2 | head -20
```

## 完整實戰範例：一分鐘定位

```bash
#!/usr/bin/env bash
# ★★★ /usr/local/bin/quickdiag —— 一分鐘系統診斷
set -uo pipefail
CORES=$(nproc)
echo "═══ $(hostname)  $(date '+%F %T')  ${CORES} cores ═══"

echo -e "\n【1】★★★ 負載"
uptime
awk -v c="$CORES" '{printf "  load/核心 = %.2f  ", $1/c;
  if ($1/c>2) print "★★★ 壅塞"; else if ($1/c>1) print "★★ 滿載"; else print "★ 正常"}' \
  /proc/loadavg

echo -e "\n【2】★★★ CPU 分類（3 秒取樣）"
mpstat 1 3 2>/dev/null | tail -1 | \
  awk '{printf "  usr=%.1f sys=%.1f iowait=%.1f steal=%.1f idle=%.1f\n",$4,$6,$7,$9,$13
        if($7>20) print "  ★★★★ iowait 高 → I/O 瓶頸"
        if($9>5)  print "  ★★★★ steal 高 → 雲端超賣"
        if($6>30) print "  ★★★ sys 高 → syscall 或 context switch 過多"}'

echo -e "\n【3】★★★ 記憶體"
free -h | sed 's/^/  /'
free | awk '/^Mem:/{p=$7/$2*100; printf "  available = %.1f%%  ", p;
  if(p<10) print "★★★★ 嚴重不足"; else if(p<20) print "★★★ 偏低"; else print "★ 充足"}'
vmstat 1 3 | tail -1 | awk '{if($7>0||$8>0) print "  ★★★★ 正在換頁 si="$7" so="$8;
  else print "  ★ 沒有換頁"}'

echo -e "\n【4】★★★ 磁碟 I/O"
iostat -xdz 1 2 2>/dev/null | awk '/^Device/{h=1;next} h&&NF>5 {
  printf "  %-10s util=%.1f%% aqu=%.2f r_await=%.1fms w_await=%.1fms",$1,$NF,$(NF-1),$(NF-4),$(NF-3)
  if($(NF-1)>4) printf "  ★★★★ 佇列積壓"
  else if($(NF-3)>50) printf "  ★★★ 寫入延遲高"
  print ""}' | tail -6

echo -e "\n【5】★★★ 卡在 I/O 的程序"
ps -eo state,pid,user,comm | awk '$1 ~ /^D/ {print "  ★★★ "$0}' || echo "  ★ 無"

echo -e "\n【6】磁碟空間"
df -hx tmpfs -x devtmpfs -x overlay 2>/dev/null | awk 'NR==1{print "  "$0;next}
  {u=$5+0; printf "  %s", $0; if(u>90) printf "   ★★★★ 快滿"; else if(u>80) printf "   ★★ 注意"; print ""}'
echo "  --- inode ---"
df -i 2>/dev/null | awk 'NR>1 && $5+0>85 {print "  ★★★ inode "$5" "$6}' || true

echo -e "\n【7】Top 記憶體（RSS）"
ps -eo pid,user,rss,comm --sort=-rss | head -6 | \
  awk 'NR==1{print "  "$0;next}{printf "  %6s %-10s %8.1fM %s\n",$1,$2,$3/1024,$4}'

echo -e "\n【8】Top CPU"
ps -eo pid,user,pcpu,comm --sort=-pcpu | head -6 | sed 's/^/  /'

echo -e "\n【9】網路"
ss -s | head -2 | sed 's/^/  /'
sar -n DEV 1 1 2>/dev/null | awk '/Average/&&$2!="lo"&&$2!="IFACE"{
  printf "  %-8s rx=%.1f KB/s tx=%.1f KB/s\n",$2,$5,$6}'

echo -e "\n【10】★★ 最近的核心訊息"
dmesg -T 2>/dev/null | grep -iE 'error|fail|oom|i/o error|reset' | tail -5 | sed 's/^/  /' \
  || echo "  ★ 無異常（或需要權限）"

echo -e "\n【11】★★★ 歷史（sar）"
if [ -d /var/log/sysstat ] || [ -d /var/log/sa ]; then
    echo "  ★ 今天 iowait 最高的時段："
    sar -u 2>/dev/null | awk 'NR>3 && $1!="Average:" && $7+0>15 {print "  ★★★ "$1" "$2" iowait="$7"%"}' | head -5 \
      || echo "  ★ 今天沒有明顯的 I/O 高峰"
else
    echo "  ★★★ sysstat 未啟用！建議："
    echo "     sudo sed -i 's/ENABLED=\"false\"/ENABLED=\"true\"/' /etc/default/sysstat"
    echo "     sudo systemctl enable --now sysstat"
fi
```

## 常見錯誤與排錯

| 現象 | 原因 | 解法 |
| --- | --- | --- |
| **`iostat` 第一行數字很奇怪** ★★★ | 那是**開機以來的平均** | `iostat -x 1 3` 看第二行以後 |
| **SSD 的 `%util` 100% 但很快** ★★★★ | SSD 能平行處理 | 看 **`aqu-sz`** 和 **`await`** |

| **`df` 100% 但 `du` 找不到** ★★★★ | **已刪除但程序開著** | **`lsof +L1`**；重啟服務 |
| **空間還有但建不了檔** ★★★ | **inode 用完** | `df -i`；刪小檔案 |

## 安全性注意事項

> [!warning] 三個要點 ★★
> ```
> ① ★★ 這些工具會顯示完整的指令列與網路連線
>      → ★★★ 含密碼的指令、內部 IP、服務拓撲
>      → ★ nethogs/iftop 需要 root（★ 不要給一般使用者 sudo）
>
> ② ★★★ sar 的歷史資料本身是敏感資訊
>      → 顯示流量模式、負載規律、服務時間
>      → ★★ /var/log/sysstat 權限應該是 755，檔案 644
>      → ★ 可以縮到 640 + adm 群組
>
> ③ ★★ iotop/nethogs 用 sudo 執行時要小心
>      → ★★★ iotop 有互動介面，按錯鍵可能影響程序
>      → ★ 批次模式（-b）比較安全
> ```

> [!question]- 測驗答案
> **Q1.** 因為**第一行是「開機以來的累計平均值」，不是「現在的狀態」**。
> 一台開機 12 天的機器，第一行告訴你的是這 12 天的平均 ——
> 就算現在磁碟 100% 滿載，平均下來可能只有 1.2%，完全看不出問題。
> **正確用法是加上「間隔 次數」，看第二行以後**：
> ```bash
> iostat -x 1 3          # ★ 每秒一次共 3 次
> vmstat 1 5 | tail -4   # ★ 丟掉表頭與第一行
> mpstat -P ALL 1 3 | tail -6
> ```
> 這對 `vmstat`、`iostat`、`mpstat`、`pidstat` 都適用。
> `sar` 是例外 —— 它讀的是歷史檔案，每一行都是實際的取樣。
>
> **Q2.** **`r`（等 CPU 的程序數）→ CPU 不足**：
> 持續 > 核心數表示程序在排隊等 CPU，此時 `us`+`sy` 通常也接近 100%。
> **`b`（等 I/O 的程序數，D 狀態）→ I/O 瓶頸**：
> 持續 > 0 表示有程序卡在磁碟等待，搭配 `wa`（iowait）確認。
> **`si`/`so`（swap in/out）→ 記憶體不足**：
> **持續 > 0 才是記憶體真的不夠**。
> **三者的關鍵都是「持續」** —— 偶爾跳一下是正常的，
> 要看的是這個數字**維持在高點**。
> 額外的 **`st`（steal）> 5 = 雲端主機被超賣**，
> 這不是你的系統問題，是供應商的問題。
>
> **Q3.** **★★★★ 不一定** —— SSD 的 `%util` 不可靠。
> `%util` 的定義是「有 I/O 請求在處理的時間比例」，
> 這對**機械硬碟**是準確的（一次只能處理一個請求，100% 就是滿載），
> 但 **SSD/NVMe 可以平行處理數十個請求** ——
> `%util` 100% 可能只是「一直有請求」，離它的極限還很遠。
> **SSD 該看的三個欄位**：
> ①**`aqu-sz`（平均佇列長度）> 4** → 請求開始積壓；
> ②**`w_await`/`r_await`（延遲 ms）** —— 好的 NVMe 應該 **< 1ms**，
> 超過 10ms 就明顯有壓力；
> ③**對照規格的 IOPS 上限**（`r/s` + `w/s`）。
> **RAID 和網路儲存的 `%util` 也同樣不可靠**（背後是多顆磁碟）。
> 用 `lsblk -o NAME,ROTA` 確認：**ROTA=1 是機械、0 是 SSD**。
>
> **Q4.** **`swpd` 是「目前有多少資料在 swap 裡」的存量**，
> **`si`/`so` 是「每秒換入/換出多少」的流量**。
> **★★★★ 只有 `si`/`so` 持續 > 0 才代表記憶體真的不夠**。
> `swpd` 有數字**不一定有問題** —— Linux 會主動把長時間沒用到的分頁
> （例如開機後就沒再碰過的服務）換出去，騰出記憶體給 page cache，
> 這是**正常且有益的行為**（受 `vm.swappiness` 控制）。
> 那些分頁換出去後就一直躺在 swap 裡，`swpd` 顯示 1.4G，
> 但如果 `si`/`so` 都是 0，表示**沒有在反覆換頁，系統很健康**。
> **真正的警訊是「持續換頁」（thrashing）** ——
> 記憶體不夠 → 換出 → 馬上又需要 → 換入 → 又要換出別的，
> 系統把時間全花在搬記憶體上。
>
> **Q5.** **★★★★ 查歷史 —— 回答「昨天下午三點發生什麼事」**。
> htop、btop、vmstat、iostat **全部只能看「現在」**，
> 但事故幾乎都是**事後才被回報**的：
> 「昨天下午網站很慢」「上禮拜三半夜掛過一次」。
> 沒有 sar 的話你只能回答「現在看起來正常」，完全無從查起。
> **啟用**（Ubuntu）：
> ```bash
> sudo apt install -y sysstat
> sudo sed -i 's/^ENABLED="false"/ENABLED="true"/' /etc/default/sysstat
> sudo systemctl enable --now sysstat
> ```
> RHEL 是 `systemctl enable --now sysstat-collect.timer`。
> **查詢**：
> ```bash
> sar -u -s 14:00:00 -e 16:00:00 -f /var/log/sysstat/sa27
> ```
> **這是裝機時成本最低、回報最高的一件事** ——
> 每台伺服器都該做。
>
> **Q6.** ①**★★★★ 檔案已刪除但程序還開著** —— 最常見。
> 檔案的目錄項被移除（`du` 掃不到）但 inode 還在、空間沒釋放，
> 要等**持有它的程序關閉檔案描述符**：
> ```bash
> sudo lsof +L1        # ★★★ NLINK=0 的就是
> sudo systemctl restart rsyslog   # ★★ 重啟持有的服務
> ```
> ②**★★ 掛載點蓋住了底下的檔案** ——
> `/var` 掛載前底下就有檔案，掛上去後那些檔案還佔空間但看不到：
> ```bash
> sudo mount --bind / /mnt/check && du -sh /mnt/check/var
> ```
> ③**★★★ inode 用完**（不是空間滿）—— `df -i` 確認；
> ④**★ 保留給 root 的空間**（ext4 預設 5%）——
> `tune2fs -m 1 /dev/sda2` 可以調降。
>
> **Q7.** **`df -i` 查的是 inode 使用量** ——
> inode 是檔案系統用來記錄「一個檔案的中繼資料」的結構，
> **每一個檔案（不論多小）都要佔一個 inode**，
> 而 inode 的數量在**格式化時就固定了**。
> **什麼情況會遇到**：
> 大量的**小檔案** —— PHP 的 session 檔、快取檔案、
> 郵件佇列、縮圖、日誌切檔、npm 的 `node_modules`。
> **症狀很迷惑**：`df -h` 顯示空間還有一半，
> 但建立新檔案卻報 **`No space left on device`**。
> ```bash
> df -i                        # ★★★ IUse% 100% 就是它
> sudo find /var -xdev -type f | awk -F/ '{print $1"/"$2"/"$3}' | \
>   sort | uniq -c | sort -rn | head       # ★★ 找檔案最多的目錄
> ```
> **解法**：刪除不需要的小檔案；
> 長期解法是重新格式化時調高 inode 密度（`mkfs.ext4 -i 8192`），
> 或改用 **XFS/Btrfs**（動態配置 inode，不會有這個問題）。
>
> **Q8.** **`cswch/s`（自願的 context switch）** ——
> 程序**主動放棄 CPU**，因為它要等 I/O、等鎖、或呼叫了 `sleep`。
> 這是**正常的行為**，數字高通常表示程式在做很多 I/O。
> **`nvcswch/s`（非自願的 context switch）** ——
> 程序**還想繼續跑，但時間片用完被核心搶佔**。
> **★★★ 這個高才代表 CPU 競爭** ——
> 表示可執行的程序比 CPU 多，大家在搶。
> **判讀**：
> ```bash
> pidstat -w 1 3
> ```
> `nvcswch` 持續很高的程序，搭配 `vmstat` 的 `r` > 核心數，
> 就確認是 **CPU 不足或程序開太多**
> （典型案例：`pm.max_children` 設成 50 但只有 4 核心）。
>
> **Q9.** **`%soft`（軟體中斷）主要是網路封包處理** ——
> 單一核心特別高，最常見的原因是**網卡的中斷全部綁在同一顆 CPU 上**。
> **確認**：
> ```bash
> cat /proc/interrupts | grep -E 'CPU|ens18'
> #  128:  12489234   0   0   0   PCI-MSI  ens18-rx-0
> #          ↑ ★★★★ 全部集中在 CPU0
> ```
> **三個處理方式**：
> ①**啟用網卡的多佇列（RSS）**（硬體層，效果最好）：
> ```bash
> ethtool -l ens18                    # 看支援幾個佇列
> sudo ethtool -L ens18 combined 4    # ★★ 啟用
> ```
> ②**啟用 RPS**（軟體層分流，虛擬機常用）：
> ```bash
> echo f | sudo tee /sys/class/net/ens18/queues/rx-0/rps_cpus
> ```
> ③**安裝 `irqbalance`** 讓系統自動分配中斷。
> 另一個可能是**單執行緒的應用程式**吃滿一顆，那要看 `%usr` 而不是 `%soft`。
>
> **Q10.** **誰在寫磁碟**：
> ```bash
> sudo iotop -oPa            # ★★★ -o 只顯示有活動的（必加）
> sudo pidstat -d 1 3        # ★★ 不需要互動介面，可寫進腳本
> ```
> **誰在用網路**：
> ```bash
> sudo nethogs ens18         # ★★★ 依【程序】顯示
> sudo iftop -i ens18 -nNP   # ★★ 依【連線】顯示（跟誰在傳）
> ```
> **沒有那些工具時**（只用核心提供的介面）：
> **磁碟** —— 讀 `/proc/<PID>/io` 的 `read_bytes`/`write_bytes`：
> ```bash
> for p in /proc/[0-9]*; do
>   w=$(awk '/^write_bytes/{print $2}' "$p/io" 2>/dev/null)
>   [ -n "$w" ] && [ "$w" -gt 10485760 ] && \
>     echo "${p#/proc/} $(cat $p/comm) $((w/1048576))MB"
> done | sort -k3 -rn | head
> ```
> **網路** —— `ss -tunp` 看連線與對應的程序、
> `sar -n DEV 1 3` 看介面流量、`ip -s link` 看累計統計。
