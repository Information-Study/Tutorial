# 資訊設備維運手冊 — 升級規劃

> [!abstract] 這份文件是什麼
> 把現有的「Linux 系列教學」（197 篇骨架）升級為涵蓋 **資訊設備安裝、部署、設定、優化、維護** 全生命週期的維運手冊。
> 本文件先定案結構與篇章清單，經確認後再執行搬遷與骨架建立。

---

## 一、定位轉變

| | 升級前 | 升級後 |
| --- | --- | --- |
| 定位 | Linux 系列教學 | 資訊設備全生命週期維運手冊 |
| 範圍 | 單機 Linux + Web/DB/容器/部署 | 再加上網路設備、Windows/AD、虛擬化、軟路由、機房硬體、憑證 PKI、維運制度 |
| 讀者 | 想學 Linux 的人 | 負責機關／企業資訊設備的維運人員 |
| 主軸 | 由淺至深學會工具 | **安裝 → 部署 → 設定 → 優化 → 維護** 的循環 |
| 規模 | 197 篇教學 + 40 索引 | 約 **348 篇教學**（新增約 151 篇）+ 約 60 索引 |

不變的部分：Ubuntu/Debian 主線 + RHEL 對照、每篇 12 段章節骨架、frontmatter 規格、
`[[wikilink]]` 交叉引用、`_工具/` 自動化維護腳本。

新增的橫向慣例：

- **網路設備**：★★★★ **Juniper JunOS 為主線**（2026-08-29 使用者改定），Cisco IOS 以 `> [!info]- Cisco IOS 對照` 摺疊區塊並列（與現有 RHEL 對照相同寫法）。
- **Windows 主題**：以 GUI 操作步驟為主、PowerShell 指令為輔，兩者並陳。
- **實務表單**：巡檢表、盤點表、變更單等可直接取用的表格，統一放 `_表單範本/`。

### ★★★★ 「依建議學習順序及邏輯順序編號」的可行性與限制

使用者要求**依建議學習順序「及邏輯順序」排序編號**。
實測 85 個索引頁都有 `## 建議閱讀順序`，但它們是**敘述性文字，且多半給出好幾條路線**，例如：

  - 效率向：Bash/Zsh 效率設定 → 現代 CLI 工具集
```

★★★★ **一組線性編號只能表達一種順序，無法同時表達三條路線。**
因此改制時必須為每章**挑一條正規順序（canonical order）**當作編號依據。
使用者指定的兩個排序依據，實務上這樣結合：

1. **建議學習順序優先** —— 以索引頁「必修／主線」那條路線為準

2. **邏輯順序作為決勝與補位** —— 學習路線沒點名、或多條路線互相衝突的篇章，
   改用邏輯順序決定：
   - **依賴在前**：被別篇當作 `prerequisites` 的，排在依賴它的篇章之前
   - **生命週期順序**：概念 → 安裝 → 設定 → 調校 → 備份 → 監控 → 安全強化 → 疑難排解
   - **由淺入深**：`difficulty` 入門 → 進階 → 專家
3. 其餘路線**仍以文字保留在索引頁的「建議閱讀順序」**，用 wikilink 指過去 ——
   讀者照樣能跳著讀，只是檔名順序反映主線。
4. ★★★ 每章的正規順序**改制前要逐章人工確認**，這是本次改制最需要判斷、

### 98 常見故障排除手冊的寫法

**定位**：這不是新的教學，是**查詢用的索引**。維運人員出事時第一個打開的就是它。

結構建議：

```
# <章節> 常見故障排除

> [!abstract] 怎麼用這份手冊
> 依「症狀」找，不是依「技術」找。找到症狀 → 看判斷分流 → 點進原文看原理。

## 快速索引（依症狀）
| 症狀 | 最可能的原因 | 先查什麼 | 原理詳見 |
| --- | --- | --- | --- |
| 連不上 SSH，Connection refused | 服務沒起來／埠改了／防火牆 | `ss -ltnp \| grep sshd` | [[…原文…]] |

## 依情境展開
### ★★★★ 情境一：<症狀>
- **現象**：實際會看到的錯誤訊息（逐字）
- **判斷分流**：看到 X 代表 A、看到 Y 代表 B
- **處置步驟**：【1】【2】【3】，附指令與預期輸出
- **原理**：一句話帶過 + `→ 原理詳見 [[原文檔名]]`
- **預防**：怎麼避免再發生

## 一頁式急救卡
出事時先跑的五個指令與判讀

## 延伸閱讀
```

**硬性要求**：
1. ★★★★ **每個情境都要有 `→ 原理詳見 [[檔名]]`**，把原理留在原文，這裡只放「怎麼辦」
2. 症狀要用**使用者實際會說的話**與**逐字的錯誤訊息**，不要用技術術語當索引
3. 涵蓋全章所有篇章會遇到的故障，不要只挑幾篇
4. 要有「一頁式急救卡」—— 出事時來不及讀長文，先跑哪幾個指令
